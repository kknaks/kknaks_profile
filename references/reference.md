# references/

## 1. 개요

**정의**
- 작업하면서 **업무용으로 참고하는 것들의 모음.** 내가 만든 것과 밖에서 받은 것이 같이 산다.

**역할**
- 일하다가 옆에 두고 꺼내 보는 실무 참고 자료를 한곳에 모은다.
- 소화해서 배우는 자료가 아니라 **찾아 쓰는 자료**다.

## 2. 무엇이 오나

| 갈래 | 예 |
| --- | --- |
| 만든 것 | 치트시트, 명령·설정 모음, 자주 쓰는 템플릿·스니펫, 정리해 둔 절차 |
| 받은 것 | 공유받은 문서·가이드, 발표 자료, 외부에서 전달받은 참고 파일 |

## 3. 경계 — `para/resources/` 와 다르다

| 기준 | `references/` | `para/resources/` |
| --- | --- | --- |
| 성격 | 일하다 꺼내 보는 실무 참고 | 밖에서 들어온 학습 자료 (세컨드 브레인) |
| 쓰임 | 반복해서 찾아본다 | 소화하고 나면 출처로 남는다 |

- 읽고 배워서 개념이 자라면 `para/areas/concept/` 로, 출처만 남기면 `para/resources/` 로 간다.
- 여기 남는 것은 **업무 중 참조가 목적인 것**뿐이다.

## 4. 색인

한 건은 폴더 하나다. 지금까지는 `YYYY-MM-DD-주제/` 로 들어왔다 — 규칙으로 확정한 것은 아니다.

| 폴더 | 무엇 | 갈래 |
| --- | --- | --- |
| `2026-08-28-sc인터뷰-경영관리부/` | SC 인터뷰 경영관리부 1차 관리자 회차(2026-08-26) — 현행업무 발견지도(AS-001~031) · 1차 질문지 · 회의록 · 트랜스크립트(mediness prod DB 추출) · 결과 보고서 초안 | 만든 것 · 받은 것 |

## 5. 아직 안 정한 것

- 하위 디렉토리 구조 (건별 폴더 `YYYY-MM-DD-주제/` 를 규칙으로 굳힐지)
- 파일 명명 규칙과 frontmatter 필드
- 받은 것 중 사내 정보가 섞인 자료의 취급 (이 레포는 공개다)
