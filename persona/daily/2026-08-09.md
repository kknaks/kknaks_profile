## 한 일

mediness는 코드 변경 없이 서버 자동생성 일일 브리핑 문서(`briefings/2026-08-09.md`) 업로드 커밋만 발생했다. 21:05 UTC에 08-07~09 기간 초판을 올렸고, 1분 뒤 기간을 08-08~09로 좁히고 CHARTY·LINKY·STUDIO·SELLY·CASTY 등 비활동 제품까지 상태판에 명시한 개정판을 재업로드했다. 이 레포 자체는 작업 결과물이 아니라 WATCH·THREADY 등 다른 레포와 Slack·Jira·Confluence 활동을 취합한 브리핑 저장소이고, 이날 커밋은 그 재생성·재배포 흔적이다.

kknaks_profile은 kknaks-agents(provider-neutral LLM 런타임) 설계를 패키지 단위로 decision 문서화하는 작업이 대부분이었다. core → process → providers → tools → sessions → skills 순서로 경계를 제안하되, 각 decision은 직전 decision을 proposed 입력으로만 참조하고 문서 연결도 파일명이 아닌 범주 수준으로만 걸었다. turn runtime 하나만 accepted로 승격됐고 나머지 6개는 proposed로 남았으며, baseline·인덱스 README도 갱신했다. 별개로 career/daily 노트 자동 퍼블리시 커밋 두 건, 알고리즘 스터디 노트(clone-graph) 한 건이 있었다.

## 막힌 것 · 판단

mediness: 같은 파일이 1분 간격으로 두 번 다르게 커밋됐다 — 두 번째가 완성도가 높은 걸 보면, 초안 배포 뒤 곧바로 재실행·보정되는 파이프라인 구조로 읽힌다.

kknaks_profile: skills를 최소 런타임 필수 요소로 승격하지 않고 "추후 조립 가능한 독립 확장 모듈"로 유지하되, "`skills/`를 지워도 첫 vertical slice가 그대로 돈다"를 성공 조건으로 못박았다. skill 출처를 "호스트의 명시적 등록 하나"로 좁혀 filesystem scan·plugin·marketplace·원격 registry·모델 자기설치를 배제했는데, 이는 기존 설계 노트를 뒤집는 결정이었다. skill 본문이 tool 권한·정책·선택·한도를 바꾸지 못한다는 경계를 명시하면서도 간접 injection·신뢰할 수 없는 등록까지는 라이브러리가 막을 수 없다는 한계를 그대로 남겼다.

## 알게 된 것

registry(등록)·turn 단위 선택·모델에 보이는 표면(prompt projection)을 다른 세 값으로 분리하고, 선택은 호스트 입력에서만 와 turn 시작에 고정돼 불변이라는 패턴이 tools·skills decision 양쪽에서 동일하게 적용됐다 — 라이브러리 설계 전반을 관통하는 원칙으로 보인다. 다만 오늘 작성한 decision 문서 두 건에서만 확인됐고 별도 reference 자료가 없어, 지식그래프 concept로는 아직 올리지 않는다 — 세 번째 맥락에서 재등장하거나 출처 자료로 정리되면 개념화한다.
