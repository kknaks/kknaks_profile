## 한 일

mediness는 문서 레포이고 코드는 별도 app 레포 PR로 착지된다. 이날의 중심선은 MCP tool 표면을 세 차례 다시 그은 것이다. 오전엔 레거시 의사결정 원장을 Action Runtime 워크플로로 이식하는 계약(SPEC-154)을 신설했고, 오후엔 그 워크플로 위에 incident·회의실 예약·WBS 조회/쓰기 tool 17종의 계약을 잡아 당일 구현까지 완주했다(WP-097, `/health` 30→47). 저녁엔 회의 재추출 세션의 MCP tool을 read-only로 넓히고, 자정 직전 레거시 tool 7종을 은퇴시켜 write surface를 11→6으로 줄였다. 곁가지로 회의 모달 v2 스펙, WP-095 DnD 좌표계 버그 수정·배포, WBS 담당자의 organization_member 전환, 전역 IA 셸(SPEC-220) 완주, 전 제품 `version` 필드 오용 정정이 있었다.

kknaks_profile에서는 AXKG SPEC-006 미결 질문이 해소되어 버전을 올리고 상호참조를 갱신, 불필요해진 중간 산출물을 정리했다. career TBD 항목을 실제 서술로 채워 발행하고 알고리즘 학습 로그도 갱신했다.

open_kknaks에서는 Claude Code CLI가 tool_result를 `user` 메시지 content 블록으로 보내는 것을 파서가 놓쳐 결과가 전량 유실되던 버그를 고치고, tool_use_id를 스키마 전반에 실었다.

## 막힌 것 · 판단

레거시 원장을 더 쓰지 않기로 한 것은 사용자 결정이며, 데이터는 이관 완료 상태라 tool은 제거하되 신규 write tool은 v1에서 보류했다. 회의 재추출 계약은 "신규 INSERT 없음"이 실제로는 라이브 누적분 마킹 수준이었음을 인지해 명시적으로 뒤집었고, 세션이 원장에 쓰는 경로가 생기지 않도록 write tool을 후보 목록에서 아예 뺐다. 3개로 쪼개려던 WP는 `server.py`·`/health` 공유 때문에 1개로 병합했다. WP-095는 삽입선과 옆 컬럼의 좌표계 불일치로 원인을 확정했고, jsdom으로는 못 잡는 성격이라 실기동 검증으로 대체했다. open_kknaks에서는 기존 최상위 tool_result 분기를 지우지 않고 하위호환 경로로 남겼다.

## 알게 된 것

tool을 후보에 넣을지(노출 축)와 write tool 호출에 사람 인증을 요구할지(인증 축)는 서로 다른 층의 통제라는 구분을 세션 설계에 명시적으로 썼다. persona 발행 파이프라인은 사람이 편집한 career와 자동 생성 daily를 한 커밋에 같이 싣는다는 것도 확인했다. 실제 CLI 출력을 직접 관찰하고서야 tool_result 유실 같은 조용한 버그를 발견했다는 점에서, 스펙만으로는 안 잡히는 통합 지점은 실제 출력 캡처로 검증해야 함을 다시 확인했다.
