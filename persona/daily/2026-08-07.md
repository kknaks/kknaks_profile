## 한 일

mediness는 실제 화면·사용에서 드러난 결함을 스펙 계약으로 승격하는 하루였다. 랜딩 에이전트 챗(SPEC-230)에서 툴 실행 로그를 카드·출처 칩·마크다운 계약으로 재정의하고, MCP 툴 카탈로그를 확대하다 예약 툴만 켜지고 동반 툴이 꺼져 에이전트가 조용히 포기한 사고를 계기로 툴 간 의존 선언과 관리자 화면 양방향 경고 계약을 신설했다. 예약 카드 수정 요청에 에이전트가 「기능 없음」이라 답한 사고는 조사 결과 백엔드 API는 이미 있고 MCP 노출만 빠진 것이라 신설이 아닌 등재로 처리했다. 토큰 사용량을 방·사용자 축으로 집계하는 관리자 화면·API를 설계하고, 회의록 요약을 배경 주입→오류 정정→유형별 정형화 3단계로 재설계했다. 조직/구성원 전환 트랙도 이날 완료 처리됐다.

kknaks_profile에서는 신규 제품 kknaks-agents의 문서 체계(baseline~architecture 5단)를 처음 세우고, LLM harness 종속을 낮추는 provider-neutral 런타임 구상을 raw 상태로 등록했다. 자동 발행 파이프라인이 다른 레포 작업을 career·daily로 반영한 커밋 2건도 있었다.

open_kknaks에서는 CLI 어댑터(codex/claude)의 usage·cost 필드 키가 실제 응답과 어긋나 값이 조용히 0으로 집계되던 버그 3건(codex 캐시/reasoning, claude 캐시, claude cost)을 실측 로그 근거로 고치고, 취소 요청이 폴링 부재로 반영 안 되던 결함도 수정해 v2.1.2를 냈다.

## 막힌 것·판단

mediness에서는 「기능 부재로 보이지만 실제론 노출만 빠진」 패턴이 반복 확인돼 신설 대신 등재로 처리 범위를 좁혔다. 토큰 집계는 캐시·reasoning이 입력·출력의 부분집합이라 산식을 한 곳에만 두기로 했고, provider별 산식 붕괴 가능성은 이번 범위에서 유보했다. 예약 수정·철회 API가 서로 다른 ID 축을 쓰는 문제는 미해결 과제로 남겼다. open_kknaks에서는 취소 감지를 pub/sub 대신 폴링으로 택했다 — pub/sub은 at-most-once라 재연결 구간 취소 메시지 유실이 지금 고치려는 결함을 재도입하기 때문이다.

## 알게 된 것

기능 부재로 보이는 사고가 실은 계약은 있고 노출만 빠진 경우가 mediness에서 반복돼, 「신설 vs 등재」 구분이 조사 범위를 좁히는 핵심 판단축임을 다시 확인했다. open_kknaks에서도 usage·cost 세 곳에서 같은 클래스의 버그(존재하지 않는 키를 fallback 없이 0 처리)가 반복돼, 실측 로그 기반 키 매핑과 「존재 여부」 판정이 재사용 가능한 패턴임을 확인했다.
