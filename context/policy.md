# Policy Context

이 문서는 로컬 Claude/agent가 문서 민감도, 접근권한, 승인 게이트 관련 판단을 할 때 먼저 읽는 정책 컨텍스트다.

## 적용 범위

- 제품 문서 자동 분류
- 문서 메타데이터 추천
- 민감 문서 판정
- read policy 후보 생성
- 승인 게이트에서 사람이 확인해야 할 위험 표시

## 기본 원칙

- 정책 판단은 추천이다. 최종 권한과 메타데이터는 사람이 승인한다.
- 문서 원본의 SoT는 Google Drive이고, 정책/메타데이터/승인 상태는 DB에 기록한다.
- 권한 없는 문서는 목록, 트리, 검색, 관련 문서 결과에서 숨긴다.
- 관련 부서로 연결되어 있어도 읽기 권한을 자동 부여하지 않는다.
- 민감 문서는 기본적으로 더 좁은 read policy를 추천한다.

## 민감 문서 후보

아래 문서는 민감 문서 후보로 본다.

| 유형 | 예시 | 기본 처리 |
|---|---|---|
| 계약 | 계약서, 견적서, NDA, 외부업체 계약 | 관리자/관련 관리 부서 중심 read policy 추천 |
| 인사 | 근로계약, 평가, 급여, 입퇴사, 개인정보 | HR/admin 중심 read policy 추천 |
| 재무 | 매출, 비용, 정산, 세금, 결제, 계좌 | admin/재무 담당 중심 read policy 추천 |
| 보안 | 계정, 토큰, 비밀번호, 인프라 secret | admin/기술 책임자 중심 read policy 추천 |
| 법무 | 분쟁, 고지, 약관, 개인정보 처리 | admin/법무 또는 경영진 중심 read policy 추천 |

## 추천 출력 원칙

민감도 또는 권한 후보를 생성할 때는 아래 필드를 우선 제안한다.

- `sensitivity`: `normal` 또는 `sensitive`
- `read_roles`
- `read_departments`
- `read_positions`
- `reason`: 왜 해당 권한/민감도를 추천했는지
- `needs_human_review`: 민감 문서 후보이면 `true`

## 금지

- 민감 문서를 공개 범위로 자동 승인하지 않는다.
- Drive 폴더 위치만 보고 접근권한을 확정하지 않는다.
- 관련 부서라는 이유만으로 상세 읽기 권한을 자동 부여하지 않는다.
- 문서 본문에 secret이 있을 때 값을 요약/복사하지 않는다. 존재 여부와 위험만 표시한다.
