# 서브넷과 서브넷 마스크

**IP 주소를 「어느 망인가」와 「그 안의 몇 번인가」로 가르는 선을 어디에 그을지의 문제.** 그 선을 옮기면 망의 크기가 달라진다.

## 정의

IP 주소는 두 부분이다.

```
192.168.0.14
└─ 네트워크 ID ─┘└ 호스트 ID ┘     선을 어디에 긋느냐가 문제
```

- **네트워크 ID** — 그 라우터에 속한 **망 전체**를 가리킨다
- **호스트 ID** — 그 안의 **개별 컴퓨터**를 가리킨다

### 클래스 — 선을 미리 정해 둔 방식

| 클래스 | 고정 비트 | 네트워크 ID | 범위 |
|---|---|---|---|
| **A** | 첫 비트 `0` | 8비트 | 0.x.x.x ~ 127.x.x.x |
| **B** | `10` | 16비트 | 128.x.x.x ~ 191.x.x.x |
| **C** | `110` | 24비트 | 192.x.x.x ~ 223.x.x.x |

**앞의 몇 비트가 클래스를 알려 주고, 클래스가 선의 위치를 정한다** — A 는 망이 적고 호스트가 많고, C 는 반대다.

### 서브넷 마스크 — 선을 직접 긋기

클래스로는 8·16·24 세 자리에만 선을 그을 수 있다. **서브넷 마스크**는 그것을 **비트 단위로** 옮긴다.

```
255.255.255.0  =  11111111.11111111.11111111.00000000
                  └────── 1 인 곳이 네트워크 ID ──────┘└ 0 이 호스트 ID ┘

/24  ← 같은 뜻의 짧은 표기 (앞에서 24비트까지가 네트워크 ID)
```

**서브넷팅** — 호스트 ID 의 앞부분을 떼어 **서브넷 ID** 로 쓰면 망 하나가 여럿으로 쪼개진다.

```
172.16.0.0 / 255.255.192.0        앞의 2비트를 떼면 → 4개의 서브넷

서브넷1  172.16.0.0/18     ~ 172.16.63.255
서브넷2  172.16.64.0/18    ~ 172.16.127.255
서브넷3  172.16.128.0/18   ~ 172.16.191.255
서브넷4  172.16.192.0/18   ~ 172.16.255.255
```

### 각 망의 양 끝은 쓸 수 없다

- **네트워크 주소** — 호스트 ID 가 **전부 0** — 그 망 자체를 가리킨다
- **브로드캐스트 주소** — 호스트 ID 가 **전부 1**(마지막 바이트 255) — 그 망 전체에게 보낼 때 → [[network-layer]]

그래서 실제로 기계에 줄 수 있는 주소는 **그 사이**다.

## 왜 중요한가

**망을 나누는 것이 곧 브로드캐스트와 보안의 경계를 나누는 것이다.** 한 망이 크면 브로드캐스트가 그만큼 넓게 퍼지고, 서로 다 보인다. 쪼개면 **트래픽도 접근도 갈린다** → [[data-link-layer]]

**그리고 클라우드에서 이 계산을 직접 한다.** VPC 를 만들 때 적는 `cidr_block = "10.0.0.0/16"` 이 정확히 이 표기이고, 그 안에 서브넷을 나누는 것이 첫 설계다 → [[infrastructure-as-code]]

## 경계와 오해

- **`/24` 와 `255.255.255.0` 은 같은 말이다** — 표기만 다르다. 짧은 쪽(CIDR)이 요즘 표준이고, 클래스 개념 자체가 그것으로 대체됐다
- **「마지막 1바이트가 0이면 네트워크 주소」는 `/24` 일 때만이다** — 필기가 그렇게 적었는데, **선을 옮기면 경계도 옮겨간다.** 위 예의 서브넷2 는 네트워크 주소가 `172.16.64.0` 이다 — 마지막 바이트가 0 이지만 셋째 바이트가 64 다
- **쪼갤수록 쓸 수 있는 주소가 준다** — 서브넷마다 네트워크 주소와 브로드캐스트 주소 **둘씩** 빠지므로, 잘게 나눌수록 낭비가 커진다
- **클래스는 역사다** — 지금은 CIDR 로 임의의 길이를 쓰므로 **A/B/C 를 외울 필요는 적다.** 다만 사설 IP 대역(`10.x`·`172.16~31.x`·`192.168.x`)이 그 구획에서 나왔다는 것은 알아 둘 값이 있다 → [[ip-address]]
- **필기의 계산 표에 오기가 있다** — 예제는 `172.16.0.0` 으로 시작하는데 결과 표는 `172.168.x` 로 적혀 있고, 2진수 줄의 값도 그와 어긋난다. **원리는 맞고 숫자가 흔들린 자리**다
- **C 클래스의 주소 개수도 어긋난다** — 필기의 「546,870,912개」는 C 클래스 **전체 대역**의 수(약 5억)에 가깝고, **망 하나당 호스트 수는 254개**다. 「가장 적은」이라는 서술과 붙어 있어 헷갈리는 자리다

## 출처

- [[2024-10-17-chapter5-network]] — 「IP주소의 구조와 클래스」가 **네트워크 ID 와 호스트 ID** 의 역할을 갈라 적고, A·B·C 클래스를 **고정 비트 패턴(`0`·`10`·`110`)과 10진수 범위**로 나란히 보인다 — 클래스가 결국 **앞 비트로 선의 위치를 알리는 규약**이라는 것이 이 대비에 담겨 있다. 「서브넷과 서브넷 마스크」 절은 서브넷팅을 **「호스트 ID 를 서브넷 ID 와 호스트 ID 로 나누는 작업」**으로 정의하고, `255.255.255.0` 을 2진수로 펼쳐 **1인 자리가 네트워크 ID** 라는 것을 보인 뒤, `172.16.0.0 / 255.255.192.0` 을 **네 서브넷으로 쪼개는 계산을 2진수와 표로** 끝까지 해 보였다. 네트워크 주소(끝 0)와 브로드캐스트 주소(끝 255)의 정의도 앞 절에 있다. 다만 결과 표의 숫자가 `172.168.x` 로 어긋나 있고, C 클래스의 주소 개수도 맞지 않는다
