# 트랜잭션 전파 (Propagation)

**트랜잭션이 걸린 메서드가 이미 트랜잭션 안에서 불렸을 때 어떻게 할지를 정하는 규칙.** 합칠 것인가, 따로 열 것인가, 거부할 것인가.

## 정의

이 규칙이 필요한 이유는 **`@Transactional` 이 붙은 메서드가 다른 `@Transactional` 메서드를 부를 수 있기** 때문이다. 부르는 쪽에 트랜잭션이 있는지 없는지에 따라 여섯 갈래로 갈린다.

| 정책 | 부르는 쪽에 트랜잭션이 **없을 때** | **있을 때(Tx1)** |
|---|---|---|
| **REQUIRED**(기본) | 새로 만든다 (Tx1) | **합친다** (Tx1) |
| REQUIRES_NEW | 새로 만든다 (Tx1) | **따로 만든다** (Tx2) |
| MANDATORY | **예외** | 합친다 (Tx1) |
| SUPPORTS | 트랜잭션 없이 실행 | 합친다 (Tx1) |
| NOT_SUPPORTED | 그냥 실행 | **현재 것을 멈추고** 트랜잭션 없이 실행 |
| NEVER | 그냥 실행 | **예외** |

세 축으로 읽으면 외우기 쉽다.

- **합칠 것인가 나눌 것인가** — REQUIRED(합침) ↔ REQUIRES_NEW(나눔)
- **없으면 만들 것인가 거부할 것인가** — REQUIRED(만듦) ↔ MANDATORY(거부)
- **있으면 쓸 것인가 거부할 것인가** — SUPPORTS(씀) ↔ NEVER(거부)

## 왜 중요한가

**「전부 성공하거나 전부 되돌린다」의 범위가 여기서 정해진다.** 기본값 REQUIRED 는 **부르는 쪽과 하나가 되므로**, 안쪽에서 실패하면 바깥쪽 작업도 함께 롤백된다 — 대개 이것이 원하는 것이다.

**REQUIRES_NEW 가 필요한 자리는 「같이 죽으면 안 되는 것」이다.** 이력 기록이나 로그처럼, **본 작업이 롤백되어도 남아야 하는 것**은 따로 열어야 한다. 반대로 그 이력을 REQUIRED 로 두면 실패한 시도의 기록까지 함께 사라진다 → [[transaction]]

**MANDATORY 는 「나는 경계를 긋지 않는다」는 선언이다.** DAO 나 내부 헬퍼가 반드시 서비스 안에서 불려야 한다면 이 정책이 그 규칙을 강제한다 — 혼자 불리면 예외로 알려 준다 → [[service-layer]]

## 경계와 오해

- **전파는 프록시를 지날 때만 적용된다** — 같은 클래스 안에서 `this.method()` 로 부르면 프록시를 안 지나므로 **전파 정책이 아예 평가되지 않는다.** `REQUIRES_NEW` 를 붙였는데 새 트랜잭션이 안 열리는 사고의 대부분이 이것이다 → [[declarative-transaction]] · [[dynamic-proxy]]
- **REQUIRES_NEW 는 커넥션을 하나 더 쓴다** — 바깥 트랜잭션을 붙들어 둔 채 새 커넥션을 얻으므로, 요청 하나가 커넥션 둘을 점유한다. 풀이 작으면 **서로가 서로를 기다려 교착**이 될 수 있다 → [[connection-pool-sizing-formula]]
- **안쪽에서 난 예외는 REQUIRED 에서 바깥까지 되돌린다** — 안쪽을 `try-catch` 로 삼켜도 트랜잭션은 이미 「롤백 표시」가 된 상태라, 바깥이 커밋하려 할 때 실패한다. **잡았는데 왜 롤백되나**의 답이 여기 있다 → [[exception-handling]]
- **필기의 진술 중 셋이 뒤집혀 있다** — MANDATORY·SUPPORTS 설명의 「없으면 예외를 발생시키고 **없으면** 트랜잭션을 하나 만든다」는 뒤쪽이 「있으면」이어야 하고, SUPPORTS 도 마찬가지다. 표는 맞고 아래 문장이 어긋난 자리라 **표를 기준으로 읽어야 한다**
- **전파는 격리 수준과 다른 축이다** — 전파는 「트랜잭션을 몇 개 여는가」, 격리는 「다른 트랜잭션의 변경이 얼마나 보이는가」다. `@Transactional` 의 속성으로 나란히 있어 섞이기 쉽다
- **파일 삭제 같은 외부 작업은 전파에 안 들어온다** — 이 회차가 푸는 문제(사진 교체 시 예전 파일 지우기)에서 **스토리지 호출은 어떤 정책으로도 롤백되지 않는다.** 전파는 DB 커넥션의 이야기다 → [[object-storage]]
