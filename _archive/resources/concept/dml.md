# DML (Data Manipulation Language)

**틀이 아니라 그 안에 든 값을 다루는 SQL 부류.** Day52 의 한 줄이 「데이터의 등록, 변경, 삭제를 다루는 SQL문법」이고, 문장은 셋(`insert`·`update`·`delete`)이다. [[ddl]] 이 만든 컬럼 타입·`not null`·기본키·유니크가 **실제로 값을 막는지는 이 세 문장을 쳐 봐야 드러난다** — 하루 전 Day51 이 틀을 만들었고 이 회차가 그 틀에 값을 넣는다.

## 정의

세 문장을 가르는 축은 **대상이 새 행인가 이미 있는 행인가**, 그리고 **`where` 를 갖는가**다.

| 문장 | 대상 | `where` | `where` 를 빼면 |
|---|---|---|---|
| `insert` | 새 행 | **없다** (자리 자체가 없다) | — |
| `update` | 이미 있는 행의 컬럼 값 | 있다 | **모든 행**의 값이 바뀐다 |
| `delete` | 이미 있는 행 | 있다 | **모든 행**이 지워진다 |

**`insert` 에만 `where` 가 없다**는 것이 세 문장의 성격을 갈라 준다. 등록은 「어느 행에」를 고를 필요가 없고, 변경·삭제는 고르지 않으면 **전부가 대상**이 된다.

### 등록 — 두 가지 문법

```sql
// 테이블명만 명시
insert into 테이블명 values(값1, 값2, ....)

// 테이블명(컬럼명) 명시
insert into 테이블명(컬럼,컬럼,....) values(값,값,...)
```

Day52 가 둘의 차이를 정확히 적었다 — 앞은 「컬럼의 순서에 맞춰 명시」해야 하고, 뒤는 「컬럼과 값의 쌍을 순서와 상관없이 대입 가능」하다. **컬럼 이름을 적는 것은 타이핑을 늘리는 대신 순서 의존을 없애는 거래**다(아래 「경계와 오해」).

값 묶음을 콤마로 이어 붙이면 한 문장으로 여러 행이 들어간다.

```sql
insert into 테이블명(컬럼명, 컬럼명,....) values
  (값,값,.....),
  (값,값,.....),
  (값,값,.....);
```

그리고 값 자리에 **다른 조회 결과**를 놓을 수 있다.

```sql
insert into 테이블명(컬럼,컬럼)
  select 컬럼, 컬럼 from 테이블명 where 조건;
```

Day52 의 두 줄이 이 문법의 규칙이다 — 「select 결과의 컬럼명과 insert 테이블의 컬럼명이 같을 필요는 없다」·「결과의 컬럼 타입과 insert 하려는 컬럼의 타입이 같거나 입력 할 수 있는 타입이어야 한다」. **이름이 아니라 순서와 타입으로 대응한다**는 뜻이고, 한 문장 안에서 [[dql]] 과 DML 이 만나는 자리다.

### 변경과 삭제 — `where` 하나가 범위를 정한다

```sql
update 테이블명 set 컬럼명=값, 컬럼명=값,......where 조건;
update 테이블명 set 컬러명=값,......;

delete from 테이블명 where 조건;
delete from 테이블명;
```

**두 문장을 각각 두 줄로 나란히 적어 둔 것이 이 절의 핵심**이다 — 위는 고른 행, 아래는 전부다. Day52 가 각각에 「조건을 입력하지 않으면 전체 테이블에 대한 값을 수정한다」·「조건을 입력하지 않으면 전체 테이블을 삭제한다」로 주의를 달았다(뒤 문장의 「테이블을 삭제」는 아래에서 바로잡는다).

## 사용 예시

Day52 의 날짜 절에 이 세 문장이 실제 값과 함께 나온다 — DML 이 [[sql-data-type]] 의 검사를 받는 모양이다.

```sql
insert into test1 (title, regdt) values('aaaa', '2022-11-22');

  /* 다음 형식의 문자열을 날짜 값으로 지정할 수 없다.*/
insert into test1 (title, regdt) values('bbbb', '11/22/2022');

/* 특정 형식으로 입력된 날짜를 date 타입의 컬럼 값으로 변환하면 입력할 수 있다.*/
insert into test1 (title, regdt) values('bbbb', str_to_date('11/22/2022', '%m/%d/%Y'));
```

**같은 값을 세 번 넣으려는데 한 번은 거절된다.** 컬럼 이름을 적었고 개수도 맞는데 **값의 표기가 타입과 맞지 않아서** 막히는 것이라, DML 의 성공 여부가 문장의 모양만으로 정해지지 않는다는 것을 보여 준다 → [[sql-date-function]]

## 왜 중요한가

**되돌릴 수 없는 명령이 여기서 처음 나온다.** [[dql]] 은 몇 번을 실행해도 데이터가 그대로지만 `update`·`delete` 는 한 번 실행되면 이전 값이 없다. 그래서 이 회차가 세 문장을 배운 직후 `autocommit` 으로 넘어가는 것이 순서상 필연이다 — **`where` 를 빼먹은 `delete` 를 구제할 수 있는지가 그 설정 하나에 걸려 있다** → [[transaction]]

**실수가 오류로 나타나지 않는다.** 컬럼 이름을 틀리면 즉시 거절되지만, `where` 를 빠뜨린 `update` 는 **정상 성공**으로 돌아온다(`Rows matched: 1000  Changed: 1000`). 문법 오류는 컴파일러가 잡아 주던 자바의 경험이 여기서 통하지 않는 자리이고, 성공 메시지의 **행 수**가 유일한 경고다.

**애플리케이션을 거치지 않고 데이터가 움직인다.** `insert ... select` 는 조회 결과를 서버 안에서 그대로 다른 테이블에 넣는다. 자바로 하면 「전부 select → 객체로 받기 → 루프 돌며 insert」의 세 단계이고 행마다 네트워크 왕복이 생기는데, 이 문장은 **한 번의 왕복**이다 → [[client-server-model]]

## 경계와 오해

- **DML ≠ DNL — Day52 는 노트 제목·목차·소제목 세 곳에서 `DNL` 이라 적었다** — `Data Manipulation Language` 의 약어는 **DML** 이다. SQL 의 부류는 앞 글자만 바뀌는 네 개(`DDL`·`DML`·`DQL`·`DCL`)라서 소리로 외우면 가운데 글자가 흔들린다. 네 개를 한 줄로 세워 두면 겹치지 않는다.

  | 약어 | 무엇을 다루나 | 문장 | 이 필기에서 |
  |---|---|---|---|
  | DDL | 구조(테이블·인덱스) | `create`·`alter`·`drop` | Day51 → [[ddl]] |
  | **DML** | 값의 등록·변경·삭제 | `insert`·`update`·`delete` | Day52 = 이 노트 |
  | DQL | 값의 조회 | `select` | Day52 → [[dql]] |
  | DCL | 권한 | `grant`·`revoke` | Day51 → [[database-user]] |

  분류에 따라 `select` 를 DML 에 포함시키기도 한다(그때는 DQL 을 따로 두지 않는다). Day52 가 둘을 나란히 나눈 것은 **읽기만 하는 문장과 데이터를 바꾸는 문장을 가른 것**이고, 그 경계가 [[transaction]]·권한·복제에서 실제로 다르게 취급되므로 유용한 구분이다.
- **`delete from 테이블명;` 은 테이블을 삭제하지 않는다** — Day52 의 「조건을 입력하지 않으면 전체 테이블을 삭제한다」에서 지워지는 것은 **모든 행**이고 테이블 정의는 그대로 남는다. 바로 다음 `insert` 가 정상 동작한다는 것이 그 증거다. 「전부 비우기」에 쓰는 문장이 셋이고 성격이 다 다르다.

  | 문장 | 남는 것 | 되돌리기 | 자동 증가 카운터 |
  |---|---|---|---|
  | `delete from t` | 테이블 정의 | **`rollback` 가능** (DML) | 그대로 유지 |
  | `truncate table t` | 테이블 정의 | 불가 (DDL 취급·암시적 커밋) | **1 로 초기화** |
  | `drop table t` | 아무것도 | 불가 | — |

  → [[ddl]] · [[transaction]] · [[surrogate-key]]
- **`update`·`delete` 에서 `where` 를 빼먹는 것은 문법 오류가 아니다** — 두 문장 모두 `where` 없는 형태가 **정당한 문법**이라 서버가 되묻지 않는다. `mysql` 클라이언트를 `--safe-updates`(= `sql_safe_updates`) 로 띄우면 **키를 쓰지 않는 `update`/`delete` 를 거절**해 이 사고를 막지만 기본값은 꺼져 있다. 「위험한 명령은 확인을 받는다」는 감각이 CLI 에는 없다 → [[cli]]
- **`update` 가 0행을 고쳐도 성공이다** — `where` 가 아무 행도 못 잡으면 오류가 아니라 `Query OK, 0 rows affected` 다. 「고쳐졌는가」는 예외가 아니라 **영향받은 행 수**로 판정해야 하고, 이것이 자바 쪽에서 `delete` 의 반환값으로 「지웠나 못 지웠나」를 알려 주던 자리와 정확히 같은 문제다 → [[crud]] · [[method]]
- **`not null` 컬럼을 「반드시 명시해야」 하는 것은 아니다** — Day52 의 「not null은 반드시 명시해야한다」는 하루 전 Day51 의 같은 문장이 반쪽이었던 것과 이어진다. 정확히는 **「값이 정해지지 않은 채 남을 수 없다」**이고, `default` 나 `auto_increment` 가 붙은 `not null` 컬럼은 생략해도 채워진다 → [[sql-null]] · [[surrogate-key]]
- **컬럼 목록을 생략한 `insert` 는 컬럼 순서에 묶인다** — `insert into t values(...)` 는 `desc t` 가 보여 주는 **현재의 순서**에 의존한다. `alter table ... add column` 한 번으로 개수가 어긋나 전부 실패하고, 더 나쁜 경우 **타입이 우연히 맞으면 다른 컬럼에 조용히 들어간다.** Day52 가 「테이블명만 명시」를 먼저 적었지만 실무의 기본형은 컬럼을 적는 쪽이다 → [[ddl]]
- **`insert ... select` 의 「컬럼명이 같을 필요 없다」는 편의와 위험이 한 몸이다** — 이름이 아니라 **위치**로 대응하므로, `(name, tel)` 를 `(tel, name)` 순서로 적어도 **둘 다 `varchar` 면 오류 없이 뒤바뀐 채 저장된다.** 컴파일러가 타입으로 잡아 주던 [[parameter-and-argument]] 의 순서 실수가, 여기서는 **같은 타입인 한 아무도 잡아 주지 않는다.**
- **`delete` 절의 소제목 「데이터 값 변경하기」는 `update` 에서 복사돼 왔다** — 삭제를 설명하는 절의 첫 줄이라 「기능」 줄과 어긋난다. 형식만 고치는 원칙이라 본문은 그대로 두었다. 세 절(`insert`·`update`·`delete`)이 같은 골격으로 적혀 있어서 생긴 복사이고, [[crud]] 에서 골격을 복사할 때 이름 오타가 함께 복사됐던 것과 같은 종류다.
- **한 문장에 여러 행을 넣는 것은 「빠른 반복」이 아니라 「하나의 문장」이다** — 값 묶음을 100개 이어 붙인 `insert` 는 100번의 `insert` 와 다르다. 한 문장이므로 **하나라도 제약을 어기면 전부 들어가지 않고**(자동 커밋 상태에서도 문장 단위가 원자적이다), 그래서 부분 성공이 없다 → [[transaction]]
- **DML 은 롤백되지만 DDL 은 안 된다** — 이 세 문장은 `rollback` 으로 되돌아가는데, 중간에 `create`·`alter`·`drop` 이 섞이면 **암시적 커밋**이 일어나 앞의 DML 까지 확정된다. 「실수하면 되돌리면 된다」가 성립하는 범위가 DML 로 한정된다 → [[ddl]] · [[transaction]]
- **`insert` 는 데이터만 쓰는 것이 아니다** — 걸어 둔 [[primary-key]]·[[unique-key]]·[[database-index]] 를 함께 갱신하고 유일성을 검사한다. 인덱스가 다섯이면 한 행을 넣는 일이 여섯 곳을 고치는 일이 된다 — **등록이 느려지는 이유가 등록 문장에 없는 자리**다 → [[database-index]]

## 함께 보는 개념

- [[dql]] — 같은 회차의 짝. `insert ... select` 로 한 문장 안에서 만난다
- [[ddl]] — 이 문장들이 시험하는 틀을 만든 부류
- [[transaction]] — `where` 를 빼먹은 뒤에 남는 유일한 수단
- [[crud]] — 자바 배열로 만들었던 다섯 연산이 이 문장들로 옮겨 온다
- [[sql-null]] — `not null`·`default` 가 `insert` 를 거절하거나 채우는 자리
- [[sql-data-type]] — 값의 표기가 타입에 걸리는 자리
- [[primary-key]] · [[unique-key]] — `insert` 가 거절되는 두 번째 이유
- [[database-index]] — 등록·변경·삭제가 함께 고치게 되는 파생 구조
- [[sql-date-function]] — 날짜 값을 `insert` 에 넣기 위한 변환
- [[database-user]] — 이 문장들을 실행할 권한이 갈리는 자리
- [[client-server-model]] — 행마다 왕복하는 것과 한 문장으로 보내는 것의 차이
