# 응용계층 (프로토콜과 포트의 짝)

**사람이 쓰는 서비스가 사는 층.** 아래층들이 「어디로, 온전하게」를 다 풀어 놓았고, 여기서는 **무슨 대화를 할 것인가**만 남는다 → [[transport-layer]]

## 정의

**클라이언트**(요청하는 쪽)와 **서버**(제공하는 쪽)가 **정해진 프로토콜**을 지켜야 통한다 → [[client-server-model]] · [[network-protocol]]

| 프로토콜 | 하는 일 | 포트 |
|---|---|---|
| **HTTP** | 웹사이트 접속 | 80 → [[http-message]] |
| **DNS** | 도메인 ↔ IP 변환 | 53 → [[domain-name-system]] |
| **FTP** | 파일 전송 | 20(데이터) · 21(제어) |
| **SMTP** | 이메일 **송신** | 25 |
| **POP3** | 이메일 **수신** | 110 |

**포트 번호가 프로토콜과 짝을 이룬다** — 「80번으로 온 것은 HTTP 로 해석한다」는 약속이다 → [[port-number]]

### DHCP — 주소를 자동으로 받는다

```
1. 컴퓨터가 DHCP 서버를 찾는다
2. 서버가 할당 여부를 묻는다
3. 컴퓨터가 필요하다고 요청한다
4. 서버가 IP 주소를 할당한다
```

**IP 주소를 사람이 안 적어도 되는 이유**가 이것이다 → [[ip-address]]

### 메일 — 세 구간, 두 프로토콜

```
송신자 ──SMTP(25)──▶ 메일서버 A ──SMTP(25)──▶ 메일서버 B ◀──POP3(110)── 수신자
        보내기                   서버끼리 전달                 가져오기
```

- **보내는 쪽은 SMTP, 받는 쪽은 POP3** — 방향마다 프로토콜이 다르다
- 서버끼리 전달할 때 **DNS 의 MX 레코드**로 상대 메일 서버를 찾는다
- SMTP 는 단계마다 **응답 코드(220·250 등)를 주고받는** 대화형이다 — 「SMTP Handshake」
- POP3 는 **받아서 서버에서 지우고**, IMAP(143)은 **서버에 두고 동기화**한다
- 실제로는 암호화 포트(POP3S 995 · IMAPS 993 · Submission 587)를 더 쓴다

## 왜 중요한가

**프로토콜을 배운다는 것은 「무엇을 어떤 순서로 말할지」를 배우는 것이다.** SMTP 의 여섯 단계(인사 → 내 정보 → 보내는 사람 → 받는 사람 → 본문 → 종료)가 그 전형이고, HTTP 도 같은 종류의 약속이다 → [[network-protocol]]

**그리고 이 층의 프로토콜들은 대개 텍스트다.** 사람이 읽을 수 있게 만들어져 있어서 **눈으로 디버깅할 수 있다** — 그것이 이 층을 배우기 쉽게 만든 설계 선택이다.

## 경계와 오해

- **DNS 는 응용계층인데 다른 통신의 준비 단계다** — HTTP 요청을 보내기 전에 이미 DNS 질의가 끝나 있어야 한다. **계층이 순서를 뜻하지는 않는다** → [[domain-name-system]]
- **POP3 를 쓰면 다른 기기에서 못 본다** — 받아 가면서 서버에서 지우기 때문이다. 여러 기기로 메일을 보는 요즘 환경에서 **IMAP 이 기본이 된 이유**다
- **25번 포트는 요즘 막혀 있는 경우가 많다** — 스팸 때문에 ISP 가 차단하므로, 실제 발송은 **587(Submission)** 을 쓴다. 필기가 그것을 함께 적었다
- **암호화되지 않은 프로토콜이 여전히 표에 있다** — Telnet·FTP·POP3 는 **평문**이라 지금은 각각 SSH·SFTP·POP3S 로 대체됐다 → [[jwt]] 의 「탈취되면 끝」과 같은 이유다
- **DHCP 로 받은 주소는 바뀐다** — 임대 기간이 있으므로 **서버에 고정 주소를 줄 때는 DHCP 를 쓰지 않는다** → [[ip-address]]
- **응용계층 로드밸런서는 내용을 본다** — URL·헤더·쿠키를 보고 나눌 수 있어 `/images/*` 와 `/api/*` 를 다른 서버로 보낸다. 그만큼 **느리고 비싸다** → [[load-balancer]] · [[reverse-proxy]]

## 출처

- [[2024-10-31-chapter7-application]] — 「응용계층의 역할」이 클라이언트·서버를 정의하고 **프로토콜-포트 표**로 이 층의 지도를 그린다. 「DHCP서버」 절이 IP 자동 할당을 **네 걸음의 대화**로 적고, 「SMTP와 POP3 프로토콜」 절이 메일을 **세 구간**(송신자→메일서버 / 서버끼리 / 메일서버→수신자)으로 나눠 각각의 절차와 포트를 보인다 — 특히 **각 단계마다 응답 코드를 주고받는다**는 것과 **MX 레코드로 상대 서버를 찾는다**는 보충, 그리고 **POP3 는 받고 지우고 IMAP 은 보관·동기화**한다는 구별이 실전 지식이다. 마지막의 「응용 계층에서 사용하는 로드밸런서」가 URL·콘텐츠 기반 분배와 **SSL 종료·DDoS 방어**를 들고, 장단점으로 「더 세밀한 라우팅 / L4보다 느리고 비쌈」을 적어 **4계층 로드밸런서와의 맞바꿈**을 분명히 했다 → [[load-balancer]]
