# 단축 평가 (Short-circuit Evaluation)

`&&` 와 `||` 는 **앞의 값만으로 결과가 정해지면 뒤를 계산하지 않는다.** 한 글자짜리 `&`·`|` 는 항상 양쪽 다 계산한다.

## 정의

논리 연산자는 네 가지다.

| 연산자 | 이름 | 결과가 `true` 인 경우 |
|---|---|---|
| `&&` | AND | 두 값이 모두 `true` |
| `\|\|` | OR | 한 개라도 `true` |
| `!` | NOT | 값을 뒤집는다 |
| `^` | XOR (배타적 비교) | **두 값이 다를 때** |

여기서 `&&`·`||` 와 `&`·`|` 가 갈린다.

| | 두 글자 (`&&` `\|\|`) | 한 글자 (`&` `\|`) |
|---|---|---|
| 대상 | 논리값 | 논리값 **과 비트값** → [[bitwise-operator]] |
| 뒤쪽 평가 | **앞 값에 따라 건너뛴다** | 항상 평가한다 |

## 사용 예시

뒤쪽에 값을 바꾸는 코드를 두면 차이가 드러난다.

```java
boolean a = true;
boolean b = false;

boolean r = a || (b = true);
// a=true, b=false, r=true
//   → a 가 true 라 결과가 정해졌으므로 (b = true) 를 실행하지 않았다

a = true;
b = false;
r = a | (b = true);
// a=true, b=true, r=true
//   → 한 글자는 뒤쪽도 실행하므로 b 가 바뀌었다
```

`&` 는 논리값과 비트값 양쪽에 쓰인다.

```java
int a = 8;    // 0b0000 1000
int b = 5;    // 0b0000 0101

System.out.println(a | b);              // 비트 연산 → 13
System.out.println(a == 8 && b == 5);   // 논리 연산 → true
System.out.println(false & true);       // 논리 연산 → false
```

## 왜 중요한가

**단축 평가가 안전 장치로 쓰인다.** 앞 조건이 거짓이면 뒤를 실행하지 않으므로, 뒤쪽에 위험한 코드를 두고 앞에서 막는 방식이 성립한다.

```java
if (arr != null && arr.length > 0) { ... }
```

`&&` 이므로 `arr` 이 `null` 이면 `arr.length` 를 아예 평가하지 않는다. 여기서 `&` 를 쓰면 양쪽을 다 계산해 예외가 난다. **한 글자와 두 글자의 차이가 동작하는 코드와 터지는 코드를 가른다.**

## 경계와 오해

- **`&` 와 `&&` 는 "같은데 하나는 비트용"이 아니다** — 논리값에도 둘 다 쓸 수 있고, 그때 결과값은 같지만 **뒤쪽을 실행하는지가 다르다.** 결과만 보면 차이가 안 보여서 놓치기 쉽다.
- **뒤쪽에 부수효과를 두면 안 된다** — 조건식 안에서 값을 바꾸거나 메서드를 부르면, 실행될지가 앞 조건에 달린다. 위 예시가 그것을 보여주는 것이고, 실무에서는 그런 코드를 쓰지 않는 쪽이 맞다.
- **`^` 는 "다르면 참"이다** — OR 계열로 보이지만 배타적 비교다. `true ^ true` 는 `false` 다.
- **단축 평가에 대응하는 `^` 는 없다** — XOR 는 양쪽을 봐야 결과가 정해지므로 건너뛸 수 없다.
