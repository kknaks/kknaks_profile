# 스테이트리스 프로토콜 (Stateless Protocol)

스테이트리스 프로토콜은 클라이언트와 서버 사이에 연결 상태(세션)를 유지하지 않고, 각 요청이 처리에 필요한 정보를 스스로 담아 독립적으로 처리되는 프로토콜이다. 반대는 세션을 만들어 그 위에서 요청을 이어 처리하는 스테이트풀(세션 기반) 프로토콜이다.

## 정의

1. 클라이언트가 서버에 처음 연결할 때 별도의 초기화 과정을 거치더라도, 그 결과를 서버가 세션으로 유지하지 않는다.
2. 각 요청은 처리에 필요한 컨텍스트(인증 정보, 이전 상태 등)를 요청 자체에 담아 보낸다.
3. 서버는 요청을 처리한 뒤 아무 상태도 남기지 않으므로, 같은 클라이언트의 다음 요청을 반드시 같은 서버가 처리할 필요가 없다.

## 사용 예시

MCP(Model Context Protocol)의 2026-07-28 신규 스펙이 이 전환의 실제 사례다. 기존 MCP는 클라이언트-서버가 `initialize` 과정을 거쳐 세션을 맺고, 그 세션 위에서 툴 목록 조회·툴 실행 요청을 처리하는 세션 중심 구조였다. 신규 스펙은 이 초기화·세션 개념을 단순화해, 각 요청이 필요한 정보를 스스로 담아 독립적으로 서버에 전달되는 스테이트리스 구조로 바꿨다.

## 왜 중요한가

서버가 특정 클라이언트의 세션을 계속 들고 있어야 한다면, 그 세션을 처음 만든 서버가 이후 요청도 계속 처리해야 한다(서버 어피니티). 여러 서버로 부하를 분산하는 로드밸런싱 환경에서는 이것이 서버 확장을 어렵게 만든다. 요청이 스스로 상태를 담아 독립적으로 처리되면 어떤 서버가 요청을 받아도 무방해지므로, 서버를 여러 대로 늘리는 확장이 훨씬 쉬워진다. MCP가 로컬 환경을 넘어 원격·클라우드 환경에서 여러 서버로 요청을 분산해야 하는 상황에 놓이면서 이 전환이 필요해졌다.

## 경계와 오해

- **스테이트리스 ≠ 상태가 아예 없음** — 서버가 상태를 다루지 않는다는 뜻이 아니라, 그 상태를 서버가 세션으로 "들고 있지" 않는다는 뜻이다. 상태는 요청 자체(토큰, 파라미터 등)나 외부 저장소로 옮겨간다.
- **[[http-session]]과의 관계** — HttpSession은 스테이트풀 방식의 대표 구현체(서버가 세션 객체를 들고 있음)다. 스테이트리스 전환은 이런 서버 측 세션 보관을 없애는 방향이다.
- **[[distributed-session]]과의 차이** — 분산 환경에서 세션을 유지하되 외부 저장소(Redis 등)로 공유하는 것은 스테이트풀을 유지한 채 확장 문제를 우회하는 절충안이다. 스테이트리스 전환은 세션 자체를 없애는 더 근본적인 방향이다.
