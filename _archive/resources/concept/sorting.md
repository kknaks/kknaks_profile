# 정렬과 비교 함수

**순서를 만드는 것.** 정렬 자체는 라이브러리가 해 주므로, 실제로 정하는 것은 **「무엇을 먼저 둘 것인가」**뿐이다.

## 정의

```cpp
sort(v.begin(), v.end());              // 기본 오름차순
sort(s.begin(), s.end());              // 문자열도 문자 단위로
sort(v.begin(), v.end(), cmp);         // 비교 함수로 순서를 정한다
```

비교 함수는 **「a 가 b 보다 앞이면 true」**를 돌려준다.

```cpp
bool cmp(const P& a, const P& b) {
    if (a.count != b.count) return a.count > b.count;   // 1순위: 많이 나온 것 먼저
    return a.first_idx < b.first_idx;                    // 2순위: 먼저 나온 것 먼저
}
```

**1순위가 같을 때 무엇을 볼지**를 정하는 것이 다중 기준 정렬이고, 빈도 정렬 문제가 정확히 그 모양이다.

### 정렬이 전처리가 되는 자리

정렬 자체가 답인 경우는 드물다. **뒤에 올 것을 쉽게 만들려고** 한다.

| 정렬한 뒤 | 무엇이 쉬워지나 |
|---|---|
| 끝나는 시간 순 | 앞에서부터 고르면 최적 → [[greedy-algorithm]] |
| 글자 순 | 같은 글자가 붙어 있어 짝짓기가 쉽다 → [[stack]] |
| 빈도 순 | 그대로 출력이 답 |

## 왜 중요한가

**「정렬하면 쉬워지나?」가 풀이의 첫 질문 중 하나다.** 무질서한 입력에서 규칙을 찾기는 어렵지만, **순서가 생기면 앞에서부터 한 번 훑는 것으로 끝나는** 문제가 많다.

**그리고 비교 함수가 곧 문제 이해다.** 그리디에서 기준을 잘못 잡으면 틀리는 것처럼, **무엇을 앞에 둘지가 답을 바꾼다** → [[greedy-algorithm]]

## 경계와 오해

- **비교 함수는 「같으면 false」여야 한다** — `>=` 를 쓰면 같은 값에서 「a 도 앞, b 도 앞」이 되어 **정렬이 깨지거나 프로그램이 죽는다.** 엄격한 부등호를 쓴다
- **정렬은 안정적이지 않을 수 있다** — 같은 값의 원래 순서가 유지된다는 보장이 없으므로, **먼저 나온 것을 앞에 두려면 인덱스를 2순위로 명시**해야 한다. 빈도 정렬이 그렇게 한다
- **정렬 비용이 전체 복잡도를 정할 때가 많다** — O(n log n) 이 그 뒤의 O(n) 순회보다 크므로 **정렬이 곧 상한**이다 → [[time-complexity]]
- **정렬해서 잃는 정보가 있다** — 원래 순서가 필요하면 **인덱스를 함께 들고** 정렬해야 한다. 값만 정렬하면 「몇 번째였는지」가 사라진다
- **문자열 정렬은 사전순이지 의미순이 아니다** — `"10"` 이 `"9"` 보다 앞에 온다. 숫자로 비교하려면 **먼저 숫자로 바꿔야** 한다 → [[number-parsing]]
