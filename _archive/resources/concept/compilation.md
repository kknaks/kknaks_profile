# 컴파일 (Compilation)

사람이 쓴 명령문을 컴퓨터가 실행할 수 있는 코드로 변환하는 것. 그 일을 하는 프로그램을 컴파일러라 한다.

## 정의

애플리케이션이 만들어져 돌기까지 세 단계다.

1. **명령문을 작성** — 사람이 읽고 쓰는 언어로 코드를 쓴다
2. **컴파일** — 컴파일러가 실행 가능한 코드로 변환한다
3. **실행** — OS 위에서 그 결과물이 돈다

즉 우리가 쓴 코드가 그대로 도는 것이 아니다. **중간에 번역이 한 번 들어가고, 실행되는 것은 번역 결과물**이다.

2번은 다시 두 단계로 나뉜다.

1. **컴파일** — 소스를 **오브젝트 파일**로 변환한다
2. **링크** — 오브젝트 파일들을 묶어 **실행파일**로 만든다

이 방식을 쓰는 대표 언어가 C·C++ 다. 실행 전에 전부 변환하는 쪽이라, 한 줄씩 변환하며 실행하는 [[interpreter]] 와 갈린다.

## 왜 중요한가

컴파일 단계가 있다는 것 자체가 두 가지를 만든다.

**첫째, 실행 전에 틀린 것을 잡을 수 있다.** 번역하는 시점에 코드를 전부 훑으므로, 문법이 어긋나거나 타입이 맞지 않으면 실행하기 전에 걸러진다. 오류가 있으면 **컴파일이 중단되어 실행파일이 아예 생기지 않는다** — 틀린 프로그램을 실행할 기회 자체가 없다. 컴파일 에러가 실행 에러보다 값싼 이유가 이것이다.

**둘째, 번역 결과물이 특정 환경에 묶인다.** 변환된 코드는 어떤 CPU 와 어떤 OS 를 향해 만들어진 것이므로 다른 환경으로 그대로 옮길 수 없다. → [[platform-dependency]]

## 경계와 오해

- **컴파일 ≠ 실행** — 변환과 실행은 다른 시점의 일이다. 컴파일이 성공했다는 것은 번역이 됐다는 뜻일 뿐, 의도대로 동작한다는 보장이 아니다.
- **컴파일 결과물이 곧 기계어인 것만은 아니다** — 언어에 따라 CPU 기계어까지 가는 것도 있고, 중간 형태까지만 만들고 실행 시점에 다시 변환하는 것도 있다. Java 가 그렇다 → [[bytecode]]
- **컴파일 ≠ 링크** — 컴파일이 끝나도 아직 실행파일이 아니다. 오브젝트 파일을 묶는 링크가 남아 있어서, 컴파일은 통과하고 링크에서 실패하는 경우가 따로 있다.
