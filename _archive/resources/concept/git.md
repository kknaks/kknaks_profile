# Git

변경에 구분번호(식별자)를 부여해 버전을 관리하는 소프트웨어 형상관리시스템(S/W Configuration Management System).

## 정의

Git 이 하는 일은 **변경을 하나씩 식별 가능한 단위로 만드는 것**이다. 파일을 덮어쓰며 최신 상태만 남기는 대신, 변경마다 식별자를 붙여 어느 시점으로도 되돌아갈 수 있게 한다.

작업은 세 자리를 오간다.

| 자리 | 무엇이 있나 | 옮기는 명령 |
|---|---|---|
| 작업 디렉토리 | 지금 편집 중인 파일 | — |
| [[staging-area]] | 이번 버전에 담을 것으로 등록한 목록 | `git add` |
| 로컬 저장소 | 식별자가 붙어 보관된 버전 | `git commit` |
| [[remote-repository]] | 호스팅서버에 올라간 저장소 | `git push` · `git pull` |

`git add` → `git commit` → `git push` 순으로 진행하면 로컬의 변경이 서버에 올라간다.

## 사용 예시

부트캠프 실습에서 쓴 최소 흐름이다.

```bash
$git add .                              # 백업파일목록에 등록
$git commit -m "변경내용(메세지)"        # 등록된 파일을 저장소에 보관
$git push                               # 호스팅서버 저장소에 업로드
```

커밋하려면 누가 한 변경인지 먼저 정해 둬야 한다.

```bash
$git config --global user.name "Your Name"
$git config --global user.email "Your E-mail"
```

## 왜 중요한가

**되돌릴 수 있으면 과감하게 고칠 수 있다.** 버전관리가 없으면 고치기 전 상태를 잃는 것이 두려워 코드를 만지지 못하고, 그래서 파일을 `최종_final_v2` 로 복사해 두는 방식으로 흐른다. 식별자가 붙은 버전이 남으면 그 두려움이 없어진다.

그리고 변경이 식별 단위로 남는다는 것은 **누가 언제 무엇을 왜 바꿨는지가 기록된다**는 뜻이다. 협업에서 Git 이 필수인 이유는 파일 공유가 아니라 이 기록 쪽이다.

## 경계와 오해

- **Git ≠ GitHub** — Git 은 내 컴퓨터에서 도는 버전관리 프로그램이고, GitHub 은 그 저장소를 올려 두는 호스팅서버 중 하나다. Git 만으로도 버전관리는 완결된다. → [[remote-repository]]
- **`commit` ≠ 업로드** — 커밋은 **로컬** 저장소에 보관하는 것까지다. 서버에 올라가는 것은 `push` 다. 이 둘을 하나로 알면 "커밋했는데 왜 안 보이나"에서 막힌다.
- **버전관리 ≠ 백업** — 백업은 잃지 않기 위한 복사본이고, 버전관리는 **변경 이력을 식별하기 위한 것**이다. 옛 필기에 `git add` 를 "백업파일목록에 등록"이라 적어 두었는데, 실제로 등록되는 곳은 백업이 아니라 다음 커밋에 담길 목록([[staging-area]])이다.
