# 컴파일 단위 (Compilation Unit)

Java 에서 컴파일에 들어가는 단위는 소스 파일 하나이고, **나오는 단위는 클래스 하나**다. 소스 하나에 클래스가 셋 있으면 `.class` 파일 셋이 생긴다.

## 정의

[[compilation]] 이 산출물을 묶는 방식이 C 계열과 갈린다.

| | C | Java |
|---|---|---|
| 입력 | 여러 소스 파일 | 소스 파일 하나 |
| 중간 산출물 | 오브젝트 파일 | — |
| 최종 산출물 | 링커가 묶은 **실행파일 하나** | **클래스마다 `.class` 하나** |

C 는 여러 갈래를 하나로 모으고, Java 는 하나를 여러 갈래로 나눈다. Java 에 링크 단계가 따로 없는 것도 이 때문이다 — 묶지 않고 각 클래스를 그대로 두고, 필요할 때 [[classpath]] 에서 찾아 쓴다.

### 파일명과 `public` 은 일치해야 한다

**`public` 클래스의 이름은 파일명과 같아야 한다.** 규칙이고, 어기면 컴파일 오류다.

JVM 이 클래스를 이름으로 찾기 때문이다 → [[constant-pool]]. `Hello` 라는 클래스를 찾을 때 `Hello.class` 를 열면 된다는 보장이 이 규칙에서 나온다.

## 사용 예시

한 파일에 클래스 셋을 두고 컴파일하면 `.class` 가 셋 생긴다.

```java
class A {
}

class B {
}

class C {
}
```

`public` 이 없으므로 파일명은 무엇이든 된다. 반대로 `public class A` 로 바꾸면 파일명이 `A.java` 여야 한다.

## 왜 중요한가

**"파일 하나 = 클래스 하나"가 규칙이 아니라 관례라는 것을 여기서 가른다.** 문법상 한 파일에 여러 클래스를 둘 수 있고 컴파일도 된다. 그럼에도 하나씩 두는 것은 찾기 쉬워서다.

그리고 `.class` 가 클래스 단위로 흩어진다는 성질이 배포 방식을 정한다. 파일이 수백 개가 되므로 그것을 하나로 묶는 일이 따로 필요해지고, 그것을 하는 것이 [[build]] 도구다.

## 경계와 오해

- **컴파일 단위 ≠ 실행 단위** — 컴파일은 파일 단위로 하지만 실행은 [[main-method]] 가 있는 클래스에서 시작한다. 둘은 다른 축이다.
- **파일명 규칙은 `public` 에만 걸린다** — `public` 이 아닌 클래스는 파일명과 달라도 된다. 이 조건을 빼고 "파일명 = 클래스명"으로만 외우면 위 예시가 왜 컴파일되는지 설명하지 못한다.
- **Java 에 링커가 없는 것이 결합을 안 한다는 뜻은 아니다** — 연결은 실행 시점에 JVM 이 한다. 시점이 옮겨진 것이다.
