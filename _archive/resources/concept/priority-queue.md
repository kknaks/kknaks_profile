# 우선순위 큐 (Priority Queue)

**넣는 순서와 상관없이 「지금 가장 우선인 것」이 먼저 나오는 큐.** 넣고 빼는 것이 각각 O(log n) 이다.

## 정의

| | [[queue]] | 우선순위 큐 |
|---|---|---|
| 나오는 것 | **먼저 넣은 것** | **가장 우선인 것** |
| 넣기·빼기 | O(1) | **O(log n)** |
| 전체 정렬 | 아니다 | **아니다** — 최솟값만 안다 |

**전부 정렬하지 않고 최솟값만 알면 될 때** 쓴다 → [[sorting]]

### 넣었다가 빼는 그리디

순회 강연 문제가 이 자료구조를 왜 쓰는지 보여 준다.

```
날짜 순으로 강연을 본다
  → 일단 큐에 넣는다
  → 큐 크기가 남은 날짜를 넘으면 → 가장 싼 강연 하나를 뺀다
```

**「일단 넣고, 넘치면 가장 나쁜 것을 버린다」** — 매번 가장 싼 것을 찾아야 하는데, 전부 다시 정렬하면 O(n log n) 이 반복된다. 우선순위 큐는 그 한 번을 **O(log n)** 으로 만든다 → [[greedy-algorithm]]

## 왜 중요한가

**「최솟값을 계속 꺼내야 하는」 형태가 자주 나온다.** 그때마다 정렬하면 비싸고, 배열에서 찾으면 O(n) 이다. **한 값만 필요한데 전부 정렬하는 것은 낭비**라는 것이 이 자료구조의 존재 이유다 → [[time-complexity]]

**그리고 그리디의 「되돌리기」를 가능하게 한다.** 되돌아보지 않는 것이 그리디인데, 순회 강연처럼 **「넣은 것 중 하나를 취소」**해야 하는 형태에서는 무엇을 취소할지 빨리 찾아야 한다.

## 경계와 오해

- **전체가 정렬돼 있지 않다** — 꺼내는 순서만 보장되고, 안을 훑으면 뒤죽박죽이다. **순회하며 읽으면 안 된다**
- **기본이 최대 힙인지 최소 힙인지 언어마다 다르다** — C++ `priority_queue` 는 **최대 힙**이 기본이라, 최솟값을 원하면 비교자를 뒤집거나 값에 음수를 넣는다. 조용히 틀리는 자리다
- **정렬과 바꿔 쓸 수 있는 것이 아니다** — 전부를 순서대로 봐야 하면 정렬이 낫고, **한쪽 끝만 반복해서 필요하면** 우선순위 큐가 낫다
- **기준이 둘이면 비교자를 정해야 한다** — 먹방 문제가 「시간」과 「번호」 두 축을 보는 것처럼, **1순위가 같을 때**를 정해야 한다 → [[sorting]]
- **map·트리와 목적이 겹칠 수 있다** — 이 문제집이 「logN 이 걸리는 자료구조로 문제 해결(map, tree, 우선순위 큐)」이라 적은 대로, **O(log n) 이 필요하다**는 요구가 먼저이고 무엇을 쓸지는 그다음이다 → [[hash-based-collection]]
