# 네트워크 계층 (라우터와 라우팅)

**망 밖으로 나가는 길을 찾는 층.** 아래층은 같은 망 안에서만 지목할 수 있었고, 여기서 **다른 망까지 가는 경로**가 생긴다 → [[data-link-layer]]

## 정의

**스위치의 한계가 이 층이 존재하는 이유다** — 스위치는 같은 네트워크 안에서만 통신시킬 수 있다. 다른 네트워크로 가려면 **라우터**가 필요하다.

- **라우터** — 데이터가 **어떤 경로로 갈지** 정하는 장비 (내비게이션)
- **라우팅** — 최적 경로를 찾는 과정
- **라우팅 테이블** — 목적지까지의 **거리와 방법**을 적어 둔 표 → [[dispatch-table]]

```
A(172.168.1.3) → B(172.168.2.12) 로 보낼 때

1. A 가 스위치에 경로를 묻는다
2. 스위치는 자기 망 정보만 있으므로 라우터 A 에게 넘긴다 (네트워크 ID 172.168.2.0)
3. 라우터 A 가 라우팅 테이블에서 경로를 찾는다 (E1)
4. E1 로 라우터 B 에게 넘긴다
5. 라우터 B 가 스위치 B 를 거쳐 B 에 닿는다
```

**「네트워크 ID 로 찾는다」**는 것이 핵심이다 — 라우터는 컴퓨터 하나하나가 아니라 **망 단위로** 길을 안다 → [[ip-address]]

### 보내는 범위가 셋이다

| 방식 | 받는 쪽 |
|---|---|
| **유니캐스트** | 하나 — 상대를 알면 1:1 |
| **브로드캐스트** | 같은 네트워크의 **전부** |
| **멀티캐스트** | **특정 그룹**만 — 둘을 섞은 것 |

## 왜 중요한가

**인터넷이 성립하는 층이 여기다.** 세상의 모든 기계를 한 망에 넣을 수 없으므로 **망을 나누고 그 사이를 잇는다** — LAN 들을 이어 WAN 을 만든다는 구조가 이 층의 일이다 → [[computer-network]]

**그리고 「내 컴퓨터에서는 되는데」의 많은 부분이 여기서 갈린다.** 같은 망 안이면 스위치까지로 끝나고, 밖이면 라우터·방화벽·NAT 를 지나야 한다 — **코드는 같은데 경로가 다르다** → [[socket-binding]]

**주소가 두 겹이라는 것도 이 층에서 완성된다.** 프레임의 MAC 은 **다음 구간**을 가리키고, 패킷의 IP 는 **최종 목적지**를 가리킨다 → [[mac-address]]

## 경계와 오해

- **라우터는 최종 목적지까지의 길을 다 알지 않는다** — **다음에 누구에게 넘길지**만 안다. 그것이 반복돼 목적지에 닿는 구조라, 중간의 한 곳만 잘못돼도 끊긴다
- **브로드캐스트는 라우터를 넘지 못한다** — 그래서 [[mac-address]] 를 묻는 ARP 도 같은 망 안에서만 된다. 밖으로 나갈 때는 **라우터의 MAC** 으로 보낸다
- **「최적 경로」의 기준이 하나가 아니다** — 홉 수·대역폭·지연 중 무엇을 볼지가 라우팅 프로토콜마다 다르다. **가장 짧은 것이 가장 빠른 것은 아니다**
- **스위치와 라우터를 「같은 연결 장비」로 묶으면 안 된다** — 보는 주소가 다르다(MAC ↔ IP)이고, **경계를 만드는 쪽이 라우터**다. 충돌 도메인은 스위치가 나누고, 브로드캐스트 도메인은 라우터가 나눈다
- **사설 IP 는 「보안성이 좋다」기보다 「밖에서 못 닿는다」다** — 필기의 표현은 결과를 성질로 적은 것이다. 밖에서 접근하려면 NAT·포트포워딩이 필요하고, **그 순간 보호는 사라진다** → [[ip-address]]
