## 소개

개발 경력은 짧지만 밀도로 일해 왔습니다. 헬스케어 AI 스타트업에 백엔드로 입사해
4개월 만에 AX 리더를 맡았고, 그 전 회사에서는 실시간 시세 파이프라인을 6개월 무장애로
운영하며 고부하 조회 성능을 3.2배로 올렸습니다. 문제를 받은 대로 구현하기보다 원인을
분해해 구조로 풀고, 개선은 주장 대신 측정으로 증명합니다.

개인사업자로 제품 네 개를 기획부터 출시·운영까지 혼자 완주해 양대 앱스토어와 PyPI,
홈서버에서 운영 중입니다. AI 를 코드 생성 도구가 아니라 팀의 일하는 방식으로 설계하는
일을 회사와 개인 양쪽에서 하고 있습니다.

## 경력

### 메디솔브 AI — AX 리더 · 2026.06 – 현재

4인 팀에서 기술 전반을 맡아 회사의 AI 전환을 이끕니다.

- **사내 AX 워크스페이스(Mediness) 주도.** 흩어진 문서·회의·의사결정·업무를 한곳에
  모아, 개발자가 아닌 구성원도 AI 와 함께 일할 수 있게 하는 사내 제품입니다. 기능
  명세 60여 건·작업 100여 건을 문서로 먼저 확정하고 구현하는 방식으로, 백엔드부터
  MCP 서버·에이전트 데몬까지 아키텍처를 설계하고 직접 구현합니다.
- **AI 의 권한 경계 설계.** AI 에게 어디까지 맡기고 어디서 사람 승인을 받을지 기준을
  세웠습니다. 상태를 바꾸는 요청은 반드시 승인 화면을 거칩니다.
- **팀의 AI 개발 환경 구축.** 자동화 규칙·검사 장치를 세팅하고, 문서와 코드가
  어긋나면 걸러내는 정합 점검 절차를 운영합니다.

### 메디솔브 AI — 백엔드 개발자 · 2026.02 – 2026.06

의료 클리닉용 상담 자동화 제품 두 개의 백엔드를 맡았습니다.

- **Charty — 실시간 AI 진료 차트.** 의사가 상담하는 동안 음성이 실시간 전사·통역되고
  AI 가 구조화된 차트를 만들어 줍니다. 실시간 스트림과 LLM 이 동시에 도는 async
  파이프라인과 전사·번역 3단계 분리를 설계했고, 기능이 한 덩어리로 엉켜 수정 범위를
  알 수 없던 서버를 역할별로 나누고 테스트 137건을 붙여 고쳐도 안전한 구조로
  바꿨습니다.
- **Linky — 외국인 환자 다국어 상담 플랫폼.** 상담사가 텔레그램·왓츠앱 등 여섯
  메신저의 문의를 인박스 하나에서 처리하고, AI 가 번역·응답하다 위험한 대화만 사람에게
  넘깁니다. 수신·응답을 큐로 분리한 워커 상태 기계와 LLM 폴백을 설계했고, 실제 대화
  상황 9가지를 자동 검증하는 도구를 만들어 출시 점검을 통과시켰습니다. 환자 개인정보
  마스킹·암호화 규칙 정의에 참여했습니다.

### 퀀터스 — 백엔드 개발자 · 2025.08 – 2026.02

퀀트 트레이딩 앱. 트레이딩의 입력이 되는 데이터 파이프라인을 맡았습니다.

- **실시간 시세 파이프라인 — 6개월 무장애.** 대표 ETF 60종 시세를 웹소켓으로 수집해
  자동트레이딩 서버에 전달했습니다. 장 중에 공급이 끊기면 서버가 낡은 가격으로
  매매를 판단하게 됩니다. 하트비트 헬스체크에 서킷브레이커를 붙여 장애 시 10초
  폴링으로 자동 전환·복귀하게 하고, 전달은 RabbitMQ, 저장은 Redis master/slave 로
  안전장치를 겹쳤습니다. 실서비스 6개월, 장 중 데이터 공백 0회.
- **뉴스·공시 조회 성능 — 처리량 3.2배.** 사용자가 관심 종목 뉴스를 여는 화면이
  고부하에서 worker timeout 으로 무너졌습니다. 원인을 분해하니 인덱스 부재, 국가별
  중복 쿼리, 동기 블로킹이 겹쳐 있었습니다. 조회 표면을 MySQL 동기 접근에서
  Elasticsearch 비동기 검색으로 전환하고 호출을 3회→1회로 접었습니다. k6 실측:
  처리량 3.2배(RPS 25.7→81.2) · 평균 응답 68% 단축 · P95 57% 개선.
- **뉴스·공시 수집·AI 요약 파이프라인.** 한국·미국 뉴스·공시 하루 약 4천 건을
  Airflow 로 1시간 주기 수집하고, LangGraph 파이프라인이 종목 판별 → 요약 → 한↔영
  번역을 처리해 사용자가 원문 없이 요지를 읽게 했습니다.
- **800GB DB 무중단 이관.** 클라우드 계약 변경으로 AWS RDS → Azure MySQL 이관이
  필요했습니다. 세 방안을 중단 시간·손실·비용으로 비교해 DMS 를 선택했고, binlog
  CDC 실시간 복제를 걸어 두고 접속만 전환해 서비스를 세우지 않고 마쳤습니다.
