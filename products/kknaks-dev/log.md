된다. **그래도 SoT 가 둘이 되지는 않는다** — AI 가 내는 `summary` 와 본문은 조립되는 값이 아니라 **그대로 실린다.** career 는 **기존 frontmatter 를 그대로 이고 본문만 바꾼다**: 전문을 받으면 모델이 `bullets`·`period` 를 다시 쓰게 되지만, 본문만 얹으면 사람 전용 필드는 **건드릴 방법 자체가 없다** — **검증으로 막기 전에 구조로 막았다는 것이 요점이다.** 그래서 발주서 검증 항목이 "계획에 `bullets`·`period` 가 있으면 거부" 에서 **"필수 필드가 사라졌으면 거부"** 로 뒤집혔다(남긴 `PROTECTED_FIELD` 는 계획 조립 경로가 하나뿐이라고 가정하지 않기 위한 것 — 저장된 계획 재시도 경로가 있고 그 계획이 다른 코드로 만들어졌을 수 있다). **`daily` 의 `date` 는 점 표기다** — 로더가 파일명(하이픈)과 대조하고 어긋나면 파일 하나가 거부되는 데서 끝나지 않고 **persona 로드 전체**가 실패하며, `reload_data` 가 기존 데이터를 그대로 둬 사이트는 옛 데이터를 계속 서빙한다. 발행 뒤에야 알게 되는 실패라 표기를 바꾸는 자리에 못박고 테스트도 따로 태웠다. **그래프 검증 제외는 예외 처리가 아니라 사실의 반영이다** — daily·career 는 상류 참조가 없어 `up:` 을 갖지 않으므로 얹으면 L2(고아)에 걸려 발행이 막힌다. 즉 얹는 쪽이 사실과 다르다. 같은 발행에 섞인 `concept` 는 **그대로 검증을 받는다**(잔디가 만든 개념도 유튜브 것과 같은 계보 규율). 층 목록(`OUTSIDE_GRAPH`)을 `LAYER_PREFIX` 옆 `plan.py` 에 둔 것도 새 층을 넣을 때 한 곳만 보게 하기 위해서다. **보호 검증 둘의 자리가 다르다** — `USER_AUTHORED_DAILY` 는 접수가 한 번, 발행이 한 번 더 막는 **이중**인데 중복이 아니라 **접수와 발행 사이 몇 시간의 경합**을 잡는 자리다(SPEC-012 §5 「본인 작성 보호는 이중이다」가 이로써 코드에 들어왔다). **⑩ 문서 환류 — P2·P3 반영 + SPEC-012 stale 해소(37%→50%).** Phase 2·3 Status 를 **DONE** 으로 올렸다: P2 는 작업 항목이 전부 닫혔고 **검증 방법이 애초에 수동 접수**라 스케줄러·API 날짜 파라미터(P5)가 없다고 열려 있는 것이 아니며, 남은 차이 하나(활동 0)는 미착수 작업이 아니라 **스펙과 구현의 계약 차이**라 Phase 가 아니라 Open Issue 가 들 자리다. progress 50% 는 **코드 Phase 셋이 닫혀 딱 절반**이라는 뜻이고, 남은 절반이 화면 전체(P4)와 **유일하게 배포가 필요한** P5(마이그레이션·볼륨·토큰·서버 클론 321MB·구 경로 제거·실발행)라 셋이 닫혔다고 앞서 잡지 않았다 — WORK-015 의 80%("BE·FE 전부 done, 실전 e2e 만 남음")가 눈금이다. **SPEC-012 는 「형식 SoT」 표의 「읽는 쪽」만 갱신했다**(`compose` 스테이지 → `daily` 게이트). **계약이 아니라 소비자 이름표라 `version` 은 0.0.1 그대로 두고 `updated_at` 만 올렸다** — 필드 소유·액션·길이 상한·갱신 규율이 한 글자도 안 바뀌었는데 version 을 올리면 "계약이 개정됐다" 는 신호가 되어 SPEC-012 를 참조하는 코드·문서를 전부 다시 대조하게 만든다. SPEC-008 v0.0.3 은 **계약 표**가 바뀌어 올린 것이라 성격이 다르다. 대신 표 아래에 한 줄 각주를 남겨 `updated_at` 만 움직인 이유가 문서 안에서 읽히게 했다. **코드 대조에서 나온 미해결 둘(고치지 않고 남긴다).** ⓐ **잔디 `concept` 만 형식 SoT 를 읽지 않는다** — SPEC-012 형식 SoT 표와 S-3 4항은 concept 템플릿·지식노트 규칙을 따르라는데 `stages/daily.py` 는 `daily_format`·`career_format` 둘만 싣고 concept 은 프롬프트에 "노트 전문" 이라고만 적혀 있다(유튜브 `stages/concept.py` 는 `READ_THE_RULES` 로 읽힌다). 같은 목적지에 두 규율이 있는 상태이고, 발행부의 `up:` 필수·계보 검증이 **막아 주기는 하므로** 조용히 나가지는 않지만 승인 화면에 계속 거부당하는 초안이 오르는 형태로 드러난다 → Open Issue, P4 에서 판단. ⓑ SPEC-012 목적지 표가 concept 액션을 `upsert` 로 적었으나 코드는 `mode=supplement`→`replace` / 그 외 `create` 로 **갈라 쓴다** — S-3 2항("이미 있으면 새 파일을 만들지 않고 보충한다")과는 오히려 코드가 더 정확하다. 표의 라벨이 느슨한 것이라 계약 위반은 아니고, SPEC-012 개정 시 함께 정리할 것. `PROTECTED_CAREER_FIELDS` 상수는 정의만 되고 **소비자가 없다**(구조로 막기로 하면서 필요가 사라졌다) — 코드 정리 대상. | [[work-017-grass-commit-pipeline\|KDEV-WORK-017]] · [[spec-011-commit-collection\|KDEV-SPEC-011]] · [[spec-012-grass-artifacts\|KDEV-SPEC-012]] · [[spec-013-grass-gate\|KDEV-SPEC-013]] · [[spec-008-gate-chain\|KDEV-SPEC-008]] · [[spec-010-apply-executor\|KDEV-SPEC-010]] |
