# rules/

커밋 전에 기계가 검사할 수 있는 정합 규칙과 그 검사기가 사는 자리다.
판단이 필요한 규칙은 각 버킷 문서(`para/*.md`)가 갖는다 — 여기는 **기계 검사 가능한 것만** 둔다.

## 규칙 1 — 개념 파일 ↔ area.md §3.4 맵

`para/areas/concept/<영역>/<stem>.md` 가 늘거나 줄면 `para/areas/area.md` §3.4 맵도
같은 커밋에서 움직여야 한다. 맵이 낡는 경로가 「개념은 만들었는데 맵은 나중에」였다 —
그 「나중에」를 커밋 시점에 끊는다.

| 커밋에 담긴 것 | 요구 |
|---|---|
| 개념 파일 추가 | 맵에 그 stem 행이 있어야 한다 (영역도 일치) |
| 개념 파일 삭제 | 맵에서 그 stem 행이 빠져야 한다 |
| 개념 파일 이동 | 새 위치 기준으로 위 둘을 적용 |

검사기: `rules/check-concept-map.py`

- `--staged` (pre-commit 기본) — **이 커밋에 올라오는 개념 파일만** 본다.
  기존에 낡아 있던 맵은 막지 않는다 — 백필을 커밋마다 강제하면 훅이 우회(`--no-verify`)로
  죽는다. 새 rot 만 막는다.
- `--all` — 전수 감사. 파일↔맵 양방향 + 번호 연속성. 백필이 끝났는지 확인할 때 쓴다.
  **백필 완료 후에도 pre-commit 을 `--all` 로 올리지 않는다** — 서버 자동 커밋(잔디·알고리즘)과
  맵이 무관하게 어긋난 순간 모든 로컬 커밋이 인질로 잡힌다. 전수는 감사로만.

## 설치 — 체크아웃마다 1회, 로컬만

```bash
git config core.hooksPath rules/hooks
```

- **서버 클론에는 설정하지 않는다.** 잔디·알고리즘 자동 커밋은 개념을 만들지 않으므로
  검사할 것도 없고, 자동 파이프라인에 훅 병목을 만들지 않는다. 훅은 opt-in 이라
  설정 안 한 클론은 원래대로 돈다.
- 우회는 `git commit --no-verify` — 맵을 고칠 수 없는 비상시에만. 우회했다면 다음
  커밋 전에 `--all` 로 확인하고 갚는다.

## 새 규칙을 더할 때

- 검사기 하나 = 파일 하나 (`check-<이름>.py`). `hooks/pre-commit` 에서 호출을 한 줄 더한다.
- staged 기준(새 위반만 차단)을 기본으로 한다 — 전수 검사를 훅에 걸면 남의 rot 가
  내 커밋을 막는다.
- 판단이 필요한 것(설명문 품질·개념인가 아닌가)은 여기 못 온다 — 그건 사람/리뷰 몫.

## 아직 안 한 것

- **맵 백필** — `--all` 기준 위반이 남아 있다(main 의 fix/concept 커밋들이 만든 개념이
  맵에 없다). 백필 후 `--all` 0 위반을 한 번 찍는 것이 목표.
- `aliases`·`up:` 누락 검사 — 옛 구조의 부팅 검증기 미이관분(area.md §3.3). 옮겨 온다면
  여기로 온다.
