# LLM 위키와 그래프를 통합해야 세컨드 브레인이 완성된다

4분 30초짜리 영상으로, 자사 도구(Graphify) 배포를 겸한 홍보물이다. 다만 "위키만으로도, 그래프만으로도 부족하다"는 진단과 환각 차단 방식은 그대로 인용할 가치가 있어 남긴다.

## 이 영상이 말한 것

### 문제 — 1:1 복사 위키는 텍스트 무덤이 된다

- 문서가 100개를 넘어가면 AI가 길을 잃고 토큰 비용만 나간다.
- 카파시가 제안한 "지식 복리" 개념 자체는 훌륭하나, 현장에서는 **문서 하나당 위키 하나를 기계적으로 1:1 복사**하는 실수를 한다. 그러면 지식이 유기적으로 섞이지 않고 텍스트 파일 무덤이 된다.
- 요약 과정에서 생긴 **AI의 미세한 환각이 위키 네트워크 전체로 기정사실처럼 전파**되고, 결국 AI는 엉뚱한 답을 내놓는 빈 껍데기가 된다.

### 진단 — 그래프 단독도 답이 아니다

- 그래프는 노드와 구조를 잇는 데는 뛰어나지만 **담길 내용이 부실하면 뼈대만 앙상한 지식망**이 된다.
- 그래프 단독의 또 다른 약점: 비슷한 말·동의어를 걸러내지 못해 **노드가 연결되지 못하고 떠다니는 고립 노드(orphan)** 가 생긴다. 영상은 이를 에이전트가 의미론적 연관성을 추론해 이어 붙이는 방식으로 해결한다고 주장한다.

### 처방 1 — 구조와 내용을 분리해 상호 보완시킨다

- 위키로 **상세한 맥락과 텍스트(살코기)** 를 채우고, 그래프로 **흔들리지 않는 구조적 뼈대** 를 세운다.
- 질의 시에는 **그래프로 먼저 위치를 빠르게 찾고, 세부 내용은 위키에서 깊이 끌어온다.**
- 비용 근거로 든 사례: 기존 RAG/위키 방식 세션당 2만 토큰 → 그래프로 사전 컴파일 후 280 토큰. 71.5배 절감이라 주장한다. **자사 사례 인용이며 독립 검증은 없다.**

### 처방 2 — 투패스 아키텍처로 환각을 차단한다

- 텍스트를 통째로 던지고 "알아서 위키나 그래프를 짜 달라"고 하면 환각이 발생한다.
- 그래서 두 단계를 **철저히 분리**한다.
  1. **로컬에서 구문 분석기(tree-sitter)만으로 결정론적 뼈대를 기계적으로 추출** — 설명서대로 조립하는 레고에 비유.
  2. 그 위에서 **비로소 AI가 문맥을 잇는다.**
- 확률이 팩트를 오염시키지 못하게 **100% 팩트 기반 뼈대 위에만 지식을 쌓는다**는 것이 핵심 주장이다.

### 운영 흐름

`raw` 폴더에 메모를 던짐 → 인제스트 스크립트가 위키 폴더에 주제별로 누적·병합 → 싱크 명령이 로컬 파일을 스캔해 그래프로 빌드. 외부 API 없이 로컬만으로 동작한다고 강조한다.

## 한계와 검증이 필요한 부분

- **홍보 영상이다.** 71.5배 토큰 절감은 자사 고객 사례이며 조건·측정 방법이 공개되지 않았다.
- 고립 노드를 "AI가 의미론적으로 자동 연결"하는 부분은 정합성 관점에서 오히려 위험할 수 있다 — 자동 추론된 연결이 틀렸을 때 그것을 걸러낼 장치가 영상에 나오지 않는다.
- 자막 기준 정리이며 화면에 나온 코드·구조는 확인하지 않았다.
