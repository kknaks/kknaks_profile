## 한 일

`MediSolveAIDev/mediness`는 코드 커밋 없이 전부 스펙 문서였다. SPEC-230(랜딩 에이전트 채팅)을 신설한 뒤 실측할 때마다 가정이 깨져 D21까지 개정했다 — turn 상한 설정이 CLI에 없어 시간 상한으로 바꿨고, 승인 게이트 MCP write 툴이 코드에 없다는 것도 드러나 "예약 wrapper 선행"을 못박았다. 저녁에 stable로 승격하고 WP-102 구현계획을 착수시켰다. 의사결정 파이프라인 고도화(WP-098)도 마무리했다 — 위임전결표를 SoT로 확정하고 사람 조회는 조직 서비스로 위임했다. 49건 배치 실측으로 AI gate 추천 완주율을 끌어올렸고, "프롬프트 스토어 미등록으로 평가가 구버전으로 돌아간" 사고를 근거로 운영 규칙(SPEC-121)을 신설했다. SPEC-221(프론트 데이터 로딩 경계)도 실측 지연 문제로 신설했다.

`kknaks/open_kknaks`(codex 워커 + Redis 브로커)는 두 커밋으로 실측 기반 버그를 고쳤다. codex CLI(0.146.0) 실제 출력을 재확인해 `tool_use`/`tool_result`에 짝짓기 id가 안 채워지고 `item` 페이로드가 flat 구조로 와 도구 실행 이벤트가 `progress`로 유실되던 문제, Redis 스트림·DLQ 키가 만료 없이 누적되던 누수를 ack/nack 시점 TTL로 함께 고쳤다. `resume` 서브커맨드가 `exec`의 부분집합 플래그만 받는다는 것도 실측으로 확인해, resume 모드에서 신규 세션과 같은 sandbox 기본값을 보내다 죽던 문제를 전용 미지원 플래그 자동 필터링으로 정식화했다.

## 막힌 것 · 판단

- codex CLI 실측 결과 turn 상한 설정이 없어 시간 상한으로 축을 바꿨다.
- 승인 게이트 MCP write 툴 부재를 실측으로 발견해 예약 wrapper를 선행 조건으로 못박았다.
- 프롬프트 스토어 미등록 사고를 계기로 배포 절차에 스토어 등록을 넣는 규칙을 신설했다.
- 위임전결표 옮겨 적는 과정의 실명 오기(조혜인→조상아)를 뒤늦게 정정했다.
- open_kknaks는 문서가 아니라 codex CLI 실측(0.146.0)으로 원인을 확인했다.
- resume 모드 플래그 억제는 신규 세션 로직과 분리했고, 브로커는 "종결 시점에만 TTL, 재시도 시 PERSIST 해제"로 정리했다.

## 알게 된 것

- "계약을 구현에 맞춘다" — 실측이 나올 때마다 가정을 폐기하며 계약을 구현 현실로 재조정하는 패턴이 반복됐다.
- 위임전결표를 SoT로 두고 사람 조회를 조직 서비스로 위임하면 문서 하나가 여러 목적을 겸하지 않아 유지비용이 낮아진다.
- CLI 서브커맨드별 허용 플래그가 다를 때, 문서가 아니라 실제 바이너리 동작 기준으로 차단 목록을 관리하는 게 안전하다.
- 진행 중 리소스에는 TTL을 걸지 않고 종결 이벤트에서만 만료를 걸며, 재큐잉 시 PERSIST로 해제하는 큐 키 수명 관리 패턴을 정리했다.
