# 프로덕트 맵 공동 캔버스 — 개발 도전 문서

Nov 12, 2026 · @kknaks

## 목표

코드에서 자동으로 뽑은 화면 지도 위에서 기획자, 디자이너, AI 에이전트가 메모를 남기고 시안을 그리는 캔버스 하나를 만든다.

- 출발점: PFCT의 [프로덕트 맵](https://blog.pfct.co.kr/product-map/)은 앱 코드로 화면 약 630개와 이동 약 1,300개를 자동으로 그린다. 그런데 지도 위 코멘트는 아직 '향후 계획'으로 남아 있다.
- 이번 도전: 그 다음 단계, 즉 지도를 **보는 곳**에서 **같이 일하는 곳**으로 바꾸는 것.
- 성공 기준: 화면 하나에 사람 메모, AI 메모, 새 시안이 함께 붙어 있고, 지도를 다시 생성해도 이 셋이 사라지지 않는다.

## 범위 (MVP)

첫 버전은 실제 앱의 한 도메인, 화면 20개 안팎을 대상으로 한다.

| 넣는다 | 뺀다 (나중에) |
| --- | --- |
| 화면 노드 + 이동 엣지 + 스크린샷 한 장 | 상태별 스크린샷 자동 촬영 |
| 화면에 붙는 메모 (작성자, 상태) | 스레드 답글, 알림 |
| 화면 옆에 새 시안 프레임 | Android/iOS 짝 비교 |
| AI 에이전트 1명 (MCP로 접근) | AI 여러 명, 역할 분담 |
| 로컬 한 대에서 혼자 작업 | 실시간 다중 접속, 권한 |
| 수동 또는 간단한 스크립트로 만든 맵 JSON | 커밋마다 자동 재생성, 버전 히스토리 |

## 아키텍처

핵심은 캔버스를 원본으로 쓰지 않는 것이다. 맵, 메모, 시안을 각각 파일로 두고 `screenId`로 잇고, 캔버스는 렌더러가 그때그때 그린다.

&#91;embedded content: 아키텍처 · 저장소 3레이어 + 렌더러\]

맵 생성기는 맵 데이터만 덮어쓰니, 코드가 바뀌어 맵을 다시 만들어도 메모와 시안은 그대로 남는다.

메모 하나의 모양 (출발점):

```json
{
  "id": "note_001",
  "screenId": "invest/account-verify",
  "author": { "type": "ai", "name": "claude" },
  "status": "open",
  "body": "400 에러 상태에서 안내 문구가 없음",
  "createdAt": "2026-11-12T21:00:00+09:00"
}
```

`screenId`는 라우트 경로처럼 코드가 바뀌어도 잘 변하지 않는 값으로 정한다. 이 값이 흔들리면 메모가 고아가 된다.

## 단계별 도전 과제

오늘 밤 목표는 0\~2단계, 즉 ‘내 맵 JSON이 open-pencil 캔버스에 지도로 뜨는 것’까지다. 각 단계는 완료 기준이 보이면 끝난 것으로 한다.

- [ ] **0. 환경 준비** — `brew install openpencil` 설치 후 `claude mcp add --scope user open-pencil -- openpencil-mcp`로 연결
  - 완료: Claude Code에서 말로 “새 문서 만들어”했을 때 빈 문서가 생김
- [ ] **1. 맵 데이터 만들기** — 도메인 하나의 화면 20개 안팎을 `screens.json`, `edges.json`으로 작성 (수동 또는 라우터 파일 파싱)
  - 완료: 모든 화면에 안정적인 `screenId`가 있음
- [ ] **2. JSON → 캔버스** — 스크립트로 도메인별 섹션, 화면 프레임, 이동 화살표를 그린다 (`openpencil eval`의 Figma Plugin API 또는 MCP)
  - 완료: .fig를 열면 지도가 보이고, 프레임 이름에 `screenId`가 들어 있음
- [ ] **3. 메모 레이어** — 메모는 `notes.json`에 `screenId` 기준으로 저장하고, 캔버스에는 화면 옆 스티커로 그린다
  - 완료: 맵을 지웠다 다시 그려도 메모가 제자리에 복원됨
- [ ] **4. AI 참여** — Claude Code에게 맵을 읽고 메모를 남기게 한다 (아래 시나리오)
  - 완료: `author: ai` 메모가 올바른 화면에 붙음
- [ ] **5. 시안 레이어** — 기존 화면 옆에 `proposal/` 프레임을 만들고, 사람과 AI 둘 다 그릴 수 있게 한다
  - 완료: 시안이 원본 화면과 연결되어 보임
- [ ] **6. 재생성 테스트** — `screens.json`에 화면 하나를 추가하고 하나를 지운 뒤 다시 생성한다
  - 완료: 메모와 시안은 유지되고, 지워진 화면의 메모는 ‘고아’로 표시됨

## AI 참여자 시나리오

AI는 처음에는 ‘검토자’ 역할만 맡긴다. 메모를 달고 시안 초안을 그릴 수는 있지만, 맵 레이어는 건드리지 못하게 한다.

| 시나리오 | 프롬프트 예시 | 결과물 |
| --- | --- | --- |
| 빈 상태 점검 | “투자 도메인 화면을 훑고, 에러나 빈 상태 화면이 없는 곳에 메모를 남겨” | `author: ai` 메모 N개 |
| 기획서 대조 | “이 PRD의 화면 흐름과 맵을 비교해서 다른 부분에 메모해” | 차이 목록 메모 |
| 메모 응답 | “열린 메모 중 디자인 문제를 골라서 시안을 그려줘” | `proposal/` 프레임 |
| 요약 | “이번 주에 달린 메모를 화면별로 정리해줘” | 채팅 답변 |

권한 규칙을 프롬프트가 아니라 코드로 지키려면, MCP 도구를 래핑한 자체 도구(`add_note`, `add_proposal`)만 AI에게 열어 주는 방법이 있다.

## 리스크와 열린 질문

사람끼리의 동시 편집은 된다. 남은 리스크는 AI 편집이 그 동기화에 타는지, 그리고 댓글 기능이 없다는 점이다.

| 항목 | 확인된 내용 (README 기준) |
| --- | --- |
| 실시간 협업 | 됨. 서버·계정 없이 WebRTC P2P(Trystero) + Yjs CRDT로 동기화 |
| 참여 방법 | 공유 버튼 → `app.openpencil.dev/share/<room-id>` 링크 |
| 프레젠스 | 커서, 선택, 편집이 실시간으로 보이고, 아바타를 누르면 그 사람 화면을 따라감 |
| AI 편집 | MCP와 CLI(RPC)로 라이브 캔버스를 수정할 수 있음. 다른 참여자에게 동기화되는지는 언급 없음 |
| 댓글 | 언급 없음 → 메모는 `notes.json`으로 직접 관리 |

출처: [open-pencil README](https://github.com/itorr/open-pencil)

오늘 밤 0단계에서 직접 확인할 것:

- [ ] AI 편집 동기화 — 브라우저 두 개로 같은 방에 들어간 뒤, 한쪽에 연결된 Claude가 노드를 추가하면 다른 쪽에도 뜨는가?
- [ ] 빈 방 문제 — P2P라서 아무도 접속해 있지 않을 때 AI가 혼자 작업한 결과는 어디에 남나? 다음 사람이 들어오면 보이나?
- [ ] 영속성 — 방의 상태가 누구의 파일에 저장되나? 기준 .fig 파일을 누가 갖고 있나?
- [ ] 화살표(커넥터)를 API로 그릴 수 있나?
- [ ] 노드에 `screenId` 같은 커스텀 데이터를 붙일 수 있나? (Figma의 `setPluginData` 대응 기능)
- [ ] 화면 600개 이상에 스크린샷까지 넣으면 캔버스가 버티나?

대안: AI 편집이 동기화되지 않거나 빈 방에서 작업이 남지 않는다면, AI는 캔버스 대신 notes.json과 proposals.json에만 쓰고 렌더러가 반영하게 한다. 협업 자체가 부족하면 tldraw 같은 화이트보드 SDK를 비교해 본다. 데이터 모델을 캔버스 밖에 두었기 때문에 갈아타기 비용은 렌더러 하나로 끝난다.
