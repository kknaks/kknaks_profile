## 2. 대응표 — 원천 9곳 · 규칙(R12~R20 · 10-29 「게이트 → 규칙」)

행별 결정 표(`correspondence.<표>`)는 없앴다. apply 가 `concern_rules` 로 계산한다. 사람 확인 88 은 「규칙이 없어 생긴 것」이었다(사용자 10-29).

| 원천 | 칸 | 판정 |
|---|---|---|
| problem-packages | `problems[].problem` · `complaints[].cc` | P id · 항목 이름 직결(규칙 아님 · 대상 없으면 open 「대응 없는 CC」) |
| problem-combos | `combos[].problem` | 쁘띠시술 = J5 앵커 없음 · 나머지는 이름을 규칙으로(P id 가 결과에 없으면 open) |
| 최적화 고민 · 연령 · synergy · 레시피 goal · 비교 제목 · 6단계 라벨 | 원천 말 그대로 | 규칙 |
| 3단계 넘김 | `deferred[].string` · `strings[].handoff` | **원 문자열 먼저**(부위 = 3단계 `nodes`) · 안 풀리거나 시술 이름이면 3단계 조각 |

규칙 순서(`cres` — 앞에서 풀리면 끝):

1. 완전 · 사전(R13): 노드 이름 · 고민 칸 · 동의어(등급 1) > 묶음 노드 이름의 낱말(등급 2 — 「피부재생/탄력」의 「탄력」) > 목적 이름 · 원천 낱말(등급 3) > 목적 이름의 동사 꼬리를 뗀 대상 낱말(등급 4). 부위가 있으면 그 부위 · 상위 부위 노드 중 가장 가까운 것, 없으면 부위 없는 노드 + 부위 속성. 키는 묶음 구분자를 남긴다(「여드름/흉터」 ≠ P9-1 「여드름흉터」)
2. 영문(R15): 원천 짝(category_en · 최적화 concern_en · 비교 id ↔ 제목, 「/」 나눈 짝 포함) + `en_extra`. 한 영문이 여러 짝에 걸리면 규칙 밖(「Hair」)
3. 외래어(R15): `loanwords`(안티에이징 → 항노화 · 컨투어링 → 윤곽)
4. 시술 이름(R19): 5단계 이름 · 동의어 · 계열 낱말이면 고민 아님 — 묶음에서 뗌
5. 괄호: 괄호가 본말 아래 노드면 하위(「색소(기미 초기)」 → P5-1) · 아니면 풀이
6. 묶음 나눔(R12): `/ · , +` — 낱말마다 붙임. **한 조각이라도 못 풀면 행 전체가 규칙 밖**
7. 꼬리말 · 머리말(R14): `tails` · `state_tails` · `lead_words`
8. 공백 나열 · 부위 + 고민 · 중증도(R12 · R17 · R18)
9. 붙여 쓴 부위 + 말(「바디리프팅」). 부위 낱말이 곧 대분류 이름(바디 = P12)이고 나머지가 그 부위에 안 맞으면 그 대분류(R17)

목적(R16): 목적 노드에 `purpose_concern`(고민 낱말 → 같은 부위로 내림)을 붙인다 — 리프팅 → 처짐 · 탄력 / 타이트닝 → 탄력 / 재생 → 피부재생. 「항X」 → X(노화 → P4).

중증도(R18 · J12): `severity_children` — 주름만 하위가 있다(초기 · 경미 → P2-3 / 중기 · 중등도 · 심화 · 중증 → P2-2). 나머지는 `severity_survey` 대로 상위 + severity. 최적화 `severity_levels` 는 단계 이름 괄호 낱말이 그 고민 아래 노드를 가리키면 그 노드(「활성 여드름」 → P6-1) — 엣지 `from_concerns` · 중증도 조합 `anchor.concern`.

**규칙 밖(R20)**: 사전에 없는 낱말 · 부위 어긋남 · 영문이 두 고민. 미용 고민 트리 밖 목적(항산화 · 피로회복 · 면역 · 영양보충)은 **J9 대로 목적 노드만 · 사람 질문 아님**(10-29). 사용자 결정 사전 `concern_words`(여러 대상 가능 — 쁘띠시술 부위 메뉴 `menu_anchor_targets` P1-1 · P1-5 · 목적 포함 · J14) · 결정 노드 `extra_concern_items[].synonyms` · `units`(⑧ 엣지 — 잇몸미소 → U5-013). 이 행만 `human_check` · 결정 `concern_unresolved` 한 줄(질문)이 있어야 하고 없으면 open. **억지로 붙이지 않는다.**

`match` = 규칙 사슬 · `match_class` = 「완전 일치」 / 「규칙 R..」 / 「규칙 밖(사람 질문)」 · `gate_status` = 자동(완전 일치) / 자동(규칙) / 사람 질문(규칙 밖).

## 3. 목적 ↔ 고민

| | 고민 | 목적 |
|---|---|---|
| 뜻 | 상태 이름 | 시술이 하는 일 |
| 노드 | taxonomy 고민 갈래 | `purposes[]` 중 `same_as_concern` 이 null 인 것 |
| 같은 말 | — | 목적 노드를 세우지 않고 그 고민에 붙임(주름 · 여드름 · 흉터 · 제모 · 미백 · 다한증 · 모공 · 탈모 · 셀룰라이트 …) |
| 엣지 | 고민 → 단위 시술(①~⑤) | 목적 → 단위 시술(① P1 목적 낱말 · ⑥ · ⑦) |

목적 표현의 원천: 5단계 `units[].purposes` · 5단계 `product_evidence` 목적 키 · 6단계 메뉴 분류 · 중분류 목적 · P1 detail 목적 낱말 · 레시피 goal · synergy target · 비교 · 3단계. 결정 없는 표현은 open 「결정 없는 목적 표현」 → `purposes[].aliases` 한 줄.
면역 · 피로회복 · 영양보충은 목적 노드이고 고민 대응 없음 그대로(J9).

## 5. 이름 → 단위 시술 · 부위로 내림

순서(`step7-apply.py` `_resolve`):

1. `resolver.no_unit` — 시술 아님 · 단위 시술 없음(결정된 것만)
2. 5단계 단위 시술 이름 · 동의어(시장가 이름 · 일반 낱말 `generic_synonyms` 빼고 · `forced_synonyms` 더함) → **부위 거름**
3. 5단계 제품 이름(저장 · 상속 후보 · 장비 이름 동의어) → **부위 거름**
4. `resolver.fam_kw` 낱말 — 고정 키면 **부위 거름**, 계열이면 앵커 부위로 `units_at` → 없으면 부위 올라가기(R21 · `climb`) → 끝까지 없으면 계열만(`no_unit_at_site`) → 부위가 없으면 원천 제품 칸 · 이름 조각으로 좁힘 → 못 좁히면 후보 전부(`concern_without_site`) → **고민 영역(R22 · 사용자 10-30)** 으로 거름: 앵커 고민(과 하위 고민 · 항목 · 갈래 「목적」뿐인 중분류 제외)의 앵커 부위 → 최상위 영역 합 밖 단위 시술 뺌 · 영역 못 정하는 고민(하위 부위 0)은 손 안 댐(셈만). 추천 조합 구성도 같다
5. 못 풂 — `unresolved_ok` 결정이 있어야(없으면 open)

**부위 거름**(검수 F2 뒤): 앵커 부위 안(또는 부위 무관 특수 부위) → 없으면 같은 계열(하위 하나면 그 하위) × 앵커 부위 → 없으면 **부위 올라가기(R21 · 사용자 10-29)**: 3단계 트리 조상 노드 자신(형제 부위 안 넣음 · 묶음 통과) → 최상위 영역 「전체」 노드(「R 전체」 자식 · 없으면 R 자신 · 묶음이면 없음 — 얼굴 → 얼굴 전체 · 바디 → 바디 · 두피 → 두피 · 목(묶음) → 없음)까지, 처음 찾은 층만 · 최상위 영역(트리에서 계산) 경계 안 넘음 → 끝까지 없으면 **계열만**(to_units 비움 · to_family 유지) + `no_unit_at_site` · 「이 부위 단위 시술 없음」. 찾은 층은 lowering 「상위 부위로 내림(층)」 · `site_layer` · `site_check` 「상위 부위 층」. (10-29 이전 W2 「계열 후보 전부」는 부위를 무시해 이중턱에 겨드랑이 · 바디 · 두피 단위 시술이 붙어 대체)
앵커 부위 = 이름 칸 부위 낱말(`site_kw` · 한 글자 · 모호 낱말 규칙) → 없으면 맥락 부위(항목 · 중분류 · `context_by_source`). 「얼굴」은 「얼굴 전체」 키만(5단계 J2).

조합 원소: 「+」 · 「or」 로 나눠 조각마다(조각이 다 낱말일 때) · 괄호 안은 부위 · 제품 · 짧은 대안 목록으로만 · 「N회」는 회차 속성. 정해 둔 원문은 `exact_overrides`(트라넥삼산 경구+주사 — 원천 질문 함께).
의료진 확인 `check_flags`: 이름에 「스킨」 · 「모공」 없이 스킨보톡스 키 하나로만 내려간 것 → 후보 + check 표시 + 의료진 질문.

| 비교 | procedure-comparison | 비교 id → 대응표 target | 시술 이름 · 원천 계열(어긋남 표시) | 속성 원문(통증 · 다운타임 · PIH …) |
| 목적 레시피 | combo-recipes | goal → 대응표 target(규칙) | 계열 후보 전부(부위 · 제품 없음) | **상담 문구(환자 설명 · 비유) 기본 포함** · 후속은 8단계 메모로도 |
| 세션 조합(순서) | treatment-sequence `common_combos` | 이름을 대응표 규칙으로(못 풀면 앵커 없음 + 이유) | 순서 이름 | 순서 note = 8단계 메모 |

사이트 이름: `combo_kind_site_names` — 결정 없는 kind 는 open. 사이트 화면 용어 전체는 `site_terms`(recommend · optimize · compare · synergy).

## 7. 8단계 메모(엣지 아님)

순서 · 금기 · 간격 · 규칙(`combination_rules`) · 세션 조합 note · 레시피 followUp · CC combos(시너지 쌍 주장) · CC alternatives 중 간격 · 금기 문장(`step8_patterns.alternatives`) · 위험 대비 효과 문장 중 순서 · 간격(`step8_patterns.riskBenefit`). 8단계가 원천 synergy 와 함께 시술 ↔ 시술 엣지로 세운다.

## 앵커 부위 없는 엣지 · 조합 구성 좁힘 순서(사용자 10-30 · 검수 review-step7-sweep)

1. **R24 이름 · 제품** — 원천 이름 조각(「+」) · 레시피 subtitle · 제품 칸 괄호/「/」 안 낱말(「PDL(V빔)」 → V빔 → U5-141 · 고정 키 낱말 포함)
2. **R23 용도** — 여럿 중 다른 고민 용도(5단계 purposes)가 박힌 단위 시술이 섞이면, 고민(과 위 고민) · 목적 이름 낱말에 든 용도의 단위 시술만 · 없으면 계열만. 용도가 하나도 안 박힌 계열은 밖
3. **R22 고민 영역 + 판단 ①** — 영역 없는 피부 고민(P4 · P5 · P6 · P7 · P9 · J10) 기본 영역 얼굴 · 튼살(P9-4) 바디(`site_rules.concern_region_default`) · 기타 P14 는 기본 없음
4. **R25 두피** — 두피 단위 시술은 고민 영역에 두피가 있을 때만
5. **R26 흉터 필러** — 흉터 고민에 M2 단위 시술 없음 → 필러 계열만 + 원천 질문
6. **판단 ②** — 필러만 여럿 남은 「후보 전부」는 그대로 + 「후보 여럿(필러 부위 못 정함 · 판단 ②)」
7. 대상 경로 = `site_rules.narrow_sources`(① ③ ④ ⑤) + 추천 조합 구성 · ⑥ ⑦ ⑧ 은 단위 시술 직결이라 밖
8. **R27** — ③ 은 (갈래 앵커 × 원천 시술 · 계열 · 단위 시술 · 앵커 부위) 하나 · CC 는 `source_ids` · `evidence.ccs` · 원천 수정 후보 「갈래 목록 복사(R27)」 · 8단계 CC7 은 source_ids 마다 색인

## 품질 규칙 R28 ~ R32(사용자 10-30 품질 목표 · 코디 R28 · 골드 U-1 ②)

허브 품질 측정 1차(`orchestration/work/phub-recommend/quality-report.md` · 1차 보관 `quality-v1/`)가 I-01 고민 → 추천의 틀린 시술을 원인으로 묶은 것 중 7단계 몫. 문장 정본 = `step7-decisions.json` `rules[]` R28~R32 · 데이터 = `quality_rules` · 코드 = `step7-apply.py` 「품질 수정」 절 · 고정 시험 QA(R29) · QB(R32) · QC(R30) · QN(R31) · Q28(R28) · S1.

적용 순서 — ① ③ ⑤ 엣지 · R27 합치기 전에 원천 CC 행마다:

1. **R30 원천 계열 밖 금지**(원인 C) — 허용 계열: ③ 원천 `procedures[].category` · ① 항목 `modality_ref` · ⑤ 항목 `modality_ref` ∪ 같은 이름 원천 CC 의 category. 밖이고 단위 시술의 원천 계열(5단계 원장 source_family · 시장가 category)도 밖이면 뺌. 둠: 계열 옮김 결정(원장 · 시장가 원천 계열 · fam_kw 옮김 낱말 「반영구」 → N3 · 「지방분해」 → N1) · 원천 이름이 그 시술을 바로 가리킴(이름 · 동의어 · 제품 · fam_kw 고정 단위). 다 빠지면 계열만 — 다시 내리지 않음
2. **R29 원천 부위 낱말**(원인 A) — 원천 문구(① ⑤ 항목 이름 · detail · 갈래 이름 / ③ cc · cc_group · cc_detail)의 3단계 부위 이름 · 강한 동의어(긴 이름 먼저) → 앵커 부위를 그 부위로. 단위 시술은 그 부위 · 하위만 → 없으면 R21 올라가기 → 없으면 계열만. 결정으로만 붙은 부위는 앵커 아님. 한 글자 부위는 `quality_rules.site_word_one_char` 정규식(볼(?!륨|류) · 코(앞이 한글이면 안 잡음) · 목(?!적|표|록|소리) …) · 「얼굴」은 `site_word_skip`
3. **R31 원천 제품 → 하위**(원인 N) — ③ 원천 제품 이름(+ CC 이름 · ⑤ 항목 이름)을 1단계 이름 · 2단계 product_family 하위로(5단계 장비 이름 동의어 `device_name_synonyms` 의 하위도 그 이름 하위 — 판단 ③ 을 지우지 않게). 하위 밖 단위 시술 뺌(하위 없는 단위 시술은 둠 · 다 빠지면 계열만). 원천이 하위를 안 정했고 R21 로 올라간 층 하위가 둘 이상 → 계열만(`sub_undecided` · site_check 「원천 하위 안 정함 · 계열만(R31)」)
4. **R28 CC 목록** — ③ `ccs[]` = evidence.ccs · ① `ccs[]` = [항목 이름](항목 = 원천 CC 일 때) · ⑤ `cc_named[]`. 조회: 질의 CC 가 원천 CC 면 같은 원천 문제(P) 안에서 `ccs[]` 에 그 CC 가 든 엣지만 · 아니면 고민 노드 엣지 전부
5. **R32 층 표시**(원인 B · U-1 ②) — 부위 검사 뒤. `layer` = 부위(앵커 부위 · 하위) · 상위(R21 로 올라간 층) · null(앵커 부위 없음)
