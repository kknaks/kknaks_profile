# Procedure Hub 고민 판정 · 실버 고민 원장 갱신

실버 7단계(고민 · 목적 · 추천 조합, 2026-10-29)에서 실제로 한 방법을 옮긴 것이다. 새로 지어낸 절차가 아니다.
6단계(패키지 — `procedure-hub-package-check`) 다음 단계다. 고객이 말하는 「고민」을 노드로 세우고, 고민 · 목적에서 5단계 단위 시술로 가는 엣지를 **원천에 적힌 만큼** 잇는다. 사이트의 「추천 패키지」 같은 조합은 추천 조합 노드로 원천별로 옮긴다.

## 2. 판정 순서

원천 행 하나마다 위에서부터. **앞에서 끝나면 뒤로 가지 않는다.** 상세 `references/concern-rules.md`.

### 2-1. 고민 정본 = taxonomy problem — 「고민」 갈래만 노드(R1 · R2)

- **대분류**: 고민 · 목적형 고민(제모 · 얼굴윤곽) = 노드. **쁘띠시술(시술 범주) · 기타(묶음) = 노드 아님** — 기타 아래 점/사마귀 · 다한증 · 피부질환은 최상위 고민 노드 · 문신제거는 목적(J2)
- **중분류** 갈래 — 고민 · 고민 + 부위(D-07 분리 · R4) = 노드 / 부위 · 시술 묶음 · 목적 · 부위 + 대상 · 대상 = 노드 아님 → 부위 · 대상 속성 · 묶음 이름 원문 · 목적으로 녹인다
- **항목** 갈래 — 고민 = 노드 / **시술 이름 = 엣지**(§2-2) / 부위 = 부위 / 시술 아님 = 표시(`resolver.no_unit` · 5단계 선례)
- **원천 밖 노드는 결정이 있을 때만**(`extra_concern_items` — 자갈턱 @턱끝 · J8 · **피부결 상위 없음 · J10**). 없는 노드를 만들지 않는다 — 다크서클 · 꺼짐 같은 말은 규칙 밖 사람 질문(J9 · R20)
- 이름 치환은 정해 둔 「쳐짐 → 처짐」만(`rename`). 사이트 이름은 노드 이름 · 다른 말은 동의어(J3 「제모」 + 털 · 체모 / 「얼굴윤곽」 + 윤곽 · V라인)

### 2-2. 시술 이름 항목은 엣지(R3 · J1)

「레이저토닝」 · 「IPL」 · 「백옥주사」 같은 항목은 고민 노드가 아니다 — **상위 고민 → 단위 시술 엣지**(⑤)이고 항목 원문은 엣지 출처로 남는다. 고객은 「레이저토닝이 고민이에요」라고 말하지 않는다.
- 항목 이름이 **질환 이름**이면(백반증 · 건선) 고민 노드와 같은 말인지 먼저 대조한다 — 단위 시술 동의어로 두면 고민 낱말이 시술로 풀린다(W3 · 모호 표시)

### 2-3. 다른 원천의 고민 표현 = 대응표 — 규칙으로 자동 · 규칙 밖만 사람 질문(R12~R20 · J11~J13)

- 원천 9곳: problem-packages(대분류 · CC — P id 직결) · problem-combos · 최적화 고민 · 연령 주 고민 · synergy target · 레시피 goal · 비교 제목 · 3단계 넘김(원 문자열 먼저 · 부위 = 3단계 nodes) · 6단계 메뉴 분류
- 행별 결정 표는 없다. apply 가 `concern_rules` 로 계산한다 — **묶음 이름은 낱말마다**(「처짐/탄력」 = P3 + P4-1) · **꼬리말 떼기**(비교 · 패키지 · 치료 · 개선 · 케어 · 집중 · 저하 · 손실 …) · **영문 · 외래어**(원천 짝 · 사전) · **목적어 → 목적 노드 + 목적 ↔ 고민** · **부위 + 고민 → 3단계 부위 + 고민** · **중증도 → 하위**(주름만 하위 · 나머지 상위 + severity) · 시술 이름 조각은 뗌. 순서 · 상세 `references/concern-rules.md` §2
- 같은 성격 행은 같은 규칙을 탄다 — 행마다 따로 추천하지 않는다(틀렸던 예 G88)
- **규칙으로 하나로 안 정해지는 것만 사람 질문**(사전에 없는 낱말 · 부위 어긋남 · 영문이 두 고민 · 미용 고민 트리 밖 목적) — 결정 `concern_unresolved` 에 질문 한 줄, 없으면 open. 후보는 적되 추천값으로 채우지 않는다. **억지로 붙이지 않는다**
- 「완전 일치」는 글자 비교 결과다(F1) — 규칙으로 푼 행은 「자동(규칙)」 + `match_class` 규칙 id 로 구분한다

### 2-4. 목적 vs 고민(R6 · J4)

- **고민 = 상태 이름**(주름 · 기미 · 처짐) · **목적 = 시술이 하는 일**(리프팅 · 타이트닝 · 재생 · 볼륨 회복 · 연장 · 축소 · 지방분해 · 근육강화 · 항산화 · 피로회복 · 면역 · 영양보충 · 문신 제거)
- 같은 말이 둘 다면(주름 · 여드름 · 제모 · 미백 · 다한증 …) **목적 노드를 따로 세우지 않고 그 고민에 붙인다**(`purposes[].same_as_concern`)
- 목적 → 단위 시술은 엣지(⑥ 5단계 용도 · ⑦ 메뉴 분류 · ① P1 detail 목적 낱말) · 목적 ↔ 고민은 `concern_rules.purpose_concern`(R16)

### 2-5. 엣지는 원천 구조만 — 적응증 아님(R7)

엣지를 만드는 원천 칸은 일곱 갈래 + 결정 노드(⑧)뿐이다.

| 갈래 | 원천 칸 |
|---|---|
| ① | taxonomy 항목 `modality_ref`(고민 · 부위 항목) · P1 쁘띠시술 항목 detail 의 고민 · 목적 낱말 |
| ② | problem-combos 패키지 `procedures`(계열 — 결정대로 계열 단위) |
| ③ | problem-packages CC `procedures`(추천 시술 이름 · 계열 코드 · 제품) |
| ④ | treatment-optimization `optimal_combo` |
| ⑤ | taxonomy 항목 = 시술 이름 |
| ⑥ | 5단계 `units[].purposes`(원장 용도) · `product_evidence` 목적 키 |
| ⑦ | 6단계 `non_packages`(7단계로 넘긴 메뉴 분류) → 안 항목의 저장 단위 시술 |
| ⑧ | 결정 노드 `extra_concern_items[].units`(사용자 결정 — 잇몸미소 → U5-013 · J14) |

- **적응증(indications) · 효과 문장 · 기대 효과는 근거로만** — 엣지를 만들지 않는다
- 원천 계열 코드와 단위 시술 계열이 다르면 **이름(5단계 판정)을 따르고** 「계열 코드 어긋남」 표시 + 원천 수정 후보(`step7-source-fix.md`). 경로마다 같게(①③⑤ · 비교 — W1)
- **쌍 주장(순서 · 간격 · 금기 · 시너지)은 엣지 아님** — 8단계 메모(`step8_notes`)만(R11)

### 2-6. 부위로 내림 → 없으면 후보 전부 + 표시(R4 · `site_rules`)

이름 · 동의어 · 제품 · 계열 코드로 단위 시술을 잡은 뒤, **모든 경로(①③④⑤)에서 같은 순서**로:

1. 앵커 부위(고민 · 중분류 · 항목 · 이름 칸 부위 · 맥락 `context_by_source`) **안의 단위 시술** — 「얼굴」만이면 「얼굴 전체」 키(5단계 J2) · 부위 무관 특수 부위(해당 없음 · 병변 단위)는 통과
2. 없으면 **같은 계열(하위 하나면 그 하위)을 앵커 부위로 내림**(F2 — 이름 일치 경로도 이 단계를 거친다)
3. 그래도 없으면 **계열 후보 전부 + `no_unit_at_site`** 「그 부위 단위 시술 없음 · 후보 전부」 — 계열에서 멈추지 않는다(W2)
4. **고민에 부위가 없으면** 계열 후보 전부 + `concern_without_site` 「부위 없음 · 후보 전부」 — 원천 제품 칸 · 이름 조각으로 좁힐 수 있으면 좁힌다
5. 「부위 밖」 단위 시술로 가는 엣지는 없다 — 끝 조건은 표시가 아니라 **결과(단위 시술 부위 ∈ 앵커 부위)**로 센다

### 2-7. 단위 시술이 없는 이름 → unit-check 로(R10 · J7)

- 이름이 5단계 어느 키로도 안 풀리면 **엣지를 만들지 않고** open 「단위 시술 없는 이름」 — 「클리닉에서 하는 시술은 전부 단위 시술」이므로 **`procedure-hub-unit-check` 로 키부터**(계열이 없으면 거기서 family-check · technique-check 로). 7단계에서 키를 만들지 않는다
- 부위 단위 시술 빈자리(제모 부위 등)도 같다 — open 「제모 부위 단위 시술 없음」 → unit-check
- 시술이 아닌 이름(처방약 · 외용제 · 실리콘시트 · 경구약)은 `resolver.no_unit` 「시술 아님」 표시 — 5단계 선례 그대로
- 이름만으로 못 푸는 조합 원소(「ALA 도포·배양」 · 「진정팩」)는 추정하지 않고 원문 보관 + 「못 풂」(`unresolved_ok`)

### 2-8. 추천 조합 — 원천별 · 영업 문구 기본 제외 · 사이트 용어(R8 · R9)

- **한 노드 타입 · kind 로 원천별**, 합치지 않는다 — 고민 패키지(사이트 「추천 패키지」 · problem-combos) · 중증도 조합(최적화) · 연령 플랜 · 연간 플랜 · 비교 · 목적 레시피 · 세션 조합(순서)
- 「추천 패키지」는 6단계 패키지가 아니다(package-check §2-0) — 사이트 화면 「고민별 시술 추천」의 조합
- 구성 내림 순서: **이름 조각 → 원천 제품 칸 → 계열 후보 전부(+ 표시)** — §2-6 과 같다
- 가격 · 등급 · 기대 효과 · 순서 문장 = 원문 속성. 순서 · 간격은 8단계 메모로도
- **영업 문구(salesPitch · upsellHook) = 보관 · 기본 응답 제외**. 레시피의 환자 설명 · 비유 = 상담 문구 · 기본 포함
- 쁘띠시술 추천 패키지 = 고민 앵커 없음 + 메뉴 이름 원문 속성(J5) — 기대 효과 문장으로 「주름」에 걸지 않는다
- **사이트 용어는 동의어로** — 「추천 패키지」 · 「고민별 시술 추천」 · 등급 기본/표준/확장/종합(entry/recommended/premium/vip) · 탭 「상담 안내」(salesPitch) · 「추가 제안」(upsellHook) · 「치료 계획 참고」 · 「시술 비교」 · 「시너지 조합 찾기」(`site_terms` · `combo_kind_site_names`)

판정마다 「원천 · 칸 · 원문 · 갈래(노드 / 엣지 / 대응 · 규칙 밖 질문) · 대상(고민 id · 목적 · 단위 시술) · 내림 상태 · 표시 · 근거」를 남긴다. 형식은 `references/record-schema.md`.

## 4. 갱신 방법

1. **결정 목록 먼저** — 변경분만, 사용자 앞에는 **표 하나**(7단계는 조사 1판 R1~R11 · J1~J9 · 보강 G1~G10 을 각각 표 하나로 받았다). 셋으로 나눈다
   - **승인**: 규칙으로 답이 닫힌 것 — 완전 일치 대응 · 기존 노드 · 기존 목적 동의어 · 원천 칸에서 나온 엣지 · 기존 키로 풀리는 조합 구성 · 원천 계열 코드 어긋남(표시)
   - **원천 질문**: 정체 · 투여 경로 · 같은 시술인가(의료진 check) — 지금 값(후보 + 표시)은 넣어 두고 질문 / **규칙 밖**: 규칙으로 하나로 안 정해지는 대응 — 후보 + 질문(추천값으로 채우지 않음)
   - **최종 판단**: 새 고민 노드 · 고민 ↔ 목적 경계 · 대분류 노드 여부 · 이름(사이트 용어 vs 지도) · 앵커 없는 조합 · 엣지 원천 갈래 추가 · 대응 규칙 — 추천 + 기본값을 깔고 결정만 받는다
   - 숫자에는 **단위(노드 / 대응 행 / 엣지 / 단위 시술 쌍 / 조합)와 판**을 붙인다. 엣지 셈 단위 = 「원천 행 × 원천 시술 낱말 하나」 · 단위 시술 쌍 = 엣지마다 붙은 단위 시술 수의 합
2. **반영 = 결정만 고치고 `step7-apply.py` 재실행** — 원장 json · md 를 손으로 고치지 않는다
   - 재실행 **전에** 지금 정본을 판 사본으로 남긴다(`step7-concerns.v1.json` 식 — 회귀 비교용)
   - **새 taxonomy 칸 = `categories[]` · `subcategories[]` · `items[]` 한 줄** — 갈래(`verdict` · `kind`) · `concern` · `sites` · `purpose` · `node`. 형식 `references/record-schema.md` §1
   - **새 고민 표현** = 결정 고칠 것 없음이 정상(규칙이 푼다). 안 풀리면 ① 사전 한 줄(`concern_rules` — 외래어 · 꼬리말 · 고민 낱말 · 목적 ↔ 고민, 근거 칸 필수 · 규칙 바꾸기는 최종 판단) 또는 ② `concern_unresolved` 질문 한 줄
   - **새 목적 표현 = `purposes[].aliases` 한 줄**(새 목적이면 `purposes[]` 한 줄 — 최종 판단)
   - **이름이 안 풀림** = 5단계 키가 있는데 이름만 다르면 5단계 동의어(unit-check) 먼저. 7단계 `resolver` 는 원천 낱말 → 키 사전(`fam_kw` · `exact_overrides` · `forced_synonyms`)이고 근거 칸(`basis`)을 반드시 단다
   - **새 세션 조합 = 이름을 규칙으로(결정 없음)** · **새 등급 = `tier_label_site`** · **새 조합 종류 = `combo_kind_site_names`**(사이트 이름)
   - 5단계 정본이 바뀌어야 하면 unit-check 로 먼저 — 7단계는 재실행만
3. **점검** — 프로필 레포 루트에서

```bash

python3 $W/step7-apply.py                    # 정본 재생성(승인된 반영 때만). 시험은 --out <scratchpad> 로
python3 $W/step7-fixture-test.py             # 결정 한 줄 빼면 · 바꾸면 open 이 나오나
python3 <스킬>/scripts/check_concerns.py --work $W --out <scratchpad>/concern-check.json
```

   open 0 · stale 0 · errors 0 · fixture 전부 · 같은 입력 재실행 바이트 동일(scratchpad `--out` 두 번 → `cmp`)
   - 앞 단계 정본(step3 · 5 · 6)을 고친 뒤면 그 단계 먼저(open 0) — 7단계는 그것을 읽는다
4. **검수** — 바뀐 행 전부를 결정 · 원천 원문과 대조(읽기 전용 검수자). 대응표 **전수** 글자 대조(자동 행 = 원천 말 == 대상 이름) · 엣지를 원천 칸에서 다시 찾기 · 엣지 단위 시술 부위 ∈ 앵커 부위 전수 · 같은 상황 경로별 처리 비교 · 앞 판 사본과 행 단위 비교(지시한 행 밖 차이 = 회귀) · step3 · 5 · 6 · 원천 md5 그대로
   - **검수 기준에 가상 문장 · 미래 원천 시험을 넣지 않는다**
5. **끝 조건 = 검수 PASS + open 0 + check errors 0** — WARN 은 고친 뒤 코디 확인

## 6. 사람 질문(규칙 밖) 답 반영 방법

질문은 `step7-origin-questions.md` 의 「사람(규칙 밖 고민 표현 · R20)」 행 = 결정 `concern_unresolved[]` 한 줄(원천 · 표현 · 질문). 답이 오면 **그 행만**, 그러나 **규칙으로** 닫는다 — 행에 대상을 박지 않는다.

| 답 | 결정 | 따라 바뀌는 것(apply 재실행) |
|---|---|---|
| **기존 고민 · 목적의 다른 말** | `concern_rules.concern_words`(고민 낱말 → 노드) 또는 `loanwords` · `purpose_concern` 한 줄(근거 = 답 출처) · `concern_unresolved` 그 줄 지움 | 같은 낱말이 나오는 행 전부 · 그 표현을 쓰는 추천 조합 앵커 · 질문 목록 |
| **트리 밖 목적을 목적 노드만으로 닫음**(항산화 · 피로회복 · 면역 · 영양보충) | 규칙 바꾸기(R20 의 트리 밖 목적 조항 — `out_of_tree_purpose_kind`) = 최종 판단 | 그 목적이 나오는 행 전부 |
| **대응 없음으로 둠** | `concern_unresolved` 그 줄에 답 기록 — 행은 계속 질문으로 남는다(⚠ 「답 = 대응 없음」 상태 칸은 아직 없음 · 세우는 것은 규칙 바꾸기) | — |
| **새 고민 노드** | 최종 판단(사용자) — `extra_concern_items` 한 줄(J8 · J10 처럼 「결정 id-이름」) | 그 낱말이 나오는 행 · 엣지 · 조합 |
| **원천 쪽이 틀림** | 원천은 고치지 않는다 — 원천 수정 후보로 | — |

- 규칙으로 풀렸는데 `concern_unresolved` 줄이 남으면 apply 가 stale 로 낸다 — 지운다
- 반영 뒤 `check_concerns.py` 「원장 낡음」 0(apply 를 임시 폴더에 다시 돌려 대조) · fixture 전부
- 답이 엣지에 닿아도 엣지는 원천 칸에서만 나온다(R7) — 대응표 답으로 엣지를 만들지 않는다
