# 허브 품질 측정에서 틀렸던 것

기록 `para/projects/company/procedure-hub/log/2026-10-30-quality-eval.md` §8. 결정 `_RESUME.md` §2 2026-10-30.
측정 쪽 실수(측정기가 틀림)와 진행 쪽 실수(순서 · 범위)를 나눠 적는다. 데이터 쪽 원인(A ~ O)은 각 단계 스킬의 mistakes 에 있다.

## 측정기가 틀린 것 — 데이터는 맞았다

| # | 틀린 것 | 어떻게 드러났나 | 바로잡은 것 |
|---|---|---|---|
| Q1 | **4자 미만 원문을 「있어도 없음」으로 셌다** — 아큐탄 serious 「간독성」 | M4 원문 대조가 부분 문자열이라 짧은 말이 실버의 다른 긴 문장 속에서만 찾아짐 | 실버 원문이 4자 미만이면 완전 같음으로 대조(2차) |
| Q2 | **부위 무관 특수 부위를 부위 층에서 걸렀다** — 「점제거 → 병변 레이저」(부위 = 병변 단위) | I-01 Q030 결과 0 | 7단계 `site_free`(병변 단위 · 해당 없음)는 부위 층 거르기 통과(2차) |
| Q3 | **방향별 같은 날 값을 안 읽었다** — 「HA 필러 + RF/HIFU 같은 날」(필러 먼저 불가 · 역순 가능)을 해소 판에서 「정보 없음」으로 셈 | 해소 판 I-07 이 raw 판보다 낮음(원인 O · Q078 · Q090) | 8단계 `reading_contract` 대로 `by_direction` · options 「순서」를 읽음(2차). 데이터에는 이미 있었다 |
| Q4 | **정규화를 문서대로 · 코드대로 따로 짤 뻔했다** | 원인 M — 문서 ≠ 코드 | 측정 · 골드 · 스킬이 `semantic.json dictionary.resolve_rules` 한 칸을 읽음 |
| Q5 | **계열 옮김 표를 손으로 들고 있었다** — Q020(흉터 · 서브시전) · Q025(얼굴윤곽 · 윤곽주사)가 2차에도 틀림 | 표에 없는 옮김 결정(M8 → N4 「서브시전」 · M14 → N1 「지방분해」) | 2 · 5 · 7단계 결정 파일에서 읽음(3차 ①) — 문항 파일 바이트 같음 확인 |
| Q6 | **정답의 부위 낱말 표가 「피코레이저」의 「코」를 부위로 잡았다**(Q013 · Q031 `site_words` [코]) | 3차 검토 | 점수엔 영향 없음 · 문항 · 정답 고정이라 측정 정답은 안 고침(보고만). 7단계 R29 는 한 글자 부위 정규식으로 막음 |
| Q7 | (남음) **원인 표의 M 「정규화 문서 ≠ 코드」는 셈이 아니라 고정 1** — `quality-eval.py causes()` 가 count 1 · 예 문장을 박아 둬서, 원인 M 을 고친 2차 · 3차 리포트에도 그대로 나온다 | 이 스킬을 만들며 리포트 원인 표를 다시 셈 | 아직 안 고침(측정 경로 몫 · 채점 아님). 리포트 원인 표를 읽을 때 M 줄은 빼고 본다 — 고치면 `--write-baseline` 으로 경로 지문 갱신 |

**배운 것**: 측정 지표가 오르면 「데이터가 나아졌나, 자를 바꿨나」를 가려야 한다. 그래서 2차부터 「1차 실버 × 이 판 측정」 대조를 나란히 낸다 — 측정만 바꾼 값은 1/6 · 맞음 72 → 75 로 거의 그대로였고, 6/6 은 데이터를 고쳐서 나왔다.

## 진행에서 틀린 것

| # | 틀린 것 | 바로잡은 것 |
|---|---|---|
| P1 | **원인 수정과 골드 빈틈을 한 번에 묶었다**(코디 — 「충돌 정리 끝 → 골드 빈틈 2 + 품질 수정 한 번에」) | 사용자 목표 승인 때 순서를 「원인 14 수정 → 재측정 → 목표 확인 → 보고 → 그다음 빈틈 2」로. 묶으면 지표가 어느 수정으로 움직였는지 갈라 볼 수 없다 |
| P2 | **CC 없는 경로 하나로만 재면 I-01 정밀도가 0.95 에 못 닿는다** — 같은 고민의 다른 CC 시술이 다 「틀림」으로 | 데이터 오류가 아니라 질의가 덜 구체적인 것 — R28 CC 슬롯(코디 판단 · 1차 방식 값과 나란히) → 골드 판단 ①(골드 도구 입력 `cc?`)로 확정. 리포트는 두 경로를 나란히 |
| P3 | **처음 설계는 측정 뒤 정답이 바뀔 여지를 안 적었다** — 2단계 다파장 결정으로 7문항 정답 하위에 KTP 가 더해짐 | 정답 칸을 「원천 근거 칸(고정)」 과 「규칙으로 계산되는 칸(바뀌면 보고)」으로 나눔 — `check_quality.py rule_field_changes` |

## 되풀이하지 않은 것

- **문항 · 정답 · 채점을 고쳐서 목표를 맞추지 않았다** — 남은 4문항(Q106 · Q108 ~ Q110)은 정답 범위 ↔ 허브 응답 범위 차이라 골드 판단으로 넘겼다
- **가상 문장 시험 없음** — 문항은 샘플 · 원천에 있는 말만 · 변형은 규칙으로 만든 것만(V0 ~ V4)
- **의료진 질문 문항은 목표 계산 밖 · 고정** — 판마다 빼는 문항을 바꾸면 비교가 깨진다
