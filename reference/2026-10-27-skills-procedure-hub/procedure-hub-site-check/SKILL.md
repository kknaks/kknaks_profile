## 2. 판정 순서

문자열 하나마다 위에서부터. **앞에서 끝나면 뒤로 가지 않는다.**

1. **이름 칸인가** — `references/name-fields.md` 17칸(시장가 메뉴 이름 · 고민 메뉴 대분류 · 영문 · 중분류 · 항목 이름 · 꼬리표 · 고민 패키지 · CC 묶음 · CC · CC 꼬리표 · 고민 조합 · 용도별 중분류 · 항목 이름 · 꼬리표 · 위험 부위 zone id · name_ko · name_en)
   - **설명 문장이면 부위 아님 — 세지 않는다**(작용기전 · 적응증 설명 · 부작용 · 문헌 · 안전 본문 · 사후관리). 행도 만들지 않는다
   - 새 파일 · 새 키가 이름 칸이면(메뉴 · 분류 · 시술 · zone 이름 · 짧은 꼬리표) `name_fields` 한 줄 추가를 결정 목록에 올린다(승인 항목)
2. **몸 겉에서 가리키는 자리인가** — 「이 사람이 여기에 맞으러 왔다」고 말할 수 있는 자리(외피 · 체표). 뼈 · 근육 · 혈관 · 신경 · 조직층 · 내부 구조는 부위 아님 → 4 의 행선지
   - 단 이름 칸의 근육 이름이 **상담 말**이면 자리다(승모근 — 노드 이름 그대로). 이름 칸의 해부학 이름이 같은 겉자리를 가리키면 그 노드의 「해부학 이름(속성)」(forehead · 비순구 · neck)
3. **어디로 가나** — 넷 중 하나
   - **기존 노드 이름 · 동의어** — 같은 자리의 다른 말(구어 · 외래어 · 영문 · 의학). 예: 브라라인 → 등 · 페이스 → 얼굴 · 하관 → 턱(묶음) · 러브핸들 → 옆구리 · 턱라인 → 턱선. 묶음 ↔ 좁은 노드는 경계 규칙(§3-5)
   - **부위 + 다른 축(D-07)** — 이름에 고민 · 계열 · 제품 · 대상 속성이 붙어 있으면 부위는 노드로, 다른 축은 떼어 `handoff[{part, axis, stage}]` 로. 예: 팔자주름 → 팔자 + 주름(7단계) · 사각턱보톡스 → 사각턱 + 보톡스(2단계) · 코조각주사 → 코 + 조각주사(2단계 계열 지방분해 주사) · 헤어라인반영구 → 두피 + 반영구 · ‹부위›라인 → 부위 + 라인(7단계)
   - **여러 부위(나열)** — 칸 하나에 부위 둘 이상. 예: 볼/관자놀이 → 볼(묶음) · 관자놀이 · 턱/턱선 → 턱(묶음)
   - **새 노드** — D-05 둘 중 하나라도: ① 원천이 그 자리를 **이름 칸에서 따로 부른다** ② 가능 시술이나 안전이 그 자리에서 달라진다. **둘 다 아니면 쪼개지 않는다**(동의어). 예: 등 · 옆구리(① 시장가가 복부와 러브핸들을 따로 매김) · 콧망울(② 비익 괴사 · 함몰 경고) · 팔 · 가슴 · 수염 · 구레나룻 · 인중 · 마리오네트 · 눈썹(① 고민 · CC 이름 칸). 상위는 이미 있는 노드
4. **부위 아님 — 행선지** — `destination: deferred` + `deferred_stage`
   - 층 · 깊이 · 대상 근육 → **4단계 기법**(진피 · 표피 · 피하)
   - 혈관 · 신경 · 합병증 · 사후관리 → **안전 정보(8단계 관계)** · 사후관리 문구(손톱)
   - 뼈 · 구조 → **작용기전 · 주입 지표**
   - 이름 전체가 제품 · 장비 → **1단계 제품**(바디써마지 · 엠페이스 · 튠페이스) / 계열 이름 → **2단계 계열**(모발이식) / 투여 경로 → **5단계 단위 시술 경로**(IV · 정맥) / 고민 · 목적 → **7단계 고민**(V라인 · 전체미백 · 전신항노화) / 비미용 적응증 → **계열 밖(비미용)**(관절치료 · 골반저근)
5. **근거 수준** — 원천 이름 칸 · 레포 파일이 값을 받치면 강, 일부면 중, 레포 밖 표준 용어집만이면 약. 약이면 **값을 넣고** `weak: true` + 의료진 질문 1줄(§3-6)

판정마다 「문자열 · 이름 칸 위치(파일#키) · 원천 문구 · 행선지 · 근거」를 남긴다(결정 `note` · `decided_by` 형식 — `references/record-schema.md`).

### 3-2. 원천은 이름 칸만

- [ ] **꼬리표(detail) 칸은 이름 칸** — 평균 7 ~ 15자 꼬리표(「콧대/코끝」 · 「등 브라라인」 · 「턱선+하관 라인 정리 전용」)

- [ ] **‹부위›살 = 부위 + 고민 「살(지방)」** — 행마다 D-07(볼살 · 등살주사 · 불독살)
- [ ] **나열 칸은 「여러 부위(나열)」** — D-07 이 아니다(v1 W6)
- [ ] **묶음 ↔ 좁은 노드** — 원천 「이마 · 눈가 · 코 · 볼 · 목」은 좁은 노드로. 묶음은 (가) 하위를 나란히 묶은 칸 (나) 위험 부위 zone 이름 (다) 해부 묶음 이름만
- [ ] **「턱」 단독 · 턱필러 · 턱보톡스 → 턱(묶음)** — 하위(턱끝 · 사각턱)는 detail 이 정할 때 5단계에서
- [ ] **얼굴 ↔ 얼굴 전체 · 바디 ↔ 전신** — 「전신」은 몸 표면일 때만 노드(「레이저 제모 (전신)」), 계통 뜻(전신항노화 · 전신재생)은 부위 아님
- [ ] **같은 글자는 같은 곳으로** — 행선지는 키(정규형 · 사전 무리) 단위. 다른 뜻이면 사전 패턴을 문맥으로 갈라 키를 나눈다(`first` · 앞뒤 막기 — 「팔(채혈 · 투여 · 자세)」 · 「눈(기관 · 동작)」)
- [ ] **고객이 부르는 이름대로** — 이름과 꼬리표가 다른 자리를 가리키면 이름 칸 문자열은 그 이름의 부위로. 예: 코조각주사 → 코(꼬리표 「콧망울 지방분해」는 꼬리표 행이 따로 콧망울)

### 3-6. 근거 약 · 질문

- [ ] **근거 약은 빈 값으로 두지 않는다 — 값 + `weak: true` + 의료진 질문 1줄** — 예: 임신선 → 복부 · 불독살 → 턱선 · 팔뚝 · 하관 → 턱(묶음)
- [ ] **해부학 이름 「약」은 노드마다 질문 1줄** — 묶음 질문 하나로는 어느 노드가 틀렸는지 답이 안 온다(v1 W5)
- [ ] **판을 옮길 때 표시도 옮긴다** — 조사 판 weak 이 결정에서 빠지면 open(가드). 틀렸던 예: 트리 밖 7행 weak 누락(v1 F2)

### 3-7. 사전

- [ ] **패턴은 낱말 경계(앞 · 뒤)를 본다** — 짧은 낱말(볼 · 코 · 목 · 등 · 입)일수록. 틀렸던 예: 「지방흡**입술**」 → 입술 · 「sub**mandibular** salivary gland」 → 하악
- [ ] **긴 복합어는 짧은 노드 이름 항목 앞에** — 같은 시작 위치면 앞 항목이 이긴다(코조각주사 122 < 코 125)
- [ ] **허용 목록에 부위 문자열을 넣지 않는다** — 허용은 open 을 조용히 지운다. 틀렸던 예: 코조각주사가 「성분 · 제품 이름」 무리에(v5 F-1)
- [ ] **영문은 대소문자 · 악센트를 접은 뒤 맞춘다** — 틀렸던 예: 「잔여 0」인데 대소문자 구분으로 50회 누락(v1 F1)

### 3-8. 끝 조건

- [ ] **끝 = 지금 원천 기준** — `step3-apply.py` open 0 · stale 0 · 결정론(같은 입력 → 바이트 같은 출력) · `step3-fixture-test.py` 6/6 · `check_sites.py` errors 0
- [ ] **가상 문장 · 해부학 목록 확장 시험은 하지 않는다** — 「새 원천이 오면?」은 구조(결정 한 줄 빼면 open 이 나오나 — fixture `remove_decision`)로 본다. 틀렸던 예: v2 ~ v4 FAIL 루프(37 · 88문장 · 표준 목록 기계 추출 발주 → 중단). 사용자 「원천에 없는 가상 문장을 왜 테스트」
- [ ] **같은 꼴 FAIL 이 판마다 나면 행을 고치기 전에 기준이 비었는지 본다**(치골궁)

## 4. 갱신 방법

1. **결정 목록 먼저** — 변경분만. 각 항목을 셋 중 하나로 나눈다(3단계는 12묶음 중 사용자 앞에 간 것 2 — U1 · U2 14건)
   - **승인**: 규칙으로 답이 닫힌 것 — 기존 노드 동의어 · D-07 분리 · 부위 아님 행선지 · 사전 패턴 경계 수정. 「추천대로」 한 번에
   - **원천 질문(의료진)**: 근거 약 문자열 · 해부학 이름 약 · 위험 부위 대응 — 값을 넣고 질문 한 줄
   - **최종 판단**: 새 노드(D-05) · 이름 칸 추가(`name_fields`) · 노드 이름 바꾸기 · 묶음 구조 변경 — 추천 + 기본값을 깔고 결정만 받는다
   - 질문에는 **원천 문자열 그대로**와 이름 칸 위치를, 숫자에는 **단위(문자열 / 등장 회 / 칸 / 노드)와 판**을 붙인다
2. **반영 = 결정 · 사전만 고치고 `step3-apply.py` 재실행(결정론)** — 원장 json · md 를 손으로 고치지 않는다. 스크립트에는 고정 숫자 assert 가 없다(셈은 결정에서 계산)
   - 재실행 **전에** 지금 정본을 판 사본으로 남긴다(`step3-sites.v5.json` 식 — 회귀 비교용)
   - **새 문자열 = `step3-decisions.json` `strings[]` 한 줄** — `key` 는 open 에 찍힌 `[정규형, 무리]` 그대로 · `destination` · `nodes` · `kind` · `handoff` · `deferred_stage` · `weak` · `question` · `decided_by`(묶음 · 검수 · 사용자) · `note`(이름 칸 위치 · 원천 문구). 형식 `references/record-schema.md` §1-1
   - **사전 밖 형태소 open** = 부위면 사전 `entries[]` 에 패턴(낱말 경계 · 복합어는 앞에) + 결정 한 줄 / 글자 겹침이면 `residual.allowed` 의 맞는 무리에 낱말(부위 문자열 아님을 확인한 뒤) / 문맥으로만 갈리면 `residual_reviewed[]` 한 줄
   - **`out_of_scope_decision` 이 붙은 open** = `strings_out_of_scope.strings[]` 의 그 결정을 `strings[]` 로 옮긴다(새로 판정하지 않는다)
   - **새 노드** = `node_additions[]`(`{name, parent, bundle}`) · `node_ids{}` · `nodes{}`(전문의 용어 · 수준 · 근거 · 위험 부위) 세 곳 + 그 노드로 가는 문자열 행. 트리 밖 이름이면 `out_of_tree[]` 에 `basis{rule1, rule2}`(D-05 ① ②)
   - **이름 칸 추가** = `name_fields.fields[]` 한 줄(`file` · `key` · `what`) — 승인 뒤
   - **의료진 답** = 그 행의 `nodes` · `weak` · `question` 또는 `nodes{}` 의 `anatomical_*` · `danger_zone*` 만
   - **지우지 않고 표시**: 원천에서 사라진 결정은 `strings_out_of_scope` 로 · 철회한 원천 수정 후보는 `source_fix.withdrawn_v5` 식 · 판마다 `changes[]` 에 `{version, key, change}` 한 줄
   - 원천 · DEC-002 가 틀려 보이면 고치지 않고 `source_fix`(B11 · B12)에
   - **층 · 깊이 · 대상 근육 · 뼈 지표는 여기서 닫지 않는다** — deferred 「4단계」 · `handoff_note` 로 넘기고 값은 `procedure-hub-technique-check`(step4 `handoffs[]` · 값 사전)에서. 3단계를 고친 뒤 `step4-apply.py` open 도 본다
3. **점검** — 프로필 레포 루트에서

```bash
python3 <스킬>/scripts/check_sites.py --work $W --out <scratchpad>/site-check.json
```

   open 0 · stale 0 · errors 0 · fixture 6/6 · 같은 입력 재실행 바이트 동일(scratchpad `--out` 두 번 → `cmp`)
4. **검수** — 바뀐 행 전부를 결정 · 원천 이름 칸과 대조(읽기 전용 검수자). 이름 칸을 독립으로 다시 뽑아 사전이 놓친 부위가 없는지(같은 사전으로 센 「0」은 증명 아님) · 인용 키 · TA2 번호 · KMA 조회를 직접 연다 · 앞 판 사본과 행 단위 비교(지시한 행 밖 차이 = 회귀) · `step1-products.json` · `step2-families.json` · DEC · 원천 md5 그대로
   - **검수 기준에 가상 문장 · 미래 원천 시험을 넣지 않는다**(§3-8)
   - 하나가 걸리면 같은 성격을 **지금 원천 안에서** 전수한다(코조각주사 → 이름 칸에 나오는 허용 낱말 64종 전부)
