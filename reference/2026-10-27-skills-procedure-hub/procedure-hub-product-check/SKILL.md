# Procedure Hub 제품 확인 · 실버 제품 원장 갱신

실버 1단계(제품 원장, 2026-10-26~28)에서 실제로 한 방법을 옮긴 것이다. 새로 지어낸 절차가 아니다.

- 정본 원장: `orchestration/work/phub-recommend/step1-products.json`(v2 · 394행 · 검수 v4 PASS)
- 결정 정본: `orchestration/work/phub-recommend/_RESUME.md` §2 — 규칙이 바뀌면 거기가 이긴다
- 과정 기록: `para/projects/company/procedure-hub/log/2026-10-28-silver-step1-product-normalization.md`
- 도구: MFDS MCP `reference/2026-10-27-mfds-mcp/` · KPIC MCP `reference/2026-10-28-kpic-mcp/` (경로는 프로필 레포 기준)

**원장은 승인 없이 고치지 않는다.** 조사 → 결정 목록(사람) → 반영 → 검수 고리를 그대로 돈다.

## 1. 언제

| 경우 | 시작점 |
|---|---|
| ① 새 제품 1건 추가 | 이름 하나 → §2 찾는 순서 전부 → §3 판정 → 새 행 |
| ② 정기 점검 | `scripts/recheck_licenses.py` 로 연결 허가 전부 재조회 → **변경분만** §3 판정 |
| ③ 외부 소식(수입 중단 · 철수 · 허가 취소 보도) | 해당 행만 §2(특히 업체 · 현 수입사) 재조사 → 소식은 근거일 뿐, 허가 상태는 식약처 · emedi 로 확인 |

정기 점검:

```bash
MFDS=reference/2026-10-27-mfds-mcp
$MFDS/.venv/bin/python <스킬>/scripts/recheck_licenses.py \
  --ledger orchestration/work/phub-recommend/step1-products.json \
  --mfds-dir $MFDS --out <scratchpad>/recheck.json            # --limit N · --ids a,b · --no-emedi
```

결과 `changes[].flags` = 취소·취하 / 수출용 / 유효기간 만료. v2 기준 연결 허가 196행 · 327건(의료기기 281 · 의약품 46) → 식약처 호출 327 + emedi 281(식약처 일 한도 안).
이 스크립트는 **연결된 허가만** 본다 — 새 허가 · 수입사 교체로 생긴 허가는 못 찾는다. 「허가 취소(이력)」 · 「확인 불가」 행은 ③처럼 §2 로 다시 찾는다.

## 2. 찾는 순서

앞 단계에서 0건이어도 멈추지 않는다. **이름 질의 0건은 「허가 없음」이 아니다** — 업체 단위 전체 목록까지 본 뒤에야 「못 찾음」이라 쓴다.

1. **이름** — 한글 · 영문 · 띄어쓰기(Bellasonic ↔ BELLA SONIC) · 점 표기(고우리 ↔ G.O.U.R.I.) · 대소문자(모델명은 대소문자 구분) 변형
2. **업체명** — 제조사 · **현 수입사** · **이전 수입사** 각각의 허가 전체 목록. 수입사가 바뀐 제품은 여기서만 나온다(젠틀맥스 = 신한씨스텍 → 시너론켄델라코리아)
3. **모델명** — 브랜드 ≠ 모델명인 경우(18-338 은 카탈로그 번호 9914-00-9035). 공식 사이트에 허가번호가 적혀 있으면 번호로 질의
4. **품목 · emedi 상세** — `xprtppYn`(수출용에 한함) · 비고 · 취소취하 · 유효기간 · 모델 목록 · 사용목적. API 에 없는 칸이라 연결 전에 반드시 연다
5. **의약품은 KPIC** — 이름 검색(부분 일치라 엉뚱한 1위 주의) → 없으면 **성분 역조회**. 외래어 표기 차이(컨트라투벡스 → 콘투락투벡스겔 · 라엔넥 → 라이넥주)
6. **국내 유통** — 피부과 · 병원 홈페이지 · 병원 가격 자료(data-anyang) · 제조/수입사 공식 · 보도. 「허가번호 미확인」 · 「허가 대상 아님」 판정의 근거
7. **해외 공식**(FDA 등) — 성분 공식명 · 장비 등급 확인용. **국내 허가 증거가 아니다**

질의는 전부 기록한다(질의 → 건수). 형식과 호출 방법: `references/query-patterns.md`.

## 3. 판정 규칙 — 체크리스트

상세 · 근거 결정: `references/rules.md`. 틀렸던 사례 전체: `references/mistakes.md`.

- [ ] **정상 허가에만 연결** — 틀렸던 예: 디클래씨가 취소 허가 23-60 에 붙어 「취소」 → 정상 11-1324 가 따로 있었다
- [ ] **취소 · 취하 · 만료는 `history`** — 정상 없이 이력뿐이면 「허가 취소(이력)」 · 추천 제외. 틀렸던 예: 지우면 같은 조사를 반복한다(인트라셀 09-682 2026-08-31 만료)
- [ ] **수출용(「수출용에 한함」)은 연결 안 함 · `reference`** → **같은 업체의 내수 허가 재탐색**. 틀렸던 예: 슈링크가 수출 허가 3건에만 붙어 있었다 → 내수 14-1422
- [ ] **재제조는 정품 아님 · `history`** — 틀렸던 예: 젠틀맥스 프로+ 를 재제조 26-194(밴스로컬)에 연결
- [ ] **비침습 ≠ 허가 대상 아님** — 「허가 대상 아님」은 출처가 있을 때만. 틀렸던 예: 출처 없던 41행 재조사 → 출처로 확정 0
- [ ] **허가번호 미확인은 추천에 넣는다** — 실재 · 국내 유통 출처는 있는데 번호만 못 찾은 경우. 예: 모르페우스8 · NCTF 필로르가 등 7행
- [ ] **이름 3칸** — 대표(한글 1) · 허가 이름(허가 쪽에만) · 검색 이름[](한/영 표시만). 이유는 `name_basis` 에만. 틀렸던 예: 검색 이름에 「(오기)」 꼬리
- [ ] **라인 / 품목** — 같은 허가를 여러 원장 이름이 가리키면 같은 제품이면 합치고, 아니면 라인 + 품목. 예: 온다 품목 3
- [ ] **같은 성분 · 용량만 다른 허가는 한 제품** — 예: 보톡스 50 · 100단위
- [ ] **업체 역할 여러 개** — 제조 / 수입 / 판매(여럿). 틀렸던 예: 더채움 「휴젤」은 제조사가 아니라 판매사
- [ ] **1단계는 제품 ↔ 허가만** — 「이 장비로 무슨 시술」은 5단계. 예: 온다 PRO 품목 「전기 수술기」 그대로
- [ ] **추정 금지** — 근거(URL · 질의) 없는 칸은 「근거 없음」. **사람이 한 말도 출처가 없으면 추정**. 틀렸던 예: 에이비오톡신 자동 연결 · 라라젯 「미용기기 전환」
- [ ] **외국어 이름이 정확히 일치하지 않으면 사람에게** — 예: 벨라소닉 ↔ BELLA SONIC 2X

상태 6종과 추천: 정상 · 허가 대상 아님(출처 또는 국내 유통 표시) · 허가번호 미확인 → `recommendable: true` /
확인 불가 · 허가 취소(이력) · 미허가 → `false`. 합침 · 빠짐 행은 `active: false` · `recommendable: false`.

## 4. 갱신 방법

1. **결정 목록 먼저** — 변경분만, 묶음 단위로. 각 항목을 셋 중 하나로 나눈다
   - **승인**: 규칙으로 답이 나오고 추천이 있는 것 — 「추천대로」 한 번에
   - **원천 질문**: 병원 · 원천만 아는 것(「피코코어는 블루코어 피코어인가요?」) — `step1-origin-questions.md` 식 한 줄
   - **최종 판단**: 사람만 확인할 수 있는 것 — 기본값(확인 불가 · 추천 제외)을 깔고 결정만 받는다
   - 질문에는 **제품 이름**을 넣고, 숫자에는 **단위(묶음 / 행 / 허가)** 를 붙인다
   - 근거가 충분해도 **승인 전엔 추천에 넣지 않는다**(검수 v3 G1)
2. **반영** — 레코드 스키마(`references/record-schema.md`)대로 행 추가 · 변경
   - **지우지 않고 표시**: 합침 `merged_into` / `merged_from` · 시술 이름으로 빠짐 `moved_to` · 끊긴 허가 `history` · 수출용 · 후보 `reference`
   - 칸을 옮기면 **옛 칸 삭제까지** 한 작업(v3 FAIL 원인: 옛 `3_line` 에 수출용이 「정상」으로 남음)
   - `summary` 수치 재계산 · 원장 업체 · 이름 오기는 원천 수정 목록(`step1-source-fix`)에 추가
3. **apply-log 한 줄** — 결정마다 「`ledger_id` 이름 — 무엇을 — 근거 결정」(`step1-apply-log.md` 형식). 반영은 스크립트로 결정론, 입력은 고정본
4. **검수** — 표본이 아니라 바뀐 행 전부를 원천 · 결정표와 대조(읽기 전용 검수자). FAIL 이면 고쳐서 다시
5. **새 행 · 허가 품목이 바뀐 행 → 계열 판정은 `procedure-hub-family-check`**(실버 계열 원장 `step2-families` 갱신)
6. **새 제품 → 단위 시술 상속(쓰는 제품 · 기법 근거)은 `procedure-hub-unit-check`** — 계열 · 기법 판정이 끝난 뒤 추천 가능 제품이 이어질 단위 시술이 있나(없으면 키를 세우거나 예외 원천 질문) 그 스킬로 step5-units 를 갱신한다

## 5. 출력 형식 — 변경 보고

```markdown
## 제품 원장 변경 보고 (YYYY-MM-DD · 대상 N행 / 허가 N건)

### 신규 (N행)
- `<ledger_id>` <대표 이름> — 상태 <6종> · 허가 <번호(상태)> · 제조 <> · 수입 <> · 판매 <> · 추천 <예/아니오> — 근거 <질의 · URL>

### 상태 변경 (N행)
- `<ledger_id>` <대표 이름> — <전 상태> → <후 상태> · <허가번호> <취소/취하/만료/수출용/재제조> <날짜> — 근거 <API · emedi 상세>

### 추천 여부 변경 (N행)
- `<ledger_id>` <대표 이름> — 추천 <예 → 아니오> · 이유 <규칙>

### 사람에게 물을 것 (승인 N · 원천 질문 N · 최종 판단 N)
- [승인] <제품 이름> — <한 줄: 무엇이 · 왜 · 추천>
- [원천 질문] <제품 이름> — <병원에 물을 한 줄>
- [최종 판단] <제품 이름> — 기본값 <확인 불가 · 추천 제외> · <확인할 것>
```

변경이 0 이면 「변경 0 — 허가 N건 재조회(질의 기록 경로)」 한 줄로 끝낸다.
