## 2. 판정 순서

원천 행(원장 항목 · 시장가 · 메뉴) 하나마다 위에서부터. **앞에서 끝나면 뒤로 가지 않는다.** 상세 `references/key-rules.md`.

### 2-1. 원장 항목 행선지 — 9종

1. **1단계 정본 제품 · 장비 행인가**(L1 active · L2 합침) → 「제품」. 그 장비 이름이 시술을 부르면(이어질 키가 없을 때 · §3-4) 「제품 + 단위 시술」 + `uses_product: true`
2. **여러 시술 조합 · 프로그램 · 큐레이션**(L7 「A + B」) → 「6단계 패키지」 — 구성은 6단계(넘김 표시만)
   - **묶음 판정(패키지인가 · 구성 · 회차 · 시그니처 · 가격)은 `procedure-hub-package-check`** — 거기서 「단위 시술」로 판정되어 돌아온 행(한 장비 다중 모드 · 같은 키 두 제제)은 이 스킬에서 그 키 동의어로
3. **하위 계열 · 재료 이름 / 기법 이름**(L8 · L9) → 「다른 단계 이름」 + `resolve`(그 하위 · 기법의 키 전부 — 조회 때 후보)
4. **시술이 아닌가**(행위가 아님 — DEC-002 D-02) → 외용 성분 = 「값」(M15 외용제 성분 · 사후관리 권장 제품) · 8단계 확인 조건 약물 = 「시술 아님(다른 단계)」 · 처방약 = 「시술 아님」. **버림은 없다**
5. **2단계 원장님 문의** → 「원장님 문의」(답 오기 전까지 단위 시술 없음)
6. 그 밖 = **시술**(L3 · L5 · L6 · L11) → 「단위 시술」 → §2-2

시장가 행은 `kind` — 시술 1회(단위 시술 + 제품 / 등급 + 규격) · 6단계 패키지 · 계열 밖. 메뉴(`problem_P1`)는 단위 시술 이름.

### 2-2. 시술이면 전부 단위 시술 — 계열부터

- **클리닉에서 하는 시술은 전부 단위 시술이다.** 계열이 없다고 시술을 빼지 않는다(10-29 원칙 — 조사의 「계열 밖 · 0」 추천이 사용자 「카복시 · 반영구는 시술 아니야?」에 뒤집힘)
- 2단계 계열 24(M1~M17 · N1~N7) 어디에도 안 들면 **`procedure-hub-family-check` 로 계열부터** — 기준은 2단계 그대로(17 정의 밖 + 문헌 독립 분야 · PMID 실재 확인 · 근거 수준 `evidence_level`). 예: N2 카복시테라피 · N3 반영구 화장 · N4 피부 소수술 · N5 태반 추출물 주사 · N6 성장호르몬 주사 · N7 펄스 전자기장 치료
- 계열에 맞는 기법이 없으면 **`procedure-hub-technique-check` 로 기법도** — K13 미세색소주입(N3) · K06 정의 넓힘(N7)
- 정체가 원천으로 안 닫히면 **웹 조사(논문 · 전문 자료 · 제조사 · 허가) + 근거 수준** — 그래도 안 닫히면 가장 가까운 기존 키 동의어 + 원천 질문(`references/origin-questions.md`)
- 유일한 예외: **시술 범위 자체**가 의심되는 행(줄기세포 관절치료) → 단위 시술 없음 + 의료진 질문 — 새로 이 갈래로 보내려면 최종 판단

### 2-3. 키 — 계열 × [안 C 하위 · 성분] × 부위 × 기법

- **하위는 「무엇을」을 바꾸는 계열만**(M5 · M8 · M9 · M13), **성분은 M16 만** — 재질 · 성분 차이(M2 · M3 · M4 · M7 · M15)는 제품 속성(J1 안 C)
- 성분을 모르면 `ingredient: 미상` + `ingredient_of: <원천 이름>` — 키는 세우고 짐작하지 않는다(U7)
- 기법 = 원천이 부르는 **가장 좁은 노드**, 없으면 4단계 계열 기본(스킨보톡스 · 다한증 = K01a · 토닝 = K04a)
- **키를 만드는 원천 = 이름 칸만**(원장 이름 · detail · 시장가 이름 · 메뉴 · 1단계 moved_to) — 적응증 문장 · 고민 트리 · zone 은 키를 만들지 않는다 · **전 조합을 만들지 않는다**
- 이미 같은 키가 있으면 새 키가 아니라 그 키의 동의어(`ledger[].units` · `market[].units` 에 기존 id)

### 2-4. 부위 — 기본값 · 해당 없음 · 병변 단위

- 원천 이름이 부르는 부위 노드(step3) — 「원천 이름」
- 부위 이름 없는 **얼굴 계열** = 얼굴 전체 + `site_basis` 「기본값 …」(J2 — 의료진이 바꿀 수 있게)
- **몸 계열**(M10 · M14 · N1)은 기본값 없음 — 이름 해석 모호 = 후보 전부(`role: 후보`)
- 수액 · 전신 투여 = **「해당 없음」** + 투여 경로(M16 · N5 · N6)
- 원천이 병변 수 · 면적으로 값을 매기면 **「병변 단위」**(점 1개 · 문신 10cm² · 쥐젖 1개 · 켈로이드) — 얼굴 전체 기본값은 틀린다
- 묶음 부위 이름(「턱보톡스」)은 키를 만들지 않는다 — 묶음 아래 키 전부 후보

### 2-5. 이름 · 동의어

- C1 「부위 + 상담 용어」 · C2 수액 「성분 + 수액」 / 「원천 이름 수액(성분 미상)」 · C3 같은 이름 둘이면 매질 미지정 쪽 「(매질 미지정)」
- 원장 · 시장가 · 메뉴 · 1단계 시술 이름 · 저장 장비 이름 = 동의어 · 여러 키를 부르는 이름 = 후보 전부 · **이름이 키와 어긋나면 후보 동의어로 낮춘다**(재생팩 → 필링 후보 · W2)

### 2-6. 붙는 것 — 키를 가르지 않는다

쓰는 제품(§3) · 시장가(시술 1회 + 제품 / 등급 + 규격 · 회차 `sessions` · 「/」 나열 = 부위마다 같은 가격) · extracted · PIH(원천 없음 = 값 없음 표시 · 추정 안 함) · 운영 정보 · 마취(계열 상속) · 4단계 속성 · 용량(붙을 키 없으면 8단계) · 목적(7단계 넘김 표시만). 6 · 7 · 8단계는 **넘김 표시만**.

판정마다 「원천 id · 원문 · 행선지 · 키(계열 · 하위 · 성분 · 부위 · 기법) · site_basis · 근거(결정 행 · 원천 필드)」를 남긴다. 형식은 `references/record-schema.md`.

### 2-6b. 안전 원문 · 부작용 덮어쓰기 값(2026-10-30 · 품질 원인 J · 골드 빈틈 ①)

허브 품질 측정 1차의 M4(원천 안전 문장 → 실버 전수 대조)에서 원천 안전 항목 1,548 중 229 가 실버에 없었고, 그중 223 이 원문만 없는 것이었다 — 5단계 `extracted[]` 가 원장 항목의 extracted **키 이름만**(`safety.common` …) 들고 문장은 안 실었다. 골드 조사도 같은 빈틈을 찾았다: 시맨틱 U2 「제품 · 단위 시술 부작용이 계열 부작용을 덮어쓴다」의 **덮어쓸 값이 실버에 없었다**(골드 G9 · D-07 은 처음에 「적재가 브론즈 원문을 읽는다」로 썼다가, 실버에 값을 싣는 쪽으로 정정 — SPEC-005 §3-0).

1. **`source_text`(원인 J)** — `extracted[]` · `taxonomy_products[]` 행마다 원천 extracted 의 `safety.*` · `aftercare` 칸 원문을 **그대로**(`SAFETY_KEYS = ('safety', 'aftercare')` · 고치지 않음 · 칸 이름 그대로). 붙는 곳이 없는 원문 보관 행(값 · 6단계 패키지 · 시술 아님 · 원장님 문의)도 `source_text` 에는 있다
2. **`side_effect_override`(골드 빈틈 ①)** — `source_text` 의 `safety.*` 값을 그 행이 **붙는 수준**에 싣는다: 제품 × 계열(× 키 하위) → `product_links[].side_effect_override[]` · 단위 시술(후보 포함) → `units[].side_effect_override[]`. 행 = `{source, id, name, level, values{common · serious · long_term …}, sub_family?, override_of: family:{계열}, priority}`
   - **우선순위**(`side_effect_override_rule.priority`): 제품 × 계열 × 키 하위 > 제품 × 계열 > 단위 시술 > 단위 시술 후보 > 계열(8단계 `safety.side_effects`). 덮이는 계열 값은 지우지 않고 `override_of` 로 근거만
   - **합병증 노드는 덮지 않는다** — 덮는 것은 부작용(흔한 예상 반응)뿐(사용자 10-29 「부작용 ≠ 합병증」)
   - 1단계 합침(`merged_into`)이면 활성 제품으로 따라간다 · 원문 보관 행은 붙는 곳이 없어 안 실음(셈 「안 실음(원문 보관(…))」)
3. 셈은 `step5-units.json` `summary.side_effect_override`(행 수준별 · product_links 행 · units 행) — 숫자를 여기 박지 않는다

예(지금 정본): 원장 「보톡스(엘러간)」(M1-2-1) → 제품 × 계열 덮어쓰기 common 「주입부위 부종 · 약간의 통증 · 멍 · 두통」 · serious 「안검하수(눈꺼풀 처짐) · 비대칭 표정(드문 경우)」 · `override_of` family:M1 / 원장 「주름」(M1-3-1) → 단위 시술 이마 보톡스(U5-001)에 common · serious · long_term 「반복 시술 시 1.5% 교근 섬유화 위험」.

## 3. 제품 상속 규칙

상세 `references/inheritance-rules.md`. **저장은 원천만, 상속은 기법 근거로.**

### 3-1. 저장 uses_product — 원천이 「이 제품 × 이 시술」을 부를 때만

시장가 이름 · 원장 장비 행(「제품 + 단위 시술」) · 1단계 메뉴명(`extra_stored`). 품목을 부르면 품목, 라인을 부르면 라인(S7).

### 3-2. 조회 때 상속 — 계열 · 키 하위 · 기법 근거 셋 다

계열(주 · 보조) 같음 · 키 하위가 있으면 같은 하위(주 · 보조) · **그리고 그 제품이 그 키의 기법을 낼 근거**:

1. **제품 출처가 목적을 채우면 잇는다** — 단위 시술 0 이 아니어도(`product_evidence` · 문구 · 필드 그대로). 대상 = 매질 미지정 K04 목적 키(겨드랑이 · 전신 레이저 제모 · 병변 레이저). 「제모 · 체모」 → 제모 키 · 「문신 · 타투 · 점 제거 · 검은점」 → 병변 키. 「색소성 병변」 · 「기미」만 · 오기 표기 · 정체 미상 기기의 계열 기재는 근거 아님(`product_evidence_excluded`)
2. **기법 안 갈리는 계열**(키 하위 없음 · 4단계 `also` 없음)은 계열 전부(S7)
3. **계열 기법이 하나면 계열 기본이 근거**(M9 K05 · M13 K07 — 정의상 호환)
4. **계열 근거**(`family_evidence`) — M15 하위 → K09 / K11 / K10 · M4 성분 하위 = K01a · 하위 없는 장비 = K01c · M5 / M17 1단계 종류(의약품 K01 · 화장품 K09)
5. **장비 속성**(M8) — 4단계 `technique_hints` 가 기법 조건(`requires` — K04a 펄스 · K04b 프락셔널)을 채움
6. **매질 일치는 매질이 기법을 정할 때만** — 그 매질의 키 기법이 갈리거나(알렉산드라이트 K04a · K04b · M5 엑소좀 K01 · K09) 조건이 있으면 근거 아님 → 위 3 · 4 · 5 · 1 이 채울 때만
7. **「확인 불가」 제품은 출처로만**(`product_map`) — 주입 출처 → K01 · 도포 출처 → K09 · 없으면 0 + 원천 질문. 도포로 추정하지 않는다
8. **도포 가드**(U5 · 4단계 H13) — ASCE+ · EXOSOME SKIN = K09 만(저장 · 상속 둘 다)
9. **근거 없으면 상속 안 함** — `technique_excluded[{unit, reason}]` 로 남는다. 장비 속성이 조건과 어긋나면 뺀다

### 3-3. 하위 키 매질만으로 부족한 경우 — 실제

- 젠틀맥스 프로 플러스(알렉산드라이트 · 장비 속성 없음): 알렉스토닝 K04a · 알렉산드라이트 프락셀 K04b = 「매질만 · 기법 근거 없음」 → 빠짐 / 엔디야그 키(보조 매질 · 매질이 기법을 정함) · 제모 · 병변 키(제품 출처) → 이어짐
- 같은 알렉산드라이트라도 롱펄스 장비(노블린 · 아포지 엘리트 플러스 · 클라리티2)는 장비 속성이 K04a 조건과 어긋나 빠짐
- 엔디야그 × K04a 는 매질로 충분 — 펄스 사전 3값을 다 허용해 조건이 아님

### 3-4. 추천 가능 제품인데 단위 시술 0 — 예외 목록뿐

「클리닉에서 쓰는 장비 → 시술은 전부 단위 시술」. 1단계 `recommendable` 제품이 저장 · 상속 둘 다 0 이면 ① 이어질 키를 세운다(원장 장비 행 「제품 + 단위 시술」 — 브이빔 · 온다 · 소프웨이브 · ASCE+ · AAPE · 루비 · KTP) ② 출처로 시술 방식이 안 닫히면 **예외** = 원장 행 `origin_question`(원천 질문) ③ 계열 밖(진단 장비)은 그대로. 예외 결정 없으면 open.
지금 5 = 진단 장비 2(3D 메타뷰 · 마크뷰) + 예외 3(셀엑소좀 · 미라셀 · 스마트자이드).

   - **새 키 = `units[]` 한 줄**(다음 `U5-NNN`) — `key` · `name` · `site_basis` · `attrs` · `notes` · `evidence_level` · `decided_by`. 원천 근거(원장 · 시장가 · 메뉴 행이 그 id 를 가리킴)가 없으면 open
   - **새 시장가 = `market[]` 한 줄** · **새 메뉴 = `problem_P1[]` 한 줄** · **새 넘김 = `handoffs.<출처>` 한 줄**
