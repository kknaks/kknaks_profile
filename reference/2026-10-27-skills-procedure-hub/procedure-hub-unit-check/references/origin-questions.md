# 원천 질문 다루는 법 — 묻고, 지금 값을 넣어 두고, 답이 오면 그 행만

출처: `orchestration/work/phub-recommend/step5-origin-questions.md`(`step5-apply.py` 산출) · 결정 `step5-decisions.json` `ledger[].origin_question` · `market[].origin_question` · `market[].staff_question` · 기록 §3-5 · §6 · `_RESUME.md` §2 10-29(U7 · F4 · F5 · 반영 확인 ③).

## 1. 원칙

- **물어도 비워 두지 않는다** — 원천 질문을 낸 행에도 지금 값(가장 가까운 키 · 「미상」 · 근거 약 표시)을 넣어 둔다. 질문은 값을 막는 게 아니라 값의 확실성을 표시한다
- **추정으로 채우지 않는다** — 모르는 성분은 「미상」, 안 닫힌 시술 방식은 상속 0(예외), 약한 근거는 `evidence_level` 「약」
- **답이 오면 그 행만** 다시 판정한다 — 결정 한 줄 고침 → `step5-apply.py`. 다른 행으로 번지면 그건 새 결정 목록
- 질문은 1 · 2단계 질문 파일(`step1-origin-questions.md` · `step2-origin-questions.md`)과 따로 — 5단계는 건드리지 않는다
- 질문에는 **원천 원문 · 파일 · id · 지금 값**을 붙인다(산출 형식 「… — `<id>` · 지금: <키 · 표시>」)

## 3. 의료진 질문 — 시술 범위

- 「피부 · 미용 시술 범위 밖인가」처럼 **범위 자체**를 묻는 행은 계열을 늘리지 않고 의료진에게 — `market[].staff_question`
- 지금 1 — 줄기세포 관절치료(시장가 1행): 단위 시술 없음 · 가격 원문만 보관(반영 확인 ③ 사용자 「빼자 일단 의료진 질문으로」)
- 이것이 「클리닉에서 하는 시술은 전부 단위 시술」의 유일한 예외다. 새 행을 이 갈래로 보내려면 최종 판단(사용자)

## 4. 2단계 원장님 문의 — 5단계는 기다린다

- 2단계 `pending_director` 행(알렉스필 · 벨르업 · 더마큐어)은 답 오기 전까지 **단위 시술 없음** — 원장 행 `dest: 원장님 문의` · `product_links.link` 「원장님 문의(계열 없음)」
- 답이 오면 2단계(`procedure-hub-family-check`) 먼저 → 5단계 그 행

## 5. 답이 왔을 때 — 순서

1. 답을 원문 그대로 `_RESUME.md` §2 에 한 줄(코디) — 답한 사람 · 날짜
2. 그 답이 바꾸는 행만 결정 목록에(`SKILL.md` §4 형식):
   - 성분 확정 → `units[].key.ingredient` 를 성분 이름으로 · `ingredient_of` 지움 · 이름 C2 · 같은 성분 키가 이미 있으면 **합침**(새 키 대신 그 키 `units`)
   - 정체 확정 → 그 계열 · 하위 · 기법 키(없으면 §2-3 순서로 세움) · `evidence_level` 지움
   - 투여 방식 확정 → `family_evidence[].product_map` 에 제품 한 줄(`techniques` · `basis` 답 원문) · 예외(`origin_question`) 지움 → 상속이 생겼는지 `check_units.py` 로 확인
   - 프락셔널 확정 → 2단계 hint · 4단계 `technique_hints` 에 가능 방식이 먼저(그 단계 스킬) → 5단계는 재실행만
   - 범위 밖 확정 → `dest` 그대로 · 질문 지움 · note 에 답
3. `step5-apply.py` → open 0 · `check_units.py` → errors 0 · 질문 수가 줄었나(`summary.origin_questions`)
4. 답이 1 · 2 · 4단계 정본을 바꾸면 그 단계 스킬로 먼저(앞 단계 정본 보강도 그 단계 결정 파일 · 스크립트로 — 10-29 듀오 하이드로젠 · 파셀라 · 계열 24 · K13)
