## 2. 판정 순서

앞 단계에서 답이 나와도 **문헌 정의 대조(5)와 근거 수준(7)은 건너뛰지 않는다.**

1. **허가 품목명 · 사용목적** — 1단계 행 `4_license.licenses[]`(정상 · 내수 허가만)의 `item` · 모델명. 사용목적 · 원재료는 emedi 품목 상세(`meddevItemSeq`)를 연다
   - `reference[]`(수출용 · 후보) · `history[]`(취소 · 재제조)의 허가는 **보지 않는다** — 1단계가 「연결 안 함」으로 둔 허가다
   - 허가 대상 아님 · 허가번호 미확인 행은 이 칸이 비어 있다 → 2부터
2. **원천 설명** — taxonomy 항목의 `detail` · `extracted.overview` · `mechanism`(`step2-apply.py` `TAX_TEXT`). 원천 위치(어느 M 칸에 있었나)는 **참고만** — `auto-` 행은 자동 병합이 엉뚱한 칸에 넣은 경우가 있다(바넥스)
3. **제조사 사양** — 공식 사이트 · 브로슈어 · FDA 510k 원문(성분 · 매질 확인용, 국내 허가 증거 아님). 인용할 페이지는 **직접 받아 문구를 확인**한다
4. **보도 · 병원 자료** — 3 이 없을 때만. 근거 수준은 「약」이 된다
5. **문헌 정의 대조** — `references/families.md` 의 18 정의 중 어디에 드는가(「무엇을 · 어떻게 넣어/쏘아 · 무엇을 일으키나」). 경로 · 작용이 정의와 다르면 그 계열이 아니다(N1 ↔ M16)
6. **주 + 보조** — 계열도 하위도 주 1 + 보조. 주를 고르는 순서: **허가 품목 → 원천 위치 → 원천 설명 첫 원리**
7. **근거 수준** — 허가 품목 · 제조사 원문이 값을 직접 받치면 강, 보도 · 중고 사양 · 병원 문장만이면 약(+ 확인 질문). 정체를 모르면 계열도 보류(원장님 문의)

조사는 행마다 「값 + 근거 문장 + 출처(URL · 파일#칸)」를 남긴다(`step2-research.json` `rows[]` · `step2-open-resolve.json` `rows[]` 형식 — `references/record-schema.md`).

## 3. 판정 규칙 — 체크리스트

근거 결정: `_RESUME.md` §2 2026-10-28. 규칙이 생긴 이유: 기록 §3. 틀렸던 사례 전체: `references/mistakes.md`. 18 정의 · 하위 칸: `references/families.md`.

### 3-1. 기준

- [ ] **계열 = 문헌 카테고리** — `literature-evidence.json` M1~M17 + N1. 체계를 새로 짜지 않는다. 틀렸던 예: 코디의 「물질 · 에너지원 재분류」 제안 철회
- [ ] **리프팅(M9) · 스킨케어(M15)도 문헌 카테고리** — 목적 · 경로처럼 보여도 빼지 않는다. 예: M9 「Non-invasive skin tightening: HIFU and radiofrequency」
- [ ] **2단계 = 계열 + 하위까지** — 부위(3) · 기법(4) · 단위 시술(5) · 목적(6)은 `deferred` 표시만. 예: M8 「제모」는 6단계 목적, 「피코초」는 4단계 기법
- [ ] **정의 · 새 근거마다 PMID** — NCBI ESummary 로 제목 · 저널 · 연도 실재 확인. 틀렸던 예: M17 근거가 부작용 논문(28296617) 하나뿐 → 정의 리뷰 31247326 추가

### 3-2. 새 계열 · 새 하위 칸을 세우는 조건

- [ ] **새 계열 = 둘 다**: ① 18 정의 어디에도 안 든다 ② 문헌이 독립 분야로 다룬다(리뷰 인용). 예: N1 지방분해 주사 = 됨(M16 정맥 영양과 경로 · 작용이 다름 · 27785706 · 38297988)
- [ ] **제품 행이 받쳐야 세운다** — 행 1개로 계열을 세우지 않는다. 틀렸던 예: 조사가 카복시 N2 추천 → 트리필 프로 1행뿐이라 안 세움(코디), 나중에 M4 주입 기기로 닫힘
- [ ] **기존 정의를 넓혀 담을 수 있으면 넓힌다** — 같은 원리를 둘로 쪼개지 않는다. 예: LED → 새 계열 대신 M8 을 「레이저 · IPL · LED(광)」로(D04)
- [ ] **용도는 계열이 아니다** — 틀렸던 예: 「비침습 지방 감소」 계열 → 에너지대로 RF M9 · 레이저 M8 · 근육 자극 M10(D11 · X6 폐지)
- [ ] **어디에도 안 들고 독립 문헌도 없으면 계열 밖** — 가장 가까운 계열에 억지로 넣지 않는다. 1단계 행은 그대로. 예: 의약품 3(아큐탄 · 라이넥 · 멜스몬) · 진단 장비 4 · 헤어셀 = 계열 밖 8
- [ ] **새 하위 칸 = 원천 이름 그대로** — 「칸이 없으니 null」로 두지 않는다. 예: M4 「무세포동종진피(hADM)」(원천 M3 하위 label) · M9 「SUPERB 초음파」(소프웨이브). 틀렸던 예: 「칸 안 만듦」 기본값이 hADM 6행을 v1~v3 내내 open 으로 둠
- [ ] **하위 칸은 「무엇으로」 한 축만** — 재질(M2 · M3 · M4 · M7) · 매질(M8) · 에너지(M9 · M10). 수입/국산 · 브랜드 · 형태 = 제품 속성 · 용도/부위/목적/방식 = 다른 단계 · 「기타」 「추가」 = 해체. 틀렸던 예: M8 하위에 피코초(방식)와 엔디야그(매질)가 형제 → 같은 Nd:YAG 피코가 두 칸으로 갈림(v2 W-2)

### 3-3. 하위 · 매질

- [ ] **M8 하위 = 광원 매질 12칸** — IPL · LED · 엔디야그 · 알렉산드라이트 · 반도체 · 탄산가스 · 루비 · Er:YAG · Er:Glass · 톨륨 · KTP · PDL. 표기는 식약처 품목명(Nd:YAG → 엔디야그 · 다이오드 → 반도체 · CO2 → 탄산가스), 품목명 없는 것은 원문
- [ ] **방식은 `technique_hint` 에 적힌 말 그대로** — 피코초 · 프락셔널 · 롱펄스 · Q-switched. 판정에 쓰지 않는다. 틀렸던 예: 피코코어 「나노초」는 비교 문장에서 나온 말(v3 W-a)
- [ ] **매질은 적힌 곳에서만** — 허가 품목 · 모델명 · 원천 설명 · 제조사 원문의 **매질 이름**. 파장 숫자만으로 정하지 않는다. 틀렸던 예: 소프라노 티타늄 755 · 1064nm → 알렉산드라이트 · 엔디야그 보조(「강」) → FDA 510k 원문은 세 파장 모두 diode(v4 F1). **예외 하나 — 다파장 장비(§3-3b · 10-30)**: 원천 파장마다 원천 문장 근거가 가장 많은 매질을 보조로 더한다(10-28 판의 「엑셀 V = 엔디야그 단독」은 이 규칙으로 엔디야그 주 + KTP 보조가 됐다)
- [ ] **주입 기기는 하위 없음** — M4 의 기기(큐어젯 · 미라젯 등 7 + 트리필 프로). 「어떻게」는 4단계

### 3-3b. 다파장 장비 — 원천 파장 낱말 → 보조 하위(사용자 10-30)

허브 품질 측정에서 「홍조 · 엑셀V」 · 「홍조 · V빔」 질문(Q019 · Q018)이 틀렸다 — 원천 CC 가 추천한 엑셀V(원천 「532 + 1064nm」)의 하위가 엔디야그 하나라, 7단계 R31(원천 제품 → 하위)이 얼굴 전체 KTP 레이저를 「하위 계열 밖」으로 뺐다. 사용자 판단 ③(5단계 「엑셀 V」 동의어에 U5-138 KTP)과도 어긋났다. 그래서 **위 「파장 숫자만으로 정하지 않는다」를 이 범위에서만 바꿨다**(`multi_wavelength.overrides` — v4 최종 검수의 보조 값 기준 (a)).

- [ ] **대상** — M8 제품의 원천 설명 · 원천 하위 · 허가 모델명에 「…nm」 파장이 **둘 이상**이고, 주 · 보조 하위에 원천 파장이 가리키는 매질이 **빠진** 행. 보조 하위가 이미 있어도 빠진 매질은 더한다(10-30 ⑤ 넓힘 — 처음 규칙은 「하위 하나만 잡힌 행」이라 노블린 · 클라리티2 · 아포지 엘리트 플러스 · 디스커버리 피코를 놓쳤고 사용자가 지목했다)
- [ ] **파장 → 매질은 원천 문장에서 센다** — 원천 브론즈 문장에 파장과 매질 이름이 **붙어 적힌 횟수가 가장 많은 매질**(동률이면 대응 안 함 · M8 하위 칸에 있는 매질만 · 매질 낱말은 2단계 M8 낱말과 같음 `medium_words`). 지금 표는 `multi_wavelength.wavelength_medium`(예: 532 → KTP · 755 → 알렉산드라이트 · 595 → PDL · 1064 → 엔디야그). 사람이 「532 는 KTP」라고 적지 않는다
- [ ] **주 하위가 반도체 레이저 · IPL · LED 면 손대지 않는다**(`skip_primary`) — 파장이 매질을 가리키지 않는다(셀렉V IPL · 트리니티 · 소프라노 티타늄 — v4 F1 「세 파장 모두 diode」와 같은 방향)
- [ ] **더한 매질은 보조(`also_sub_families`)** — 주는 그대로. `sub_family_basis` 에 「보조 KTP(원천 파장 532nm) — 다파장 장비(사용자 10-30)」
- [ ] **전수로 본다** — `multi_wavelength.seen[]` 이 다파장 M8 행 전부와 처리(보조 더함 · 빠진 매질 없음 · 주 하위가 매질 안 가리킴)를 남긴다. 지금 값 = 그 칸(10-30 판: 전수 22 · 보조 더함 14 · 빠진 매질 없음 5 · 반도체 2 · IPL 1)
- [ ] **바꾼 뒤 5 → 7 → 8 → semantic 재실행** — 하위가 바뀌면 5단계 제품 → 단위 시술 상속 · 7단계 R31 · 측정 정답 하위가 같이 바뀐다(측정 문항 파일에서 「정답 하위」가 규칙으로 계산되는 칸이라 7문항에 KTP 가 더해졌다 — `procedure-hub-quality-eval` 이 무엇이 바뀌었는지 보고한다)

### 3-4. 주 + 보조

- [ ] **복합 장비 · 두 재료 = 주 계열 1 + `also_families`** — 예: 바넥스프로 M10 + M9 · 하모니카 M2 + M3 · 이브타이탄 M9 + M10(19행). 틀렸던 예: 한 칸만 허용하면 복합 장비가 한 계열 추천에서 빠진다
- [ ] **하위도 주 1 + `also_sub_families`** — null + open 으로 두지 않는다. 예: 젠틀맥스 프로 알렉산드라이트 + 엔디야그 · 바이리즌 M4 PN + M2 HA(17행). 틀렸던 예: 「매질 2종이면 null」 → open 40
- [ ] **주 = 허가 품목 → 원천 위치 → 원천 설명 첫 원리** — 예: 클라리티2 허가 2종 → 원천 설명 첫 매질 Nd:YAG = 주
- [ ] **보조의 근거도 주와 같은 기준** — 파장 숫자만 · 이 제품에 **연결 안 된 허가**는 근거 아님. 틀렸던 예: 울트라V 보조 PCL 이 1단계가 연결 안 한 수출 허가 20-682 근거(v4 F2) · 트루피코 보조(파장 694 · 755 뿐)
- [ ] **보조 하위는 `{family, sub_family}` 객체** — 같은 계열 보조도 family 를 적는다(v4 W2)

### 3-5. 충돌 · 약한 근거 · 정체 미확인

- [ ] **허가 품목 > 원천 설명** — 부딪치면 주 = 허가, 원천 쪽은 보조 + `conflict` 한 줄. 지우지 않는다. 예: 셀렉V 허가 IPL ↔ 원천 Q-switched Nd:YAG(충돌 6행)
- [ ] **근거 약 = 값 + 표시** — `evidence_level: 약` + `confirm_question`. 빈 값으로 두지 않는다. 예: 실루엣소프트 PLLA(↔ PLGA 자료) · 아이콘 · 아톰 등 9
- [ ] **정체 미확인 = 계열도 보류** — family null · `pending_director` · 1단계 상태(확인 불가 · 추천 제외) 그대로. 조사 값은 `researched_value` 에만. 예: 알렉스필(필링인가 레이저 시술 이름인가) · 벨르업(출처가 사진 폴더뿐) · 더마큐어
- [ ] **지금 계열은 `step2-families.json` `family` 한 곳에서 읽는다** — 1단계 `family.code` 는 원천 위치. 틀렸던 예: 조사가 코드 칸을 읽어 4행(소프라노 티타늄 · 버츄RF · 셀리뉴 · 소노퀸) 추천 칸이 틀림 → `research_errata`
- [ ] **`auto-` 행은 위치보다 설명** — 틀렸던 예: 바넥스가 원천 M14(냉각) 칸 — 설명은 RF + 석션 → M9
- [ ] **1단계 값이 틀려 보이면 고치지 않고 `source_fix_candidates`** — 예: 셀리뉴 `1_identity.detail` 「마이크로니들 고주파」 ↔ 원천 · 웹 「모노폴라 RF」

### 3-6. 이름

- [ ] **계열 이름 = 국내 공식 출처 → 없으면 문헌 영문의 한글 + `name_status: 공식 출처 미확인`** — 상담 용어 · 원천 이름은 동의어. 예: M1 보툴리눔 톡신 · M2 성형용 필러(식약처 안전정보 원문). 틀렸던 예: `name_basis` 에 출처가 있는데 상태는 미확인(v1 F1)
- [ ] **품목명이 계열 일부에만 해당하면 `name_basis` 에만** — 예: 「안면조직고정용실」은 M7 12행 중 3행 → 동의어 X(v2 W-3)

## 4. 갱신 방법

1. **결정 목록 먼저** — 변경분만, 묶음 단위로. 각 항목을 셋 중 하나로 나눈다(2단계는 18묶음 중 9 승인 · 9 최종 판단)
   - **승인**: 규칙 · 허가 품목 · 문헌으로 답이 닫힌 것 — 「추천대로」 한 번에(예: D05 주입 기기 → M4 · D14 현장 기기 허가 품목대로)
   - **원천 질문**: 병원 · 원장님만 아는 것 — 정체(`pending_director`) · 재질 · 매질 확인(`confirm_question`). `step2-origin-questions.md` 식 한 줄
   - **최종 판단**: 계열 수를 늘림 · 계열 밖으로 빼 추천에서 빠짐 · 정의를 넓힘 · 근거가 정의 일반론뿐인 것 — 추천 + 기본값을 깔고 결정만 받는다
   - 질문에는 **제품 이름**을, 숫자에는 **단위(행 / 묶음 / 계열)와 판**을 붙인다
2. **반영 = `step2-apply.py` 입력에 결정 추가 → 재실행(결정론)** — 원장 json 을 손으로 고치지 않는다
   - 재실행 **전에** 지금 정본을 판 사본으로 남긴다(`step2-families.v5.json` 식 — 회귀 비교용. v2 · v3 사본이 그 역할을 했다)
   - 새 행 · 행 재판정: 입력 `step2-research.json` `rows[]` 에 판정 1행(`verdict` · `recommended_family` · `also_families` · `basis` · `bundles` = 새 묶음 id)
   - 하위 값: 규칙으로 나오는 것은 스크립트가 낸다(원천 하위 이름 `SUB_LABEL` · M8 매질 `m8_light` · M7 허가 품목). 안 나오면 `SUB_BY_NAME` 이름별 지정 또는 `step2-open-resolve.json` `rows[]` 해결 값(`resolve` · `basis` · `sources` · `level` · `ask` · `conflict`)
   - 새 하위 칸: `SUBS[<계열>]` 에 원천 이름 그대로 · 새 계열: 입력 `families[]` 정의 + PMID · 예외 처리(`TO_OUT` · `OUT_KIND` · `DIRECTOR`)도 결정 근거와 함께
   - 스크립트의 고정 수치 assert(`len(ITEMS) == 352` · 계열 18 · 원장님 문의 3 · 근거 약 9 · `set(RESOLVE) == OPEN_BEFORE`)는 **결정한 수치로** 같이 바꾼다 — assert 를 지우지 않는다
   - **지우지 않고 표시**: 빠진 행은 행을 두고 결정에 사유 · 정정은 `research_errata` · 1단계 오류는 `source_fix_candidates` · 원천과 부딪친 값은 `conflict` · 철회한 결정 행은 ~~취소선~~
   - 판마다 바뀐 행 표(`*_delta`)를 하나 더 남기고, md 의 지난 판 설명은 그 판의 숫자로 고정하거나 지운다(기록 §5-6)
3. **점검** — `scripts/check_families.py` 오류 0 · 새 행 0 · open 0 · summary 일치
4. **검수** — 표본이 아니라 바뀐 행 전부를 결정 · 원천과 대조(읽기 전용 검수자). 인용 페이지는 직접 받아 문구 대조 · PMID 실재 확인 · scratchpad 재실행으로 바이트 동일 확인 · 앞 판 사본과 필드 단위 비교(지시한 행 밖 차이 = 회귀) · `step1-products.json` md5 그대로
   - 하나가 걸리면 같은 성격을 전수한다(v4 F1 → 트루피코)
5. **끝 조건 = 검수 PASS + open 0** — PASS 만으로 「끝」이라 적지 않는다. 원장님 문의 · 근거 약은 open 이 아니라 질문 목록으로 남는다
6. **부위 판정은 `procedure-hub-site-check`** — 2단계는 부위를 `deferred` 표시만 한다. 새 메뉴 · 이름의 부위 문자열은 그 스킬로 step3-sites 를 갱신한다
7. **새 계열은 `procedure-hub-unit-check` 의 「계열 없는 시술」에서도 온다** — 5단계 원칙(10-29 「클리닉에서 하는 시술은 전부 단위 시술 — 계열이 없으면 계열을 늘린다」)으로 제품 행 없이 시술 원천(원장 항목 · 메뉴 · 시장가)만으로 N2 ~ N7 이 섰다(N2 카복시는 2단계에서 「제품 행 1개」로 안 세웠던 것 · 트리필 프로는 M4 그대로). 기준(17 정의 밖 + 문헌 독립 분야 · PMID · 근거 수준)은 같다. 계열을 세운 뒤 단위 시술 키는 그 스킬로

```markdown
## 계열 원장 변경 보고 (YYYY-MM-DD · 판 <전 → 후> · 대상 N행)

### 신규 (N행)
- `<ledger_id>` <대표 이름> — <계열 코드 이름> · 하위 <주>(+ 보조 <family 하위>) · 보조 계열 <> · 판정 <맞음/옮김/여러/계열 밖> · 근거 <강/약> — <허가 품목 · 원천 설명 · 출처>

### 계열 · 하위 변경 (N행)
- `<ledger_id>` <대표 이름> — <전 계열 · 하위> → <후 계열 · 하위> · 이유 <규칙 · 바뀐 원천(허가 품목 · 설명)> — 근거 <>

- <계열> 새 하위 칸 「<원천 이름 그대로>」 — 걸리는 행 N · 출처 <원천 위치>
```
