## 원칙

v2 · v3 의 원칙(KOS 사본 · KOS 가 기준 · 데모 지점에만 쓴다 · 운영 쓰기 금지 · 상담 · 수납 · 시술 추가는 상담사가 KOS 에서)은 **그대로** 이어진다. 앱에서 더해지거나 달라지는 것만 적는다.

- **앱 = iOS 만**(일단 — 사용자 지시 10-27). 한 앱 · 화면 폭으로 폰 / 태블릿 배치(S4 §1.1 그대로)
- **앱 범위 = 시안 4탭 전부(예약 현황 · 내원 현황 · 시술 현황 · 설정) + 알림 + 로그인 + 웹 따라잡기 + 상담사 계정 · 배정 푸시 + QR 문진 + 신분증 스캐너**(사용자 지시 10-27). **폰 · 태블릿 칸 = 합집합**(코디 기본값 · 이의 없음) — 한쪽 시안에만 있는 칸도 두 기기 모두에 둔다
- **앱도 예약 · 내원 현황에서 쓴다**(사용자 지시 10-27) — 시안 「보기 전용」(A:214 · 디자인 Q-1)을 따르지 않는다. 쓰기는 **웹과 같은 back API · 같은 규칙**. 단 아래 「웹에서만」은 앱에서 뺀다
- **[수납하기] · [처방전 출력] = 웹에서만**(사용자 지시 10-27) — 앱(폰 · 태블릿)은 수납 필요 · 처방전 상태를 **보기만**(버튼 없음). 10-27 「앱도 쓴다」 줄의 「수납하기」는 이 줄로 빠진다(표 위쪽 = 나중 줄)
- **웹이 정본 · 앱은 웹에 맞춘다**(사용자 지시 10-26) — 웹 / 앱 규칙 차이는 질문이 아니라 앱 할 일(R3 §10.1). 상태 이름 · 색도 웹 2계층 그대로(아래 4)
- **앱 알림 = 상담사 호출 · 의사(원장) 호출 두 가지만**(사용자 지시 10-27 「알림은 지금 상담사 호출 의사 호출만」) — 시안의 수납 필요 · 상담 시작 · 귀가 완료 · 마취 20분 · 본사 예약 요청 알림과 그 설정 항목은 뺀다
- **시안에서 뺌**(사용자 지시 10-27): [리포트 QR 전송](여정 리포트 없음) · 「본사 예약 요청」 알림 · 설정(원천 없는 항목 — AP-30)
- **앱은 KOS 를 직접 부르지 않는다** — 모든 KOS 쓰기 · 읽기는 back 을 거친다(지금 앱과 같음 · S4 §7). 아래 KOS 표는 back 이 부르는 것
- **직무별 권한 · 역할별 첫 화면은 마지막에 한 번에**(사용자 지시 10-26 ⑩ · U6) — 이번 앱 판도 역할별로 탭 · 버튼을 숨기지 않는다(AP-3)
- **법적 검토는 나중**(사용자 지시 10-27) — 신분증 이미지 보관 · 주민번호 마스킹 · 보관 기간은 PoC 동안 SPEC · 코드 주석(「법적 검토 필요: 신분증 이미지 · 주민번호 처리」)으로만 남긴다. 주석 자리는 아래 6.7

## 1. 사람 × 기기 — 하루 흐름

### 1.1 한눈에

| 사람(ccc 역할) | 데스크 웹(PC) | 폰(앱) | 태블릿(앱) | 받는 알림 |
|---|---|---|---|---|

| **데스크 기기**(사람이 아니라 자리) | 데스크 PC = 코디 · 관리자 계정 | — | **데스크 태블릿 = 코디 계정 로그인** · 고객이 문진을 채우고, 데스크가 여권을 찍는 기기 | — |

- 「데스크」 = 코디가 앉는 자리(v3 「데스크(코디)」). 사람 역할은 코디 하나이고, 기기는 데스크 PC(웹) · 데스크 태블릿(앱) · 코디 본인 폰(앱) 셋이다(10-26 「고객 입력 QR = 우리 앱 · 받는 기기 ① 데스크 태블릿 ② 코디 본인 폰 — 코디 계정 로그인」)
- **한 계정이 기기 · 웹 · 앱에 동시 로그인**(사용자 구상 10-26) — 토큰은 HMAC 무상태라 지금 구조에서 막히지 않는다 · 기기마다 푸시 토큰 등록(S4 §5-1.1 `device`). 「기기 하나에 여러 계정」은 AP-4
- 역할별로 보이는 탭 · 버튼은 **나누지 않는다**(직무별 제한은 마지막 · AP-3)

### 1.2 코디의 하루 (데스크 PC 웹 + 데스크 태블릿 + 코디 폰)

```text
 아침   데스크 PC 웹 「예약 현황」 — 오늘 표 · 공지 (웹 그대로 · v3 1)
        코디 폰 앱 로그인(코디 계정) · 데스크 태블릿 앱 로그인(코디 계정)
 고객 도착
   ├─ 웹(또는 앱) 예약 상세 「접수 전」
   │    ├─ [스캔할 기기] → 데스크 태블릿 / 코디 폰 → 앱 스캔 화면 → 여권 찍기
   │    │      → 앱 스캔 확인 → [저장] → KOS 고객 수정 + 사진(KOS · ccc) → 웹 상세에 들어옴     (6.7)
   │    ├─ [태블릿에 띄우기] → 데스크 태블릿(또는 코디 폰) 앱 문진 화면 → 고객이 채움
   │    │      → [제출] → KOS 문진 제출 + ccc 방문별 이력 → 웹 상세 건강 정보에 들어옴         (6.6)
   │    └─ 진행 경로 · [시술실 선택] → [접수 완료](웹 · 앱 같은 묶음)                          (6.2)
   ├─ 상담 필요 → 상담 대기 → [상담사 선택] → [○○ 실장 호출](웹 · 앱)
   │      → KOS 상담사 지정 + 그 실장 폰에 푸시                                               (6.3)
   ├─ (실장이 KOS 에서 상담 · 수납 · 시술 대기 전환) → 시술 구간(v2)
   └─ 귀가 대기 → 수납 필요 0 이면 [귀가 완료](웹 · 앱) · 수납 · 처방전은 **웹에서만**          (6.2)
 돌아다닐 때  코디 폰 앱 「예약 현황」 · 「내원 현황」으로 보고, 같은 쓰기(접수 · 호출 · 귀가 완료 · 취소 · 메모)
```

### 1.3 상담사(실장)의 하루 (폰 앱 + KOS 웹)

```text
 앱 로그인(상담사 계정 — AP-1 · AP-2) → 알림 권한 → 기기 토큰 등록
 코디가 [○○ 실장 호출] → 폰에 「상담사 호출」 푸시 → 누르면 앱 그 예약 상세(상담 카드)            (6.3)
 고객과 방으로 → **KOS 웹에서** [상담 시작] · 상담 기록 · 수납 · 시술 추가 · 오더 메모 · 시술 대기 전환
 앱은 사본을 읽어 「상담 · 진행」 → 「시술 · 대기」로 바뀌는 것을 보여 줄 뿐(쓰기 버튼 없음 — v3 6)
```

- 실장이 앱에서 상담 시작을 누르는 일은 **없다** — 「실장이 방에서 시작하면 자동으로 바뀜」(M:256)은 KOS [상담 시작] → 사본 조회로 바뀌는 것(10-26 「상담 구간 흐름」 줄 · 디자인 Q-4 닫힘)

### 6.3 상담사 배정 → 푸시 (새로)

원천 = 10-26 「[실장 호출] = 상담사 지정(KOS `update-reservation{counselor}`) + 앱 알림까지」 · §1 메모 「상담사가 배정되면 그 상담사 앱으로 푸시 · 의사 호출 푸시와 같은 구조 · 상담사(실장) 계정 · 역할 · ccc 계정 ↔ 직원 사본 연결(의사의 `staffId` 처럼)」 · DEC-006 D-38.

```text
 ① 코디(웹 또는 앱) 상담 카드 [상담사 선택] — 목록 = ccc 직원 사본 COUNSELOR 태그 · 시스템 계정 · 제외 env 뺌 · 「KOS-DEMO」는 데모에서 보임
                                            · 지금 상태(비어있음 / {방} 상담 중) 먼저 비어있음(R5 §5.8)
 ② [○○ 실장 호출] → back: KOS 내부 update-reservation{scheduleId, counselor} → event_log(counselor_call)   ← 지금 웹 그대로
 ③ (새) back: 트랜잭션 커밋 뒤 비동기로 그 상담사(staff)에 연결된 상담사 계정의 device 토큰 전부에 APNs 발송 · push_log
 ④ 실장 폰: 「상담사 호출」 알림 → 누르면 앱이 열리고 그 예약 상세(상담 카드)
 ⑤ 실장은 고객과 방으로 → KOS [상담 시작] (ccc 버튼 없음)
```

- **KOS 에 상담사 「호출」은 없다** — 알림은 ccc 만의 것(Q-97 · CS§6). KOS 에 남는 것은 상담사 지정(`reservation.counselor`)뿐
- 같은 구조 = S4 §5-1(APNs 직접 · Firebase 0 · JWT 40분 · 죽은 토큰 삭제 · 재시도 1회 · 잠금 화면에 고객 이름 · 국적 · 시술 이름 없음) — 그대로 쓴다
- 받는 사람 · 내용 · 누르면 갈 곳 · 다시 호출 · 다른 상담사로 바꿀 때 · 관리자도 받나 · `push_log` 에 무엇을 싣나 = **AP-14 ~ AP-17**
- **상담사 계정이 있어야 받는다** — 지금 역할 = admin · doctor · nurse · coordinator(R5 §3.4). 상담사 역할 · 계정 만드는 법 · 직원 사본 연결 = **AP-1 · AP-2**
- `KOS-DEMO` · 시스템 계정 제외 규칙은 상담사 **목록**의 규칙(10-27) — 계정 만들기도 같은 제외를 쓸지 AP-1

- 목록의 원천(서버 `push_log` 인가 · 기기 안 알림 기록인가) · 읽음 저장 · 역할에 맞지 않는 설정 항목(예: 간호사에게 원장 호출 켜기)을 보일지 · 설정 끄기의 뜻(서버가 안 보냄 / 기기만 안 울림) = **AP-15 · AP-19 · AP-20**
- 지금 S4 「배지 숫자는 쓰지 않는다」(§5-1.3) — 앱 아이콘 배지인지 헤더 종 배지인지 다르다. 헤더 종 배지는 시안대로 넣고, **앱 아이콘 배지는 그대로 쓰지 않는다**로 읽는다(AP-20)

### 6.7 여권 스캔 (새로)

원천: 10-26 「고객 데이터 = 신분증 스캔 + 문진 · 국적 · 여권번호 · 신분증 = 데스크가 앱으로 스캐너를 열어 스캔한 값」 · 「기존 고객 수정 = 내부 `update-visitor-personal-information` · KOS 값 먼저 → 고침 → 읽은 묶음 전체」 · 「신분 확인 상태 = ccc DB」 · v3 정할 것 ⑤ 「신분증 이미지 = KOS 에 올린다」 · 10-27 「스캐너 = 촬영 가이드 틀 · 기존 고객 여권 = 스캔하고 수정 · 사진 ccc · KOS 둘 다」 · 「가이드 = 마스킹 자리」 · 「iOS 만 · 스캐너 = 여권만 · 주민등록증은 스캔하지 않는다(확인용)」 · AK Q-145 코디 기본값(묶음 전체 + 바꿀 칸).

```text
 ① 시작: 데스크 웹 예약 상세 「신분 확인」 [스캔할 기기] → 기기 고르기(휴대폰 · 데스크 태블릿 — W:308-342 idle)
         (앱 예약 상세에서 바로 여는 길 · QR 로 여는 길 — AP-35)
 ② 기기 앱: 스캔 화면(S11) — 카메라 + 여권 촬영 가이드 틀
 ③ 찍기 → 기기에서 여권 값 읽기(영문 성 · 이름 · 여권번호 · 국적 · 생년월일 · 성별 · 만료일 — 읽는 방법 AP-36)
         국적 = 여권 alpha-3 → KOS alpha-2(Q-48)
 ④ 스캔 확인(S12): 읽은 값 ↔ KOS 지금 값(back 이 내부 get-visitor 로 읽음) 나란히 · 데스크가 고침 · 사진 미리보기
 ⑤ [저장] → back:
      a. 저장 직전 내부 get-visitor 를 다시 읽고 → 개인 정보 묶음 13키 전부 + 바뀐 칸만 → 내부 update-visitor-personal-information
      b. 사진 → KOS 공개 generateUploadingImageUrl → PUT → registerVisitorImages
              + ccc 비공개 저장소(배포 서버 · 공개 URL 없음 · 로그인 직원만 back 거쳐 열람)
      c. ccc identity_check 한 줄(method = 앱 스캔 · 기기 · 시각) + event_log
 ⑥ 웹 · 앱 상세 「신분 확인」 = 「{기기}에서 수신 · HH:MM · 자동 입력됨(확인 후 수정 가능)」(W done 단계 문구 · 5초 폴링)
```

- **여권만 스캔한다** — 주민등록증은 스캔하지 않는다(눈으로 확인하는 용도 · 사용자 지시 10-27). 내국인은 웹 [확인 완료](표시만 · R5 §5.12)로
- **촬영 가이드 틀 = 마스킹 자리까지 정해 주는 것**(10-27) — 가이드에 맞춰 찍으면 주민번호 뒷자리 자리를 알 수 있어 가려서 저장한다. 코디 기본값: **가린 사진만** ccc · KOS 둘 다에 올리고 **원본은 어디에도 남기지 않는다**(기기 사진첩 · 앱 캐시 포함으로 읽음 — AP-37) · **여권은 가리지 않는다**
  - 같은 날 나중 줄 「스캐너 = 여권만」으로 **지금 범위에서 가릴 신분증이 없다** — 여권 가이드 틀은 찍는 자리(사진면 · MRZ)만 정하고 가림은 없다. 마스킹 자리를 코드 구조로 둘지 = AP-38
- **새 고객 / 기존 고객**
  - 기존 고객(KOS 고객 있음 — 예약된 고객은 모두 그렇다): 위 ⑤a — **스캔하고 수정**(10-27). 「KOS 값 먼저 채워 보여 주고 → 데스크가 고침 → 읽은 묶음 전체」(10-26). 묶음 = 13키 전부 + 바꿀 칸(Q-145 코디 기본값 · AK§6 데모 확인: 바꾼 3칸만 바뀜)
  - 예약 등록 때 새로 만든 고객도 같은 길(v3 4.1 「신규 고객은 예약 등록 때 만든 고객을 같은 길로 고친다」)
  - KOS 고객이 아직 없는 사람(예약 전 · 워크인)을 앱에서 스캔으로 만드는 길은 결정 없음 = AP-39
- 스캔 영문 이름 → `passportSurname` · `passportGivenNames` · **`name`(카드 이름)은 건드리지 않음**(R5 OQ-741 planner 기본값 · 사용자 확인 대기 — AP-40)
- **사진 = ccc · KOS 둘 다**(10-27). ccc 저장 = 배포 서버 비공개 저장소(코디 기본값) — 어디 · 어떻게(infra) · 보관 기간 = AP-41 · AP-42. KOS 이미지 분류 · 촬영 장비 코드(`get-codes` — U§5)와 공개 업로드 실호출은 **미확인**(KOS 표 #20)
- **신분 확인 상태 = ccc DB**(10-26 · D-25) — 스캔 저장도 [접수 완료] 조건이 아니다(10-27 · D-54)
- **법적 검토 주석 자리**(10-27): ① 스캔 사진 저장(ccc 저장소 · KOS 업로드) 코드 ② 마스킹 자리(있다면) ③ 보관 기간 · 지우기 ④ SPEC-004 개정 절 머리 — 문구 「법적 검토 필요: 신분증 이미지 · 주민번호 처리」
- 스캔 실패(못 읽음 · 흐림 · 빛 반사 · KOS 저장 실패 · 사진 업로드만 실패) = AP-43
