## 1. 시작 상태 — 수납이 끝난 고객

- 수납이 끝나면 KOS 에 시술 목록이 올라간다. 결제가 끝나면 간호팀에 「시술 대기」 알림이 뜨고, 그것이 약물 준비의 신호다(간호사 09:05)
- KOS: 일정 `flowStep = PROCEDURE_WAITING` · 시술 = 일정의 `tasks[]`(type `PROCEDURE`) · 오더 메모 = 일정의 `orderMemo`(일정에 하나, 작업별 아님)
- 데모 예(2026-10-20 조회): 작업 3개 모두 `NOT_STARTED` · `paymentRequired: true` · 시술권 · 방 · 담당 없음 · `orderMemo` 있음 · 작업 메모(`memo` · `assigneeMemo` · `doctorMemo`) 비어 있음
- 현황판이 보여 주는 것: **어느 방에 누가(고객) 들어갔고, 그 고객의 시술과 메모**
- 시술 준비(약물 · 장비)는 현황판에 표시하지 않는다
- **카드가 생기는 때**(2026-10-21 추가 · D-21 · D-22): KOS 일정이 `PROCEDURE_WAITING` 이 되면(조회 주기만큼 뒤). **수납 전(`paymentRequired`)이어도 띄우고 「수납 필요」**. **방이 있는 고객만** — 지금 KOS 는 코디가 내원 때 「방 배정」 작업(ETCETERA)으로 방을 준다. 방 없는 고객 = 라운지 대기 = 시술 현황에 안 나온다. ~~「방 배정」 작업은 시술 목록에 안 보인다~~ (2026-10-22 바뀜 · E2E-4) → 읽기 전용 한 줄로 실린다(웹에서 빼는 것은 기록만 — SPEC-003 OQ-517)
- 오더지 카드 나열 · 정렬 [입실순 | 배치순] — 입실 = 방이 배정된 시각 · 배치 = KOS 방 `order`(D-18)

  - **[시작] 조건**(2026-10-21 추가 · D-30): 호출한 시술은 **유효 호출이 수락된 뒤**, 호출 안 한 시술은 담당의가 있을 때. **새 호출이 생기면 수락 전까지 [시작] 꺼짐**. 순서 · 동시 진행 수는 막지 않는다
  - **[종료]는 [시작]한 시술에만**(D-31)
  - 시술마다 진행 · 대기 · 완료를 구분한다 — `시술1 진행 · 시술2 대기`. KOS 는 이 구분이 없다 → **ccc DB 가 관리**
  - `[종료]` = KOS 그 작업 완료(`DONE`). `[시작]` 시각은 ccc DB 에만(KOS 에 넣을 자리 없음)
  - ~~시술 중에는 현황판 · 컴퓨터를 조작하지 않는다 — 시술 여러 개를 받는 동안 제어는 **태블릿 · 폰에서만**~~ (2026-10-21 바뀜) → 태블릿 · 폰이 생기기 전까지는 현황판에서
- **KOS 상태는 두 층이다**(HAR `시술진행.har` · 공개 API 재조회)
  - 작업 칸(화면 「대기중 · 준비중 · 호출함 · 진행중」) — 원장이 수락하면 「진행중」. 작업 `status` 는 `READY` 그대로라 「진행중」은 의사 배정으로 보인다(추정)
  - 일정 단계(`flowStep`) — 수락해도 `PROCEDURE_WAITING` 그대로. KOS 는 따로 `[시술 진행]` 버튼을 눌러야 `PROCEDURE`. **ccc 에는 이 별도 버튼이 없다** — 첫 [시작]이 대신한다
