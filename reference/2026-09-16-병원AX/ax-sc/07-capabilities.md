# 7. 핵심 제품 역량

> SC-AX 제품 정의서 v0.1 · 검증 전 초안
> 허브: [`00-overview.md`](./00-overview.md) · 앞 절: [`06-scope.md`](./06-scope.md)
>
> [6절](./06-scope.md)이 **무엇을 만들지**를 정했다면, 이 절은 **그것이 무엇을 할 수 있어야 하는가**다. 화면이나 기술을 정하는 자리가 아니다.

### 6절과 어떻게 이어지는가

| 6절 | 7절에서 다루나 | 왜 |
|---|---|---|
| **M-1 ~ M-5** (1차 기능) | **다룬다** | 이 절의 전부다 |
| M-6 ~ M-14 (2~4차 기능) | 다루지 않는다 | 조사(D-1~D-4)와 1차 사용 결과가 나오기 전에 역량을 고정하면 틀린다 |
| **D-1 ~ D-4** (조사) | **다루지 않는다** | **사람이 묻고 정리하는 일이지 제품이 하는 일이 아니다.** 진행 방식은 [9절](./09-roadmap.md) |
| D-5 (레거시 인덱스) | 다루지 않는다 | **도구가 훑는 일이라 역량이 필요하지만 2차다.** 범위는 D-2 결과를 본 뒤 정한다 |

`[해석]` **역량은 트랙 A만 갖는다.** 트랙 B는 사람이 묻고 정리하는 일이라 "무엇을 할 수 있어야 하는가"를 물을 대상이 아니다. 다만 **그 결과를 담는 자리(M-5)는 제품이므로 역량을 갖는다.** D-5(도구로 훑기)만 예외적으로 역량이 필요한데 2차이므로 이 절에 없다.

## 7.1 무엇을 할 수 있어야 하는가

> ✎ **여기를 고치면 같이 확인** — 역량(C-n)을 더하거나 빼면 → 7.2 의존 · 6.1 모듈 · 8절 「이 절이 다른 절에 요구하는 것」 · 9.1 마일스톤의 괄호

### M-1 조직 정보와 권한

| # | 할 수 있어야 하는 것 | 푸는 상황 | 선행 |
|---|---|---|---|
| **C-1** | 본부·부서·팀·직급·담당 업무를 등록하고 유지한다. **상태를 기준으로 걸러 본다**(예: 특정 서류가 없는 사람만) | `US-1` `US-1B` | 없음 |
| **C-2** | 지금 연락이 되는지 안다 (재직·휴가·외근 수준) | `US-1` | C-1 |
| **C-3** | 누가 무엇을 볼 수 있는지 정한다 | `US-6` `US-7` | C-1 |
| **C-4** | 누가 무엇을 열어봤는지 남긴다 | `US-7` | C-3 |
| **C-5** | 관리자가 개발자 없이 부서·직급·상태값을 바꾼다 | — | C-1 |
| **C-6** | 팀·전사에 공지를 보내고 읽었는지 안다 | — | C-1 · C-3 |

`[해석]` **C-2는 "지금 연락이 되는가" 수준까지다.** 자리 비움을 분 단위로 표시하는 것은 인권 침해 소지로 제동이 걸렸다([HOLD-3](./06-scope.md)). 판단이 나기 전까지 **재직·휴가·외근 정도로만** 만든다.

`[해석]` **C-5가 빠지면 M-1이 운영되지 않는다.** 조직이 바뀔 때마다 개발 요청이 들어오고, 그러면 조직 정보가 실제와 어긋난 채로 남는다.

### 모듈에 걸치는 것

| # | 할 수 있어야 하는 것 | 푸는 상황 | 선행 |
|---|---|---|---|
| **C-19** | **누가 언제 무엇을 고쳤는지 남는다** (업무 지시·회의록·조직 정보) | `US-4` `US-5` | C-3 |
| **C-20** | **지운 것을 일정 기간 안에 되살린다** | `US-6` | C-3 |

`[해석]` **C-19는 C-4와 다르다.** C-4는 *열어본* 기록이고 C-19는 *고친* 기록이다. 계약서를 각자 고쳐 덮어써 무엇이 언제 바뀌었는지 사라지는 문제(PR-5.6)가 같은 뿌리이며, 회의록과 업무 지시에서 먼저 필요하다.

`[해석]` **C-20이 없으면 [P-5](./05-principles.md)가 성립하지 않는다.** P-5는 *"기록이 지워지는 것"* 을 되돌릴 수 없는 것으로 분류했는데, **되살릴 방법이 있으면 되돌릴 수 있는 것이 된다.** 그러면 삭제를 매번 승인받을 이유가 줄어든다.

### M-2 업무일지

| # | 할 수 있어야 하는 것 | 푸는 상황 | 선행 |
|---|---|---|---|
| **C-7** | 업무를 등록하고 담당자에게 배정한다. 본인도 등록하고 위에서도 넣는다. **담당자가 정해지지 않은 업무만 따로 모아 본다** | `US-2` `US-4` | C-1 |
| **C-8** | 업무 상태와 진행을 남긴다 | `US-4` | C-7 |
| **C-9** | 끝내지 못한 일이 다음 날로 이어진다. **이어진 일은 원본과 한 흐름으로 묶여 목록에는 최신 것 하나만 보인다** | `US-3` `US-4` | C-8 |
| **C-10** | 남은 기록에서 업무일지와 보고서를 만든다 | `US-3` | C-8 |
| **C-11** | 마감이 캘린더에 뜨고 다가오면 알린다. **공휴일이 자동으로 표시된다** | `US-4` | C-8 |

`[해석]` **C-10이 이 모듈의 핵심이다.** 나머지는 다른 도구도 한다. *"일한 것이 그대로 기록이 된다"* 는 [4.1의 약속](./04-vision-and-value.md)이 지켜지는 지점이며, 여기서 사람이 다시 쓰게 만들면 [P-3](./05-principles.md)이 깨지고 이 제품을 쓸 이유가 없어진다.

### M-3 회의실

| # | 할 수 있어야 하는 것 | 푸는 상황 | 선행 |
|---|---|---|---|
| **C-12** | 회의 내용을 기록으로 남긴다 | `US-5` | 없음 |
| **C-13** | 기록에서 결정과 할 일을 뽑는다 | `US-2` | C-12 |
| **C-14** | 뽑은 할 일을 담당자에게 넘긴다. 사람이 확인하고 보낸다 | `US-2` `US-4` | C-13 · C-7 |
| **C-15** | 회의록을 누가 볼 수 있는지 정한다 | `US-2` | C-3 |

`[해석]` **C-14는 이어지는 두 번째 문제를 푼다.** 회의가 연달아 있으면 직전 회의의 할 일을 배정하지 못한 채 넘어가는데(PR-3.2), 뽑아 놓고 승인만 기다리게 두면 그 자리에서 넘어간다.

`[해석]` **C-15는 정책이 정해져야 완성된다.** 회의록을 기본 공개로 할지 비공개로 할지, 무엇을 걸러낼지가 미정이다([HOLD-4·5](./06-scope.md)). **다만 기능은 만든다** — 기본값을 나중에 바꿀 수 있게 두고, 정해지기 전까지는 참석자만 보는 쪽으로 둔다.

### M-4 대시보드

| # | 할 수 있어야 하는 것 | 푸는 상황 | 선행 |
|---|---|---|---|
| **C-16** | 개인이 오늘 자기 할 일을 본다. **날짜를 짚으면 그날 일정이 보이고 눌러서 들어간다** | `US-4` | C-8 |
| **C-17** | 관리자가 팀 상태와 준 일의 진행을 본다. **숫자를 누르면 그 상태의 업무 목록이 열린다** | `US-4` | C-8 · C-14 |
| **C-18** | 대표가 전사 현황을 본다 | `US-4` | C-17 |

`[해석]` **셋은 다른 화면이다.** 대표는 아홉 상황 중 다섯을, 부서장은 그 외를 겪는다([3.4](./03-users-and-situations.md)). 하나로 만들어 권한만 다르게 하면 아무에게도 안 맞는 화면이 된다.

`[해석]` **C-18은 마지막에 켠다.** 기록이 쌓이기 전에 전사 현황을 앞세우면 감시로 읽혀 기록이 남지 않는다([P-2](./05-principles.md)).

### M-5 데이터 맵

| # | 할 수 있어야 하는 것 | 푸는 상황 | 선행 |
|---|---|---|---|
| **C-21** | 데이터 항목을 등록하고 유지한다 — 어느 부서가 무엇을 어떤 형태로 어디에 갖고 있는지, 얼마나 자주 고치는지, 누가 책임지는지 | `US-5` | C-1 |
| **C-22** | **실제 자료가 있는 곳으로 링크가 연결된다.** 눌러서 바로 간다 | `US-5` `US-1B` | C-21 |
| **C-23** | 부서 사이에 무엇이 오가는지 본다 | `US-1B` | C-21 |
| **C-24** | 민감한 내용이 어디 있는지 표시하고, 그것만 걸러 본다 | `US-6` `US-7` | C-21 · C-3 |

`[해석]` **이 모듈은 조사(D-1~D-3)의 결과를 담는 자리다.** 조사 결과를 문서로만 두면 **그 문서가 또 어디 있는지 모르게 되고**(PR-5.10의 반복), 조사 시점의 스냅샷이라 곧 낡는다. 시스템 안에 넣어야 갱신된다.

`[해석]` **C-22가 이 모듈의 값어치를 결정한다.** 목록만 있고 실제 자료로 갈 수 없으면 *"어디 있는지는 아는데 여전히 찾아가야 하는"* 상태로 남는다. 다만 여는 것까지는 아니다 — **위치를 알려주는 것과 내용을 찾아 주는 것은 다르고, 뒤쪽은 M-6(2차)다.**

`[해석]` **C-24는 C-3(권한)의 재료가 된다.** 민감한 것이 어디 있는지 알아야 권한을 정확히 걸 수 있다. 다만 순서가 반대여도 된다 — 기본 권한은 조직 정보만으로 만들고, 정밀하게 만들 때 이것을 쓴다.

## 7.2 무엇 없이 무엇을 못 만드는가

```
C-1 조직 구조
 ├─ C-2 연락 가능 여부
 ├─ C-5 관리자 설정
 ├─ C-3 권한 ─── C-4 접근 기록
 │              └─ C-6 공지
 │              └─ C-15 회의록 열람 범위
 └─ C-7 업무 등록·배정
      └─ C-8 상태·진행
           ├─ C-9 다음 날로 이어짐
           ├─ C-10 일지·보고서 파생
           ├─ C-11 마감 알림
           └─ C-16 개인 화면 ─ C-17 팀 화면 ─ C-18 전사 화면

C-12 회의 기록 ─ C-13 결정·할 일 추출 ─ C-14 배정 ─┘

C-3 권한 ─┬─ C-19 수정 이력      (모듈에 걸침)
          ├─ C-20 지운 것 되살리기
          └─ C-24 민감 정보 표시

C-1 ─ C-21 데이터 항목 ─┬─ C-22 실제 자료로 링크
   (조사 결과가 채움)   ├─ C-23 부서 간 이동 경로
                       └─ C-24
```

`[해석]` **C-1이 전부의 뿌리다.** 조직 구조 없이는 배정할 대상도, 권한을 걸 단위도, 화면을 나눌 기준도 없다.

`[해석]` **C-12·C-13은 C-1을 기다리지 않는다.** 회의를 기록하고 할 일을 뽑는 것까지는 조직 정보 없이 된다. 막히는 것은 **넘기는 순간(C-14)** 이다.

`[해석]` **다만 먼저 시작하지는 않는다.** [9.2](./09-roadmap.md)에서 **M-2(업무일지)를 M-3(회의실)보다 앞에** 두었다 — C-14는 7.3대로 *C-7과 같은 자리로 들어가므로*, 업무일지가 없으면 **뽑은 할 일이 들어갈 자리가 없어 회의록만 쌓인다.** "시작할 수 있다"가 "먼저 해야 한다"는 뜻은 아니다.

## 7.3 만들 것과 가져다 쓸 것

| 역량 | 어떻게 | 왜 |
|---|---|---|
| C-1 조직 구조 | **만들기** — 인사 담당자에게 받아 넣는다 | 조직 구조는 회사마다 다르고 이미 정리된 자료가 있다 |
| C-2 연락 가능 여부 | **만들기** + 근태 자료 연동 | 출입 기록이 이미 있다 |
| C-3·C-4 권한·접근 기록 | **만들기** | 이 제품의 차별점 ②-a이며 남에게 맡길 수 없다 |
| C-5 관리자 설정 | **만들기** | — |
| C-6 공지 | **만들기** + 메신저 연동 검토 | 사내 메신저가 이미 있고 거기로 가야 읽힌다 |
| C-7~C-9 업무 등록·상태·이월 | **만들기** | **현행 도구가 이미 하는 일이다.** 규칙을 그대로 받아온다 |
| C-10 일지·보고서 파생 | **만들기** | 이 제품의 핵심. 대체재가 없다 |
| C-11 마감 알림 | 만들기 + **캘린더 연동** | 대표가 구글 캘린더로 옮기는 중이다(S12). 별도 캘린더를 만들면 두 곳을 보게 된다 |
| **C-12 회의 기록** | **가져다 쓰기** | 음성 기록은 이미 쓰는 서비스가 있다. 직접 만들 이유가 없다 |
| **C-13 결정·할 일 추출** | **가져다 쓰기 + 만들기** | 언어 모델은 가져다 쓰고, **조직 맥락을 넣어 담당자를 맞추는 부분은 만든다** |
| C-14 배정 | **만들기** | C-7과 같은 자리로 들어간다 |
| C-15 회의록 열람 범위 | **만들기** | C-3 위에 얹는다 |
| C-16~C-18 화면 | **만들기** | — |
| C-19 수정 이력 | **만들기** | 어느 모듈에나 걸리므로 처음부터 같은 방식으로 남겨야 한다. 나중에 붙이면 이전 기록이 비어 있다 |
| C-20 되살리기 | **만들기** | — |
| C-21~C-24 데이터 맵 | **만들기** | 조사 결과를 담을 그릇이라 **내용보다 먼저 만들어도 된다.** 조사가 나오는 대로 채운다 |

`[사실]` 회의록 도구가 중간에 끊기고 회의마다 요약 양식이 맞지 않는다는 문제가 이미 있다(PR-3.4). 그리고 *"구글에서 제공하지 않는 타사 API는 어렵더라"* 는 진술이 있다(S9).

`[해석]` **C-12를 가져다 쓰되 무엇을 쓸지는 정하지 않았다.** 지금 쓰는 것들이 이미 불안정하므로, 바꿀지 그대로 쓸지는 [9절](./09-roadmap.md) 착수 시 정한다.

## 7.4 지지 않는 조건 — 현행 도구가 이미 하는 것

> ✎ **여기를 고치면 같이 확인** — 재현 목록을 바꾸면 → **9.1 마일스톤 통과 조건의 건수 배분** · 9.5 판정 조건

경영관리부가 쓰는 자체 제작 도구는 요구서에 적히지 않은 것까지 이미 하고 있다. **이 목록을 재현하지 못하면 명백한 후퇴다.**

| 현행이 이미 하는 것 | 어느 역량에 걸리나 |
|---|---|
| 끝내지 못한 일이 다음 날로 자동으로 넘어간다 (완료·반복·퇴사자는 제외) | **C-9** |
| 진행률과 상태가 서로 자동으로 맞춰진다 | C-8 |
| 휴무가 전 부서 캘린더에 자동으로 표시된다 | C-2 · C-11 |
| 업무 마감일이 캘린더에 자동으로 뜬다 (따로 일정을 만들지 않는다) | **C-11** |
| 여러 사람이 동시에 봐도 화면이 자동으로 갱신된다 | 전 역량 |
| 입력 중 자동 저장되고, 새로고침해도 입력값이 남는다 | 전 역량 |
| 근무 시간 중 "오늘 남은 내 일"이 떠오른다 | C-16 |
| 관리자가 전 직원에게 즉시 공지를 띄운다 | C-6 |
| 퇴사 처리 시 통계·이월·담당자 목록에서 빠지되 **입력 이력은 남는다** | C-1 · C-3 |
| **이어진 업무가 원본과 한 흐름으로 묶여 목록에 최신 것 하나만 뜬다** | **C-9** |
| 공휴일이 캘린더에 자동으로 표시된다 | C-11 |
| 대시보드의 통계 숫자를 누르면 그 상태의 업무 목록이 열린다 | **C-17** |
| 캘린더 날짜에 올리면 그날 일정이 뜨고 누르면 상세가 열린다 | C-16 · C-17 |
| 상태를 기준으로 걸러 본다 (예: 특정 서류가 없는 사람만) | C-1 |

`[해석]` **이것들은 차별점이 아니라 출발선이다.** 없으면 "예전 것이 더 나았다"가 나온다. 요구서 본문에는 없고 **현행 동작 블록에만** 적혀 있어 목록만 훑으면 놓친다.

`[해석]` 그중 둘은 **"기능은 있는데 쓸 수 없게 되는"** 유형이라 특히 위험하다. 이월은 되는데 원본과 안 묶이면 같은 업무가 날짜별로 쌓여 목록이 못 쓰게 되고, 통계 숫자가 보이는데 눌러 들어갈 수 없으면 결국 다시 물어보게 된다. **만들어도 안 쓰이는 결과가 된다.**

## 7.5 원칙이 여기서 어떻게 적용되는가

### 어디서 사람이 멈춰 세우는가 (P-5)

[P-5](./05-principles.md)는 **되돌릴 수 없는 것만 사람이 멈춰 세운다**고 정했다. 1차 역량에 대입하면 이렇다.

| 흐르게 둔다 | 사람이 멈춰 세운다 |
|---|---|
| C-13 회의에서 할 일이 뽑히는 것 | **C-3 권한이 바뀌는 것** |
| C-9 다음 날로 이어지는 것 | **C-14 할 일을 다른 사람에게 넘기는 것** |
| C-8 상태가 갱신되는 것 | |
| C-10 일지가 만들어지는 것 | |

`[해석]` **C-14를 멈춰 세우는 이유는 되돌릴 수 없어서가 아니라 사람 사이의 일이기 때문이다.** 잘못 배정된 일은 취소할 수 있지만, 받은 사람에게는 이미 간 것이다. 대표도 같은 이유로 자동 배정에 반대했다 — *"그러면 대표님 왜 있어요?"*

`[해석]` **C-10(일지 파생)은 흐르게 둔다.** 여기에 승인을 넣으면 매일 확인 버튼을 누르게 되어 [P-3](./05-principles.md)이 깨진다. 대신 **본인이 고칠 수 있게** 한다.

### "AI를 몰라도 쓸 수 있어야 한다"를 원칙으로 되돌릴 것인가

[5절](./05-principles.md)에서 원칙에서 내리고 7절에서 재판정하기로 했다.

`[해석]` **1차 범위에서는 되돌리지 않는다.** 1차 다섯 모듈에서 AI가 하는 일은 C-12(기록)와 C-13(추출)뿐이고, 사용자는 **결과를 확인할 뿐 AI를 다루지 않는다.** 판단이 갈릴 자리가 없다.

`[가설]` **2차의 M-6(자료 검색)에서는 갈린다.** 말로 물어 찾는 방식은 묻는 법을 알아야 쓸 수 있고, 그때 *"이 기능은 좀 알아야 쓸 수 있는데 그래도 넣을까"* 가 실제 판단이 된다. **그 시점에 다시 판정한다.**

### 대면 보고가 주던 맥락은 무엇이 대신하는가

[2.4에서 남긴 숙제](./02-background-and-problems.md)다. 대면 보고는 그 자리에서 분위기와 판단 근거까지 전달되는데, 비교표에는 그 축이 없다.

`[해석]` **1차에서는 대신하지 않는다.** C-12·C-13이 잡는 것은 **회의**의 맥락이지 대면 보고의 맥락이 아니다. 대표가 받는 대면 보고는 시스템 밖에서 일어난다.

`[해석]` 다만 **대면 보고가 필요한 이유 자체를 줄일 수는 있다.** 대표가 대면으로 확인하던 것 중 "무엇이 어디까지 갔는지"는 C-17·C-18이 대신한다. 남는 것은 판단과 논의이고, 그것은 대면이 맞다.
