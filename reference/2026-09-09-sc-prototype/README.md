# SCAX 네이버 키워드 순위 PoC

키워드별 네이버 PC 통합검색의 **첫 파워링크 광고 영역**에서 타겟 도메인의 순서를 확인하고 `.xlsx`로 저장한다. 사이드바 이름은 요청에 따라 ‘블로그 상위 노출’이며, 현재 순위 계산 대상은 블로그가 아닌 파워링크다.

## 실행

Node.js 20.19 이상, npm, `curl`이 필요하다.

```sh
npm install
npm run dev
```

- 프론트: http://localhost:13000
- 백엔드: http://localhost:18000
- 두 포트 중 하나가 사용 중이면 실패한다. 다른 포트로 자동 전환하지 않는다.
- `Ctrl+C`로 두 프로세스를 종료한다.

## 사용

1. 타겟 도메인을 확인한다. 기본값은 `daybeauclinic13.com`이다.
2. 기본으로 입력된 이미지 속 19개 키워드를 수정하거나, 엑셀의 키워드 열을 입력칸에 붙여넣는다. 한 번에 50개까지 입력하며 빈 칸과 중복은 제외한다.
3. 순위 조회를 누른다. 결과의 순위 숫자를 누르면 해당 응답에서 확인한 광고 목록을 펼친다.
4. 조회 완료 또는 중단 후 엑셀 저장하기를 누른다. 필터와 관계없이 이번 조회 전체 결과를 저장한다.

## 판정과 범위

- 백엔드가 `curl`로 검색 HTML을 받아 Cheerio로 광고 행을 파싱한다. 브라우저 자동화는 사용하지 않는다.
- 광고의 목적지 도메인을 HTML의 `onclick` 문자열 또는 표시 URL에서 읽으며, 코드를 실행하거나 광고 링크·노출 추적 URL을 요청하지 않는다.
- `www.`만 정규화하고 도메인을 정확히 비교한다. 변하는 `ader.naver.com` 추적 링크는 타겟으로 받지 않는다.
- 첫 파워링크 목록의 광고 행을 위에서부터 1로 센다. 광고 안의 추가 링크는 별도 광고로 세지 않는다. 같은 사이트가 여러 번 등장하면 첫 순위를 표시하며, 광고 목록에서는 모두 확인할 수 있다.
- 타겟이 정상적으로 파싱된 목록에 없으면 ‘미노출’이다. HTTP 오류, 차단 페이지, 파워링크 영역 누락, 인식하지 못한 구조는 ‘조회 실패’다. 광고가 아예 없는 페이지도 영역을 검증할 수 없으면 조회 실패로 처리한다.
- 지역·기기·시각에 따라 사람의 브라우저에서 보는 순위와 달라질 수 있다. 순위는 해당 서버 요청이 받은 첫 광고 목록에 한정한다.
- 순차 조회 사이에 1초를 두며, 중단은 현재 요청 완료 후 적용한다. 단일 로컬 사용자용이며 동시 조회는 제한한다.
- 별도 DB와 이력 저장은 없다. 새 조회 또는 새로고침 시 이전 결과가 사라지므로 필요한 결과는 엑셀로 저장한다.

## 구성과 검증

- `src/`: React 프론트
- `server/`: Express API, 검색 파서, ExcelJS 내보내기
- `src/vendor/`: 제공된 `sc-design-system/frontend/src`의 SCAX CSS와 Icon 참조본. CSS에 있던 불필요한 닫는 중괄호 하나만 제거했다. 원본 레포는 수정하지 않았다.
- `npm test`: 광고 행 순서·도메인 비교·구조 오류·엑셀 셀 타입을 검증하는 단위 테스트 6개
- `npm run build`: 프론트 빌드
- E2E는 사용자가 직접 수행한다. Playwright는 플레이스 수집에만 사용하며 E2E 설정은 없다.

`npm run start`는 빌드된 프론트까지 백엔드 포트(기본 18000)에서 제공하는 선택 실행 방식이다. 평소 PoC 확인은 위의 `npm run dev`를 사용한다.

## 플레이스 순위 조회 (같은 PoC)

사이드바의 ‘블로그 상위 노출’ 아래 ‘플레이스 순위 조회’를 선택한다. 기존 포트 13000/18000을 공유하고, `/api/place/check`에 `{keyword, target}`을 보낸다. 타겟은 공백 무시·부분 일치이며 모든 매칭을 보존한다. 전체 순위와 페이지는 첫 매칭, 광고 제외 순위는 첫 일반 매칭 기준이다. 광고만 있으면 광고 제외 순위가 없다. 동일 업체의 광고/일반 결과는 별도 집계하고, 스크롤 중 같은 항목을 다시 읽은 경우만 중복을 제거하며, 다른 페이지에 다시 노출된 항목은 해당 페이지의 순서대로 센다. 각 lazy-load placeholder로 스크롤한 뒤 MutationObserver로 실제 업체 항목으로 교체되는 것을 기다린다. 미로딩 항목이 모두 사라지고 최하단 렌더링이 완료된 후 DOM 순서대로 페이지 전체를 읽는다. 스크롤·페이지 전환에 고정 시간 sleep은 없으며 타임아웃은 실패 판정에만 사용한다.

`server/place.mjs`는 Express 없이 import 가능하다. 프로세스당 Chromium 하나를 재사용하고 조회마다 컨텍스트를 닫는다. 60초 제한, 요청 사이 2초 간격이다. 각 페이지 최하단까지 스크롤하며 전체 항목을 수집한 다음 타겟을 판정한다. 발견되면 그 페이지에서 종료하고, 없을 때만 다음 페이지로 넘어가 최대 5페이지까지 확인한다. 광고에서만 발견되면 광고 제외 순위는 없다. 이후 페이지의 동명 매칭은 수집하지 않는다. 못 읽거나 차단된 경우 ‘조회 실패’, 정상 수집 목록에 타겟이 없으면 ‘미노출’이다. 검색 결과 전체가 아닌 수집한 최대 5페이지 기준이다. 화면에는 순위와 발견 페이지를 표시하며 플레이스 전체 목록은 표시하지 않는다.

수집 브라우저 설치: `npx playwright install chromium`. Playwright는 이번 동적 수집의 실행 의존성이다. E2E 자동화 설정은 없고 수동 화면 검증은 사용자가 담당한다. `npm test`는 네트워크 없는 파서·워크북 테스트, `npm run smoke`는 강남역성형외과 / 무이성형외과의 실제 수집 확인이다.

### 검증된 사실 (제공된 사전 조사)

- 지도 HTML은 약 2.3KB SPA 셸이고 내부 allSearch API는 `CE_EMPTY_TOKEN` 빈 응답이었다. 플레이스 iframe에 대한 curl 요청은 HTTP 429였다. 정적 수집은 재조사하지 않았다.
- 제공 스크립트의 2026-09-09 실측은 5페이지 184건(광고 12건), 무이성형외과의원 전체 10위 / 광고 제외 6위 / 1페이지였다. 이 숫자는 현재 고정값이 아니다.
- searchIframe 재탐색, lazy-load 스크롤, 숫자 페이지 이동을 제공된 `../2026-09-09-place-rank-poc/pw_rank.mjs`에서 옮겼다. 상호는 전체 이름 요소를 우선해 분리된 span과 진료과 단독 텍스트의 혼동을 보완했다.

### 하지 않을 것

배치·크론·DB·알림·모바일 순위는 구현하지 않는다. 캡차 우회·프록시 회전·UA 랜덤화도 하지 않는다. 위치를 고정하지 않으며 헤드리스 기본 위치로 측정한다는 사실을 UI와 엑셀 조회 기준에 명시한다. 수동 3개 키워드 조회 → xlsx 다운로드는 사용자 확인 항목이다.

## 블로그 탭 · 타겟 키워드 / 타겟 이미지

‘블로그 상위 노출’ 메뉴는 이제 파워링크가 아닌 네이버 블로그 탭을 조회한다. 타겟 키워드는 검색 결과 제목·요약의 공백 무시 부분 일치, 타겟 이미지는 검색 썸네일의 pHash 비교다. 썸네일은 중복 URL을 제거하고 8개씩 병렬 다운로드하며 완료 순서가 아닌 글 카드의 순서로 순위를 계산한다. PNG/JPG/WebP 4MB 이하를 업로드할 수 있다. 결과의 ‘매칭 글’로 원문을 열 수 있다.

Playwright로 초기 목록을 확인한 뒤 타겟이 없으면 최하단 스크롤을 최대 3회 추가한다. 네이버 추가 검색 응답과 DOM 렌더링 완료 이벤트를 기다리고, 새 썸네일 URL만 8개씩 병렬 비교한다. 타겟을 찾으면 조기 종료한다. 글 본문에만 있는 이미지는 조회하지 않는다. 63비트 pHash 거리 6 이하를 같은 이미지로 간주하는 PoC 기준으로, 원본 및 기본 검색 썸네일 비율(250:208)의 중앙 크롭을 비교한다. 일반적인 압축·축소 차이는 허용하지만 다른 크롭·편집·색상 변경의 정확성을 보장하지 않는다. 일부 앞순위 이미지를 읽지 못하면 미노출 대신 조회 실패로 표시한다. 외부 AI API는 사용하지 않는다.
