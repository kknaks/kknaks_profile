# 정규화 (Normalization)

데이터 중복을 제거하기 위해 테이블을 논리적 단위로 분리하는 관계형 데이터베이스 설계 원칙이다.

## 정의

- 동일한 데이터가 여러 테이블에 반복 저장되면 갱신 시 불일치가 생긴다.
- 정규화는 중복 데이터를 별도 테이블로 분리하고 외래 키(참조)로 연결해 이 문제를 해소한다.
- 결과적으로 데이터 정확도와 일관성이 높아진다.
- 반면 조회 시 조인(JOIN)이 필요해 입출력 문법이 복잡해지고 쿼리 성능이 낮아질 수 있다.

## 왜 중요한가

중복 없이 한 곳에만 저장된 데이터는 수정 시 한 곳만 바꾸면 전파가 끝난다. 금융 거래처럼 정확도가 생명인 도메인에서 중복 데이터는 조용한 불일치로 이어져 치명적 버그가 된다.

## 경계와 오해

- **정규화 ≠ 성능 최적화** — 정규화는 정확성을 위한 설계다. 조인 비용으로 성능이 낮아질 수 있어, 성능이 우선이면 의도적으로 비정규화(denormalization)를 선택한다.
- **정규화는 관계형 DB에 특유** — 도큐먼트 DB·컬럼 패밀리 DB는 의도적으로 중복을 허용하며 정규화를 하지 않는다. 이 선택 덕분에 분산 처리가 쉬워진다.
