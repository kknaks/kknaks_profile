# 업무 상세 재설계 — 후행 조회·상위 변경·여섯 덩어리

업무 상세를 **여섯 덩어리**로 다시 짜고, 그 화면이 요구하는 **읽기 경로 하나(후행)** 와
**쓰기 칸 하나(상위)** 를 연다. 그리고 **선행이 화면에 안 뜨던 배선 하나**를 고친다.

> 1 파일 = 1 work = **빌드 계획**. SPEC 의 외부 계약 본문은 복제하지 않고 **절 번호로** 가리킨다.
> **이 문서는 착수 전 계획이다.** 모든 phase 가 `TODO` 이고 코드는 한 줄도 쓰지 않았다.
>
> **backend 가 먼저다.** 후행 조회와 상위 변경 칸이 없으면 화면이 그릴 재료가 없다.
> BE 셋이 끝난 뒤 FE 셋이 돈다 — **이 work 안에서 BE·FE 는 병렬이 아니라 직렬이다.**

## Domain / Schema

**새 표 0건 · 새 컬럼 0건.** 이 판이 저장에 더하는 것은 **인덱스 하나**뿐이다.

| 무엇 | 모양 |
|---|---|
| `predecessor_task_id` 인덱스 | `task_predecessors` 의 역방향 조회용. 지금 인덱스는 `ix_task_predecessors_task_id` 하나다 |

- **실제 schema 의 SoT 는 모델 metadata** 이고 이 문서는 필요 여부만 적는다.
- ⚠ **설치 방법이 열려 있다** — Alembic 도 migrations 체계도 없고
  (`baseline-004-projects.md:525-526`) 「기존 표에 인덱스를 더하면 `schema_sync` 가 못 만든다」는
  선례가 있다(`backend/src/ax_workspace/platform/persistence.py:1650-1653`).
  **SPEC-007 §7.1 OQ-703 이 그것을 backend 에 보냈다** — **Phase B-1 의 첫 작업이 그 답이다.**

**불변식 — 깨지면 안 되는 것**

1. **후행은 저장되지 않는다.** `task_predecessors` 행 하나가 양쪽을 답한다.
2. **선행은 같은 프로젝트 안에서만** 선다. 그래서 **한 트리의 프로젝트가 갈리면 안 된다.**
3. **V-8** — 직접 작업은 중심 업무의 직속에만. **이 판이 그것을 «이동»에서도 지킨다.**
4. **선행은 시작을 막고 하위는 완료를 막는다.** 두 코드를 합치지 않는다.
5. **뗀 관계는 행을 지우지 않고 닫는다**(`released_at`).
6. **부분 이동이 없다** — 상위 이동의 게이트가 걸리면 아무것도 안 움직인다.

## Internal Interface Contract

SPEC 의 외부 API 계약을 복제하지 않는다. 여기 고정하는 것은 **후속이 의존하는 내부 입출력**뿐이다.

**후행 투영 (application 내부)**

- 입력: 업무 · 행위자
- 판정: 그 업무를 선행으로 삼는 **활성 행**을 역방향으로 읽고 → 대상마다 **읽기 판정** →
  못 읽으면 배열에서 빼고 **건수를 올린다**
- 출력: `successors`(읽을 수 있는 것만 · `version` 포함) + `hidden_successor_count`
- **되돌이 빗장**: 읽기 판정이 부른 상세에서는 후행 투영을 접는다 — 선행 요약이 같은 자리에
  같은 빗장을 갖고 있다(BASE-005 § 2-2)

**상위 이동 판정 (application 내부)**

- 입력: 업무 · 새 상위(또는 비우기) · 행위자 · 회차
- 판정 순서: **0 취소됨 → 1 읽기 → 2 끝난 업무 → 3 담당 미확정 → 4 순환 → 5 이 업무의 V-8 →
  6 «직속 하위»의 V-8 → 7 프로젝트 자손 파급의 선행 잠금**
- **6 은 읽을 수 없는 하위까지 세고, 이름은 읽을 수 있는 것만 낸다** — 선행 게이트가 이미 그 모양이다
- 출력: 옮겨진 업무 + **프로젝트가 따라 옮겨진 자손 전체** + 오른 회차 + 진행 기록
- **전부 한 transaction.** 게이트가 걸리면 **아무것도 움직이지 않는다**

**후행 해제 (application 내부)**

- 입력: A(지금 열린 업무) · B(후행) · **B 의 회차** · 행위자
- 권한: **A 를 고칠 수 있거나 B 를 고칠 수 있으면** 통과
- 효과: `(task_id=B, predecessor_task_id=A)` 의 **활성 행 하나를 닫는다**. **B 의 회차가 오른다**
- 출력: 갱신된 **A 의 후행 묶음**
- **멱등이 아니다** — 이미 닫혔으면 대상이 없으므로 404

## Rollback

- **BE·FE 가 직렬이라 FE 를 먼저 되돌린다.** 화면은 서버 칸이 있어도 안 그리면 그만이다.
- 부분 revert 영향:
  - **후행(B-1)** 과 **상위 변경(B-2)** 은 서로 독립이라 한쪽만 되돌릴 수 있다
  - **후행 해제(B-3)** 는 B-1 에 의존한다 — B-1 을 되돌리려면 B-3 을 먼저
  - **F-3(연결 편집)** 은 B-2·B-3 에 의존한다 — 서버를 되돌리면 F-3 을 먼저
- **인덱스는 되돌리지 않아도 해롭지 않다** — 조회가 없어지면 쓰이지 않을 뿐이다
- **데이터 변경이 없다** — 이 판은 관계 «행»을 새로 만들지 않는다.
  후행 해제로 닫힌 행은 `released_at` 이 찬 채로 남고, 되돌리려면 다시 걸면 된다
