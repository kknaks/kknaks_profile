### Business Requirement

- 회의 **생성·수정 모두** The Connect 에서 그 시간·그 인원에 쓸 수 있는 회의실을 골라 예약·변경한다(D-07~D-09)
- 회의 정보 수정 모달의 일정 칸이 겹치지 않고, 같은 사람이 두 번 참석자로 들어가지 않는다(D-06 · OQ-909)
- 지난 회의를 불러와도 **시간은 새 회의 것**이고, 안건마다 **어디서 왔는지**가 맞게 보인다(D-10 · D-11)
- 회의록 생성이 **90초에 끊기지 않고**, 조직의 프로젝트·업무·사람 이름으로 **STT 오인식을 바로잡고** 무엇을 바꿨는지 **보정 표**로 남기며,
  안건이 **회의 흐름 순서**로 서고, 할 일 기한이 **회의보다 앞서지 않는다**(D-12~D-19)
- AX 업무 생성이 **조직의 프로젝트·업무·사람 목록을 받고** 시작한다(D-20)
- AX 채팅의 **회의 생성이 업무 생성과 같은 흐름·디자인**(쪽 나눔·거절·초안 저장·단추)으로 서고, **회의 수정 카드에서 회의실도 바꾼다**(D-04 · D-05 · D-09)

## 2. UX Contract

시안이 없는 판이다. 화면 모양은 **지금 화면을 기본값**으로 두고, 이 절이 말하는 것만 바꾼다.

### 2.1 회의 정보 수정 모달 — 일정 칸 · 참석자 (D-06 · OQ-909)

- **일정 칸이 왼쪽 열 안에 든다.** `[날짜][시작][종료]` 세 칸이 왼쪽 열 폭을 넘지 않는다 — **날짜 칸 폭을 줄인다**(지금 `200px` 고정 · FE §3-1).
  종료 시각 칸이 오른쪽 열의 「조직도 내 이름 검색」 입력 밑에 깔리지 않는다(원본 §3.1-8 의 칸은 그대로)
- 같은 줄 모양을 쓰는 **생성 모달(`BookingModal`)도 넘치지 않아야 한다** — 두 모달이 같은 클래스(`.meeting-when`)를 쓴다(FE §3-3). 생성 모달은 한 열이라 지금은 넘치지 않는다 — **고친 뒤에도 넘치지 않는다**
- **참석자 중복 방지**(OQ-909): 이미 담긴 사람은 **검색 결과·조직도에 다시 담기지 않는다**. 같은 사람이 두 번 오면 **서버도 하나로 합친다** — 생성은 이미 합치고(`commands.py:153`), **수정(`MeetingInfoPatch`)은 지금 합치지 않는다** → 수정도 합친다
- 키보드 검색·선택 · 좁은 화면 · 오류 위치는 **이번 범위 밖**(OQ-909)

### 2.2 회의실 고르기 — 생성 · 수정 · AX 카드 (D-07 · D-08 · D-09 · OQ-906)

**한 셀렉트 모양을 네 자리가 같이 쓴다** — 생성 모달 · 수정 모달 · AX 회의 생성 카드 · AX 회의 수정 카드.

```text
기존 — 회의실 3 (변경 안 함)          ← 수정 때만 · 맨 위 (원래 방이 없던 회의면 이 줄도 없다)
─────────────────────────
회의실 예약 없음                       ← 생성 때는 기본값
회의실 1 (6인)                        ← Connect 가용 목록 — 그 시간·그 인원에 쓸 수 있는 방만
회의실 2 (4인)
```

- **목록은 날짜·시작·종료·참석 인원(사내+사외)이 바뀔 때마다 다시 받는다**(지금 생성 모달은 300ms 기다렸다 부른다 — 그 틀을 쓴다 · `BookingModal.tsx:124-160`)
- **정원 조건**: 가용 목록에는 **정원 ≥ 참석 인원**인 방만 선다(지금 목록엔 정원 필터가 없다 — BE §2.2)
- **기존 방 줄(수정 때만)** — 새 조건에서도 그 방을 쓸 수 있으면 고를 수 있고 「(변경 안 함)」. **새 조건에서 쓸 수 없으면 비활성 + 이유 한 줄**(D-08 · 기본값):
  - 시간이 겹침 → 「새 시간에 예약 불가」 · 정원이 모자람 → 「새 인원보다 작은 방」
  - 기존 줄이 비활성이면 **선택이 「회의실 예약 없음」 으로 옮겨 가지 않는다** — 사람이 다른 방이나 「예약 없음」 을 고를 때까지 [저장]이 막힌다
    (조용히 예약이 풀리는 일을 막는다 — OQ-1016 코디 기본값). **막힌 이유를 [저장] 옆에 한 줄로** 보인다 — 「회의실을 다시 골라 주세요 — 기존 회의실을 새 시간·인원에 쓸 수 없습니다」(H-2). 셀렉트 안 회색 글자만으로 두지 않는다
- **「가용 없음」 과 「조회 실패」 를 가른다**(OQ-906):

  | 상태 | 셀렉트 | 문구(OQ-1017 코디 기본값) |
  |---|---|---|
  | 가용 없음(조회는 됨, 쓸 방이 없음) | 기존 줄(있으면) · 「회의실 예약 없음」 만 | 「이 시간·인원에 예약 가능한 회의실이 없습니다」 |
  | 조회 실패(Connect 에 닿지 않음) | 기존 줄은 **「(확인 못 함)」** 으로 고를 수 있게 두고 · 「회의실 예약 없음」 | 「회의실 정보를 불러오지 못했습니다 — 다시 시도」 + [다시 시도] |

  지금은 둘 다 **빈 목록**이라 화면이 가르지 못한다(`bootstrap/application.py:1043-1065` 가 실패를 `[]` 로 삼킨다)
- **조회 실패 중 「기존 (확인 못 함)」 을 둔 채 저장하면**(H-1) — 회의는 저장되고(OQ-1008 · 지금 동작), 시각이 바뀐 경우 Connect 예약은 **옛 시각에 남을 수 있다.** 저장 뒤 결과 줄에
  「회의는 바뀌었습니다 — 회의실 예약은 확인하지 못했습니다. The Connect 에서 확인해 주세요」 를 보인다. **다시 맞추는 단추([다시 동기화])는 이번 판에 없다** — 다음 수정 저장이 다시 맞춘다
- **저장(생성·수정) 직전 서버가 가용을 다시 확인한다**(OQ-906). 그새 방이 찼으면 → **§4.3 오류** + 셀렉트를 **그 시간에 가능한 방만으로 다시 그린다**(넣은 값은 그대로 · 원본 §3.1-11 생성 규칙과 같은 모양). 수정에서는 **자동 대체하지 않는다**(OQ-1004 닫힘 — 거절 + 가능 목록)
- **수정 모달의 장소 자유 입력 칸**(`#meeting-head-place` · FE §4)은 **이 셀렉트로 바뀐다**(OQ-1005 닫힘 — 생성 모달에도 글자 칸이 없다)
- 고른 방은 저장 뒤 회의의 **장소 글자**로도 보인다(지금처럼 `location = room_name`). 「회의실 예약 없음」 으로 저장하면 **예약을 취소하고 장소 글자를 비운다**

### 2.3 「지난 회의 불러오기」 · 안건 출처 (D-10 · D-11)

- 입구는 지금 그대로 — 생성 모달의 제안 카드 「지난 「{회의명}」」 + [불러오기](회의명이 같을 때만 · FE §5-1)
- **[불러오기]는 날짜·시작·종료를 바꾸지 않는다**(D-10 · 원본 §3.1-5 → 이 판). 가져오는 것은 지금처럼 **목적(비었을 때만)·회의실(이름이 같으면)·참석자·결론 안 난 안건**이다
- **안건 출처는 안건마다**(D-11 · 원본 §4.1-2 → 이 판):

  | 안건 | 출처 | 화면 문구 |
  |---|---|---|
  | 불러온 지난 회의의 **결론 안 난** 최종 안건 | `carried` | 「지난 회의에서 넘어옴」 |
  | 사람이 이 회의에서 **새로 쓴** 안건(생성 모달 · 빠른 시작 자리표시 · 회의 중 사람 벌에 더한 것) | `manual` | **「새로 추가된 안건」**(지금 「직접 입력」 → 바꾼다) |

- **문구 변경은 `manual` 을 정하는 자리 전부에 붙는다**(코디 판정 — 출처를 정하는 자리 전부가 같은 규칙): 생성 모달에서 손으로 더한 안건(`BookingModal.tsx:443`) ·
  생성 서버(`mtg/application.py:415`) · **빠른 시작 자리표시 안건**(`:467`) · **메모 폴백 「기존 회의록」 안건**(`:564`) · **회의 중 사람 벌에 더한 안건**(`:1225`).
  빠른 시작의 빈 자리표시·메모 폴백처럼 **사람이 직접 더하지 않은 안건에도 「새로 추가된 안건」 이 선다**(H-4) — 사용자 E2E 에서 확인한다(WORK-012)

- **두 입구가 같다** — 생성 모달 [불러오기] 와 회의 상세의 **[다음 회의 예약]**(지난 회의 미결 안건을 미리 담아 여는 모달 · `MeetingDetailPage.tsx:1393-1399`). 둘 다 **안건마다 출처를 보낸다**
- 불러온 안건을 사람이 지우면 그 안건은 없다. 불러온 안건의 제목을 사람이 고쳐도 **출처는 「넘어옴」 그대로**(OQ-1009 코디 기본값 — 어디서 왔는지는 바뀌지 않는다)

### 2.5 회의록 화면 — 안건 순서 · 용어 보정 표 (D-15 · D-16 · D-17 · D-18)

- **최종 회의록의 안건이 회의 흐름 순서로 선다** — 그 안건의 줄들이 딛는 **가장 이른 근거 구간** 순(D-15). 주제 묶음은 유지한다
- **회의록 화면 끝에 「용어 보정」 표**(D-18 · 기본값):

  | 열 | 값 |
  |---|---|
  | 들린 말 | STT 표기 (예: 「캐스티」) |
  | 바로잡은 말 | 정확 표기 (예: 맥락 목록의 프로젝트명) |
  | 처리 | **「바꿈」**(`auto` — 회의록 본문에 바로잡은 말로 썼다) · **「표에만」**(`presumed` — 본문은 들린 말 그대로, 확인을 사람에게 남긴다) |

  - 표는 **읽기 전용**이다(이번 판) · 최종 벌이 선 회의(「종료」·「실패」에서 사람이 채운 뒤)에서만
  - **비었을 때를 가른다**(H-3): 정정이 돌았고 바꿀 것이 없었으면(`[]`) 표 자리에 **「바로잡은 용어 없음」** 한 줄 · 정정이 돌지 않은 회의(`null` — 이 판 이전 회의·합성 실패)는 **표 자리 자체가 없다**
  - 「바꿈」 은 **되돌릴 수 있는 쌍**이다 — 들린 말이 표에 남아 있어 사람이 [수정]에서 되돌린다(D-16)
- 「참석 N명」 · 화자 라벨은 **그대로**(OQ-905 · D-17 「화자 라벨은 바꾸지 않는다」)

## 3. User Scenario

- **S-1. 수정 모달 일정** — 회의 목록 [수정] → 날짜·시작·종료가 왼쪽 열에 한 줄로 들어가고, 오른쪽 검색 입력 뒤에 아무것도 깔려 있지 않다.
  검색으로 이미 담긴 사람을 다시 고를 수 없다
- **S-2. 수정에서 회의실 바꾸기** — 회의실 3 으로 잡힌 회의를 30분 늦추고 참석자를 둘 더한다 → 셀렉트 맨 위 「기존 — 회의실 3」 이 「새 인원보다 작은 방」 으로 비활성 →
  가용 목록에서 「회의실 1 (6인)」 → [저장] → Connect 예약이 회의실 1·새 시간으로 바뀌고 장소가 「회의실 1」
- **S-3. 조회 실패** — Connect 가 닿지 않으면 셀렉트 위에 「회의실 정보를 불러오지 못했습니다 — 다시 시도」. 「예약 없음」 으로 저장하거나 [다시 시도]
- **S-4. 불러오기** — 생성 모달에서 지난 「주간 회의」 를 [불러오기] → 시간은 내가 정한 그대로, 결론 안 난 안건 둘이 「지난 회의에서 넘어옴」 으로 담김 →
  안건 하나를 더 쓴다 → 회의 시작 화면에서 그 하나는 「새로 추가된 안건」
- **S-5. 회의록** — 1시간 회의를 끝냄 → 최종 합성이 15분 안에 끝나 「종료」 → 안건이 이야기한 순서로 서 있고, 끝에 「용어 보정」 표:
  「캐스티 → (프로젝트명) · 바꿈」 · 「이백만 원 → 200만 원? · 표에만」 → 할 일 기한은 회의일보다 앞서지 않는다
- **S-6. AX 회의 생성** — AX 채팅 「내일 3시 주간 회의 잡아 줘, 민아·지호」 → 회의 생성 카드가 업무 생성 카드처럼 4쪽으로 선다(AX 배지·초안 1회차) →
  「회의실·안건」 쪽에서 가용 회의실 → [수정]으로 생성 모달을 열어 안건을 고치고 「저장」(2회차) → [등록]
- **S-7. AX 회의 수정** — AX 채팅 「그 회의 1시간 미뤄 줘」 → 회의 수정 카드에 새 시간과 회의실 셀렉트(맨 위 기존 방) → [등록] → Connect 예약도 옮겨짐
- **S-8. AX 업무 생성** — 「CRM KPI 정리 업무 만들어 줘」 → AX 가 맥락 목록에 실린 프로젝트 이름에서 그 프로젝트를 바로 잡아 초안의 「업무 연결」 에 넣는다

## 4. Interface Contract

**바뀌는 API·필드·오류만** 적는다. 나머지는 지금 코드 그대로다. 인증·소유는 지금 규칙(`current_principal` · 회의 권한) 그대로다.

### 4.1 회의실 목록 — `GET /api/meetings/rooms` (원본 §3.1-11 → 이 판 · D-07 · D-08 · OQ-906)

| 항목 | 지금 | 이 판 |
|---|---|---|
| 요청 | `?starts_at&ends_at` | `?starts_at&ends_at&people&meeting_id` — **`people`** = 참석 인원(사내+사외) · **`meeting_id`** = 수정 중인 회의(있으면 **그 회의 자신의 예약을 점유에서 뺀다** — 안 빼면 기존 방이 늘 「겹침」 이다) |
| 응답 | `[{room_id, name, capacity, available?}]` · **Connect 실패도 `[]`** | `[{room_id, name, capacity, available, current, unavailable_reason}]` — `available` = 그 시간·인원에 쓸 수 있음 · **`current`** = `meeting_id` 의 지금 방(수정 때 맨 위 줄) · `unavailable_reason` ∈ `time_conflict` · `capacity` · `null`. **`current` 인 방은 쓸 수 없어도 목록에 낸다**(비활성 줄), 그 밖에는 `available` 인 방만 |
| 오류 | 없음(실패를 삼킨다) | **Connect 에 닿지 않으면 `503 ROOM_SERVICE_UNAVAILABLE`** — 「조회 실패」. 예약 시스템이 설정되지 않은 환경(계정 env 없음)은 지금처럼 `200 []` |

- AX 도구 `meeting_room_list` 도 같은 인자(`people` · `meeting_id`)와 같은 규칙을 갖는다(지금은 시간만 · BE §2.2)
- 정원 판정 = `capacity ≥ people`. `capacity` 를 모르는 방은 정원 조건으로 빼지 않는다(OQ-1011 코디 기본값)

### 4.2 회의 생성 — `POST /api/meetings` · AX `meeting.reservation.create` (D-11 · OQ-906)

### 4.5 AI 맥락 목록 — 회의록 · AX 업무 생성이 같이 쓴다 (원본 §7.1·§7.2-1 → 이 판 · D-13 · D-14 · D-20)

**드러나는 계약이 아니라 AI 에 싣는 입력의 계약이다**(사용자에게 화면으로 서지 않는다). 그래도 결정이 정한 범위를 고정하려고 여기 적는다.

| 항목 | 계약 |
|---|---|
| 저장 | **별도 테이블을 두지 않는다.** AI 를 부를 때마다 **그 순간 DB 를 조회**해 조립한다 — 새로 생긴 프로젝트도 다음 호출부터 들어간다 |
| 담는 것 | **조직 전체**(사용자 결정 D-13 — 「프로젝트는 다 · 업무는 완료 안 된 것만 · 구성원은 다」) — **프로젝트 전부** — `{id, name, status}` · **업무 = 완료도 취소도 안 된 것만**(취소 제외 = D-14 **기본값**) — `{id, title, project_id, state, due_date}` · **구성원 전부** — `{id, name, unit, position}`. 호출자 시야로 좁히지 않는다 |
| 쓰는 자리 | ① 회의 **웜스타트**(첫 배치 맥락) ② **최종 합성**(정정 pass 의 근거) ③ **AX 대화**(업무 생성 — D-20 · **매 턴**) |
| 중간 배치(D-13 「중간」) | **세션을 새로 열 때마다 다시 싣는다** — 웜스타트 · **timeout 뒤 새 세션 재시도**(§4.6) · 세션 유실로 다시 시작할 때. 같은 세션을 이어 쓰는 둘째 배치부터는 세션이 이미 받았으므로 다시 싣지 않는다(원본 §7.1 「이후 배치 = 증분만」 그대로) |
| 도구 조회 | **보조로 남는다** — 지금 도구(`task_list` · `project_list` · `meeting_get` · `member_list`)와 레지스트리는 그대로. 「목록에 있는 것은 목록에서 먼저 찾고, 상세가 필요할 때만 도구로」 |
| 크기 | **상한 없음 — 기본값(코디) · 크기 관측 후 재검토**(DEC 에 없는 값 · 근거는 메디니스 「조직 규모에서 전량은 실을 수 있는 크기」 · BE §5.7) |
| 모양 | 프롬프트의 한 덩어리 — 「조직 맥락 목록(이 호출 시각 기준)」 머리 + 위 세 표. 모양 상세는 구현 |
| 범위·권한 | **조직 전체**(D-13) · AX 대화는 **매 턴** — §7 OQ-1002(① 정정 2026-10-07) |

### 4.6 AI 호출 timeout · 재시도 (원본 §8-8 · 구현 → 이 판 · D-12 · OQ-902)

| 단계 | env | 기본값 | 지금 |
|---|---|---|---|
| 회의 배치 | `AX_AI_TIMEOUT_BATCH_SECONDS` | **240** | Codex 90 · Claude 180 고정 |
| 회의 웜스타트 | `AX_AI_TIMEOUT_WARMSTART_SECONDS` | **240** | 같음 |
| 최종 합성 | `AX_AI_TIMEOUT_FINAL_SECONDS` | **900** | 같음 |
| 대화(AX 채팅 · 보고서 생성) | `AX_AI_TIMEOUT_CONVERSATION_SECONDS` | **180** | 같음 |

- **provider 와 무관하다** — Codex·Claude 가 같은 값을 쓴다. 보고서 생성(`generate`)은 지금처럼 대화와 같은 provider 를 쓰므로 **대화 값**을 따른다(도출)
- 재전사 timeout(1200초)은 그대로
- **timeout 재시도 = 새 세션 1회 — 단계를 가리지 않는다**(OQ-902 문장 「timeout 이 나면 같은 세션 3회 대신 새 세션으로 1회」 는 단계 한정이 없다 · 코디 판정):
  - **최종 합성** — timeout 이면 같은 세션 resume 대신 **새 세션으로 1회**(전사 전량은 §4.7 대로 늘 싣는다 · 맥락 목록도). 그 1회도 실패하면 회의는 「실패」(원본 §8-8 그대로 — [다시 시도]는 재전사부터)
  - **배치·웜스타트** — timeout 이면 **새 세션으로 1회**: 웜스타트 맥락(회의 정보·안건·참석자 수·이전 회의·**맥락 목록**)을 다시 보내고 그 배치의 미처리 구간을 싣는다. 그 1회도 실패하면 지금처럼 **조용히 넘기고 다음 배치에 합친다**(원본 §7.1 실패 행). 새 세션이 서면 이후 배치는 그 세션을 이어 쓴다 · **새 세션으로 여는 배치에는 지금까지의 AI 벌(안건·줄)도 함께 싣는다**(새 세션은 앞 배치를 기억하지 못한다 — 구현 확인 2026-10-07, 검수 WP2 W-6)
  - **배치는 회의마다 한 줄로 돈다**(겹쳐 돌지 않는다 — 원본 §7.1 「회의당 배치 하나」) · **재시도(새 세션 1회) 중 도착한 발화는 다음 배치에 합친다** — 배치 한 번이 최대 240+240초 걸려도 90초 배치 주기(`AX_MEETING_BATCH_MAX_WAIT_SECONDS`)와 겹치지 않는다 · **새 세션 참조는 재시도가 성공한 순간 갈아 끼운다**(실패하면 옛 참조를 둔 채 다음 배치가 다시 새 세션을 시도한다 — 코디 판정 W-r2-1)
  - **timeout 이 아닌 실패**(스키마 위반·근거 없는 줄 등)는 지금 규칙(최종 = 시도 3회 · 세션 유실이면 콜드 스타트 / 배치 = 다음 배치에 합침) 그대로다
- **「생성 중」 이 길어진다**(H-9) — 최종 900초 + 새 세션 1회면 최대 약 30분 「정리 중」. 진행 표시·예상 시간 문구는 이번 판에 없다 — 사용자 E2E 에서 체감을 확인한다(WORK-012)

### 4.7 최종 합성 — 정정 pass · 재전사 전체 발화 · 용어 보정 표 · 안건 순서 (원본 §8-3·5·6 → 이 판 · D-15 · D-16 · D-17 · OQ-904)

1. **입력에 재전사 전체 발화를 매번 싣는다**(OQ-904) — 세션을 이어 쓰든 새로 열든. 지금은 콜드 스타트에서만 싣는다(`finalize_service.py:241`)
2. **한 번의 합성 안에서 두 단계**(메디니스 Pass 1 → Pass 2):
   - **정정 pass** — 원문에서 STT 오인식으로 보이는 표기를 **AI 맥락 목록**(§4.5)의 이름에 비춰 고르고 등급을 단다
   - **다시 쓰기** — 정정 결과를 반영해 최종 벌을 처음부터 짓는다(원본 §8-5 그대로)
3. **등급**(D-17 · 기본값):

   | 등급 | 무엇 | 회의록 본문 |
   |---|---|---|
   | `auto` | **확실한 기술 용어·고유명사**(제품·프로젝트·시스템명) | 바로잡은 말로 쓴다 |
   | `presumed` | **인명·숫자·금액·일정** | **들린 말 그대로** — 표에만 남긴다 |
   | (없음) | **화자 라벨** | **바꾸지 않는다** |

4. **결과에 용어 보정 표**가 더해진다 — 사용자에게 보이는 항목 = **`heard`(들린 말) · `corrected`(바로잡은 말) · `grade`(`auto`|`presumed`)**.
   회의 상세 응답의 **최상위**(`meeting`·`agendas` 옆)에 `term_corrections: [{heard, corrected, grade}] | null` 로 실린다(상세 응답에 「최종 벌」 객체가 따로 없다 — 코디 판정 2026-10-07, WP2 구현 질문)(순서 = 원문에 처음 나온 순 — OQ-1012 코디 기본값).
   **「정정이 돌았는가」 는 회의에 남기는 nullable 시각 `term_corrected_at` 이 말한다**(코디 판정 N-1) — 정정 pass 가 들어간 최종 합성이 성공해 적재될 때 그 시각을 찍는다(보정 표 행과 같은 트랜잭션).
   응답: `term_corrected_at` 이 **null 이면 `term_corrections: null`**(정정이 돌지 않았다 — 이 판 이전 회의 · 최종 합성 실패) / **있으면 행 목록**(0개면 `[]` — 돌았는데 바로잡을 것이 없었다 · H-3 · §2.5)
5. **중간 배치는 정정하지 않는다**(D-16) — 배치 출력에 보정 표가 오면 버린다
6. **검증이 하나 는다** — 원본 §8-6 의 다섯 + **보정 표 모양**(`heard`·`corrected` 1~100자 · `grade` 둘 중 하나 · 같은 `heard` 중복은 첫 것만 — 수치·중복 규칙은 OQ-1013 코디 기본값). 보정 표가 틀려도 **시도를 실패시키지 않고 그 항목만 버린다**(근거와 결이 다르다 — 본문은 이미 섰다)
7. **안건 순서**(D-15) — 적재할 때 서버가 최종 안건을 **그 안건 줄들의 가장 이른 근거 시작 시각** 순으로 다시 매긴다(모델이 낸 순서에 기대지 않는다). 줄이 없는 안건은 끝에, 같은 시각이면 모델 순서
8. **원문(스크립트)은 바꾸지 않는다** — 원본 §8-3 「재전사한 최종 원문이 사실의 SoT」 그대로. `auto` 치환을 원문에도 적용하느냐는 OQ-1003

|---|---|---|
| ① 말에 날짜가 있음 | 그 날짜 | 그대로 — 단 **회의일보다 이르면 비운다** |
| ② 다음 회의 전날 | 「이어진 다음 회의(이월 관계이거나 **같은 주제의 다음 예약**)」 — 코드는 **같은 owner 의 아무 다음 예약**까지 잡는다(BE §5.5) | 「다음 회의」 = **이 회의에서 이월된 회의(`carried_from` = 이 회의)만 · 취소된 회의 제외 · 이 회의보다 뒤에 시작하는 것 중 가장 이른 것** · 그 전날이 **회의일보다 이르면 비운다** |
| ③ 없음 | `null` | 그대로 |
| 날짜 계산 | `.date()` — KST 변환 없음 | **모든 날짜를 KST(`Asia/Seoul`)로** 뽑는다 — 회의일 · 다음 회의일 · 하한 비교 |
| 「회의일」 | — | **이 회의의 시작 시각의 KST 날짜.** 같은 날 기한은 허용 |

- 프롬프트·출력 스키마의 기한 설명(②)도 같은 규칙으로 맞춘다 — 모델이 옛 규칙으로 전날을 계산해 ① 로 내는 경로(BE §5.5 경로 (d))도 하한 검사가 막는다
- 회의 중 잠정 후보의 기한도 같은 하한을 탄다(OQ-1014 코디 기본값)
- **비운 이유는 남기지 않는다**(H-10) — 「금요일까지라고 했는데 기한이 없다」 로 보일 수 있다. 사용자 E2E 에서 확인한다(WORK-012)

### Validation

- 안건 `source` ∈ `manual`·`carried` — 그 밖은 `422` · `carried` 는 `carried_from_meeting_id` 가 있어야 한다
- 회의실 `people` 은 0 이상 정수 · `meeting_id` 는 호출자가 수정할 수 있는 회의여야 한다(아니면 그 인자를 무시하지 않고 `404`)
- `room.room_id` 는 §4.1 이 낸 방이어야 한다 — 아니면 `422 ROOM_NOT_FOUND`
- 보정 표 항목은 §4.7-6
- timeout env 는 **양의 정수(초)** — 숫자가 아니면 지금 설정 로딩(`settings.py:202-213` 의 `int(os.getenv(...))`)처럼 시작 때 예외로 멈추고, **0·음수도 시작 오류로 멈춘다**(조용한 기본값 금지 — OQ-1015 코디 기본값)

## 5. Implementation Rules

### 서버

- **회의실** — Connect 어댑터(`platform/the_connect.py`)의 가용 계산에 **정원 조건**과 **「이 회의 자신의 예약을 점유에서 뺀다」** 를 더한다.
  어댑터의 실패(`RoomGatewayUnavailable` 등)를 **목록에서 `[]` 로 삼키지 않고 `503` 으로** 올린다(`bootstrap/application.py:1043-1065`).
  수정의 Connect 동기화(`_sync_room_reservation`)는 **방 변경·예약 신설·취소**를 다 받는다 — 새 예약은 생성의 이중 예약 울타리(`meeting_room_creation_attempts`)를 그대로 쓴다
- **안건 출처** — 생성의 「회의 단위 출처」(`mtg/application.py:415`)를 **안건별 값**으로 바꾼다. **생성 전용 안건 입력 모델을 따로 둔다**(안건별 `source` 를 받는다 — 코디 판정 W-r2-5). 지금 `MeetingAgendaDraftInput` 은 회의 중 안건 추가 입구(`mcp.py:905,1779` · `http.py:87` · `bootstrap/application.py:3889`)도 쓰므로 **그 모델은 그대로(`title` 만)** 두고, 생성 입력(`MeetingReservationInput.agendas`)만 새 모델을 쓴다
- **AX 회의 수정 카드** — `meeting.info.update` 를 `SUPPORTED_ACTION_TYPES`(`confirmation.py:29-36`)에 더하고 `_edit_contract` 갈래(`platform/actions.py:1690-1706`)에 회의 수정 편집 계약을 세운다 · 화면 카드 고르기(`MessageList.tsx:295-333`)에 갈래를 더한다 · 옛 `meeting.update` 실행(`bootstrap/application.py:3745-3765`)은 새 수정 검증 경로를 부른다
- **AI 맥락 목록** — 조립 함수 **하나**를 회의 웜스타트·최종 합성·AX 대화가 같이 부른다(세 자리에 따로 짜지 않는다)
- **timeout** — provider 를 만드는 자리(`create_conversation_provider` 와 그 호출부)가 **단계 값**을 받는다. 지금은 프로필 하나(`CodexCliProfile(runtime_home=…)`)에 기본값 90 이 박혀 있다
- **기한** — `next_meeting_after` · `resolve_due` · 날짜 변환(`_aware(...).date()`)을 한 규칙으로 맞춘다. KST 상수는 이미 `rooms.py`·`export.py` 에 있다 — 같은 값을 쓴다
- **보정 표** — 최종 출력 스키마(`ai_final_output.json`)·파서(`finalize.py`)·적재·회의 상세 응답에 같은 모양으로

### 프론트

- 회의실 셀렉트는 **부품 하나**로 네 자리(생성·수정 모달 · AX 생성·수정 카드)에서 쓴다
- AX 회의 생성 카드는 **`AxDraftCard` 의 틀**(쪽 나눔·머리·단추·접힌 한 줄)을 쓰고 쪽 내용만 회의 것으로 — 새 카드 틀을 따로 짓지 않는다
- 안건 출처 문구 `manual` = 「새로 추가된 안건」(`labels.ts:750`)
- DS 부품 안에서 — 새 시각 요소는 만들지 않는다

### 스키마 변경

- 보정 표 저장 · AX 회의 초안 저장 · 안건 출처(이미 칸은 있다)의 저장 구조는 **WORK-012 Domain/Schema**. 운영은 `backend/migrations/manual/*.sql`

## 6. Verification

### Acceptance Criteria

**회의 정보 수정 모달**

- AC-01 수정 모달에서 날짜·시작·종료가 왼쪽 열 안에 들고, 종료 시각 칸이 검색 입력 밑에 깔리지 않는다(앱 창 기본 크기 · 생성 모달도 넘치지 않음)
- AC-02 이미 담긴 참석자는 검색·조직도에서 다시 담기지 않는다 · 수정 API 에 같은 id 가 두 번 와도 하나로 저장된다

**회의실**

- AC-03 생성·수정·AX 생성 카드·AX 수정 카드에서 **같은 셀렉트**가 선다 — 수정만 맨 위 「기존 — 회의실 N (변경 안 함)」
- AC-04 가용 목록은 시간·인원 조건을 따르고(정원 ≥ 인원), 조건이 바뀌면 다시 받는다
- AC-05 기존 방을 새 조건에서 못 쓰면 그 줄이 비활성 + 이유(시간 · 정원)
- AC-06 **수정에서 방을 바꾸면 Connect 예약이 그 방·그 시간으로 바뀐다**(실물 1회) · 「회의실 예약 없음」 이면 예약 취소·장소 비움 · 예약 없던 회의에 방을 고르면 새 예약(중복 없음)
- AC-07 Connect 장애 때 목록이 `503` 이고 화면이 「불러오지 못했습니다」 를 「가용 없음」 과 다르게 보인다 · 저장 때의 장애는 문구로 알린다(동작은 OQ-1008)
- AC-08 저장 직전 그새 방이 찼으면 `409 ROOM_BOOKING_REFUSED` + 가능한 방만으로 셀렉트가 다시 선다

**불러오기 · 안건 출처**

- AC-09 [불러오기]가 날짜·시작·종료를 바꾸지 않는다
- AC-10 불러온 미결 안건만 「지난 회의에서 넘어옴」, 손으로 쓴 안건은 「새로 추가된 안건」 — 생성 모달 · [다음 회의 예약] 두 입구 모두
- AC-11 `carried` 안건 + 이어온 회의 없음 = `422`

**회의록**

- AC-12 단계별 timeout 이 env 로 바뀌고 기본값이 240/240/900/180 이다 — 설정 시험 + **실물 1회: 30분 이상 회의의 최종 합성이 90초를 넘겨도 끝난다**
- AC-13 최종 합성 첫 시도가 timeout 이면 새 세션 1회로 다시 걸린다(시험 — 같은 세션 resume 이 3번 나지 않는다) · **배치·웜스타트도** timeout 이면 새 세션 1회(웜스타트 맥락·맥락 목록을 다시 보냄) → 그것도 실패면 그 구간을 다음 배치에 합친다 · 재시도 중 도착한 발화는 다음 배치로 가고 배치가 겹쳐 돌지 않는다 · 새 세션 참조는 성공 때만 바뀐다(시험)
- AC-14 최종 합성 입력에 재전사 전체 발화가 언제나 실린다(이어 쓰기 포함)
- AC-15 회의록 끝에 「용어 보정」 표 — `auto` 는 본문이 바뀌어 있고 `presumed` 는 본문이 그대로 · 화자 라벨 불변 · 중간 배치에는 표가 없다
- AC-16 최종 안건이 가장 이른 근거 시각 순으로 선다
- AC-17 할 일 기한이 회의일(KST)보다 이르지 않다 — 「다음 회의」 는 이월 회의만·취소 제외 · 10-07 사례 재현(같은 날 오후 다른 예약) 시 기한 `null`
- AC-18 AI 맥락 목록이 웜스타트·최종·AX 대화에 실린다(프로젝트 전부 · 완료·취소 안 된 업무 · 구성원 전부) — 프롬프트 스냅숏 시험 · 새 프로젝트를 만들면 다음 호출에 들어간다

**AX**

- AC-19 AX 회의 생성 카드가 쪽 나눔·AX 배지·회차·거절·수정(초안 저장)·등록을 갖는다 · 프로젝트·연관 업무 칸은 없다
- AC-20 AX 회의 생성 카드에 근거 자료가 서고 첨부 초안을 붙일 수 있다
- AC-21 AX 회의 수정 카드가 **고칠 수 있는 카드**(새 편집 계약 — 결과 카드가 아님)로 서고, 회의실을 바꾸면 Connect 예약이 바뀐다(실물 1회) · **옛 `meeting.update` 확정도 저장 직전 재확인·`409 ROOM_BOOKING_REFUSED` 를 탄다**(시험)
- AC-22 AX 업무 생성이 맥락 목록의 프로젝트 이름으로 프로젝트를 잡는다(시험 대역 + 실물 1회)
