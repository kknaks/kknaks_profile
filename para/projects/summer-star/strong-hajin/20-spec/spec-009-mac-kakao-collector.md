# Mac 카톡 수집기 — 로컬에서 읽어 서버로 올리는 조회 전용 백그라운드 앱

> **⚠ v0.5.1 (2026-10-06 · 4차 검수 ★1·★2·W4-2 — `review-spec-work-r4.md`)** — handshake `selected_rooms` 에
> **`external_id`(=chatId)** 추가(서버 room_id ↔ 로컬 chatId 매핑 · ★1) · 메시지 키·aid 를 **`(연동,chatId,logId)`**
> 로 맞춤(S8 과 일치 · W3-7 잔여) · 「다시 연결」(`reset-account`)은 **웹 세션 라우트**이고 앱은 handshake `reset_at`
> 으로 안다(★2).

> **⚠ v0.5.0 (2026-10-06 · 3차 검수 R3-F1·R3-F2·W3 — `review-spec-008-009-r3.md`)** — **R3-F2** 닫기 = **웹뷰 실제
> 파괴 · 앱 프로세스만 메뉴 막대 상주**(「숨기기」가 아니다 — 숨은 웹뷰가 녹음을 이어가는 사고를 막음). 수집기는
> 네이티브+기기 토큰이라 창과 무관하게 돈다. **R3-F1** 기기 토큰 = **`Authorization: Bearer` · 서버 해시만 보관 ·
> §4.6 수집기 라우트+고른 방 조회 범위만** · 발급은 세션 있는 웹이 하고 **`kakao_store_device_token` 으로 Rust
> 키체인에** 넣는다 · 새 발급은 옛 토큰 철회(D-45). **W3-3** 고른 방 변경은 status 응답 `selected_rooms_version` 으로
> 알아 handshake 재호출 · **W3-7** 머리·필드 정정(선택은 **서버 정본** · `selected_rooms`). **SPEC-006 은 v0.6.0.**
>
> **⚠ v0.4.0 (2026-10-06 · 재검수 R-F1·R-F2 — `review-spec-008-009-r2.md` · 사용자 정정 반영)** — **R-F1(정정)**

### Business Requirement

Mac 앱이 **백그라운드로 상주**하며, 카카오톡이 켜져 있고 사람이 **고른 방**의 대화를 로컬에서 읽어 서버로
올린다(D-14·D-18). 서버 메시지함은 그것을 **조회만** 한다(D-17). 과거는 **이 Mac 로컬에 있는 만큼**(D-20).

### Scope

**In Scope**

- 백그라운드 상주 · 카카오톡 실행 여부 확인 · 로그인 계정 = 카톡에 로그인한 계정 · 계정 바뀌면 멈춤(D-45)
- 로컬 DB 를 **읽기 전용**으로 여는 **원칙**(사본/읽기 전용) — 여는 **방식**은 구현 몫(위 경계)
- 방 목록(1:1·단체, 오픈채팅 제외) · 메시지(고른 방만) · 실시간 감지(폴링) · 고른 방 정보 **로컬 저장**
- 첨부 — 사진·앨범·파일 = 감지 즉시 CDN 에서 받아 **서버로 업로드** · 동영상·음성 = 메타만 · 이모티콘 = 표식 ·
  만료 = 「만료됨」
- 서버 업로드·상태 보고(SPEC-008 §4.6 소비) · 전체 디스크 접근 권한 안내

**Out of Scope**

- **발송**(D-17) · 오픈채팅방(D-18) · Windows(D-14)
- **DB 여는 방식의 절차**(키·userId·복호) — 구현 몫, 근거 문서 참조만(머리 주석)
- 서버 쪽 저장·조회·렌더 — SPEC-008
- 동영상·음성 **파일** 저장(메타만, D-31)

### 이 앱과 SPEC-006 래퍼의 관계 — **경계가 다르다**

SPEC-006 데스크톱 래퍼는 **커맨드 넷**(`shell_info`·`wake_guard_acquire`·`wake_guard_release`·`open_external`)뿐이고
**파일 시스템·프로세스·범용 셸 권한이 하나도 없다**(`frontend/src-tauri/src/lib.rs:7-13`). 카톡 수집은 **로컬
파일(카톡 DB)을 읽고 전체 디스크 접근을 요구**하므로 **그 불변식과 정면으로 다르다.**

→ **수집을 회사판 medi-ax 데스크톱 앱에 더한다**(사용자 결정 2026-10-06 · OQ-901 닫힘 · W-7 — 운영 서버에 붙는

SPEC-006 의 다음이 **더는 성립하지 않아 개정이 필요하다**(W-6 — I-2 하나가 아니다):

| 깨지는 것 | SPEC-006 근거 | 왜 |
|---|---|---|
| 불변식 **I-2** 커맨드 넷 | `lib.rs:7-13` | 수집은 로컬 파일을 읽는다(커맨드/권한이 는다) |
| 「창 하나·트레이 없음·백그라운드 없음」 | SPEC-006 §2·`:110`·`:272` · AC-T23·T33·T47 | 수집기는 창 없이 상주하고 **메뉴 막대 아이콘**을 쓴다(§2.1) |

**이 개정은 SPEC-006 v0.6.0 이 받는다.** v0.4.0 이 트레이·백그라운드·전체 디스크 접근을, v0.6.0 이 **닫기=웹뷰 파괴·프로세스만 메뉴 막대 상주**(R3-F2 — 「숨기기」가 아니라 L-06·S-6 무변경)·**카톡 방 «목록 탐색» 커맨드 + `kakao_store_device_token`**·판 가르기(N-10)를 더한다. SPEC-009 는 능력의 계약을 세우고 SPEC-006 이

## 2. UX Contract

이 앱은 화면이 거의 없다 — **상태를 서버(설정 카톡 메뉴)가 보인다**(SPEC-008 §2.5). 앱 자신의 표면은 최소다.

### 2.1 앱 표면 (최소)

- **상주 표식**: 메뉴 막대/트레이 아이콘 — 켜짐/수집 중/멈춤. 창은 필수가 아니다
- **상주·창(R3-F2)**: 수집은 **회사판 medi-ax** 에 들어간다. **창(웹뷰)을 닫으면 창은 실제로 파괴되고 앱 프로세스만
  메뉴 막대에 남는다**(마지막 창이 닫혀도 종료를 막는다 · 종료는 트레이 메뉴 · 트레이 「열기」가 창을 새로 만든다).
  **「숨기기」가 아니다** — 숨은 웹뷰가 마이크를 이어 돌리거나 녹음 중 기기가 잠드는 사고를 막기 위해서다(SPEC-006
  L-06·S-6 무변경). **수집기는 창과 무관**하게 네이티브+기기 토큰으로 돈다(SPEC-006 v0.6.0)
- **권한 안내(N-11)**: 전체 디스크 접근(FDA)이 없으면 **한 화면** — 「시스템 설정 > 개인정보 보호 > 전체 디스크 접근에서 **medi-ax** 를 켜 주세요」 + 여는 단추. **딥링크(`x-apple.systempreferences:`)는 `open_external`(http(s) 전용 · `guard.rs:125-135`)로 못 열어 수집기 네이티브 코드가 직접 연다**(웹 커맨드 아님). **FDA 는 plist 키·entitlement 로 얻는 것이 아니라 사용자의 TCC 허용**이고, 앱은 읽기 실패를 `reason=permission` 으로 감지한다(`kakao-survey.md` §3)
- **인증(장수명 기기 토큰 · R3-F1)**: 앱 웹뷰 설정의 「이 Mac 연결」 단추 → **세션 있는 웹이 `POST /api/device-tokens`
  로 발급** → 받은 토큰을 **`kakao_store_device_token` 커맨드로 Rust 키체인에** 넣는다(화면·브라우저 저장소에 안 남김).
  수집기는 그 토큰을 **`Authorization: Bearer`** 로 §4.6 라우트에만 쓴다 — **창 쿠키에 기대지 않아 창을 닫아도 수집
  이어짐**. 토큰이 없거나 철회되면 상태 `login_required`(앱 로컬 표식) + 트레이. 자세히는 §4

### 2.2 상태는 서버가 보인다 (SPEC-008 §2.5 · §4.6 status)

앱이 보고하는 상태가 설정 카톡 메뉴의 상태 카드로 나타난다. 보고 필드는 **SPEC-008 §4.6 `status` 가 정본**:

- `app`: `on`(기기 이름·버전)/`off` — **주기 보고 30초**, 서버가 「90초 무보고 = `off`」 판정(W-3)
- `kakao`: `running`(이 Mac 로그인됨)/`off`/**`unreadable`** + `reason`: `permission`(전체 디스크 접근 없음)·
  `version`(DB 못 엶)·`unknown`(W-2 · D-42)
- `account`: 카톡 로그인 계정 이름 · `account_changed:true` 면 **멈춤**(「계정이 바뀌었습니다 — 다시 연결」 — 이 단추는 **웹 세션 라우트** `reset-account` ★2 · 앱은 handshake `reset_at` 으로 안다, W-4·D-45)
- **방별 상태(W-1)**: 메시지 묶음 업로드의 `backfill_done` 표지로 서버가 `backfilling`→`live` 로 바꾼다
  (로컬에 있는 만큼 거슬러 올라간 뒤). `paused` 는 `app:off`/`kakao:off` 에서 파생

## 3. 수집 경계 — 입출력 계약 (**절차는 구현 몫**)

로컬 DB 를 **여는 방식**은 이 문서가 쓰지 않는다(머리 주석 · 근거 `kakao-db-fields.md`). 여기서는 **그 경계가
무엇을 받고 무엇을 내는지**만 고정한다. 구현은 이 입출력을 지키면 된다.

### 3.1 경계

| 쪽 | 계약 |
|---|---|
| **입력** | **카카오톡에 로그인한 계정**(사람이 고르는 목록 없음, D-18·D-38). 그 계정의 로컬 데이터가 수집 대상이다 |
| **출력 — 방 목록** | `(방 id · 종류 1:1/단체 · 이름 또는 참여자 이름)`. **오픈채팅 제외**(D-18). 이름이 비면 참여자로 엮는다(`kakao-db-fields.md` §5). **이 목록은 서버가 아니라 앱 웹뷰의 프론트에 Tauri 커맨드로 준다**(R-F1 · §3.2) |
| **출력 — 메시지 행** | `(chatId · logId · 발신자 · 보낸 시각 · 종류 · 본문 · 첨부 메타)` — 업로드는 서버 내부 `room_id`(handshake 의 `external_id`=chatId 로 매핑 · ★1)로 보낸다. **중복 방지 키 = `(연동, chatId, logId)`** · `aid`=`SHA-256("{연동}:{chatId}:{logId}:{seq}")`(W3-2) — SPEC-008 §4.6 이 중복을 버린다(`kakao-db-fields.md` §6) |
| **출력 — 첨부 메타** | 종류(사진·앨범·파일·동영상·음성·이모티콘) · 이름·크기·MIME · CDN 참조 · 만료 추정(`kakao-db-fields.md` §2·§3·§4) |
| **실패** | DB 를 못 열면 **「읽기 불가」 상태**(권한/버전) — 예외를 삼키지 않고 상태로 올린다(SPEC-008 §4.6 status `unreadable` · D-42) |

- **원칙**: **읽기 전용**으로 연다(사본 또는 읽기 전용 열기 — `kakao-db-fields.md` 방법). 카톡 DB 를 쓰거나
  바꾸지 않는다. 키·복호 결과·DB 경로는 **Mac 밖으로 내보내지 않는다**(D-16)
- **로그인 계정 식별자를 못 찾는 경우가 있다**(`kakao-db-fields.md` §0-2·§8 DB-1) — 그 복구 역시 **구현 몫**.
  복구에 실패하면 위 「실패」로 떨어진다

### 3.2 고른 방 · 실시간

- **방 «목록 탐색»만 로컬, 고른 방(선택)은 서버 정본이다(R-F1 정정 2026-10-06).** 앱 웹뷰의 설정 프론트가
  **Tauri 커맨드**로 **방 목록을 Rust 로컬 카톡 DB 에서** 받아 고르기 창에 그린다(① 목록 조회만 로컬). **고른 결과의
  저장은 서버 API `POST /api/integrations/{id}/rooms`**(② 선택은 서버 · D-26). 빼기·현재 선택 조회도 서버다
- 수집기는 **handshake·생존 신호 때 서버의 고른 방(`selected_rooms`)을 받아 로컬 캐시**한다(SPEC-008 §4.6) — 그 방만
  수집한다. **선택 정본은 서버**이고 로컬 캐시는 사본이다. Tauri 가 웹뷰에 노출하는 것은 **방 «목록 탐색» 커맨드**
  (SPEC-006 v0.6.0) — 선택 저장 커맨드가 아니다(선택은 프론트가 서버 API 로 직접)
- **실시간 감지 = 폴링**(`kakao-survey.md` §2 — 로컬 변경을 주기로 확인). **기본 간격 2초**(사용자 결정 2026-10-06 · OQ-902)
- **최초/재시작**: 서버가 준 마지막 반영 지점 이후만 올린다(빠진 것 메우기, SPEC-008 §5)

## 4. Interface Contract

이 앱이 **서버에 거는 호출은 SPEC-008 §4.6 다** — 여기서 다시 정의하지 않고 소비한다.

| SPEC-008 §4.6 경로 | 이 앱이 쓰는 때 |
|---|---|
| `GET …/kakao/handshake` | 붙을 때 — **서버의 고른 방(`selected_rooms`:{room_id, external_id=chatId, last_logId})** · `reset_at` · `selected_rooms_version`(로컬 캐시 · ★1·W3-3) |
| `POST …/kakao/messages` | 메시지 묶음 올리기(그 방이 서버의 고른 방이어야 · 서버가 **`(연동,chatId,logId)`** 로 중복 버림) — **매니페스트 없음**(서버 정본) |
| `POST …/kakao/attachments/{aid}` | 사진·앨범·파일 바이트 + 메타 올리기 |
| `POST …/kakao/status` | 앱·카톡·계정·읽기 불가 상태 보고 |

### 인증 (R3-F1 · OQ-906 닫힘)

- 앱은 **장수명 기기 토큰**으로 서버에 붙는다 — 발급은 **세션 있는 앱 웹뷰**가 `POST /api/device-tokens`(SPEC-008 §4.2),
  받은 토큰을 **`kakao_store_device_token` 커맨드로 Rust 키체인에** 넣는다(화면·저장소에 안 남김). 수집기는 그 토큰을
  **`Authorization: Bearer`** 로 §4.6 라우트에만 쓴다 — **서버는 토큰의 해시만 보관**(원문 재조회 불가)
- **범위**: 이 토큰은 **§4.6 수집기 라우트 + 카톡 고른 방 조회에만** 통한다 — 웹 라우트(`current_principal`)엔 거절.
  만료 없음 → 서버가 「마지막 사용 시각」을 보인다
- **창 쿠키에 기대지 않아** 창을 닫아도(= 웹뷰 파괴 · 프로세스만 상주 · R3-F2) 수집이 이어진다 — 주말 내내 창을
  닫아 둬도 토큰으로 올려 사진 CDN TTL(~3일) 안에 받아 둔다
- **철회·무효**: 설정에서 철회(`DELETE /api/device-tokens/{id}`) · **새 발급은 같은 회원의 옛 토큰을 철회**(D-45 —
  사람당 Mac 한 대) · 비밀번호 변경·회원 비활성 때 함께 무효. 토큰이 없거나 철회되면 상태 `login_required`(앱 로컬
  표식 · 서버가 아니라 앱이 띄운다 · N-12) + 트레이. 다시 연결하면 **handshake 의 `selected_rooms` 마지막 지점부터** 메운다

### 첨부 처리 (D-30·D-31)

| 종류 | 처리 |
|---|---|
| 사진 · 앨범 · 파일 | **감지 즉시** CDN 에서 받아 `POST …/kakao/attachments` 로 업로드(서버가 hostPath 저장). CDN 은 **시간제한**(사진 ~3일 · 파일 ~14일, `kakao-db-fields.md` §3)이라 **늦으면 못 받는다**. **50MB 를 넘으면 받지 않고** 메타만 올린다 — 메시지함은 「너무 큼 — 카톡에서 확인」(v0.2.0 · SPEC-008 §2.2) |
| 동영상 · 음성 | **메타만** 올린다(파일 안 받음 · 크기 무관). 메시지함은 표시만(「카카오톡에서 보기」) |
| 이모티콘 · 스티커 | **표식만**(「(이모티콘)」) — CDN URL 이 아니라 스토어 경로(`kakao-db-fields.md` §2) |
| 만료 | 수집 전에 CDN 이 만료되면 **「만료됨」** 메타로 올린다(복구 안 함, D-30) |

### Validation / 경계

- 오픈채팅방은 방 목록에서 **뺀다**(D-18)
- 계정이 바뀌면 **수집 멈추고** `account_changed` 보고(D-45) · 카톡은 **계정당 Mac 한 대**(`kakao-survey.md` §5 K-12)
- 카톡이 꺼져 있으면 **새 메시지가 로컬에 안 들어온다** — 조회는 로컬에 있는 것까지(`kakao-survey.md` §2·K-1).
  꺼짐을 상태로 올린다

## 5. Implementation Rules

- **Rust 로 직접 구현**한다. DB 여는 방식은 **mykakao Mac 방식**(자체 키 유도 + 표준 sqlcipher)을 따른다 —
  mykakao DEC-001(채택) · SPEC-001. **`kakaocli` 는 참고(reference-only)일 뿐** 사이드카·런타임 의존이 아니다
  (mykakao DEC-001 「kakaocli 는 reference-only, 런타임 의존성으로 두지 않는다」). 참고 시 라이선스(MIT) 표기
- **DB 여는 방식(키·userId·복호)의 절차는 이 문서 밖**이다 — 근거 `…/mykakao/20-spec/spec-001-message-extraction.md`
  (user_id 복구 절차 포함) · `kakao-db-fields.md`. §3.1 입출력만 지키면 된다
- 카톡 DB 는 **읽기 전용**(사본/읽기 전용 열기). 쓰기·체크포인트·앱 조작 없음
- 키·DB 경로·복호 결과는 **Mac 안에서만**. 서버로 가는 것은 §3.1 출력과 §4 상태뿐(D-16)
- 전체 디스크 접근이 필요(`kakao-survey.md` §3) — 없으면 §2.1 안내, 상태 `unreadable`
- **폴링 간격 기본값 = 2초**(OQ-902 닫힘 — 사용자 결정 2026-10-06). 백오프는 구현
- **수집은 회사판 medi-ax 데스크톱 앱에 더한다**(OQ-901·W-7 닫힘). 그 앱에서 깨지는 SPEC-006 불변식·AC·셸
  시험은 **§1 관계 표**가 전수로 세며, **SPEC-006 v0.6.0 이 그것을 고친다**(이번 판에서 함께)
- 서버 호출은 SPEC-008 §4.6 계약을 **그대로** 따른다 — 이 앱이 스키마를 새로 만들지 않는다

## 6. Verification

### Acceptance Criteria

- AC-01 앱이 백그라운드로 상주하고, 전체 디스크 접근이 없으면 §2.1 안내를 보인다
- AC-02 카카오톡 실행/꺼짐/**읽기 불가(권한·버전)**를 상태로 올린다(SPEC-008 §4.6 status)
- AC-03 카톡 로그인 계정 이름을 올리고, 계정이 바뀌면 **수집을 멈추고** `account_changed` 를 보고한다(D-45)
- AC-04 방 목록 = **1:1·단체만**(오픈채팅 없음). 이름 없는 방은 참여자 이름으로
- AC-05 방 **목록 탐색만 로컬**(Tauri 커맨드) · **고른 방(선택)은 서버 정본**(`POST …/rooms`), 수집기는 handshake 로
  받아 로컬 캐시(R-F1 정정) · 그 방만 올린다 · 서버가 고른 방 아니면 **403**(매니페스트 없음)
- AC-06 메시지 행이 `(방 id, 메시지 번호)` 로 중복 없이 올라간다 · `backfill_done` 표지로 방이 `live` 가 된다(W-1)
- AC-06b 상태를 **주기(30초)로 보고**하고, **기기 토큰으로 붙어 창을 닫아도(웹뷰 파괴·프로세스 상주) 수집이 이어진다**(R3-F2·OQ-906) ·
  토큰 없음/철회면 `login_required`(앱 로컬 표식) · 계정이 바뀌면 `account_changed` 보고 → 사람이 웹에서 `reset-account`(세션 · ★2) → 앱은 handshake `reset_at` 으로 재개(W-4)
- AC-07 사진·앨범·파일 = 감지 즉시 받아 업로드 · 동영상·음성 = 메타만 · 이모티콘 = 표식 · 만료 = 「만료됨」
- AC-08 카톡 DB 를 **읽기 전용**으로만 연다(쓰기·조작 없음) · 키·DB 경로가 서버로 가지 않는다
- AC-09 DB 를 못 열면 예외를 삼키지 않고 「읽기 불가」 상태로 올린다
- AC-10 서버 호출이 **SPEC-008 §4.6** 그대로다(그 사람 세션으로 붙음)
