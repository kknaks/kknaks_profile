# SH-IMP-015 — 메시지 호버 행동 막대(스레드 열기 · AX 업무 생성)

상태: 미착수  
생성일: 2026-10-07  
갱신일: 2026-10-07  
출처: 사용자 제안(슬랙 화면 비교), 2026-10-07

## 문제

메시지함의 대화(슬랙·카톡)·메일에서 메시지 하나를 두고 할 수 있는 행동이 없다. 스레드는 「답글 N개」 를 눌러야만 열리고, 메시지를 업무로 옮길 길이 없다.
(WORK-011 1단계는 「메시지함 = 조회·읽음, hover 행동 막대 없음」 으로 정했다 — DEC-008. 이 항목은 그 결정을 2단계에서 넓히는 것.)

## 기대 결과

- 메시지에 마우스를 올리면 슬랙처럼 오른쪽 위에 작은 **행동 막대**가 뜬다
  - **스레드 열기 / 답글 달기**(슬랙) — 오른쪽 스레드 패널을 연다
  - **AX 업무 생성** — 이 메시지(필요하면 앞뒤 대화)를 근거로 AX 초안을 만들어 업무 > 수신함(또는 새 업무 창)으로 → [SH-IMP-008](SH-IMP-008-message-to-task-ax.md) 과 같은 흐름
  - (선택) 원문 열기 · 링크 복사
- 카톡은 조회 전용이라 「답글」 없이 AX 업무 생성만
- 메일은 메일 머리(답장 옆)에 같은 AX 업무 생성

## 코디 의견 (2026-10-07)

- AX 업무 생성은 **메시지 한 줄이 아니라 맥락**을 넘긴다 — 슬랙은 스레드 전체(있으면), 카톡은 앞뒤 몇 줄, 메일은 그 메일. 한 줄만 주면 AX 가 업무 내용을 지어낸다
- 결과는 바로 업무가 아니라 **AX 초안 → 사람이 「등록」**(기존 원칙 「AX 초안 = 새 업무 추가를 AI 가 채운 것」)
- 만든 업무의 출처 행에 **원래 메시지로 돌아가는 링크**(출처 종류 「외부 수집」 — DEC-008)
- 메시지 쪽에는 **「업무 만듦」 표시**를 남겨 같은 메시지로 두 번 만드는 것을 줄인다(막지는 않음)
- 행동 막대는 슬랙 = 스레드 열기 · AX 업무 생성 / 카톡 = AX 업무 생성만 / 메일 = 머리에 AX 업무 생성

## 사용자 추가 (2026-10-07)

- **두 단계 호버(슬랙과 같게)**: 1차 = 메시지에 호버하면 **아이콘만** 있는 막대(글자 없음) · 2차 = 막대의 아이콘에 호버하면 그 위에 **설명 툴팁**(예: 「스레드의 댓글」 · 「AX 로 업무 만들기」)
- **AX 업무 생성은 AX 와 같이 간다** — 단추를 누르면 기존 AX(채팅 서랍)가 그 메시지 맥락을 받아 열리고, AX 가 기존 「AX 초안」 흐름으로 업무 초안을 만든다(별도 창·별도 흐름을 새로 만들지 않음)

## 막대 구성 (사용자 확정 2026-10-07)

| 채널 | 1차 호버 아이콘(2차 호버 = 설명 툴팁) |
|---|---|
| 슬랙 | **스레드 열기** · **AI 업무 생성** · **AI 내용 요약** |
| 카톡 | **AI 업무 생성** · **AI 내용 요약** |

- **AI 내용 요약**: 그 메시지가 속한 맥락(슬랙 = 스레드 전체 또는 그 앞뒤 대화 덩어리 · 카톡 = 앞뒤 대화)을 AX 채팅 서랍에서 요약해 보여 준다 — 업무 생성과 같은 AX 흐름, 요약은 저장하지 않는다(필요하면 AX 에서 업무로 이어 감)
- 표기는 제품 용어에 맞춰 「AX」 로 쓸지(「AX 업무 생성 · AX 요약」) 시안 때 정한다

## 동작 (사용자 확정 2026-10-07)

막대 = **스레드에 답글 | 업무 생성 | 내용 요약** (슬랙 앱 호버 막대와 같은 모양 · 아이콘만 · 아이콘 호버 = 툴팁). 카톡은 업무 생성 | 내용 요약.

| 단추 | 순서 |
|---|---|
| 업무 생성 | ① 오른쪽 AX 채팅 서랍이 열린다 ② 채팅에 「(해당 메시지) 읽고 업무를 생성해 줘」 말풍선이 선다 — **실제로는 그 메시지 위아래 100줄**을 AX 에 넘긴다 ③ 기존 AX 업무 생성 흐름(스텝 바이 스텝)으로 진행 ④ AI 업무 생성 추천이 제시된다 |
| 내용 요약 | ① 오른쪽 AX 채팅 서랍이 열린다 ② 「(해당 메시지) 요약해 줘」 말풍선 — 실제로는 위아래 100줄 ③ 요약을 답한다 |

## 코드 확인 — 가능 여부 (2026-10-07 · origin/main f0ad522)

- **가능하다.** 대화 전송이 이미 「본문 + 참고 자료(`context`)」 를 따로 싣는다 — `sendConversationMessage(id, body, context[])`(`lib/api.ts:744`), 서버가 참고 자료를 프롬프트에 붙인다(`platform/codex_cli.py:558`). 말풍선 = 본문, 100줄 = 참고 자료로 나뉜다
- 지금 참고 자료 종류는 `task | work_request` 둘(`viewModels.ts:1030`) — **「메시지」 종류 하나를 더한다**(방 id + 메시지 key). 100줄은 **서버가 DB 에서 꺼내** 프롬프트에 싣는다(프론트가 본문을 실어 보내지 않음 · 남의 방이면 거절)
- 방 메시지 조회는 지금 **과거 방향 cursor 만** 있다(`GET /api/inbox/rooms/{id}/messages?cursor`) — 「그 메시지 기준 위아래」 를 꺼내는 서버 조회가 새로 필요
- 메시지 호버는 지금 없다 — `.scax-imsg` hover 규칙 없음, 스레드는 「답글 N개」(답글 1개 이상일 때만, `RoomView.tsx:100`)로만 열린다. 「스레드에 답글」 은 기존 스레드 패널·`thread_ts` 답장 경로를 그대로 쓴다 — **슬랙 권한 추가 불필요**(운영 토큰 scope 는 조사 때 확인)
- 서랍을 여는 자리는 `App.tsx` 의 `isAxOpen` · `chat.send(...)` — 메시지함에서 열고 보내는 입구를 더한다

- 메일은 호버 막대가 아니라 머리의 [답장] 옆 「업무 생성」 · 「요약」 단추로 같은 흐름을 탄다 → [SH-IMP-008](SH-IMP-008-message-to-task-ax.md)

## 넘기는 맥락 (사용자 확정 2026-10-07)

- **서버가 우리 DB 에서 조합해** 프롬프트에 싣는다 — 프론트는 방 id · 메시지 key 만 넘긴다
- 원문(슬랙 API JSON 등)을 그대로 싣지 않고 **우리 모양으로 줄인 JSON** — 한 줄 = `{at, sender, text, attachments(이름만), thread_reply_count}`, 고른 메시지에 `target: true` (blocks·리액션·내부 id 는 뺀다 — 토큰만 먹는다)
- 범위: 채널 메시지 = 위아래 100줄 · **스레드 안 답글 = 그 스레드 전체(부모 포함)** · 100줄이 안 되면 있는 만큼
- 남의 방 메시지면 서버가 거절
