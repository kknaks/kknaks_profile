## 문제

10-07 회의 「주간 제품·개발 진행 및 병원 AX 확장 회의」(`ba109824-…`)에서 **8명 넘게** 말했는데(사용자), 전사의 화자 라벨은 **6개**다(운영 DB `meeting_transcripts` distinct `speaker_label` = 6). 서로 다른 사람이 같은 화자로 묶인 것으로 보인다.

## 지금 코드 (2026-10-07 · origin/main f0ad522 · 코디 확인)

- 화자 분리는 **Soniox 에 맡긴다** — 실시간 `stt-rt-v5` · 종료 뒤 재전사 `stt-async-v5`, 둘 다 `language_hints:["ko"]` + `enable_speaker_diarization:true` 만 넘긴다(`platform/soniox.py:5, 81, 258-268`). 화자 수 힌트·용어(context) 없음
- 회의록은 **재전사 원문**으로만 만든다(실시간 원문 폴백 없음 · `modules/meetings/retranscribe.py`)
- 화자 실명 대조·추정 없음 — 화자는 익명 라벨(BE 리포트 §5.7)
- 비교: 메디니스는 종료 뒤 음원 전체를 ElevenLabs 배치 STT(`diarize=true`)로 다시 돌려 그 화자 클러스터를 채택하고, 등록된 음성 프로필과 대조(임계 0.45)해 실명을 확정, 나머지는 LLM 이 참석자 후보에서 추정한다(`mediness-app back/app/services/meeting_v2_finalize.py`)

## 운영 확인 (2026-10-07 · 코디)

- 이 회의는 **종료 뒤 재전사를 했다** — `meetings.transcript_source = final`. 화면의 6 라벨은 실시간이 아니라 **음원 전체를 다시 돌린 재전사(Soniox `stt-async-v5` 화자 분리)의 결과**다 → 재전사로도 8명+ 를 6으로 묶었다
- 라벨별 블록/글자: 1 = 38/2667 · 2 = 26/502 · 3 = 32/1511 · **4 = 50/3126** · 5 = 14/714 · 6 = 3/362 — 4·1 처럼 큰 라벨이 여러 사람을 묶었을 가능성

## 조사 항목

- Soniox 비동기 전사가 받는 옵션 중 화자 분리 품질에 닿는 것(화자 수 힌트 · context/용어) — **외부 API 문서 확인 필요**
- 이 회의 음원에서 실제 화자 수와 라벨별 발화량(어느 라벨이 여러 사람을 묶었나)
- 메디니스 방식(배치 STT 공급자 · 음성 프로필 대조 · LLM 화자 추정) 중 가져올 범위
