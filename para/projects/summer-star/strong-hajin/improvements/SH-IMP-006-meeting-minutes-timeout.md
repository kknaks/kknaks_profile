# SH-IMP-006 — 회의 종료 후 AI 회의록 생성 실패(최종 합성 시간 초과)

상태: 조사 중  
생성일: 2026-10-06  
갱신일: 2026-10-07  
출처: 운영 버그 기록 BUG-001(reference 에서 이관, 2026-10-07)

## 요약

2026-10-06 14:00 시작한 「병원 CRM KPI 체계 정리 회의」가 종료된 뒤 AI 회의록 생성에 실패했다. 녹취 스크립트는 남았지만 회의록은 생성되지 않았고, 화면에 실패 안내와 재시도 버튼이 표시됐다.

## 증상

- 운영 회의 상세에 「회의 내용은 저장됐지만 글로 옮기지 못했습니다. 다시 시도할 수 있습니다」 안내가 표시됐다.
- AI 회의록 본문은 비어 있고 스크립트 패널에는 전사 내용이 남아 있었다.
- 운영 DB에서 해당 회의는 `failed` 상태이며 `failure_reason` 은 `회의록을 만들지 못했습니다 — 잠시 뒤 다시 시도해 주세요` 였다.

## 재현·대상

| 항목 | 값 |
|---|---|
| 환경 | 운영 `https://ax.medisolveai.xyz` |
| 회의 | 병원 CRM KPI 체계 정리 회의 |
| 시작 시각 | 2026-10-06 14:04 KST (14:00 예정) |
| 회의 ID | `3abe9f9b-5409-4c99-b24e-7138c860fc5d` |
| 최종 상태 | `failed` |

## 조사 결과

1. 운영 클러스터의 back, front, postgres, redis, worker 4개 등 8개 파드는 모두 `Running`, `1/1 Ready`였다. 따라서 조사 시점의 파드 비정상이나 전체 서비스 다운은 확인되지 않았다.
2. 회의 녹취와 실시간 요약 배치는 DB에 기록돼 있었다. `meeting_batch_runs` 36회 중 35회는 성공했고, 1회는 `Codex CLI conversation timed out` 으로 실패했다.
3. `worker-meeting` 로그에서 종료 후 최종 합성을 수행하던 Codex CLI 프로세스가 제한 시간 90초를 넘겨 종료됐다.
4. 예외는 `subprocess.TimeoutExpired` 에서 `ProviderRequestFailed: Codex CLI conversation timed out` 으로 변환됐고, 최종 합성 실패가 회의의 `failed` 상태와 일반 재시도 안내로 기록됐다.
5. 확인된 실패 시도에는 큰 전사/요약 payload가 Codex CLI 호출 인자로 포함돼 있었다. 입력 크기가 timeout의 원인인지는 아직 입증되지 않았다.

## 원인

**직접 원인:** 최종 회의록 합성에 사용된 Codex CLI 호출이 90초 제한 안에 완료되지 않았다.

**근본 원인:** 아직 확정되지 않았다. 입력 길이, CLI/모델 응답 지연, 운영 자원 경합 중 어느 요인이 주된 원인인지는 현재 로그만으로 구분할 수 없다. 동일 회의의 요약 배치에서도 timeout이 한 차례 있어 간헐적 지연 가능성은 보이나, 이것만으로 원인을 특정하지 않는다.

## 영향

- 녹취 데이터는 남아 있으나 최종 AI 회의록이 없는 실패 상태가 발생했다.
- 사용자는 화면의 「다시 시도」 동작에 의존해야 한다.
- 로그 조사 과정에서 다른 날짜의 동명 회의와 혼동할 수 있어, 제목만으로 대상을 식별하면 안 된다. 본 건은 회의 ID로 확인했다.

- [ ] 수정 후 동일한 대용량 전사 조건에서 재현 검증한다.
