# SH-IMP-014 — 데스크톱 앱에서 내려받기가 안 됨(첨부 · 회의록 내보내기)

상태: 조사 중  
생성일: 2026-10-07  
갱신일: 2026-10-07  
출처: 운영 E2E(사용자), 2026-10-07

## 문제

medi-ax 데스크톱 앱에서 **메시지함 첨부 받기**와 **회의록 내보내기**가 동작하지 않는다. 같은 화면을 웹(브라우저)에서 하면 받아진다.
회의록 내보내기는 WORK-010 에서 「셸이 앱 origin `/api/` 를 가로채 쿠키를 실어 받아 다운로드 폴더에 저장」 으로 고쳤던 경로다 — WORK-011 셸 변경(카톡 수집기 · 닫기 = 웹뷰 파괴 · on_navigation · 판 가르기) 뒤의 **회귀**일 수 있다.

## 사용자 확인 (2026-10-07)

- 운영 **웹**에서는 회의록 내보내기 · 메일 · 슬랙 · 카톡 첨부가 모두 받아진다 — 서버·파일 문제가 아니다
- **앱**에서는 네 갈래 모두 **다운로드 자체가 뜨지 않는다**(실패 토스트도 없음) — 셸이 받아서 실패한 게 아니라 가로채기 전에 요청이 사라졌을 가능성(가설: WORK-011 on_navigation 허용 목록이 다운로드 이동·`_blank` 를 취소). 셸 로그로 확인할 것

| 내려받기 | 경로 |
|---|---|
| 회의록 내보내기 | WORK-010 셸 가로채기 경로 |
| 메일 첨부 | `/api/inbox/mail/{id}/attachments/…` |
| 슬랙 · 카톡 첨부 | `/api/inbox/rooms/{id}/attachments/…` |

- 이 표가 전부라는 보장은 없다 — 발주 때 프론트의 다운로드·`_blank`·blob 입구를 전수 grep 한다

## 기대 결과

- 앱에서 첨부 받기·회의록 내보내기가 다운로드 폴더에 저장되고 결과 토스트가 뜬다(WORK-010 동작)
- 새 내려받기 경로(`/api/inbox/mail/{id}/attachments/…` · `/api/inbox/rooms/{id}/attachments/…`)도 같은 셸 가로채기를 탄다

## 진행 관리

- [ ] 앱(현재 fix2 dmg)에서 회의록 내보내기 재현 · 셸 로그 확인
- [ ] WORK-010 의 다운로드 가로채기 코드가 WORK-011 셸 변경 뒤에도 불리는지 확인(회귀 여부)
- [ ] 첨부 URL 이 가로채기 대상(경로·origin·새 탭 `_blank`)에 들어가는지 확인
- [ ] 수정 → dmg 재빌드·공증 → 앱에서 두 경로 확인
