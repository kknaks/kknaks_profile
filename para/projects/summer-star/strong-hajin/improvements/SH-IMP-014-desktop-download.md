# SH-IMP-014 — 데스크톱 앱에서 내려받기가 안 됨(첨부 · 회의록 내보내기)

상태: 완료  
생성일: 2026-10-07  
갱신일: 2026-10-07  
출처: 운영 E2E(사용자), 2026-10-07

## 문제

medi-ax 데스크톱 앱에서 **메시지함 첨부 받기**와 **회의록 내보내기**가 동작하지 않는다. 같은 화면을 웹(브라우저)에서 하면 받아진다.
회의록 내보내기는 WORK-010 에서 「셸이 앱 origin `/api/` 를 가로채 쿠키를 실어 받아 다운로드 폴더에 저장」 으로 고쳤던 경로다 — WORK-011 셸 변경(카톡 수집기 · 닫기 = 웹뷰 파괴 · on_navigation · 판 가르기) 뒤의 **회귀**일 수 있다.

## 사용자 확인 (2026-10-07)

- 운영 **웹**에서는 회의록 내보내기 · 메일 · 슬랙 · 카톡 첨부가 모두 받아진다 — 서버·파일 문제가 아니다
- **앱**에서는 네 갈래 모두 **다운로드 자체가 뜨지 않는다**(실패 토스트도 없음) — 셸이 받아서 실패한 게 아니라 가로채기 전에 요청이 사라졌을 가능성(가설: WORK-011 on_navigation 허용 목록이 다운로드 이동·`_blank` 를 취소). 셸 로그로 확인할 것

| 내려받기 | 경로 |
|---|---|
| 회의록 내보내기 | WORK-010 셸 가로채기 경로 |
| 메일 첨부 | `/api/inbox/mail/{id}/attachments/…` |
| 슬랙 · 카톡 첨부 | `/api/inbox/rooms/{id}/attachments/…` |

- 이 표가 전부라는 보장은 없다 — 발주 때 프론트의 다운로드·`_blank`·blob 입구를 전수 grep 한다

## 조사 결과 (2026-10-07 · FE 리포트 §1 + 사용자 확인)

- **사용자 확인(앱)**: 회의록 내보내기는 **저장된다**. 메시지함 첨부(메일·슬랙·카톡)는 **안 된다**
- 셸 가로채기 코드는 WORK-011 에서 바뀌지 않았다 — 「WORK-011 회귀」 가설 기각. 옛 TLS 패닉은 fix2 에서 고쳐졌다
- 두 입구는 **모양이 다르다**(FE §1-4):

| 입구 | 링크 모양 | 셸이 타는 길 | 서버 disposition | 앱 결과 |
|---|---|---|---|---|
| 회의록 내보내기 `MeetingDetailPage.tsx:1060` | `<a href>` 같은 탭 · download·target 없음 | A — `on_navigation` 가로채기(쿠키 실어 받기) | 항상 `attachment` | **저장됨** |
| 메시지함 파일 카드 `InboxAttachments.tsx:40` · 메일 `MailView.tsx:401` · 모두 받기 `:79-91` | `<a download target="_blank">` | C — wry 가 셸 훅 전에 WKDownload(`on_download`)로 넘김 · `_blank` 와 겹칠 때 순서 미확인 | 이미지·PDF·MD `inline`, 그 밖 `attachment` | **안 됨** |
| 메시지함 이미지 원본 `InboxAttachments.tsx:162` | `<a target="_blank">` | A 또는 B | 이미지라 `inline` → 셸이 받고 **알림 없이 끝남**(lib.rs:327-330) | (같은 증상 예상) |

- → 원인은 **메시지함 링크 모양(`download`+`_blank`)이 탄 길 C, 그리고 `inline` 응답의 무알림 종료** 쪽으로 좁혀졌다. 앱 터미널 실행 + 셸 로그(`[shell][download] …` · `webview-download success=…`)로 한 번 재현하면 C 인지 inline 인지 확정된다(FE §10)

## 결정 (사용자 2026-10-07) — A. 속성 맞추기

- **화면(UI)은 그대로.** 메시지함 받기 링크(`InboxAttachments.tsx` `DownloadLink` · 모두 받기 · `MailView.tsx` 이미지 받기)에서 `download`·`target="_blank"` 를 빼 회의록 내보내기와 같은 셸 가로채기 길(A)을 타게 한다
- 받기 요청에는 서버가 `attachment` 로 응답한다(미리보기는 지금처럼 `inline`) — 받기/미리보기를 주소로 가른다
- 셸·dmg 는 이 항목 때문에 바꾸지 않는다(011 은 별도) · 완료 = 앱에서 메일·슬랙·카톡 첨부가 다운로드 폴더에 저장되고 토스트가 뜸(SH-IMP-007 함께 닫힘)

## 기대 결과

- 앱에서 첨부 받기·회의록 내보내기가 다운로드 폴더에 저장되고 결과 토스트가 뜬다(WORK-010 동작)
- 새 내려받기 경로(`/api/inbox/mail/{id}/attachments/…` · `/api/inbox/rooms/{id}/attachments/…`)도 같은 셸 가로채기를 탄다
