# Tauri 웹 래퍼

2026-09-22 사용자 대화에서 확정한 방향을 기록한다. accepted는 아래 방향에 대한 합의이며, 구현·설치 검증·배포 완료를 뜻하지 않는다. 상세 계약은 SPEC-006에 있으며, 구현·실측과 배포 절차는 후속 작업이다.

## Context

사용자는 기존 웹 프로젝트를 Tauri로 감싸 배포하려 한다. 목적은 회의실 녹음 중 자동 절전으로 녹음이 끊기는 문제 해결과 추후 OS 시스템 알림 지원이다.

사용자 원문:

> 우리가 tauri 로 래퍼 하는 이유는 1. 회의실 녹음 문제 2. 시스템 알림문제 (추후 알림시스템구현 예정)

> 키체인 굳이 해야하나 쿠키기반 안돼 ?

> 설치 파일 배포 방식은 그대로 계승 하면 되지 이거 문서화도 하고 계속 개발 하고 배포 할거니가

참조 조사는 `orchestration/work/strong-hajin-projects/research-task-management-tauri.md`에 있다. task_management의 Tauri 구성은 참고하되 그 프로젝트의 인증·프론트 동봉 방식을 통째로 계승하지 않는다.

## Options

| Option | Description | 판단 |
|---|---|---|
| A | 배포된 HTTPS 웹을 Tauri 창에서 열고 웹·API를 같은 origin으로 제공 | 채택. 기존 쿠키 인증과 웹 구조를 유지 |
| B | FE 번들을 앱에 동봉하고 별도 API에 연결 | task_management의 현 구조. 이번 방향으로 채택하지 않음 |
| C | 백엔드·DB까지 앱에 동봉 | 이번 범위 밖 |

## Decision

| ID | 결정 | 근거 |
|---|---|---|
| D-01 | Tauri는 기존 웹의 데스크톱 래퍼로 둔다. 화면·업무 로직과 서버는 기존 웹 제품을 이어간다 | 사용자 래핑 목적 및 쿠키 유지 제안에 대한 동의 |
| D-02 | 로그인은 세션 쿠키 기반을 유지한다. 키체인·Bearer 전환을 필수 조건으로 두지 않는다 | 사용자 쿠키 유지 요청. 같은 origin으로 웹·API 제공 |
| D-03 | 회의 녹음 시작·재개 시 자동 절전 방지를 요청하고, 일시정지·종료 시 해제한다. 화면 꺼짐은 허용하며 직접 잠자기·덮개 닫기를 막는 것을 요구하지 않는다 | 사용자가 문제를 회의 중 자동 절전으로 특정. 수동 절전은 사용자 의도라고 확인 |
| D-04 | OS 알림 연결을 래퍼의 책임으로 둔다. 알림 생성·수신·읽음 등 알림 시스템 자체는 후속 구현이다 | 사용자 명시 |
| D-05 | task_management의 Tauri 설치파일 빌드 구성을 출발점으로 계승한다. 앱 이름·식별자·아이콘·웹 연결 주소는 Strong Hajin 소유 값으로 분리한다 | 사용자 설치파일 배포 방식 계승 요청. 기존 제품과 설치·저장 영역이 충돌하지 않도록 제품별 설정 필요 |
| D-06 | 일회성 빌드로 끝내지 않고, 이후 개발과 재배포를 반복할 수 있도록 구조·절차·버전별 결과를 문서화한다 | 사용자 지속 개발·배포 및 문서화 요청 |
| D-07 | 데스크톱은 macOS와 Windows를 모두 지원한다. 최소 OS 버전·CPU 아키텍처·설치파일 형식은 후속 확정한다 | 2026-09-22 사용자 양쪽 지원 확정 |
| D-08 | 운영 프론트와 백엔드는 사용자 Mac Studio에 올린다. 기존 k8s 인프라를 활용하며 별도 Vercel 배포는 두지 않는다. 웹·API는 같은 HTTPS origin으로 제공한다 | 사용자 서버 지정 및 D-02 쿠키 유지 |
| D-09 | 설치파일은 제품 코드 저장소의 GitHub Releases에서 관리하고, 릴리즈 문서는 프로필 저장소의 제품 `60-release`에서 관리한다. 같은 버전·태그와 Release 링크로 연결한다 | 사용자 배포 위치 및 문서 위치 확정 |

## Rationale

래퍼 도입 목적에 필요한 네이티브 기능을 추가하면서 기존 웹의 인증과 업무 기능을 유지한다. 프론트 동봉과 Bearer 인증은 참조 프로젝트의 선택이지 Tauri의 필수 조건이 아니다.

계승할 실물은 `task_management/app/front/src-tauri/tauri.conf.json`의 번들 구성과 프론트 package의 Tauri CLI 실행 체계다. 참조 체크아웃 `a720b6ef2c9d7dcfebc2595c4d00cb76621b01d8`에서 서명·공증·자동 업데이트·CI 설정은 확인되지 않았다. 외부 수동 운영 여부까지 부정하는 것은 아니다. 이 항목들을 이미 있는 배포 체계로 간주하지 않는다.

웹 배포와 앱 배포는 구분한다. 웹 변경과 네이티브 셸 변경의 호환 범위, 설치파일 재배포 시점은 상세 설계에서 정한다.

## Resulting Spec
