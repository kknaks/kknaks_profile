# 고도화 1판 — 운영과 데스크톱 앱에서 나온 개선 19건, 사용자가 본 것과 조사·운영 확인이 보여 준 것

운영(`https://ax.medisolveai.xyz`)과 데스크톱 앱(medi-ax)을 쓰며 개선 항목 **19건**(SH-IMP-001~019)이 나왔다.
이 문서는 항목마다 **사용자가 본 것 · 조사가 확인한 지금 코드의 동작 · 코디가 운영 DB·로그에서 확인한 것**을 눕힌다.

**판단하지 않는다.** 무엇을 채택하고 무엇을 범위에서 빼는지는 DEC-009 가 가른다.
항목별 「사용자 정리」·「결정」 절의 결정 문장은 DEC-009 로 옮기고, 여기에는 그 결정이 기대는 **관찰과 요구**만 둔다.

### 입력 1 — 회의 생성·편집

#### SH-IMP-001 — AX 회의 생성이 AX 업무 생성과 다르다

- **문제 (사용자)** AX 채팅에서 「회의 생성해 줘」 하면 나오는 확인 카드가, 스텝 바이 스텝으로 진행되는 AX 업무 생성과
  UI·흐름이 다르다. 참고자료는 업무 생성 AX 카드와 같은 기준·동작이어야 한다 (BASE-007 1 · SH-IMP-001 사용자 정리)
- **화면 (BASE-007)** `section.scax-actioncard.action-task-card.action-meeting-card` (`data-state="rejected"`) — 회의명·주최자·참석자·날짜·시간·첨부, 첨부 목록 비어 있음
- **지금 동작 — 서버 (BE §1.1 · §1.4)**
  - 서버엔 의도 분류기도 단계 상태 기계도 없다. 업무 생성의 「스텝」 은 프롬프트 정책을 본 모델이 탐색 도구를 부른 뒤
    `task_create_self` 한 번으로 Action 카드 1장을 만드는 것이다
  - 회의 생성은 `meeting_create` → `meeting.reservation.create` 카드 1장. **프로젝트·연관 업무·자료 탐색 지시가 없고**,
    프로젝트·참고 업무 필드도 없다. 초안 저장(`save_draft`)도 없다
  - 회의 확정 실행이 참고 업무 목록을 읽는 코드는 있으나 입력 스키마가 그 키를 받지 않아 들어올 길이 없다 (BE §1.4)
- **지금 동작 — 화면 (FE §2)**
  - 업무 = `AxDraftCard` — 읽기 전용 요약 **4쪽**(기본 정보 · 체크리스트 · 업무 연결 · 자료) + 수정은 바깥 모달 · 거절 · 등록
  - 회의 = `ActionMeetingCard` — 한 장 카드 + 인라인 편집. **거절 단추·AX 배지·회차·참고 업무가 없고**, 「저장」 도 confirm 이다
  - 두 카드가 공유하는 것은 `scax-actioncard` 클래스와 `Badge` 뿐 (FE §2-3 표)

#### SH-IMP-002 · SH-IMP-004 — 수정 모달에서 종료 시간 칸이 검색 입력 밑에 깔린다

두 항목을 함께 둔다 — 사용자가 같은 원인으로 보았고 조사가 그것을 코드로 설명했다.

- **문제 (사용자)**
  - 002: 회의 정보 수정 모달의 「조직도 내 이름 검색」 입력 뒤에 정체 모를 버튼이 있다 — **의도한 UI 가 아니다(버그)**
  - 004: 왼쪽 열의 `[날짜][시작][종료]` 가 열 폭을 넘쳐 **종료 시간 칸이 오른쪽 열 검색 입력 밑에 깔린다**
  - 002 의 「버튼」 은 이 깔린 종료 시간 칸으로 보인다 **(확인 필요라고 사용자가 적었다)**
- **화면 (사용자 캡처 2026-10-07)** 날짜 `2026/10/07` · 시작 `16:30` 까지 보이고 종료 칸은 검색 입력 뒤로 일부만 비친다.
  BASE-007 근거: `input.search-input-box[aria-label="조직도 내 이름 검색"]`
- **지금 동작 (FE §3 — CSS 계산값, 실측 아님)**
  - 두 열 `2fr 3fr` → 왼쪽 ≈277px. 그 안에 날짜 **200px 고정** + 줄지 않는 시간쌍 → 줄 ≈400px, **≈125px 넘친다**
  - 검색 입력 옆에 **실제 단추 요소는 없다.** 보이는 「단추」 는 넘친 **종료 시각 트리거** `button.select-trigger` 이고,
    DOM 순서상 뒤인 검색 입력이 그 위에 그려져 가린다 (FE §3-2)
  - 이 모달을 여는 곳은 회의 목록 카드 [수정] 한 곳. 생성(`BookingModal`)·AX 카드 편집은 다른 컴포넌트다 (FE §3-3)
- **BASE-007 의 요구 중 남은 것** — 결과 선택·중복 방지·키보드 동작(002) · 좁은 화면 배치·유효성 오류 위치(004) 는
  항목의 「기대 결과」 에만 있고 사용자 정리·조사가 닿지 않았다

#### SH-IMP-003 — Connect 회의실 가용성(생성·수정)

- **문제 (BASE-007 3)** 장소가 자유 입력이라 실제 회의실 가용성과 이어지지 않는다. AX 는 요청 시간에 예약 가능한 4인실이 없다고
  답했는데 수정 모달엔 `회의실 2 (4인)` 이 들어 있었다
- **요구 (사용자 2026-10-07)**
  - 회의 **수정** 때도 바뀐 날짜·시간·참석 인원으로 The Connect 에서 가능한 회의실을 검색하고, 회의실을 고르거나 「선택 안 함」 을 고른다
  - The Connect 에 **회의 수정 기능이 있다** — 우리 쪽 수정이 Connect 예약 수정으로 이어져야 한다
  - 수정 때 셀렉트 구성 제안: 맨 위 「기존 — 회의실 3 (변경 안 함)」(수정 때만) → 「회의실 예약 없음」 → Connect 조회 결과 목록
- **지금 동작 (BE §2 · FE §4)**
  - Connect 는 **회사 공용 계정 1개**로 방 목록·날짜별 예약 목록·구성원 조회와 예약 생성·수정·취소를 부른다. 가용 조회는 전용 API 가 아니라
    날짜별 예약 목록을 받아 **로컬에서 겹침 판정** (BE §2.1 표)
  - **생성**: 가용 조회 + 실제 예약. 차 있으면 정원이 맞는 가장 작은 방으로 자동 대체, 그것도 없으면 409 (BE §2.2)
  - **수정**: 시간 키가 있을 때만 **같은 방으로 시간만 PUT** — 가용 조회 없음 · 참석자 미반영 · 성공하면 장소 글자를 다시 쓰지 않는다.
    수정 모달은 저장마다 시간을 함께 보내서 시간이 안 바뀌어도 PUT 이 나간다 (BE §2.2)
  - Connect PUT 에 참석자를 실으면 200 을 주면서 참석자를 지운다는 실측 기록이 코드 주석에 있어 **의도적으로 싣지 않는다** (BE §2.3)
  - 회의실 고르기 UI 는 **생성 모달에만** 있다 — 라디오 목록 + 기본 「회의실 선택 안 함」. 수정 모달의 `#meeting-head-place` 와
    AX 카드의 장소 칸은 자유 입력이다 (FE §4)
  - AX 의 「4인실 없음」 근거 도구 `meeting_room_list` 는 빈 방 표시만 하고 **정원 필터가 없다** — 4인 판단은 모델 몫. 그 대화에서 실제로 무엇을
    불렀는지는 로그로만 안다 (BE §2.2 · §10-5, 운영 확인 안 함)
  - 회의 시간 겹침 검사(`MEETING_TIME_OVERLAP`)는 주최자·참석자 시간 블록만 본다 — **Connect 회의실 점유와 비교하지 않는다** (BE §2.4)

#### SH-IMP-016 — AX 채팅으로 만든 회의를 AX 채팅에서 바꾸기

- **요구 (사용자 2026-10-07, 001·003 논의 중)** AX 채팅에서 생성된 회의의 **시간·인원·회의실**을 AX 채팅으로 바꾸고, 변경이 Connect 예약 수정으로 반영되며,
  시간·인원이 바뀌면 가능한 회의실을 다시 조회한다(003 과 같은 기준)
- **지금 동작 (BE §1.5)** AX 수정 카드 `meeting_update` → `meeting.info.update` 가 **이미 있다** — 시간·참석자·장소 글자. 회의실을 바꾸는 값은 없다.
  시각이 바뀌면 기존 예약을 같은 방으로 옮긴다(003 의 수정 경로와 같다)

#### SH-IMP-005 — 「이전 회의 정보 불러오기」

- **문제 (사용자 2026-10-06~07 — 「버그다」)** 재현: 회의 생성 → 이전 회의 정보 불러오기
  1. 이전 회의의 **시간이 새 회의에 들어간다**
  2. 생성 때 **손으로 쓴 안건**이 회의 시작 화면에서 「지난 회의에서 넘어옴」 으로 나온다
- **요구 (사용자 확정)** 불러오면 지난 회의에서 **결론이 안 난 항목**이 안건으로 들어가고 그것만 「지난 회의에서 넘어옴」, 새로 추가한 안건은 「새로 추가된 안건」
- **화면** 뷰포트 1676×936 · `p.scax-agenda-block__source` 「지난 회의에서 넘어옴」 · 사용자: 안건은 수동 작성, 회의 정보만 불러옴
- **지금 동작 (BE §3 · FE §5)**
  - 「이전 회의 정보 불러오기」 라는 문구는 코드에 없다 — 실제 UI 는 생성 모달의 제안 카드 「지난 「{회의명}」」 + [불러오기].
    회의명이 지난 회의와 **정확히 같을 때만** 뜬다
  - **① 시간 — 원인: 화면.** 불러오기가 지난 회의 상세를 읽어 날짜·시작·종료를 폼에 그대로 넣는다 (BE §3.1 · FE §5-1)
  - **② 출처 — 원인: 서버가 회의 단위로 출처를 정함 + 화면이 안건별 출처를 버림.** 화면은 안건별 `manual/carried` 를 갖고 있으나
    제출 때 제목만 보낸다. 서버는 이어온 회의 값이 있으면 그 요청의 **안건 전부**를 `carried` 로 저장한다 (BE §3.2 · FE §5-2)
  - **같은 결함의 두 번째 입구** — 회의 상세의 [다음 회의 예약] 도 이어온 회의 값을 넘겨, 그 모달에서 쓴 안건이 전부 `carried` 가 된다 (BE §3.2)
  - 「결론 안 난 항목」 고르기는 **프론트에만** 있다(final 벌 · 결론 안 남 · 제목 중복 제외) (BE §3.3)
  - 지금 출처 문구: `manual` = 「직접 입력」 · `carried` = 「지난 회의에서 넘어옴」 · `set`·`derived` 는 만드는 서버 코드가 없다 (FE §5-2 표)

### 입력 5 — 메시지함에서 AX 로

#### SH-IMP-015 — 메시지 호버 행동 막대

- **문제 (사용자 제안, 슬랙 화면 비교 2026-10-07)** 메시지함 대화에서 메시지 하나를 두고 할 수 있는 행동이 없다. 스레드는 「답글 N개」 를 눌러야만 열리고, 메시지를 업무로 옮길 길이 없다
- **요구 (사용자 2026-10-07)**
  - 슬랙처럼 메시지에 호버하면 오른쪽 위에 **아이콘만** 있는 막대 → 아이콘에 호버하면 **설명 툴팁**(두 단계 호버)
  - 막대: 슬랙 = 스레드에 답글 · 업무 생성 · 내용 요약 / 카톡 = 업무 생성 · 내용 요약
  - 단추를 누르면 **기존 AX 채팅 서랍**이 열리고 「(해당 메시지) 읽고 업무를 생성해 줘」 / 「요약해 줘」 말풍선이 선다 — 실제로는 그 메시지 위아래 맥락을 넘긴다.
    별도 창·별도 흐름을 새로 만들지 않는다
  - 넘기는 맥락은 서버가 우리 DB 에서 조합한 **우리 모양**(원문 JSON 이 아니다) · 남의 방이면 거절
- **코디 의견 (2026-10-07 — 사용자 확인 없음)** 만든 업무의 출처 행에 원래 메시지로 돌아가는 링크 · 메시지 쪽에 「업무 만듦」 표시(막지는 않음) · 결과는 AX 초안 → 사람이 「등록」
- **지금 동작 (코디 · BE §8-pre · FE §6)**
  - 대화 전송이 이미 **본문 + 참고 자료**를 따로 싣는다. 참고 자료 종류는 `task`·`work_request` **둘**이고 나열 지점이 **5곳** (BE §8-pre-1)
  - 방 메시지 조회는 **과거 방향 커서만** 있다 — 「기준 위아래」 조회는 없지만 (방, 시각) 인덱스로 양방향 범위는 가능 (BE §8-pre-2)
  - 메시지 행에 **호버 규칙·행동 자리 0.** 스레드 입구는 「답글 N개」 줄 하나뿐이고 답글 0개면 없다 — 패널·조회·답장 경로 자체엔 답글 수 조건이 없다 (FE §6-1)
  - 카톡도 같은 메시지 컴포넌트를 쓴다 (FE §6-2)
  - 「서랍을 열며 보내기」 의 기존 사례는 `askAx` 하나(오늘 화면) — 메시지함은 받지 않는다. 말풍선에 참고 자료 칩을 그리는 코드는 0 (FE §6-4)
  - 「스레드에 답글」 은 기존 스레드 패널·답장 경로를 그대로 쓸 수 있어 **슬랙 권한 추가가 필요 없다** (코디)

## 이 문서가 답하지 않은 것

1. 이번 고도화에 무엇을 넣고 무엇을 미루는가 — 019·013①·009 의 처분 포함
2. 회의 생성·수정의 회의실 고르기와 Connect 반영 범위, AX 회의 생성·수정 카드가 무엇을 따르는가

4. 회의록 생성 고도화의 범위 — timeout · 맥락 · 교정 · 안건 순서 · 기한 규칙
5. AX 업무 생성이 받을 맥락
6. 앱 내려받기를 어느 쪽(웹·셸)에서 고치나, 메일 SVG 이미지를 받나

9. 위 어긋남 ①~⑬ 각각의 처분
