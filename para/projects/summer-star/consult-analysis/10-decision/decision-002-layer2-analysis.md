# DEC-002 2층 판정과 분석

DEC-001(두 층 분리 · 예약 성공 정의 · 국적 출처)을 이어받는다. 1층(SPEC-001)은 고치지 않는다.

## 결정

| ID | 결정 | 근거 |
|---|---|---|
| D-01 | 2층은 **별도 테이블**로 1층 id(`conversation_id` · `message_id` · `customer_id`)를 가리킨다. 같은 SQLite 파일 안 · 1층 테이블에 칸을 더하지 않는다 | DEC-001 D-05 · SPEC-001 §8 |
| D-02 | 모든 판정 행은 **판정 주체(`rule` / `llm` / `human`) · 근거 메시지 id · 판정 버전**을 갖는다. LLM 판정은 신뢰도 · 모델 이름도 | DEC-001 D-05 |
| D-03 | **예약 단계**(방 단위): `inquiry` → `form_sent`(상담사가 예약표 발송 · 자동응답 안의 빈 표 제외) → `form_filled`(고객이 예약표 회신 = **예약 성공**). 판정은 규칙 | DEC-001 D-06 · D-07 |
| D-04 | `form_filled` 규칙 = 고객 메시지에 **예약표 칸이 2개 이상** 채워져 있음. 칸 사전은 실측으로 만든다(채널 · 예약표 판마다) | 사용자 「예약 회신」 · BASE-002 |
| D-05 | 규칙의 **경계 사례만 사람 확인**(칸 1개만 · 예약표 없이 날짜 · 이름만 보냄 등) — **50건 안쪽**으로 올린다. 사람 판정은 `human` 으로 덮는다 | 게이트 사람 몫 50 안쪽 |
| D-06 | **언어 판정**은 메시지 단위 규칙 → 방 언어 = 고객 메시지 글자 수 최다 언어. 값: `zh-Hant`(번체) · `zh-Hans`(간체) · `en` · `ko` · `ja` · `other` · `none`(글자 없음). 번체/간체는 변환 사전(외부 패키지 허용)으로 가른다 · 섞이면 `mixed` 비율도 남긴다 | 사용자 「규칙 + LLM」 · 한자권 89% |
| D-07 | **문의 주제 · 시술명**은 **방 단위 LLM 라벨**. 주제 목록(예: 시술 · 가격 · 일정 · 위치 · 통역 · 후기 · 기타)과 시술명 정규화는 SPEC 에서 표본으로 정한다 | 사용자 「규칙 + LLM」 |
| D-08 | LLM 은 **로컬 CLI 로만** 부른다(방 본문이 로컬 밖 저장소 · 레포로 가지 않는다). 결과는 DB 에만 | DEC-001 D-10 |
| D-09 | **국적**은 DEC-001 D-08 순서(예약표 國籍 → 본인 언급 → 언어 추정). 출처 칸을 같이 | DEC-001 D-08 |
| D-10 | **통계 항목**(언어별 · 예약 성공/실패별 · 채널별): 방 수 · 전환율 · 예약까지 턴 수 / 시간 · 고객 메시지 길이 · 첫 메시지 형태 · 우리 첫 응답까지 시간 · 문의 시각(KST) · 이모지 · 사진 사용 · 자동응답 받음 여부 · 문의 주제 · 시술 | 사용자 「어떤 대화가 예약까지 · 언어별 특징 · 언어적 통계」 |
| D-11 | 표본이 작다(성공 약 90) — 모든 비율에 **분모 건수**를 같이 쓰고, 칸 건수가 작으면(예: 10 미만) 표시한다. 인과가 아니라 차이로 쓴다 | BASE-002 |
| D-12 | 결과물 = **분석 보고서**(`para/…/consult-analysis/` md) + **차트 페이지**(비공개 Artifact). 둘 다 **건수 · 비율만** — 고객 본문 · 이름 인용 0 | 사용자 「보고서 + 차트」 · DEC-001 D-10 |
| D-13 | 2층 판정 · 집계 스크립트는 `scripts/` · 외부 패키지는 2층부터 허용(번간 변환 등) — 의존성은 스크립트 옆에 명시 | DEC-001 D-09 · 1층 표준 라이브러리 원칙은 1층에만 |
| D-14 | LLM = 로컬 **`claude -p`** · 모델 **haiku**(표본 30방도 haiku 하나 · 모델 비교 안 함 · Opus 안 씀). 호출당 토큰 · 비용을 표본에서 재고 전체 전에 보인다 | SPEC-002 OQ-201 권장 A · 사용자 「하이쿠도 괜찮아」 · 「오퍼스는 비용이 너무 크지 않아?」 |
| D-15 | 다른 메신저로 넘긴 방은 성공으로 세지 않고 `handoff_mentioned` 로 표시만 · 보고서 한계에 건수 | OQ-202 권장 A |
| D-16 | `confirmed` 단계는 두지 않는다 · LLM `staff_confirmed` 는 참고 값 | OQ-203 권장 A |
| D-17 | 번간을 가를 글자가 없는 한자는 값 `zh`(번간 미상)를 더한다 | OQ-204 권장 A |
| D-18 | 즉시응답 흐름(`flow`)이 보낸 예약표는 `form_sent` 로 센다(`form_source = 'flow'` 구분) | OQ-205 권장 A |
| D-19 | 사람 확인 큐 15건 판정 — 3 · 4 · 7 번 `form_filled`(7 번은 칸 이름 없이 두 사람 자료를 보냄 → 규칙 `form_sent` 를 덮음) · 나머지 12건 규칙 값 그대로. 판정 파일 `data/review_decisions.csv`(로컬) | 코디 판정안 · 사용자 「응 !!!」 |
| D-20 | 시술 목록 넓힘 — `rejuran` · `mole_wart_removal` · `acne_scar` · `pore_texture` · `eye_area` 추가 · 중화권 별칭(美國音波 → ulthera · 鳳凰電波 → thermage · 黃金微針 → rf_microneedle · 喬雅露 → juvelook · 麗珠蘭 → rejuran · 水光 → skinbooster 등)을 지시문에 · `other` 시술은 원래 이름을 짧게 `procedures_other`(DB 만)에 | 표본 `other` 57%(방 기준) · 사용자 승인 |
| D-21 | 다른 메신저 언급(`handoff_mentioned`)은 낱말 경계 규칙(앞뒤가 라틴 글자 아님) — IG 12 · FB 17. SPEC 의 21 · 73 은 부분 일치 대략치 | etl 재현 12꼴 · 사용자 승인 |
| D-22 | 시술 목록에 `fat_dissolving`(消脂針 · 83방) · `tune`(Tune · 66방)을 지금 더한다 — 재시험 · 전체를 한 번에 돌리려고 | SPEC-002 OQ-206 · 코디(LLM 다시 돌리는 일을 줄임 · 사용자 「결과 빨리」) |
| D-23 | LLM 라벨을 예약표 메시지를 뺀 입력으로 **전체 다시**(약 $0.8 · 30분) — 예약표 칸이 주제로 읽혀 성공 방 주제가 오염됐다 | etl 오염 점검 4 · 코디(비용 작음 · 틀린 주제 통계를 내지 않는다) |
