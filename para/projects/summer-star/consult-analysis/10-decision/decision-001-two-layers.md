# DEC-001 두 층 분리와 예약 성공 정의

## 결정

| ID | 결정 | 근거 |
|---|---|---|
| D-01 | **두 층으로 나눈다.** 1층 = 원본을 펼치기만 한 정규화(판단 없음). 2층 = 판정(라벨). 한 테이블에 섞지 않는다 | 예약 성공 · 국적은 원본에 필드가 없다(BASE-001). 섞으면 원본과 추정이 구분되지 않는다 |
| D-02 | 1층 테이블은 `customer` · `conversation` · `message` · `attachment` | 원본 구조(방 · 참가자 · 메시지 · 첨부) 그대로 |
| D-03 | 1층은 **원본 건수와 맞아야 끝**이다 — 방 510 · 메시지 7,093 · 첨부 종류별 건수. D-13 · D-14 로 범위가 넓어진 뒤의 수는 **SPEC-001 §7 이 기준** | 펼치기만 했으니 셈이 같아야 한다 |
| D-04 | 이중 인코딩은 1층 적재 때 복원한다. 복원은 판단이 아니라 변환이다 | BASE-001 실측 |
| D-05 | 언어 판별 · 국적 · 문의 유형 · 예약 단계는 전부 **2층**. 판정 칸에는 근거 메시지 id · 판정 주체(규칙/LLM/사람) · 신뢰도를 둔다 | 기계 판단이 들어간 값 |
| D-06 | **예약 성공 = 고객이 예약표를 채워 회신한 것.** 단계는 `inquiry` → `form_sent` → `form_filled`(= 성공) | 사용자 「예약 회신을 말하는 거야. 그거 받으면 병원에 전달했대」 |
| D-07 | 자동응답의 빈 예약표는 `form_sent` 로 세지 않는다 | 영업시간 외 문의하면 누구나 받는다(150방) |
| D-08 | 국적 출처 순서: ① 회신 예약표의 國籍 칸 ② 대화 중 본인 언급 ③ 언어 추정. 출처를 값과 함께 남긴다 | 원본에 국적 필드 없음 · 예약표에 國籍 칸이 있음 |
| D-09 | DB = 로컬 SQLite, `data/` 아래 · gitignore. 파서 · 적재는 이 프로젝트 `scripts/` | 사용자 지정 |
| D-10 | 이 레포는 PUBLIC — 문서 · 스크립트 · 커밋에 고객 이름 · 메시지 본문 · 사진 금지. 수치와 구조만 | 원본이 고객 DM |
| D-11 | 순서: **1층 먼저.** 2층은 1층이 원본 건수와 맞은 뒤 | 사용자 「1층 먼저」 |
| D-12 | 반응(`reactions[]`)은 다섯 번째 테이블 `reaction` 으로 담는다. D-02 의 네 테이블에 이것을 더한다 | SPEC-001 OQ-101 권장 A · 사용자 이의 없음(2026-11-16) |
| D-13 | 보관함 바로 아래 놓인 대화 JSON(폴더 밖)도 방 1개로 싣는다 | SPEC-001 OQ-102 권장 A — 방 꼴 그대로 · 버릴 근거가 원본에 없음 |
| D-14 | **페이스북 메신저 대화도 1층에 넣는다.** 범위 = 인스타그램 DM + 페이스북 메신저 | 사용자 「응」(SPEC-001 OQ-103 B) — 같은 클리닉 상담 · 인스타그램의 약 3배 |
| D-15 | **방마다 들어온 채널을 남긴다**(인스타그램 / 페이스북 메신저). 채널은 원본 폴더 위치로 정해지는 사실이라 1층 칸이다 | 사용자 「어떤 메신저로 왔는지도 필요할 것 같아」 |

## 열린 것

- OQ-001 2층 판정 방식(규칙 먼저 + 애매한 것 LLM/사람) — 2층 착수 때
- OQ-002 상담사 확정 안내(`confirmed`) 단계를 둘지 — 문구 패턴 확인 뒤
- OQ-003 첨부 파일(사진 · PDF) 자체를 분석 대상으로 삼을지 — 1층은 경로만 가리킨다
