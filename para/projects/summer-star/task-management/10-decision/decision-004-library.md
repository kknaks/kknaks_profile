# 문서함 정책

BASE-004 의 영역 정책. 2026-09-03 사용자 논의로 v1 범위 확정.

> 근거 표기: 「확정」 = 2026-09-03 사용자 논의, `P/Q-xx` = 분석 리포트, 파일명 = `00-design/`.

## 1. 범위

- In: PARA 고정 트리 + 하위 폴더 자유 생성, 목록·즐겨찾기(정렬), md 상세·편집(자동 저장), 메타데이터, 사람이 거는 연결, md 업로드, 더보기 메뉴, 휴지통(복원·영구 삭제), 용량 표시
- Out(v2): AI 색인·임베딩·백링크·문서 간 링크 자동 추출, 버전 관리, pdf·docx 등 다중 형식, 문서함에서 새 문서 만들기, 회의/업무에서 문서 생성, 즐겨찾기 필터·전용 화면
- **폐기**: 탐색안(`자료함.dc.html`)의 폴더 그리드·미리보기 3종·다중 선택 툴바·이동 드로어 — 확정안이 정본 (Q-26)

## 4. 생명주기

| 결정 | 내용 | 근거 |
|---|---|---|
| **폴더 최상위** | **PARA 4종 고정 시드**(01 Projects / 02 Areas / 03 Resources / 04 Archive) — 삭제·이름 변경 불가. 하위 폴더만 자유 생성(폴더 행 `+`) | 확정 |
| **폴더 ↔ 프로젝트** | **자동 생성하지 않는다.** 폴더는 사람이 정리하는 축, 프로젝트·업무·회의 관계는 「연결」 축 — **두 축 독립.** 프로젝트 이름 변경·삭제가 폴더에 전파되지 않는다 | 확정 |
| 문서 생성 | **업로드만** — 문서함에서 빈 문서 만들기 없음 | 확정 |
| 편집 | 자동 저장(포커스 해제). **버전 스냅샷 없음** | 확정 · 14-library §문서 화면 |
| **삭제** | **소프트 딜리트 → 휴지통.** 휴지통에서 복원 또는 영구 삭제. 화면 미설계 → OQ | 확정 |
| **복구 창구** | **영역별로 각자** — 문서는 문서함 휴지통, 업무는 업무 목록, 유형·프로젝트는 설정. 공통 휴지통을 두지 않는다 | 확정 |
| 용량 | 표시만. **상한·차단 없음** | 확정 |

## 5. CRUD 정책

| 행위 | 정책 | 근거 |
|---|---|---|
| 생성(C) | 업로드 드로어에서만. 파일별로 위치·연결 프로젝트·연관 업무·태그 입력, 「첫 파일 값 모두 적용」 지원. **업로드는 하단 버튼에서만 발생**(드롭 즉시 업로드 아님). md 외 형식은 거부 | 14-library §업로드 · 확정 |
| 조회(R) | 본인 것 전부. 휴지통 문서는 목록·검색·첨부 선택에서 제외되고 휴지통에서만 보인다 | 확정 |
| 수정(U) | 본문은 편집 탭에서 자동 저장. 메타데이터(태그·연결)는 레일에서. 이름 바꾸기·폴더 이동·복제는 더보기 메뉴 | 14-library |
| 삭제(D) | 더보기 「휴지통」 → 소프트 딜리트. 영구 삭제는 휴지통에서 | 확정 |

## 7. 저장·실패 정책

DEC-003 §7 의 원칙을 승계한다 — **처리하는 실패만 처리하고 그 밖의 예외는 fallback 없이 전파.**

| 상황 | 처리 | 근거 |
|---|---|---|
| md 아닌 파일 업로드 | 거부 + 안내. 부분 업로드하지 않는다 | 확정 |
| 업로드 실패 | 파일 단위로 실패 표시. 성공분은 유지(드로어는 파일별 카드 구조) | 14-library §업로드 |
| 자동 저장 실패 표시 | 미정 — DEC-001 OQ-4 와 공통 규칙으로 | → DEC-001 OQ-4 |
