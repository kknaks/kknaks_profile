# 회의록 정책

BASE-003 의 영역 정책. 2026-09-03 사용자 논의로 생성·회의 중·종료 전 구간 확정.

> 근거 표기: 「확정」 = 2026-09-03 사용자 논의, `P/Q-xx` = 분석 리포트, 파일명 = `00-design/`,
> 「soniox」 = `orchestration/work/docs-v1/soniox-study.md`.

## 1. 범위

- In: 회의록 생성·시작 전·실시간 받아쓰기(마이크)·녹음 원본 저장·사람 트랙·AI 배치 요약·근거 타임칩·종료 통합·편집·업무 생성/갱신·첨부·소프트 딜리트

## 4. 생명주기

| 결정 | 내용 | 근거 |
|---|---|---|
| 상태 흐름 | scheduled → recording → generating → ended. 통합 실패 시 ended + 실패 표시 | 확정 |
| **회의 중 2트랙** | 사람은 회의록 탭에 직접 입력, **AI 는 AI 요약 탭만 채운다.** AI 는 사람 트랙에 개입하지 않고 **줄 제안도 하지 않는다** | 확정 |
| **AI 트랙 안건 축** | 사람이 만든 안건을 컨텍스트로 받아 거기에 맞춰 채운다. **안건이 없거나 어디에도 안 맞으면 AI 가 새 안건을 만든다** | 확정 |
| **배치 갱신 방식** | **회의 중에는 증분 추가만**(기존 AI 줄 수정 안 함) → **종료 후 최종 배치가 AI 탭 전체 재정리** | 확정 |
| **종료 파이프라인** | 종료 → 「회의록 생성중」 스피너 → ① 마지막 배치(AI 탭 전체 재정리 = 로그성 기록) → ② **통합본 생성(회의록 탭 = 정본)**. 통합본 줄은 AI 줄의 타임스탬프를 물려받아 근거 칩을 갖는다 | 확정 |
| **통합 규칙** | **사람 줄 우선.** 같은 내용을 말하는 줄이면 **사람이 쓴 문장을 그대로 쓰고**, AI 줄에서는 **근거 타임스탬프만 가져온다**. AI 트랙에만 있는 내용은 통합본에 **추가로 붙인다**. AI 가 사람 문장을 다듬거나 바꾸지 않는다 | 확정(OQ-7 해소) |
| **통합본 재생성** | **없음.** 정상 생성분은 편집으로만 고친다. 「다시 생성」은 **실패 상태에서만** 노출 | 확정 |
| 삭제 | **소프트 딜리트** (업무와 동일) — 잘못 만든 회의록 정리용. **녹음 원본은 삭제하지 않는다**(영구 보관, §6). 확인 모달 미설계 → OQ | 확정 · Q-23 |
| **300분 초과 회의** | **다루지 않는다.** Soniox 스트림 한도(300분)를 넘는 회의는 실사용에서 없다고 보고, 재연결·세션 경계 처리를 v1 에 넣지 않는다. 실제로 그런 경우가 나오면 그때 만든다 | 확정(OQ-4 해소) |
| 반복 회의 | **v1 제외** — 반복 규칙·자동 생성 없음 | 확정 |

## 7. 저장·실패 정책

**처리하는 실패는 아래에 열거한 것뿐이다. 그 밖의 예외는 fallback 하지 않고 그대로 전파한다** —
광범위한 예외 포착은 어디서 깨졌는지를 가린다(사용자 확정).

| 상황 | 처리 | 근거 |
|---|---|---|
| **회의 중 배치 실패** | 조용히 넘기고, 그 구간 트랜스크립트를 **다음 배치에 합쳐 재시도**. 사용자에게 표시하지 않음 | 확정 |
| **JSON 스키마 위반** | **그 배치 결과 전체 폐기.** 부분 파싱해 반쯤 넣지 않는다 — 깨진 데이터가 DB 에 들어가는 게 요약 한 번 건너뛰는 것보다 나쁘다. 폐기 구간은 다음 배치로 | 확정 |
| **없는 업무 참조** | **화이트리스트 검증** — 웜스타트로 준 업무 ID 목록 밖의 ID 는 거부(회의 중 생성분은 다음 배치 컨텍스트에 반영). 참조가 틀린 줄은 **taskId 만 떼고 action 줄로 강등** — 내용은 살린다 | 확정 |
| **마지막 배치 실패** | AI 탭은 회의 중 증분 상태 그대로 유지(버리지 않음) | 확정 |
| **통합본 생성 실패** | 자동 재시도 2회 → 실패 시 스피너 걷고 **회의록 탭에 사람 원본 노출 + 「통합 정리 실패 · 다시 생성」 배너**. 사람 원본·AI 탭·트랜스크립트·녹음이 모두 남아 있어 회의록이 비지 않는다 | 확정 |
| **스피너 타임아웃** | 무한 대기 금지 — 시간 초과도 실패로 처리 | 확정 |
| 자동 저장 | 포커스 해제 시 (편집 모드) | 12-meeting-notes §편집 |

재시도 횟수(2회)·타임아웃·배치 임계치 등 **수치는 spec 에서 정한다.**

| Out | 내 업무 | 업무 생성·갱신 — **연다**(버튼 트리거) | DEC-002 §8 |
| In | 내 업무 | 웜스타트 컨텍스트 = **선택 프로젝트 + 그 프로젝트의 업무 + 미리 작성된 안건** | 확정 |
| In | 문서함 | 첨부는 연다. **단 v1 은 md 파일만**이고, **회의 중 md 작성(`source=local`·`agendaId`)은 v2** — 문서 생성 경로가 v1 에 없다(DEC-004 §4). **자료함 문서를 AI 컨텍스트로 넘기는 것도 v2**(색인이 v2) | 확정 · DEC-004 |
| Out | 캘린더 | 회의 일정 표시·드로어 재사용 — 연다. **회의록이 「전체 페이지 상세 + 상세 드로어」 두 표면을 제공**하고 캘린더가 드로어를 재사용한다(DEC-005 §2). **회의 일시는 회의록이 소유**하고 `schedule` 은 그 파생이다(DEC-005 §3) | 13-calendar · DEC-005 |
| Out | 알림 | **닫는다** — 알림은 별도 도메인, v1 회의록 범위 밖 | 확정 |
