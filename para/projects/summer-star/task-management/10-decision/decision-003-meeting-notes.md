# 회의록 정책

BASE-003 의 영역 정책. 2026-09-03 사용자 논의로 생성·회의 중·종료 전 구간 확정.

> 근거 표기: 「확정」 = 2026-09-03 사용자 논의, `P/Q-xx` = 분석 리포트, 파일명 = `00-design/`,
> 「soniox」 = `orchestration/work/docs-v1/soniox-study.md`,
> **`MF-n` = `reference/2026-09-06-task-management-app/Meeting flow.md` §0 결정 번호표(2026-09-07 실물 확인 뒤 사용자가 흐름을 단계별로 닫은 결정 35건 — `MF-1 ~ MF-71`).**
>
> **2026-09-07 개정.** 실물 확인(회의 1건을 처음부터 끝까지 돌림)에서 나온 결정 `MF-1 ~ MF-70` 을 반영했다.
> 크게 바뀐 넷 — ① **종료 시 배치와 통합 호출이 없어졌다**(MF-56 · 57): 종료 후에는 **async 재전사 → 최종 회의록 호출 한 번**이다
> ② **배치가 컨텍스트를 받지 않는다**(MF-50): 발화만 넘기고 안건·줄·업무·유형은 AI 가 도구로 조회한다
> ③ **배치가 매번 AI 트랙 전체를 낸다**(MF-53): 서버가 AI 트랙을 갈아끼운다
> ④ **편집이 좁아졌다**(MF-60 · 62): 줄 종류 전환·안건 삭제가 없다.
>
> **2026-09-07 저녁 추가 — MF-64(정정) · 66 · 67 · 68 · 69 · 70.**
> ⑤ **payload 드로어는 회의록 것이다**(MF-67): 업무 탭 드로어를 재사용하지 않고 회의록이 자기 드로어 둘을 갖는다 — 필드 = `payload` 키
> ⑥ **칩은 둘로 갈린다**(MF-64 정정): 논의·결정은 줄 추가 드로어, 액션·업무는 payload 드로어가 바로 뜨고 「저장」에 줄 + `payload` 한 요청
> ⑦ **OQ-8 · OQ-9 가 닫혔다**(MF-68 · 69 · 70): MCP 는 별도 컨테이너 · 단명 토큰은 `auth_session` 행 · 웜스타트 실패 처리는 만들지 않는다.
>
> **2026-09-08 추가 — MF-71**(실물 회의 8 · 9 에서 확정).
> ⑧ **중간 배치는 AI 혼자 쓴다**(MF-71): 회의 중 배치는 **사람 안건·사람 줄을 보지 않는다.**
> `list_agendas()` · `get_agenda(id)` 는 **최종 제출에서만** 부르고, 중간 배치의 codex `enabled_tools` 는
> 업무 셋(`list_tasks` · `get_task` · `list_work_types`)뿐이다 — 프롬프트 지시가 아니라 **설정으로** 잠근다.
> 미러 안건이 없어지고 AI 안건은 전부 신설이며(`humanAgendaId` 는 중간에 항상 `null`), 합치는 것은 최종 한 번이다(MF-56).
> 근거 — 회의 9 실측에서 AI 가 사람 노트를 읽자 **AI 요약이 사람 노트의 톤을 그대로 따라갔다.**
> 「두 사람이 각자 적는다」는 처음 개념과 어긋난다.
> `Meeting flow.md` 와 이 문서가 부딪히면 **`Meeting flow.md` 가 이긴다.**

## 1. 범위

- In: 회의록 생성·시작 전·실시간 받아쓰기(마이크)·녹음 원본 저장·사람 트랙·AI 배치 요약·근거 타임칩·**종료 후 async 재전사·최종 회의록(AI 작성)·STT 용어 보정**·편집·업무 생성/갱신·첨부·소프트 딜리트
- Out: 반복 회의, 예약 알림(알림 도메인 분리), 시스템 오디오 녹음, 외부 캘린더 자동 등록, 자료함 문서를 AI 컨텍스트로 전달 — 전부 v2

**2026-09-06 시안 대조 결과 확정분** (2026-09-07 MF 반영으로 일부 개정)

| 항목 | 결정 |
|---|---|
| **「업무」 줄** | **유지한다 — 줄 종류는 4종이다**(논의 · 결정 · **업무** · 액션). 시안 회의 중 팝오버(`회의록.dc.html` L925~936)가 **3종만** 그린 것은 **누락**으로 본다 |
| **「일시정지」** | **v1 에 넣는다.** 시안 3화면 헤더(`회의록.dc.html` L798 · L1085 · L1235) 그대로. **§4 의 「세션 경계 처리는 v1 밖」에 대한 예외**로 둔다 — 회의 중 잠깐 멈추는 것은 실제로 생기는 일이고, 화면 셋 모두가 그 자리를 갖고 있다 |
| **마이크·스트림 실패** | **일시정지 상태로 떨어뜨린다.** 배너로 사유를 말하고, **다시 시작은 사용자가 누른다** — 별도 「다시 연결」 버튼을 만들지 않는다(일시정지 해제가 그 역할). **자동 재연결을 하지 않는다**(§7 「자동 재시도를 두지 않는다 — 실패를 가린다」) |
| **로컬 파일 업로드 첨부** | **UI 만 그린다 — v2 게이트.** 드래그앤드롭 영역과 「최대 50MB」 문구(`회의록.dc.html` L1192 · L1342)를 시안대로 그리되, 조작하면 「**v2에서 제공됩니다**」 토스트만 뜨고 **네트워크 요청이 나가지 않는다**(SPEC-001 U-2 규격). **자료함 문서(md)와 URL 링크 두 갈래는 실동작**이다 |
| **회의 「장소」** | **v1 에 넣지 않는다.** ERD `meeting` 에 `location` 컬럼을 만들지 않고, API 요청·응답에도 두지 않으며, 시안의 「회의실 A」(`회의록.dc.html` L153 · L795)는 **그리지 않는다** |
| **종료 후 편집 범위** | **줄 삭제 · 줄 추가 · 줄 수정 · 업무 넣기 · 안건 제목 수정 — 다섯이 전부다**(2026-09-06 · **MF-60 · MF-62 로 2026-09-07 확정**). 경계 — ① **삭제는 회의록 탭(최종 회의록)에서만**. AI 탭·트랜스크립트·녹음은 그대로 남는다(§6) — 근거 칩이 가리킬 원본이 있어야 한다 ② **업무가 생성된 줄을 지워도 업무는 지우지 않는다**(§8 「회의록은 업무를 만들고 갱신만 한다」) ③ **안건은 제목만 고친다. 안건 삭제는 없다**(MF-62) — 줄은 항상 안건에 속하므로(§3) 안건을 지우면 딸린 줄이 통째로 날아간다. 필요 없는 줄은 줄 단위로 지운다 ④ **줄 종류는 편집에서 못 바꾼다**(MF-60) — 액션↔논의↔업무 전환마다 갈래(이미 넣은 업무 처리 · `taskId` 없는 업무 줄 · 페이로드 없는 액션 줄)가 늘어난다. 종류가 틀렸으면 그 줄을 **지우고 필요하면 새로 적는다** ⑤ **줄을 지운 자리는 그대로 둔다**(MF-36) — 뒤 줄을 당기지 않는다. **줄 순서 변경은 여전히 없다** |
| **안건 `next` 배지 문구** | **회의 상태에 따라 갈린다**(2026-09-06). `state='next'` 는 하나인데 뜻이 둘이다 — 회의 중에는 「아직 이번 회의에서 안 다룸」이고, 종료 후에는 「이번 회의에서 못 다뤘으니 다음 회의로」다. **회의 중 = 「대기」**(시안 L909 · L1149 · L1299). **시작 전에는 배지가 없다** — 안건 `state` 가 `null` 이고(SPEC-006 §4) 진행 상태가 아직 없다 · **종료 후 = 「다음 논의로」**(시안 L214 · L422 · L1525 · L1740 · L1960 의 「다음으로」를 이 문구로 확정). 시안이 이미 상태별로 나눠 그려 두었고, 그 판단이 맞다 |
| **AI 한 줄 요약 바** | **v1 에 넣는다.** **최종 회의록 호출(§4 종료 파이프라인 ②)의 출력에 `headline` 필드 하나가 더 붙는 것**이고, 별도 호출을 만들지 않는다(MF-56 으로 호출이 하나뿐이라 「종료 시 배치에서 내나 통합에서 내나」는 성립하지 않는다). 저장은 `meeting.ai_headline`(`database/README.md`). 표시는 디자인 시스템 **[09] L727~733** 규격 그대로 — 상세 상단 `top 150 · 1640×56` 한 개, 회의 중 회색 상태 바와 **같은 자리**를 쓴다(`#EEF1FE` / 테두리 `#C9D1FB` / 배지 「AI 한 줄 요약」 + 한 문장 + 우측 카운트). **우측 카운트는 최종 회의록 기준 다섯이다 — 「안건 n · 논의 n · 결정 n · 액션 n · 업무 n」**(MF-25 · 화면에 그리는 그것을 센다. 이전 「안건 n · 결정 n · 액션 n」은 세는 대상과 그리는 대상이 달라 어긋났다 — F-11) |
| **확인 모달 크기** | **줄 하나 지우는 확인은 420 폭 · 한 문장**(MF-63). 「안 지워지는 것」은 적지 않는다. **600 은 회의 삭제처럼 진짜 무거운 것에만** 남긴다 — 모달이 두 크기가 되고 컴포넌트는 `ConfirmModal` 하나 그대로다(`frontend/README.md` §6) |

> 근거 — 시안에는 화면에 있으나 **BASE-003 · DEC-003 · ERD `meeting.md` · SPEC 어디에도 grep 0건**이었다(리뷰어 1·2 가 각각 올린 자리).
> 개인 워크스페이스라 장소를 공유할 상대가 없고, 쓰는 곳이 없는 필드를 만들면 비어 있는 채로 남는다.
> SPEC-006 OQ-7 · SPEC-007 OQ-2 가 이 결정으로 닫힌다.

> **「업무」 줄 근거** — **서버 표면이 이미 다 있다**: 액션(새 업무)은 `POST /api/tasks`, 업무(기존 갱신)는 `PATCH /api/tasks/{id}`,
> 상태를 바꾸는 갱신은 전용 `PATCH /api/tasks/{id}/status`(게이트·로그·실행취소가 붙는다. 일반 PATCH 에 `status` 를 실으면 **422**).
> **디자인 시스템 [09] L668~672 에 규격도 있다** — 라벨 `#5F6470` + 유형 배지 + **「업무 갱신」 버튼**(액션은 `#4B52A8` + 「업무 생성」).
> **정책이 「회의록이 업무를 만들고 **고친다**」(§5)** 인데 업무 줄을 빼면 **고치는 입구가 화면에서 사라진다** —
> 회의 중 팝오버에도 없고(S007-OQ-5) 상세·편집 6화면에도 없다(리뷰어3 M-3).
> **SPEC-007 OQ-5 · SPEC-008 M-3 이 이 결정으로 닫힌다.**

> **첨부 근거** — v1 에 **로컬 파일 업로드 경로가 없다**(정정 §A-11 · DEC-004 §3). 첨부는 **자료함 문서(md) · URL 링크** 두 갈래뿐이고
> 업무(SPEC-003 U-7)가 이미 그렇게 돈다. 회의도 같다.
> **50MB 상한은 계약에 담지 않는다** — 업로드가 v2 이므로 v1 에 검증할 대상이 없다. 문구는 시안대로 그리되 **v2 게이트 아래**에 둔다.
> **SPEC-007 OQ-19 가 이 결정으로 닫힌다.**

> **일시정지 근거** — 시안이 회의 중 세 화면 **모두** 헤더에 두었다. §4 의 「세션 경계 처리는 v1 에서 다루지 않는다」는
> **여러 세션을 이어 붙이는 복원**을 뜻하고, **한 세션 안에서 멈췄다 잇는 것**은 그 범위가 아니다 — 예외로 명시한다.
>
> **마이크 실패가 이 결정으로 함께 풀린다** — 스트림이 끊기면 **일시정지 상태**가 되고 사용자가 다시 켠다.
> 「다시 연결」 버튼을 따로 만들 필요가 없고, **자동 재연결도 하지 않는다**(§7).
> **SPEC-007 OQ-1 · OQ-21(U-8 마이크 실패 · U-9 녹음 끊김 화면)이 이 결정으로 닫힌다** — 두 화면은 별도 화면이 아니라
> **일시정지 상태 + 사유 배너**다.

## 2. 권한·소유 정책

| 결정 | 내용 | 근거 |
|---|---|---|
| 소유·접근 | DEC-001 승계 — 본인 세션만 | DEC-001 §2 |
| 화자 표기 | **참석자·발언자 이름 없음.** 스크립트는 익명 화자 라벨(화자 1/2)까지만 — Soniox 익명 라벨과 일치. **용어 보정(§6)도 화자 라벨은 어떤 경우에도 바꾸지 않는다** | 12-meeting-notes §v1에서 뺀 것 · soniox · MF-54 |
| **AI 의 데이터 접근** | AI 는 **API 래퍼 도구(최대 7개)**로만 우리 데이터를 읽는다(MF-2). **여는 도구는 단계별로 다르다**(MF-71) — **회의 중 배치는 업무 셋**(`list_tasks` · `get_task` · `list_work_types`)**뿐**이고 **최종 제출에서만 일곱 전부**다. 안건 도구 둘(`list_agendas` · `get_agenda`)을 중간에 안 여는 것은 **프롬프트 지시가 아니라 `enabled_tools` 설정**이다. **DB 직결이 아니다.** 도구는 **이 회의·이 계정 범위**에서만 답하고, 그 범위 판정은 **백엔드가 진다** — 회의마다 **본인 계정으로 단명 토큰을 새로 발급**해 도구 호출 헤더에 싣고, 회의가 끝나면 best-effort 로 폐기한다(MF-4). **그 토큰의 실체는 `auth_session` 의 `kind='meeting'` 행이다**(MF-69) — `/start` 때 INSERT 하고 **② 가 끝나면 행을 삭제**한다(폐기 = 행 삭제. 실패는 자연 만료로 흡수). **무상태 JWT 짧은 TTL 은 쓰지 않는다** — 폐기 표면이 없어 「best-effort 폐기」가 성립하지 않는다. 사용자 세션 JWT 를 그대로 주지 않는다. 도구 밖의 능력(셸 · 파일 · 웹 검색 · 이미지 · codex 내장 앱)은 **프롬프트가 아니라 codex 설정(allow list)이 잠근다**(MF-3) | MF-2 · MF-3 · MF-4 · MF-71 |

AI 세션 id 가 없는 동안 **배치는 돌지 않는다** — 트리거는 평가하되 제출하지 않는다. **실패 처리를 따로 만들지 않는다**(MF-70 · OQ-8 닫힘) — 별도 기록 테이블 · 재시도 경로 · 재웜스타트 갈래가 없고 **남기는 것은 예외 전파 로그뿐**이다. 이미 있는 두 경로로 흘러간다: **회의 중** = 배치 미제출(SPEC-007 검증 0) · **종료 후** = 세션이 없어 ② 가 `final_failed`(SPEC-008) → 「다시 시도」 배너. 「설계한 것 이외의 에러는 터지게 둔다」(BASE-003 L43) 그대로 | MF-1 · **MF-70** (D-2/DG-9 함께 닫힘) |
| **회의 중 배치 실패** | 조용히 넘기고, 그 구간 트랜스크립트를 **다음 배치에 합쳐 재시도**. 사용자에게 표시하지 않음 | 확정 |
| **JSON 스키마 위반** | **그 배치 결과 전체 폐기.** 부분 파싱해 반쯤 넣지 않는다 — 깨진 데이터가 DB 에 들어가는 게 요약 한 번 건너뛰는 것보다 나쁘다. 폐기 구간은 다음 배치로. **AI 트랙은 직전 성공분 그대로 남는다**(전량 교체는 검증을 통과한 결과로만) | 확정 · MF-53 |
| **없는 업무 참조** | **서버 사후 검사** — 배치 입력에 화이트리스트를 싣지 않지만(MF-50) 검사는 남긴다. 기준 목록은 **회의 프로젝트의 업무(무소속 회의면 무소속 업무)** 를 검사 시점에 서버가 조회한 것. 목록 밖 `taskId` 를 가리키는 줄은 **`taskId` 만 떼고 action 줄로 강등** — 내용은 살린다. 페이로드 안의 참조(유형 · 프로젝트 · 연관 업무)도 같은 자리에서 검사한다 | 확정 · MF-50 · MF-59 |
| **회의 중 AI 줄에 페이로드가 실려 옴** | **서버가 버린다**(`null` 로 저장). 프롬프트에도 「회의 중에는 `null` 로 둬라」를 적는다 | MF-52 |
| **재전사 실패**(①) | **fallback 없음.** 실시간 결과로 몰래 최종 회의록을 만들지 않는다. `ended` + 실패 표시 + **「다시 시도」 하나**. 다시 시도는 ①부터 — 음성 원본 + 안건 + 그동안의 요약을 다시 던진다 | MF-58 |
| **최종 회의록 생성 실패**(②) | 자동 재시도 2회 → 실패 시 스피너 걷고 **회의록 탭에 사람 원본 노출 + 「회의록 생성 실패 · 다시 시도」 배너**. 사람 원본·AI 탭·트랜스크립트·녹음이 모두 남아 회의록이 비지 않는다 | 확정 · MF-58 |
| **스피너 타임아웃** | 무한 대기 금지 — 시간 초과도 실패로 처리. **재전사는 처리 시간에 공식 수치가 없다 — 「즉시」로 설계하지 않는다** | 확정 · MF-37 |
| 자동 저장 | 포커스 해제 시 (편집 모드) | 12-meeting-notes §편집 |

재시도 횟수(2회)·타임아웃·배치 임계치 등 **수치는 spec 에서 정한다.**

### AI 도구 연결 (MF-2 · MF-3 · MF-4 · MF-55)

| 항목 | 결정 |

| **형태** | **백엔드 API 의 얇은 래퍼**(MF-2). DB 직결이 아니다. 권한 경계는 백엔드가 진다 — MCP 는 두 번째 게이트가 아니다 |

| **잠금** | 못 쓰게 하는 것은 **codex 설정 allow list**(MF-3). 프롬프트에도 적지만 실제 차단은 설정이 한다. deny list 는 없다 — 상세는 `system/README.md` §codex |
| **토큰**(MF-4 · **MF-69**) | 회의(turn)마다 **본인 계정으로 단명 토큰을 새로 발급** → codex 실행 옵션의 MCP 헤더로 주입 → 마감 시 best-effort 폐기(실패는 자연 만료로 흡수). 사용자 세션 JWT 를 그대로 주지 않는다. **축은 `auth_session` 행이다**(OQ-9 닫힘) — `kind='meeting'` 행을 더한다. **발급** = `/start` 때 본인 계정으로 행 INSERT → 토큰을 MCP 헤더에 싣는다 · **검증** = MCP 가 부르는 REST 가 그 행으로 계정 · 회의 범위를 본다 · **폐기** = ② 가 끝나면 **행 삭제**(best-effort). **무상태 JWT 짧은 TTL 은 안 쓴다** — 폐기 표면이 없어 MF-4 의 「best-effort 폐기」가 성립하지 않는다 |
| **웜스타트가 주는 것** | **컨텍스트를 싣지 않는다.** 역할 · 규칙 · **용어 다섯의 뜻** · 도구만 준다(MF-55). 용어 — **안건**(주제. 「무엇에 대해 이야기하는가」. 회의의 뼈대) ├ **논의**(아직 정해지지 않은 것 — 의견 · 현황 공유 · 질문) ├ **결정**(이 회의에서 정해진 것 — 되돌리려면 다시 회의해야 하는 것) ├ **액션**(이 회의 때문에 **새로 생긴 할 일**) └ **업무**(**이미 있는 업무**의 현황·변경). **넷은 전부 안건에서 파생된다. 안건 없이 떠 있는 줄은 없다 → 줄을 만들기 전에 먼저 어느 안건인지를 정한다.** 액션과 업무를 가르는 선 — 이미 하고 있던 일의 현황 보고는 액션이 아니라 업무다. 업무는 반드시 실제로 있는 것만 가리킨다. 프롬프트 초안은 `reference/2026-09-06-task-management-app/ai-prompt-draft.md` §A |
