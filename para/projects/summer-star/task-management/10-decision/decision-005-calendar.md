# 캘린더 정책

BASE-005 의 영역 정책. 2026-09-03 사용자 논의로 확정.

> 근거 표기: 「확정」 = 2026-09-03 사용자 논의, `P/Q-xx` = 분석 리포트, 파일명 = `00-design/`.

## 1. 범위

- In: 월·주·일 뷰, 일정 표시 5규칙, 동적 유형 필터, 생성·상세 드로어 재사용, 드래그 이동·기간/길이 변경, 겹침 차단
- Out(v2): 외부 캘린더 일정 표시, 반복 일정
- **캘린더 전용 생성 폼·상세 화면을 만들지 않는다** — 전부 재사용 | 13-calendar §생성 흐름

## 2. 권한·소유 정책

| 결정 | 내용 | 근거 |
|---|---|---|
| 소유·접근 | DEC-001 승계 | DEC-001 §2 |
| **데이터 소유** | 캘린더는 **데이터를 소유하지 않는다.** 업무·회의를 시간축으로 보여주는 뷰이며, 변경은 원 영역의 갱신으로 나간다 | 13-calendar |
| **회의 상세 드로어** | **회의록이 소유**하고 캘린더가 재사용한다(업무 상세 드로어와 같은 구조). 회의록은 전체 페이지 + 상세 드로어 두 표면을 제공 | 확정(Q-15 해소) |

## 3. 필드 정책 — 일정 테이블 분리

**업무·회의의 시간 정보를 별도 `schedule` 테이블로 분리한다**(확정). 캘린더가 두 소스를 한 번에 읽고, 겹침 검사를 한 곳에서 하며, v2 외부 캘린더가 붙을 자리를 만든다.

| 필드 | 필수 | 허용값/제약 | 근거 |
|---|---|---|---|
| source_type | ✔ | `task \| meeting` (v2: `external`) | 확정 |
| source_id | ✔ | 업무·회의 FK | 확정 |
| start_at / end_at | ✔ | | 확정 |
| is_all_day | ✔ | 종일·기간 일정 구분 | 13-calendar §표시 규칙 |

- 회의는 시간이 사실상 필수라 `schedule` 행이 항상 있고, 업무는 무일정을 허용하므로 없을 수 있다

**`schedule` 은 파생이다 — 원본은 각 영역이 소유한다** (2026-09-05 개정).

| 사실 | 원본(소유) | schedule |
|---|---|---|
| 업무의 **기한** | **업무 `due_date`** — 리스트 기본 정렬·D-day 의 근거. 조인 없이 읽는다 | 기한이 있으면 **종일 일정**(`is_all_day=true`)으로 파생 |
| 업무에 **시간까지 지정** | 업무 | 시간 일정으로 파생 |
| 회의 일시 | 회의록 | 시간 일정으로 파생(회의는 시간이 사실상 필수) |

- **방향은 한 쪽이다** — 원본을 고치면 `schedule` 이 갱신된다. 캘린더에서 드래그하면 **원본(업무 `due_date` · 회의 일시)을 고치고**, 그 결과가 `schedule` 로 내려온다. 원본이 하나라 어긋나지 않는다
- `schedule` 이 갖는 것은 **시간축 배치뿐** — `start_at`·`end_at`·`is_all_day`. 기한 같은 도메인 속성을 담지 않는다
- 일정도 기한도 없는 업무는 `schedule` 행이 없다(무일정 허용 — DEC-002 §3)
- 캘린더 조회·겹침 검사는 여전히 `schedule` 한 테이블에서 끝난다(분리한 이유는 유지)
- 비용: 업무 목록의 종료일 정렬·D-day 표시에 조인이 붙는다(수용)
- 유형 색은 **유형이 들고 있는 값**을 쓴다. 디자인의 **유형 4색 고정은 폐기 — 정정 대상** | 확정 · DEC-001 §3

## 4. 생명주기 — 드래그 규격

뷰마다 허용 동작이 다르다(확정).

| 뷰 | 허용 |
|---|---|
| **월** | 일자 이동 · 기간 좌우 드래그로 기간 변경. **시간 변경 불가** |
| **주** | 일자 이동(같은 시간 유지) · 종일 좌우 드래그(기간 변경) · **종일 → 시간대 드롭 시 그 지점부터 1시간 기본** · 시간 항목 일자 이동 · 위아래 드래그로 길이 조절 |
| **일** | 시간대 이동(드래그 앤 드롭) · 위아래 드래그로 길이 조절 |

**드래그 고스트는 목적지 크기로 그린다** — 축을 넘나들 때만 기간이 바뀐다.

| 이동 | 고스트 |
|---|---|
| 종일 밴드 → 시간 그리드 | **1시간 블록 크기로 축소** (7일 바를 그대로 들고 하루 칸에 넣는 모양이 되면 안 된다) |
| 시간 그리드 → 종일 밴드 | 하루짜리 종일 칩 (원래 기간을 기억하지 않는다) |
| 같은 축 안 이동 | 원래 기간·길이 유지 |

**드래그 결과는 원 데이터 갱신**으로 나간다 — 업무면 업무 일정 갱신, 회의면 회의 일정 갱신.

## 7. 저장·실패 정책 — 겹침 차단

DEC-003 §7 원칙 승계 — **설계한 실패만 처리, 그 밖은 fallback 없이 전파.**

| 상황 | 처리 | 근거 |
|---|---|---|
| **겹침** | **시간 있는 일정끼리 시간대가 겹치면 생성·이동을 거부**하고 토스트로 사유를 알린다. 경고만 하고 통과시키지 않는다. **종류 불문 — 업무↔회의도 서로 막는다** | 확정 |
| 겹침 검사 대상 | **시간 있는 일정만.** 종일·기간 일정은 검사하지 않는다(기간에 걸친 일이지 그 시간을 점유한 게 아니다) | 확정 |
| 경계 접촉 | 끝시각 = 시작시각(10–11 / 11–12)은 겹침이 아니다 | 확정 |
| 취소 일정 | 검사에서 제외 | 확정 |
| **드래그 중 판정** | 겹치는 자리는 **애초에 드롭되지 않는다**(드롭 불가 표시, 놓으면 원위치). 놓은 뒤 거부하지 않는다 | 확정 |
| **길이 조절** | 인접 일정 경계에서 멈춘다(그 이상 안 늘어남) | 확정 |
