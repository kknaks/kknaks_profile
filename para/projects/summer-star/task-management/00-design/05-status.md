# 상태 전이

보드: `상태 변경 · 드롭다운`, `완료 처리 직후 · 토스트`, `취소 사유 입력 · 모달`

## 상태 5종

| 상태 | 색 | 의미 |
|---|---|---|
| 시작전 | `#9EA2AE` | 생성 직후 기본값 |
| 진행중 | `#33AAFF` | |
| 완료 | `#7181F8` | |
| 취소 | `#B3B3B3` | 사유 필수 |
| 지연 | `#E2685B` | 사용자가 고르는 값이 아님 — 종료일이 지났고 완료/취소가 아니면 자동 |

드롭다운 목록에는 시작전 / 진행중 / 완료 / (구분선) / 취소 4개만 나온다. 지연은 표시 전용.

## 전이 규칙

```
시작전 → 진행중 | 완료 | 취소
진행중 → 완료 | 시작전 | 취소
완료   → 진행중            (되돌리기)
취소   → 시작전            (되살리기, 사유 기록은 로그에 남음)
```

- 완료 → 취소는 불가. 먼저 진행중으로 되돌린다
- 모든 전이는 로그에 `상태 A → B`로 기록

## 상태 변경 지점

1. 리스트 행의 상태 셀 클릭 → 드롭다운 (트리거 셀 좌측 정렬, 아래 8px)
2. 상세 헤더의 상태 드롭다운
3. 칸반 카드 드래그 (미설계 — `01-screens.md` 참고)

현재 값은 배경 `#F4F5FF` + 상태색 텍스트로 표시한다.

## 완료 처리

1. 카드/행이 즉시 완료로 이동. 칸반에서는 완료 컬럼 최상단에 `방금` 표시로 삽입, 테두리 `#7181F8` + 강한 그림자
2. 하단 중앙 토스트: 400×56, `#1E1E1E`, 4초, `완료 처리했습니다` + `실행취소`(#A6CDFF)
3. 실행취소를 누르면 직전 상태로 복원하고 로그도 되돌린다
4. 결과자료가 비어 있어도 완료를 막지 않는다. 대신 완료 후 상세 결과자료 카드에 `완료 시 필수` 안내가 남는다

## 취소 처리

모달 600px (되돌리기 어려운 결정이므로 팝오버·드로어 아님).

- 사유 칩: `일정 연기` / `요건 변경` / `중복 업무` / `직접 입력`
- 직접 입력 시 textarea
- `취소 사유를 로그에 기록` 체크(기본 켜짐)
- 버튼: `닫기` / `업무 취소`(#1E1E1E)
- 취소 후: 제목 `#9EA2AE` + line-through, 유형 배지는 테두리형으로 바뀜, 종료일 칸에 사유 표시
