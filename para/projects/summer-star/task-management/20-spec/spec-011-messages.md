# 메시지함 — v1 목록 화면(비활성)

**v1 에 메시지가 없다.** 수신 경로가 연동 관리에 걸려 있고 연동이 목 UI 이기 때문이다(DEC-006 §1). 그래서 이 영역은 **화면만 세운다** — 사이드바 메뉴는 정상 노출·정상 진입하고, 필터 카드·목록·빈 상태를 그대로 그리되 조작하면 「v2에서 제공됩니다」 안내만 뜬다.

> 기능/정책 묶음 단위의 **외부 계약** 문서다. client / QA / 외부 통합이 이 문서만 읽고 따를 수 있어야 한다.
> SPEC에는 table schema 전문, ORM field, repository/service 구조, PR 계획, 구현 순서, 라우트·컴포넌트 파일 경로 같은 내부 구현을 두지 않는다.

### Business Requirement

- **v2 에서 연동이 열릴 때 뒤(백엔드)만 붙이면 되도록 앞을 미리 세운다**(DEC-001 §v2 스코프). 숨기면 제품의 형태가 보이지 않고, v2 에서 화면부터 다시 만들게 된다.
- **사이드바 메뉴를 흐리게 하지 않는다**(DEC-006 OQ-2 해소). 메뉴는 정상이고, 들어가면 비활성 화면이 보인다 — 홈·채팅처럼 진입 자체를 막는 것과 다르다(FE §10).

### Scope

In scope:

- **사이드바 「메시지」 진입** — 정상 노출·정상 진입
- **필터 카드**(채널 / 처리 상태) · **목록 영역** · **우측 빈 상태** — 전부 비활성으로 그린다
- 헤더 요소(검색 · 「연동 관리」 · 「AI로 업무 추출」) — 비활성
- **메시지함 반응형**(미설계 — 여기서 확정)

Out of scope — **전부 v2 이고, 이 spec 은 그 계약을 쓰지 않는다**(DEC-006 §1·§5):

- 메시지 수신·적재 · 상세·원문 · **읽음 처리** · **업무 등록** · 일정 추가 · AI 업무 추출 · 답장 컴포저 · 연결된 기록 · 보관·삭제
- 채널 연동 상태·재연동 — 연동 관리(SPEC-010 U-4)도 v2 다

## 2. UX Contract

### Placement

앱 셸 안의 페이지. 좌 필터 카드 + 중앙 목록 + 우 빈 상태 3단이다(P-71 골격 그대로).

```text
+──────────+─────────────────────────+──────────────────+
│ 필터 카드 │ 목록 영역                │ 빈 상태          │
│ 260      │ (유동)                   │ 「메시지를 선택   │
│ 채널     │                          │  하세요」        │
│ 처리 상태 │                          │                  │
+──────────+─────────────────────────+──────────────────+
```

**화면 전체가 SPEC-001 U-2 의 「아직 열리지 않은 기능」 표시를 입고 있다** — 원래 컴포넌트를 그대로 그린 위에 한 겹을 얹고, 조작하면 「v2에서 제공됩니다」 토스트만 띄운다. 규격을 여기서 다시 정의하지 않는다.

### U-1. 진입 · 화면 전체 상태

- **상태**: 사이드바 「메시지」는 **정상 색**이고 누르면 **정상 진입**한다(DEC-006 OQ-2). 들어가면 위 3단이 보이고 **전부 비활성**이다 — 불투명도 0.45, 커서 `not-allowed`, 레이아웃은 그대로(SPEC-001 U-2)
- **문구**: 화면 상단에 안내 한 줄 — 「**연동이 열리면 메시지가 이곳에 모입니다 · v2에서 제공됩니다**」
- **CTA**: 없다. 어느 요소를 눌러도 **네트워크 요청이 나가지 않고** 토스트만 뜬다
- **기대 결과**: **홈·채팅과 다르다** — 그쪽은 라우트가 없어 진입하지 않고 토스트만 뜨지만(FE §10), 메시지함은 **화면이 있어 들어간다**(DEC-006 §4)

### U-2. 필터 카드 (260)

- **상태**: 채널(전체 / 메일 / 카카오톡 / 슬랙) + 처리 상태(확인 필요 / 업무로 등록됨 / 보관) 항목이 보인다. 전부 비활성
  - **건수를 표시하지 않는다** — 디자인(P-71)의 「전체 24 · 메일 9」 같은 숫자는 **v1 에 셀 데이터가 없다**(DEC-006 §3). 없는 수를 그리면 있는 것처럼 읽힌다(§7)
  - 채널 색(메일 `#EAF4FF`/`#338BF6` 등)은 **출처 표시 전용 축**이라 업무 유형 배지와 섞지 않는다([02] CHANNEL · [10])
- **문구**: 항목 이름만
- **CTA**: 누르면 「v2에서 제공됩니다」 토스트
- **기대 결과**: 필터가 걸리지 않는다. 카드는 **v2 에서 그대로 살아날 자리**다

### U-3. 목록 영역 · 우측 빈 상태

- **상태**
  - *목록*: **비어 있다.** 공용 빈 상태(S-25) — 「아직 받은 메시지가 없습니다」 + 캡션 「채널 연동은 v2에서 제공됩니다」
  - *우측*: 「**메시지를 선택하세요**」 + 「**여는 순간 읽음으로 기록되므로 자동으로 열지 않습니다**」(15-messages §읽음 처리 — v2 구현 시 지킬 규칙을 화면에 보존한다)
- **문구**: 위와 같다
- **CTA**: 빈 상태의 「안 읽음만 보기」·「채널 연동 상태」 진입점은 **그리되 비활성**이다
- **기대 결과**: **첫 진입에서 아무것도 자동 선택하지 않는다**(DEC-006 §4). v1 에는 열 메시지가 없고, v2 에서도 이 규칙이 그대로 간다

### U-4. 헤더 요소

- **상태**: 「업무 후보」 배지 · 검색 입력 · 「연동 관리」 · 「AI로 업무 추출」이 보이되 비활성이다
- **문구**: 디자인 그대로
- **CTA**: 누르면 「v2에서 제공됩니다」 토스트. **「연동 관리」도 마찬가지다** — 연동 화면 자체가 v2 다(SPEC-010 U-4)
- **기대 결과**: 헤더에서 나가는 요청이 하나도 없다

### U-5. 반응형 — 메시지함 (미설계 확정)

| 구간 | 메시지함 |
|---|---|
| **< 1280** | 최소 폭 안내 화면(SPEC-000 U-2) |
| **1280 ~ 1439** | 사이드바 숨김 + 햄버거, 여백 48. **필터 카드를 접는다** — 좌상단 「필터」 버튼으로 **오버레이 260**. 목록 유동 + 우측 빈 상태 **400 고정** |
| **≥ 1440** | 사이드바 200, 여백 80 → 240 연속 보간. 필터 260 + 목록 유동 + 우측 400~420 |

- 근거: `08-responsive.md` §규칙(축소형을 만들지 않는다 — 260 이 아니면 숨김) · L20(좌 유동 + 우 400 고정) · §C Q-34(absolute 금지)
- 문서함(SPEC-005 U-10)·캘린더(SPEC-009 U-11)와 **같은 방식**이다 — 좁아지면 좌측 보조 패널을 오버레이로 접는다

## 3. User Scenario

### S-1. 사용자 — 메시지함에 들어간다

1. 사이드바에서 「메시지」를 누른다 → **정상 진입**한다(메뉴가 흐리지 않다).
2. 필터 카드·목록·빈 상태가 보이고 상단에 「연동이 열리면 메시지가 이곳에 모입니다 · v2에서 제공됩니다」가 있다.
3. 목록은 「아직 받은 메시지가 없습니다」다.

### S-2. 사용자 — 조작해 본다

1. 채널 필터 「메일」을 누른다 → 「**v2에서 제공됩니다**」 토스트만 뜨고 화면이 그대로다.
2. 검색·「AI로 업무 추출」·「연동 관리」도 같다.
3. **어느 조작에서도 네트워크 요청이 나가지 않는다.**

### S-3. 사용자 — 창을 좁힌다

1. 1439 이하로 줄이면 **필터 카드가 접히고** 좌상단에 「필터」 버튼이 생긴다.
2. 1280 미만은 최소 폭 안내 화면이다.

## 4. Interface Contract

### API Contract

**해당 없음.** v1 에 메시지함 API 표면이 없다(DEC-006 §3·§5 · `backend/README.md` §10 「메시지함 — 없다」). 이 화면은 **어떤 요청도 보내지 않는다.**

### Request / Response

**해당 없음** — 위와 같다.

### Validation

**해당 없음** — 입력을 받지 않는다.

### Case Matrix

이 spec 에서 일어날 수 있는 것은 하나뿐이다.

| 에러 코드 | 백엔드 출력 | 프론트 출력 | 표시 위치 |
|---|---|---|---|
| `v2_not_available` | `501 {detail:"v2에서 제공됩니다", code:"v2_not_available"}` | 「v2에서 제공됩니다」 토스트 | 화면 하단 토스트 |

- **정상 경로가 아니다.** 화면은 요청을 보내지 않으므로, 이 코드는 **표시 게이트가 새서 호출이 나갔을 때의 안전망**이다(`backend/README.md` §8-2 · SPEC-001 U-2)
- 조회 실패·자동 저장 실패 같은 케이스가 **없다** — 부를 API 가 없다

### Flow

**해당 없음** — 서버와 오가는 흐름이 없다. 사용자가 조작하면 화면이 토스트를 띄우고 끝난다.

### State / Lifecycle

**해당 없음** — v1 에 상태를 가질 리소스가 없다(DEC-006 §3).

### Data Contract

**해당 없음** — v1 에 저장 대상이 없다. **메시지 스키마는 v2 에서 연동과 함께 정의한다**(DEC-006 §3 · `database/README.md` §2 「만들지 않는 표 — 메시지」).

## 5. Implementation Rules

- **데이터도 API 도 만들지 않는다**(DEC-006 §3·§5 · G-8 「v2 기능의 컬럼을 미리 만들지 않는다」). 테이블·엔드포인트·스키마 어느 것도 v1 에 없다
- **화면은 그대로 그린다.** 원래 컴포넌트를 만들고 **감싸는 방식 하나**로 비활성 처리한다 — 화면마다 `disabled` 를 흩뿌리면 v2 에서 걷어내기 어렵다(FE §9)
- **없는 수를 그리지 않는다.** 필터 항목의 건수, 「업무 후보 n」, 「마지막 동기화」 시각은 **표시하지 않는다** — 셀 데이터가 없어 목업 숫자가 되고, 사용자가 실제 값으로 읽는다(§7)
- **자동 선택 금지 규칙을 화면에 보존한다** — 우측 빈 상태의 문구가 그 규칙의 근거를 담는다. v2 구현 시 이 규칙을 그대로 따른다(DEC-006 §4 · 15-messages §읽음 처리)
- **사이드바 메뉴를 흐리게 하지 않는다**(DEC-006 OQ-2). 진입까지는 정상이다
- **채널 색은 출처 표시 전용 축**이다 — 업무 유형 배지·상태 색과 섞지 않는다([10] · SPEC-002 §4 팔레트 규칙과 같은 근거)

## 6. Verification

### Acceptance Criteria

앱 창에서 사람이 직접 확인하는 문장으로 적는다.

- [ ] 사이드바 「메시지」가 **흐리지 않고**, 누르면 **화면이 뜬다**
- [ ] 필터 카드 · 목록 · 우측 빈 상태가 **전부 보이고** 비활성이다(레이아웃이 원래대로다)
- [ ] 상단에 「**연동이 열리면 메시지가 이곳에 모입니다 · v2에서 제공됩니다**」가 보인다
- [ ] 목록에 「아직 받은 메시지가 없습니다」가, 우측에 「**메시지를 선택하세요**」와 「여는 순간 읽음으로 기록되므로 자동으로 열지 않습니다」가 보인다
- [ ] 채널 필터·처리 상태·검색·「AI로 업무 추출」·「연동 관리」 어느 것을 눌러도 「**v2에서 제공됩니다**」 토스트만 뜬다
- [ ] 어떤 조작에서도 **네트워크 요청이 나가지 않는다**
- [ ] 필터 항목에 **건수 숫자가 없다**(24 · 9 같은 목업 수가 보이지 않는다)
- [ ] **자동으로 선택된 메시지가 없다**
- [ ] 창을 1280~1439 로 줄이면 **필터 카드가 오버레이**로 접히고, 1280 미만은 최소 폭 안내 화면이다
