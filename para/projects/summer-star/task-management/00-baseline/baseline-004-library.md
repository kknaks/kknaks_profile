# 문서함

문서를 폴더에 놓고 프로젝트·업무·회의와 링크로 잇는 위키. 2026-09-03 사용자 논의로 v1 범위 확정 — **md 전용·업로드만·색인과 버전은 v2**.

> 아직 결정하지 않은 날것의 입력이다. 정리보다 보존이 우선이다.

## Raw

2026-09-03 사용자 논의에서 나온 그대로:

- 폴더 최상위는 **PARA 4종 고정**(01 Projects / 02 Areas / 03 Resources / 04 Archive) — 시드로 주고 삭제·이름 변경 불가, 하위만 자유 생성.
- 프로젝트 폴더 자동 생성은 안 한다. "일단 수동으로 관리할까?" → **폴더는 사람이 만들고, 프로젝트·업무·회의 관계는 「연결」로.** 두 축 독립.
- **AI 색인은 v2** — "UI는 v2에서 제공됩니다로 가자". 따라서 본문 임베딩·문서 간 링크 자동 추출·백링크도 v2.
- **버전 관리도 v2** — "편집 버전관리도 v2에서 하자". v1 편집은 자동 저장만.
- 삭제는 **소프트 딜리트 + 휴지통 화면**(복원·영구 삭제). 복구 창구는 **영역별로 각자** — 문서는 문서함 휴지통, 업무는 업무 목록, 유형·프로젝트는 설정.
- **v1 은 md 만 업로드 허용** — pdf·docx 등은 v2. (따라서 회의록 첨부·업무 참고자료도 v1 은 md 만)
- 문서 생성 경로는 **업로드만** — 문서함에서 새 문서 만들기는 v1 에 없다.
- 용량 바는 **표시만**, 제한 없음.
- 즐겨찾기는 넣되 **목록 정렬까지만** (별도 필터·화면 없음).

## Context

디자인(`14-library.md` + `문서함.dc.html` 화면 5종, P-56~P-60)이 트리·목록·상세/편집 3열·더보기 팝오버·업로드 드로어까지 정의돼 있다. 09-03 사용자 확정으로 **탐색안(`자료함.dc.html`)은 폐기**되고 이 확정안이 정본이다(Q-26 해소). 첨부 대상으로 업무(BASE-002)·회의록(BASE-003)이 이 영역을 참조한다.

## Why It Matters

- **업무·회의의 자료가 모이는 곳이다.** 업무 참고자료·결과자료, 회의 첨부가 전부 여기를 가리킨다 — 문서함이 서야 그 연결이 실체가 된다.
- **v1 은 의도적으로 얇다.** 색인·버전·다중 형식을 걷어내면 남는 건 「올리고, 정리하고, 연결하고, 읽고 고친다」뿐이다. 위키의 값은 v2 에서 색인·백링크가 붙을 때 나온다.
- **폴더와 연결을 별개 축으로 둔 것**이 이 영역의 설계 판단이다 — 사람이 정리하는 축(폴더)과 관계를 잇는 축(연결)을 섞지 않는다.

## Possible Direction

확정 사항을 DEC-004 로 내린다. 디자인 정정 2건(회의 중 md 생성 → v2, v2 안내로 대체되는 UI 3종)과 미설계 화면(휴지통)은 OQ. 첨부 형식 제약(md 전용)은 DEC-002·DEC-003 에 소급 반영한다.
