# 인증·설정

자체 로그인(아이디+비밀번호)과 설정 영역 — 개인 설정(프로필·경력·목소리), **업무 설정(유형·프로젝트 관리)**, 연동 관리. 2026-09-03 사용자 논의로 범위 확정.

> 아직 결정하지 않은 날것의 입력이다. 정리보다 보존이 우선이다.

## Raw

2026-09-03 사용자 논의에서 나온 그대로:

- 소셜 로그인은 버튼만, 자체 로그인으로 구현. 아이디(메일 아님)/패스워드. 패스워드 8자(특수문자 포함) → 문자+숫자+특수문자 조합으로 확정. JWT + 쿠키 인증.
- 회원가입 없음 — "DB에 시드 넣어서 그걸로 쓸 거야". 비밀번호 찾기 없음. 세션은 access 1시간/refresh 7일. 다른 기기 로그아웃은 프론트만. 실패·잠김은 논외.
- 업무 설정은 "내가 업무를 등록하는 걸 동적으로 제어하는 것". 기본 3종(미팅·회의/개인 업무/문서·보고)을 제공하고, 유저가 외부미팅/내부미팅/팀미팅 같은 유형을 만들 수 있게. 등록 폼: 종류(미팅/업무)·설명(이름)·색(디자인 시스템 허용 색 중 선택). 영문명(slug)은 논의 끝에 제거 — 키값 자동 생성이면 필요 없다.
- 프로젝트 등록: 이름·색.
- 삭제는 소프트 딜리트 — "다른 페이지에서는 옛날 정보 그대로 띄워줄 수 있잖아, 다만 생성될 때 연결을 못할 뿐". 기본 3종은 삭제 불가.
- 계정 삭제·목소리 녹음·연동 관리는 목 UI만 — "v2에서 소셜 회원가입/회원가입/삭제 넣을 거라서 금방 만드니까 프론트 페이지만 만들어 놓을라고".

## Context

디자인 패키지(`11-auth-profile.md` + `로그인 · 계정 · 프로필.dc.html`, 화면 7종 P-04~P-13)가 입수돼 있고, docs-v1 Phase 1 의 첫 영역이다. 단, 디자인은 이메일 로그인 폼으로 그려져 있고 업무 설정(유형·프로젝트 관리) 화면은 없다 — 이번 논의가 그 공백을 정책으로 먼저 채웠다.

## Why It Matters

- **업무 설정이 이 제품의 원천 데이터다.** 업무 생성이 유형·프로젝트를 참조하므로, 설정이 먼저 서야 업무를 만들 수 있다 — 6영역 중 최우선으로 문서화하는 이유 (사용자 확정 2026-09-03).
- **계정 경계가 있어야 데이터 격리·세션이 성립한다.** 개인용 단일 사용자 도구지만 로그인은 실구현한다 — v2 에서 소셜 회원가입·회원가입·계정 삭제를 열 때 이 골격 위에 얹는다.
- **v1 은 골격, 바깥 연결은 v2.** 가입·소셜·연동·실녹음처럼 외부 인프라가 필요한 것은 화면(UI)만 만들어 두고 기능은 v2 로 민다 — "금방 만드니까 프론트 페이지만" (사용자).

## Possible Direction

Raw 의 결정들을 DEC-001(정책 8절)로 내리고, 화면이 없는 업무 설정·복구 UI 는 디자인 OQ 로 남긴다. spec 은 Phase 2 게이트(Q-28·33·34) 뒤.

## 기능명세

| # | 기능 | 설명 | v1 범위 | 근거 |
|---|---|---|---|---|
| 1 | 로그인 | 아이디(이메일 아님)+비밀번호 자체 로그인. JWT 쿠키 인증 | **실구현** | P-04 · 사용자 확정 |
| 2 | 소셜 로그인 | 「회사 계정으로 계속하기」 버튼 | UI만 (v2: 소셜 회원가입) | P-04 · 11-auth-profile §로그인 |
| 3 | 세션 | access 1h / refresh 7d. 「로그인 상태 유지」 체크 시 refresh 저장, 미체크 시 세션 쿠키 | **실구현** | 사용자 확정 |
| 4 | 로그아웃 | 설정 메뉴 하단, 확인 모달 후 실행 | **실구현** (모달 미설계 → OQ) | 11-auth-profile §설정 공통 골격 · Q-21 |
| 5 | 프로필 | 아바타·이름·이메일(표시 전용)·회사/소속/직무·업무 시간. 포커스 해제 시 자동 저장 | **실구현** | P-05 · 11-auth-profile §프로필 패널 |
| 6 | 경력 | 인라인 한 줄 추가/편집, 재직 중 체크, 현재 경력 → 프로필 값 | **실구현** | P-07 · C-41 |
| 7 | 목소리 | 샘플 녹음 드로어·상태 표시 | **UI만 목**(mock) — 실녹음·학습 v2 | P-09 · C-38 · 사용자 확정 |
| 8 | 비밀번호 변경 | 드로어. 현재/새/확인 + 강도 3조건 + 「다른 기기 모두 로그아웃」 토글(UI만) | **실구현** (토글은 UI만) | P-08 · C-42 |
| 9 | **업무 설정 — 유형 관리** | 기본 3종(미팅·회의/개인 업무/문서·보고) 시드 제공 + 사용자 정의 유형 등록(종류·이름·색) | **실구현** — 화면 미설계 → OQ | 사용자 확정 · 디자인 없음 |
| 10 | **업무 설정 — 프로젝트 관리** | 프로젝트 등록(이름·색) | **실구현** — 화면 미설계 → OQ | 사용자 확정 · Q-01~02 |
| 11 | 연동 관리 | 메일·카카오톡·슬랙·외부 캘린더 연결 | **UI만 목** — API 연동 v2 | P-06 · 사용자 확정 |
| 12 | 계정 삭제 | 메뉴 하단 + 확인 모달 | 버튼만 (v2) | 11-auth-profile §설정 공통 골격 |
| 13 | 회원가입 · 비밀번호 찾기 | **없음.** 계정은 DB 시드로 생성, 잊으면 DB 에서 리셋. 로그인 화면의 두 링크는 제거(디자인 정정) | 제외 (회원가입은 v2) | 사용자 확정 |

**v2 예약 묶음**: 소셜 회원가입 · 회원가입 · 계정 삭제 · 연동 API · 실녹음/학습 · 다른 기기 로그아웃 실동작.

> **v2 스코프 = 프론트만 구현** (전 영역 공통, 2026-09-03 확정)
> 위 항목들은 v1 에서 **UI 를 그대로 그린다** — 화면·컴포넌트를 만들되 비활성 처리하고,
> 조작하면 「v2에서 제공됩니다」 토스트. 숨기지 않는다. v2 에서는 뒤(백엔드)만 붙이면 된다.
