# 화면 계약 3페이지 — 모니터링 · 채팅 · 데이터

`app/front/`(Next.js 15 App Router) 안에 데모 라우트 그룹을 만들고 세 화면을 낸다.
이 문서는 라우트·셸·토큰 레이어·화면별 컴포넌트 계약과 **하드코딩 금지(파생 카운트)**
규약을 정한다. 시각 값(hex·px·타입 스케일)의 SoT 는 디자인 패키지이고, 이 문서는
**그것을 어느 데이터에 붙이는지**를 정한다.

> 기능/정책 묶음 단위의 **외부 계약** 문서다.
> **시각 토큰 값을 이 문서에 전사하지 않는다** — `design/01-tokens.md` 가 SoT 이고 여기서는
> 링크와 규약만 갖는다. 두 곳에 hex 를 두면 반드시 어긋난다.
> API·응답 필드의 SoT 는 [[spec-003-api-and-chat-contract|SPEC-003]],
> 답변 객체는 [[spec-005-agent-loop-and-gates|SPEC-005]] 다.

### Business Requirement

- **결과만 보여주는 대시보드가 아니다.** 어느 계층이든 브론즈 원본까지 내려가는 경로가
  화면에 항상 열려 있다(디자인 `08` 규칙 3 = SPEC-001 AC-9).
- **표기와 실제가 어긋나지 않는다.** 카운트·배지·범례 숫자를 하드코딩하지 않고 전부 API
  응답에서 파생시킨다(디자인 `08` 규칙 7).
- **PII 원값이 화면 어디에도 없다.** 언마스킹 UI·권한 UI를 만들지 않는다.
- **「실시간」을 표방하지 않는다.** 기준일 배지를 전 화면에 두고 라이브 인디케이터를 만들지
  않는다(DEC-005 D4).
- 포트폴리오 사이트를 깨지 않는다 — 기존 `globals.css`·`/chat`·루트 레이아웃 불변.

### Scope

In scope:

- 라우트·셸·토큰 레이어·폰트·최소 폭 처리·접속 게이트 화면
- 세 화면의 컴포넌트 계약과 상태, 파생 카운트의 출처 필드
- `node_id`·`edge_id` 규약과 좌표 자산 키잉, 페이지 간 URL 직렬화
- 답변 6블록 ↔ 답변 객체 필드 매핑, 메시지 상태 5종의 화면 요구

Out of scope:

- 시각 토큰 값 자체(디자인 `01-tokens.md` 가 SoT)
- API 응답 필드 정의(→ SPEC-003) · 답변 객체(→ SPEC-005) · 테이블·enum(→ SPEC-001)
- 시각 상세의 문장·배치 자체(디자인 몫) — 정정 이력은 §7.2
- 반응형(데스크톱 전용) · 다국어(한국어 전용)

### U-1. 데모 셸 · 전역 헤더

- **상태**: 3화면 공통. 탭 순서 **모니터링 · 채팅 · 데이터** 고정, 현재 탭 활성 표시.
  포트폴리오 `TopNav`·`PageFooter` 는 이 그룹에 **주입되지 않는다**.
- **문구**: 로고 `Ontology`. 탭 라벨 3종. 기준일 배지 `<as_of> 기준`.
- **파생**: 모니터링 탭의 카운트 배지 = **알림 상태 KPI 수**(관찰은 배지 없음).
  기준일 배지 = `/api/kpi/cards.as_of` 파생 — **하드코딩 금지**.
- **기대 결과**: 탭 클릭 시 해당 라우트로 이동. 세 화면이 같은 셸을 공유한다.

### U-2. 접속 게이트 화면

- **상태**: 세션이 없으면 세 라우트 어디로 들어와도 게이트만 보인다(셸 없음 또는 최소 셸).
  입력 1칸 · 제출 · 에러.
- **문구**: SPEC-003 U-1 의 문구를 그대로 쓴다 — 안내 「내부 공유용 데모입니다. 공유받은
  비밀번호를 입력해 주세요.」 · 실패 「비밀번호가 올바르지 않습니다.」
- **CTA**: Enter 또는 「들어가기」. 빈 입력이면 no-op.
- **기대 결과**: 성공 시 원래 가려던 라우트로 복귀(기본 `/ontology/monitoring`).
  세션이 있으면 게이트가 나타나지 않는다.
- **금지**: 시도 횟수 표시·잠금·계정 안내(rate limit 없음 — DEC-005 D2).

### U-3. 최소 폭 안내

- **상태**: 데모 컨테이너 폭이 **1280px 미만**이면 화면 대신 안내를 띄운다.
- **규약**: `min-width` 는 **데모 컨테이너에만 스코프**한다. 루트(`html`/`body`)에 걸지
  않는다 — 포트폴리오와 공유하는 표면이고 `globals.css` 에 이미 반응형이 있다.
- **문구**: 데스크톱 전용임을 알리는 한 문장(디자인 정정본 반영 — §7.2 D-16).

### U-4. 모니터링 — 타이틀 · KPI 카드

- **상태**: 세로 흐름 한 화면(타이틀 → KPI 카드 행 → 그래프 + 우측 컬럼). 탭으로 쪼개지
  않는다.
- **정렬**: KPI 카드는 **알림 → 관찰 → 정상** 순, 알림이 항상 맨 왼쪽.
- **필드 계약**(`/api/kpi/cards`): 카드 1장이 요구하는 값 —
  `label` · `latest` · `status` · `dod` · `dod_pct` · `unit` · `grain` · `spark[7]` ·
  `alert_days` · `node_state` · `thresholds` · `direction`.
- **`grain` 이 카드마다 다르다.** 일별 카드 행에 주별 지표(유기 신호)가 섞이므로 카드가
  자기 `grain` 을 싣고, 화면은 그 값으로 캡션을 만든다(「(주간)」 등) — 하드코딩 금지.
- **미관측 카드**: 값 `—`, 스파크라인 없음, 점선 테두리.
- **「그 외 KPI」 카드**: 카드로 낸 지표를 제외한 나머지의 **상태별 내역을 파생**시킨다.
  「나머지 전부 정상」이라고 단정하지 않는다 — 관찰이 섞여 있으면 그대로 드러낸다.
- **기간 스테퍼**: `/api/kpi/cards` 의 기간 파라미터에 물린다. 다음 기간이 없으면 비활성.
- **기대 결과**: 카드 클릭 시 해당 노드가 그래프에서 선택 상태가 된다(구현 재량 —
  §7 OQ).

### U-5. 모니터링 — 원인 분석 그래프

- **상태**: 정상(그래프) · 로딩 · 에러. SVG 고정 좌표 렌더.
- **인코딩**(디자인 `03-graph-encoding.md` 가 SoT): **색 = 상태 · 모양 = 노드 타입 ·
  선 스타일 = 엣지 판정 · 선 굵기 = 신뢰도**. 두 축을 색으로 겹치지 않는다.
- **판정 라벨 표기**(이 문서가 SoT — 디자인과 API 가 다른 말을 쓴다):

  **엣지 판정** — API 값이 곧 정본 한글값이라 **번역이 없다**(2026-09-02 정정. 이전 판의
  `산출0`·`외생` 은 spec 이 만든 표기였고 폐기됐다).

  | `verdict`(정본 = API = 화면) | 선 | 인과 서술 |
  |---|---|---|
  | `채택` | 실선 | ✅ |
  | `자동 확정` | 실선(Primary) | ✅ |
  | `선언` | 파선 | ✅ |
  | `보류` | 점선 | ✖ |
  | `기각` | 흐린 점선 + × | ✖ (배제 근거로만) |

  **노드 타입** — 여기는 번역이 있다. API 는 영문 enum 이고 화면은 한글 카피를 쓴다.

  | `node_type`(API) | 화면 카피 |
  |---|---|
  | `kpi` | KPI |
  | `intervention` | 개입 |
  | `organic` | 유기 |
  | `exogenous` | 외생 |
  | `unobserved` | 미관측 |
  | `attribute` | 속성 |

  화면이 `node_type` 영문 값을 그대로 노출하지 않는다.
- **툴바**: [판정 전체] [채택만] [☐ 기각] [☑ 미관측].
- **데이터 획득**: 최초 **1회** `/api/graph?verdicts=<5종 전체>` 로 받고, 토글은
  **클라이언트 필터**로 처리한다. 토글마다 재요청하지 않는다.
- **파생 카운트**: 헤더 `노드 {표시}/{전체} · 엣지 {표시}/{전체}` 와 범례의 판정별 개수는
  응답의 `counts` 와 현재 필터에서 파생한다 — **하드코딩 금지**.
- **선택**: 엣지 클릭 → 인스펙터 대상 갱신 + 양 끝 노드 강조. hover → 방향 배지.

### U-6. 모니터링 — 엣지 인스펙터

- **필드 계약**(`/api/graph` edges): `from` · `to` · `verdict` · `sign` · `lag` ·
  `confidence` · **`kind`** · **`note`**(사람이 읽는 설명) · `evidence`(근거 수식) ·
  `reason`(기각·보류 사유) · `edge_id`.
- **문구**: 근거는 한 줄, 설명은 두 줄 이내(우측 컬럼이 고정 높이 안에서 분배된다).
- **CTA 2종**:
  - 「원본 데이터 보기」 → `/ontology/data?tier=…&table=…` — 목적지는 **엣지 양 끝 노드의
    `source`**(`/api/graph` 노드 필드)에서 파생한다. 매핑을 화면에 손으로 두지 않는다.
  - 「이 엣지로 질문하기」 → `/ontology/chat?q=…` — 프리필 문구는 FE 조합(구현 재량).
- **하단 노트**: 기각 엣지가 남아 있다는 사실을 알린다(디자인 `08` 규칙 5).

### U-7. 모니터링 — 예보 카드

- **필드 계약**(`/api/forecast`): `title` · `message` · `rule` · `edge`(+`edge.evidence`) ·
  `trigger` · `target` · `horizon` · `risk` · `note`.
- **제목·본문은 서버가 준다.** 근거 추적 앱이라 카피를 FE 에 흩지 않는다.
- **수치·신뢰도·lag 를 화면에 하드코딩하지 않는다** — 전부 응답값이다.
- **`risk` ↔ 카드 색**: `알림` → 알림 계열, `관찰` → 관찰 계열(디자인 `02` 예보 카드).
- **신뢰도가 낮은 엣지는 그 사실을 함께 표시한다**(SPEC-003 AC-7).

### U-8. 채팅 — 빈 상태

- **상태**: 히어로(아바타 · 제목 · 설명) + 시작 카드 4장 + 입력.
- **파생 규칙**(무엇이 데이터이고 무엇이 정적 카피인지 — 이 문서가 확정):
  - **데이터 파생**: 카드의 dot 색 · 상태 라벨(「알림 · <지표명>」)은 `/api/kpi/cards` 의
    알림 상태 KPI 에서 만든다.
  - **정적 카피**: 카드의 **질문 문구**와 **메타 줄**은 예측 불가능한 값이므로 정적으로 둔다.
  - 알림 KPI 가 4장에 못 미치면 정적 카드로 채운다(3·4번 카드는 애초에 알림 파생이 아니다).
- **고지**: 입력 아래에 마스킹·일 1회 배치 고지를 둔다(문구는 디자인 `05`).

### U-9. 채팅 — 메시지 상태 5종

디자인에 없는 상태다(리포트 §2.2). **API 계약이 요구하므로 화면이 반드시 가진다.**

| # | 상태 | 화면 요구 |
|---|---|---|
| 1 | `pending` | assistant 버블에 **부분 텍스트**(`content`)와 **도구 단계 리스트**(`steps`)가 자란다. **2초 폴링**. 스피너만 두지 않는다 — 무엇을 하고 있는지가 보여야 한다 |
| 2 | `done` | 답변 6블록(U-10) 렌더 |
| 3 | `failed` | 실패 문구 + **「다시 시도」** 버튼 → retry 엔드포인트 |
| 4 | `AI_TIMEOUT` | 180초 초과. `failed` 와 같은 버블이되 문구로 구분 |
| 5 | `CONVERSATION_BUSY` | `pending` 이 있는 동안 **컴포저 잠금**(FE 선차단). 409 를 사용자에게 노출하지 않는다 |

- 폴링은 `done`/`failed` 로 바뀌면 중단한다.
- 시각 설계(버블 형태·단계 리스트 표현·문구)는 디자인 정정본을 따른다(§7.2 D-12) —
  이 문서는 상태와 데이터 요구만 고정한다.

### U-10. 채팅 — 답변 6블록 ↔ 답변 객체 매핑

블록 순서는 고정이다. 각 블록의 출처는 [[spec-005-agent-loop-and-gates|SPEC-005]] §4 다.

| # | 블록 | 출처 필드 | 없을 때 |
|---|---|---|---|
| 1 | 상태 배지 | `premise_correction.corrected` · `unknowns[]` | 배지 없음 |
| 2 | 본문 | `answer` | — (필수) |
| 3 | 근거 블록 | `citations[]` — `metric`·`grain`·`period`·`source{tool,table,column}`·**`row_count`** | 블록 생략 |
| 4 | `used_edges` 칩 | `used_edges[]`(+`edge_id`) | 빈 배열이면 「이 답변은 엣지를 밟지 않았습니다」 문구 |
| 5 | 드릴다운 표 | **`drilldown{table,view,columns,rows,masked_fields,total}`** | 블록 생략 |
| 6 | 후속 질문 칩 | **`followups[]`** | 블록 생략 |

- 드릴다운 표는 **최대 5행** 표시 + 「전체 보기」. `total` 이 5를 넘으면 **「5 / N」을 밝힌다**
  — 소리 없는 절단 금지.
- 「전체 보기」 → `/ontology/data?tier=bronze&table=…&filters=…`(§4 직렬화 규약).
- 드릴다운 행은 **마스킹 표기**로만 나온다(SPEC-001 §4).

### U-11. 채팅 — `used_edges` 칩과 하이라이트

**2026-09-02 사용자 확정 — 우측 520px 근거 그래프 패널은 두지 않는다.**
디자인 `05` §근거 그래프 패널 · `07` §used_edges 하이라이트의 ②(패널 점등)는 폐기하고,
칩 + 점프로 일원화한다. 리포트 C-4 의 A안(동적 유도 부분그래프)·B안(패널을 게이트 대상에서
제외) 모두 채택하지 않는다 — **패널 자체가 없다.**

- **표시**: 답변 안 칩 목록 하나뿐. 칩은 판정 인코딩(선 스타일·색)을 배지로 그대로 쓴다.
  칩 문구는 `from → to`.
- **동작**: 칩 클릭 → `/ontology/monitoring?edge=<edge_id>` 로 이동해 **모니터링 그래프에서
  해당 엣지가 선택·하이라이트된 상태**로 진입한다.
- **게이트 5-③ 의 검증 대상 화면 = 모니터링 그래프 단일**이다
  ([[spec-005-agent-loop-and-gates|SPEC-005]] OQ-4 를 이 항목이 닫는다).
  채팅에는 하이라이트 대상 그래프가 없으므로 집합 비교가 성립할 화면이 하나로 좁혀진다.
- 채팅 스레드는 `max-width` 중앙 정렬 단일 컬럼이 된다(패널 제거로 폭이 회수된다 —
  구체 레이아웃은 디자인 정정본 — §7.2 D-17).

### U-12. 채팅 — 컴포저

- **검증**: trim 후 1자 이상 **1,000자 이하**. 초과 시 컴포저 아래 문구
  「질문은 1,000자까지 입력할 수 있습니다」(SPEC-003 Case Matrix).
- **잠금**: 같은 대화에 `pending` 이 있으면 전송 잠금(U-9 #5).
- **프리필**: `/ontology/chat?q=…` 로 들어오면 입력에 채워 둔다. 기존 포트폴리오 `/chat`
  이 이미 `?q=` 를 쓰므로 같은 패턴을 따른다.
- 빈 입력은 no-op(에러를 띄우지 않는다).

### U-13. 데이터 — 계층 탭과 테이블 칩

- **계층**: 브론즈 · 실버 · 골드 **3계층만** 다룬다.
  **온톨로지 계층(`ontology_nodes`·`ontology_edges`)은 데이터 화면에서 명시적으로
  제외**한다 — 모니터링 그래프가 이미 그 계층의 표면이다.
- **브론즈 표시 구조**: 원천 축 3(vegas · 리뷰 · nexus)을 1단 칩으로 두고, **nexus 를
  고르면 하위 14테이블이 2단 칩으로 열린다**. 합성 테이블을 만들지 않는다 — 칩은 전부
  `/api/layers/bronze/tables` 응답의 실제 테이블에 1:1 대응한다.
- **골드 칩은 5개다** — `gold_kpi_daily` · `gold_kpi_weekly` · **`gold_kpi_monthly`** ·
  `gold_promo_calendar` · `gold_retention_monthly`. 월 View 가 정본에 들어오면서 4 → 5 가
  됐다(SPEC-001 §4). 칩 목록은 **테이블 목록 응답에서 파생**하므로 정본이 늘면 칩도 는다.
- **파생 카운트**: 계층 탭의 테이블 수는 `/api/layers/{layer}/tables` 에서 파생한다
  (브론즈 **16** · 실버 **6** · 골드 **5**). 하드코딩 금지.
- **상태 키**: 선택 테이블은 인덱스가 아니라 **테이블 이름**으로 식별한다 — 목록 순서가
  바뀌면 인덱스는 조용히 어긋난다.

### U-14. 데이터 — 표와 마스킹

- **헤더**: `1–N / total` 을 항상 표시한다(`total`·`returned`·`offset` 파생).
- **마스킹 바**(PII 테이블): 마스킹 컬럼 수와 이름을 **`masked_fields` 에서 파생**해 문구를
  만든다. 「언마스킹 기능은 제공하지 않습니다」를 함께 둔다.
- **중립 바**(PII 없는 테이블): 「실명·전화·생년월일은 이 계층으로 올라오지 않습니다」 계열로
  둔다. **「환자 식별 정보는 이 계층까지 올라오지 않습니다」는 쓸 수 없다** —
  `chart_no` 는 그대로 반입·노출되므로 자기 표와 모순된다(SPEC-001 §4).
  최종 카피는 디자인 정정본을 따른다(§7.2 D-2).
- **언마스킹 UI·권한 UI 를 만들지 않는다**(DEC-002 · 디자인 `08` 규칙 1).
- **컬럼 부분 표시**: 전 컬럼을 보여주지 않을 때 「N개 컬럼 중 M개 표시」를 밝힌다.

### U-15. 데이터 — 컬럼 상세와 계층 역추적

- **컬럼 상세 필드**(`/api/layers/{layer}/{table}/lineage`):
  브론즈·실버 → 원본 값 / 실버 규칙(**`rule_id`** G-0xx) / 쓰이는 곳(**`downstream`**),
  골드 → 계산식(`formula`) / **`gate`** / 쓰이는 곳.
  미확정 값은 **`is_provisional`** 로 표시한다 — `—` + 「미확정」, 0 으로 채우지 않는다.
- **「이 원본이 가는 곳」 / 「이 테이블이 이어지는 곳」**: `/api/layers/{layer}/tables` 의
  **`flows_to[]`** 에서 만든다. 각 항목 클릭 → 해당 계층·테이블로 점프
  (`?tier=…&table=…`).
- **골드 → 실버 → 브론즈 역추적 경로가 항상 있어야 한다**(디자인 `08` 규칙 3 =
  SPEC-001 AC-9).
- 각 계층에 근거 기록 링크를 단다 — 브론즈 → 기록 02 · 실버 → 04 · 골드 → 05 ·
  그래프 → 07(`note_ref` 파생).

## 3. User Scenario

### S-1. 방문자 — 첫 진입

1. 공유 링크로 들어온다. 세션이 없어 접속 게이트(U-2)가 뜬다.
2. 비밀번호를 넣으면 기본 진입 화면 `/ontology/monitoring` 으로 간다.
3. 헤더 탭으로 세 화면을 오간다. 기준일 배지가 어느 화면에도 있다.

### S-2. 방문자 — 알림에서 원인으로

1. 모니터링 KPI 카드 행 맨 왼쪽에 알림 지표가 있다(정렬 규칙 U-4).
2. 아래 그래프에서 그 노드에 닿는 엣지를 클릭한다 → 인스펙터에 판정·근거·설명이 뜬다.
3. 「원본 데이터 보기」 → 데이터 화면의 해당 테이블로 이동한다.

### S-3. 방문자 — 기각을 확인

1. 그래프 툴바의 [☐ 기각] 을 켠다.
2. 기각 엣지가 × 표시와 함께 나타나고 헤더·범례 카운트가 함께 변한다(재요청 없음).
3. 인스펙터에 기각 사유가 뜬다 — 「따져봤고 아니었다」는 기록이 남아 있다.

### S-4. 방문자 — 채팅에서 그래프로

1. 채팅에서 질문한다. `pending` 동안 부분 텍스트와 도구 단계가 자란다(U-9).
2. `done` 이 되면 답변 6블록이 뜬다(U-10).
3. `used_edges` 칩을 클릭한다 → `/ontology/monitoring?edge=<edge_id>` 로 이동해 그 엣지가
   선택된 상태로 전체 그래프를 본다(U-11).

### S-5. 방문자 — 드릴다운

1. 답변의 드릴다운 표에서 마스킹된 브론즈 행 5개를 본다. 「5 / N」이 함께 보인다.
2. 「전체 보기」 → 데이터 화면의 브론즈 테이블로 필터가 적용된 채 이동한다.
3. 화면 어디에도 실명·전화·생년월일 원값이 없다.

### S-6. 경계 — 폭이 좁을 때

1. 창을 1280px 미만으로 줄이면 최소 폭 안내가 뜬다(U-3).
2. 포트폴리오 페이지는 영향받지 않는다 — `min-width` 가 데모 컨테이너에만 걸려 있다.

### S-7. 경계 — 답변 실패

1. 180초를 넘기면 메시지가 `failed` 가 되고 「다시 시도」가 뜬다.
2. 재시도는 재제출이다 — 새 줄을 만들지 않고 같은 메시지를 되살린다(SPEC-003).

## 4. Interface Contract

### API Contract

이 화면들이 부르는 엔드포인트는 [[spec-003-api-and-chat-contract|SPEC-003]] §4 가 SoT 다.
화면↔엔드포인트 매핑도 그 문서의 표를 따른다. 여기서는 **화면이 요구해서 SPEC-003 이 갖게
된 필드**만 다시 적는다(중복 정의가 아니라 요구의 출처 표기):

| 엔드포인트 | 화면이 요구한 필드 | 요구 위치 |
|---|---|---|
| `/api/kpi/cards` | `dod` · `dod_pct` · `unit` · `grain` · `spark[7]` · 기간 파라미터 | U-4 |
| `/api/graph` | 엣지 `kind` · `note` · `edge_id`, 노드 `source` | U-5 · U-6 |
| `/api/forecast` | `title` · `message` · `edge.evidence` | U-7 |
| `/api/layers/{layer}/{table}/lineage` | `rule_id` · `gate` · `downstream` · `is_provisional` | U-15 |
| `/api/layers/{layer}/tables` | `flows_to[]` | U-15 |
| 답변 객체 | `drilldown` · `followups[]` · `citations[].row_count` · `used_edges[].edge_id` | U-10 |

### 라우트와 URL 직렬화

| 경로 | 화면 | 비고 |
|---|---|---|
| `/ontology/monitoring` | 모니터링 | **기본 진입** |
| `/ontology/chat` | 채팅 | |
| `/ontology/data` | 데이터 | |

- 라우트 그룹은 `app/(ontology)/` 이고 URL 접두는 `/ontology/` 다.
  **기존 `/chat`(포트폴리오 채용담당자 채팅)은 건드리지 않는다.**
- 페이지 간 상태 공유는 **URL 쿼리와 세션 쿠키뿐**이다. 전역 스토어를 두지 않는다.

| 파라미터 | 쓰는 곳 | 형식 |
|---|---|---|
| `?edge=<edge_id>` | 채팅 칩 → 모니터링 인스펙터 선택 | 안정 `edge_id` 1개 |
| `?tier=<bronze\|silver\|gold>&table=<table_name>` | 인스펙터·드릴다운 → 데이터 | 테이블은 **이름**(인덱스 아님) |
| `&filters=<직렬화>` | 드릴다운 → 데이터(필터 적용) | `/api/layers` 의 `filters` 와 같은 구조 |
| `?q=<질문>` | 인스펙터·데이터 → 채팅 프리필 | 기존 `/chat?q=` 와 같은 패턴 |

`used_edges` 를 페이지 간에 들고 다니지 않는다 — 모니터링은 `edge_id` 하나만 받는다.

### `node_id` · `edge_id` 규약과 좌표 자산

- **`node_id` 는 snake_case** 이고, 확정 목록은 [[spec-001-data-layer-contract|SPEC-001]] §4
  의 25종 표가 SoT 다. 화면·API·URL 이 같은 id 를 쓴다.
- 그래프 좌표는 FE 정적 자산이다(`viewBox 0 0 1130 560`, 5열 레이어 배치).
  **좌표 자산은 확정 `node_id` 로 키잉한다** — 디자인 `nodes.json` 의 camelCase id 를
  그대로 쓰지 않는다. 매핑 표를 화면 코드에 손으로 두면 노드 하나가 조용히 사라진다.
- 좌표 자산은 **25행 전건**을 가져야 한다. `/api/graph` 가 준 노드 중 좌표가 없는 것이
  1건이라도 있으면 **렌더 실패로 드러낸다**(조용히 빼지 않는다).
- **`edge_id` 규약은 `<from>__<to>`** 다(밑줄 2개). 예: `cancel_rate__reservations` ·
  `payment_visits__sales_total`. `/api/graph` · `used_edges[]` · URL `?edge=` 가 같은 값을
  쓴다(SPEC-003 · SPEC-005). `(from, to)` 쌍이 유일하므로 파생 가능한 값이지만, URL 에
  싣기 위해 **응답이 문자열로 실어 준다** — 화면이 조립하지 않는다.

### 토큰 레이어 계약

디자인은 **단일 라이트 테마**이고 기존 `globals.css` 는 **dark-first 단일 테마**다.
겹치는 지점이 없어 기존 토큰으로 환원할 수 없다. 따라서:

1. **`app/front/app/globals.css` 를 수정하지 않는다.** 포트폴리오 전 페이지가 그 위에 선다.
2. 데모 셸(`app/(ontology)/layout.tsx`)의 **컨테이너 스코프**에 신규 토큰을 선언한다 —
   `[data-surface="ontology"] { --ont-*: … }`. 접두어 `--ont-` 로 전역 토큰과 이름 충돌을
   막는다.
3. 그 컨테이너에 **`color-scheme: light` 를 재선언**한다. 전역이 `dark` 라 재선언하지 않으면
   네이티브 위젯(스크롤바·폼 컨트롤)이 다크로 샌다.
4. **환원 가능한 것은 환원한다** — Mono 폰트(`--font-mono`, 디자인 요구와 같은 서체) ·
   전환 시간 120ms · 간격 스케일 대부분.
5. **신규 토큰의 값 목록은 `design/01-tokens.md` 가 SoT 다.** 이 문서에 hex 를 전사하지
   않는다. 필요한 계열은 텍스트·서피스/보더·Primary 3종·상태 4종×3값·계층 배지 3종×4값·
   보조색·그라디언트 2종·라이트용 섀도 4종·타입 스케일이다.

- **Pretendard 를 도입한다**(2026-09-02 사용자 확정). Sans 는 데모 라우트 그룹에서

- **도입 경로는 `next/font`** 다. 디자인 `01-tokens.md` 가 적은 **jsDelivr CDN `@import` 는

| 마스킹 바의 컬럼 수·이름 | 같은 응답의 `masked_fields` |
| 드릴다운 「5 / N」 | 답변 객체 `drilldown.total` |
| 예보 카드의 제목·본문·근거 수치 | `/api/forecast` |
| 인스펙터의 판정·신뢰도·lag·근거 | `/api/graph` edges |

### 프로토타입 의존 금지

`design/*.dc.html` 과 `support.js`(`x-dc` 커스텀 엘리먼트 + `{{ }}` 템플릿 런타임)는
**레이아웃·값·동작을 읽기 위한 참조물**이다. 산출 코드의 런타임 의존이 아니며,
`data-dc-script` 블록을 옮겨 심지 않는다. 새 CSS 프레임워크를 도입하지 않는다 —
인라인 style + 토큰 `var()` 라는 기존 관례를 따른다.

### State / Lifecycle

화면 상태는 전부 클라이언트 상태 + URL 파라미터다. 서버가 소유하는 상태 전이는
메시지(`pending → done/failed`)뿐이고 그 정의는 SPEC-003 이 갖는다.

```text
모니터링   filter(전체|채택만) · showRejected · showUnobserved · selectedEdge · hoverEdge · period
채팅       draft · conversationId · messages(서버) · hoverChip
데이터     tier · tableName · selectedRow · period · filters
```

### Data Contract

- 화면이 만드는 도메인 값은 없다. 전부 SPEC-001/003/005 의 값을 표시할 뿐이다.
- 화면 카피로 쓰는 판정 라벨만 이 문서가 소유한다(U-5 매핑표).

## 5. Implementation Rules

- **`globals.css` 불변.** 데모 토큰은 컨테이너 스코프에만 선언한다.
- **`min-width` 는 데모 컨테이너에만.** 루트에 걸지 않는다.
- **카운트·수치·판정 라벨을 하드코딩하지 않는다.** 전부 응답 파생이다(§4 표).
- **소리 없는 절단 금지.** 부분 표시(드릴다운 5행·컬럼 부분 표시·필터된 그래프)는 항상
  전체 대비 몇 개인지 밝힌다.
- **언마스킹 경로를 만들지 않는다.** 마스킹 해제 토글·권한 UI·원값 툴팁 전부 금지.
- **「실시간」·「지금」·「live」 카피를 만들지 않는다.** 자동 갱신·라이브 인디케이터 없음.
- **기존 포트폴리오 표면을 건드리지 않는다** — `/chat`, 루트 `layout.tsx`, `TopNav`,
  `PageFooter`, `globals.css`.
- 데스크톱 전용·한국어 전용이다.
