# 작업 요약 — cc-procedure-map (cc-prototype)

기간: `2026-11-12` ~ `2026-11-17`
결과: 맵 1루프 완료 — `reference/2026-11-12-open-pencil/medikit/medikit.fig` 「시술현황 맵」(화면 56 · 연결 79 · 메모 173) · 사용자 화면 확인까지. 2루프(피드백 반영)는 열지 않고 마감 · 배포 대상 아님

## 1. 무엇을 했나

cc 기획안 「시술현황」(738줄)을 한 캔버스에서 「[화면] ─버튼→ [화면] + 그 옆 정책 · 기획 메모」 로 보는 프로덕트 맵이 필요했다. 오픈소스 디자인 편집기 OpenPencil 0.16.0(데스크톱 앱 + bun 전역 CLI · MCP)을 깔고, 메디킷(primary = CRM blue `#1d8bff`) 토큰을 변수 컬렉션으로 옮겼다.
사용자가 준 시안 HTML(3차 v11)을 디자인 정본으로 컴포넌트 26 세트(변형 120)를 만들고, 맵은 데이터(`screens` 56 · `edges` 79 · `notes` 173 JSON + `layout.json`)를 원본으로 두고 렌더러가 캔버스에 그리는 구조로 세웠다(5053 노드 · 두 번 돌려 같은 수).
일은 코디 → pencil 리드 → 섹션별 서브에이전트로 나눴다. 리드 혼자 headless 로 직렬 렌더했다. 산출물은 전부 `reference/2026-11-12-open-pencil/` 에 있다.

## 2. 적용한 기술·개념

- **화면 흐름 맵을 데이터 원본 + 렌더 결과로 — 캔버스는 손으로 고치지 않는다**
  - 왜 이걸 골랐나: 화면 56 · 연결 79 · 메모 173 을 캔버스에 직접 그리면 고칠 때마다 손으로 옮겨야 하고, 「이 정책은 기획안 어디서 왔나」 를 캔버스로는 검사할 수 없다. 노드 이름 규약(`screen/<id>` · `edge/<from>→<to>` · `note/<id>` · `marker/<screen>/<no>`)과 JSON 을 두니 고아 연결 0 · 출처 줄 없는 메모 0 · 원문과 다른 인용 0 을 기계로 셌다. 재실행 멱등(5053 = 5053)이라 섹션별 서브에이전트가 각자 파일을 만들고 리드가 합칠 수 있었다
  - 무엇이 어려웠나: 배치는 `gen-layout.py` 의 섹션 격자라 섹션을 넘는 연결이 긴 화살표로 얽혔다(1루프 남음). 캔버스를 직접 고친 사람(공유 방 등)의 수정은 다음 렌더에 덮인다 — 의견은 말로 받아 데이터에 넣는다
  - 근거: `cc-procedure-map/{screens,edges,notes,layout}.json` · `_maplib.js` · `run-map.sh` · `pencil-map-report.md`
  - 개념: [[screen-flow-map]] · [[artifact-traceability]]
- **「와이어프레임」 이라는 말이 디자인 입힌 화면을 뜻했다 — 회색 뼈대가 아니라 시안 수준의 흐름 맵**
  - 왜 이걸 골랐나: 사용자가 「전체 와이어 프레임으로」 라고 해서 회색 와이어 맵부터 발주했다. 그런데 사용자 뜻은 「와이어 프레임인데 디자인 다 먹인거야」 였다. 정정이 다섯 번 쌓여 앞 워커를 끝내고 새 브리프로 다시 발주했다(「디자인 된 화면이 필요하다고 제발좀」)
  - 무엇이 어려웠나: 「컴포넌트 라이브러리는 선택」(정정 2)을 「컴포넌트까지 넣는다」(정정 3)로 뒤집는 식으로 결정이 왔다 갔다 했다. 용어의 뜻을 처음 물을 때 결과물 그림 하나로 확인했어야 했다
  - 근거: `pencil-correction-1..5.md` · `cc-procedure-map-pencil-wire.OLD-brief.md` · `_RESUME.md` §2
  - 개념: [[wireframe]]
- **키트 토큰을 편집기 변수로 옮기고, 시안 값이 린트와 부딪히면 값이 아니라 규칙을 끈다**
  - 왜 이걸 골랐나: 0.16.0 에는 공식 문서(개발판)의 `figma.variables` · 텍스트 스타일 · 효과 스타일이 없었다. 그래서 색은 `createVariableCollection` · `createVariable` · `bindVariable` 로, 타이포 28 · 그림자 3 은 컴포넌트로 옮겼다. 시안은 키트에 없는 상태색(`status/*` 28 · `crm/*` 7)을 써서 변수가 29 → 64 로 늘었다. 린트(대비 · 최소 글자 · 터치 영역)가 시안 값과 부딪혔지만 색을 바꾸면 시안 정본이 깨지므로, 사용자 승인으로 그 세 규칙만 껐다(앱 설정 `designCheck.disabledRules` — 이 PC 에만)
  - 무엇이 어려웠나: 재실행 때 컬렉션을 지우면 컴포넌트의 바인딩이 끊긴다. 그래서 「페이지만 다시, 변수는 이름이 같으면 값만 맞춤」 으로 바꿨다
  - 근거: `medikit/import-medikit.js` 8 · 58–69줄 · `_vars.js` · `pencil-components-report.md`
  - 개념: [[design-token]]
- **컴포넌트는 키트 목록이 아니라 시안에서 필요한 것만 — 화면은 인스턴스로**
  - 왜 이걸 골랐나: 메디킷 컴포넌트 40종을 다 들이는 대신, researcher 가 시안과 기획안에서 세운 목록(26 세트)만 만들었다. 화면은 그 인스턴스로 짜서 시안 수정이 세트 한 곳에 모인다. 세트에 없는 레일 아이콘 · 꺾쇠는 글자로 대신했고, `secondary` · `surface-board` 변수가 없어 가까운 값으로 그렸다(2루프 후보)
  - 무엇이 어려웠나: 「기존 시술현황 페이지는 절대 참고 금지」 와 「사용자가 준 시안은 정본」 이 함께 있었다. 첫 조사 브리프에 금지 대상(DAY 보드 템플릿)을 참고 목록으로 적었다가 정정 1 로 막았다. 워커가 열지 않았음을 확인했다
  - 근거: `research-components.md` · `research-correction-1.md` · `components/*.js` · `pencil-map-report.md`(분리 45 · `custom/` 64)
  - 개념: [[design-system]]

## 3. 막혔던 것 / 사고

- **공식 문서와 설치판 API 가 달랐다** → `figma.variables` undefined → 0.16.0 의 `figma.*` 직접 함수를 탐색해 옮겼다. CLI 는 node 20 에 `fs/promises.glob` 이 없어 `bun ~/.bun/bin/openpencil` 로 돌렸다. 문서가 개발판 기준이면 설치판 버전부터 맞춰 본다(`pencil/tools.md` 에 남김)
- **앱 모드 eval 이 앱을 망가뜨렸다(3회)** → 병렬 eval · 한 세션 생성/삭제 반복에 WASM 「Out of bounds memory access」, 20초 넘는 eval 은 CLI 타임아웃 → 앱을 닫고 headless(`eval <file.fig> -w --stdin`)를 리드 혼자 직렬로 돌림. 사용자는 결과를 앱에서 연다. headless PNG 는 Pretendard 를 Inter 로 바꾸므로 배치 확인용으로만 쓴다
- **자동화가 잡은 문서 ≠ 사용자 화면의 탭** → 사용자 「안 열리는데?」 → 사용자가 UI 에서 파일을 열어야 같은 문서가 된다. 이 확인 중 데스크톱 전체 스크린샷을 찍어 개인 창이 담겼고, 바로 지우고 사과했다. 화면 확인은 사용자에게 묻는다
- **결정 번복 다섯 번 · 워커 교체** → §2 「와이어프레임」 항목. 정정을 한 워커에 누적시키지 말고, 방향이 바뀌면 새 브리프로 끊는다
- **기획안과 시안 결정이 세 곳에서 달랐다(U2 지정 호출 「모든 의사」 · U8 귀가 대기 카드 위치 · U12 확인 필요 기준)** → 브리프는 시안 결정 우선이었는데 워커는 기획안을 따랐다. 맵의 목적(기획 시각화)상 기획안 쪽이 맞다고 보고 남겼다. 사용자 판단은 받지 못했다(§7)
- **실시간 공유가 안 붙었다** → 사용자가 앱에서 방 링크(`app.openpencil.dev/share/<room>`)를 보냈는데 상대 브라우저가 「Waiting for someone who has this file」 → 웹(최신 개발판)과 데스크톱 0.16.0 의 버전 차이 또는 P2P 망 차단으로 판단. 같은 PC 브라우저로 갈라 보는 방법만 안내하고 결과는 받지 못했다(§7)
