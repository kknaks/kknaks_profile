# 작업 요약 — api-swagger-docs (cc-prototype)

기간: `2026-11-11` ~ `2026-11-12`
결과: 세 번 머지 · 배포 완료 — Swagger(코드 #21 · infra #48) → 외부 연동 API 1차(#22 · #49) → 2차(#23 · #50) · 운영 실호출 확인

## 1. 무엇을 했나

협업자(링키 · 차티)가 우리 back 을 부르려면 호출 주소 · 인증 · API 설명이 필요하다고 했다. 그때까지는 admin 계정을 공유해 직원 API 를 쓰는 구조였다.
먼저 back 전체에 Swagger(`/api/docs`)를 달았다. 70개 operation 의 필드 683개에 설명을 붙였고, 동작은 바꾸지 않았다.
이어서 협업자 니즈(상품 가격 · 기존 고객의 남은 시술권 · 이름 + 이메일로 조회 · 예약)를 조사 4건으로 확인했다. 그 결과를 DEC-010 으로 닫고 직원 API 와 분리한 `/api/ext/*` 를 만들었다. 구성은 연동처 키 · 호출 제한 · 호출 기록 · KOS 메뉴 9표 저장이다.
다음 날 협업자가 세 개를 더 요청했다. 예약 가능 시간대 · 과거 시술 · 예약 내역을 DEC-011 로 정해 같은 틀에 붙였다. 지금 외부 API 는 6개이고 연동처는 키 하나로 전부 부른다.

## 2. 적용한 기술·개념

- **연동처 전용 API 를 직원 API 와 분리** — 계정 공유 대신 `X-Api-Key`(연동처별 · `hmac.compare_digest`)로 정한 6개 경로만 연다
  - 왜 이걸 골랐나: admin 공유는 모든 고객 · 메모 · 채팅이 열리고, 기록상 직원과 구분이 안 되고, 끊으면 직원도 영향을 받는다. 외부 라우터는 Bearer 를 보지 않고 직원 라우터는 키를 보지 않게 해 경계를 코드 한 줄로 고정했다
  - 무엇이 어려웠나: 기록에 개인정보를 남기지 않으면서 남용을 보려면 「누가 · 어느 경로 · 결과」만 남겨야 했다. 키 없는 거절은 IP 로 세되 원문을 저장하지 않고, 같은 IP · 같은 결과는 1분에 1줄로 접었다
  - 근거: `procedure/back/app/api/ext.py` · DEC-010 D-10 ~ D-26 · 코드 #22 `e0e4a16`
- **존재를 드러내지 않는 조회(열거 방지)** — 이름 + 이메일이 둘 다 맞아야 고객을 돌려준다. 고객 없음 · 이메일 틀림 · 짧은 이름은 바이트까지 같은 404 다
  - 왜 이걸 골랐나: 404 문구나 갈래가 다르면 키를 가진 쪽이 「이 이메일은 고객이다」를 알아낼 수 있다. 예약 경로만은 KOS 중복 검사 때문에 존재가 드러나는데, 이것은 막지 않고 받아들였다. 연동처만 부를 수 있고 호출 제한 · 기록이 있어서다. 이 점은 Swagger 에 적었다(D-35)
  - 무엇이 어려웠나: KOS 이름 검색은 부분 일치에 페이지가 있다. 짧은 이름이면 「이메일만으로 찾기」가 된다 → 한 페이지(1000) 상한 · KOS id 중복 제거 · 이름 정확 일치로 좁혔다(Q-A)
  - 근거: `review-doc-r1.md` W1 · W2 · Q-A · `research-name-email-lookup.md` · 운영 실호출 404 세 경로 같은 바이트
- **「없음」과 「모양 깨짐」을 가르는 외부 응답 읽기** — KOS 가 `{}` 를 주면 빈 목록, `data` 가 배열이 아니거나 원소가 깨지면 `502`
  - 왜 이걸 골랐나: 1차 코드 검수에서 이름 검색 응답 모양이 깨지면 「0명 → 새 고객 생성」으로 흘러 KOS 에 고객을 새로 만드는 갈래가 나왔다(W1). 모양이 깨진 것은 「없음」이 아니라 「모르겠음」이라 쓰기를 멈춰야 한다
  - 무엇이 어려웠나: 시험의 가짜 KOS 는 늘 `{"data": [...]}` 를 줘서 시험은 다 통과한다. 실물에서만 터지는 자리다. 문서 검수가 KOS 문서의 `{}` 사례로 찾아냈다(add1 W1)
  - 근거: `ext-review-r1.md` W1 · `review-doc-add1.md` W1 · `add1-review-r1.md` N1 · DEC-011 D-16
- **두 벌이 되면 안 되는 규칙을 한 함수로** — 가능 시간대의 남은 자리와 예약 생성의 정원 검사가 같은 함수 · 같은 사본을 본다. 그래서 「목록에 있는 시각이면 정원으로 거절되지 않음」이 성립한다
  - 왜 이걸 골랐나: 계산을 따로 짜면 목록에는 있는데 예약이 거절되는 일이 생긴다. 시간대 요청마다 KOS 슬롯을 1번 받아 공유 사본을 날짜 잠금 안에서 갈았다
  - 근거: DEC-011 D-02 · planner Q1 · Q2 · 로컬 실물(남은 자리 3 → 2)
- **Swagger 설명을 시험으로 고정** — 「설명 빠진 곳 0」 · 오류 표 = 실제 raise · 외부 경로 parameters 에 이름 · 이메일 없음
  - 무엇이 어려웠나: 2차에서 `date` 질의가 들어오며 「parameters = `X-Api-Key` 하나」 단언이 깨졌다. 단언을 지우면 이름 · 이메일 질의 금지를 지키는 유일한 시험이 사라진다 → `date` 하나만 허용하도록 넓혔다(add1 W3)
  - 근거: `tests/test_ext_docs.py` · `tests/test_openapi_docs.py` · 코드 #21 · #23

- reviewer_doc 터미널이 꺼져 있어 dispatch `--inject` 가 거절됐다(`no recognized agent`) → 쉬던 researcher 터미널을 `/clear` 하고 맡겼다

- 컨테이너 안 e2e 스크립트가 `No module named 'app'` → `-w /app -e PYTHONPATH=/app` 로 풀었다
