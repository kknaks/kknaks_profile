# 기획자 피드백 — 1차 데모(데스크 · 원장 · 간호사) · 시술 관제 개념

> 요청 기록이다. 아직 아무것도 정하지 않았다. 「사용자 판단」 칸은 사용자가 항목을 하나씩 보며 채운다.
> 정하는 것은 DEC 가 갖는다.

## 출처

- 대상: 배포본 ccc.medisolveai.xyz 의 **1차 화면**(데스크 · 권태윤 원장 · 강도윤 간호사 계정), 2026-10-14 캡처 7장
- 피드백: `reference/2026-10-12-cc-prototype/CC데모-피드백.html`(캡처 + 핀 + 항목)
- 변경 목업: `reference/2026-10-12-cc-prototype/CC데모-변경목업.html`(역할 바꿔 가며 눌러 봄, 주황 점선 = 변경)
- 2차(헤더 · 예약관리 · 폰 현황판, BASE-006)는 대상이 아니다 — 배포 전

## 기획자가 「먼저 볼 것」으로 꼽은 것

| 항목 | 이유 (기획 원문) |
|---|---|
| D4 · D5 | 접수가 동선과 시술권을 어떻게 다루는지 정한다. 화면 문구보다 처리 기준의 문제다 |
| D11 · D12 | 배정을 사람이 고르는지, CC가 제안하고 사람이 승인하는지가 CC 개념의 중심이다 |
| N1 | 마취 같은 준비 시간을 CC가 알아야 원장 호출과 다음 동선을 맞출 수 있다 |
| C1 · C2 | 동선이 상담 · 오더로 바뀐다는 것과, 오더와 실제 시술을 대조한다는 것이 EMR과 다른 점이다 |
