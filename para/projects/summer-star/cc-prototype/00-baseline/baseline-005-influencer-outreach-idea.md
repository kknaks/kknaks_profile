# 인플루언서 협찬 — Casty 로 찾고, Linky 에서 먼저 말을 건다(대화 생성)

> 아이디어 노트다. 아직 아무것도 정하지 않았다.

## 아이디어

병원이 인플루언서 협찬을 진행한다. 우리 **Casty** 의 인플루언서 탐색 알고리즘으로 대상을 찾고,
협찬 문의는 **Linky** 에서 보낸다. 그러려면 Linky 에 **대화 생성**(우리가 먼저 말을 거는 것)이 있어야 한다.

### 사용자 원문 (2026-10-10)

> 병원에서 인플루언서 협찬을 진행 한다고 햇는데
>
> 우리 casty 중에 인플루언서 탐색 알고리즘이 있어 그랬을때 이 사람도 링키에서 협찬 문의를 해야해서
> 링키는 대화 생성도 잇어야 하지 않을까 ?

## 코디 메모 — 왜 「대화 생성」이 따로 필요한가

- 예약(BASE-004)은 **고객이 먼저** DM 을 보낸다 — Linky 는 들어온 대화에 답한다(인바운드).
- 협찬은 **우리가 먼저** 말을 건다 — 아직 대화가 없는 상대에게 새 대화를 연다(아웃바운드).
- 그래서 Linky 에 「대화 목록에 없는 상대에게 첫 메시지」 흐름이 생긴다: Casty 결과 → 대상 선택 → 채널 선택 → 첫 메시지(협찬 제안 템플릿) → 이후는 기존 대화처럼.

```text
Casty(인플루언서 탐색) → 대상 → Linky 대화 생성(첫 메시지) → 협찬 대화 → (병원/cc 에 협찬 건 전달?)
```

## 확인해야 할 제약 — 확인 전

> 코디가 알고 있는 일반 지식이다. 공식 문서로 확인하지 않았다 — 조사 대상.

- 메타(인스타그램·페이스북 메신저) 메시징 API 는 대체로 **상대가 먼저 보낸 뒤 일정 시간 안에만** 답할 수 있게 되어 있다 — 처음 보는 상대에게 API 로 먼저 DM 을 보내는 게 막혀 있을 수 있다.
- 왓츠앱 비즈니스는 우리가 먼저 보낼 때 **승인받은 템플릿 메시지**만 쓸 수 있는 구조로 알고 있다.
- 라인 · 쓰레드도 채널별 규칙이 다를 수 있다.
- → 채널마다 「API 로 먼저 말 걸기」가 되는지, 안 되면 대안(사람이 앱에서 첫 DM 을 보내고 Linky 가 그 대화를 이어받기 · 이메일 등)을 조사해야 한다.

## 열린 질문

- 채널별 아웃바운드 가능 여부 (위 제약 조사)
- Casty ↔ Linky 연동 — Casty 결과를 Linky 가 어떻게 받나
- 협찬 건이 병원(cc)까지 오나 — 병원이 협찬 대상·일정을 cc 에서 보나, 본사 안에서 끝나나
- 협찬 진행 상태 — 제안 · 응답 · 조건 협의 · 확정 · 방문 · 게시 …
- 협찬 방문 고객이 예약(BASE-004)·현황판(BASE-003)과 어떻게 이어지나
- Linky 고도화가 이 레포(cc-prototype)의 범위인가, Linky 레포의 일인가
