# 전체현황판 「현황 › 예약 현황」

> 기능 계약은 `20-spec/`(SPEC-005), 작업 순서는 `30-work/` 가 갖는다. 이 문서는 무엇을 정했고 무엇이 열려 있는지만 갖는다.
> 업무 흐름 정본은 `reference/2026-10-26-cc-reservation/workflow-v3.md`. 결정 이력(뒤집힌 것 포함)의 원천은
> `orchestration/work/overall-board/_RESUME.md` §2 2026-10-26 줄 · §1 2026-10-26 메모 — **이 문서와 `_RESUME` 가 다르면 `_RESUME` 가 맞다.**

## Context

2026-10-23 시술 현황판을 「Ceramique 전체현황판」의 「현황 › 시술 현황」으로 옮긴 뒤(SPEC-003 0.4.0 ~ 0.5.1), 2026-10-26 사용자와 예약 구간을 한 단계씩 닫았다(BASE-009). 단계마다 KOS 화면 HAR → 데모 지점 조회 · 허가 받은 쓰기 시험 → 사용자 답의 순서였고, 리포트 15건이 근거다. 끝에 사용자가 「코드까지 다 작성해서 알려줘 — e2e 로컬 해보게」라고 했다.

> **r2(2026-10-26)**: SPEC-005 r1 검수 뒤 사용자 결정 U1 ~ U7 을 **D-44 ~ D-50** 으로 더했다. D-01 ~ D-43 은 그대로이고, U 가 좁히거나 바꾼 곳은 그 D 줄 끝에 「→ D-nn」만 달았다.
>
> **r3(2026-10-27)**: 사용자 로컬 E2E batch 1(`orchestration/work/overall-board/reservation-e2e-feedback.md` 23건) 중 사용자가 정한 것 = `_RESUME` §2 2026-10-27 줄 6개 + §1 메모 1줄을 **D-51 ~ D-57** 로 더했다. **뒤집힌 D 의 그 부분은 지우지 않고 ~~취소선~~ + 「(2026-10-27 바뀜 → D-nn)」** 로 두고 바로 뒤에 지금 것을 적었다(D-12 · D-16 · D-18 · D-32 · D-45 · D-01 끝). 23건 중 「대기」(고칠 것 · 결정 아님)는 SPEC-005 0.3.0 부록 F 가 갖는다.
>
> **r4(2026-10-27)**: 사용자 로컬 E2E batch 2 · 3 · 4(`reservation-e2e-feedback.md`) 와 그날 뒤 `_RESUME` §2 2026-10-27 줄(지금 파일 35 · 42 · 60 · 61행)을 **D-58 ~ D-61** 로 더했다(부상태 색 · 상담사 목록 제외(로그인 시스템 계정 + env · 운영 배포 때 지점 시스템 계정 id 더함) · 웹 = 구현본 정본 · 공지 [수정하기]). 뒤집힌 곳은 r3 과 같은 꼴(~~취소선~~ + 「(2026-10-27 바뀜 → D-nn)」 · D-04 앞 반) · 좁힌 곳은 「→ D-nn」(D-09 · D-11 · D-36). batch 2 · 3 의 「대기」(고칠 것)는 SPEC-005 0.4.0 부록 G 가 갖는다. r3 의 「`_RESUME` 50 ~ 55행」은 줄이 끼어들어 **지금 62 ~ 67행**이다(번호는 고치지 않는다 — 부록 A r4 표에 둘 다 적음).

근거 칸 표기: **사용자 지시** = 사용자가 말한 것 / **코디 기본값** = 코디가 제안하고 사용자가 이의를 달지 않은 것(사용자가 바꾸면 바뀐다) / **조사 결과** = 리포트(약호는 workflow-v3 머리말 표 — R · Q · U · C · RM · RT · MT · MC · CS · PD · PP · PC · TA · RX · RXD). `_RESUME 10-26 #n` = `_RESUME.md` §2 표의 파일 n 행 — **0.1.0 작성 때 기준**. r2 때 U1 ~ U7 줄이 파일 49행에 끼어들어 지금 파일에서는 #49 ~ #77 이 한 행씩 밀렸다(#49 → 50행 …). 번호는 고치지 않는다(SPEC-005 · 리포트가 같은 번호를 쓴다). U 줄은 「`_RESUME` U 줄」로 적는다.
