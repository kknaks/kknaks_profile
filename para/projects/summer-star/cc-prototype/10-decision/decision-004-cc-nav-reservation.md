# cc 2차 — 공통 헤더 세 갈래 · 기기별 현황판 · 예약관리 데모

> 기능 계약은 `20-spec/`, 작업 순서는 `30-work/` 가 갖는다. 이 문서는 무엇을 정했고
> 무엇이 열려 있는지만 갖는다.

## Context

1차(DEC-002 · SPEC-001)는 2026-10-14 마감. 같은 10-16(금) 시연에 2차를 넣는다(사용자 「넣어야해」).
요청 원문 · 와이어프레임은 BASE-006, 예약 흐름 배경(Linky → cc → KOS)은 BASE-004.

## Decision

### 헤더 · 화면 갈래

| ID | 결정 | 근거 |
|---|---|---|
| D-01 | 로그인 뒤 모든 화면에 공통 헤더 `현황판 \| 예약관리 \| 내 스케쥴` | BASE-006 원문 1 |
| D-02 | 현황판 = 1차 `/desk` 그대로 | 원문 2 |
| D-03 | 내 스케쥴 = 1차 `/staff`(5직군 직원 페이지) 그대로 | 사용자 「내 스케쥴이 /staff야」 |
| D-04 | 예약관리 = 새 화면. **먼저 빈 페이지**로 헤더에 연결하고, 내용은 시안이 나온 뒤 | 사용자 「공통 헤더 만들고 예약관리는 빈페이지로 코드 작업 해도 돼?」 |
| D-05 | 폰 폭에서는 헤더 세 갈래가 **햄버거 메뉴**로 접힌다 | 사용자 「폰 현황판은 헤더가 햄버거로」 |
| D-06 | 1차의 직군 고정 가드(데스크 → `/desk` 만 · 직원 → `/staff` 만)를 푼다 — 헤더로 누구나 세 화면을 오간다. **데스크 계정에는 내 스케쥴이 없다**(직원 홈이 없는 계정) → 데스크 헤더는 `현황판 \| 예약관리` | 코디 기본값(데스크 계정은 `/staff` 홈이 없다 — `StaffShell` 가드) |

### 기기별 현황판

| ID | 결정 | 근거 |
|---|---|---|
| D-07 | 데스크톱 · 탭 = 현황판 **도면** | 원문 「탭 - 현황판 도면」 |
| ~~D-08~~ | ~~폰 = 도면 대신 **목록** — 고객별 한 줄(이름 · 지금 방 · 단계 · 담당), 방별로 접어 볼 수 있다~~ — 2026-10-14 뒤집음 → D-19(시안 「현황판 폰 v1」은 쓰지 않는다) | 원문 「폰 - 목록 정도만」 · 사용자 「추천으로 가자」 |
| D-09 | 폰 · 탭 경계는 1차 직원 페이지와 같은 760px | 코디 기본값(`StaffShell` `wide = w >= 760`) |

### 예약관리 데모

| ID | 결정 | 근거 |
|---|---|---|
| D-10 | 예약관리는 **데모** — Linky 연동 자리에 데모 전용 버튼 [링키 예약 요청 생성] | BASE-006 데모 1 |
| D-11 | 흐름: 요청 생성 → 예약 테이블에 줄 → [KOS 등록하기] → 미리보기 모달 → [등록하기] → 스크린샷 첨부 → 상태 변경 | BASE-006 데모 1~7 |
| D-12 | 스크린샷은 지금 HTML 로 만든다 — **원본은 사용자가 준다** | 원문 6 |
| D-13 | 와이어의 「예약 불가」는 **「변경 요청」으로 바꾼다** — 병원이 사유를 **텍스트로** 적어 본사로 돌려보낸다. 본사가 「시간을 바꿔야 하는구나」를 보고 고객에게 전한다 | 사용자 「예약 불가 -> 변경 요청으로 … 변경요청 사유는 텍스트로」 |
| D-14 | 변경 요청이 오면 본사가 고객과 다시 대화해 시간을 고친 **수정 요청**을 넣는다 → 기존 예약 아래에 이어 붙는다(와이어 화면 4 · 5) | 사용자 「다시 변경된 요청으로 고객이랑 대화해서 시간 수정해서 넣어줄거야」 |
| D-15 | 수정 요청도 데모 버튼으로 만든다(Linky 자리) | 사용자 「수정요청 버튼도 만들고」 |
| D-16 | 병원 쪽 버튼 = `KOS 등록하기 \| 변경 요청하기`, 수정 요청 줄은 `KOS 수정하기 \| 변경 요청하기` | BASE-006 「사용자가 짚은 것」 · D-13 |
| D-17 | 예약관리 화면은 **시안부터** — frontend 워커가 claude design(`dda9a931-…`)에 초안 → 사용자 수정 → 구현(DEC-002 D-07 방식). 와이어는 구조 참고만 | 사용자 「우리가 디자인 시안부터 다시 할거야」 |
| D-18 | KOS 는 여전히 호출하지 않는다 — 등록 · 수정 자리에 `kos api 연동 필요` 주석(SPEC-001 §9 형식) | DEC-002 · SPEC-001 §1 Out |

### 시안 검토 뒤 (2026-10-14)

| ID | 결정 | 근거 |
|---|---|---|
| D-19 | 폰 현황판 = **1차 현황판의 오른쪽 패널(`Aside` — 예약 · 현황 · 직원 · 고객 탭) 그대로**를 폭 전체로. 새 목록 시안은 쓰지 않는다. 탭은 1차 도면 화면 그대로 | 사용자 「모바일/탭 버전에서 이것 보여주자고 그대로 지금 현황판 코드에서」(캡처 4장 = Aside 네 탭) |
| D-20 | 예약관리 = 시안 「Ceramique 예약관리 v1」 **그대로**(장면 9개 · 상태 6개 · 와이어와 바꾼 것 포함). 등록 전 변경 요청 뒤 수정 줄도 시안대로 `[KOS 수정하기]` | 사용자 「시안대로가는데」 · 「예약은 지금 보여준데로」 |
| D-21 | **기존 디자인 무변경** — 1차 화면(현황판 도면 · 왼쪽 메뉴 사이드바 · Aside · 직원 페이지)과 기존 시안 파일은 고치지 않는다. 새 화면은 기존 디자인(medikit · Ceramique 테마 · 1차 컴포넌트) 기준으로 맞춘다 | 사용자 「기존 디자인은 건드리면 안된다 · 기존 디자인기준으로 맞춰야해」 |

| D-22 | (1차 버그) 「오늘 시술 후보」의 보유 시술권: **A** 같은 시술권 묶음의 회차가 하나라도 동선에 있으면 그 묶음은 후보에서 뺀다 + **B** 보유 시술권 후보도 상담 종료 뒤에만 보인다(접수 때는 접수 모달에서 고른다). SPEC-001 §5.4 3번을 SPEC-002 §4 가 대신한다 | 사용자 「추천 시술은 첫방문 상담 이후에 뜨는거 아닌가」 · 「응 추천으로」(E2E batch-2 #2) |
