# 명동 PoC v2 — 시술 현황판

> 기능 계약은 `20-spec/`, 작업 순서는 `30-work/` 가 갖는다. 이 문서는 무엇을 정했고
> 무엇이 열려 있는지만 갖는다. 업무 흐름 정본은 `reference/2026-10-12-cc-prototype/workflow-v2.md`.

## Context

10-16 명동점 인터뷰 뒤 「지금 현황판 말고 시술 현황판」(BASE-008). 2026-10-20~21 사용자와 흐름 ①~⑦ 을 하나씩 정했고, 시안은 사용자가 claude design 에서 직접 고쳐 확정했다. 작업 노트 · 결정 이력(뒤집힌 것 포함)은 `orchestration/work/myeongdong-poc-v2/_RESUME.md` §2.

## Decision

### 범위 · 코드 · 배포

| ID | 결정 | 근거 |
|---|---|---|
| D-01 | 새 기능 폴더 **`procedure/`**(`front` Next.js + `back` FastAPI · 새 DB). **기존 `cc/` 코드는 쓰지 않는다** — 시드 · 시나리오 · 동선 로직 없음 | 사용자 「기존 코드 다 무시하고 시술현황만 새로」 · DEC-001 |
| D-02 | **테마 · 디자인 시스템 유지** — medikit · Ceramique 토큰 · `medikit-patches.css` · 틀 컴포넌트(헤더 · 사이드바 · 오른쪽 패널) 모양을 `cc/` 에서 **복사**(기능끼리 import 금지) | 사용자 · DEC-001 |
| D-03 | **배포 = 기존 주소 `ccc.medisolveai.xyz` 를 시술현황으로 교체.** `cc/` → `_archive/cc/`, Actions · infra 차트 · Secret 을 `procedure/` 로 | 사용자 「기존 주소로 올릴 거야」 · DEC-003 |
| D-04 | 범위 = 시술 현황판(간호 스테이션 · 의국 화면) **구현 · 배포까지** | 사용자 |
| D-05 | ccc 로그인 = **관리자 계정 1개**(간호 스테이션 · 의국 공용). 값은 env · k8s Secret. 직원 개인 계정은 나중 | 사용자 |

### KOS 연동

| ID | 결정 | 근거 |
|---|---|---|
| D-06 | **KOS 데모 지점에 실제로 붙는다** — v1 의 「KOS 호출 없음 · 주석만」(DEC-002 D-10 · OQ-208, DEC-004 D-18)을 **대체**. 운영 호스트의 DEMO 테넌트(「세라미크의원 명동점 DEMO」). 운영 명동점 키 금지 | 사용자 · 실호출 확인 |
| D-07 | 공개 API = 데모 키 `KOS_API_tenent_dev` → `exchange-token` → `Authorization: <token>` / 내부 API = **시스템 계정**(사용자 계정 · 데모 「관리자」 역할) `sign-in` → `Authorization: Bearer <token>`(≈14시간 · refresh 없음). 토큰은 만료 시각 기준 보관 · 만료 10분 전 · 401 이면 재로그인 1회. 키 값 · 사용법 메인 = ax-clinic-project(private) | 실호출 · HAR |
| D-08 | **조회** — 구역 「4층」만. 일정 = 내부 `get-schedules-grouped-by-zone` **10초마다**. 직원 = 공개 `getAccounts` · 방 = 내부 `get-rooms` **1시간마다**(+ 서버 시작). **조회 시간 09:00~21:00 KST**(운영 10~20 앞뒤 1시간) | 사용자 · HAR |
| D-09 | **기준** — KOS 에 있는 상태는 KOS 가 기준(일정 · 시술 목록 · 결제 · 오더 메모 · 방 · 고객 단계 · 시술 완료/시각 · 집도의 · 호출 여부) → 조회 때 덮어쓴다. KOS 에 없는 것만 ccc 기준(마취 · [시작] 시각 · 호출 기록 · 지정 원장). ccc 조작이 KOS 에 반영되기 전엔 덮어쓰지 않고 「KOS 반영 중」 + 재전송, 끝내 실패하면 카드에 「KOS 반영 실패」 | 사용자 「응」 |
| D-10 | **현장은 KOS 를 직접 조작하지 않는다** — ccc 가 조작 화면 | 사용자 |
| D-11 | 원장 목록 = KOS 원장 역할. **시스템 계정(DOCTOR 태그를 가짐) · 「마취용」 · 비활성은 계정 id 로 뺀다** | 사용자 · 데모 역할 확인 |

### 데이터 모델

| ID | 결정 | 근거 |
|---|---|---|
| D-12 | **ccc DB 가 KOS 를 품는 더 큰 구조** — 모든 행에 ccc id(주인) + `kos_id`(있으면). KOS 에서 오는 것(고객 · 일정 · 시술 · 방 · 직원)은 지금 KOS 원천, ccc 에만 있는 것(마취 회차 · 호출 기록 · 수락 · 시작 · 귀가 대기 · 조작 로그 · KOS 반영 상태). 필드 이름은 ccc 이름 + KOS 대응표 | 사용자 「KOS 데이터 + 우리 데이터」 · 장기: KOS 를 화면 하나씩 교체 |
| D-13 | 조작은 **이벤트 로그로 쌓는다**(지우거나 고치지 않음) — 되돌리기 · 원장 기여 보기는 나중에 이 로그로 | 사용자 |
| D-14 | 개인정보는 **화면에 쓰는 것만** 저장(이름 · 읽기 · 국적 · 신규 여부 · 차트번호). 연락처 · 생년월일 · 메모는 쓸 화면이 생길 때 | 코디 기본값 |
| D-15 | PoC DB = SQLite. PoC 뒤 PG + Redis(그때 판단) | 사용자 |

| D-17 | 구조 = 헤더 · 왼쪽 사이드바 · 가운데 **오더지 카드 나열**(도면 아님) · 오른쪽 패널(탭 현황 · 호출 · 고객). 헤더 메뉴 = 「시술 현황」 하나 | 시안 · 사용자 |
| D-18 | 정렬 **[입실순 \| 배치순]** — 입실 = 방이 배정된 시각(「방 배정」 작업) · 배치 = `get-rooms` `order` | 사용자 · 코디 기본값 |
| D-19 | 카드 = 머리(방 · 고객 · 국적 · 신규 · 입실) → 오더 메모(`MemoCard` 3줄 · 120자 접기) → 마취 → 시술 목록(전체 선택 · 줄마다 체크 · [시작]/[종료]/「호출함」) → **아래 큰 버튼 하나**(「시술 선택 후 의사 호출」/「의사 호출 · N건」, 다 끝나면 같은 자리가 [귀가 대기]) | 시안 r4 |
| D-20 | 오른쪽 「현황」 = 상태 수 칸 = 필터(전체 · 확인 · 대기 · 마취 · 호출 · 진행) + **「확인이 필요」**(호출 미수락 5분 · 마취 20분 초과, 오래된 순, 기준 · 막대) | 시안 |

### 흐름

| ID | 결정 | 근거 |
|---|---|---|
| D-21 | ① **KOS 일정이 시술 대기(`PROCEDURE_WAITING`)가 되면 카드가 생긴다** — 수납 전(`paymentRequired`)이어도 띄우고 「수납 필요」 | 사용자 |
| D-22 | **방이 있는 고객만** 카드. 방 없는 고객 = 라운지 대기 = 시술 현황에 안 나온다. 「방 배정」 작업(ETCETERA)은 시술 목록에 안 보인다 | 사용자 |
| D-23 | ② **마취는 고객 상태(대기 · 진행)와 별개** — 대기 · 진행 어느 때나 [마취 시작] · [마취 종료]. 고객 단위 · 여러 회차 · 시술에 묶지 않음 · 동시 진행 1개 · 보라 · 20분 넘으면 빨강. **시안(시술 대기에서만)을 고친다**. KOS 「마취용」 배정은 하지 않는다(ccc DB 만) | 사용자 |
| D-24 | ③ 의사 호출 — 카드에서 **대기 시술**을 체크 → [의사 호출] → 「모든 의사」 또는 원장 한 명(비어 있는 원장 먼저). KOS = `change-tasks-assignees`(담당 = 시스템 계정) → `call-tasks-doctors`(고른 시술만) | 시안 · 실호출 |
| D-25 | **호출은 만든 시각과 함께 쌓기만** 한다. 시술마다 유효 호출 = 그 시술이 들어간 **가장 최근 호출**. 같은 시술을 다시 호출하면 그 시술은 새 호출로 넘어간다 | 사용자 「호출 생성 시각 기준으로 남기는 게」 |
| D-26 | **진행 중 · 완료 시술은 호출 대상이 아니다**(체크 꺼짐 · 원장 못 바꿈) | 사용자 |
| D-27 | ④ **수락 = 의국 화면**(오른쪽 「호출」 탭) — 원장이 자기를 골라 [수락]. 받는 시술 = 그 호출이 유효 호출인 시술 중 **아직 수락 안 된 것만** → KOS `change-tasks-doctors`(그 `sequences` · 고른 원장 id). 지정 호출의 [다른 원장에게] = 같은 시술로 「전체」 호출을 새로 만든다. 시안 P11(수락 = 수락 전 호출 전부)을 고친다. 개인 폰 · 앱 수락은 나중 | 사용자 · 실호출(관리자 계정이 원장 대신 수락 200) |
| D-28 | **[되돌리기] 없음**(토스트 · 호출 탭 모두) — 되돌리기 정책은 나중에 로그로 | 사용자 |
| D-29 | ⑤ 시술 [시작] · [종료] — **원칙은 시술실 태블릿 · 모바일, 지금은 간호 스테이션 현황판에서**(나중엔 웹 ↔ 앱 모두 · 스테이션이 보조) | 사용자 |
| D-30 | [시작] 조건 — 호출한 시술은 **유효 호출이 수락된 뒤**, 호출 안 한 시술은 담당의가 있을 때. **새 호출이 생기면 수락 전까지 [시작] 꺼짐**. 순서 · 동시 진행 수는 막지 않는다 | 사용자 · 시안 P4 |
| D-31 | [종료]는 **[시작]한 시술에만** | 사용자 |
| D-32 | **그 고객의 첫 [시작] = 시술 진행** → KOS `changeFlowStep(PROCEDURE)`(공개). [시작] 시각은 ccc 만. [종료] = KOS `change-tasks-complete`(그 시술 하나) — **완료 상태만** 올린다 | 사용자 · HAR |
| D-33 | ⑥ **[귀가 대기] = 방 빼기(라운지로)** — 시술이 다 끝나야 보인다 · 현황판에서 누른다 → KOS `changeFlowStep(PROCEDURE_DONE)`. **시술 완료로 방을 비우지 않는다**(KOS 화면은 마지막 완료 때 방을 비워 보이지만 ccc 는 [귀가 대기]까지 그 고객의 방). 카드는 흐리게 맨 뒤 | 사용자 · HAR |
