# 고객 문진 웹 — 결정

> 기능 계약은 SPEC-006, 작업 순서는 WORK-010 이 갖는다. 이 문서는 무엇을 정했는지만 갖는다.
> 결정 원천은 `orchestration/work/overall-board/_RESUME.md` §2 — **이 문서와 `_RESUME` 가 다르면 `_RESUME` 가 맞다.**

## Context

DEC-007(앱 다음 판)은 문진을 **직원 기기(데스크 태블릿 · 코디 폰)의 우리 앱 화면**에서 고객이 채우게 했다(D-13 · D-45 · 잠금 화면). 앱 판 구현 중 2026-10-27 사용자가 「문진은 고객 웹에서 하겠지」로 뒤집고, 방식을 KOS 설문 링크가 아닌 **ccc 고객용 웹 문진 페이지**로 정했다(「우리 웹페이지를 만들어서 · 나중에 KOS 안 쓰는 상황 고려」). 다만 그날 앱 판은 멈추지 않고 끝까지 갔고(앱 APP5 문진 화면 · BE4 문진 API 는 끝났으나 보류), 2026-10-28 사용자가 「고객 폰으로 할 거니까 웹페이지 만들어서 이 웹페이지로 설문하게」로 착수했다.

근거 칸 표기: **사용자 지시** = 사용자가 말한 것 / **코디 기본값** = 코디 제안 · 이의 없음. `_RESUME 10-27` 등 = `_RESUME.md` §2 그 날짜 줄(줄 이름으로 적는다).

## 근거 개념

없음 — 사용자 지시에서 나왔다. 앞 결정과 잇는 곳은 각 줄에 DEC-007 번호로 적었다.

### DEC-007 에서 바뀌는 줄

DEC-007 본문은 고치지 않는다(이 문서가 뒤의 결정). 문진에 닿는 DEC-007 줄은 아래처럼 읽는다.

| DEC-007 | 이 문서 뒤 |
|---|---|
| D-01 「QR 문진」 · 「시안 없는 화면(문진 …)」 | 문진은 앱 범위 밖 → 고객 웹(D-01) |
| D-13 고객 입력 = 우리 앱 · 받는 기기에서 고객이 채움 | **뒤집힘** — 받는 기기는 QR 만 보여 주고 고객은 자기 폰 웹(D-01 · D-03) |
| D-43 [태블릿에 띄우기] = 띄우기 요청 → 그 기기 | 길은 그대로 · 그 기기가 여는 것 = 문진 화면 → **QR 화면**(D-03) |
| D-44 QR = 코디 폰 우리 앱으로 찍으면 같은 화면 · 10분 · 링크 복사 · 메신저 뺌 | QR 을 **고객 폰 카메라**가 찍어 웹으로(D-03) · 10분 · 링크 복사 · 메신저 뺌은 그대로(SPEC-006 OQ-808) |
| D-45 문진 화면 잠금 · [직원] 길게 · 대기 화면 | **없어짐**(앱 문진 화면 뺌 — D-05) |
| D-46 언어 칩 6 | 그대로 · 웹 화면에서(D-06) |
| D-47 앱 제출 때 이력 한 줄 | 그대로 · 웹 제출 때(D-06) |
| D-71 문진 잠금 해제 실패 = 기기별 | 잠금이 없어져 쓸 곳 없음(SPEC-006 OQ-802) |

## 열린 것

결정 줄 안에서는 없다. 계약에서 남은 것(토큰 싣는 곳 · 시한 · 속도 제한 · 잠금 해제 API · KOS 없이 갈 때 고객 값 원천 등)은 SPEC-006 §12 OQ-801 ~ OQ-814 에 기본값과 함께 둔다.
