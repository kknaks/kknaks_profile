# 앱 다음 판 — 결정

> 기능 계약은 SPEC-004 0.4.0(r2 = 0.4.1), 작업 순서는 WORK-009 가 갖는다. 이 문서는 무엇을 정했는지만 갖는다.
> 업무 흐름 정본은 `reference/2026-10-27-cc-app/workflow-app.md`. 결정 원천은 `orchestration/work/overall-board/_RESUME.md` §2 — **이 문서와 `_RESUME` 가 다르면 `_RESUME` 가 맞다.**

## Context

시술 현황 앱(SPEC-004 0.3.2 · TestFlight 빌드 3)은 시술 구간만 다룬다. 2026-10-26 예약 구간을 웹으로 닫으면서(DEC-006) 앱이 할 일 — 고객 입력 QR · 신분증 스캐너 · 상담사 푸시 — 을 「앱 판」으로 미뤘다(DEC-006 D-01 · D-23 · D-26 · D-29 · D-38). 2026-10-27 사용자가 앱 시안 v4(폰 · 태블릿 4탭)를 다시 받고 앱 범위 · 스캐너 · 문진 언어 · 알림을 정했고, planner 가 흐름 초안(workflow-app)과 정할 것 45개를 올려 사용자가 **기본값 전부 승인**했다(「응 그렇게 가자」).

근거 칸 표기: **사용자 지시** = 사용자가 말한 것 / **코디 기본값** = 코디 제안 · 이의 없음 / **승인 기본값** = workflow-app AP-n 의 planner 기본값을 사용자가 승인(10-27). `_RESUME 10-26` · `_RESUME 10-27` = `_RESUME.md` §2 그 날짜 줄(줄 이름으로 적는다 — 행 번호는 밀리므로 쓰지 않는다).

## 근거 개념

없음 — 사용자 지시 · 시안 · KOS 조사에서 나왔다. 앞 결정과 잇는 곳은 각 줄에 DEC-005 · DEC-006 번호로 적었다.
