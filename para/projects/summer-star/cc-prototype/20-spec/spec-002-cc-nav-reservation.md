## 1. 공통 헤더 (D-01 ~ D-06)

| 경로 | 화면 | 헤더 갈래 |
|---|---|---|
| `/desk` | 현황판(1차 그대로) | 현황판 |
| `/reservations` | 예약관리 — **0.1.0 은 빈 페이지**(제목 + 「준비 중」 한 줄) | 예약관리 |
| `/staff` · `/staff/patient/[scheduleId]` | 내 스케쥴(1차 그대로) | 내 스케쥴 |
| `/login` | 로그인 | **헤더 없음** |

- 헤더 하나를 세 경로가 공유한다. 지금 경로의 갈래가 선택 표시
- 갈래 보이기: 직원 계정(frame ≠ `desk`) = 세 갈래 · 데스크 계정(frame = `desk`) = `현황판 | 예약관리`(D-06)
- 1차 가드 해제: `/desk` 의 「데스크 아니면 `/staff` 로」 · `StaffShell` 의 「데스크면 `/desk` 로」를 지운다. 데스크 계정이 `/staff` 를 직접 열면 `/desk` 로 보낸다(직원 홈 없음 — 이것만 남긴다)
- 로그인 뒤 첫 화면은 1차 그대로(`homePath`)
- 로그아웃 · 계정 표시 등 1차 화면 헤더에 있던 것은 공통 헤더로 옮긴다 — 같은 기능이 두 번 보이지 않게
- 폭 < 760px: 세 갈래가 햄버거 메뉴로 접힌다(D-05 · D-09). ≥ 760px: 갈래가 헤더에 나란히
- 디자인 언어는 1차 화면과 같은 medikit · Ceramique 테마. 별도 시안 없음

## 2. 기기별 현황판 (D-07 · D-09 · D-19 · D-21)

- 폭 ≥ 760px(탭 · 데스크톱): 1차 `/desk` **그대로**(도면 · 왼쪽 메뉴 사이드바 · 1280 미만이면 Aside 서랍 — 지금 동작). 레이아웃 손대지 않는다
- 폭 < 760px(폰): 도면 · 왼쪽 메뉴 사이드바를 감추고 **1차 `Aside`(예약 · 현황 · 직원 · 고객 탭)를 폭 전체**로 보인다. 컴포넌트 · 동작은 1차 그대로(접수 · 예약 상세 · 방 패널 · 직원/고객 선택 등 Aside 가 여는 것 전부 같은 모달 · 패널). Aside 의 서랍 닫기 버튼 등 폰에서 의미 없는 것만 숨긴다
- 시안 「Ceramique 현황판 폰 v1」은 쓰지 않는다
- 새 API 없음

## 3. 예약관리 (D-10 ~ D-18 · D-20 · D-21)

**화면 정본 = claude design `dda9a931-…` 「Ceramique 예약관리 v1.dc.html」**(로컬 사본 `orchestration/work/cc-nav-resv/design-upload/`) · 해설 `orchestration/work/cc-nav-resv/design-report.md` §A. 문구 · 칸 · 상태 색 · 모달 · 데모 상자 모양은 시안 그대로. 구현은 1차 front 의 medikit 컴포넌트 · Ceramique 테마로(D-21).

### 3.1 모델 (back · 관제 DB 에 새 테이블)

예약 줄 `ResvRequest`:

| 필드 | 뜻 |
|---|---|
| `id` | 줄 id |
| `groupId` | 같은 예약의 이력 묶음(첫 요청 줄의 id) |
| `kind` | `request`(예약 요청 · 본사) / `modify`(수정 요청) |
| `modifyReason` | `modify` 일 때 `customer`(고객 시간 변경 — 확정 뒤) / `change_request`(변경 요청 반영) |
| `receivedAt` | 받은 시각 |
| `customer` | `{name, reading, chart, nat, natCode, sex, birth, phone, zone, isNew}` — **가짜 값 풀**(시안 샘플 값) |
| `date` · `time` | 예약 일시 |
| `proc` · `lang` | 시술 · 통역 언어 |
| `before` | `modify` 일 때 바뀐 칸의 이전 값 `{time?, date?}` (취소선 표시용) |
| `status` | `requested`(예약 확인중) · `confirmed`(예약 확정) · `change_requested`(변경 요청) · `modify_requested`(수정 확인중) · `modified`(수정 확정) · `superseded`(변경됨) |
| `changeReason` · `changeAt` | 변경 요청 사유(텍스트) · 시각 |
| `registeredAt` | KOS 등록/수정 시각 |
| `snapshot` | 등록/수정 때 남기는 「KOS 등록 화면」 값(시안 스크린샷 모달 칸 — 고객 · 구분 · 국적/성별 · 예약 일정 · 층/권역 · 희망 시술 · 통역 · 예약 메모(자동 작성)). front 가 HTML 로 그린다. 등록 전 바뀐 줄은 `null` |

### 3.2 API

| 메서드 · 경로 | 동작 |
|---|---|
| `GET /api/reservations` | 줄 전부 + 요약 칩 수(확인 필요 · 변경 요청 · 확정 · 전체) + `version` |
| `POST /api/reservations/demo/request` | **데모 전용** — 가짜 풀에서 다음 고객으로 `request` 줄 생성(`requested`) |
| `POST /api/reservations/demo/modify` | **데모 전용** — 대상: `change_requested` 줄이 있으면 그 묶음의 가장 최근 것, 없으면 가장 최근 `confirmed`/`modified`. 대상 아래에 `modify` 줄(`modify_requested`, 시간 변경 + `before`). 대상 없으면 409 |
| `POST /api/reservations/{id}/register` | `requested` · `modify_requested` 줄만. → `confirmed`(request) / `modified`(modify) · `registeredAt` · `snapshot`. modify 면 같은 묶음의 이전 유효 줄 → `superseded`. 주석 `kos api 연동 필요`(SPEC-001 §9 형식 — 등록 = 예약 생성 · 수정 = 예약 변경) |
| `POST /api/reservations/{id}/change-request` `{reason}` | `requested` · `modify_requested` 줄만, `reason` 비면 400. → `change_requested` · 사유 · 시각 |

- 조작 응답 `{version}`, 성공 시 1차와 같은 SSE 로 갱신 알림(front 는 다시 읽기)
- `POST /api/admin/reset` 때 예약 줄도 비운다(데모 처음 상태 = 빈 테이블)
- 상태가 맞지 않는 조작은 409(도메인 예외 → 1차와 같은 오류 형식)

### 3.3 화면 (`/reservations`)

- 시안 장면 1~7 흐름 그대로: 빈 상태 · 데모 상자(주황 점선 「데모 전용 · 링키 연동 자리」 [링키 예약 요청 생성] · [링키 수정 요청 생성] — 대상 없으면 막힘) · 테이블(본사 요청 | 병원 상태 | 비고) · 묶음 머리(이력 2건 이상) · KOS 등록/수정 미리보기 모달 · 스크린샷 모달(KOS 카드 모양, `snapshot` 값) · 변경 요청 모달(사유 비면 막힘) · 토스트 · 새 줄 강조
- 버튼: `requested` · `modify_requested` = `[KOS 등록하기 | KOS 수정하기] · [변경 요청하기]` / `confirmed` · `modified` = `[스크린샷 보기]` / `superseded` = `[이전 스크린샷]`(snapshot 없으면 「KOS 등록 전에 바뀌어 스크린샷이 없어요」)
- 폭 < 760px 배치는 시안에 없다 — 테이블이 가로로 넘치지 않게만(시연은 데스크톱)

## 4. 1차 계약 정정 — 오늘 시술 후보 (D-22)

SPEC-001 §5.4 3번(보유 시술권 — 「이미 동선에 들어간 `ticketId` 는 빼고」)을 이것으로 바꾼다. 1 · 2번(오늘 결제 시술 · 원장 상담)은 그대로.

- 보유 시술권 후보는 **상담 종료 뒤**(오늘 결제 시술 후보와 같은 조건)에만 보인다. 접수 전 · 접수 때는 접수 모달에서 시술권을 고른다
- 같은 시술권 묶음(`bundleId`)의 회차가 하나라도 동선에 있으면 **그 묶음 통째로** 후보에서 뺀다

## 5. 기획자 피드백 반영 (D-23 ~ D-35 · BASE-007)

목업 참고: `reference/2026-10-12-cc-prototype/CC데모-변경목업.html`(로컬) · `assets/cc-feedback-*.png`. 목업과 이 절이 다르면 **이 절이 맞다**(뺀 것이 많다). 디자인 언어는 1차 그대로.

### 5.1 데이터 · API (back)

- **시드**(D-24): visitor 에 `phoneticName`(string|null) · `phone`(string|null, `+국가번호 번호` 한 줄) · `categories`([{name, color}]) 추가. 시나리오 `seed.json` 의 공개본 값은 가짜 — 가짜 이름에 맞춘 한글 읽기, 형식만 맞춘 가짜 번호. VIP 1명(`categories:[{name:"vip500",color:"CYAN"}]`)
- **응답**: 고객이 나오는 곳 전부(`GET /api/board` customers · reservations, 환자 상세, 직원 홈)에 `phoneticName` · `phone` · `vip`(bool — categories 중 이름이 `vip` 로 시작) 추가. 화면에 전화번호를 **보여 주지는 않는다**(검색에만)
- **시술권 차감**(D-32): 보유 시술권 사용 처리는 그 시술 단계가 **완료(finish)될 때**. 접수 · 배치 때가 아니다. `보유 n/m` 의 n 은 완료된 것만 빠진다. KOS 주석(시술권 차감)
- **추가 요청 메모**(D-33): `POST /api/desk/memo {scheduleId, category: "reservation"|"consultation", text}` → 그 고객 오늘 예약 메모 / 상담 메모 **끝에 줄을 덧붙인다**(빈 text 400). 덧붙인 줄은 바로 보인다(SPEC-001 §2 공개 시점 규칙의 예외 — 데스크가 지금 쓴 것). 상담 종료 이벤트가 상담 메모를 채워도 덧붙인 줄은 남는다. `POST /api/desk/check-in` 도 선택 `memo: {category, text}` 를 받아 같은 처리. KOS 주석 `changeReservationMemo` · `updateScheduleConsultationInfo`
- §4(시술 후보 정정)도 이번에 구현한다

### 5.2 화면 (front)

- **한글 읽기**(D-25): 영문 이름 옆 회색 작은 글씨 — 예약 카드 · 접수 모달 · 고객 패널 · 현황 카드 · 직원 화면 고객 줄. 한국인 · 값 없으면 없음
- **경과 시간**(D-28): `lib/time.ts` 의 `fmtElapsed` · `fmtMinSec` 를 하나의 형식으로 — `N시간 M분` · `M분` · `방금`(1분 미만). 쓰는 곳 전부 같은 함수
- **예약 탭**(D-26 · D-34): 칸 = 접수 전(예약 시각 ≥ 지금 · 미접수) · 늦음(예약 시각 < 지금 · 미접수) · 귀가. 칸을 누르면 그 상태만, 다시 누르면 전체. 노쇼는 칸 없이 목록 맨 아래 흐리게(1차 표시) · [노쇼]는 예약 상세 그대로. 카드 = `시각 · 영문 이름 · 한글 읽기 · [첫 방문/재내원] · [접수]`(`assets/cc-feedback-d7-resv-card.png`)
- **고객 검색**(D-29): Aside 탭 위 검색 칸. 영문 이름 · 한글 읽기 · 전화번호(숫자만 비교) — 오늘 예약 + 원내 고객. 결과를 누르면 원내 고객 = 고객 패널, 미접수 = 예약 상세
- **현황 탭**(D-30): 원내 고객 카드 — 상태 배지 · 방 · 담당 · 대기 시간 · VIP 칩. 오래 기다린 순. 누르면 그 고객의 고객 패널. 오늘 받을 시술 · 주의사항 없음. 위 상태별 숫자 칸은 1차 그대로
- **접수대기실 → 고객 패널**(D-27): 도면의 접수대기실 목록에서 이름을 누르면 방 목록이 아니라 1차 고객 패널(`CustomerPanel`). 고객 패널 버튼 줄(`수면시술실로 이동 | 귀가`)에 **[방 배정]** — 고객이 접수대기실에 있을 때만. 누르면 방 고르기(1차 배치 목록과 같은 후보) → `POST /api/desk/place`
- **접수 모달**(D-31 · D-32 · D-33): 위에서부터 ① 이름 · 한글 읽기 · 칩 / 성별 · 나이 · 국적 · 예약 시각 ② **지난 방문**(재내원만 — 날짜 · 시술 · 담당 · 상담 원문 접기/펼치기, 요약 금지) ③ 오늘 동선 선택지(상담 · 원장 상담 · 보유 시술권 — **자동 체크 없음**, 시술권 줄 오른쪽 「보유 시술권 n/m · 오늘 사용 예정 · 시술 완료 때 차감」) ④ 추가 요청 — 카테고리 셀렉터(예약 메모 · 상담 메모) + 메모 입력(선택) ⑤ [취소] [접수]. **없음**: 전화번호 · 동선 순서 미리보기(「오늘 동선」 칩) · 보낼 곳. 버튼 동작(접수 → 접수대기실)은 1차 그대로
- **예약관리 부연 설명 삭제**(D-35): E2E batch-2 #1 표 그대로

### 5.3 E2E batch-3 반영 (0.3.1)

원문 · 원인: `orchestration/work/cc-nav-resv/e2e-feedback-batch-3.md` #1 ~ #8. §5.2 와 다르면 이 절이 맞다.

- **예약 탭 칸**(§5.2 대체): **전체 · 접수 전 · 지연 · 귀가**. 「늦음」→「지연」. 「전체」 = 오늘 예약 수, 처음 선택. 다른 칸을 누르면 그 상태만
- **예약 카드 두 줄**: 1줄 `시각 · 영문 이름 · [첫 방문/재내원] · VIP` / 2줄 `한글 읽기`. [접수]는 오른쪽. 이름은 자르지 않는다
- **지연 표시**: 지연 카드에 `N시간 M분 지연` · `M분 지연`(D-28 형식) — SPEC-001 §3 9번 「지연 표시 없음」을 대신한다

### 5.5 현황 — 현재 상태 · 경과 시간 두 줄 (0.3.3)
