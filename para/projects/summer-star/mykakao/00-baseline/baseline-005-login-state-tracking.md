# 로그인 상태 트래킹 + 자동 재조정

카톡 로그인/로그아웃/프로세스 상태를 추적하고, **등록해둔 방을 접근 가능해질 때마다 자동으로 최신화**한다. 사용자가 버튼을 누르지 않아도 추적 방이 빈틈없이 쌓이게 하는 축적 엔진의 토대.

> baseline-003(V2)의 축적을 **자율화**한다 — 수동 import → 상태 기반 자동 재조정.

## Raw (사용자 설계)

- 초기 유저는 추적할 방이 없음. 처음 앱 켜고 **추적할 카톡방을 등록**한다.
- 등록 정보는 **DB에 저장**되어 앱/카톡을 껐다 켜도 유지된다.
- 그 이후 등록된 방은 **항상 최신 상태를 유지하려고** 한다(접근 가능해질 때마다 따라잡기).
- 트레이 우클릭 메뉴에서 로그인 상태를 직접 본다(유저 닉네임 + 로그인/로그아웃 dot).

## Context — 왜 상태 트래킹이 토대인가

복호는 "카톡 실행 + 로그인 + 방 열림"일 때만 가능(키가 메모리에 있어야). 그래서 **언제 수집 가능한지**를 정확히 알고 그 창을 놓치지 않는 게 자율 축적의 전제다.

## 상태 모델 (3상태 — 관찰자는 앱)

```
[DOWN]        카톡 프로세스 없음                  → 복호 불가
[UP·로그아웃] 프로세스는 있으나 세션 없음         → 계정 DB 안 열림·키 없음 → 복호 불가
[UP·로그인]   프로세스 + 세션 활성               → 계정 DB 열림·키 회수 가능 → ✅ 수집 가능
                └ 세부: 방별 열림/닫힘 (방별 키)
```

## 재조정 루프 (핵심)

등록된 추적 방 = 원하는 상태(최신). 앱이 이벤트마다 실제와 맞춘다:
```
앱 시작        → DB에서 추적 방 로드 → 로그인? → 접근 가능한 방 델타 따라잡기 + 감시 시작
로그인 감지    → 추적 방 델타 따라잡기 + 감시 재개
방 열림 감지   → 그 방 델타 따라잡기
(방 열린 동안) → 실시간 append (P2)
로그아웃/종료  → 감시 일시정지 (다음 로그인 때 델타로 자동 메꿈)
```
"항상 최신"은 best-effort — 접근 불가 구간은 접근 가능해질 때 델타로 수렴.

## Why It Matters

- 이게 되면 사용자는 앱을 신경 안 써도 추적 방(여친 대화 등)이 계속 축적된다 — 패턴 추출(BASE-003 목적)의 안정적 원천.

## 아직 안 정한 것

- 각 전이의 세부 정책(로그아웃 판정 기준의 최종 신호 조합)은 spec/구현에서 실측 확정.
- 여러 방 동시 열림 시 키 상주 타이밍.
