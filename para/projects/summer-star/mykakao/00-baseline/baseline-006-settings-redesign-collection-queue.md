# 설정 UI 리디자인 + 백그라운드 수집 큐 + 트레이 정비

설정 페이지를 카톡 스타일 2탭으로 리디자인하고, 방 선택을 좌우 transfer 방식으로 바꾸며,
저장 시 백그라운드 수집 큐로 히스토리를 모으고, 트레이 상태 메뉴를 정비한다.

> 승인 목업: `claude.ai/code/artifact/7340ba99-f258-4f5f-824a-5149112f96da`
> BASE-005(로그인 상태 트래킹) 위 — 상태 트래커가 큐의 "대기 중" 방을 열림 감지 시 자동 수집.

## Raw (사용자 설계)

**레이아웃**: 화면 전체 폭. 카톡 스타일(옐로우·말풍선·아이콘, 이모지 금지).

**탭**: `채팅방 설정` | `채팅방 + 채팅목록`

**채팅방 설정 = transfer**: 좌(내 카톡 방 전체) → 우(추적할 방). `[취소][저장]`.
- 저장은 우측이 변동되면 **자동 활성화**(dirty).
- 저장 시 → 추적 시작 + **DB에 백그라운드 큐 행 생성** → 백그라운드로 히스토리 저장.

**수집 태스크 흐름**:
```
저장 → DB 큐 행 생성 → 백그라운드 수집 → UI 폴링(수집 중 스피너) → 완료 시 대화 렌더
수집 불가(닫힌) 방 → "대기 중" → 카톡에서 열리거나 메시지 오면 자동 수집(강제 아님)
```

**트레이 우클릭 메뉴 정비**:
- 글씨 전부 **까만 글씨**(현재 회색 MF_GRAYED → 오너드로우).
- `로그인 유저 : <본인 닉네임>` (현재 "-" → 실제 이름 해석).
- 상태 점: **초록(로그인) / 빨강(로그아웃)** 색 원 (이모지 금지).
- 정보 항목은 **클릭만 안 되게**(비선택), 글씨는 까맣게.

## Why It Matters

- 지금 설정은 세로 스크롤 ①②③로 산만하고 디자인이 약하다. transfer + 큐로 "등록→자동 수집"이 한눈에.
- 트레이는 상주 앱의 첫 접점 — 상태가 또렷하게 보여야 한다.

## "유저가 바로 안 보내면?" (설계 확정)

강제하지 않는다. 큐에 **대기 중**으로 두고, BASE-005 상태 트래커가 그 방 **열림을 감지하는 순간 자동 수집**.
유저가 아무 것도 안 해도 언젠가 활동이 생기면 따라잡는다.

## 아직 안 정한 것

- 본인 닉네임의 견고한 소스(Profile.nickname 비어있음 — 다른 소스 조사 필요).
- 큐 재시도 정책(대기→열림 감지 시 즉시 vs 배치).
