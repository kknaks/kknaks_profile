
# 작업 요약 — tongky-quality-re1 (interpret-pwa)

기간: `2026-11-16` ~ `2026-11-16`
결과: 머지 · 배포까지 — 끊김 값(D-67 · code #13 · infra #56) · 세 참여자(D-68 ~ D-70 · code #14 · infra #57 · #58) · 사전 고유명사만(D-71 · code #15 · infra #59). 요금 실측 v2 는 문서로 남김

## 1. 무엇을 했나

통키 실기기 중국어 대화에서 손님 말이 문장 중간에 잘리고, 번역 음성이 나오는 동안 한 뒷말이 통째로 사라졌다. 끊김 상한(1000 ms)과 front 반이중(재생 중 마이크 송신 멈춤)이 원인이었다. 끊김 값을 먼저 바꿔 배포했고(D-67), 사용자가 「고객 – 통키 – 직원」 세 참여자 모델을 내놓아 반이중을 걷었다. 통키가 순차 통역사처럼 차례 끝에 말하고, 늘 듣고, 자기 목소리를 버리고, 끼어들면 물러난다(D-68 ~ D-70). 배포 뒤 대화 흐름은 사용자 표현으로 「훌륭」했지만 울쎄라 · 써마지가 사전 이름으로 한 번도 안 나왔다. 사전 170개 전부(약 2만 자 · 431짝 — Soniox 문서 한도의 두 배)가 원인으로 좁혀졌다. 고유명사 74개 · 정방향 + 역방향만(별칭 0)으로 줄여 배포했다(D-71 · 약 7천 자). 끝으로 Soniox 청구 기록으로 연결 1회 원가(42.4원 추정 → 14.55원 실측)를 다시 재 요금 문서 v2 를 만들었다.

## 2. 적용한 기술·개념

- **세 참여자 순차 통역 — 차례 끝에 말하고 · 늘 듣고 · 자기 목소리 버리고 · 끼어들면 물러난다** → [[consecutive-interpreter-turn-taking]] · 걷어 낸 앞 방식 [[half-duplex-echo-suppression]]
  - 왜 이걸 골랐나: 반이중은 되먹임을 확실히 끊는 대신 재생 중 상대 말을 버린다. 그 대가가 실기기에서 「손님 뒷말 소실」로 드러났다. 손님 쪽 TTS 를 끄는 A안(자막만)은 사용자가 「설계를 다시」로 버렸다. 통키를 통로가 아니라 대화의 세 번째 참여자로 보면, 사람 순차 통역사가 하는 네 가지 행동이 그대로 규칙이 된다. 숫자(차례 끝 1초 = 실제 무음 약 2초 · 끼어들기 = 반대 언어 토큰 2개)는 합성 63세션 조사 뒤 사용자가 골랐다
  - 무엇이 어려웠나: 자기 목소리 걸러내기에 두 겹이 필요했다. 재생 구간 안의 재생 언어 토큰을 버리고, Soniox agent text(재생 중인 문장을 미리 알림)로 모델이 스스로 빼게 했다. 멈춤 절차의 순서(`audio_stop` 먼저 · 진행 중일 때만 `cancel` · 기다림이 다른 처리를 막지 않음)와 멈춘 뒤 재생 어림을 되돌리는 자리(`Playback.cut()`)가 문서 리뷰 · 코드 리뷰에서 FAIL 로 나왔다. 실기기에서 차례 기다림 1.0 ~ 1.05초 · 되울림 버림 0 · 자기 번역 0 으로 나왔다
  - 근거: `back/app/service/interpret/turn.py` · `front/lib/outputWindow.ts` · DEC D-68 ~ D-70 · `research-turn-taking-report.md` · `review-spec-095-report.md` · `review-wp30-31-code-report.md` · `-r2-report.md` · code PR #14
- **번역 용어 짝은 「힌트」 — 사전이 클수록 덜 먹는다. 고유명사만 · 정방향 + 역방향만** → [[context-catalog-injection]] · [[translation-glossary-normalization]]
  - 왜 이걸 골랐나: 짝을 431개 실은 운영 context 에서는 울쎄라가 0/72 였고, 같은 짝 2 ~ 3개만 실으면 70/70 이었다. 순서를 바꾸기 · 지시문 · 영문 짝 빼기 · agent text 는 효과가 없었다. Soniox 문서도 `translation_terms` 를 「맞을 때만 쓰는 쪽으로 기우는」 힌트로 적는다. 사용자가 「사전에 매핑 되는 말은 그대로 나가야지」 · 「고유명사들만 지금 넣어야 하는 거 아니냐고」로 범위를 정했다. 그 뒤 「지금 너무 자세하게 쓰니까 충돌 나는 거지」로 별칭 짝도 뺐다
  - 무엇이 어려웠나: 줄일수록 좋아졌지만 매번은 아니었다. 같은 문장의 다른 영문 상표 뒤에서 울쎄라가 `Ulthera` 로 나왔고, 실기기 zh 에서 써마지가 `超声刀`(울쎄라 계열 말)로 나왔다. 사전 줄이기로 숨어 있던 시드 값도 드러났다 — zh-Hant 고유명사 둘의 이름이 일반 낱말 `雷射`(레이저)라 역방향이 「클라리티2」 로 바뀐다. 줄인 뒤 합성 결과: 울쎄라 18/18 · 리쥬란 힐러 0/6 → 6/6 · 일곱 언어 6,916 ~ 7,768자
  - 근거: `back/app/service/glossary.py` `build_context` · 시드 `.11`(`proper`) · DEC D-71 · `research-translation-terms-report.md` · `research-proper-noun-dict-report.md` · `dict-classification.md` · `wp33-context-report.md` · `review-wp33-code-report.md` W-1 · code PR #15
- **합성 음성 시험은 실기기를 대신하지 못한다 — 양쪽 다 틀린다** → [[golden-set-regression]]
  - 왜 이걸 골랐나: 숫자는 합성 음성으로 빨리 고정하고, 결정은 실기기로 닫았다(끊김 · 세 참여자 · 사전 모두 배포 뒤 사용자 실기기 1회)
  - 무엇이 어려웠나: 합성에서 「제모 → 제목」이 6/6 이라 받아쓰기 힌트를 지켜야 한다고 봤는데, 실기기에서는 3/3 「제모」였다. 반대로 합성에서 써마지 zh 가 6/6 이었는데 실기기에서는 4/4 틀렸다. ja 「써마지 → 서마지」는 사용자가 AI 음성 탓으로 판단했다. 합성 결과로 정한 결정(받아쓰기 힌트 170개 유지)은 사용자가 뒤집었고(74개만), 실기기가 사용자 쪽을 맞췄다
  - 근거: `wp33-context-report.md` B.1 · 운영 기록 2026-11-16 19:20 ~ 19:37(로컬 · 수치만) · D-55(2000 을 합성으로 시험해 1000 유지) → D-67 실기기로 뒤집음
- **원가는 추정 말고 청구 기록으로** → [[empirical-limit-probing]]
  - 왜 이걸 골랐나: 11-12 요금 설계는 연결 1회를 가장 큰 언어의 추정 토큰(42.4원)으로 잡았다. Soniox usage-logs 는 호출마다 토큰 · 청구액을 남긴다. 실기기 세션 7개의 실제 청구를 세션 · 항목별로 맞췄다
  - 무엇이 어려웠나: STT 6줄 · TTS 69줄을 세션 시작 · 발화 시각으로 맞춰야 했다(미매칭 0). agent text 가 따로 청구된다는 것(청구액 3.5%)이 이때 처음 드러났다. 연결 1회 14.55원 · 발화 1개 3.02원 · 월 2만 원(마진 50%)으로 하루 110발화

## 3. 막혔던 것 / 사고

- 코디가 추측을 사실처럼 말했다가 사용자에게 크게 혼났다(「우기지 말고」). 「2000 은 새 값」이라고 했는데 D-55 가 이미 합성으로 시험해 1000 을 남긴 값이었다. 「zh 에만 별칭이 있다」고 했는데 일곱 언어 모두에 있었다. 확인한 것과 추측을 갈라 말하는 것으로 바꿨다 — 이후 「안 재 봤어」 「추측」을 먼저 밝혔다
- 손님 쪽 TTS 를 끄는 A안을 바로 내놓았다가 사용자가 「설계를 다시」로 버렸다. 증상(재생 중 소실)을 막는 안부터 냈고, 대화 모델(누가 언제 말하나)을 먼저 보지 않았다
- 바로잡기로 사전 이름 실패를 덮을 수 있다고 봤다. 그런데 바로잡기는 알려진 틀린 꼴만 바꾼다 — `美白针` 을 넣어도 미백의 `美白` 이 보호돼 못 바꿨다. 하루치 기록에서 Soniox 가 울쎄라 · 써마지 사전 이름을 낸 것은 0회였다. 맞아 보인 것은 모두 바로잡기가 바꾼 것이었다. 엔진 입력(사전) 쪽을 고쳐야 했다
- 주간 사용량 98% 경고로 계정을 바꿨다. 워커는 새 터미널로 다시 띄웠고, 브리프 · 리포트가 파일이라 끊김이 없었다
- 마감 dry-run 이 infra 브랜치를 「미머지 의심」으로 멈췄다. 우리 변경(#59)은 머지됐고 그 뒤 main 에 다른 프로젝트 커밋(#60)이 올라와 있었다. 내용 비교 뒤 브랜치를 `origin/main` 에 맞춰 통과시켰다
- 실기기 zh 세션 하나가 Soniox 연결 10초 초과로 실패했다(청구 0 · 10초 뒤 새 세션 정상) — 원인은 안 봤다
