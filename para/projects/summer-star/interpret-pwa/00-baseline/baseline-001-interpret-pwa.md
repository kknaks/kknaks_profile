## 확인한 사실 (코디 2026-10-26)

### Procedure Hub 용어집

- `GET https://stg-procedure-hub.medisolveai.com/api/v1/glossary/matrix` — 인증 없이 JSON.
- 2026-10-26 응답: `version` `2026-07-01-reviewed-v5` · `count` 158 · `langs` `en · ja · zh · th · vi · yue`.
- 행 필드: `category` · `ko` · 언어별 표기(6개) · `source` · `verified_at` · `note`. 카테고리 15개(필러 · 보톡스 · 레이저 · 실리프팅 · 스킨부스터 등).
- 158행 모두 6개 언어 표기가 채워져 있다.

### Soniox

- 실시간 번역은 `translation.type` `two_way`(`language_a` · `language_b` 양방향) · `one_way`(`target_language` 한쪽) 두 가지. 양방향은 두 언어를 정해야 한다 — <https://soniox.com/docs/stt/rt/real-time-translation>
- `enable_language_identification` 이면 토큰마다 `language`, 그리고 `translation_status`(`original` · `translation`)가 붙는다 — 같은 문서.
- `context` 는 `general` · `text` · `terms` · `translation_terms`(`source` · `target`) 네 칸, 전체 8,000토큰(약 1만 자) 한도, 넘으면 `invalid_request` — <https://soniox.com/docs/stt/concepts/context>
- 용어집 158행으로 상대 언어 하나 기준 `terms`(ko) + `translation_terms`(ko → 그 언어)를 JSON 으로 만들면 약 8,300~9,700자(zh · yue 가 가장 짧고 th 가 가장 길다). 토큰 기준 한도 안인지는 실물 호출로만 확정된다.

### ccc 통역 원형

- cc-prototype 의 통역은 back 이 WebSocket 으로 중계한다 — 마이크 PCM → back → Soniox STT(two_way) → 자막, 확정 발화 번역문 → Soniox TTS → PCM → 스피커. TTS 재생 중에는 마이크를 멈춘다(반이중, 스피커 되먹임 방지). 근거: `orchestration/work/_archive/cc-prototype/sts-prototype/`.

### Soniox (2026-11-14 · <https://soniox.com/docs/stt/models.mdx>)

- 2026-11-03 `stt-rt-v6` 출시. `stt-rt-v5` 는 Deprecated, **2026-12-15 제거**(뒤로는 v6 로 자동 연결). v5 와 API 호환 — 모델 이름만 바꾼다.
- v6 변경 중 관련: 「More accurate real-time translation that adjusts how much speech it gathers before translating」 · 「gets more out of the context you provide」 · 이름 · 전문 용어 인식 향상.
- 지금 설정 `max_endpoint_delay_ms: 1000`(범위 500 ~ 3000 · 기본 2000 — 2026-10-10 조사 `research-soniox-report.md`). `endpoint_sensitivity` · `endpoint_latency_adjustment_level` 미사용. context `text`(자유 서술) 칸 미사용.

## 확인한 사실 (코디 2026-11-16)

### 실기기 zh 세션 둘 (운영 기록 · 문장은 로컬만)

- **11:00 세션(끊김 1000)**: 손님 쪽 확정 발화 가운데 문장 중간에서 잘린 것 6. 잘린 뒤 이어 한 말은 기록에 없고, 손님이 같은 질문을 처음부터 다시 말한 것이 2번.
- **11:39 세션(D-67 — 끊김 2000 · -0.3 배포 뒤)**: 손님의 두 문장이 한 발화로 확정됐다(중간 잘림 줄어듦). 그러나 그 번역 음성이 재생되는 동안 손님이 이어 한 말은 기록에 없고, 다음 발화는 조각 하나(두 낱말)뿐이다.
- 원인은 둘이 겹친다. ① Soniox 는 문장 경계에서 발화를 확정한다(말이 이어져도). ② 확정되면 곧바로 번역 음성이 나가고, front 는 재생 동안 마이크 소리를 보내지 않는다(반이중 · `front/lib/interpret.ts` 송신 조건 · `front/lib/halfDuplex.ts` — 재생 끝 +400 ms 재개). ②가 잘린 뒤의 말을 버린다.
- 반이중은 cc-prototype 에서 `echoCancellation` 이 폰 스피커 · Web Audio 재생 소리를 못 빼 번역 음성이 다시 번역되는 루프가 나서 들인 것이다. 그때 「재생 중 상대 말은 버려진다」를 대가로 받아들였다(개념 `half-duplex-echo-suppression`).
- 루프는 **양쪽 재생이 다 있어야** 돈다. 그리고 다시 들어온 소리는 **언제나 지금 재생 중인 언어**다. 한 사람이 이어 말하는 경우 그 말은 재생 언어와 반대 언어다.
- Soniox 는 토큰마다 언어를 붙인다(two_way · 기존 `assembler` 가 원문 언어로 side 를 정함).

### Soniox 끊김 값 (2026-11-16 · <https://docs.soniox.com/stt/rt/endpoint-detection.mdx>)

- 끊김은 소리 없음만이 아니라 멈춤 · 억양 · 문맥으로 정한다(semantic endpointing). `max_endpoint_delay_ms` 는 **상한**(500 ~ 3000 · 기본 2000) · `endpoint_sensitivity` 는 낮출수록 덜 끊음(-1.0 ~ 1.0 · 기본 0.0).
- 운영 키로 실물 연결 1회: 2000 · -0.3 오류 없음 · 범위 밖 값(5)은 거절.
