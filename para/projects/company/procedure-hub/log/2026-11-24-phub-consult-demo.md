## 1. 무엇을 했나

명동점 KOS 진료항목 324 개를 허브 케이스에 매핑하고(v3 매핑 JSON), 그 위에 「명동점 전용 상담 실장 봇」 을 올렸다 — 얼굴 점 · 진료항목 목록 · 모달 · 주제 · 장바구니 기초. 허브 데이터는 케이스 단위 시술 · 고민 → 케이스 연결 · 부작용 분류로 보강했다. 11-23 답 한 턴 입력이 9만 ~ 41만 토큰이라 원인을 재고(SPEC-011 · 실물 입력 −51%), 이어 「상담 품질」 을 22 기준 · 13 시나리오 × 3 = 192 턴 측정으로 정의해 구멍 H1 ~ H16 을 고쳤다(SPEC-012). 측정에서 허브 데이터 구멍 3(입꼬리주름 0 · 팔자 필러 없음 · 타이트닝 3)이 나와 데이터를 고치고 stg 에 다시 실었다.

## 2. 적용한 기술·개념

- **품질을 기준표 × 시나리오 × 반복 실측으로 정의** → [[golden-set-regression]] — 「잘 나왔다」 대신 기준 22 개 · 정답표(허브 · 매핑 값으로만 · 사람 확인 칸 분리) · 같은 대화 3 번 돌려 흔들림까지 센다
  - 왜 이걸 골랐나: 비용 작업에서 「예전 답이 말하던 정보를 지금도 말하나」 만 보다 사용자 기준(상담 품질 — 의도 · 말 바꾸기 · 주제 나누기)과 어긋났다. 기준을 사용자와 먼저 닫고, 측정을 기계 판정으로 만들었다.
  - 무엇이 어려웠나: 채점 규칙이 너그러워 수치가 부풀었다(「확인이 필요」 를 정규식이 놓쳐 100% → 85%). 검수가 원 답을 직접 판정해 잡았다. 전 · 후 비교는 **같은 gold · 같은 정답표 · 같은 채점 판** 이어야 한다(gold 해시를 meta · 정답표에 박고 다르면 멈춤).
  - 근거: `quality/QUALITY.md` · `quality/base-report.md` · `review-quality-base.md` · `quality/after6-report.md`
- **측정 범위는 「바뀐 파일이 어느 호출에 실리나」 로 정한다** — 부분 측정으로 시간을 아끼려다 1차 프롬프트(모든 턴에 실림)를 바꾼 뒤 30/192 턴만 재 검수 FAIL
  - 근거: `review-spec-012-code-r4.md` P1-1
- **데이터를 더했는데 목록이 줄 수 있다(상위 넓힘 규칙)** — 허브 `concern-candidates`(`upper=auto`)는 직접 줄이 0 일 때만 상위 고민으로 넓힌다. 볼 주름에 직접 근거 4 줄을 넣자 16 → 6
  - 왜 이걸 골랐나: 「품질 그대로」 원칙으로 그 4 줄을 보류하고, 같은 꼴을 전수로 셌다(이번 묶음 때문에 줄어든 고민 0).
  - 근거: `data-gap3-report.md` v1.4 · `upper_survey.py` · `review-data-gap3-r4.md`
- **판단은 LLM · 사실은 앱 · 낱말 판정 금지** → [[prompt-engineering]] — 「~돼?」 같은 동형 어미로 물음을 가르니 평서문을 얼렸다(「관심이 있어」). 뜻은 1차 소넷 출력 · 데이터(이름 일치 · 포함 관계)로만
  - 근거: `review-spec-012-r2.md` P1-A · `SPEC-012-consult-quality.md`
- **허브 stg 일회성 적재 반복** → [[seed-data]] — 머지 → 승격 PR → CD(alembic head) → VM 에서 같은 이미지로 dry-run → 한 트랜잭션 적재 → 재시작 → `gold/health` 해시 확인. 앞 작업 절차서 그대로 두 번째로 돌았다.
  - 무엇이 어려웠나: macOS tar 가 `._*` 파일을 실어 SVG 가 242 로 보였다(VM 에서 지움). DB 백업을 먼저(`stg-pre-consult-demo-20261124.dump`).
  - 근거: `_archive/procedure-hub/phub-gold-jev/stg-runbook.md` · PROCEDURE-HUB #35 · #36

## 3. 막혔던 것 / 사고

- **고침 루프가 끝나지 않음** — 고칠 때마다 다른 곳이 조금씩 흔들려(1차 출력 표본) after1 ~ after6 여섯 번 실측(회당 약 40 분 · $17). 멈춤 기준(코드 탓 하락 0 이면 마감 · P2 는 넘김)을 처음에 정하지 않았다 → 사용자 「언제까지 고치냐」 → 마지막 회차에 기준을 박고 끝냄.
- **원인이 구조인데 증상마다 규칙을 더함** — 앱이 「이번 말의 대상」 을 앞 상태와 합치는 규칙(교체 · 추가 · 되돌림 · 좁힘 · 넓힘)을 말투마다 쌓았다. 192 턴은 통과했지만 시나리오 밖 말(「같이 보톡스도」)에서 울쎄라가 빠지고 목록 0 · 「제대로 짚지 못했어요」. 사용자 「밑도 끝도 없다」 → 다음 작업: 1차가 지금 원하는 선택 전체를 내고 앱은 데이터 확인만.
- **코디가 발주를 승인 없이** — 「이게 어려워?」 를 승인으로 읽고 한도 없애기 · 가격 빼기를 발주했다가 취소(11-23). 질문 · 짜증 ≠ 승인.
- **워커가 조용히 멈춤** — 검사 하나(silver-check · 스크래치 180MB 복사본)가 30 분 넘게 안 끝나 워커가 기다림 · 컴퓨터 잠자기 · 세션 재시작으로 워커 셋이 꺼짐. heartbeat 만 보고 「진행 중」 이라 말했다 → 터미널을 직접 열어 확인하기로.
- **토큰 원인을 Jev 문서를 안 읽고 단정** — 「Jev 로는 안 풀린다」 → 정정. 원 문서부터 연다.
