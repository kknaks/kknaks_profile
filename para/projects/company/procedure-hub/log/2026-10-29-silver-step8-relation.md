### 1-2. 원천끼리 말이 달랐다

같은 계열 쌍에서 먼저 할 쪽 · 같은 날 가능 여부 · 간격 숫자가 원천마다 달랐다. 예: 보톡스 ↔ HIFU 는 synergy 「보톡스 2주 후 리프팅」(보톡스 먼저) ↔ 원칙 · 규칙 · 최적화 13건 「HIFU 먼저」. 순서 · 간격 · 같은 날 충돌이 계열 쌍 19 · 확인 조건 등급 충돌이 76(같은 계열 · 같은 조건인데 원천마다 금기 · 주의 · 확인만이 다름)이다.

### 1-3. 관계 말고도 자리 없는 안전 · 상담 원천이 있었다

- **확인 조건**: 사전 체크(pre-procedure-checklist) · 동의서 필수 고지(consent-checklist) · taxonomy 금기 칸이 「임신」 · 「항응고제」 · 「켈로이드」 같은 사람 조건을 문장으로 적는다. 시술↔시술이 아니라 사람↔시술이다.
- **합병증**: complications 원천이 계열마다 합병증 이름 · 중증도 · 발생률 · 처치 · 예방을 적는다. 원천이 있는 계열은 일부뿐이다.
- **위험지대**: anatomy-danger-zones 가 부위마다 혈관 깊이 · 신경 · 조직 두께 · 요령을 적는다. 10-28 결정으로 부위 노드에 붙이지 않고 안전 정보로 두기로 했다.
- **근거**: 문헌(PMID) · 근거 문장 · 웹 출처 · 가이드 표기가 칸마다 다른 꼴로 있다.

## 3. 정한 규칙

1. **쌍 하나에 엣지 하나 + 주장 칸.** 끝점 쌍마다 엣지를 하나 세우고, 원천 주장은 칸으로 쌓는다 — 원천 · 원문 · 종류 · 원문 등급 + 사이트 라벨 · 간격 · 먼저 하는 쪽 · 이유 · 조건 · 근거(G1 · D-03 · 10-26 「시너지 · 순서 · 간격 · 금기 = 엣지 하나의 속성」).
2. **끝점은 원천 이름이 가리키는 만큼.** 시술군 코드는 계열 끝점(단위 시술은 조회 때 상속), 이름은 5단계 정본으로 풀어 하나면 이름 일치 · 여럿이면 후보 전부. 「대신」은 대체(택 1)로 세고 시너지로 세지 않는다(G2 · G3).
3. **게이트 없음.** 화살표 문장 · 원칙 · 규칙 · 위험 문장의 쌍도 문장 패턴(`sentence.patterns`)으로 결정론 처리한다. 행별 대응표(manual_map)를 두지 않는다. 규칙으로 하나로 안 정해지는 것만 원천 질문(U8-1 (나)).
4. **간격 낱말 사전.** 원문의 간격 낱말마다 읽는 갈래가 하나 있다.

   | 원문 | 칸 |
   |---|---|
   | N일 · N주 · N개월(후 · 이상 · 간격) | days [하한, 상한](일) · 「이상 · 후 · 뒤 · 최소」면 open_high |
   | 택 1 | 종류 대체(택 1) · 간격 비움 |
   | 동시 금지 · 같은 날 불가 · 당일 금지 | same_day false |
   | 같은 날 가능 · 당일 병행 · 동시(금지 없이) | same_day true |
   | 직후 · 즉시 | same_day true · days [0, 0] |
   | 별도 세션 | same_day false |
   | 같은 부위 · 동일 부위 | 조건 「같은 부위」 |
   | …전에 | first 만 |
   | 사이사이 | 반복 표시 · 간격 없음 |
   | 반복 · 매회 · N회 | 반복 · 회차 표시(간격 아님) |
   | 의료진이 … 평가해 간격 결정 | 간격 없음 + 의료진 판단 표시 |
   | …에 한해 · 순서 유연 · 순차 | 조건부 표시 · 순서 유연 표시 · 원천 순서로 first |

   원문에 간격 낱말이 있는데 숫자 칸 · 표시가 비면 open 이다(사전 갈래를 빼면 걸린다).
5. **숫자 칸만 읽는다(reading_contract).** 추천 · AI 는 `interval.days` · `interval.first` · `interval.same_day` 만 읽는다. 원문 `interval.text` 는 보관만 한다. 사용자가 물은 것 — 「2주 후를 AI 가 알아들을 수 있을까」 — 에 대한 답이 이 규칙이다.
6. **하위 조건별 값(by_sub_condition).** 원문이 하위 조건으로 갈리면(「비박리: … / 박리: …」) 겉 칸을 비우고 by_sub_condition 표시를 단다. 읽는 쪽은 options 의 하위 조건별 값을 읽는다. 하위 조건 없는 「또는」(「같은 날 또는 2주」)은 감싼 범위를 겉 칸에 그대로 둔다.
7. **충돌은 보존.** 순서 · 같은 날 · 간격 · 조건 등급 · 대기 기간이 원천끼리 다르면 전부 남기고 엣지에 충돌 표시를 단다. 고른 값을 담는 칸은 두지 않는다(D-13b · 6단계 꿀광토닝 선례). 대표 충돌은 의료진 질문으로.
8. **피함 엣지.** 「기미에 고에너지 레이저 금지」 같은 고민 조건 금기는 확인 조건 노드를 따로 세우지 않고 7단계 고민 노드 → 단위 시술의 새 엣지 종류 「피함(금기 조합)」으로 둔다. 고민 낱말은 고민 노드 하나만 가진다(7단계 W3 교훈 · U8-2 (가)). SPEC-004 엣지 타입 개정은 빌드 때.
9. **한정어가 붙은 묶음 끝점은 조건부.** 끝점 원문에 출력 · 깊이 한정어(고출력 · 고에너지 · 고강도 · 강한 · 박리성 · 어블레이티브 · 심부)가 있는데 끝점이 이름 일치 단위 시술이 아니라 묶음(계열 · 기법 · 하위 계열 · 부위 …)으로 열렸으면 「조건부 — 단위 시술 미특정」 · 기본 상속 · 기본 응답에서 뺀다 · 한정어 원문 보관 · 원천 질문. 피함 · 간격 금기 · 같은 날 불가 · 조합 금기 · 확인 조건 모두 같다. 5단계 키에 출력 · 깊이 칸이 없어 한정어로 좁힐 수 없기 때문이다.
10. **확인 조건 = 사람 조건 원장.** 조건 노드 53 은 결정 파일의 사전 · 패턴으로 잡는다. 원문 등급은 그대로 두고 3분류(금기 · 주의 · 확인만)를 덧붙인다. 상담 · 시술 준비 · 고지 문장은 조건 엣지가 아니라 계열 원문 속성이다(G10).
11. **안전은 계열에 붙여 상속.** 합병증은 계열마다 노드 · 원천 없는 계열은 gap. 위험지대는 주의 엣지 속성 · safe_layers 는 4단계 참조(복사 안 함). 필수 고지는 원문 그대로(쪼개지 않음)(G11~G13).
12. **근거 강도는 원문 등급만.** 숫자를 만들지 않는다. URL 없는 출처 문자열은 웹이 아니라 「원문 출처 문자열(내부 · 통설)」, 「;」로 이은 URL 은 multi_url 표시만(G14 · 검수 W2).

## 5. 틀렸던 것 · 배운 것

### 5-1. 한정어를 떼고 계열 전체로 연 피함 — 검수 F1

- **무엇**: 피함 엣지 3(「기미 환자에 **고출력** 레이저 …」 · 「기미에 **고에너지** 레이저 금지」 · 「**고출력** 레이저 금지」)의 끝점이 레이저 계열 전체였다. 「고출력 · 고에너지」는 끝점을 풀 때 앞 낱말로 떼어져(`strip_prefix`) qualifier 글자로만 남았다.
- **왜 문제인가**: 계열 끝점은 조회 때 계열의 단위 시술 전부가 상속된다. 그러면 「기미 → 토닝 = 피함」이 된다. 7단계에는 기미 → 얼굴 전체 토닝 등 레이저 단위 시술 추천 엣지가 있고, 같은 원문은 「저출력 토닝만 권장」이라고 말한다. 충돌 표시도 질문도 없었다.
- **바로잡음**: 한정어가 붙은 묶음 끝점은 「조건부 — 단위 시술 미특정」 · 기본 적용 제외 · 의료진 질문. 같은 성격 전수로 「심부 필링(페놀)」 · 「심부 필링(TCA 50%+)」 · 「이소트레티노인 ↔ 박리성 레이저 · 심부 필링」도 걸렸다. 「IPL 단독 · 고출력」은 IPL 단위 시술 하나로 이미 좁혀져 그대로 둔다.
- **배운 것**: **끝점을 풀려고 뗀 낱말이 끝점의 범위를 정하는 낱말일 수 있다.** 떼어 낸 수식어는 버리지 말고 「이 낱말로 좁혀야 하는데 좁힐 칸이 없다」를 표시로 남긴다. 금기는 넓게 열면 안전해 보이지만, 넓게 연 금기가 추천을 뒤집는다.

### 5-2. 하위 조건이 섞인 겉 칸 — 검수 F2(안전 쪽 오독)

- **무엇**: 원문이 하위 조건으로 갈리는 주장 2건에서 겉 숫자 칸이 하위 조건을 감싼 범위였다. 보톡스 ↔ 레이저는 「비박리: 같은 날 가능(레이저 먼저) / 박리 CO2 · Er:YAG: 3일~1주」인데 겉 칸이 same_day true · first 레이저 · days [0, 7]. 숫자 칸만 읽으면 박리 CO2 + 보톡스도 「같은 날 가능」이다. 콜라겐 부스터 ↔ 레이저는 「논어블레이티브 2~4주 / 어블레이티브 3~4개월」인데 겉 칸 days [14, 120] 이라 어블레이티브 하한이 2주로 읽혔다.
- **원인**: apply 가 하위 조건 있는 options 도 「또는」처럼 범위를 감싸고, same_day 는 하나라도 true 면 true 로 뒀다. 「숫자 칸만 읽는다」는 규칙을 세워 놓고, 숫자 칸이 원문의 일부만 담는 경우를 정하지 않았다.
- **바로잡음**: 하위 조건이 서로 다르면 겉 칸을 비우고 by_sub_condition 표시 · 읽기 규칙(reading_contract)에 「겉 칸이 비고 by_sub_condition 이면 하위 조건별 값을 읽는다」를 더함. 하위 조건 없는 「또는」 5건은 그대로.
- **배운 것**: **「이것만 읽는다」는 규칙을 세우면, 그 칸이 원문 전체를 대표하지 못할 때 무엇을 하는지도 같이 정해야 한다.** 합쳐서 하나로 만든 값은 덜 안전한 쪽으로 기운다 — 비워서 「갈라 읽어라」고 알리는 편이 맞다.

### 5-3. 처음 게이트 88 설계 — 7단계 · 8단계 조사

- **무엇**: 7단계는 「완전 일치만 자동 · 나머지는 사람 확인」으로 대응표 88 행을 게이트에 올렸다. 8단계 조사도 같은 꼴로 수작업 대응 38 · 화살표 분해 48 = 86 을 unconfirmed 게이트로 추천했다(U8-1 (가)).
- **드러남**: 사용자가 질문 페이지 게이트 탭을 보다가 「다 각각 고민 목적으로 가면 되는 거 아니야」 — 88 은 사람이 판단할 일이 아니라 **규칙이 없어서** 생긴 것이었다. 같은 성격 행의 추천이 서로 어긋나 있었다(「처짐/탄력」 → 처짐 하나 · 「탄력 저하」 → 처짐 + 탄력).
- **바로잡음**: 7단계는 규칙 R12~R20 으로 88 → 13 → 0. 8단계는 U8-1 (나)로 게이트 0 · 문장 패턴 · 간격 사전.
- **배운 것**: **「사람 확인」은 판단이 필요한 곳이 아니라 규칙을 아직 안 쓴 곳에 쌓이기 쉽다.** 게이트 행이 많으면 먼저 같은 꼴끼리 묶어 규칙으로 쓸 수 있는지 본다. 규칙으로 안 되는 것만 질문으로 남기면 질문이 짧고, 답이 오면 그 줄만 고친다.
