## 0. 한 장 요약

- **골드 = 규칙을 다 적용한 그래프 + 그 위를 탐색하는 허브 도구.** 미리 만든 카드 묶음이 아니다. 허브는 병원과 무관하게 고정이고, 병원 상품(KOS)과의 연결은 앱 쪽 연결 층이다. 허브에는 LLM 이 없다.
- **조사**: 골드 규칙 17 · 상담 의도 12 · 허브 도구 9 · 의도별 탐색 경로 11 · 펼친 뒤 엣지 24,392 · 결정 묶음 6(D-01~D-18) · 사용자 판단 3(U-1~U-3).

- **기록만**: KOS 연결 조사(K1~K8) · 허브 평가 실험(골드 뒤).
- **다음**: SPEC-005 · WORK-003 — 작성 · 검수 FAIL 5 → 수정 → 재검수 진행 중(10-30 기준).

## 1. 골드가 무엇인가

**무엇을 · 왜**: 「골드」를 무엇으로 볼지가 먼저 정해져야 규칙 · 도구 · 스펙이 정해진다. 처음 생각과 사용자가 정한 것이 달랐다.

메달리온(10-26 방향): 브론즈(원천 JSON 21개) → 실버(개체 원장 1~8단계) + 시맨틱(읽는 정본) → **골드**(상담에 바로 쓰는 층).

| 질문 | 정한 것 | 출처 |
|---|---|---|
| 골드는 미리 만든 「카드 묶음」인가 | **아니다 — 실버 · 시맨틱에 규칙을 다 적용한 그래프**이고, 질문이 오면 허브 도구가 그 위를 탐색한다. 규모상 탐색이 ms 단위라 미리 묶을 이유가 없다(조사 실측: 추천 4 질의 0.54ms) | _RESUME §2 10-30 「골드 = 규칙 적용 그래프 + 허브 도구 탐색」 · 사용자 「그래프 탐색은」 |
| 병원이 바뀌면 허브도 바뀌나 | **허브는 고정 · 병원 무관.** 병원 상품은 표준 꼴 + 소스별 어댑터(KOS 가 첫째) → **연결 층**(앱 쪽). 허브에 없는 건 「허브 보강 후보」 목록만 | 같은 행 · 사용자 「병원 바뀌어도 허브는 안 바뀜」 |
| 상담 앱은 어떻게 생겼나 | 유저 질문에 빠르고 정확하게 — Jev(빠른 슬롯 추출) 뼈대 · Claude 가 답 생성 · **허브에는 LLM 없음**. 화면 = 채팅 + 왼쪽 얼굴 지도에 부위별 추천 시술 · 설명 · 병원 상품(디자인 `reference/2026-10-30-chatry-sample`) | _RESUME §2 10-30 「목표 · 아키텍처(사용자)」 |

그래서 골드 조사는 「카드를 몇 장 만드나」가 아니라 **「어떤 규칙을 적용해 그래프를 펼치고, 어떤 도구가 어떤 경로로 탐색하나」** 를 물었다. KOS 연결 조사는 같은 시각 별도 워커로 돌렸다(사용자 「응 발주해」).

## 2. 골드 조사 요약

**무엇을 · 왜**: 지금 실버 json 으로 직접 계산해 골드의 규칙 · 도구 · 경로를 추천안으로 만들었다(읽기 전용 · 추정 없음). 숫자는 `gold-research.json`.

### 2-1. 상담 샘플 → 허브 호출

샘플 상담(S3p 11단계)을 장면마다 허브 호출로 옮겼다 — 「이마 주름」 → 고민 → 추천 / 「소프웨이브는 어떻게 하는 거예요」 → 시술 카드 / 「사우나 가도 돼요」 → 사후관리 / 「셋 다 같이 해도 돼요」 → 쌍 확인 / 「6주 전에 보톡스 맞았는데」 → 이전 시술 경과. 가격은 허브가 아니라 연결 층.

### 2-2. 의도 12 · 도구 9 · 경로 11

| 의도(상담 질문 종류) | 도구 |
|---|---|
| I-01 고민 → 추천 | T2 recommend |
| I-02 설명 · I-03 사후관리 · I-04 부작용 · I-05 회복 · I-10 용량 · 제품 | T3 procedure_card(칸 골라 받기) |
| I-06 비교 | T6 compare |
| I-07 같이 · 순서 · 간격 · I-08 이전 시술 뒤 | T4 pair_check |
| I-09 나한테 해도 되나(확인 조건) | T5 check_conditions |
| I-11 추천 조합 · 패키지 | T7 combos |
| I-12 가격 | — (연결 층) |
| 공통 | T1 resolve(말 → 노드) · T8 neighbors(정해 둔 경로 밖 · 홉 제한) · T9 vocab(Jev 슬롯 선택지) |

도구는 REST · MCP 가 같은 코어를 쓰고 결정론이다. 의도마다 탐색 경로 P-01~P-11 을 지금 데이터로 따라가 값을 적었다(예: 「턱선 처짐」 → 턱선 HIFU · 턱선 실리프팅 · 턱선 보톡스).

## 3. U-1 ② — 부위 고민에 얼굴 전체 층도 같이

**무엇을 · 왜**: 「턱선 처짐」을 물으면 턱선 시술만 낼지, 얼굴 전체 시술(소프웨이브 · 얼굴 전체 HIFU …)도 낼지. 샘플 상담은 후자를 했다.

| 보기 | 턱선 처짐이면 |
|---|---|
| ① 가까운 층만(R21 그대로) | 턱선 HIFU · 턱선 실리프팅 · 턱선 보톡스 3 |
| **② 가까운 층 + 얼굴 전체(층 표시 다르게)** — 추천 | 3 + 얼굴 전체 8(조사 당시 판) |

사용자 「데이터 단계에서는 U-1 만 · 추천으로」(_RESUME §2 「골드 U-1 = ② 추천대로」). 붙은 조건: **하위 계열은 원천 제품으로 거른다**(품질 원인 N). 실버에서는 7단계 R32(엣지 `layer` = 부위 · 상위 · 없음)와 R31(원천 제품 → 하위)로 들어갔다. 뒤집으려면 「상위」 엣지를 빼는 규칙 하나다.

> 관찰(판단 아님): R31 뒤 지금 판에서는 추천 엣지 중 SUPERB 초음파(소프웨이브)로 가는 것이 0 이다 — 원천 「리프팅기기(울쎄라 · 써마지)」가 하위를 HIFU · RF 로 정해서. U-1 을 고른 근거였던 샘플 장면이 지금 데이터로는 안 나온다. 골드 E2E · 샘플 대조 때 볼 거리(`2026-10-30-quality-eval.md` §13).

## 7. KOS 연결 — 기록만

**무엇을 · 왜**: 병원 상품(KOS 명동점)이 허브와 어떻게 이어지는지 조사했지만, 지금은 반영하지 않는다 — 「kos 는 일단 기록만 · 허브 데이터 유효한지 품질 측정 테스트가 먼저」(사용자).

- 구조 차이: 허브 단위 시술은 「계열 × 부위 × 기법」(제품 무관), KOS 시술은 이름 하나(제품 · 용량은 진료 항목이 가짐) → 시술 ↔ 단위 시술 · 약제 · 장비 ↔ 제품으로 따로 잇는 게 맞는 짝
