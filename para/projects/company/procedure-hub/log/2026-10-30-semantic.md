## 1. 왜

### 1-1. 층 정의 — 시맨틱이 무엇인가

메달리온 방향(10-26)은 브론즈(원장 JSON) → **실버(개체 원장) + 시맨틱(관계 엣지 + 메타데이터)** → 골드였다. 시맨틱 = 업무 용어 · 개체 사이 관계 · 읽는(계산) 기준 · 동의어와 실제 데이터 대응을 한 정본으로(정의 `para/resources/note/db/2026-09-10-data-medallion-overview.md`).

10-29 사용자가 빌드 앞 순서를 정했다 — 연결 구조 HTML → **시맨틱 정의 확정** → 골드 규칙(최종 판단 한 표) → SPEC-005 → 적재 · 골드 · REST · MCP → E2E. 골드 규칙은 이번 범위가 아니다. 시맨틱은 골드에 넘길 「상속 규칙 정의」까지만 한다.

### 1-2. 흩어진 사전 · 흩어진 규칙

| 무엇 | 실버 1~8단계에서 | 문제 |
|---|---|---|
| 노드 · 엣지 종류 | 각 단계 json 의 칸 · 페이지 뽑기(노드 14 · 엣지 32) | 같은 「계열」 이름이 두 뜻(제품 계열 판정 · 단위 시술 키) · 「출처」 3종 · 「상위 고민」 한 종류에 상하와 옆 관계가 섞임 |
| 동의어 | 14곳 — 제품 이름 · 계열 동의어 · 부위 사전 · 기법 이름 · 단위 시술 동의어 · 패키지 동의어 · 고민 · 목적 이름 · 대응표 · 고민 규칙 사전 · 7단계 resolver · 8단계 resolver · 조건 패턴 · 간격 사전 · 문장 패턴 | 같은 낱말을 7단계 resolver 는 단위 시술로, 8단계 alias 는 계열 + 조건으로 풂(31 중 17 대상 다름) · 「비타민C」 = 7단계 단위 시술 · 8단계 시술 아님 |

### 1-3. 부작용 ≠ 합병증(사용자 10-29)

사용자 「합병증이랑 부작용은 다른 거잖아」. **부작용** = 흔한 예상 반응(멍 · 부기) · **합병증** = 예상 밖 이상 결과(혈관 폐색 · 감염). 그런데 실버 8단계 합병증 노드 65 중 severity mild 가 38 — 절반 넘게가 흔한 예상 반응이었다. 합병증 gap 17계열을 부작용 문장으로 메우지 않는다는 것도 같이 정했다.

## 5. 틀렸던 것 · 배운 것

### 5-1. 페이지 뽑기를 정본으로 볼 뻔했다

연결 구조 페이지의 노드 14 · 엣지 32 는 그림을 그리려고 뽑은 것이다. 실버 칸에서 다시 보니 「끝점 묶음」은 실버에 노드가 없었고(문자열), 「상속 후보」는 저장 엣지가 아니라 조회 결과였고, 관계 주장의 출처는 엣지가 아니라 주장 칸이었다. **그림은 정본이 아니다 — 정본 칸에서 다시 센다.**

### 5-2. 같은 이름이 같은 뜻은 아니다

「계열」 엣지 둘(제품 → 계열 · 단위 시술 → 계열)은 이름이 같아도 하나는 판정, 하나는 정체(키)였다. 반대로 이름이 다른 「출처」 셋은 한 뜻이었다. 합칠지 나눌지는 이름이 아니라 칸(판정 · 근거 칸이 있나, 바뀌면 정체가 바뀌나)으로 정했다.

### 5-3. 사전 겹침을 다 「겹침」으로 셌다

조사 판은 겹침 147 이었다. 그중 7단계와 8단계가 같은 낱말을 다른 수준(단위 시술 · 계열 + 조건)으로 푼 것은 대상이 다른 게 아니라 **수준이 다른 것**이었다. qualifier 로 합치니 겹침에서 빠졌다. 남은 겹침은 갈래(A ~ J)마다 처리(전부 · 후보)가 정해져 있다.

### 5-4. 합병증 셈에 흔한 반응이 섞였다

합병증 노드 65 의 절반 넘게(mild 38)가 멍 · 부기 같은 흔한 반응이었다. severity 는 원천 칸이라 결정론으로 나눌 수 있었다. 경계에 걸린 9건(mild 인데 「흔함」 낱말이 없음)은 추정하지 않고 의료진 질문으로 남겼다.
