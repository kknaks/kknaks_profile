## 1. 무엇을 했나

피부 상담 목업(#98) 큰 화면에 「분석 결과 → 추천 시술」을 얹었다. 시술 정보는 사내 Procedure Hub(stg, 인증 없는 `GET /api/*`)에서
받아 스냅샷(`hub-snapshot.json`)으로 넣었다. 왼쪽 3D 패널 안 얼굴 좌우에 부위 카드 6장을 두고, 카드마다 얼굴 표면의 앵커 점과
지시선으로 잇는다. 카드에는 3D 텍스처에서 잘라 낸 부위 확대 사진 · 등급·점수 · 시술 탭 · 간단 설명이 있고, [자세히] 가 원리·금기·
효과 시점·사후 관리 모달을 연다. `reference/2026-10-21-charty-poc/web/`.

## 2. 적용한 기술·개념

- **3D 표면 앵커를 화면 지시선으로** [[surface-anchor-leader-line]] — 메시 위 점 6개를 매 프레임 투영해 DOM 카드와 SVG 선으로 잇는다
  - 왜 이걸 골랐나: 시안(2D 사진 위 콜아웃)과 달리 얼굴이 돈다. 좌표를 화면에 박으면 회전 때 점이 피부를 떠난다. 메시 좌표 + 투영이면 점이 피부에 붙어 따라가고, 얼굴 뒤로 넘어간 점은 raycast 로 가림 판정해 흐린다
  - 무엇이 어려웠나: ① 점이 회전 중 한 프레임 늦었다 — `Vector3.project(camera)` 는 `matrixWorldInverse` 를 쓰는데 그 값은 `gl.render` 안에서 갱신된다. OrbitControls 가 이번 프레임에 바꾼 카메라가 아니라 지난 프레임 행렬로 투영했다. 워커 실행에선 통과하고 리뷰어 실행에서 1.16px 로 깨지는 flaky 로 드러났다 → useFrame 첫 줄 `camera.updateMatrixWorld()`. 시험 기준(1px)은 그대로 두고 3회 반복 통과 ② 터미널 에이전트는 얼굴을 보며 클릭할 수 없다 → `__faceViewer.pickAt(cx, cy)`(캔버스 px raycast → `{p, n, uv}`)로 스크린샷 좌표를 찍는 경로 ③ 디버그 훅 객체를 다른 컴포넌트가 통째로 다시 만들어 키가 지워졌다 → `Object.assign` 으로 덧붙이기 ④ `data-visible` 을 스무딩된 현재값으로 재면 0 에 닿지 않는다 → 목표값 기준
  - 근거: `web:src/components/viewer/anchor-projector.tsx` · `code-review-report.md` F-1 · `spec-review-report.md` W-4·W-7·W-10 · `e2e/areas.spec.ts` R-12~R-16
- **UV 아틀라스에서 부위 잘라 보이기** [[uv-atlas-overlay]] 보강 — 앵커의 `hit.uv` 로 텍스처 둘레를 CSS `background-position/size` 로 잘라 카드 썸네일에
  - 왜 이걸 골랐나: 본인 얼굴이라 잘라낸 이미지를 파일로 남기면 안 된다. 런타임 CSS 크롭이면 산출물이 없고, 필터 텍스처를 그대로 따라간다. 오버레이(주름·모공)는 PNG 알파를 `mask-image` 로 써서 셰이더와 같은 합성
  - 무엇이 어려웠나: 반경 120 텍스처 px · 64px 로는 「피부색 판」이라 사용자가 「안 보인다」 → 반경 200·280·360 을 잘라 비교해 **부위별 반경 + 중심 이동**(눈가는 눈·눈썹, 팔자는 코 옆~입가가 들어오게)으로 바꾸고 96px. 흐림 opacity 를 부모에 주면 곱해져 사진까지 사라진다 → 사진 칸만 따로 감싸 0.75
  - 근거: `web:src/components/screen/area-crop.tsx` `CROP_FRAMES` · `fe-report.md` 2루프 U-4 · 3루프 V-3 · `screens/loop3-crops.png`(gitignore)
- **하위 항목에 없는 값은 상위로 대체하고 단위를 표시** [[labeled-upward-fallback]] — Hub 는 modality → subcategory → item 3단. 카드 시술명(V빔·엑셀V…)은 item 이고 item 이 자기 설명을 갖지만 금기·시술 시간 같은 칸은 비어 있다
  - 왜 이걸 골랐나: 비면 숨기기(정보 손실) · 상위 값을 조용히 쓰기(V빔 금기인 척 레이저 전체 금기) 둘 다 틀렸다. 상위 값을 쓰되 섹션마다 「레이저 전체 기준」을 붙여 **어느 단위의 사실인지**를 화면에 남겼다. subcategory 는 extracted 가 null 이라 건너뛴다
  - 무엇이 어려웠나: 「Hub 에 V빔 단위 정보가 있나」를 코디는 modality 단위만 보고 「모달이 레이저 전체 설명이 된다」로 잘못 예측했다 — planner 가 item 에 extracted 가 있음을 실물로 확인해 대부분 시술명 단위가 됐다. 프락셔널레이저처럼 item 노드가 없는 것만 전부 상위
  - 근거: `web:src/data/hub/hub.ts` `modalSections` · `SPEC.md` §4-3 · `hub-snapshot.test.ts` R-5

## 3. 막혔던 것 / 사고
