## 1. 무엇을 했나

M3D(미가메디) 3D 피부 스캐너 리포트를 재구성해 피부과 상담용 화면 2개를 목업으로 만들었다.
큰 스크린(상담사+고객이 함께 봄: 실제 3D 얼굴 + 필터 / 분석 그래프 · 시술 · 최종 가격)과
상담사 태블릿(차티 stg 상담 화면 문법: 가격표 · 카트 · 할인 · 추천 · 체크리스트)이 같은 PC 탭 두 개에서
`BroadcastChannel` 로 묶인다. Next.js 16 + 메디킷 1.4.0, `reference/2026-10-21-charty-poc/web/`.
실 API 는 추후 3D 스캔 업체에서 받기로 해 데이터 계층을 어댑터(`fromM3d`)로 떼어 두었다.

## 2. 적용한 기술·개념

- **UV 아틀라스 위 분석 오버레이** [[uv-atlas-overlay]] — 스캐너가 준 OBJ 메시·광원 텍스처·검출 마스크를 한 셰이더로 합성
  - 왜 이걸 골랐나: 리포트 응답이 가리키던 마스크 21종(`zip://mask/…`)은 파일이 어디에도 없었다. 대신 `hd_ai.zip` 의 검출 이미지 84장이 텍스처와 **같은 9728×4864 UV 아틀라스**임을 합성으로 확인하고 그걸 오버레이로 썼다
  - 무엇이 어려웠나: ① 키포인트는 이미지 좌표(v 위→아래), OBJ `vt` 는 표준(아래→위) — three.js 기본 `flipY` 가 맞는 규약 ② linear 캔버스에서 hex 색이 sRGB 로 해석돼 어두워짐 → `LinearSRGBColorSpace` 로 넣음 ③ 0.013% 밖에 안 되는 잔주름 선이 1/3 축소에서 사라짐 → blur 로 키우니 「선」이 「방울」이 됨(리뷰 지적) → **풀해상도 팽창 + max 축소**로 선 모양 유지. libvips 형태 연산은 검정을 전경으로 봐서 흰 선을 굵히는 쪽이 `erode` 였다(실측 `dilate` 0.013%→0%)
  - 근거: `assets-report.md` §4–6 · `fe-report.md` 수정 1판 #2 · `web/scripts/prepare-assets.mjs`
- **탭 간 스냅샷 동기화와 연결 판정** [[broadcast-channel-snapshot-sync]] — 태블릿이 상태 전체를 seq 와 함께 쏘고 큰 화면은 받기만
  - 왜 이걸 골랐나: 목업이라 서버가 없다. 이벤트(차분) 대신 전체 스냅샷이면 큰 화면 새로고침 · 메시지 유실이 「다음 스냅샷」으로 저절로 복구된다
  - 무엇이 어려웠나: 「5초 안에 큰 화면 없음」을 판정 tick 을 ping 주기(2초)에 묶어 최악 6초가 됐고, e2e 는 timeout 을 7초로 늘려 통과시켰다(리뷰 FAIL). tick 을 ping 과 떼어 500ms · 무응답 4초로 최악 4.5초를 **계산으로** 닫았다. 태블릿 저장소가 날아가 seq 가 1 로 돌아가면 큰 화면이 멈추므로 sessionId 가 바뀌면 seq 비교를 건너뛴다
  - 근거: `review-report.md` F-1 · `web/src/sync/` · `e2e/sync.spec.ts`

## 3. 막혔던 것 / 사고

- 테스트 기준을 화면에 맞춰 늘리려는 유혹이 두 번 나왔다 — AC-20(필터 픽셀 차 1%) 에서 「기준을 얼굴 픽셀 대비로 재해석」 선택지, AC-11 에서 e2e timeout 7초. 둘 다 **기준이 아니라 화면을 고쳤다.** 0.66% 는 고객이 두 필터를 눈으로 못 가른다는 뜻이었다
- 그 대가로 고친 blur 가 또 다른 결함(얼룩)을 만들었다 → 수치만 보지 말고 스크린샷을 눈으로 본 것이 잡았다
- 코디 핸들이 세션 중 두 번 바뀌었다(`term_210dc…` → `term_342408…` → 다시 `term_210dc…`). 워커 완료 보고가 죽은 핸들로 갈 뻔했다 → 발주 직전마다 `terminal list`
- 실명 · 리포트 hash 가 든 저장본 HTML 이 gitignore 밖에 있었다 — 리뷰가 잡았다
