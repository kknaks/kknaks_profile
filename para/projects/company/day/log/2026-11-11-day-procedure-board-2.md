## 2. 적용한 기술·개념

- **같은 API · 다른 테넌트면 같은 동작 — 환경별 가드 없애기** [[dev-prod-parity]] — `trial_writes` · `KOS_TRIAL_WRITES_ON_LIVE` · `TRIAL_STEPS` · dev `is_demo` 거르기 제거
  - 왜 이걸 골랐나: 「확인 안 된 KOS 쓰기를 실제 병원에 먼저 보내지 말자」로 데모만 열어 둔 가드가 확인 단계 없이 굳어, 같은 코드가 데모/운영에서 다르게 동작했다. dev/prod 분리는 스키마(`day_dev` · `day_prod`)에 넣는 연결 데이터로 이미 된다. 확인은 데모 실물로 하고, 확인된 쓰기는 모든 연결에 같게 연다
  - 무엇이 어려웠나: 갈리는 자리가 한 줄(factory)에서 플래너 · 보내기 직전 검사 · outbox · board · auth 로 퍼져 있었다 — researcher 전수조사(23자리)로 뿌리와 성격((가) 안전장치 · (나) 서버 격리 · (다) 그 밖)을 갈랐다. `is_demo` 칸은 사용자 결정으로 표시 데이터로 남기고 구조 테스트(`tests/architecture/test_demo_flag.py`)로 「칸 · 시드에만」을 지킨다
  - 근거: `research-demo-vs-live-report.md` · CENTURION_DAY 96fff917 · Delivery #234
- **HAR + 데모 실물로 외부 쓰기 확인하기** [[public-vs-internal-api]] — KOS 쓰기 5개(시작 취소 · 완료 취소 · 귀가 대기 1·2 · 재호출) · 집도의 변경 · 방 이동 · 차트 메모
  - 왜 이걸 골랐나: cc-prototype 구현을 근거로 짠 쓰기가 「확인 안 됨」으로 남아 있었다. 사용자가 데모 지점에서 직접 눌러 KOS 결과를 보고, 모자란 동작은 KOS 웹 HAR(`집도의변경` · `삭제후의사호출` · `방이동` · `차트작성1~3`)로 요청 경로 · 칸만 확인했다(값은 옮기지 않음)
  - 무엇이 어려웠나: 코디가 「KOS 에서 취소해 보라」처럼 KOS 에 없는 기능을 짐작해 시험을 제안했다가 정정했다. KOS 사실(의사차트는 집도의를 골라야 쓸 수 있고 고르면 수락 → 진행 중이 됨 · 완료된 시술은 안 바뀜)이 설계를 바꿨다 — 시술 전 의사차트는 DAY 에만 두고 [수락] 때 검증 뒤 보낸다
  - 근거: `research-har-room-chart-report.md` · `reference/2026-11-09-cc-day/har/*.har`(gitignore) · SPEC-002 KOS 쓰기 표
- **「방 배정」 판정을 이름 · 구조가 아닌 설정 id 로** [[no-inference-from-free-text]] — `crm_connection.config.room_assign_etc_task_id` ↔ KOS `etceteraTaskId`
  - 왜 이걸 골랐나: 「방 붙은 기타 작업 + DAY 가 호출 안 함」이라는 구조 판정이 KOS 가 기타 작업마다 방을 붙이는 실데이터에서 기타 작업 전부를 숨겼다(로컬 DB 로 15건 중 1건만 진짜 방 배정). KOS 기타 작업 마스터에는 `id` · `title` 뿐이라 병원마다 이름이 달라도 되는 기준은 설정 id 뿐이었다(설정 화면 없이 DB 데이터 · 데모 값 683ba150… · prod 는 배포 때)
  - 무엇이 어려웠나: 앞서 코디가 「구조로 판정해 병원마다 이름이 달라도 된다」고 설명했던 것이 틀렸다 — DB 를 열어 보고서야 드러났다. 카드 방 계산에서도 「방 배정」을 빼야 점유 이동 뒤 카드가 원래 방으로 되돌아가지 않았다(코드 리뷰 W1)
  - 근거: `e2e-feedback.md` F10 · CENTURION_DAY b8a59cc3 · Delivery #239
- **조작한 카드만 갱신 — version + OOB 조각** [[server-rendered-fragments]] — HTMX 동작 응답 = 누른 카드 조각 + OOB(인박스 · 탭 숫자 · 원장 상태) + 판 version · SSE 신호는 version 만
  - 왜 이걸 골랐나: 버튼 한 번에 판 전체 조각 교체 + `sse:board` 로 한 번 더 그려 진행 중 카드가 모두 새로고침되고 「⋯」가 늦게 떴다(F7 · F8)

  - 근거: `review-236v3-report.md` · `review-doc-merge921-report.md` F1 · SPEC-002 실시간 갱신
- **외부 원장 + DAY 이력으로 차트 동시성** [[optimistic-lock]] · [[external-write-queue]] — DAY 안 동시 저장은 연 때 값(baseLogId) 비교로 막고 · DAY 저장은 이력 + outbox · 반영 확인 전 동기화가 덮지 않게(guard) · KOS 웹 수정은 동기화로 받아 이력(source kos)에 남기고 · 양쪽 동시면 외부가 이김

  - 무엇이 어려웠나: 「방 배정」이 없을 때 새로 만들면 KOS 가 새 작업 번호를 바로 주지 않아(응답 `{}`) 순서가 뒤집혔다 — 방 배정 먼저(확인 뒤) → 나머지 이동으로 바꿨다
