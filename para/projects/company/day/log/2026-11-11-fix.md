DAY 직원 앱을 처음으로 TestFlight(개발 앱 `DAY Dev`)에 올리고, 사용자가 실기기에서 본 것을 받아 고쳤다. 올리는 과정에서
dev 서버 설정 구멍(앱 로그인 응답에 서버 주소가 안 실림 · APNs · 시스템 계정)이 드러나 먼저 메웠고, 이어서 실기기 피드백
10건(시술현황 카드 · 채팅 · 알림 · 읽음 표시)과, 앱에만 있고 서버에 없던 통역, 꺼져 있던 채팅 첨부 저장소를 스펙 →
Delivery #241(v1 → v5) → 코드 → 독립 리뷰 순으로 닫았다. 스펙은 10판까지 갔다 — 사용자 결정이 작업 중에 계속 더해지고
(8 · 9 · 10번 · 저장소) 뒤집혔기(저장소 경로 · 컨테이너 이름) 때문이다.

## 2. 적용한 기술·개념

- **release 빌드에서만 드러나는 설정 구멍** [[externalized-configuration]] — TestFlight 앱 로그인이 `environment_unavailable` 로 막혔다. dev 서버가 로그인 응답에 자기 공개 주소(`api_base_url`)를 안 실어서다
  - 왜 이걸 골랐나: 앱은 한 바이너리가 로그인 응답으로 dev/prod 를 가르게 지어져 있고, release 빌드는 주소 · 환경 둘 중 하나라도 없으면 fail-closed 로 막는다. 서버 설정 한 줄(`DAY_PUBLIC_API_BASE`)을 채우는 것이 맞는 수리였다
  - 무엇이 어려웠나: 웹은 그 칸을 쓰지 않고 시뮬레이터는 debug 빌드라 검사를 건너뛴다 — 정식 빌드가 실제 서버에 붙기 전까지 아무 시험도 이 구멍을 밟지 않았다. 서버 로그와 앱 코드(`session_controller.dart` `_targetFrom`)를 같이 따라가서 찾았다
  - 근거: `be-dev-env-report.md` · `review-1-report.md` · CENTURION_DAY#240
- **방화벽 뒤 비밀 저장소에 허용된 경로로 넣기** [[secret-store]] — Key Vault 방화벽이 VM 서브넷만 허용하고 계정에 방화벽 변경 권한이 없었다
  - 왜 이걸 골랐나: 방화벽에 IP 를 잠깐 여는 길은 권한(`vaults/write`)이 없어 실패했다. 이미 허용된 경로(VM)를 SOCKS 터널(`ssh -D`)로 거쳐 사용자 토큰으로 REST 를 불렀다 — 방화벽 · 권한은 그대로 두고 값만 파일에서 곧바로 넣는다
  - 무엇이 어려웠나: `az` CLI 는 SOCKS 를 타지 않아 `curl --socks5-hostname` + `az account get-access-token` 으로 직접 불러야 했다. 값이 화면에 안 나오게 표준입력으로만 넘겼다
  - 근거: `_RESUME.md` §5(APNs 키 · Soniox 키)
- **연동용 시스템 계정은 사람이 아니다** — 채팅 403 · 푸시 대상 제외 · 호출 알림 미수신이 한 뿌리였다. 로그인한 계정이 KOS 동기화용 시스템 계정이었다
  - 왜 이걸 골랐나: 사용자는 「관리자는 다 접근 가능해야」로 규칙 변경을 먼저 떠올렸지만, 규칙(시스템 계정 = 활성 직원 아님)은 두고 dev 의 시스템 계정을 다른 계정으로 바꾸는 쪽을 골랐다 — 스펙 세 곳을 안 건드린다
  - 무엇이 어려웠나: 화면은 「서버에 연결 중…」만 보여 원인이 안 드러났다. 서버 로그(403) → 채팅 서비스의 판정 코드 → dev DB 의 `is_system_account` 로 내려갔다. 교체는 컨테이너 안 일회성 스크립트로 새 계정 KOS 로그인을 먼저 확인한 뒤 연결 설정 두 칸만 갈았다
  - 근거: `e2e-feedback.md` 참고-1 ~ 4 · `_RESUME.md` §5
- **표시 계산은 한 곳에** — 목록 카드가 「시술 모두 완료」인데 「시술 대기」로 보였다. 상태 칸이 4상태만 정의하고 방 상세만 「모두 완료」를 계산했다
  - 왜 이걸 골랐나: 새 상태값을 서버에 더하지 않고, 방 상세가 쓰던 계산 · 글자 · 조건([귀가 대기] = 서버 `canHome` + 편집 권한)을 목록 카드가 같은 함수로 쓰게 했다
  - 근거: SPEC-003 개정 ⑧ · `review-app-report.md`
- **읽음 표시 — 서버는 읽은 자리만, 셈은 앱이** — 카톡식 「안 읽은 사람 수」
  - 왜 이걸 골랐나: 서버가 메시지마다 수를 주면 읽음 한 번에 여러 메시지의 고친 모양을 멤버마다 보내야 한다. 이미 있는 `last_read_seq` 를 멤버 줄에 싣고 작은 이벤트 하나(`chat_member_read`)만 더했다 — migration 없음
  - 무엇이 어려웠나: 문서 리뷰가 구멍을 찾았다. 서버는 **보내기에서도** 보낸 사람의 읽은 자리를 올리는데 이벤트는 읽음 요청이 올렸을 때만 나간다 → 받고 1초 묶음 읽음이 나가기 전에 답장하면 숫자가 재연결까지 남는다. 「메시지를 받으면 보낸 사람은 거기까지 읽은 것」 + 「합치기는 늘 max」로 앱 쪽에서 닫았다(서버 그대로). 보고 있는 방에서 내 숫자가 1초 깜빡이는 것도 같은 판에서 잡았다
  - 근거: `review-doc-2-report.md` F1 · W1 · W2 · `correction-read-1.md` · `correction-read-2.md` · `be-3-report.md` · `review-app-3-report.md`
- **겹쳐 띄운 것의 자리는 다시 잰다** [[viewport-aware-overlay]] — 키보드를 연 채 길게 누르면 메뉴가 공중에 떴다
  - 무엇이 어려웠나: 원인이 둘이었다. ① 메뉴 route 가 포커스를 가져가 키보드가 닫히고 `reverse` 목록이 다시 잡히는데 자리는 누른 순간 한 번만 쟀다 ② 목록이 줄 번호로 element 를 재사용해, 새 메시지가 끼면 붙잡고 있던 element 가 다른 메시지를 그린다. 리뷰는 ①의 한 계기(새 메시지)만 짚었고, 「자리를 바꿀 수 있는 계기를 전부 세라」로 맡겨 12종과 ②가 나왔다
  - 근거: `app-3-report.md` · `review-app-3-report.md` W1 · `app-fix3-report.md`
- **옮겨 온 코드는 원천과 줄 단위로 대조한다** [[websocket-relay]] — 통역 서버를 interpret-pwa 에서 이식
  - 왜 이걸 골랐나: 앱과 스펙이 이미 interpret-pwa 계약으로 지어져 있었고, 더 오래된 원형(cc-prototype)에는 운영 장애를 낸 keepalive 가 남아 있었다. 인증만 DAY 세션으로 갈아 끼웠다
  - 무엇이 어려웠나: 「그대로 가져왔다」를 믿지 않고 리뷰가 AST 로 비교했다(달라진 곳 = 세션 파일 하나 · 줄마다 스펙 근거). 동시 세션 자리는 모든 종료 경로에서 한 번만 반납되는지를 경로 표와 변이 시험으로 굳혔다. 외부 한도는 문서가 아니라 API 로 물었다 — Soniox 조직 한도가 음성 인식 10 · 음성 합성 3 이라 정한 상한 6 과 맞지 않는다는 게 그때 나왔다
  - 근거: `research-interpret-report.md` · `be-2-report.md` · `review-be-report.md` · `_RESUME.md` §1(I-1)
- **비밀 없는 저장소 접근(관리 ID)** [[workload-identity]] · [[secret-store]] — 채팅 첨부 저장소가 계정 키 · 연결 문자열을 받지 않게 만들어졌다
  - 왜 이걸 골랐나: 저장소 쪽에서 키 인증이 꺼져 있어 선택지가 없었고, 그 결과 Key Vault 비밀 하나가 사라졌다. 환경 분리는 경로 폴더가 아니라 컨테이너(설정값)로 — 사용자가 「env 마다 접근할 컨테이너가 달라지는 것」으로 정리했다
  - 무엇이 어려웠나: 로컬에서는 VM 관리 ID 를 쓸 수 없어 실물은 배포 뒤에만 돈다. 그래서 먼저 dev 컨테이너 안에서 토큰이 나오는지만 확인해 두고, 코드는 가짜 자격 · SDK 예외 모양으로 시험한 뒤, 배포 직후 컨테이너에서 올리기 → 읽기 → 지우기를 돌렸다. 없앤 비밀 이름은 금지 목록에 남겨 Git 설정으로 되돌아오는 길을 막았다
  - 근거: `spec-7-report.md` ~ `spec-10-report.md` · `be-4-report.md` · `review-be-3-report.md`
- **문서 리뷰와 코드를 같이 돌리고 계약 지적은 먼저 받기** — 8 · 9 · 10번과 저장소
  - 왜 이걸 골랐나: 앞 판은 문서 리뷰가 끝난 뒤 코드를 시작했다. 뒤 판은 같이 돌리고 리뷰어가 계약에 닿는 지적을 리포트 전에 한 줄로 먼저 보내게 했다

## 3. 막혔던 것 / 사고

- **「아직 없다」를 다시 확인하지 않았다** — 저장소 컨테이너가 이미 `dev` · `prod` 로 만들어져 있었는데, 코디는 앞서 한 번 조회한 결과(`files` 하나)로 「아직 없음 · `daydev` 로 가정」을 스펙 9판 · 서버 코드 · Delivery v4 에 적었다 → 사용자 「컨테이너 안 받은 거 아니야?」로 다시 조회 → 10판 · v5 로 정정. 가정으로 짓기 전에 그 순간의 상태를 다시 본다
- **분리를 권한 문제로 과하게 답했다** — 사용자는 「env 마다 다른 컨테이너를 보게」를 말했는데 코디는 「같은 VM 권한이면 서로 읽을 수 있으니 권한까지 나눠야 분리」로 답해 두 번 되물음을 받았다 → 설정 수준 분리로 정리
- **Delivery 등록을 미뤘다** — SPEC-000 이 draft 라는 이유로 로컬 `wp-plan.md` 만으로 코드를 시작했다 → 사용자 「왜 이슈로 안 했어」. 2차 때도 baseline pending 으로 먼저 올렸다. 코드 워커가 승인보다 먼저 돌았다
- **브랜치 이름** — 사용자가 말한 「fix」를 slug · 브랜치 이름 그대로 썼다 → PR 직전에 `fix-app-re1` 로 교정(브랜치만 `git branch -m` · 워크트리 경로는 그대로)
- **자동 서명 archive 실패** [[code-signing]] — 팀에 등록 기기가 0대라 개발 프로파일을 못 만든다 → 서명 없이 archive → 앱만 entitlements 로 ad-hoc 서명 → export 에서 배포 서명(푸시 entitlement 가 production 으로 들어가는지 확인). 저장소 README 에는 아직 없다
- **Key Vault 이름을 설정 파일에서 통째로 읽었다** — `infra.json` 값에 설명이 붙어 있어 첫 호출이 전부 실패(변경 0). 첫 낱말만 쓰게 고침
- **dispatch 스크립트의 인자 수** — 재개 노트 갱신 파이썬에 인자를 덜 넘겨 두 번 실패(발주는 나감 · 기록만 다시)
- **리뷰어의 완료 보고 중복** — worker_done 이 두 번 왔고 리뷰어가 스스로 정정을 보냈다
