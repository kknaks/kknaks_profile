## 1. 무엇을 했나

직원 앱 시술현황 차트가 읽기 전용이고(까만 줄 · 탭바 겹침), 예약 · 접수 단계에서 앱으로 할 수 있는 일이 없었다. 두 단계로 나눴다.
WORK-001 은 앱 차트를 웹과 같은 기능(탭별 저장 · 담당자 · 시술전후사진)으로 올리고, 웹 HTML 경로뿐이던 차트 저장 · 사진에 `/api` JSON 짝을 만들었다.
WORK-002 는 앱에 예약현황 탭(웹 예약 상세를 읽기 전용으로)을 새로 두고, 버튼 셋 — [문진 QR] · [여권 스캔](iOS Vision · Android CameraX + ML Kit) · [태블릿에 보내기](웹 · 앱 → 코디 계정 태블릿 하나) — 을 붙였다. 고객 문진은 DAY 공개 페이지 `/q` 가 KOS 양식을 그리고 DAY DB 먼저 저장한 뒤 KOS 에 낸다.
사용자 시뮬레이터 E2E 뒤 dev 가 두 번 앞서가 합치기(번호 · migration 겹침)를 거쳐 dev 에 머지 · 배포 · TestFlight 에 올렸고, 마감 전에 SPEC 을 머지된 구현에 맞췄다(spec-sync).
