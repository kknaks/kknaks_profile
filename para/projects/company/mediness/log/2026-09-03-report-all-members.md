## 1. 무엇을 했나

데일리 리포트 첫 실발송(09-03)에서 태스크가 하나도 없는 구성원(천수정)이 스레드에서 빠졌다. 원인은 버그가 아니라 승인됐던 「활동 0 ∧ 열린 0 생략」 규칙 + 집계가 태스크에서 출발하는 구조(태스크 없는 사람은 구조적으로 안 보임). 사용자 확정(「0건이어도 전원 다 보여야 한다」)으로 모수를 **활성 구성원 명부 전원**(C레벨 제외 불변)으로 뒤집고 생략 규칙을 폐지했다.

## 2. 적용한 기술·개념

- **모수의 출발점 뒤집기** — 「태스크 가진 사람」(GROUP BY 부산물) → 「명부 전원」(OrganizationMember LEFT JOIN RuntimeTask)
  - 왜: 생략 규칙만 없애도 태스크 0건인 사람은 여전히 안 보인다 — 생략은 증상이고 출발점이 원인
  - 무엇이 어려웠나: 태스크 조건(삭제 제외)을 WHERE 에 두면 0건인 사람의 NULL 행이 걸러져 outer join 이 무의미 — **ON 절**로 이동
  - 근거: mediness-app#148 · task_daily_report.py
- **모수 2축 분리(스펙)** — 플래너가 §3.1 「모수」 한 칸을 태스크 모수(무엇을 세나)/사람 모수(누구 칸을 만드나)로 갈라 명문화 — 구 서술의 암묵 전제(「태스크 가진 사람」)가 생략 규칙을 굳혔던 자리
  - 근거: mediness#691
