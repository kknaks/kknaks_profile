# 개요

사내 업무의 원료가 흩어져 있었다. 기획·정책 문서는 Git 저장소 안에만 있어 비개발자가 읽기 어려웠고, 회의는 끝나면 사람의 기억으로만 남았고, 결정은 메신저 스레드에 묻혔고, 「지금 이 제품 어디까지 왔나」는 물어봐야 알 수 있었다. Mediness 는 이 넷을 하나의 웹 워크스페이스로 모은 사내 제품이다.

구성은 네 컴포넌트다. 브라우저 UI(Next.js), REST + WebSocket 을 함께 서빙하는 API 서버(FastAPI + PostgreSQL + Redis), AI 코딩 에이전트가 사내 지식을 도구로 호출할 수 있게 여는 MCP 서버, 그리고 사용자 PC 에서 도는 에이전트 데몬이다. 핵심 설계 원칙 하나는 **서버가 사용자 대신 LLM 을 호출하지 않는다**는 것 — 브라우저는 얇은 UI 로 두고, 무거운 에이전트 실행은 사용자 PC 또는 백그라운드 워커가 맡는다. 덕분에 서버는 상태와 권한만 책임지고, 모델·에이전트 교체가 서버 재설계로 번지지 않는다.

기능은 도서관(문서 트리·검색·댓글·발행)에서 시작해 실시간 STT 회의록, 커밋 이력 검색, 제품 파이프라인 대시보드, 의사결정 원장, 부서 문서 스페이스, 그리고 여러 승인 게이트를 한 커널로 일반화한 Action Runtime 까지 확장됐다. 60여 개의 기능 명세와 100여 개의 작업 단위(WP)를 문서로 먼저 확정하고 구현하는 방식으로 진행했다.

# 기술스택

**백엔드 — FastAPI + PostgreSQL + Redis**

- FastAPI 를 고른 이유는 REST 와 WebSocket 을 한 프로세스에서 다뤄야 했기 때문이다. 브라우저·사용자 PC 데몬·회의 오디오 스트림이 각각 다른 WS 엔드포인트로 붙고, 같은 인증·권한 레이어를 공유한다.
- PostgreSQL — 회의·결정·업무가 전부 관계형이고 상태 기계를 가진다. 도메인 객체는 전부 **soft delete** 로 통일하고 FK 는 기본 `ON DELETE RESTRICT` 로 뒀다. 감사 로그·전이 로그·커밋 이력처럼 「지워지면 안 되는 것」은 append-only 테이블로 분리했다.
- 검색은 처음부터 임베딩으로 가지 않고 `pg_trgm` GIN 인덱스로 시작했다. 사내 규모에서 충분했고, 벡터 검색은 필요해질 때 도입하기로 미뤄 뒀다.
- Redis — JWT 블랙리스트, WebSocket 라우팅 맵(어떤 사용자가 어느 노드에 붙어 있나), 캐시. AOF 로 영속.
- SQLAlchemy + Alembic 으로 스키마를 마이그레이션 단위로 관리한다.

**인증 — 진입점 3개, 토큰 1종**

브라우저 로그인 / 사용자 PC 데몬 / MCP(OAuth 2.0 DCR + PKCE) 세 진입점이 모두 **같은 서버가 발급한 단일 JWT** 를 받는다. 진입점마다 토큰 종류를 나누면 검증 경로가 셋으로 갈라지고 권한 판정이 어긋난다. 발급 경로만 다르고 검증은 한 곳에서 끝나게 했다. 권한은 역할 문자열이 아니라 **capability leaf key** 로 판정하고 매핑을 DB 에 두어, 권한을 넓히려고 코드를 고치지 않게 했다.

**MCP — Streamable HTTP**

문서·회의·커밋·제품 조회를 MCP 툴로 노출해서, 사내 지식이 브라우저 밖(AI 코딩 도구)에서도 같은 권한 아래 쓰이게 했다. 툴 이름·응답 스키마 컨벤션을 먼저 정하고, 모든 호출을 append-only 감사 로그에 남긴다.

**프론트엔드 — Next.js App Router + TypeScript**

- 화면 최초 진입의 read 는 **서버 컴포넌트에서 시작**하고, 사용자 동작 이후의 변경·갱신·스트림은 BFF(route handler) 를 거친다. 이 경계를 문서로 못 박아 둔 이유는 팀마다 데이터 취득 위치가 달라지면 인증 토큰이 브라우저로 새기 때문이다. 브라우저가 API 서버를 직접 호출하는 경로는 만들지 않았다.
- Tailwind + shadcn/ui — 컴포넌트를 의존성으로 끌어오지 않고 복사해 소유하는 쪽을 택했다. 사내 디자인 토큰을 계속 갈아끼워야 했다.

**AI 레이어 — 자체 LLM 호출 패키지 + 프롬프트 DB**

LLM 호출은 직접 SDK 를 import 하지 않고 자체 추상화 패키지를 통해서만 한다(provider·model 교체를 호출부가 모르게). 프롬프트는 코드 상수가 아니라 **DB 에 버전·활성본·롤백과 함께** 저장하고 관리자 화면에서 편집한다. 프롬프트 한 줄 고치자고 배포하지 않기 위해서다.

**회의 — 실시간 STT + 화자 분리**

외부 실시간 STT WebSocket 으로 부분 인식 → 확정 텍스트를 받고, 종료 후 LLM 이 요약과 할 일·결정·리스크·주제 네 종류를 추출한다. v2 에서 화자 분리 엔진을 얹어 라이브 매핑 + 종료 후 정정을 지원한다.

**운영 — Docker Compose + Prometheus / Loki / Grafana**

온프레미스 단일 서버에 Docker Compose 로 올리고, 일 1회 DB 덤프와 스냅샷을 호스트로 백업한다. 단일 노드가 SPOF 인 건 알고 감수한 트레이드오프이고, 외부 호스팅 이관은 다음 버전 선택지로 남겨 뒀다. 메트릭·로그·대시보드는 Prometheus + Loki + Grafana 로 자체 운영한다.

**데스크톱 — Tauri**

웹 렌더링을 그대로 감싸는 얇은 셸. 에이전트 데몬을 내장하고, 회의 녹취 중 절전 진입을 막는다. Electron 대신 Tauri 를 고른 건 셸이 하는 일이 적어 런타임을 통째로 번들할 이유가 없었기 때문이다.

# 주요기능

**도서관** — 기획·정책·결정 문서를 트리와 전문 검색으로 서빙한다. 비개발자도 Git 을 몰라도 읽고, 문서 단위 댓글과 본문 인용(Quote anchor) 단위 검토 의견을 남긴다. 브라우저에서 올린 문서를 저장소 main 에 바로 발행할 수 있고, 연 문서(.md/.html/.xlsx)는 원본 그대로 내려받는다. 화면정의서 안에 쓴 화면 DSL 블록은 도서관에서 실제 컴포넌트 화면으로 인라인 렌더된다.

**회의실** — 브라우저에서 녹취를 시작하면 실시간으로 자막이 쌓이고, 종료 시 통합 요약과 할 일·결정·리스크·주제가 자동 추출된다. 화자 분리, 제품 태그 라벨링, 회의록에서 나온 제안을 원장 항목과 나란히 비교하는 뷰까지 지원한다.

**채팅 / AX 에이전트** — 로그인 직후 랜딩이 에이전트 채팅방이다. 채팅방 하나가 에이전트 세션 하나에 1:1 로 묶이고, 스트림은 WS 커넥션이 아니라 **서버 측 상주 소비자**가 받아 DB 에 적재한다. 그래서 방을 나가도 작업이 계속되고 재입장하면 그동안의 기록이 그대로 보인다. 별도로 사용자 PC 데몬 경로도 있어, 브라우저에서 보낸 요청을 각자의 PC 에 있는 AI 코딩 도구가 실행하고 결과를 스트리밍해 온다.

**의사결정 원장** — 결정이 발생한 자리(메신저)에서 봇을 태그하면 AI 가 관련 문서를 능동 탐색해 초안을 만들고, 사람이 폼으로 확정해 원장에 등록한다. 이후 승인·보류·폐기의 결정 arc 와 1:N 실행 태스크의 실행 arc 를 상태 전이로 추적하고, 전이마다 다음에 행동할 사람에게 DM 이 간다. 전사 대시보드와 「내 의사결정」 개인 대시보드에서 drill-down 한다.

**제품 현황 대시보드** — 전사 제품을 6단계 파이프라인으로 롤업하고, 제품별 버전·배포 환경·QA 검증 시트를 연결한다. 파이프라인 단계 변경은 상류 신호를 LLM 이 읽어 제안하고 사람이 승인하는 게이트를 거친다. 버전 단위 WBS·간트로 스프린트 업무계획을 세우고 드래그로 순서를 바꾼다. 금요일에는 제품×버전×주차 매트릭스 주간회의록이 스냅샷으로 자동 생성된다.

**부서 스페이스** — 부서별 문서 workspace. 마크다운 문서의 저장·버전·충돌 해결, 스프레드시트(.xlsx) 공동 편집과 버전 관리, 타 부서에 read/comment 권한으로 공유하는 링크와 「공유받은 문서함」을 제공한다. AI 가 문서 전체 초안을 제안하고 피드백을 반복해 다듬는 draft proposal 도 있다.

**Action Runtime** — 「AI 가 초안을 만들고 사람이 승인해야 반영된다」는 패턴이 회의실 예약, 장애 대응, 의사결정 흐름, 업무 생성·수정·삭제에서 반복되자 이를 **워크플로 커널 + 조각 + 조립 계약**으로 일반화했다. 새 승인형 기능은 조각을 조립해 만든다. 관리자는 콘솔에서 워크플로 그래프와 실행 상태를 시각적으로 본다.

**AI 브리핑** — 여러 외부 소스를 어댑터로 수집해 하루 단위로 종합하고, 날짜별 조회 뷰어와 MCP 툴·자연어 질의로 열람한다.

**커밋 이력 검색** — Webhook 으로 push 를 받고, 누락 구간은 REST 로 재귀 walk 해 메워 이력을 완결시킨다. 파일 단위 변경까지 인덱싱해 「왜 이렇게 짰지」를 문서 옆에서 답할 수 있게 했다.
