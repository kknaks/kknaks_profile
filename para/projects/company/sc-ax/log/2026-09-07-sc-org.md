
# 작업 요약 — sc-org (sc-ax)

기간: `2026-09-04` ~ `2026-09-07`
결과: SC 조직도 반입 산출물 3종(ERD·모델·시드) 완성, 프로필 main 머지. SC 코드레포 생성·실제 적재는 다음 작업.

## 1. 무엇을 했나

sc-ax 에 SC(더에쓰씨) 조직도 데이터(169명 CSV)를 넣어야 하는데, mediness 에 이미 조직도
도메인이 있어 그 테이블 구조·코드를 그대로 쓸 수 있는지가 물음이었다. para 에 sc-ax 자리부터
스캐폴딩하고, mediness 조직도 도메인을 read-only 조사 워커 1명으로 전수한 뒤(문서+코드,
리포트 595줄), CSV 를 그 구조에 대조해 「그대로 들어간다」를 확인하고, 반입 산출물 3종
(`output/erd.md`·`models.py`·`seed_sc_org.py`)을 만들었다.

## 2. 적용한 기술·개념

- **문서·코드 세대 판별 후 이식 기준 확정** — mediness 조직도 문서에는 1세대(테이블 없는 파생
  렌더, WP-055)와 2세대(canonical directory, 테이블 16개)가 공존했고, 문서에만 있고 코드에
  없는 기능도 3건(alias·preview_token·job_position)이었다
  - 왜 이걸 골랐나: 문서를 요구사항으로 그대로 옮기면 실존하지 않는 기능을 이식 범위에 넣게
    된다 — spec 자신이 「스키마는 코드가 SoT」라 명시해서 코드 기준으로 확정
  - 무엇이 어려웠나: 브리프에 준 SSOT(work-055)가 하필 구세대였다 — 워커가 grep 전수로
    세대 차이를 잡아 올렸다. SSOT 로 준 문서도 세대 검증 대상이다
  - 근거: `org-chart-survey-report.md` §1.3·§1.4
- **어휘 테이블의 용도 전환으로 스키마 무수정 이식** — mediness 가 직급 테이블을 일부러 없앤
  (job_position drop) 자리에서, SC 의 직급(사원~대표이사)을 구조가 동일한 `job_function`
  (조직별 어휘 + 기간형 배정)에 실어 스키마 수정 0 으로 해결
  - 왜 이걸 골랐나: 직급 전용 테이블 신설은 mediness 와의 구조 동형성을 깨고, member 컬럼으로
    박으면 기간형(이력) 축을 잃는다. mediness prod 에서 job_function 이 0행이라 충돌도 없다
  - 무엇이 어려웠나: 직능(무슨 일)과 직급(서열)은 의미가 다르다 — 테이블 이름과 실제 어휘가
    어긋나는 비용을 문서(`erd.md` §2)에 명시하는 것으로 갚았다
  - 근거: `output/models.py` JobFunction docstring · 리포트 §2.2(8)
- **기간형(temporal) 조직 디렉터리 스키마** ([[temporal-table]]) — 소속·직급·직책·고용을 전부 half-open
  `[valid_from, valid_to)` 기간 관계로 두고, 겹침 방지를 애플리케이션이 아니라 PostgreSQL
  GiST EXCLUDE 제약 7개로 강제하는 구조를 그대로 반입
  - 왜 이걸 골랐나: 겸임(1인 5팀 팀장)·주소속 단일성·이력 보존이 전부 이 구조 위에서 공짜다 —
    현재 상태만 갖는 평면 스키마로 줄이면 나중에 이력 요구가 올 때 전면 재설계가 된다
  - 무엇이 어려웠나: SC 원본에 입사일이 15/169 뿐이라 `started_on` NOT NULL 이면 고용형태
    167건을 실을 수 없었다 → nullable 완화로 풀되, NULL 시작 기간은 겹침 판정 하한이 무한대라
    두 번째 기간을 넣으려면 입사일부터 채워야 한다는 제약을 문서에 남겼다
  - 근거: `output/models.py` 헤더 3번 · `erd.md` §3
- **실데이터 특이 케이스의 명시적 처리** — 같은 이름 행들이 겸임(김명지 5행=1명)과
  동명이인(이호연 2행=2명)으로 갈렸다
  - 왜 이걸 골랐나: 이름 기반 자동 병합은 동명이인을 삼킨다 — 병합 조건을 「비고=겸임」으로
    좁히고, 겸임자 주소속은 추론 대신 `PRIMARY_OVERRIDE` 상수로 박아 판단을 코드에 남겼다
  - 무엇이 어려웠나: 주소속 판별 근거가 데이터에 없었다 — 메모("중복") 없는 원행(GB일본)을
    주소속으로 삼는 휴리스틱을 쓰되 경고 출력으로 드러나게 했다
  - 근거: `output/seed_sc_org.py` PRIMARY_OVERRIDE · dry-run 실측(165명/소속 169)

## 3. 막혔던 것 / 사고

- **발주 디렉토리 이름을 문자 그대로 팠다** — 사용자의 「work/task」는 `work/{task}`
  (작업 슬러그 자리) 뜻이었는데 디렉토리를 `task` 로 생성 → mediness 워크트리 2개가
  `task`/`task-spec` 이름으로 남았다. work 디렉토리는 `sc-org` 로 개명했지만 워크트리는
  이름 그대로 쓰고 마감 때 삭제했다. 자리표시자로 들리는 지시어는 발주 전에 실값을 확인한다
- **조사 목적의 어긋남** — 첫 보고를 「코드 재사용성 판단 질문 10개」로 끌고 갔다가
  사용자 반려. 실제 질문은 「이 CSV 가 이 테이블에 들어가냐」였다 — 원본 데이터
  (reference CSV)를 먼저 열어봤으면 한 턴에 끝날 답이었다. 판단 재료보다 원본 대조가 먼저다
- **코디 터미널 핸들이 세션 도중 두 번 바뀌었다** (09-04 발주 때, 09-07 마감 때) —
  archive-work.sh 의 자기 제외가 stale 핸들 기준이라 그대로 돌리면 **자기 세션 터미널을
  닫을 뻔**했다. dry-run 계획의 터미널 목록을 실행 전에 눈으로 대조하고,
  `ORCA_TERMINAL_HANDLE=<현재값>` 으로 override 해서 실행했다
