## 1. 무엇을 했나

디자이너가 방향을 바꿔 새 디자인 시스템(`TheSC AX Design System`)을 세웠고, 앱은 구 DS
(`styles.css` 1613줄 + Claude Design `SCAX`) 위에 있었다. **앱 전체를 새 DS 로 옮기고 구 DS 를
코드에서 없애는 것**이 이번 작업이다.

바퀴 14개로 끊어 돌렸다 — 조사 → 토큰 → 셸 → 부품(표시·클래스이관·폼) → 아이콘 → 화면 6장 →
공유부분 → 은퇴 → 디렉토리 구조화 → `ds/` 분리 → main 머지 → 자정 버그.

착지: 화면 13개 전부 새 DS, 구 `styles.css` **삭제**(과도기·예외 파일 0), `src/` 91파일 평면 →
도메인 구조, `ds/` 부품이 앱 문구에서 분리. `tsc` 0 · vitest 524/524 · `backend/` 무변경.

## 2. 적용한 기술·개념

- **DS 를 화면보다 먼저 옮기는 순서** — 토큰 → 셸 → 부품 → 화면
  - 왜 이걸 골랐나: 화면부터 가면 화면마다 같은 부품을 각자 만든다. 공용 어휘를 먼저 갈면
    **시안 없는 화면이 따라온다.** 실제로 업무 화면 바퀴는 테스트 41건이 깨질 거라 봤는데 5건이었다
  - 무엇이 어려웠나: 중간 바퀴에서 구 CSS 가 안 줄어 「진척이 없어 보이는」 구간이 길다.
    조사 리포트가 그걸 미리 예측해 둬서 버틸 수 있었다
  - 근거: `design/ds-token-report.md` §11 · 커밋 `1ff3e51`~`2a353ff`

- **「한 바퀴는 한 가지 원인만」** — 회귀 원인을 가르기 위한 작업 분할 규칙
  - 왜: 「레이아웃 재설계 + 부품 이관」을 같이 하면 깨졌을 때 어느 쪽 탓인지 못 가른다.
    그래서 `.btn` 이관을 화면 바퀴에 얹지 않고 전용 바퀴(3c)로 뺐다
  - 근거: `_RESUME.md` §2 · 커밋 `36ba1d5`

- **사다리(①시안 ②골격 ③토큰·부품 ④발명 금지)** — 「없을 때 무엇을 하나」의 규칙
  - 왜: 워커 넷이 병렬로 돌 때 각자 지어내면 **짝퉁 부품 40개**가 생긴다. ④를 「구 것 두고
    `DS-gaps` 에 올려라」로 막았다
  - 무엇이 어려웠나: 병렬이 끝난 뒤에도 그 규칙을 유지해 예외 파일이 쌓였다(§3 참조)
  - 근거: `sc-meeting-redesign-ds-import-brief.md` §1-1 · `design/DS-gaps.md` 46건

- **런타임 CSS 변수 참조를 테스트로 잠그기** — `GraphCanvas` 가 `getComputedStyle` 로 읽는 색
  - 왜: 이름이 어긋나면 **테스트는 통과하는데 화면에서 색만 사라진다.** CSS 는 없는 변수에
    에러를 안 낸다. 「CSS 가 정의하는 이름 == 코드가 읽는 이름」 검사가 유일한 자동 방어다
  - 근거: `features/graph/GraphCanvas.tsx` · 커밋 `0220428`

- **병렬 작업의 충돌원 차단** — 워크트리 4개를 동시에 돌리며 `styles.css`·`App.tsx`·공용 부품을 금지
  - 왜: 모든 바퀴가 「자기 구획을 구 CSS 에서 지운다」를 하면 그 파일에서 전부 부딪힌다.
    **삭제를 마지막 한 번으로 미루니** 충돌이 `index.css` 의 `@import` 세 줄로 줄었다
  - 근거: `_parallel-common.md` P-1~P-6 · 머지 커밋 `da0a5fc`·`9a6f3b2`·`247860c`

- **문구를 prop 으로 올려 `ds/` 를 앱에서 떼기**
  - 왜: 기본값(`actionLabel = "다시 시도"`)을 두면 「안 넘기면 한국어」라 분리가 아니다.
    기본값 없이 필수 prop 으로 두고, 호출부가 `lib/labels` 에서 가져다 넘긴다 —
    **문구는 여전히 한 곳에 모이고 부품은 언어를 모른다**
  - 근거: 커밋 `379e2e7` · 합격선 `grep '"[가-힣]' src/ds/` → 0

## 3. 막혔던 것 / 사고

- **과도기 파일이 쌓여 코드가 나빠졌다** — 「화면이 안 바뀌게」를 우선하니 구 규칙을 못 지우고
  옆에 새 걸 얹고, 얹은 걸 또 다른 파일로 뺐다(`overrides-transitional`·`avatar`·`action-cards`·
  `shared-blocks`). 사용자가 「코드를 쓰레기로 만들고 있다」고 지적해 알았다 → 바퀴 9 에서 넷 다 삭제.
  **한 번은 맞는 판단이었으나 마지막 정리를 자꾸 미룬 것이 틀렸다**

- **`:root` 토큰을 규칙보다 먼저 지울 뻔했다** — 은퇴 바퀴에서 토큰 블록이 「이미 덮임」으로
  분류돼 지워졌는데 남은 400여 규칙이 그 이름을 읽고 있었다. **빌드도 테스트도 멀쩡히 통과한다.**
  워커가 파일을 훑다 발견해 되살렸다

- **빈 검사 5건** — 클래스가 소스 어디에도 없어 **처음부터 아무것도 검사하지 않던** 테스트 줄들
  (`ax-search-path`·`ax-turn-graph`·`ax-rail-tool-result`·`ax-rail-tool-time`·`queryByRole("업무 추가")`).
  CSS 를 옮길 때마다 「없음 단언이 통과로 바뀌는 것」을 보라고 브리프에 넣어 둔 덕에 계속 잡혔다

- **머지가 만든 무한 렌더 루프** — main 이 `setSurface` 를 매 렌더 새 함수로 바꿨고 우리 seam 이
  그걸 의존성에 뒀다. **양쪽 변경이 겹쳐야만 생겨 각자 브랜치에선 안 보였다.** `App.test` 가 멎어서 발견

- **코디 오판 셋** — ① 「BE 계약 없으면 안 그린다」로 시안 기능을 접었다(사용자 교정) ② 실측을
  여섯 집안만 grep 해 124곳이라 했는데 실제 674곳(워커 정정) ③ 실패 5건을 전부 「기존 시간 버그」로
  묶었는데 1건은 우리가 만든 회귀였다(워커가 시간대를 나눠 재서 갈라냄)

- **도구 사고** — `orca terminal create` 가 타임아웃을 반환해도 터미널은 생성된다. 실패로 읽고
  재시도해 **고아 터미널 16개**를 만들었다. `terminal send` 는 `--enter` 없으면 붙여넣기만 된다.
  `orchestration reply` 가 안 닿는 워커가 있어 같은 답을 세 번 보냈다
