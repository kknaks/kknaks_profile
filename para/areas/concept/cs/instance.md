# 인스턴스와 객체 (Instance, Object)

`new` 로 확보된 메모리가 **인스턴스**다. 클래스에서만 나오는 것이 아니라 배열도 `new` 로 만들어지는 인스턴스다.

## 정의

`new` 는 세 가지 일을 한다.

1. 필요한 만큼 메모리를 **확보**한다
2. 확보한 자리를 타입별 **기본값으로 초기화**한다 → [[default-initialization]]
3. 그 메모리의 **시작 주소를 리턴**한다

```java
// new 명령은 메모리를 확보하는 명령이다.
// - 리턴 값은 확보된 메모리의 시작 주소이다.
// - 이렇게 값을 저장하기 위해 확보된 메모리를 "인스턴스"라 부른다.
```

리턴된 주소를 받아 두는 변수가 [[object-reference]] 다. 이 필기는 배열을 배우면서 그 관계를 이렇게 정리했다.

```text
new연산자를 통해 메모리를 할당하는 것을 인스턴스라고 한다.
인스턴스로 생성된 배열을 객체라고 한다.
객체가 더 포괄적인 개념이다.
배열의 주소를 레퍼런스라고 한다.
```

## 사용 예시

같은 인스턴스를 두 이름이 가리킬 수 있고, 아무도 가리키지 않을 수도 있다.

```java
int[] a = new int[5];   // 인스턴스 하나, 레퍼런스 하나
int[] b = a;            // 인스턴스 하나, 레퍼런스 둘
b[0] = 7;
System.out.println(a[0]);   // 7 — 같은 인스턴스다

new int[10];            // 받는 레퍼런스가 없다 → 만들어진 즉시 가비지
```

클래스로 만들면 확보되는 것이 **필드를 다 담을 만큼의 한 덩어리**다. 배열에서 「길이 × 원소 크기」였던 것이 클래스에서는 「선언한 필드의 합」이 된다 → [[class]]

```java
Score s1 = new Score();   // name·kor·eng·math·sum·aver 여섯 자리가 한 덩어리로
Score s2 = new Score();   // 또 한 덩어리 — s1 과 아무 관계가 없다
```

## 왜 중요한가

**`new` 가 하는 일을 알면 왜 결과를 반드시 받아야 하는지가 설명된다.** `new` 는 메모리를 확보하고 주소를 돌려주는 것까지만 한다 — 그 주소를 아무도 받지 않으면 그 메모리에 다시 닿을 방법이 없고, 만들어진 순간 [[garbage-collection]] 대상이 된다. 인스턴스는 **이름을 갖지 않는다**는 것이 핵심이고, 이름을 갖는 쪽은 레퍼런스다.

그리고 **인스턴스와 이름의 개수가 따로 움직인다**는 것이 이후의 많은 것을 설명한다. 인스턴스 하나에 이름이 여럿 붙으면 한쪽에서 고친 것이 다른 쪽에 보이고([[object-reference]]), 이름이 없으면 회수된다([[garbage-collection]]). 클래스와 [[inheritance]] 를 배울 때 "부모 타입 변수가 자식 인스턴스를 가리킨다"는 말이 성립하는 근거도 이 분리다 → [[polymorphism]]

**그리고 「클래스를 하나 더 만들까」와 「인스턴스를 하나 더 만들까」가 갈린다.** 리팩터링 회차의 `App` 이 게시판과 공지사항을 이렇게 만든다.

```java
BoardCommand boardCommand = new BoardCommand("게시판");
BoardCommand noticeCommand = new BoardCommand("공지사항");
```

**클래스는 하나, 인스턴스는 둘이다.** 두 메뉴가 각자의 게시글 목록(`LinkedList boardList`)과 제목을 갖고 서로 섞이지 않는데, 그 근거가 전부 「인스턴스가 둘」이라는 데 있다. `NoticeCommand` 라는 클래스를 만들면 같은 코드가 한 벌 더 생기고 「공지사항」이라는 글자만 달라졌을 것이다 — **달라지는 것이 값뿐이면 클래스를 늘릴 이유가 없다** → [[class]] · [[polymorphism]]

이것은 필드가 `static` 이던 동안에는 **불가능한 배치**였다. 18일 앞선 회차의 `UserCommand`·`ProjectCommand` 는 필드와 메서드가 다 `private static` 이라, 게시판을 두 개 만드는 유일한 방법이 **클래스를 하나 더 만드는 것**이었다. 그 회차에서는 그것이 제약으로 느껴지지 않았고, **같은 클래스를 두 번 써야 하는 요구가 생기자 `static` 을 버릴 이유가 생겼다** → [[static-member]] · [[cohesion]]

## 경계와 오해

- **객체가 인스턴스보다 포괄적인 개념인 것은 아니다** — 이 필기는 "객체가 더 포괄적"이라고 정리했지만, 통용되는 구분은 **포괄 관계가 아니라 말하는 각도**다. 실체 그 자체를 가리킬 때 「객체」, 그것이 **어느 클래스의** 실체인지를 강조할 때 「인스턴스」라 부른다("`Phone` 클래스의 인스턴스"). 사실상 같은 것을 두 이름으로 부르는 것이고, 한쪽이 다른 쪽을 담고 있는 관계로 외우면 나중에 어긋난다.
- **인스턴스는 클래스에서만 나오지 않는다** — 배열도 인스턴스다. 이 필기가 클래스를 배우기 전에 배열에서 이 말을 만난 것이 그 때문이다.
- **`new` 없이 만들어지는 인스턴스도 있다** — 문자열 리터럴(`"종료"`)과 배열 축약 초기화(`{1,2,3}`)가 그렇다. 문자열 리터럴은 같은 내용이면 같은 인스턴스가 재사용되기까지 한다 → [[string-comparison]]
- **인스턴스 ≠ 인스턴스 변수** — 인스턴스는 확보된 메모리 자체, 인스턴스 변수는 그 안에 든 필드다. 이름이 닮아서 섞이기 쉽다.
- **`new` 는 값을 넣어 주지 않는다** — 기본값으로 채우는 것까지다. 배열이라면 `0`·`null` 이 들어간 상태이고, 쓸 값을 넣는 것은 그다음 일이다 → [[default-initialization]]. 클래스라면 그 「그다음」을 맡는 문법이 생성자다 → [[constructor]]
- **필드 초기자로 만드는 인스턴스는 선언 순서에 묶인다** — 리팩터링 회차의 `App` 은 명령 객체 넷을 필드 초기자에서 만드는데, 그중 하나가 다른 하나의 결과를 쓴다(`new ProjectCommand("프로젝트", userCommand.getUserList())`). **필드 초기자는 위에서 아래로 실행되므로** 두 줄의 순서를 바꾸면 `userCommand` 가 아직 `null` 이라 터진다. 「생성자 안에서 만든다」와 「필드 선언에서 만든다」는 같은 `new` 인데 **순서를 읽는 방법이 다르다** → [[constructor]] · [[default-initialization]]
- **인스턴스가 여럿이어도 메서드는 한 벌이다** — 확보되는 것은 **필드 자리**뿐이고 메서드 코드는 인스턴스마다 복사되지 않는다. `c1.plus(2)` 와 `c2.plus(2)` 가 서로 다른 값을 고치는 것은 코드가 달라서가 아니라 넘어가는 대상이 달라서다 → [[this-reference]]
