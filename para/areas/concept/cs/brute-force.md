# 완전탐색 (Brute Force)

**가능한 경우를 빠짐없이 다 해 보는 것.** 영리한 방법을 찾기 전에 **먼저 검토해야 할 기본값**이다 — 상한이 작으면 이것으로 끝난다.

## 정의

```cpp
// 아홉 중 두 명을 빼는 모든 조합 — 36가지
for (int i = 0; i < 9; i++)
  for (int j = i + 1; j < 9; j++)
    if (total - h[i] - h[j] == 100) { ... }
```

**「다 해 봐도 되는가」를 [[time-complexity]] 로 먼저 확인**하고, 되면 이것을 쓴다.

경우를 만드는 모양이 몇 가지다.

| 모양 | 언제 |
|---|---|
| 중첩 반복문 | 뽑을 개수가 고정 (둘을 빼기) |
| 재귀로 가지 뻗기 | 개수가 가변 → [[recursion]] |
| **조건을 바꿔 가며 전체를 반복** | 답이 되는 기준값을 모를 때 |

세 번째가 이 문제집의 안전영역 문제다 — **물 높이를 0부터 최대까지 올려 가며 매번 영역을 세고** 그중 최대를 고른다. 각 높이에서의 계산은 [[depth-first-search]] 이고, 그 바깥을 감싼 것이 완전탐색이다.

## 왜 중요한가

**정답을 보장한다.** 놓치는 경우가 없으므로 **틀릴 수 없고**, 다른 풀이를 검증하는 기준으로도 쓴다.

**그리고 「안 되는 이유」가 분명해진다.** 완전탐색이 시간을 넘으면 그때 비로소 **무엇을 줄일지**를 묻게 된다 — 중복 계산을 없앨지, 정렬로 순서를 만들지, 절반씩 쪼갤지 → [[divide-and-conquer]] · [[greedy-algorithm]]

**처음부터 영리하게 풀려다 틀리는 것보다 낫다.** 상한을 보고 되면 그냥 하는 것이 실전에서 빠르다.

## 경계와 오해

- **「완전탐색 = 느리다」가 아니다** — 경우의 수가 작으면 가장 빠르고 안전한 선택이다. 느린 것은 **경우의 수가 클 때**다
- **중복을 세지 않게 조심해야 한다** — `j = i + 1` 로 시작하는 것이 같은 쌍을 두 번 보지 않기 위한 장치다. 순서가 의미 없는 조합에서 흔히 틀리는 자리다
- **뽑는 것과 빼는 것을 뒤집으면 쉬워진다** — 아홉에서 일곱을 고르는 것과 **둘을 빼는 것**은 같은 문제인데 코드 길이가 다르다. 「무엇을 고를까」를 뒤집어 보는 것이 이 문제의 요령이다
- **가지치기를 해도 완전탐색이다** — 답이 될 수 없는 가지를 잘라 내도 **빠짐없이 본다는 성질은 유지**된다. 그것이 백트래킹이다
- **탐색과 계산을 겹쳐 쓰면 복잡도가 곱해진다** — 안전영역이 `높이 개수 × 격자 크기`인 것처럼 **바깥 반복이 안쪽 비용을 곱한다** → [[time-complexity]]

## 출처

- [[2025-04-30-Pr2309]] — 아홉 난쟁이 중 일곱을 고르는 문제. **뽑는 것이 아니라 빼는 것으로 뒤집은 것**이 이 풀이의 요점이다 — 일곱을 고르는 조합이 곧 「둘을 빼는 이중 반복문」이 되고 경우의 수는 36가지뿐이다. 상한이 작다는 것이 이 방법을 허락한다
