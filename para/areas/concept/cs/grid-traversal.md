# 격자 탐색 (dx·dy 배열과 경계 검사)

**2차원 배열에서 인접 칸으로 옮겨 다니는 코드의 정형.** 문제가 달라도 **이 뼈대는 그대로**다.

## 정의

```cpp
int dx[4] = {0, 1, 0, -1};      // 네 방향을 배열로
int dy[4] = {1, 0, -1, 0};

for (int i = 0; i < 4; i++) {
    int ny = y + dy[i];
    int nx = x + dx[i];

    if (ny < 0 || ny >= n || nx < 0 || nx >= m) continue;   // 1. 격자 밖인가
    if (visited[ny][nx]) continue;                          // 2. 이미 봤는가
    if (a[ny][nx] == 0) continue;                           // 3. 갈 수 있는가

    visited[ny][nx] = visited[y][x] + 1;
    q.push({ny, nx});
}
```

세 조각이 항상 함께 온다.

| 조각 | 하는 일 |
|---|---|
| **방향 배열** `dx`·`dy` | 네 방향(또는 여덟)을 **반복문으로** 돌게 만든다 |
| **경계 검사** | 배열 밖으로 나가는 것을 막는다 |
| **`visited`** | 같은 칸을 두 번 보지 않게 한다 — **없으면 끝나지 않는다** |

**검사 순서가 중요하다** — 격자 밖인지를 **가장 먼저** 봐야 한다. `a[ny][nx]` 를 먼저 읽으면 **범위 밖 메모리를 읽는다** → [[array]]

## 왜 중요한가

**같은 뼈대가 문제마다 다른 이름으로 나온다** — 미로의 최단 거리, 배추 덩어리 수, 안전 영역, 넓이 구하기. **바뀌는 것은 「무엇을 셀 것인가」뿐**이고 옮겨 다니는 코드는 같다.

**그리고 `visited` 를 어떻게 쓰느냐로 얻는 것이 달라진다.**

| 쓰는 법 | 얻는 것 |
|---|---|
| `visited[ny][nx] = 1` | **방문 여부만** — 덩어리 세기 → [[depth-first-search]] |
| `visited[ny][nx] = visited[y][x] + 1` | **거리까지** — 최단 거리 → [[breadth-first-search]] |

배열 하나가 「봤다」와 「몇 번째에 봤다」를 겸한다.

## 경계와 오해

- **경계 검사를 나중에 하면 터진다** — 조건 순서가 곧 안전이다. 이 문제집이 「경계값 조건을 먼저 탐색 후에 다른 조건을 검색하자」로 남긴 교훈이 이것이다
- **`visited` 는 큐에 넣을 때 표시한다** — 꺼낼 때 표시하면 **같은 칸이 큐에 여러 번 들어간다** → [[queue]]
- **배열을 넉넉히 잡는 것은 습관이지 해법이 아니다** — `a[104][104]` 처럼 여유를 두면 실수를 덜지만 **경계 검사를 대신하지는 않는다**
- **네 방향과 여덟 방향은 문제가 정한다** — 대각선을 인접으로 볼지가 답을 바꾸므로 **문제 문장에서 확인**해야 한다
- **좌표 표기를 섞으면 조용히 틀린다** — `(y, x)` 로 쓸지 `(x, y)` 로 쓸지 **한 파일 안에서 하나로** 정해 쓴다
