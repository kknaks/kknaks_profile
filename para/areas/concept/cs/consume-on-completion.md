# 소모성 자원은 완료 때 차감 — 「쓸 예정」 과 「썼다」 를 나눈다

회차권 · 이용권처럼 쓰면 줄어드는 자원은 **계획에 올린 순간**이 아니라 **그 일을 끝낸 순간** 줄인다. 계획 단계에서는 「오늘 사용 예정」 표시만 하고, 중간 취소 · 노쇼 · 진행 안 함이면 아무것도 되돌릴 필요가 없게 둔다.

## 정의

1. **두 상태를 가른다** — 예정(계획에 묶임 · 남은 수 그대로) / 사용(완료 · 남은 수에서 빠짐)
2. **차감 = 완료 사건** — 「작업에 자원 id 가 붙었다」 가 아니라 「그 작업이 done 이 됐다」 로 센다. cc-prototype 2차는 `ticket_used(steps)` 를 **state == done 인 단계의 ticketId** 로 바꿨다. 그 전에는 접수 · 시술 추가 · 결제 완료 때 붙은 ticketId 를 전부 사용으로 세서 `보유 n/m` 이 접수 순간 줄었다
3. **사용 수는 저장하지 않고 완료에서 계산한다** — 따로 차감 기록을 쓰지 않으면, 완료를 되돌리는(undo) 순간 사용도 자연히 되돌아간다. 취소 · 노쇼 · 진행 안 함은 done 이 아니라 애초에 안 빠진다
4. **예정끼리의 겹침은 따로 막는다** — 차감은 완료 때여도, 같은 장을 두 작업에 동시에 묶지 못하게 하는 것은 「예정」 단계의 규칙이다. 묶음(10회권)의 한 회차가 이미 계획에 있으면 그 묶음을 다시 후보로 띄우지 않는다

## 왜 중요한가

- 계획 때 줄이면 **취소마다 보상 처리**가 생긴다. 시술 중간 취소 · 노쇼는 흔하고, 되돌림을 빠뜨리면 고객의 남은 회차가 조용히 사라진다
- 「묶였다」 를 사용으로 세면 화면의 숫자가 거짓이 된다 — 접수 직후 「보유 9/10」 이 보이지만 실제로는 아직 아무것도 하지 않았다
- 외부 원천 시스템도 대개 같은 모양이다 — KOS 캡처에서 시술권은 작업 DONE → USED, CANCELED → 유지였다

## 경계와 오해

- **결제 시점 ≠ 차감 시점** — 돈을 받는 것(결제)과 권리를 쓰는 것(차감)은 다른 사건이다. 회차권은 이미 결제가 끝난 권리다
- **재고 예약(hold)과 다르다** — 여기서 「예정」 은 남은 수를 잠그지 않는 표시일 뿐이다. 동시 예약이 문제라면 별도의 잠금 · 홀드가 필요하다
- **완료가 외부 시스템에 반영돼야 하면** 차감 반영도 그 완료 사건에 붙인다(cc-prototype 은 `finish` 자리에 `kos api 연동 필요` 주석)
