# 시범으로 꼴을 굳히고 묶음으로 나눈 뒤 전수로 되센다

큰 원천을 여러 작업자가 나눠 가공할 때의 순서. **작은 시범으로 표 · 칸을 먼저 확정하고**, 나머지를 3~4 묶음으로 나눠 병렬로 쓰고, 합치는 작업자가 겹침 · id · 외래키를 다시 검사한 뒤, **합친 결과에서 원천을 다시 전수로 뽑아 빠진 것을 센다.** 묶음 경계에서 빠진 것은 묶음 안에서는 보이지 않는다.

## 정의

1. **시범** — 대표 묶음 2~3개(큰 것 · 작은 것 · 성질이 다른 것)로 한 작업자가 끝까지 간다. 산출은 데이터가 아니라 **표 구조와 「담을 칸 없는 값」 목록**이다
2. **구조 확정** — 담을 칸 없는 값이 0 이 될 때까지 표 · 칸을 고친다. 여기서 확정한 꼴이 모든 묶음의 계약이 된다
3. **묶음 병렬** — 나머지를 묶음으로 나눠 같은 브리프 · 같은 검사로 돌린다. 묶음 사이에 걸치는 항목은 **누가 맡는지 규칙을 적는다**(「둘 사이 관계는 번호가 작은 묶음이 맡는다」)
4. **합치기** — 별도 작업자가 id 충돌 · 겹침 · 외래키를 검사하고 하나로 만든다
5. **보완** — 합친 결과를 기준으로 원천을 **다시 전수로** 뽑아 빠진 항목을 세고, 담을 것은 행으로 · 안 담을 것은 「안 담음 — 이유」로 남긴다

## 왜 중요한가

- 원천 전체를 한 작업자가 한 번에 하면 검수가 불가능하고, 시범 없이 나누면 묶음마다 꼴이 달라 합칠 수 없다
- **묶음 경계가 누락의 자리다.** 걸치는 항목을 서로 상대 묶음 몫으로 넘기면 합칠 때 어느 쪽에도 없다. 겹침 규칙을 적어도 해석이 갈리면 같은 일이 난다 — 그래서 합친 뒤 전수 재추출이 절차 안에 있어야 한다
- 「약 160 빠졌다」 같은 어림은 틀린다 — 실제 재추출은 198 · 15 항목이었다. 세어 보기 전엔 수를 말하지 않는다

## 경계와 오해

- **시범 ≠ 작은 본작업** — 시범의 산출은 확정된 데이터가 아니라 **표 구조**다. 시범 결과를 그대로 본작업에 넣으려면 확정 단계를 한 번 더 거친다
- **겹침 규칙이 있다 ≠ 빠지지 않는다** — 규칙은 누락을 줄이지만 없애지 않는다. 검출기는 합친 뒤의 전수 대조다
- **합치기 검사 ≠ 보완** — 합치기는 「들어온 것끼리」 맞는지 보고, 보완은 「원천에 있는데 안 들어온 것」을 본다. 둘은 다른 질문이다
- **시점을 박은 묶음 검사는 합친 뒤 깨진다** — 묶음마다 둔 검사가 자기 시작 시점의 해시 · 행 수를 기대하면 다음 단계가 데이터를 고칠 때 FAIL 난다 → [[schema-parity-test]]
