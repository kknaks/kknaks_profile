# BFS (너비 우선 탐색)

**가까운 것부터 한 겹씩 넓혀 가며 보는 탐색.** 그래서 **처음 닿은 순간이 곧 최단 거리**다.

## 정의

큐에 넣고 꺼내는 것이 전부다 → [[queue]]

```cpp
queue<pair<int, int>> q;
q.push({0, 0});
visited[0][0] = 1;                       // 출발 칸을 1로 두면 칸 수가 그대로 답이 된다

while (q.size()) {
    tie(y, x) = q.front(); q.pop();

    for (int i = 0; i < 4; i++) {        // 인접 칸으로 → [[grid-traversal]]
        int ny = y + dy[i], nx = x + dx[i];
        if (경계 밖 || visited[ny][nx] || 못 가는 칸) continue;

        visited[ny][nx] = visited[y][x] + 1;   // 이전 칸 + 1
        q.push({ny, nx});
    }
}
cout << visited[n - 1][m - 1];
```

```
출발 ─┬─ 1칸 거리 전부 ─┬─ 2칸 거리 전부 ─┬─ ...
      └────────────────┴────────────────┘
      한 겹을 다 본 뒤에 다음 겹으로 간다
```

**`visited` 가 방문 표시와 거리를 겸한다** — `visited[y][x] + 1` 한 줄이 「몇 번째 겹인가」를 이어 간다.

## 왜 중요한가

**가중치가 없는 최단 거리는 이것으로 끝난다.** 모든 이동의 비용이 같으면 **먼저 닿은 것이 가장 짧은 것**이므로, 도착 칸에 처음 값이 적히는 순간 답이다 — 더 볼 필요가 없다.

**「최단」이라는 낱말이 문제에 있으면 먼저 이것을 떠올린다.** 이 문제집의 판단이 그대로다: 「가중치가 없는 최단 거리 → BFS 로 판단 가능」 → [[time-complexity]]

## 경계와 오해

- **가중치가 있으면 BFS 로는 안 된다** — 이동 비용이 다르면 「먼저 닿은 것이 가장 싼 것」이 성립하지 않는다. 그때는 다른 방법이 필요하다
- **`visited` 를 꺼낼 때 표시하면 느려지고 틀릴 수 있다** — 같은 칸이 큐에 여러 번 들어가고, 나중에 들어간 더 긴 경로가 값을 덮어쓸 수 있다. **넣을 때 표시**한다
- **BFS 는 재귀로 쓰지 않는다** — 큐가 본질이라 반복문으로 쓴다. 재귀로 쓰는 것은 [[depth-first-search]] 쪽이다
- **출발을 0 으로 둘지 1 로 둘지가 답을 바꾼다** — 「지나는 칸 수」를 세는 문제라 이 풀이는 출발을 1 로 뒀다. **무엇을 세는지**에 맞춰야 한다
- **메모리를 DFS 보다 많이 쓸 수 있다** — 한 겹의 칸이 전부 큐에 들어가므로 넓은 격자에서는 큐가 커진다 → [[time-complexity]]
- **도착하면 멈출 수 있다** — 이 풀이는 전부 돈 뒤 도착 칸을 읽는데, 도착 즉시 끝내면 그만큼 아낀다. 답은 같다

## 출처

- [[2025-06-11-pr2178]] — 미로에서 (1,1) 에서 (N,M) 까지의 최소 칸 수. 「**가중치가 없는 최단 거리 / BFS 로 판단 가능**」이라는 두 줄이 문제에서 알고리즘으로 가는 판단을 그대로 보인다. 코드에서 `visited[ny][nx] = visited[y][x] + 1` 한 줄이 방문 표시와 거리 누적을 겸하고, 「최단 거리는 전에 방문 횟수에 +1을 해주자」가 이 회차의 교훈으로 남았다. 입력이 붙어 있는 숫자열이라 `s[j] - '0'` 로 문자에서 숫자를 뽑는 처리도 함께 있다
