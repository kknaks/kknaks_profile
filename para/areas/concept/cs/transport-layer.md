# 전송계층 (3방향 핸드셰이크·혼잡제어)

**끝에서 끝까지 「제대로 도착했는가」를 책임지고, 도착한 것을 어느 프로그램에 줄지 정하는 층.** 아래층이 길을 찾았다면 여기는 **그 길로 온 것이 온전한지**를 본다 → [[network-layer]]

## 정의

역할이 둘이다.

1. **오류를 점검한다** — 혼잡제어 · 흐름제어 · 오류제어
2. **어느 애플리케이션에 줄지 식별한다** — 포트 번호 → [[port-number]]

### 제어 셋

| 제어 | 무엇을 맞추나 |
|---|---|
| **혼잡제어** | **네트워크**가 감당할 양 — 잘 가면 늘리고, 타임아웃이나 중복 ACK 가 오면 줄인다 |
| **흐름제어** | **받는 쪽**이 감당할 양 — ACK 를 받아야 다음을 보낸다 |
| **오류제어** | 확인응답과 시간초과로 **손실·순서 뒤바뀜·훼손**을 잡아 재전송 |

**혼잡제어와 흐름제어가 다른 것을 본다** — 앞은 길이 막히는 것, 뒤는 상대가 못 받는 것이다. 이름이 비슷해 섞기 쉬운 자리다.

### 3방향 핸드셰이크

```
송신자 ──SYN(임의의 번호 x)──▶ 수신자          "연결할까요?"
       ◀─SYN(y) + ACK(x+1)──                "네, 그쪽은요?"
       ──ACK(y+1)──────────▶                "좋습니다"
```

**서로가 「보낼 준비」와 「받을 준비」를 각각 확인**하므로 세 번이 필요하다 → [[tcp]]

### TCP 헤더가 들고 있는 것

| 항목 | 무엇 |
|---|---|
| **일련번호** | 보내는 데이터가 **몇 번째 바이트부터**인지 |
| **확인응답번호** | 받은 쪽이 **어디까지 받았는지** (받은 크기 + 일련번호) |
| **윈도우 크기** | 한 번에 보낼 수 있는 **최대 크기** — 상대가 받을 수 있는 양 |
| **코드비트** | 이 패킷의 성격 — URG · ACK · PSH · RST · **SYN** · **FIN** |

```
1500바이트를 500씩 보낼 때 일련번호:  1 → 501 → 1001
```

**연결을 열 때의 코드비트가 `SYN=1`**, 두 번째 응답이 `SYN=1, ACK=1` 이다.

### UDP — 축약된 쪽

헤더에 **송신·수신 포트, 길이, 검사합** 넷뿐이다. **신뢰성을 보장하지 않는 대신 빠르고**, 브로드캐스트에 주로 쓴다 → [[tcp]]

## 왜 중요한가

**「연결」이라는 말의 실체가 여기서 드러난다.** 물리적으로 이어진 선이 생기는 것이 아니라 **양쪽이 번호를 주고받고 서로의 상태를 기억하기 시작하는 것**이다 — 그래서 연결에 비용이 들고, 끊긴 것을 알아채는 데 시간이 걸린다 → [[socket]]

**그리고 포트 번호가 이 층의 것이라는 게 중요하다.** IP 가 기계까지 데려다주고, **포트가 그 안의 프로그램을 고른다** — 한 서버에 여러 서비스가 함께 사는 근거다 → [[port-number]] · [[socket-binding]]

## 경계와 오해

- **혼잡제어는 「네트워크에 미안해서」 하는 것이다** — 내 처리량만 보면 무조건 많이 보내는 게 낫지만, 모두가 그러면 **길이 막혀 전부 느려진다.** 잘 가면 늘리고 실패하면 줄이는 규칙이 그 균형이다 → [[universal-scalability-law]]
- **흐름제어를 「정지-대기」로만 이해하면 느린 이유를 모른다** — 하나 보내고 ACK 를 기다리면 왕복 시간마다 한 개다. **윈도우 크기**가 그것을 「ACK 없이도 이만큼은 보내도 된다」로 바꾼다 → [[little-law]]
- **UDP 가 「나쁜 TCP」가 아니다** — 실시간 영상·음성은 **늦게 온 재전송이 쓸모없다.** 잃더라도 계속 가는 것이 맞는 경우가 있다
- **3방향 핸드셰이크는 공격에도 쓰인다** — SYN 만 보내고 마지막 ACK 를 안 보내면 서버가 **반쯤 열린 연결을 쌓아 두게** 된다(SYN 플러딩)
- **일련번호가 랜덤으로 시작한다는 것이 보안 장치다** — 0 부터 시작하면 남이 번호를 짐작해 끼어들 수 있다. 필기가 「일련번호는 랜덤으로 생성」이라 적어 둔 이유다
- **필기의 코드비트 표에 오기가 있다** — `TRUG`·`RSH`·`TURG` 는 각각 **URG**(긴급)·**PSH**(상위 계층에 즉시 전달)의 오기다

## 출처

- [[2024-10-23-chapter6-transport]] — 「전송계층의 역할」이 **오류 점검**과 **어느 애플리케이션에 전달할지 식별** 둘로 역할을 갈랐다. 혼잡제어를 「하나만 보내고 ACK 가 오면 2배 증가 / 타임아웃이면 줄이고 / 동일한 ACK 가 여러 번 오면 줄이고 / 정상이면 다시 배수로」로 **알고리즘의 골격까지** 적은 것이 이 장에서 가장 값진 부분이다. 「3방향 핸드셰이크」는 SYN·ACK 의 숫자가 **`+1` 로 이어지는 것**을 대화체 주석과 함께 보였다. TCP 헤더 절이 **포트 번호 세 구간**(well-known / registered / dynamic)과 주요 포트 표, **일련번호·확인응답번호를 1500바이트를 500씩 나눠 보내는 예**로 설명하고, 윈도우 크기를 「송신 가능 > 수신 가능이면 데이터 누수」로 짚는다. UDP 헤더는 **넷뿐인 필드 표**로 TCP 와의 차이를 보인다. 다만 코드비트 표의 `TRUG`·`RSH` 는 URG·PSH 의 오기다 → [[tcp]] · [[load-balancer]]
