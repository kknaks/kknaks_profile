# DNS (Domain Name System)

**이름을 IP 주소로 바꿔 주는 조회 체계.** Day46 의 한 줄이 정의다 — 「IP 주소를 모르면 DNS서버에 접근하여 IP주소를 검색한다」. 통신은 언제나 [[ip-address]] 로 이뤄지고, 이름은 **접속 직전에 주소로 바뀌어 사라진다.**

## 정의

이름으로 접속하는 코드에는 **단계가 하나 숨어 있다.**

```text
"www.example.com"  ──(DNS 조회)──▶  93.184.216.34  ──(접속)──▶  연결
```

자바는 이 단계를 `InetAddress` 의 정적 메서드로 노출한다.

```java
InetAddress ia = InetAddress.getByName(String domainName);
InetAddress[] iaArr = InetAddress.getAllByName(String domainName);
```

**둘의 차이가 이 개념의 핵심을 담고 있다.** 하나를 돌려주는 것과 배열을 돌려주는 것이 함께 있는 이유는 **이름 하나에 주소가 여럿일 수 있기** 때문이다. 큰 서비스는 같은 이름에 IP 를 여러 개 등록해 두고, 조회할 때마다 순서를 바꿔 내려 준다 — `getByName` 이 돌려주는 「그 하나」는 **그중 첫 번째일 뿐 고정된 값이 아니다.**

## 사용 예시

Day46 은 얻은 주소를 그대로 소켓 생성자에 넘긴다.

```java
Socket socket = new Socket(InetAddress.getByName("domainName"),50001);
```

**포트는 여전히 손으로 적는다.** 이름이 대신해 주는 것은 IP 뿐이고, 이름 안에 포트가 들어 있지 않다 — `Socket(String, int)` 처럼 문자열을 그대로 넘기는 형태도 결국 안에서 같은 조회를 한다 → [[port-number]]

## 왜 중요한가

**서버를 옮겨도 클라이언트를 다시 배포하지 않는다.** IP 를 코드에 적어 두면 서버 이사가 곧 클라이언트 수정인데, 이름을 적어 두면 **바꿀 곳이 DNS 한 곳**이다. 「내 컴퓨터에서는 됐는데」의 원인으로 IP 하드코딩을 짚었던 자리에서, 이름이 그 답의 절반이 된다 → [[ip-address]] · [[command-line-arguments]]

**기계 여러 대를 이름 하나로 가릴 수 있다.** `getAllByName` 이 배열인 것이 그 증거다 — 클라이언트는 몇 대가 있는지 모른 채 이름만 알고, 뒤에서 대수가 늘거나 줄어도 코드가 그대로다. 부하 분산과 장애 대체의 가장 싼 형태가 여기서 나온다 → [[distributed-processing]]

**실패가 한 종류 늘어난다.** 이름을 쓰면 「주소를 못 찾음」과 「찾았는데 못 붙음」이 갈리고, 자바는 그것을 `UnknownHostException` 과 `ConnectException` 으로 구별해 준다. **접속 코드 한 줄이 실패할 수 있는 방식이 둘이 되는 대가**로 위의 이득을 얻는 것이다 → [[exception-handling]]

## 경계와 오해

- **DNS 조회 ≠ 접속** — 이름을 넣고 접속하는 코드가 한 줄이라 한 번에 일어나는 것으로 보이는데, **조회가 먼저 끝나고 그 결과로 접속한다.** 그래서 조회가 느리면 접속 시도조차 시작되지 않고, 조회는 서버가 죽어 있어도 성공한다 — **이름이 풀리는 것은 그 서버가 살아 있다는 증거가 아니다.** 「DNS 는 되는데 접속이 안 된다」가 모순이 아닌 이유다.
- **「IP 주소를 모르면 DNS 서버에 접근한다」는 도메인 이름을 알 때의 이야기다** — Day46 의 문장은 IP 를 모르면 언제든 찾을 수 있는 것처럼 읽히는데, DNS 는 **이름 → 주소** 사전이다. 이름도 모르면 찾을 방법이 없다. 그리고 **DNS 서버 자체는 IP 로 찾아간다** — 이름으로 찾으면 무한히 돌기 때문이고, 그 IP 는 코드가 아니라 OS 설정(대개 DHCP 로 받는다)에 있다. **이름을 쓰는 체계의 밑바닥에는 이름 없이 아는 주소가 하나 있어야 한다.**
- **도메인 이름 ≠ URL** — `https://example.com:8080/api` 에서 이름은 `example.com` 한 조각뿐이다. 프로토콜·포트·경로는 DNS 가 모른다. 「주소창에 치는 것」을 전부 도메인으로 부르면 **왜 포트를 따로 적어야 하는지**가 설명되지 않는다 → [[network-protocol]]
- **도메인(도메인 이름) ≠ 도메인(업무 영역)** — 개발에서 「도메인」은 업무 영역·모델을 뜻하는 말로도 쓰인다(도메인 객체, 도메인 로직). **낱말이 같고 관계가 전혀 없다.** 이 노트를 가리킬 때 `[[도메인]]` 이 아니라 `[[domain-name-system]]` 으로 거는 이유다.
- **`localhost` 가 되는 것은 DNS 때문이 아니다** — 이름을 주소로 바꾸는 일은 DNS 서버에 묻기 **전에** 먼저 `hosts` 파일에서 찾는다. `localhost` → `127.0.0.1` 은 거기에 적혀 있어서 **네트워크가 끊겨 있어도** 풀린다. 그래서 개발 중에는 `hosts` 에 줄을 넣어 이름을 내 기계로 돌릴 수 있고, 반대로 **거기 남은 줄 때문에 DNS 를 고쳤는데 안 바뀌는** 일도 생긴다 → [[ip-address]]
- **조회 결과는 캐시된다 — 그것이 배포 사고가 되는 자리다** — OS 도 JVM 도 결과를 들고 있는다. 특히 JVM 은 성공한 조회를 기본적으로 오래(설정에 따라 영구히) 캐시하므로, **DNS 에서 새 IP 를 가리키게 바꿔도 이미 돌고 있는 자바 프로세스는 옛 IP 로 계속 접속한다.** 「DNS 를 바꿨는데 왜 아직 옛 서버로 가나」의 답이 이것이고, 서버를 재시작해야 반영되는 이유다 → [[caching]]
- **주소를 이름으로 되돌리는 것은 별개이고 비싸다** — 반대 방향 조회(reverse lookup)는 다른 기록을 쓰고 없을 수도 있다. 자바에서 `InetSocketAddress.getHostName()` 은 그 조회를 **몰래 시도해 멈출 수 있고**, `getHostString()` 은 하지 않는다. Day46 이 접속한 클라이언트를 볼 때 `getHostString()` 을 쓴 것이 결과적으로 맞는 선택인데, **두 메서드가 비슷한 이름으로 나란히 있고 하나만 네트워크를 탄다** → [[socket-binding]]
- **이름이 있어도 IP 는 여전히 필요하다** — 이름은 **찾는 방법**이고 통신은 주소로 한다. 그래서 방화벽·라우팅·접근 제어는 전부 IP 기준이고, 「이름으로 허용」은 그 이름이 지금 가리키는 주소를 허용하는 것이라 **주소가 바뀌면 조용히 어긋난다** → [[ip-address]]
