# 누적합과 슬라이딩 윈도우

**구간의 합을 매번 다시 더하지 않는 것.** 창을 한 칸 밀 때 **빠지는 것을 빼고 들어오는 것을 더한다.**

## 정의

연속한 K일의 최대 온도 합을 구한다고 하자.

```
[매번 다시 더하기]  구간마다 K 번 더한다      → O(N × K)
[창을 밀기]         sum = sum - 빠지는 값 + 들어오는 값  → O(N)
```

```cpp
int sum = 0;
for (int i = 0; i < k; i++) sum += a[i];    // 첫 창
int best = sum;

for (int i = k; i < n; i++) {
    sum = sum - a[i - k] + a[i];             // 한 칸 밀기
    best = max(best, sum);
}
```

**바뀌는 것은 양 끝 두 개뿐**이라는 관찰이 전부다 → [[time-complexity]]

### 사촌 — 구간에 값을 뿌려 두기

트럭 주차 문제는 방향이 반대다. **구간을 훑는 것이 아니라 구간에 표시해 둔다.**

```cpp
for (각 트럭) for (t = 시작; t < 끝; t++) cnt[t]++;   // 시간마다 몇 대인지
for (t = 1; t <= 100; t++) fee += 요금[cnt[t]] * cnt[t];
```

**시간 축을 배열로 펼쳐 두고 세는 것**이라, 상한(1~100)이 작기 때문에 성립한다.

## 왜 중요한가

**같은 값을 여러 번 더하지 않는다는 것이 많은 최적화의 원형이다.** 겹치는 계산을 알아채고 **재사용하는 것**이 [[divide-and-conquer]] 의 절반 재사용과도, 캐시와도 같은 발상이다 → [[caching]]

**그리고 「무엇이 바뀌는가」만 보는 습관을 준다.** 전체를 다시 계산하는 코드를 보면 **변하는 부분만 갱신할 수 있나**를 묻게 된다.

## 경계와 오해

- **첫 창을 따로 만들어야 한다** — 반복문 안에서 밀기만 하면 시작값이 없다. **초기 K개를 먼저 더하는 줄**을 빠뜨리기 쉽다
- **인덱스가 하나 어긋나기 쉽다** — 빠지는 것이 `a[i-k]` 인지 `a[i-k+1]` 인지가 창의 정의에 달렸다. **작은 예제로 손으로 확인**하는 것이 빠르다
- **합이 넘칠 수 있다** — 값과 개수가 크면 `int` 를 넘는다 → [[overflow]]
- **구간을 배열로 펼치는 방식은 상한에 기댄다** — 트럭 주차가 1~100 이라 되는 것이지, 범위가 크면 **그 배열 자체가 불가능**하다 → [[time-complexity]]
- **누적합 배열과 슬라이딩 윈도우는 다른 도구다** — 누적합 배열(`S[i] = a[0..i]`)은 **아무 구간이나 O(1)** 로 답하고, 슬라이딩 윈도우는 **고정 크기 창을 밀 때** 쓴다. 이 문제집은 뒤쪽이다
