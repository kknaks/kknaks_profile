# 증감 연산자 (Increment / Decrement)

값을 1 증가시키거나 감소시키는 연산자. **연산자를 앞에 붙이는지 뒤에 붙이는지에 따라 값을 쓰는 시점이 달라진다.**

## 정의

| 표기 | 이름 | 순서 |
|---|---|---|
| `++i` · `--i` | 전위 (pre-fix) | **먼저 바꾸고** 그 값을 쓴다 |
| `i++` · `i--` | 후위 (post-fix) | **먼저 쓰고** 그 다음에 바꾼다 |

후위 연산은 바뀌기 전 값을 어딘가에 잠깐 남겨 둔다. 옛 필기가 그것을 이렇게 풀어 썼다.

```java
i++;
// int temp = i;      ← 현재 값을 임시로 저장한다
// i = i + 1;
// temp 를 아무도 쓰지 않으면 temp 는 사라진다
```

전위는 순서가 뒤바뀐다.

```java
--i;
// i = i - 1;
// temp = i;
```

**`i` 가 바로 증가하는 것이 아니라 레지스터에 값을 임시로 저장하고 그 값을 쓰는 것**이며, 어셈블리어를 보면 확인할 수 있다.

## 사용 예시

값을 쓰는 자리에 후위 연산을 두면 순서가 드러난다.

```java
int i = 2;
i++;                          // i = 3  (결과를 아무도 안 쓴다)
System.out.println(i++);      // 3 을 출력하고 i 는 4 가 된다
System.out.println(i);        // 4
```

첫 줄처럼 **결과를 쓰지 않는 자리에서는 전위·후위가 같다.** `i++;` 과 `++i;` 는 구별할 이유가 없다. 차이는 그 값을 쓸 때만 나타난다.

### 열흘 뒤 실습에서 네 자리가 다 나온다

같은 회차의 코드 안에 전위·후위가 각각 두 번 쓰이는데, **네 자리 모두 값을 쓰는 자리**라 하나도 바꿔 쓸 수 없다.

```java
public static int getSeqNo()   { return ++seqNo; }              // 올린 값을 준다
public static void add(User u) { users[userLength++] = u; }      // 늘리기 전 칸에 넣는다
public static User delete(...) { users[--userLength] = null; }    // 줄인 뒤 칸을 비운다
for (int i = index + 1; i < userLength; i++) { ... }             // 결과를 안 쓴다
```

| 코드 | 쓰이는 값 | 후위/전위를 바꾸면 |
|---|---|---|
| `return ++seqNo` | 올린 뒤 값 | 첫 회원 번호가 `0` 이 된다 |
| `users[userLength++]` | 늘리기 전 값 | 빈 칸 하나를 건너뛰고 넣는다 |
| `users[--userLength]` | 줄인 뒤 값 | 쓰지 않는 칸을 비우고 마지막 값이 남는다 |
| `i++` | 없음 | 아무 차이 없다 |

**세 자리는 값의 뜻이 다 다르다.** 「지금까지 발급한 개수」에서 다음 번호를 얻으려면 올린 뒤 값이고, 「지금 몇 개 들었나」에서 넣을 칸을 얻으려면 올리기 전 값이다 — 개수와 인덱스가 `1` 차이라는 것이 전위·후위 선택으로 표현된다 → [[one-based-numbering]] · [[surrogate-key]]

## 왜 중요한가

**한 줄에 "값을 쓰는 일"과 "값을 바꾸는 일"이 함께 들어 있다.** 그래서 그 줄의 결과를 읽으려면 순서를 알아야 하고, 순서를 잘못 짚으면 1 만큼 어긋난 값으로 계속 계산한다. 배열 인덱스나 반복 카운터에서 이 어긋남이 흔하다.

거꾸로 말하면, **결과를 쓰지 않는 자리라면 전위·후위를 고민할 필요가 없다.** 반복문의 `i++` 이 그런 자리다.

## 경계와 오해

- **한 식에서 같은 변수를 여러 번 증감시키지 않는다** — `i++ + i++` 같은 코드는 읽는 사람이 순서를 추적해야 한다. 동작이 정해져 있어도 쓰지 않는 편이 맞다.
- **후위 연산의 결과는 바뀌기 전 값이다** — `System.out.println(i++)` 이 증가 후 값을 출력할 것으로 읽기 쉽다. 옛 필기의 마지막 예시도 `i` 를 `5` 라고 적어 두었는데 실제로는 `4` 다 — `i++` 두 번(`3`→`4`)이 아니라 `i++`(2→3) 뒤 `println(i++)`(3 출력, 4)이므로 남는 값은 `4` 다.
- **증감 연산자는 변수에만 쓴다** — `5++` 처럼 [[literal]] 에는 쓸 수 없다. 바꿀 자리가 있어야 한다 → [[variable]]
- **`i = i++` 는 값이 바뀌지 않는다** — 후위 연산이 돌려준 옛 값을 다시 `i` 에 대입하기 때문이다.
- **`return ++seqNo` 를 「1 더해서 돌려준다」로 읽으면 절반이 빠진다** — 필드가 실제로 바뀐다. `return seqNo + 1` 은 같은 값을 돌려주면서 아무것도 바꾸지 않으므로, **두 번 부르면 같은 번호가 나와** 식별 번호가 겹친다. 한 글자 차이가 「발급」과 「계산」을 가른다 → [[read-side-effect]]
- **증감 연산자 한 개도 원자적이지 않다** — `++seqNo` 는 한 식이지만 읽고·더하고·쓰는 세 단계로 실행되므로, 스레드 둘이 동시에 부르면 같은 번호를 받는다. 「한 줄이니 한 동작」으로 보이는 것이 이 오해의 원인이다 → [[bytecode]]
- **결과를 쓰지 않는 자리에서만 취향의 문제다** — `for` 의 `i++` 이 그 자리다. 배열 인덱스나 발급 카운터처럼 값을 쓰는 자리에서는 **둘 중 하나만 맞다.**
