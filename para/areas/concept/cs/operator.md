# 연산자 (Operator)

값을 계산하거나 비교하는 문법. Java 의 연산자는 종류가 일곱 갈래이고, 어느 것을 먼저 계산하는지는 **우선순위**가 정한다.

## 정의

| 이름 | 종류 | 하는 일 |
|---|---|---|
| 산술 연산자 | `+` `-` `*` `/` `%` | 두 값을 사칙연산한다 |
| 관계 연산자 | `>` `<` `>=` `<=` `==` `!=` | 두 값을 비교한다 |
| 논리 연산자 | `&&` `\|\|` `!` `^` | 두 논리값을 비교한다 → [[short-circuit-evaluation]] |
| 비트 연산자 | `&` `\|` `^` `~` `>>` `>>>` `<<` | 비트를 연산한다 → [[bitwise-operator]] · [[bit-shift]] |
| 조건 연산자 | `조건 ? 값1 : 값2` | 조건에 따라 값을 정한다 → [[ternary-operator]] |
| 증감 연산자 | `i++` `++i` `i--` `--i` | 1 증가·감소시킨다 → [[increment-operator]] |
| 할당 연산자 | `+=` `-=` `*=` `/=` `%=` | 계산하고 대입한다 |

**우선순위에 따라 코드가 수행된다.** 순서를 확실히 하려면 `()` 로 묶는다 — 특히 [[bit-shift]] 는 우선순위가 낮아서 괄호가 필요하다.

### 산술 연산자

```java
System.out.println(100 + 27);
System.out.println(100 - 27);
System.out.println(100 * 27);
System.out.println(100 / 27);
System.out.println(100 % 27);   // 나눈 나머지
```

### 관계 연산자 — 결과는 `boolean` 이다

```java
int a = 10, b = 20;

boolean r1 = a < b;      // true
// int r2 = a < b;       // 컴파일 오류! 비교 결과는 boolean 이다
```

### 할당 연산자 — 대입과 연산의 축약

```java
int i = 2;

i = i + 20;    // 이 코드를
i += 20;       // 이렇게 줄인다

i = 2;
i *= 5;        // 10
```

`&=` `|=` `^=` `<<=` `>>=` `>>>=` 도 같은 방식으로 있다.

## 왜 중요한가

**연산자마다 결과 타입이 정해져 있다는 것이 핵심이다.** 관계 연산의 결과는 `boolean` 이라 `int` 에 담을 수 없고, 산술 연산의 결과는 피연산자 타입을 따라간다 → [[type-promotion]]. 이 규칙을 모르면 컴파일 오류의 이유를 짐작할 수 없다.

우선순위는 외우기보다 **괄호로 드러내는 쪽**이 낫다. 읽는 사람이 규칙을 기억해야 하는 코드는 그 자체로 비용이다.

### 두 달 반 뒤 — 그 비용이 권한 검사에서 청구된다

Day66 의 게시글 변경 서블릿이 괄호 없이 `||` 와 `&&` 를 섞었다.

```java
} else if (loginUser == null || loginUser.getNo() > 10 && board.getWriter().getNo() != loginUser.getNo()) {
  out.println("<p>변경 권한이 없습니다.</p>");
```

**`&&` 가 `||` 보다 우선순위가 높으므로** 실제로 묶이는 것은 이렇다.

```java
loginUser == null || (loginUser.getNo() > 10 && board.getWriter().getNo() != loginUser.getNo())
```

즉 **회원 번호가 10 이하면 뒤 조건 전체가 거짓이 되어 남의 글도 고칠 수 있다.** 「번호 10 이하는 관리자」를 뜻한 것으로 보이지만, 그 규칙이 어디에도 적혀 있지 않고 **가입 순서가 권한이 된다.**

괄호를 앞쪽에 묶으면 정반대가 된다 — `(a || b) && c` 로 읽으면 로그인하지 않은 사람도 조건에 걸리는 방식이 달라진다. **어느 쪽이 의도였는지 코드만 보고는 알 수 없다**는 것이 이 자리의 진짜 문제다 → [[short-circuit-evaluation]] · [[http-session]]

## 경계와 오해

- **비교 결과를 숫자로 쓸 수 없다** — C 계열에서는 `true` 가 1 로 통하지만 Java 는 `boolean` 과 숫자가 다른 타입이다. `int r = a < b;` 는 컴파일 오류다.
- **`/` 는 피연산자 타입을 따른다** — `100 / 27` 은 정수끼리라 `3` 이다. 소수를 얻으려면 한쪽을 실수로 만들어야 한다.
- **축약형은 형변환을 숨긴다** — `i += 1.5` 는 컴파일되지만 `i = i + 1.5` 는 오류다. 축약형에 암묵적 형변환이 들어 있어서다. "그냥 축약"이라고만 알면 이 차이를 설명할 수 없다.
