# 레퍼런스 (Reference)

값을 직접 담지 않고 **메모리의 주소를 담는 변수.** `new` 가 리턴한 시작 주소를 받아 두는 자리이고, 이것이 기본 타입 변수와 갈리는 지점이다.

## 정의

```java
int[] arr1 = new int[5];
```

`arr1` 은 다섯 개의 `int` 를 담고 있는 것이 아니다. `new` 가 확보한 [[instance]] 의 **시작 주소**를 담고 있다.

| | 담는 것 | 예 |
|---|---|---|
| 기본 타입 변수 | 값 자체 | `int i = 5;` |
| 레퍼런스 | 인스턴스의 주소 | `int[] arr = new int[5];` |

아무것도 가리키지 않는 상태를 `null` 이라 한다.

```java
int[] arr1;
arr1 = new int[5];

// 배열 레퍼런스를 초기화시키고 싶다면 null로 설정하라.
arr1 = null; // 즉 레퍼런스가 아무것도 가리키지 않음을 의미.
```

## 사용 예시

`null` 인 레퍼런스로 인스턴스에 닿으려 하면 실행 중에 터진다.

```java
// 레퍼런스가 배열 인스턴스를 가리키지 않은 상태에서 사용하려 하면?
System.out.println(arr1[0]); // NullPointerException 실행 오류!
```

레퍼런스를 다른 인스턴스로 바꾸면 **앞의 인스턴스는 가리키는 것이 없어진다.**

```java
int[] arr = new int[5];   // 인스턴스 A 를 가리킨다
arr = new int[3];         // 이제 B 를 가리킨다 → A 는 가비지
```

→ [[garbage-collection]]

## 왜 중요한가

**"값을 담는 변수"와 "주소를 담는 변수"가 갈리면 세 가지가 한꺼번에 설명된다.**

1. **대입이 복사가 아니다** — `b = a` 는 주소만 복사한다. 그 뒤 `b[0]` 을 바꾸면 `a[0]` 도 바뀐다. 인스턴스는 하나이고 그것을 가리키는 이름이 둘인 상태다.
2. **메서드에 넘긴 배열의 내용은 바뀔 수 있다** — 넘어가는 것은 주소의 복사본이므로, 호출된 쪽에서 원소를 고치면 호출한 쪽에도 보인다. 반대로 매개변수에 다른 배열을 대입하는 것은 호출한 쪽에 영향이 없다. Day13 의 `m1(values)` 예제가 그것을 코드로 확인한 자리다 → [[call-by-value]]
3. **인스턴스는 아무도 가리키지 않게 될 수 있다** — 그것이 가비지의 정의다.

그리고 **`NullPointerException` 이 왜 컴파일에서 안 잡히는지**도 여기서 나온다. 문법은 완전하다 — 주소가 비어 있는지는 그 줄을 실행해 봐야 안다.

## 경계와 오해

- **`null` 은 숫자 0 이 아니다** — 이 필기는 `arr1 = null;` 옆에 "0으로 설정"이라 적었다. `null` 은 **아무 인스턴스도 가리키지 않음**을 나타내는 별개의 리터럴이고, 내부 표현이 0 이라는 보장도 명세에 없다. 실제로 `arr == 0` 은 컴파일 오류다 → [[literal]]
- **`null` 과 빈 배열은 다르다** — `new int[0]` 은 인스턴스가 **있고** `length` 가 0 이다. `null` 은 인스턴스가 없어서 `length` 조차 물을 수 없다. `String[] args` 가 그 예다 — 인자를 안 넘겨도 `null` 이 아니다 → [[command-line-arguments]]
- **레퍼런스가 가리키는 것을 바꾸는 것과 가리키는 대상의 내용을 바꾸는 것은 다르다** — `arr = new int[3];` 은 이름의 목적지를 바꾸고, `arr[0] = 1;` 은 인스턴스를 고친다. 앞의 것은 다른 레퍼런스에 영향이 없고 뒤의 것은 있다.
- **레퍼런스는 배열만의 이야기가 아니다** — 배열에서 처음 만나지만, **기본 타입 여덟 개(`byte`·`short`·`int`·`long`·`float`·`double`·`char`·`boolean`)를 뺀 모든 타입이 레퍼런스**다. `String` 이 대표적이다 — `String s = "Hello";` 는 값을 담은 것처럼 보이지만 인스턴스의 주소를 담고 있고, 그래서 `==` 비교가 내용 비교가 아니다 → [[data-type]] · [[string-comparison]]
- **`null` 은 「없음」을 나타내는 값으로도 쓰인다** — 아직 안 가리키는 상태를 뜻하지만, 메서드가 "해당하는 것이 없다"를 알리는 반환값으로도 쓴다(`getMenuTitle` 이 유효하지 않은 번호에 `null` 을 돌려주는 것). 편리한 대신 **부르는 쪽이 검사를 잊으면 그 자리가 아니라 한참 뒤에서 터진다** → [[conditional-flattening]]
- **Java 의 레퍼런스는 C 의 포인터가 아니다** — 주소를 담지만 그 값을 볼 수도, 더하거나 뺄 수도 없다. 배열 밖의 메모리에 손댈 방법이 없으므로 범위를 벗어난 접근이 예외로 잡힌다.
- **레퍼런스의 `==` 는 「같은 것인가」이고 값 비교가 아니다** — Day19 의 `indexOf` 는 `users[i] == user` 로 찾는다. 이름·번호가 다 같은 다른 인스턴스를 넘기면 **`-1` 이 온다.** 같은 회차의 `findByNo` 는 `getNo() == userNo` 로 `int` 를 비교하므로 같은 `==` 가 여기서는 값 비교다 — **연산자가 아니라 양쪽 타입이 뜻을 정한다** → [[data-type]] · [[linear-search]]
- **인스턴스를 배열에 넣는 것은 복사가 아니다** — `toArray()` 가 만든 사본의 칸에는 원본 배열과 **같은 주소**가 들어 있으므로, 사본을 통해 `setName` 을 부르면 원본 회원이 바뀐다. 배열을 새로 만든 것과 그 안의 것을 새로 만든 것은 다른 일이다 → [[defensive-copy]]
- **배열에서 끊긴 인스턴스가 곧 사라지는 것은 아니다** — `UserList.delete` 는 `users[--userLength] = null` 로 칸을 비운 뒤 그 회원을 **반환값으로 돌려준다.** 참조가 하나 남아 있으므로 호출한 쪽에서 이름을 찍을 수 있다. 「지웠다」는 **어느 참조를 끊었는가**의 이야기다 → [[garbage-collection]] · [[array-element-removal]]
- **`NullPointerException` 은 예외지 컴파일 오류가 아니다** — 잡아서 넘길 수는 있지만, 대개는 잡을 것이 아니라 `null` 이 어디서 왔는지 찾을 것이다 → [[exception-handling]]
