# Rust 소유권과 빌림

Rust가 가비지 컬렉터 없이 메모리와 자원을 안전하게 정리하기 위해 사용하는 컴파일 시점 규칙이다. 값의 책임자를 하나의 소유자로 정하고, 소유권을 넘기지 않는 접근은 참조를 통한 빌림으로 표현한다.

## 정의

Rust의 소유권 시스템은 다음 세 축으로 작동한다.

1. **소유권(ownership)** — 각 값에는 소유자가 하나 있으며, 소유자가 유효 범위를 벗어나면 값이 `drop`되어 관련 자원이 정리된다.
2. **이동(move)** — `String`처럼 `Copy`가 아닌 값을 다른 변수나 함수에 값으로 넘기면 소유권이 이동한다. 이동 후에는 이전 변수를 사용할 수 없다.
3. **빌림(borrowing)** — 소유권을 넘기지 않고 접근하려면 `&T`로 공유 참조를, 변경하려면 `&mut T`로 가변 참조를 빌린다.

빌림 검사기(borrow checker)는 컴파일할 때 참조가 원본 값보다 오래 남지 않는지, 같은 값에 대한 접근이 다음 규칙을 지키는지 검사한다.

- 공유 참조 `&T`는 동시에 여러 개 존재할 수 있다.
- 가변 참조 `&mut T`가 활성화된 동안에는 같은 값에 대한 다른 활성 참조를 함께 둘 수 없다.
- 참조는 가리키는 값보다 오래 살아남을 수 없다.

수명(lifetime)은 참조가 유효한 범위와 여러 참조 사이의 관계를 나타낸다. 대부분은 컴파일러가 추론하며, 관계가 모호한 함수에서는 `'a` 같은 수명 매개변수로 명시한다. 이 규칙을 통과한 코드에는 소유권 추적을 위한 런타임 장치가 추가되지 않는다.

## 사용 예시

```rust
fn print_length(text: &str) {
    println!("길이: {}", text.len());
}

fn append_language(text: &mut String) {
    text.push_str(" Rust");
}

fn main() {
    let mut message = String::from("Hello");

    print_length(&message);       // 공유 참조로 읽기만 빌린다.
    append_language(&mut message); // 가변 참조로 배타적으로 빌린다.

    println!("{message}");       // 두 빌림이 끝나 소유자가 다시 사용한다.
}
```

`main`이 `message`의 소유권을 계속 가진다. 두 함수는 참조만 받아 사용하므로 호출이 끝난 뒤에도 `message`를 쓸 수 있다. 반대로 `fn consume(text: String)`에 `message`를 값으로 넘기면 소유권이 함수로 이동하여 호출 뒤의 `message`는 사용할 수 없다.

## 왜 중요한가

해제된 메모리를 가리키는 참조, 같은 자원의 중복 해제, 동기화되지 않은 가변 접근 같은 오류를 실행 전에 차단한다. 자원의 정리 시점은 소유자의 범위로 결정되므로 런타임 [[garbage-collection]]의 회수 시점에 의존하지 않으면서도 수동 해제에서 생기는 결함을 줄인다.

가변 참조의 배타성은 여러 실행 흐름이 같은 메모리를 동시에 변경하는 데이터 경합을 막는 기반이 된다. 따라서 메모리 안전성과 동시성 안전성의 일부를 테스트나 실행 중 감시가 아니라 [[compilation]] 단계의 검사로 옮긴다.

## 경계와 오해

- **소유권 ≠ 값이 항상 하나만 존재함** — `Copy` 타입은 대입할 때 값이 복사되고, `clone()`을 명시하면 독립된 값을 만들 수 있다. 하나인 것은 특정 값에 대한 정리 책임이다.
- **빌림 ≠ 소유권 이동** — 참조를 전달하면 호출이 끝난 뒤에도 원래 소유자가 값을 사용할 수 있지만, 값을 그대로 전달해 이동시키면 이전 이름은 더 이상 유효하지 않다.
- **공유 참조 여러 개 허용 ≠ 아무 때나 가변 참조와 혼용 가능** — 읽기 참조와 가변 참조의 활성 구간이 겹치면 컴파일되지 않는다.
- **수명 ≠ 객체를 오래 살게 만드는 기능** — 수명 표기는 참조 사이의 유효 범위를 설명할 뿐, 실제 값의 생존 기간을 연장하지 않는다. 이름의 [[variable-scope|스코프]]와 값·참조의 유효 기간도 같은 개념이 아니다.
- **`mut` ≠ 힙 저장** — `mut`는 바인딩이나 참조를 통해 변경할 수 있다는 뜻이다. 값이 스택과 힙 중 어디에 놓이는지는 타입의 표현과 컴파일러 최적화에 달렸다.
- **Rust의 기본 불변 바인딩 ≠ 불변 객체** — `let`의 기본 불변성은 그 바인딩을 다시 쓰지 못한다는 뜻이고, [[immutability|불변 객체]]는 인스턴스의 내용이 바뀌지 않는다는 뜻이다.
- **소유권 시스템 ≠ 메모리만을 위한 규칙** — 파일, 소켓, 잠금처럼 범위를 벗어날 때 정리가 필요한 자원에도 같은 결정적 정리 원리가 적용된다.
- **가비지 컬렉터가 없음 ≠ 메모리 오류가 전혀 없음** — `unsafe` 코드, 외부 함수 인터페이스, 논리적인 자원 누수는 별도의 검토가 필요하다.
