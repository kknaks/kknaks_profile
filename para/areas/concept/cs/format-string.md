# 서식 문자열 (Format String)

출력할 **틀을 문자열 하나로 적고 값은 따로 넘기는** 방식. 틀 안의 `%...` 자리표가 넘어온 인수로 채워진다. 문자열을 `+` 로 이어 붙이는 것과 결과는 같아 보이지만, **어느 값이 어느 자리에 가는지를 문자열이 정한다**는 점이 다르다.

## 정의

자리표 하나의 생김새는 이렇다.

```text
%[인수인덱스$][플래그][폭][.정밀도]변환문자
```

`printf` 가 실제로 쓰는 변환문자는 몇 개뿐이다.

| 변환 | 받는 값 | 예 |
|---|---|---|
| `%s` | 아무 것 (`toString()`) | `%s` → `제목` |
| `%d` | 정수 | `%d` → `12` |
| `%f` | 실수 | `%.1f` → `84.3` |
| `%t`·`%T` | 날짜·시각 | `%tY` → `2024` |
| `%%` | (자리표가 아니라 `%` 글자) | |

**`%t` 는 혼자 쓰이지 않는다.** 뒤에 접미사 한 글자가 반드시 붙어 **두 글자**로 하나의 변환이 된다 → [[date-time]]

| | 뜻 | | 뜻 |
|---|---|---|---|
| `%tY` | 4자리 연도 | `%tH` | 24시간제 시 |
| `%tm` | 2자리 월 | `%tM` | 분 |
| `%td` | 2자리 일 | `%tS` | 초 |

### 인수를 고르는 두 방식

`$` 앞의 번호가 **몇 번째 인수를 쓸지 직접 고르는** 것이다. 없으면 순서대로 하나씩 소비한다.

| 표기 | 어느 인수를 쓰나 |
|---|---|
| `%s` (인덱스 없음) | **자기 앞의 「인덱스 없는 자리표」 개수 + 1** 번째 |
| `%1$s` (명시 인덱스) | 언제나 1번째 |

핵심은 **명시 인덱스는 순서 소비에 끼어들지 않는다**는 것이다. `%3$tm` 이 중간에 있어도 뒤에 오는 인덱스 없는 자리표는 그것을 세지 않는다. 그래서 한 인수를 여러 번 쓰면서도 나머지 자리표의 짝이 흐트러지지 않는다.

**인덱스는 1부터다.** 배열이 아니라 번호이기 때문이다 → [[one-based-numbering]]

## 사용 예시

같은 값을 세 번 쓰는 자리가 이 필기에서 처음 나온다. 날짜 하나를 연·월·일로 찍어야 하기 때문이다.

```java
private static void listBoard() {
  System.out.println("번호 제목 작성일 조회수");
  for (int i = 0; i < boardLength; i++) {
    Board board = boards[i];
    System.out.printf("%d %s %tY-%3$tm-%3$td %d", (i + 1), board.getTitle(),
        board.getCreatedDate(), board.getViewCount());
  }
}
```

자리표 다섯 개가 인수 네 개에 어떻게 붙는지 풀어 보면 이렇다.

| 자리표 | 종류 | 붙는 인수 |
|---|---|---|
| `%d` | 순서 1번째 | `(i + 1)` |
| `%s` | 순서 2번째 | `board.getTitle()` |
| `%tY` | 순서 3번째 | `board.getCreatedDate()` |
| `%3$tm` | 명시 3번 | `board.getCreatedDate()` |
| `%3$td` | 명시 3번 | `board.getCreatedDate()` |
| `%d` | 순서 **4번째** | `board.getViewCount()` |

**마지막 `%d` 가 조회수를 받는 것은 우연이 아니라 규칙이다.** 명시 인덱스 두 개가 순서를 소비하지 않으니 앞의 인덱스 없는 자리표는 여전히 셋이고, 그래서 넷째 인수로 간다.

그런데 **첫 날짜 자리를 `%3$tY` 로 바꾸면 이 줄이 깨진다.** 인덱스 없는 자리표가 `%d`·`%s`·`%d` 셋이 되고 마지막 `%d` 가 3번 인수(날짜)를 받아 `IllegalFormatConversionException` 이 난다. **인덱스를 붙이는 것과 안 붙이는 것이 뒤쪽 자리표의 짝을 움직인다.**

인수가 하나뿐일 때는 첫 자리만 순서로 두고 나머지를 전부 되돌려 가리킨다.

```java
System.out.printf("작성시간: %tY-%1$tm-%1$td %1$tH:%1$tM:%1$tS", board.getCreatedDate());
```

자리표 여섯 개에 인수는 하나다. 인덱스가 없었다면 `%tm` 이 2번 인수를 찾다가 `MissingFormatArgumentException` 이 난다 — **인수 인덱스가 여기서 필수인 이유**다.

같은 값을 화면마다 다르게 찍는 것도 서식 문자열이 하는 일이다. 목록은 `%tY-%tm-%td` 까지, 조회는 `%tH:%tM:%tS` 까지 붙인다. **저장된 값은 하나고 형식만 둘이다.**

프롬프트 문구도 서식 문자열이다 — `Prompt.input` 이 받은 것을 그대로 `printf` 에 넘긴다 → [[varargs]]

```java
board.setTitle(Prompt.input("제목(%s)?", board.getTitle()));
```

## 왜 중요한가

**틀과 값이 갈라져서 틀만 고칠 수 있다.** 날짜 형식을 `2024-06-19` 에서 `2024/06/19` 로 바꾸는 일이 문자열 한 곳을 고치는 일이 된다. `+` 로 이어 붙인 코드였다면 값을 꺼내는 코드와 구분자가 뒤섞여 있어 같이 손대야 한다.

**이어 붙이기로는 못 하는 것을 한다.** 자리 폭 맞추기(`%5d`), 소수점 자리 고정(`%.1f`), 그리고 **한 값을 여러 번 쓰기**다. 이 필기의 날짜 출력이 세 번째에 해당한다 — `getCreatedDate()` 를 세 번 부르지 않고 인수 하나로 끝낸다.

**그리고 컴파일러가 봐 주지 않는다는 것이 이 개념의 실질이다.** 자리표 개수·인수 타입·인덱스 범위가 전부 실행 시점에 검사되므로, 서식 문자열의 실수는 **테스트로 그 줄을 실제로 실행해 봐야** 드러난다. 자리표가 하나 늘었는데 인수를 안 늘린 코드는 아무 경고 없이 빌드된다 → [[exception-handling]]

## 경계와 오해

- **`%t` ≠ 한 글자 변환** — `%tY` 처럼 접미사가 반드시 붙는다. `%t` 만 쓰면 `UnknownFormatConversionException` 이다. `%s`·`%d` 를 먼저 배우면 「`%` + 한 글자」로 굳어서 이 규칙이 예외처럼 보인다.
- **`%tm` 은 분이 아니다** — 월이다. 분은 `%tM` 이고, **대소문자가 뜻을 바꾼다.** `%tY`(2024) 와 `%ty`(24) 도 같은 쌍이다. 「분」을 `%tm` 으로 적으면 시:월:초가 찍히는데 둘 다 두 자리 숫자라 눈에 걸리지 않는다.
- **인수 인덱스는 「앞에서 몇 번째 `%`」가 아니다** — 명시 인덱스가 든 자리표는 순서 소비에 참여하지 않으므로, `%` 를 왼쪽부터 세어 인수를 짝지으면 이 필기의 `listBoard` 를 잘못 읽는다. 세어야 하는 것은 **인덱스 없는 자리표만**이다.
- **`printf` 는 줄바꿈을 넣지 않는다** — `println` 과 갈리는 자리다. 이 필기의 `listBoard`·`viewBoard` 는 `%n` 도 `\n` 도 없이 `printf` 를 연달아 불러서 **제목·내용·작성시간·조회수가 한 줄에 붙어 나온다.** Day17 의 `listUser` 에는 `\n` 이 있었는데 게시판 코드로 오면서 빠졌다. 예외도 오류도 없고 화면만 읽을 수 없게 된다 → [[newline-character]]
- **`%n` 과 `\n` 은 같지 않다** — `%n` 은 플랫폼의 줄바꿈으로 바뀌고 `\n` 은 항상 LF 다. 서식 문자열 안에서는 `%n` 이 제자리다 → [[platform-dependency]]
- **서식 문자열의 오타는 통과한다** — 이 필기의 `Prompt.input("내용(%s", board.getContent())` 는 닫는 괄호와 `?` 가 빠졌지만 컴파일도 실행도 된다. `%` 가 든 부분만 해석되고 나머지는 글자 그대로 찍히기 때문이다. **자리표가 맞으면 문구가 깨진 것은 아무도 알려 주지 않는다.**
- **값을 서식 자리에 넣으면 안 된다** — 사용자가 입력한 문자열을 형식 문자열로 넘기면 그 안의 `%` 가 자리표로 읽힌다. 값은 반드시 인수로 보낸다 → [[varargs]]
- **`%d` 자리에 아무 것이나 넣을 수 있다** — 가변 인수가 `Object` 로 받으므로 컴파일러가 막지 않고 실행 중에 `IllegalFormatConversionException` 이다. `%s` 만 타입을 가리지 않는다 → [[data-type]]
