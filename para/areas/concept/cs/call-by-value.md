# 값에 의한 전달 (Call by Value)

메서드를 호출하면 인수의 **값이 복사되어** 매개변수에 들어간다. 기본 타입이면 값 자체가 복사되고, 레퍼런스면 **주소가 복사된다.** Java 에는 이 한 가지 방식만 있다.

## 정의

복사되는 것이 무엇인지가 타입에 따라 갈리고, 그 결과 호출한 쪽에 보이는 것도 갈린다.

| 넘기는 것 | 매개변수에 복사되는 것 | 매개변수의 값을 바꾸면 | 가리키는 인스턴스를 고치면 |
|---|---|---|---|
| 기본 타입 | 값 자체 | 호출한 쪽은 그대로 | (해당 없음) |
| 레퍼런스 | 인스턴스의 **주소** | 호출한 쪽은 그대로 | **호출한 쪽에도 보인다** |

이 필기는 앞쪽을 「call by value」, 뒤쪽을 「call by reference」라 나눠 배웠다.

```text
call by value    : 메서드를 호출할 때 primitive data type을 파라미터에 넘긴다.
                   자바에서는 primitive data type에 대해서 메모리(변수) 주소를 넘기는 방법이 없다.
call by reference : 메서드를 호출 할 때 주소를 넘긴다.
```

두 줄이 가리키는 현상은 맞지만, **Java 에서는 뒤쪽도 값 전달이다** — 넘어가는 「주소」가 곧 레퍼런스 변수에 담긴 값이기 때문이다 → 「경계와 오해」

## 사용 예시

배열을 넘기고 호출된 쪽에서 원소를 고치면, 호출한 쪽에서 그것이 보인다.

```java
package study.lang.method;

public class Test09 {
  public static void main(String[] args) {
    int[] values = new int[] {100, 110, 120};
    m1(values);
    System.out.println(values[0]);      // 200
  }

  static void m1(int[] value) {
    value[0] = 200;
  }
}
```

`value` 와 `values` 는 **다른 변수인데 같은 인스턴스를 가리킨다.** 주소의 복사본을 받았기 때문이다 → [[object-reference]]

그런데 매개변수에 **다른 인스턴스를 대입**하면 결과가 뒤집힌다.

```java
static void m2(int[] value) {
  value = new int[] {0, 0, 0};        // 이 프레임의 변수만 목적지가 바뀐다
}
// m2(values) 를 부른 뒤에도 values[0] 은 100 이다
```

**이 두 예제의 차이가 Java 의 전달 방식을 판정하는 기준이다.** 진짜 참조 전달이라면 뒤 예제에서도 호출한 쪽 변수가 새 배열을 가리키게 되어야 한다 → [[jvm-stack]]

## 왜 중요한가

**"배열은 바뀌고 `int` 는 안 바뀐다"를 두 규칙으로 외우면 예외가 계속 나오지만, 한 규칙으로 보면 전부 설명된다.** 항상 값이 복사되고, 복사된 것이 주소일 때만 같은 인스턴스에 닿을 수 있다. 그래서 다음 세 가지가 한꺼번에 정리된다.

1. **`swap(a, b)` 메서드는 Java 에서 만들 수 없다** — 기본 타입 두 개를 받아 호출한 쪽 변수를 맞바꾸는 것은 불가능하다. 매개변수를 바꿔도 복사본이 바뀔 뿐이다.
2. **배열·객체를 넘기는 것은 「내보내는 통로」가 된다** — 호출된 쪽이 내용을 고치면 부른 쪽이 그것을 읽는다. `return` 없이 결과를 주고받는 방식이고, 편한 대신 **어디서 값이 바뀌었는지 호출부만 봐서는 알 수 없다.**
3. **큰 객체를 넘기는 비용이 크지 않다** — 인스턴스를 복사하는 것이 아니라 주소만 복사하기 때문이다.

## 경계와 오해

- **Java 에 call by reference 는 없다** — 이 필기가 1.7 을 「call by reference」로 배운 자리다. 참조 전달은 **변수 자체를 넘기는 것**(호출된 쪽의 대입이 호출한 쪽 변수에 반영되는 것)인데, Java 에서는 위 `m2` 처럼 반영되지 않는다. 넘어간 것은 변수가 아니라 **변수에 담긴 주소 값의 복사본**이다. 이 구분을 흔히 「call by sharing」이라 부른다. "주소를 넘기니 참조 전달"로 외우면 **왜 원소는 바뀌는데 재대입은 안 먹히는지** 설명할 수 없다.
- **인스턴스가 공유되는 것 ≠ 참조로 전달된 것** — 공유는 주소 복사만으로도 성립한다. 관찰되는 현상(내용이 같이 바뀐다)은 두 방식에서 똑같이 나타나므로, 판정은 **재대입이 보이는가**로 한다.
- **"primitive data type 에 대해서 주소를 넘기는 방법이 없다" 는 primitive 만의 제약이 아니다** — 필기의 문장은 기본 타입만 그렇고 레퍼런스는 변수 주소를 넘긴다는 뜻으로 읽히기 쉽다. Java 는 **어떤 타입이든 변수의 주소를 넘길 수 없다.** 레퍼런스에서 넘어가는 것도 변수의 주소가 아니라 **인스턴스의 주소**다. C 의 `&a` 에 해당하는 것이 아예 없다 → [[object-reference]]
- **값 복사 ≠ 인스턴스 복사** — 주소만 복사되므로 인스턴스는 하나다. "넘기면 복사된다"를 깊은 복사로 읽으면 호출된 쪽의 수정이 왜 보이는지가 모순으로 남는다 → [[instance]]
- **`String` 은 넘겨도 호출한 쪽이 바뀌지 않는다** — 레퍼런스인데도 배열처럼 되지 않는 이유는 전달 방식이 달라서가 아니라, 문자열을 「고치는」 연산이 원래 인스턴스를 수정하지 않고 **새 인스턴스를 만들어** 매개변수만 그것을 가리키게 하기 때문이다. 즉 `m2` 와 같은 모양이다 → [[string-comparison]]
- **`final` 매개변수는 전달 방식과 무관하다** — 매개변수를 재대입하지 못하게 막을 뿐이고, 가리키는 인스턴스의 내용은 그대로 고칠 수 있다.
