# 계약 표면 전수조사 (Contract Surface Enumeration)

**계약(가정·의미)을 바꿀 때, 그 계약이 닿는 자리를 코드에서 전부 세고 시작하는 것.** 결정은 "무엇을 바꾸나"만 말한다 — "어디에 닿나"는 grep 이 말한다.

## 왜 필요한가

mediness 에서 "요청자 = 담당자" 가정을 깨고 담당자 지정을 열었을 때, 결정에 적힌 입구 2개(웹 모달·채팅)만 구현했다. 그 가정을 깔고 있던 **나머지 자리들이 실기동에서 연쇄로 터졌다**:

- MCP 툴 설명 문구("담당자는 본인 고정") → 에이전트가 스스로 거절
- 승인 카드의 결재자 축(담당자 키로 읽음) → 수신자가 결재자가 되어 요청자 목록에서 카드 소실
- WBS 등록 경로·승인 버튼 화이트리스트 → 계약 밖에 방치

**스펙이 좁으면 검수도 못 잡는다** — 검수는 "스펙과 일치하나"만 보므로, 스펙에 없는 표면은 통과한다. 유일한 검출기가 실기동 반려가 된다.

## 방법

1. 바꾸는 엔티티·가정에 대해 **만들거나 · 고치거나 · 보여주거나 · 설명하는** 모든 경로를 grep 으로 목록화한다 — 생성 seam·화면·API·MCP 툴 스키마·**툴 설명 문구까지**(LLM 은 설명서를 계약으로 읽는다).
2. 그 목록을 발주 브리프·스펙에 박는다 — "이 표면들이 전부 새 계약을 따른다"가 계약이 된다.
3. **실기동 반려 1호는 버그가 아니라 범위 누락의 신호다** — 즉시 패치하지 말고 "같은 뿌리의 구멍이 몇 개인가"를 먼저 센다. 패치로 쫓아가면 구멍이 연쇄된다.

관련: [[derived-predicate]] — 파생 판정의 전제 컬럼 의미가 바뀔 때 정확히 이 조사가 필요하다.
- **경계 규칙의 읽기 길 V1 ~ V12**(cc-prototype 내부 채팅) — planner 가 코드 grep 으로 길을 표로 세고, backend 는 길마다 HTTP 시험 + 거름을 하나씩 빼는 mutation(13 중 12 죽음)으로 표가 실제로 잠겼는지 확인했다. 그래도 푸시 받는 사람(커밋 뒤 다시 읽기)은 표에서 「안 바꿈」으로 잘못 분류돼 문서 리뷰가 잡았다 · [[2026-10-30-internal-chat]]
- **같은 이름의 두 층**(DAY 판 받은함) — 웹 전용 목록 `rules.inbox()` 의 `startable` · `waiting` 과, 앱도 읽는 카드별 `inbox.section` 의 같은 값 이름이 따로 있었다. 「시작 가능 · 시술 대기를 없앤다」를 이름으로 grep 하면 둘이 섞인다 — 조사가 소비처(웹 라우터 vs 앱 칩)로 층을 갈라 줘서 웹 층만 지웠다. 전수조사의 단위는 이름이 아니라 **누가 읽는가**다 · [[2026-11-12-fix-web]]
- **값을 빼는 것과 모양을 바꾸는 것은 다르다** — 깔린 앱이 받는 응답에서 `needs[].why = accept` 를 빼도 앱 파서가 값 목록을 검사하지 않으면(문자열 그대로 · 모르는 칸 null) 깨지지 않고 표시만 사라진다. 반대로 값 이름 바꾸기 · 칸 모양 바꾸기는 깨진다. 그래서 「앱 수정 필요?」는 소비 코드의 파서를 열어 보고 판정한다 → [[tolerant-reader]] · [[2026-11-12-fix-web]]

## 같은 화면을 그리는 경로도 표면이다

DAY 예약 상세는 네 경로가 같은 조각을 그렸다(POST 띄우기 · GET 상세 · 동행 저장 · 신분확인). 그중 POST 만 공개 주소(`origin`)를 넘겼다. SSE 신호로 GET 이 다시 그리면 `qrUrl = null` 이 되어 QR 과 [태블릿에 보내기]가 「떴다 사라졌다」. 증상은 시한 · 시간대처럼 보였지만, 원인은 **같은 출력을 만드는 입구 하나가 입력을 빠뜨린 것**이었다.

- 세는 단위는 「이 값을 쓰는 곳」 이 아니라 **「이 화면을 그리는 모든 경로」** 다.
- 빠뜨림을 막는 방법은 인자를 필수로 바꾸는 것이다. 그러면 타입 검사가 남은 입구를 대신 센다. 공개 주소 함수도 두 벌이던 것을 하나로 모았다.
- 같은 상수를 두 뜻으로 쓰는 곳도 표면이다. 배치 행을 1시간으로 바꾸면서 동행 판정이 같은 `ROW_MINUTES` 를 쓰고 있어 묶기 조건이 조용히 넓어질 뻔했다. 함수와 상수를 나눴다.
