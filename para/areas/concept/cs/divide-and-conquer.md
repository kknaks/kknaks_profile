# 분할 정복 (Divide and Conquer)

**문제를 절반(또는 몇 조각)으로 쪼개 각각 풀고 합치는 것.** 쪼갤 때마다 크기가 반이 되면 **O(log n)** 이 된다.

## 정의

### 반으로 쪼개기 — 거듭제곱

`A^B mod C` 를 B 번 곱하면 O(B) 다. 지수를 반으로 쪼개면 다르다.

```
A^B = (A^(B/2))² 이고, B 가 홀수면 A 를 한 번 더 곱한다
```

```cpp
long long power(long long a, long long b, long long c) {
    if (b == 0) return 1;
    long long half = power(a, b / 2, c);      // 절반을 한 번만 계산해 재사용
    long long r = half * half % c;
    if (b % 2) r = r * a % c;
    return r;
}
```

**절반의 결과를 한 번만 구해 두 번 쓰는 것**이 핵심이다 — 그래서 호출이 `log B` 번뿐이다 → [[time-complexity]]

### 넷으로 쪼개기 — 쿼드트리

```
사각형이 전부 같은 값인가?
  ├ 그렇다 → 그 값 하나로 끝
  └ 아니다 → 사분면 넷으로 나눠 각각 다시 묻는다
```

**「멈추는 조건」과 「나누는 방법」 둘만 정하면 된다** — 나머지는 재귀가 한다 → [[recursion]]

## 왜 중요한가

**필요한 복잡도에서 알고리즘을 역산하는 대표 사례다.** 「O(log n) 이어야 한다」가 먼저 있고, 그것을 만족하는 구조가 **반씩 줄이는 것**이다 → [[time-complexity]]

**그리고 재귀가 가장 자연스럽게 맞는 자리다.** 「같은 문제의 더 작은 판」이 그대로 함수 호출이 되므로, 반복문으로 쓰면 오히려 복잡해진다.

## 경계와 오해

- **쪼갠다고 다 분할 정복이 아니다** — 쪼갠 조각들이 **같은 종류의 문제**여야 하고, **합치는 방법**이 있어야 한다. 그냥 나눠 도는 것은 순회다
- **중복 계산을 재사용하는 것이 이득의 원천이다** — `power(a, b/2)` 를 두 번 부르면 O(n) 으로 돌아간다. **한 번 구해 변수에 담아 두 번 쓰는 것**이 전부다
- **재귀 깊이는 안전하지만 폭이 문제일 수 있다** — 반씩 줄이면 깊이는 log 라 얕다. 반면 쿼드트리처럼 **가지를 넷으로 뻗으면 호출 수 자체가 는다** → [[recursion]]
- **모듈러 연산은 곱할 때마다 해야 한다** — `A^B` 를 다 구한 뒤 나머지를 취하면 **자릿수가 넘친다.** 매 단계에서 `% C` 하는 것이 필수다 → [[overflow]]
- **분할 정복 ≠ 이분 탐색** — 이분 탐색은 **한쪽만 보고 버리는** 것이라 합치는 단계가 없다. 절반씩 줄인다는 점만 같다

## 출처

- [[2025-05-09-Pr1629]] — `A^B mod C`. 「**재귀함수를 사용해서 2분할 할 수 있다 / 분할 정복을 사용하여 O(log n)으로 해결 가능하다**」 두 줄이 이 개념을 그대로 담았다 — **필요한 복잡도가 먼저** 있고 방법이 뒤따른다
- [[2025-06-16-pr1992]] — 쿼드트리 압축. 「재귀함수 호출 / **4개의 재귀함수 호출**」로 나누는 갈래가 둘이 아니라 넷인 경우를 보인다. 「전부 같은 값이면 멈춘다」는 종료 조건이 압축 그 자체가 되는 구조다. 다만 본문의 H1 이 `Pr.1993` 으로 잘못 적혀 있다
- [[2025-05-09-Pr4375]] — 1 로만 이루어진 N 의 배수 찾기. **전제조건 칸이 앞 문제에서 그대로 복사돼 있다** — 「A, B, C 는 2,147,483,647 이하」와 「무조건 단순하게 곱하면 오버플로우」는 `A^B mod C` 문제의 제약이고 이 문제의 것이 아니며, 「사용 알고리즘」의 두 줄도 같다. **실제 풀이는 나머지를 이어 붙이며 반복하는 쪽**이라 분할 정복이 아니다 — 이 노트가 이 개념 아래 붙어 있는 것은 그 복사 때문이고, 그 사실 자체가 기록으로 남을 값이 있다
