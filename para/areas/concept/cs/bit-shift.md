# 비트 이동 연산자 (Bit Shift)

비트를 왼쪽·오른쪽으로 옮기는 연산자. **한 칸 옮기는 것이 2를 곱하거나 나누는 것과 같다.**

## 정의

| 연산자 | 방향 | 빈자리를 채우는 값 |
|---|---|---|
| `<<` | 왼쪽 | 오른쪽 빈자리에 `0` |
| `>>` | 오른쪽 | 왼쪽 빈자리에 **부호 비트** (음수면 `1`) |
| `>>>` | 오른쪽 | 왼쪽 빈자리에 항상 `0` |

경계를 넘어간 비트는 버린다.

**`>>>` 가 따로 있는 이유는 Java 에 unsigned 타입이 없기 때문이다.** 부호를 무시하고 순수하게 비트만 밀어야 할 때 쓴다.

### 이동 횟수는 타입 크기로 나눈 나머지다

이동 횟수의 유효 범위는 그 자료형의 비트 수까지고, 그보다 크면 **나머지만큼만** 이동한다.

```java
System.out.println(3 << 1);    // 6
System.out.println(3 << 33);   // 6   (33 % 32 = 1)
System.out.println(3 << 65);   // 6   (65 % 32 = 1)
System.out.println(3 << 97);   // 6
```

## 사용 예시

왼쪽 이동은 2의 승수를 곱한다.

```java
int i = 1;                     // [00000000000000000000000000000001]
System.out.println(i << 1);    // 2
System.out.println(i << 2);    // 4
System.out.println(i << 3);    // 8
System.out.println(i << 4);    // 16

i = 11;                        // [...00001011]
System.out.println(i << 1);    // 22
System.out.println(i << 2);    // 44
System.out.println(i << 3);    // 88
```

오른쪽 이동은 나눈다. 음수일 때 빈자리가 `1` 로 채워지는 것을 확인할 수 있다.

```java
int i = 105;                   // [00000000000000000000000001101001]
System.out.println(i >> 1);    // 52    ← 105 / 2 = 52.5 → 52

int j = -87;                   // [11111111111111111111111110101001]
System.out.println(j >> 1);    // -44   ← 왼쪽 빈자리가 부호 비트 1 로 채워졌다
```

소수점이 생기면 **그보다 바로 아래 정수**가 결과다.

### 「1.5배」를 쓰는 관용구

18일 뒤 회차의 가변 배열 실습이 이 연산자를 실제로 쓴 첫 자리다.

```java
int newSize = oldSize + (oldSize >> 1);      // 1.5배
```

`oldSize >> 1` 이 절반이므로 원래 크기에 그 절반을 더한 것이다. `oldSize * 1.5` 로 쓰면 `double` 이 되어 다시 `int` 로 되돌려야 하는데, 시프트는 정수 안에서 끝난다 → [[dynamic-array]] · [[type-casting]]

**그리고 「버림」이라는 성질이 여기서 함정이 된다.** `oldSize` 가 0 이나 1 이면 `oldSize >> 1` 이 0 이라 `newSize` 가 `oldSize` 와 같아지고, 배열이 영원히 늘어나지 않는다. 곱셈으로 써도 `1 * 1.5 = 1.5 → 1` 로 같은 결과이므로 **시프트 탓이 아니라 「비율만 정하고 최소 증가량을 정하지 않은」 탓**이다.

### 「나누기」가 아니라 「바이트 꺼내기」로 쓰는 자리

23일 뒤 회차에서 이 연산자가 **처음으로 산술이 아닌 일에 쓰인다.** Day38 의 필기가 그 용도를 「비트 연산자를 통해 바이트를 1바이트까지 이동 해야한다」로 적었다.

```java
    out.write(no >> 24);
    out.write(no >> 16);
    out.write(no >> 8);
    out.write(no);
```

**`int` 하나를 바이트 넷으로 쪼갠다.** 원하는 바이트를 오른쪽 끝으로 밀어 놓고 `write` 가 그 끝의 1바이트만 가져가게 한다 — 즉 시프트가 「자리 고르기」를 하고 자르는 일은 다른 데서 일어난다 → [[io-stream]]

되돌리는 쪽은 방향이 반대다. `<<` 로 자리를 되돌리고 `|` 로 합친다.

```java
      user.setNo(in.read() << 24 | in.read() << 16 | in.read() << 8 | in.read());
```

```java
      int len = in.read() << 8 | in.read();
```

**`<<` 와 `>>` 가 한 값을 왕복시키는 짝으로 쓰이는 첫 코드**이고, Day10 에서 배운 「2를 곱하고 나눈다」와 같은 연산인데 하는 일의 이름이 다르다 → [[bitwise-operator]] · [[length-prefix-framing]]

## 왜 중요한가

**곱셈·나눗셈보다 빠르다.** 산술 연산은 연산 레지스터를 경유하지만 시프트는 비트에 바로 적용되므로, 값을 배수로 늘릴 때 `* 2` 대신 `<< 1` 을 쓰는 코드가 실무에 자주 나온다.

그리고 [[bitwise-operator]] 와 짝으로 쓰인다. 여러 정보가 한 정수에 들어 있을 때, 시프트로 원하는 자리를 끝으로 옮기고 마스크로 꺼내는 것이 기본 패턴이다.

## 경계와 오해

- **우선순위가 낮다** — 산술 연산자보다 뒤라서 `a + b << 2` 는 `(a + b) << 2` 가 된다. 의도한 순서를 `()` 로 드러내야 한다 → [[operator]]
- **`0001 >> 2` 는 `0100` 이 아니다** — 옛 필기에 "`0001 >> 2` 는 `0100` 으로 바뀐다"고 적혀 있는데 방향이 뒤집혔다. `>>` 는 오른쪽이므로 `0001 >> 2` 는 `0000` 이고, `0100` 이 되는 것은 `0001 << 2` 다. **같은 노트의 다른 예시들은 방향이 맞다.**
- **`>>` 와 `>>>` 는 양수에서 결과가 같다** — 부호 비트가 `0` 이므로 차이가 안 드러난다. 음수에서만 갈린다.
- **오른쪽 이동은 버림이다** — 나누기와 완전히 같지 않다. 음수에서 `-87 >> 1` 이 `-44` 인 것은 `-43.5` 를 **아래로** 내린 것이고, 0 쪽으로 자르는 정수 나눗셈(`-87 / 2 = -43`)과 결과가 다르다.
- **이동 횟수가 크면 0 이 되는 것이 아니다** — 타입 크기로 나눈 나머지만큼 이동하므로 `3 << 33` 은 `0` 이 아니라 `6` 이다.
- **Day10 시점에는 「빠르다」가 쓰는 이유였는데 실제로 쓰인 이유는 그것이 아니다** — 18일 뒤 가변 배열 코드의 `oldSize >> 1` 은 배열을 늘릴 때 **한 번** 실행된다. 속도가 문제가 되는 자리가 아니고, `* 0.5` 로 쓰면 `double` 이 끼어 형변환이 붙는 것을 피한 것이다. **「2로 나눈다」를 정수 안에서 표현하는 관용구**로 읽는 것이 실제 코드에 더 맞는다 → [[type-casting]] · [[type-promotion]]
- **작은 값에서 0 이 되는 것을 잊으면 조용히 멈춘다** — `1 >> 1` 도 `2 >> 2` 도 0 이다. 배수를 계산하는 데 쓸 때 「최소한 얼마는 늘어난다」를 따로 보장하지 않으면 경계값에서 아무 일도 일어나지 않는다 → [[dynamic-array]]
- **바이트를 꺼낼 때 마스크(`& 0xFF`)가 보이지 않는 것은 필요 없어서가 아니다** — 교과서의 관용구는 `(no >> 24) & 0xFF` 인데 Day38 은 `& 0xFF` 를 쓰지 않는다. **자르는 일을 `write(int)` 가 대신 하기 때문**이다 — 그 메서드가 하위 8비트만 쓰고 나머지를 말없이 버린다. 그래서 이 코드에서 시프트가 하는 일은 「값을 잘라 내기」가 아니라 **「원하는 바이트를 맨 아래로 옮기기」**뿐이다. `write` 가 아니라 `byte[]` 에 직접 담는 코드로 옮겨 쓰면 마스크가 다시 필요해지고, **관용구를 통째로 외우면 마스크가 왜 있는지도 왜 여기 없는지도 설명하지 못한다** → [[bitwise-operator]] · [[io-stream]]
- **`>>` 와 `>>>` 중 어느 쪽을 써야 할 것 같은데 여기서는 결과가 같다** — 회원 번호가 음수면 `no >> 24` 는 왼쪽을 부호 비트 `1` 로 채우므로 `>>>` 와 값이 다르다. **그런데 `write` 가 하위 8비트만 가져가고, 그 8비트는 두 연산자에서 같다.** 그래서 `-1` 을 넣어도 `FF FF FF FF` 가 나가고 읽는 쪽이 `-1` 로 되돌린다. **부호가 걸릴 것 같은 자리인데 걸리지 않는 이유가 시프트가 아니라 자르는 쪽에 있다** — 마스크 항목과 같은 구조다.
- **읽는 쪽에서 부호 확장이 걸리지 않는 것도 우연이 아니다** — `in.read()` 는 `int` 로 0~255 를 돌려주므로 `<< 24` 로 올려 `|` 로 합쳐도 위쪽에 `1` 이 새어 들지 않는다. **`byte` 배열에서 직접 조립했다면 `bytes[1] << 16` 이 부호 확장으로 상위 비트를 전부 `1` 로 만들어 앞 바이트를 덮어쓴다** — `(bytes[1] & 0xFF) << 16` 이 필수인 자리다. `read()` 의 반환 타입이 `byte` 가 아닌 것이 이 버그를 막아 주고 있다 → [[io-stream]] · [[type-promotion]]
- **접두사 크기의 한계가 시프트 횟수에 숨는다** — Day38 이 길이를 `>> 8` 과 그대로 두 바이트로 적으므로 최대 65535 다. 값이 그것을 넘으면 상위 비트가 `write` 에서 버려지고 **예외 없이 다른 숫자가 저장된다.** 「2바이트를 쓴다」가 코드에 숫자로 없고 `>> 8` 한 번이라는 사실에만 있어서, 한계를 늘리려면 시프트 줄을 세어야 한다 → [[length-prefix-framing]] · [[overflow]]
