# 여권 MRZ 연속 인식 — 한 장 촬영 대신 프레임마다 읽고 검사 숫자로 확정

여권 사진면 아래의 **기계 판독 영역(MRZ)** 은 두 줄 · 44자(TD3)에 여권번호 · 생년월일 · 만료일과 각각의 **검사 숫자**를 싣는다. 사용자가 한 장 찍어 읽게 하지 않고, 카메라 영상의 **프레임마다 MRZ 자리만** 기기 안 OCR 로 읽고, 검사 숫자가 맞는 같은 판독이 **연속으로 나오면** 그 프레임을 자동으로 찍는다. OCR 의 잘못 읽음은 칸 종류별 보정과 검사 숫자로 걸러 낸다.

## 정의

1. **한 장 촬영이 아니라 연속 프레임** — 카메라 세션을 직접 열어(iOS `AVCaptureSession`) 프레임을 받는다. 시스템 촬영 화면(`UIImagePickerController`)은 근접 초점 · 매크로 렌즈 전환을 앱이 못 잡아, 여권을 가까이 대면 흐렸다. 세션을 직접 열면 렌즈 묶음(트리플 → 듀얼 와이드 → 와이드)을 고르고 **가까우면 iOS 가 초광각(매크로)으로 바꾸게** 둘 수 있다. 광각만 있는 기기는 최소 초점거리에 맞춰 조금 확대한다
2. **틀 영역만 읽는다** — 화면에 가이드 틀을 그리고, 틀 아래 MRZ 자리만 잘라 OCR(기기 안 `Vision` · 외부 서비스 0)에 넘긴다. 앞 프레임 처리가 끝난 뒤 · 일정 간격 이상일 때만 다음 프레임을 읽는다
3. **틀 ↔ 영상 좌표는 미리보기 레이어에게 묻는다** — 화면 틀과 센서 프레임은 비율 채움 · 회전 · 크기가 다르다. 손으로 계산하거나 「방향 뒤 좌표인지 애매한」 관심 영역 옵션을 쓰지 않고, 미리보기 레이어의 변환(`metadataOutputRectConverted(fromLayerRect:)`)으로 센서 좌표를 받아 그 영역을 잘라 세운다
4. **칸 종류별 보정** — OCR 은 `<`(채움)를 `K` · `«` 로, 숫자 칸의 `0` 을 `O` 로 읽는다. 날짜 · 검사 숫자 칸은 글자 → 숫자(O→0 · I→1 · S→5 · B→8 …), 국적 · 이름 칸은 숫자 → 글자. 글자 · 숫자가 섞인 여권번호 칸은 그대로 안 맞으면 헷갈리는 자리를 **적게 바꾼 것부터** 바꿔 검사 숫자가 맞는 쪽을 고른다. `K` → `<` 는 양옆이 채움일 때만(이름 속 K 는 그대로). 줄 끝이 덜 · 더 읽힌 경우도 채운다
5. **통과 조건을 현실에 맞춘다** — 검사 숫자 **전부** 일치 조건은 실기기에서 한 번도 통과하지 못했다. 여권번호 · 생년월일 · 만료일 셋이 맞으면 통과로 하고 종합 검사 숫자 실패는 허용했다
6. **연속 두 프레임 같은 판독이면 확정** — 한 프레임의 우연한 일치를 막는다. 판독이 끊기면 처음부터 센다. 확정되면 진동 + 그 프레임의 틀 영역만 사진으로
7. **사람이 끝낼 길을 늘 둔다** — [촬영] 버튼은 늘 보이고(그 사진에서 읽기 → 못 읽으면 바로 손 입력), 정해진 시간씩 몇 번 못 읽으면 [손으로 입력]. 카메라 권한이 없으면 처음부터 손 입력

## 사용 예시

전체현황판 앱(Flutter + iOS 네이티브)의 나눔:

```text
네이티브 (Swift)                         Dart
──────────────────────────────           ──────────────────────────────
AVCaptureSession · 렌즈 · 초점            
프레임 → 틀 아래 MRZ 영역만 잘라            
Vision 인식 → '<' 든 긴 줄 2개 이상 ──▶ checkMrz(lines)
                                          칸별 보정 · 검사 숫자 · 연속 2회
                                   ◀── none | lines | pending | confirmed
confirmed → 진동 · 틀 영역 JPEG(메모리)  ─▶ 확인 화면(읽은 값 ↔ 원천 지금 값)
```

검사 숫자 규칙과 보정 표는 Dart 한 곳(`mrz.dart`)에만 두고 네이티브는 글자를 넘기기만 한다 — 자동 인식과 [촬영] 사진 판독이 같은 판정을 쓴다. 상태 글자(「판독 줄 찾는 중」 · 「두 줄 읽음 — 맞추는 중」 · 「확인 중 — 그대로 들고 있어 주세요」)가 사용자에게 무엇을 기다리는지 알려 준다.

## 왜 중요한가

- **검사 숫자는 OCR 의 오류 탐지기다** — 보정이 그럴듯한 후보를 여럿 낼 때 맞는 것을 고르는 기준이 된다. 검사 숫자 없이 보정하면 틀린 여권번호가 조용히 저장된다
- **한 장 촬영은 실패를 사용자에게 넘긴다** — 흐린 사진 → 못 읽음 → 다시 찍기를 사람이 반복한다. 연속 인식은 사용자가 「대고 있기」 만 하면 된다
- **엄격한 조건 = 영영 안 되는 기능** — 표준대로 「전부 일치」 를 걸면 정확해 보이지만 실기기에서 0 회 통과였다. 무엇을 포기하고(종합 검사 숫자) 무엇으로 메우는지(연속 2회 · 확인 화면 · 원천 지금 값과 나란히)를 정해야 쓸 수 있다

## 경계와 오해

- **시뮬레이터로는 확인할 수 없다** — 시뮬레이터는 카메라가 「있음」(가짜 카메라)으로 열려 「카메라 없음 → 손 입력」 길도 안 타고 자동 시험이 멈췄다. 보정 · 판정은 지어낸 견본으로 단위 시험, 카메라 · 초점 · 실제 판독은 실기기에서만
- **법적 검토 대상이다** — 신분증 이미지를 다룬다. 사진은 메모리로만 넘기고 사진첩 · 파일에 저장하지 않으며, 여권(TD3)만 읽고 주민번호가 실린 신분증은 읽지 않는다. 코드 자리마다 「법적 검토 필요」 주석을 남겼다
- **[[transcript-term-correction]] 과 닮았지만 다르다** — 그쪽은 정답 목록에 비춰 고르고, 여기는 **검사 숫자라는 자기 검증**이 정답을 고른다. 고칠 후보를 「적게 바꾼 것부터」 보는 것은 같다
- **[[pdf-text-layer]] 와 다르다** — 그쪽은 글자가 이미 텍스트로 있는지 가르는 문제, 여기는 영상에서 글자를 새로 읽는 문제다
