# script 태그와 실행 순서

**브라우저는 HTML 을 위에서 아래로 읽다가 `<script>` 를 만나면 멈추고 그것을 먼저 실행한다.** 그래서 스크립트를 어디에 두느냐가 화면이 언제 보이는지를 정한다.

## 정의

```html
<script type="text/javascript"> ... </script>   <!-- 실행된다 -->
<script type="text/plain">      ... </script>   <!-- 텍스트로 취급 — 실행 안 된다 -->
```

**읽는 순서가 곧 실행 순서**다.

```
<html> 읽기 → <h1> 그리기 → <script> 만남 → 멈추고 실행 → 나머지 태그 그리기
```

스크립트가 도는 동안 **그 아래 태그는 아직 렌더링되지 않았다** — 그래서 스크립트에서 아래쪽 요소를 찾으면 없다.

두 가지가 따라 나온다.

- **스크립트는 마지막에 두는 것이 기본**이다 — 화면이 먼저 그려지고, 스크립트가 찾을 요소도 이미 있다
- **스크립트 오류는 페이지를 죽이지 않는다** — 콘솔에 찍고 **다음 코드로 넘어간다** → [[exception-handling]]

## 왜 중요한가

**「내 코드가 왜 안 도나」의 절반이 순서 문제다.** 요소를 못 찾는 것도, 값이 아직 없는 것도, 화면이 늦게 보이는 것도 전부 **읽는 순서**에서 나온다. 자바에서 `main` 이 시작점이던 것과 달리, 여기서는 **문서를 읽는 흐름 자체가 실행 흐름**이다 → [[main-method]]

**그리고 실패가 조용하다.** 자바는 예외가 나면 그 흐름이 끊기는데, 브라우저는 스크립트 하나가 터져도 다음 것을 계속 실행한다 — **일부만 동작하는 화면**이 나오므로 콘솔을 보는 습관이 곧 디버깅 능력이 된다

## 경계와 오해

- **`type` 을 틀리게 적으면 조용히 실행되지 않는다** — 필기의 예시가 `text/javascrip`(오타)인데, 실제로 그렇게 쓰면 브라우저가 **모르는 타입으로 보고 실행하지 않는다.** 오류도 안 난다. 오늘날은 `type` 을 아예 생략하는 것이 기본이다
- **「마지막에 둔다」는 관례이지 유일한 답은 아니다** — `defer`·`async` 속성으로 **읽기를 멈추지 않게** 할 수 있고, 문서 로딩 완료 이벤트를 기다리는 방법도 있다. 이 회차는 위치로만 푼다
- **외부 파일이면 내려받는 동안도 멈춘다** — `<script src="...">` 는 네트워크 왕복이 렌더링을 막는다. 위치의 문제가 **속도의 문제**가 되는 지점이다 → [[http-message]]
- **스크립트가 만든 화면은 처음 HTML 에 없다** — 검색 엔진이나 정적 분석이 보는 것과 사용자가 보는 것이 갈린다 → [[static-and-dynamic-content]] · [[template-engine]]
