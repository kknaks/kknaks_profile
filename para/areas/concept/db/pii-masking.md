# PII 마스킹 (PII masking)

개인 식별 정보(PII — 실명·전화번호·생년월일 등)의 원값은 저장 계층에 보존하되, 사람이나
시스템에게 나가는 표시·전달 표면에서 값의 전부 또는 일부를 가려 내보내는 통제 방식이다.
소거(값 자체를 없앰)·가명화(다른 값으로 치환)와 달리 원본 데이터의 재처리·감사 가능성을
유지한 채 노출만 막는다.

## 정의

1. **반입 판정이 먼저다** — 컬럼 단위로 「그대로 반입 / 마스킹 후 반입 / 미반입」을 가른다.
   원천에서 이미 마스킹된 값(예: 플랫폼이 닉네임 처리한 리뷰 작성자)은 그대로 둬도 되고,
   식별자 원값(실명·전화·생년월일)은 마스킹 대상이며, 하위 계층에는 값 대신 파생
   플래그만 반입하는 방법도 있다(예: 이름의 로마자 여부 판정은 원천 계층에서 하고
   표준화 계층에는 플래그만 넘긴다 — 실명 미반입).
2. **비정형 속 PII 도 대상이다** — 구조화된 컬럼만이 아니라 자유 텍스트(리뷰 본문 등)에
   섞여 들어온 실명도 전처리 단계에서 마스킹한다. 마스킹은 후속 처리(파싱·LLM 채점)보다
   앞에 온다 — 뒤에 두면 중간 산출물에 원값이 남는다.
3. **가리는 지점을 한 군데로 모은다** — 소비자(화면·API·에이전트)마다 각자 가리면 규칙이
   여러 벌이 되어 반드시 어긋난다. 마스킹 뷰 같은 단일 경계를 세우고 모든 소비자가 그
   경계를 지나게 한다.

## 왜 중요한가

원본 보존과 노출 금지는 한 데이터에 동시에 걸리는 상충 요구다. 저장 계층에서 지우면
행수 대사·재처리·감사가 무너지고, 아무 데서도 안 가리면 유출이다. 마스킹은 이 상충을
「저장은 원값, 표면은 가림」으로 분리해 둘 다 성립시킨다. 가리는 지점이 흩어져 있으면
새 소비 경로(신규 도구·디버그 엔드포인트)가 생길 때마다 구멍이 되므로, 경계가 한 군데인지가
설계의 핵심이다.

## 경계와 오해

- **마스킹 ≠ 비식별화** — 마스킹된 표시값은 재식별 위험을 줄일 뿐 없애지 않는다. 원값이
  저장 계층에 남아 있으므로 저장소 접근 통제는 별개로 필요하다.
- **마스킹 ≠ 소거·가명화** — 소거는 원본을 잃고, 가명화는 치환 매핑이 새 비밀이 된다.
  재처리·감사가 필요하면 마스킹, 원값이 영영 불필요하면 소거가 맞다.
- **프롬프트 지시 ≠ 경계** — LLM 에게 「이름을 말하지 마라」고 지시하는 것은 마스킹이
  아니다. 지시는 뚫린다. 모델이 마스킹된 값만 받게 데이터 계층에서 가려야 나갈 원값이
  없다.
- **원천에서 이미 가려진 값 ≠ 내 마스킹의 성과** — 원천 정책이 바뀌면 같이 뚫린다.
  반입 판정표에 「원천에서 마스킹됨」을 근거로 남겨 추적 가능하게 한다.
