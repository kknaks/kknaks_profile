# 디자인 토큰

디자인 토큰은 색상, 글자 크기, 간격, 모서리 반경처럼 반복해서 쓰는 시각적 값을 이름으로 정의한 것이다. 여러 화면과 컴포넌트가 같은 값을 참조하게 해 디자인 기준을 공유한다.

## 정의

토큰은 이름과 값의 대응으로 표현할 수 있다. 예를 들어 `color-primary`에 주요 행동의 색상을, `space-medium`에 기본 간격을 지정한다. 이름에 역할을 담으면 값뿐 아니라 사용 의도도 전달하기 쉬워진다.

레퍼런스 사이트에서 추출한 색상이나 간격은 토큰을 정리하는 재료가 된다. 추출한 값에 이름을 부여하고, 어떤 요소에 적용할지 규칙을 마련하면 [[design-system]]의 구성 요소로 사용할 수 있다.

## 사용 예시

착지 교안의 HTML 예제를 축약하면 다음과 같다. 수치와 색상은 원본 사이트에서 추출한 값이 아니라 교안의 학습용 값이다.

```html
<style>
  :root {
    --color-surface: #ffffff;
    --color-primary: #2458c6;
    --space-medium: 16px;
    --space-large: 32px;
    --radius-card: 12px;
  }
  .card {
    padding: var(--space-large);
    margin-bottom: var(--space-medium);
    border-radius: var(--radius-card);
    background: var(--color-surface);
  }
  .card a { color: var(--color-primary); }
</style>
<section class="card">
  <h2>팀 문서를 한곳에서 검색하세요</h2>
  <a href="#guide">사용 방법 보기</a>
</section>
<section class="card" id="guide">
  <h2>문서를 등록하고 검색하세요</h2>
  <p>검색어를 입력하면 관련 내용을 찾을 수 있습니다.</p>
</section>
```

두 카드는 같은 간격과 모서리 토큰을 참조한다. `--radius-card`를 변경하면 두 카드의 모서리가 함께 바뀐다. 변수 선언은 값을 정의하고, `.card` 규칙은 그 값을 사용할 대상을 정한다.

## 왜 중요한가

값을 화면마다 따로 지정하면 비슷한 요소에 서로 다른 간격이나 색상이 적용되기 쉽다. 토큰으로 공통 값을 관리하면 변경 지점을 줄이고 일관성을 유지하기 쉬워진다.

AI로 UI를 생성할 때도 구체적인 토큰을 제공하면 AI가 색상과 간격을 매번 새로 선택해야 하는 범위를 줄일 수 있다. 다만 적용 규칙까지 함께 제공해야 토큰의 사용이 흔들리는 것을 줄일 수 있다.

## 경계와 오해

- **토큰이 같다 ≠ 디자인이 적용됐다** — `:root` 토큰 값이 디자인과 일치해도 그 토큰을 쓰는 규칙(간격·행간·컴포넌트 치수)이 다르면 화면은 다르다. 적용 여부는 토큰 표가 아니라 규칙 층에서 검사한다(금지 간격 grep, 정의 없는 변수 참조, 지역 오버라이드).
- **primitive 이름 ≠ semantic 이름** — 화면에서 `--gray-500` 을 직접 부르면 값은 같아도 층위가 어긋난다. 화면은 `--text-tertiary` 같은 역할 이름만 쓴다.

- **값 목록만으로 디자인 시스템이 완성되지는 않는다.** 어떤 상황에서 어떤 토큰과 컴포넌트를 사용하는지 별도 규칙이 필요하다.
- **CSS 변수는 토큰을 표현하는 한 방법이다.** 이 예제의 구현 방식이 디자인 토큰의 정의 전체는 아니다.
- **자동 추출이 서비스 적합성을 판단해 주지는 않는다.** 추출 전에 레퍼런스가 서비스의 목적과 인상에 맞는지 확인해야 한다.
- **토큰 공유만으로 모든 화면의 품질이 보장되지는 않는다.** 정보 구조와 문구 등은 별도로 설계하고 검수해야 한다.
