# 경과 시간은 「지금 상태가 시작된 뒤」 — 상태와 시간을 한 칸에 두 줄로

관제 화면의 「N분」 은 **무엇이 시작된 뒤의 N분인지**가 같이 읽혀야 값이 된다. 기준을 「지금 상태가 시작된 시각」 하나로 정하고, 화면에는 **현재 상태(1줄)와 그 상태의 경과(2줄)를 한 칸에 붙여** 보인다. 시간만 떨어져 있으면 전체 체류인지 그 상태의 시간인지 읽히지 않는다.

## 정의

1. **기준 시각은 상태 전이가 정한다** — 상태가 바뀔 때마다 `since = now` 로 다시 잡는다. 「경과」 = `now − since`. 방문 전체 체류 · 예약 지연(예약 시각 기준)은 **다른 값**이라 다른 이름으로 둔다
2. **1줄 = 현재 상태** — 대기 계열은 상태 라벨 + 「중」(`다음 단계 대기 중` · `귀가 대기 중`), 진행 계열은 진행 중인 단계 이름(`포텐자 펌핑팁` · `실장 상담`)
3. **2줄 = `<종류> N분 경과`** — 종류는 상태 key 에서(대기 · 상담 · 시술). 1분 미만은 `대기 1분 미만` 처럼 0 을 쓰지 않는다
4. **오래 걸림은 2줄에만 색을 얹는다** — 대기 계열이 기준(예: 30분) 이상이면 빨강. 진행 중인 시술 시간에는 붙이지 않는다
5. **문구는 함수 하나가 만든다** — cc-prototype 은 현황에 시간이 보이는 9곳(도면 칸 · 접수대기실 · 현황 카드 · 고객 패널 머리 · 직원 화면 …)이 같은 함수를 쓴다. 곳마다 문구를 만들면 앞말이 일부에만 붙는다(실제로 그랬다)

## 왜 중요한가

- 값은 이미 맞았는데 **표기 때문에** 틀린 정보처럼 읽혔다 — back 은 처음부터 상태 전이 때 `since` 를 다시 잡았지만, 도면 칸이 「3분」 과 「다음 단계 대기」 를 떨어뜨려 두어 「전체 3분」 으로 읽혔다. 고칠 곳은 계산이 아니라 문구였다
- 대기가 길어진 사람을 찾는 것이 관제 화면의 일이다. 기준이 섞이면 「30분 대기」 경고가 방금 상태가 바뀐 사람에게도, 오래 기다린 사람에게도 붙지 않는다

## 경계와 오해

- **경과 시간 ≠ 지연** — 지연은 약속 시각(예약)과의 차이, 경과는 현재 상태가 시작된 뒤다. 같은 카드에 둘이 나와도 섞지 않는다
- **형식 통일 ≠ 의미 통일** — `N시간 M분` 으로 형식을 맞춰도 「무엇의 시간인지」 앞말이 없으면 해결이 아니다
- **사용자가 정한 줄 구성은 문자 그대로 옮긴다** — 「두 줄」 을 한 줄로 합치는 제안은 같은 정보라도 지시를 바꾼 것이다(cc-prototype 2차 질책)
