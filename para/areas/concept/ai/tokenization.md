# 토큰화 (Tokenization)

토큰화는 텍스트를 분석 목적이나 모델에 맞는 처리 단위로 나누는 과정이다. 토큰은 단어·형태소·부분 문자열 등일 수 있으며, 반드시 사람이 이해하는 최소 의미 단위와 일치하지는 않는다.

## 정의

공백 기반 토큰화는 띄어쓰기로 텍스트를 나눈다. 형태소 기반 방식은 어근·조사·어미 등의 구조를 활용한다. 서브워드 방식은 학습된 부분 문자열을 사용해 드문 단어도 여러 조각으로 표현한다.

BPE와 WordPiece는 서브워드 분할 방법이다. SentencePiece는 BPE나 Unigram 등을 지원하는 토크나이저 도구다. 서브워드는 사전에 없는 단어인 OOV를 다루는 데 도움이 되지만, 표현 가능한 범위는 문자·바이트 처리 방식에도 영향을 받는다.

분할된 토큰에 부여하는 토큰 ID는 식별자다. 번호가 가깝다고 의미가 가까운 것은 아니다. 신경망에서는 이 ID로 임베딩 테이블의 벡터를 찾는 방식이 흔하다.

모델이 아는 토큰 전체의 집합을 **어휘(vocabulary)** 라 한다. 보통 수만 개 수준이고, **어휘 크기가 곧 출력층의 크기**이며 다음 토큰의 확률분포는 이 어휘 위에서 정의된다([[language-model]]).

### 단위를 무엇으로 고르나

쪼개는 단위는 문자와 단어 사이 어디든 될 수 있다. 양 끝에 각각 한계가 있어 서브워드로 절충한다.

| 단위 | 어휘 크기 | 시퀀스 길이 | 의미 | 모르는 단어 |
| --- | --- | --- | --- | --- |
| 문자 | 아주 작음 | 아주 김 | 거의 없음 | 문제 없음 |
| 단어 | 빠르게 증가 | 짧음 | 있음 | UNK 로 처리 |
| 서브워드 | 수만 개 | 중간 | 어느 정도 | 조각으로 표현 |

서브워드를 쓰는 이유가 셋이다.

1. **의미가 남는 수준으로 나눈다.** 「요리하기 → 요리 + 하기」. 문자 단위는 어휘가 몇십 개로 끝나지만 「요」 하나에는 뜻이 없고 문장 하나가 수백 스텝으로 늘어난다. 같은 조각을 포함한 단어들은 학습 결과를 공유한다 — 「요리」를 배운 모델은 요리사·요리법·요리하기를 같은 조각 위에서 처리한다.
2. **어휘 크기를 압축한다.** 한국어처럼 어미가 붙는 말은 단어 단위로 세면 먹다·먹었다·먹었었다·먹겠습니다가 전부 다른 단어가 된다. 「먹」 + 어미 몇 개로 쪼개면 훨씬 작은 어휘로 같은 표현을 다룬다. 꼬리 쪽 드문 단어도 공통 조각으로 표현된다([[zipf-law]]).
3. **모르는 단어를 유추할 수 있다.** 단어 단위 어휘는 처음 보는 단어를 전부 `UNK` 하나로 처리해 신조어·고유명사·오타가 같은 토큰이 되고 정보가 사라진다. 서브워드는 이미 아는 조각들의 조합으로 표현하므로 학습 때 못 본 단어도 문맥 안에서 다룰 수 있다.

서브워드에도 한계가 있다. **잘게 쪼개질수록 시퀀스가 길어지고 비용은 토큰 수로 매겨진다.** 영어 위주로 만든 토크나이저에 한국어를 넣으면 같은 뜻에 토큰이 몇 배 더 든다.

## 사용 예시

```python
text = "파이썬으로 데이터를 분석한다"
tokens = text.split()
assert tokens == ["파이썬으로", "데이터를", "분석한다"]
```

공백 분할은 `파이썬으로`에서 조사 `으로`를 분리하지 않는다. 형태소 분석기는 이런 문법적 요소를 분리할 수 있고, 서브워드 토크나이저는 학습된 어휘에 따라 또 다른 조각을 만든다. 따라서 같은 텍스트라도 토크나이저가 다르면 토큰과 토큰 수가 달라진다.

## 왜 중요한가

토큰화는 이후 벡터화가 볼 수 있는 단위를 결정한다. 한국어 조사나 복합어를 적절히 처리하지 못하면 같은 대상을 가리키는 표현이 다른 용어로 계산되거나 검색어의 일부가 검색 가능한 단위로 남지 않을 수 있다.

같은 문장도 모델이 다르면 토큰 수가 다르다. 토큰 수가 **과금 단위이자 컨텍스트 길이의 단위**이므로, 토크나이저 선택이 비용에 직접 들어간다. 한국어 서비스에서 영어 기준 토큰 수를 그대로 추정하면 어긋난다.

어휘 크기는 출력층의 크기를 결정한다. 어휘가 커지면 파라미터와 매 스텝의 계산량이 같이 커진다.

전처리는 모델에 맞아야 한다. 형태소 분석이나 불용어 제거가 전통적인 어휘 분석에 도움이 되더라도, 사전 학습 모델의 입력에서는 문맥을 훼손할 수 있다.

## 경계와 오해

- **토큰화 ≠ 벡터화** — 토큰화는 단위를 나누고, 벡터화는 수치 표현을 만든다.
- **토큰 ID ≠ 의미 좌표** — 식별자 사이의 숫자 차이로 의미 유사도를 계산하지 않는다.
- **토큰화 ≠ 청킹** — 청킹은 긴 문서를 검색·처리할 조각으로 나누는 작업이며, 각 청크 안에 여러 토큰이 들어갈 수 있다.
- **토큰 ≠ 단어** — 사람이 세는 단어 수와 모델이 세는 토큰 수는 다르다. 과금·컨텍스트 계산은 토큰 기준이다.
- **같은 문장 ≠ 같은 토큰 수** — 모델마다 토크나이저가 달라 비교 가능한 수치가 아니다([[perplexity]] 비교가 어려운 이유이기도 하다).
- **서브워드 ≠ 형태소** — 학습된 빈도로 나뉜 조각이라 문법 단위와 일치하지 않는다.
- **개별 토큰의 깨진 표시 ≠ 전체 인코딩 실패** — 바이트 조각이 독립된 문자처럼 표시되지 않을 수 있으므로 전체 인코딩·디코딩 결과를 함께 확인한다.
