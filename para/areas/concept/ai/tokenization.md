# 토큰화 (Tokenization)

토큰화는 텍스트를 분석 목적이나 모델에 맞는 처리 단위로 나누는 과정이다. 토큰은 단어·형태소·부분 문자열 등일 수 있으며, 반드시 사람이 이해하는 최소 의미 단위와 일치하지는 않는다.

## 정의

공백 기반 토큰화는 띄어쓰기로 텍스트를 나눈다. 형태소 기반 방식은 어근·조사·어미 등의 구조를 활용한다. 서브워드 방식은 학습된 부분 문자열을 사용해 드문 단어도 여러 조각으로 표현한다.

BPE와 WordPiece는 서브워드 분할 방법이다. SentencePiece는 BPE나 Unigram 등을 지원하는 토크나이저 도구다. 서브워드는 사전에 없는 단어인 OOV를 다루는 데 도움이 되지만, 표현 가능한 범위는 문자·바이트 처리 방식에도 영향을 받는다.

분할된 토큰에 부여하는 토큰 ID는 식별자다. 번호가 가깝다고 의미가 가까운 것은 아니다. 신경망에서는 이 ID로 임베딩 테이블의 벡터를 찾는 방식이 흔하다.

## 사용 예시

```python
text = "파이썬으로 데이터를 분석한다"
tokens = text.split()
assert tokens == ["파이썬으로", "데이터를", "분석한다"]
```

공백 분할은 `파이썬으로`에서 조사 `으로`를 분리하지 않는다. 형태소 분석기는 이런 문법적 요소를 분리할 수 있고, 서브워드 토크나이저는 학습된 어휘에 따라 또 다른 조각을 만든다. 따라서 같은 텍스트라도 토크나이저가 다르면 토큰과 토큰 수가 달라진다.

## 왜 중요한가

토큰화는 이후 벡터화가 볼 수 있는 단위를 결정한다. 한국어 조사나 복합어를 적절히 처리하지 못하면 같은 대상을 가리키는 표현이 다른 용어로 계산되거나 검색어의 일부가 검색 가능한 단위로 남지 않을 수 있다.

전처리는 모델에 맞아야 한다. 형태소 분석이나 불용어 제거가 전통적인 어휘 분석에 도움이 되더라도, 사전 학습 모델의 입력에서는 문맥을 훼손할 수 있다.

## 경계와 오해

- **토큰화 ≠ 벡터화** — 토큰화는 단위를 나누고, 벡터화는 수치 표현을 만든다.
- **토큰 ID ≠ 의미 좌표** — 식별자 사이의 숫자 차이로 의미 유사도를 계산하지 않는다.
- **토큰화 ≠ 청킹** — 청킹은 긴 문서를 검색·처리할 조각으로 나누는 작업이며, 각 청크 안에 여러 토큰이 들어갈 수 있다.
- **개별 토큰의 깨진 표시 ≠ 전체 인코딩 실패** — 바이트 조각이 독립된 문자처럼 표시되지 않을 수 있으므로 전체 인코딩·디코딩 결과를 함께 확인한다.
