# AI 활용 준비 데이터 (AI Ready Data)

특정 AI 작업에 필요한 품질·구조·맥락·보안·접근성을 갖춰 활용할 수 있도록 준비된 데이터다. 준비 여부는 데이터 자체에 붙는 절대적인 등급이 아니라, 정해진 작업의 요구조건을 충족하는지로 판단한다.

## 정의

AI 활용 준비 상태는 다음 다섯 측면에서 확인한다.

| 조건 | 확인할 내용 | 예시 |
| --- | --- | --- |
| 정제성 | 오류·중복·누락을 활용 목적에 맞게 처리했는가 | 빈 본문을 검토 대상으로 분리하고 중복 기준을 명시한다 |
| 구조화 | 형식·자료형·단위를 일관되게 표현했는가 | 문서 식별자, 제목, 본문, 수정일을 공통 필드로 둔다 |
| 맥락화 | 의미를 해석하는 데 필요한 배경이 있는가 | 적용 대상, 유효 기간, 원본 위치를 보존한다 |
| 보안 및 준수 | 허용된 주체와 목적에 따라 사용할 수 있는가 | 민감정보 처리와 조회 권한 검사를 수행한다 |
| 접근성 | 허용된 주체가 필요한 데이터를 찾고 읽을 수 있는가 | 검색 가능한 저장소와 안정적인 조회 방식을 제공한다 |

예를 들어 `매출: 100`은 형식이 올바르더라도 의미가 불충분하다. 통화, 집계 기간, 집계 범위를 함께 제공해야 계산이나 비교에 사용할 수 있다. 문서 역시 폐기된 규정과 현행 규정을 구분해야 올바른 답변의 근거가 된다.

학습 데이터에서는 사례와 정답의 품질이, 검색 증강 생성에서는 질문에 맞는 근거의 검색 가능성이 중요하다. 업무 도구를 실행하는 에이전트에서는 최신성과 작업 권한도 확인해야 한다.

### 준비 과정

1. **수집:** 필요한 원천 자료를 모으고 원본 식별자, 출처, 수집 시점을 기록한다.
2. **정제:** 오류와 중복을 검사하고 자동 수정 가능한 자료와 검토가 필요한 자료를 나눈다.
3. **표준화:** 날짜·단위·필드 이름을 통일하고 적용 범위와 버전 등 맥락을 보존한다.
4. **활용에 맞는 표현 생성:** 의미 검색이 필요하면 텍스트를 임베딩한다. 정확한 식별자 조회나 수치 계산에는 다른 표현과 조회 방식을 사용할 수 있다.
5. **이력 및 갱신 관리:** 원본과 가공본의 연결, 변환 규칙, 권한을 유지하고 수정·삭제를 파생 데이터에 반영한다.

출처 문서는 네 번째 단계를 벡터화로 설명하지만, 벡터화가 모든 AI 작업의 필수 단계는 아니다. 출처 기록과 권한 관리도 마지막에만 수행하는 작업이 아니라 수집부터 제공까지 이어지는 조건이다.

준비 결과는 필수 메타데이터 누락률, 중복률, 갱신 지연뿐 아니라 실제 질문에 대한 답변 정확성, 근거 적합성, 권한에 따른 조회 결과로 검증한다. 기준과 임계값은 해당 업무에 맞게 정한다.

## 사용 예시

출처 교안의 Python 예시는 제품 보증 문서를 정제하고 중복을 검사한다. 다음은 같은 입력 사례와 판정 기준을 축약한 실행 예시다. 첫 문서는 보존하고, 공백만 다른 두 번째 문서는 중복으로, 세 번째 문서는 빈 본문으로 제외한다.

```python
import hashlib
from datetime import date

rows = [
    {"text": "  제품 A의   보증 기간은 1년입니다. ",
     "source": "manual-a", "updated_on": "2026-02-01", "access": "public"},
    {"text": "제품 A의 보증 기간은 1년입니다.",
     "source": "manual-a", "updated_on": "2026-02-01", "access": "public"},
    {"text": " ", "source": "manual-b",
     "updated_on": "2026-02-01", "access": "public"},
]

ready, rejected, seen = [], [], set()
for number, row in enumerate(rows, 1):
    try:
        text = " ".join(row["text"].split())
        source = row["source"].strip()
        updated_on = date.fromisoformat(row["updated_on"]).isoformat()
        access = row["access"]
        if not text or not source:
            raise ValueError("본문 또는 출처 누락")
        if access not in {"public", "internal"}:
            raise ValueError("알 수 없는 접근 등급")
        digest = hashlib.sha256(text.encode("utf-8")).hexdigest()
        key = (source, updated_on, access, digest)
        if key in seen:
            raise ValueError("동일 출처·버전·권한의 중복 본문")
        seen.add(key)
        ready.append({
            "text": text,
            "metadata": {
                "source": source, "updated_on": updated_on,
                "access": access, "content_hash": digest,
                "transforms": ["normalize_whitespace", "validate_fields"],
            },
        })
    except (KeyError, ValueError, TypeError, AttributeError) as error:
        rejected.append({"row": number, "reason": str(error)})

assert len(ready) == 1
assert len(rejected) == 2
print(ready)
print(rejected)
```

중복 키에는 본문 해시뿐 아니라 출처·버전·권한이 들어간다. 본문이 같아도 이 맥락이 다르면 보존할 이유가 있기 때문이다. 해시는 내용 비교 수단이며 사실의 정확성을 증명하지 않는다.

이 예시는 정제·표준화·기초 이력 관리만 보여준다. `access` 필드를 저장해도 실제 접근 제어가 실행되지는 않는다. 민감정보 검사, 권한 집행, 검색 및 답변 품질 평가는 별도로 필요하다.

## 왜 중요한가

오래된 규정이나 설명 없는 수치를 입력하면 모델이 자연스러운 문장으로 잘못된 답을 만들 수 있다. 데이터의 적용 시점과 의미를 보존하면 이런 오류를 진단하고 올바른 근거를 선택할 기준이 생긴다.

원본 식별자와 변환 이력을 유지하면 문제가 발생한 데이터를 역추적하고 다시 처리할 수 있다. 준비된 데이터를 재사용하면 반복 가공을 줄일 수 있지만, 성능 개선과 비용 절감의 정도는 실제 작업에서 확인해야 한다.

## 경계와 오해

- **정제 완료 ≠ AI 활용 준비 완료** — 오류와 중복을 제거해도 의미·권한·최신성이 부족할 수 있다.
- **벡터화 ≠ 품질 검증** — 임베딩은 비교 가능한 표현을 만들 뿐 원문의 오류를 고치지 않는다.
- **접근성 ≠ 전면 공개** — 허용된 주체가 필요한 자료를 조회할 수 있어야 한다는 조건이다.
- **권한 메타데이터 ≠ 권한 집행** — 검색 결과를 모델에 전달하기 전에 실제 접근 가능 여부를 검사해야 한다.
- **데이터 개선 ≠ 환각·편향 제거 보장** — 모델과 검색·생성 과정의 영향을 함께 평가해야 한다.
- **지식 그래프 ≠ 모든 AI의 필수 요건** — 개체 간 관계를 따라가는 작업인지 판단해 도입한다.
- **AI Ready 데이터 ≠ 데이터 패브릭** — 전자는 특정 활용에 대한 준비 상태이고, 후자는 분산된 데이터를 발견·연결·통제·제공하는 운영 구조다.
- **추론 입력 ≠ 모델 학습** — 데이터를 참고해 답하는 것과 모델 가중치를 갱신하는 것은 별개다.
- 출처에서 언급한 데이터 준비 시간 80%는 조사 근거가 명시되지 않았으므로 일반적인 비율이나 계획의 기준값으로 확정하지 않는다.
