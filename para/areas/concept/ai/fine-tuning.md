# 파인튜닝 (Fine-tuning)

출시된 모델을 우리 문제에 맞추는 **추가 학습**이다. 가중치를 바꾸지만 사전학습보다 데이터·비용이 훨씬 적다(수백~수천 건 수준).

## 정의

바꾸는 것은 「무엇을 아는가」가 아니라 **「어떻게 행동하는가」**다. 도메인 문체, 고정된 출력 형식, 특정 작업의 정확도에 적용한다.

| 맞는 일 | 안 맞는 일 |
| --- | --- |
| 행동 · 문체 학습 | 자주 바뀌는 사실 주입 |
| 고정된 출력 형식 | 최신 정보 반영 |
| 좁은 작업의 정확도 | 사내 문서 검색 |

데이터와 비용이 들고, **사실이 바뀌면 다시 학습해야 한다.** 그래서 적응 기법 셋 중 마지막에 온다 — 프롬프트로 안 되고 RAG 로도 안 될 때다([[foundation-model]]).

데이터 품질이 양보다 앞선다. **잘 만든 수백~수천 건이 잡음 섞인 수십만 건보다 낫다.** 라벨 하나가 잘못되면 모델이 그걸 배운다.

기법상으로는 제공사의 사후학습과 같다. 주체와 목적만 다르다([[model-training-stages]]).

## 왜 중요한가

가중치를 바꾸는 순간 **되돌리기가 어려워진다.** 프롬프트는 즉시 되돌리지만 파인튜닝한 모델은 학습을 다시 해야 한다. 그래서 「먼저 싼 것부터」라는 순서가 단순한 비용 절약이 아니라 **되돌릴 수 있는 것부터**라는 원칙이다.

모델 단종과도 엮인다. 우리가 파인튜닝한 베이스가 단종되면 그 위에 쌓은 학습도 같이 날아간다.

## 경계와 오해

- **파인튜닝 ≠ 지식 주입** — 행동을 바꾸는 수단이다. 사실은 [[retrieval-augmented-generation]] 쪽이다.
- **데이터가 많을수록 좋다 ≠ 성립** — 선별된 소량이 잡음 섞인 대량을 이긴다.
- **파인튜닝 ≠ 사후학습** — 기법은 같고 주체와 목적이 다르다.
- **성능 개선 ≠ 확인된 개선** — 평가 체계 없이 파인튜닝하면 좋아졌는지 판정할 수 없다([[golden-set-regression]]).
- **합성 데이터 ≠ 공짜 라벨** — 만든 모델의 편향과 오류가 그대로 상속된다.
