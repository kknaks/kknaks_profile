# LLM 텍스트 워터마킹

LLM 텍스트 워터마킹은 모델이 다음 토큰을 선택하는 확률 분포에 비밀 규칙으로 작은 편향을 주어, 사람이 읽는 품질은 유지하면서 생성 출처를 통계적으로 검출할 수 있는 신호를 남기는 기법이다.

## 정의

생성 분포형 LLM 텍스트 워터마킹은 다음 요소로 구성된다.

1. **기본 토큰 분포** — LLM이 현재까지의 문맥으로 다음 토큰별 확률을 계산한다.
2. **비밀 키와 문맥** — 비밀 키와 앞선 토큰 또는 문맥을 해시해 각 생성 위치에서 재현 가능한 값을 만든다.
3. **후보 집합 분할** — 재현된 값에 따라 후보 토큰 일부를 워터마크 대상인 그린리스트로, 나머지를 레드리스트로 정한다. 고정 목록 대신 위치마다 분할을 바꾸면 규칙 추정을 어렵게 할 수 있다.
4. **확률 편향** — 자연스러운 후보 가운데 그린리스트 토큰의 점수에 작은 보너스를 주고, 조정된 분포에서 다음 토큰을 샘플링한다.
5. **신호 누적** — 이 과정을 반복하면 긴 출력에서 그린리스트 토큰이 우연한 기대치보다 자주 나타난다.
6. **통계적 검출** — 검출기는 같은 키와 문맥으로 각 위치의 그린리스트를 재현하고, 관측 횟수가 기대 횟수에서 얼마나 벗어났는지 z-score 등의 통계량으로 계산한다.

그린리스트의 기본 비율을 `p`, 검사한 위치 수를 `n`, 실제 그린리스트 토큰 수를 `g`라고 하면 단순화한 검출 점수는 다음과 같이 나타낼 수 있다.

```text
z = (g - n × p) / sqrt(n × p × (1 - p))
```

검출기는 이 점수를 사전에 정한 임계값과 비교한다. 임계값이 낮으면 워터마크를 더 많이 찾지만 인간의 글을 잘못 탐지할 위험이 커지고, 임계값이 높으면 오탐은 줄지만 워터마크가 있는 글을 놓칠 수 있다.

완성된 문자열에 제로 폭 문자 같은 특수 문자를 넣는 문자 삽입형 워터마크도 있다. 그러나 이는 정규화나 복사·붙여넣기로 쉽게 제거될 수 있으며, 토큰 선택의 통계에 신호를 남기는 생성 분포형 워터마크와 구현 및 검출 원리가 다르다.

## 사용 예시

다음은 실제 LLM이나 특정 기업의 구현이 아니라, 비밀 키와 이전 토큰을 이용해 위치별 그린리스트를 재현하고 검출 점수를 계산하는 최소 예시다.

```python
import hashlib
import math


def is_green(previous: str, candidate: str, secret_key: str) -> bool:
    value = f"{secret_key}|{previous}|{candidate}".encode("utf-8")
    return hashlib.sha256(value).digest()[0] < 128


def watermark_score(tokens: list[str], secret_key: str) -> float:
    if len(tokens) < 2:
        raise ValueError("검출에 사용할 토큰이 부족합니다.")

    green_count = sum(
        is_green(previous, current, secret_key)
        for previous, current in zip(tokens, tokens[1:])
    )
    n = len(tokens) - 1
    p = 0.5
    return (green_count - n * p) / math.sqrt(n * p * (1 - p))


sample = "AI 모델은 문장을 자연스럽게 생성한다".split()
print(f"z-score: {watermark_score(sample, 'demo-secret'):.2f}")
```

같은 키와 토큰 문맥을 입력하면 `is_green`은 언제나 같은 판정을 반환하므로 검출기가 생성 시점의 후보 분할을 재현할 수 있다. 실제 생성기에는 그린리스트 후보의 모델 점수를 조정하는 과정이 별도로 필요하다.

## 왜 중요한가

텍스트에는 이미지의 픽셀이나 음원의 파형처럼 신호를 숨길 넓은 표면이 없다. LLM 텍스트 워터마킹은 글 자체에 눈에 띄는 표식을 붙이지 않고도 생성 출처를 확인할 수 있는 단서를 제공한다. 생성 서비스의 투명성 표시, 대량 생성 콘텐츠 조사, 출처 확인을 보조하는 데 활용할 수 있다.

동시에 이 개념을 확률적 판정으로 이해하지 않으면 검출 결과를 작성 주체나 부정행위의 확정적 증거로 오용하게 된다. 실제 운영에서는 분석한 토큰 수, 임계값, 예상 오탐률과 미탐률, 적용 언어와 문서 유형을 함께 평가해야 한다. 교육·채용·제재처럼 사람에게 영향을 주는 결정에는 [[human-in-the-loop]] 검토와 이의 제기 절차가 필요하다.

## 경계와 오해

- **LLM 텍스트 워터마킹 ≠ 보이지 않는 문자 삽입** — 생성 분포형 방식은 완성된 문자열에 별도 문자를 넣지 않고 토큰 선택 빈도에 통계적 편향을 남긴다.
- **워터마크 검출 ≠ AI 작성의 확정 판정** — 인간의 글도 우연히 임계값을 넘을 수 있고, 워터마크가 있는 글도 검출되지 않을 수 있다.
- **비밀 키 ≠ 다음 토큰의 무조건적 결정** — 키와 문맥은 후보 분할이나 샘플링 규칙에 관여하지만 실제 출력에는 모델 확률, 온도와 다른 샘플링 설정도 작용한다.
- **긴 글의 검출력 ≠ 짧은 글의 검출력** — 짧은 글은 신호가 누적될 위치가 적어 우연한 편차와 워터마크 편향을 구별하기 어렵다. 최소 표본을 충족하지 못하면 판정 불가로 처리해야 한다.
- **검출력 향상 ≠ 품질 보존** — 워터마크 편향을 강하게 적용하면 자연스러움이나 정확도가 떨어질 수 있다. 코드, 수식, 인용문, 법률 문구와 고유명사처럼 허용 토큰이 제한된 구간에서는 특히 그렇다.
- **번역·의역·동의어 치환 ≠ 무손실 제거** — 후처리는 신호를 약화할 수 있지만 의미, 문체, 전문용어와 사실 정확성도 바꿀 수 있으며 다른 생성 모델의 신호를 새로 남길 수도 있다.
- **공개된 단순 모형 ≠ 기업의 실제 구현** — 실제 제품의 키 구성, 후보 분할, 샘플링 함수와 판정 임계값은 공개 예제보다 복잡하거나 비공개일 수 있다.
- **기술적 워터마크 ≠ 명시적 출처 공개** — 워터마크는 AI 사용 사실, 사용 모델과 사람의 편집 범위를 밝히는 절차를 보완할 뿐 대체하지 않는다.
