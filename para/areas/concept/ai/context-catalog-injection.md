# AI 맥락 목록 — 테이블 없이 호출 때 DB 를 조회해 프롬프트에 싣기

AI 가 조직의 이름(프로젝트·업무·사람)을 **도구로 하나씩 찾게 두지 않고**, 호출할 때마다 서버가 DB 를 조회해 **목록 전체를 프롬프트에 먼저 실어** 주는 것. 도구 조회는 상세가 필요할 때만 쓰는 보조로 남는다.

## 정의

1. **별도 테이블을 두지 않는다** — 목록은 저장물이 아니라 **조회 결과**다. 새 프로젝트가 생기면 다음 호출부터 들어간다
2. **담는 범위를 결정으로 고정한다** — Strong Hajin 은 「프로젝트 전부 · 완료·취소 안 된 업무 · 구성원 전부」(조직 전체)
3. **한 함수가 조립하고 여러 자리가 같이 쓴다** — 회의록(중간 배치 첫 턴 · 최종 합성 · 용어 보정의 근거)과 AI 업무 생성
4. **세션의 첫 턴·새 세션에만 싣는다** — 세션을 이어 쓰는 모델은 앞 턴을 기억하므로, 매 턴 실으면 세션 기록에 같은 목록이 쌓여 입력만 불어난다. 웜스타트 · timeout 뒤 새 세션 · 세션 유실 때 다시 싣는다

### 실시간 STT · 번역에 용어를 싣기 — 통키

LLM 프롬프트만이 아니다. 실시간 번역 STT(Soniox)는 연결 설정의 `context` 에 용어 쌍(`translation_terms`)을 받는다. 같은 원리로 **연결 때 한 번** 사전을 통째로 싣는다.

- **양방향으로 싣는다** — 정방향(ko → 현지명: 상담사 말을 옮길 때) · 역방향(현지명 · 현지 별칭 → ko: 손님 말을 옮길 때). 역방향이 없으면 손님이 부른 현지 별명이 직역된다(대만어 「美國音波」 → 「미국 음파」)
- **번역 단계에 준다 — 번역 뒤 치환이 아니라** — 결과 문장에서 우리가 낱말을 바꾸면 문장이 어색해지고 이미 나간 TTS 와 어긋난다. 엔진 입력에 주면 자막 · 음성이 한 번에 맞는다. 실물: 용어집 있음 en · zh 3/3 vs 없음 1/3 · 0/3
- **한도를 넘으면 줄이는 순서** — `terms`(일반 낱말) → 역방향 별칭 → 역방향 기본 → 정방향 별칭. 정방향 기본은 끝까지 남기고, 그래도 거절되면 정방향만으로 1회 재연결. 한도 자체는 문서값이 아니라 실측으로 → [[empirical-limit-probing]]
- **엔진이 내는 문자로 싣는다** — 중국어는 간체로만 나오므로 번체로 적힌 사전 칸은 싣기 직전 간체로 → [[chinese-script-conversion]]
- **엔진은 「더 긴 짝 우선」 을 보장하지 않는다** — 정방향에 「써마지 → 鳳凰電波(FLX)」 와 「써마지 CPT → 黃金電波」 를 같이 실었더니 「써마지 CPT」 문장이 대만어로 FLX 이름이 됐다(같은 문장 en 은 맞음). 짧은 짝(브랜드 단독 별칭)이 긴 짝을 덮는다. 새 term 을 싣는 순간 기존 별칭이 모호어가 되는 것 — 대륙 칸에서 热玛吉 단독을 뺀 것과 같은 이유가 한국어 쪽에 생겼다. 한국어 별칭 「써마지」 를 지우자 黃金電波 로 맞았다

## 왜 중요한가

- 도구 조회만 두면 모델이 **제목 부분 일치 · 상한 없는 목록**에 기대 연관 업무와 프로젝트를 놓친다. 「도구마다 한 번」 같은 탐색 규칙은 프롬프트 지시일 뿐 강제되지 않는다
- STT 오인식을 바로잡는 근거가 된다 — 「캐스티」 가 무엇의 오인식인지는 조직의 이름 목록이 있어야 안다 → [[transcript-term-correction]]

## 경계와 오해

- **「카탈로그」 ≠ 새 테이블** — 이름 때문에 별도 저장소로 들리기 쉽다. 사용자가 그렇게 읽고 막아 이름을 「AI 맥락 목록(호출 때 DB 조회)」 으로 바꿨다
- **범위는 결정이 정한다, 기본값이 좁히지 않는다** — 「호출자가 볼 수 있는 것만」 으로 좁힌 기본값이 사용자 결정(「전부」)과 어긋나 검수에서 정정됐다
- 크기 상한을 두지 않은 것은 「조직 규모에서 전량은 실을 수 있는 크기」 라는 판단이다 — 커지면 관측 후 다시 본다. 큰 프롬프트는 전달 통로의 한도에 걸린다 → [[argv-length-limit]]. 외부 엔진이 한도를 대략값으로만 알려 주면 실측해 기본값과 줄이는 순서를 정한다 → [[empirical-limit-probing]]
- **싣는 짝끼리 겹치면 결과는 엔진이 정한다** — 접두어가 겹치는 짝을 함께 실을 때 어느 쪽이 이길지는 문서로 알 수 없다. 추측으로 별칭을 유지하지 말고, 새 term 을 넣을 때 그 term 문장을 실물로 한 번 돌려 본다
- [[retrieval-augmented-generation]] 처럼 질문마다 골라 싣는 것이 아니다 — 작고 닫힌 목록을 통째로 싣는다
