# LLM 위키

LLM 위키는 에이전트가 새 원료를 기존 지식과 비교·분해·병합하고 목차와 색인을 계속 갱신하는 파일 기반 지식 관리 패턴이다. 원료 문서를 단순히 쌓는 대신 재사용 가능한 개념과 연결이 누적되게 한다.

## 정의

LLM 위키는 보통 다음 계층과 반복 루프로 구성된다.

1. `raw/` 같은 원료 영역에 원문과 출처 메타데이터를 보존한다.
2. 인제스트 전에 사용자가 자료의 수집 목적과 기대 활용처를 남긴다.
3. 에이전트가 새 원료에서 개념, 개체, 주장과 관계를 추출한다.
4. 기존 위키를 검색해 중복 개념을 새로 만들지 않고 해당 문서에 내용을 병합한다.
5. 새 개념이 필요하면 출처와 연결된 문서를 만들고 관련 개념 사이에 링크를 추가한다.
6. 목차, 색인, 변경 로그와 종합 문서를 최신 상태로 갱신한다.
7. 질의할 때 관련 위키 문서와 그 원출처를 회수해 답변을 합성한다.
8. 끊어진 링크, 중복 개념, 오래된 색인과 미처리 원료를 정기적으로 검사한다.

에이전트의 행동 기준은 사용자의 역할, 기록 목적, 대상 독자, 원하는 산출물을 적은 핵심 맥락과 프로젝트 지침에 둔다. 수집·질의·정리 절차가 안정되면 각각을 `/ingest`, `/query`, `/lint` 같은 반복 가능한 스킬로 고정할 수 있다.

## 사용 예시

개인 지식 볼트를 다음과 같이 나눌 수 있다.

```text
vault/
├── CLAUDE.md
├── core-context.md
├── raw/
│   ├── articles/
│   └── videos/
├── wiki/
│   ├── index.md
│   ├── concepts/
│   └── syntheses/
└── outputs/
```

사용자가 웹 클리퍼로 영상을 `raw/videos/`에 저장하고 수집 이유를 기록하면 `/ingest`가 기존 개념을 찾아 내용을 병합하고 `wiki/index.md`를 갱신한다. `/query`는 질문에 필요한 위키 문서와 원출처를 읽어 답하고, `/lint`는 중복 문서와 끊어진 링크를 찾는다.

## 왜 중요한가

AI와의 대화나 개별 스크랩은 그대로 두면 세션과 파일 단위에 갇히기 쉽다. LLM 위키는 새 자료를 기존 지식에 반복적으로 병합해 같은 개념에 여러 출처와 관점이 누적되게 한다. 그 결과 과거에 수집한 자료를 새로운 질문과 산출물에 다시 사용할 수 있다.

Markdown 파일을 원장으로 쓰면 사람과 에이전트가 동일한 내용을 읽고 편집할 수 있으며, 별도의 벡터 데이터베이스 없이도 작은 규모의 지식 시스템을 시작할 수 있다. 규모가 커지면 전문 검색, 의미 검색 또는 [[knowledge-graph-assisted-retrieval]]을 보조 계층으로 추가할 수 있다.

## 경계와 오해

- **LLM 위키 ≠ 원료 파일 모음** — 원료를 기존 개념과 병합하고 목차·색인·링크를 갱신하는 누적 루프가 있어야 한다.
- **LLM 위키 ≠ 자동으로 생성된 개인 지식** — 에이전트의 요약과 분해 결과는 재사용 가능한 재료이며, 사용자의 이해와 검토를 거친 결론을 대신하지 않는다.
- **LLM 위키 ≠ RAG의 완전한 대체재** — 파일 기반 탐색은 구성이 단순하지만 문서가 많아지면 누락, 지연, 컨텍스트 증가가 생길 수 있다.
- **LLM 위키 ≠ 검색 정확도 보장** — 색인과 링크가 낡거나 병합 기준이 불명확하면 관련 자료를 놓칠 수 있으므로 대표 질의로 품질을 평가해야 한다.
- **자동 인제스트 ≠ 무제한 자동 수정** — 작은 배치로 변경을 검토하고 원료와 생성물을 구분하며 복구 가능한 버전 기록을 유지해야 한다.
- **지식 그래프 ≠ 위키 원장** — 그래프는 관계 탐색을 돕는 압축된 지도이고 상세 설명과 근거는 위키와 원출처에 남는다.
