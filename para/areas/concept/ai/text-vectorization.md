# 텍스트 벡터화 (Text Vectorization)

텍스트 벡터화는 텍스트를 연산 가능한 숫자 벡터로 표현하는 과정이다. BoW, TF-IDF, 학습된 임베딩은 서로 다른 정보를 반영하는 벡터화 방법이다.

## 정의

문서 N개를 각각 D차원 벡터로 표현하면 N × D 행렬이 된다. 같은 좌표계에서 비교하려면 각 열의 의미나 벡터를 생성한 모델이 일관되어야 한다.

| 방법 | 표현하는 정보 | 일반적인 형태 |
| --- | --- | --- |
| BoW | 어휘별 등장 횟수 또는 등장 여부 | 어휘 사전 크기의 희소 벡터 |
| TF-IDF | 문서 내 빈도와 코퍼스 내 희소성 | 가중치를 부여한 희소 벡터 |
| 학습된 임베딩 | 학습 목표에 따른 의미적 관계 | 모델이 정한 차원의 밀집 벡터 |

BoW는 기본적으로 단어 순서를 버린다. 연속된 토큰을 묶는 n-gram을 특징으로 사용하면 일부 순서 정보를 표현할 수 있다. 예를 들어 `머신 러닝 입문`의 단어 bigram은 `머신 러닝`, `러닝 입문`이다.

희소 표현은 대부분의 값이 0인 표현이고, 밀집 표현은 여러 차원에 값이 채워진 표현이다. 밀집 벡터에도 0은 존재할 수 있다.

## 사용 예시

```python
from collections import Counter

vocabulary = ["파이썬", "데이터", "수학"]
tokens = "파이썬 데이터 파이썬".split()
counts = Counter(tokens)
vector = [counts[word] for word in vocabulary]
assert vector == [2, 1, 0]
```

이 BoW 벡터의 첫 좌표는 `파이썬`의 빈도다. 다른 문서도 동일한 어휘 순서로 변환해야 비교할 수 있다. 등장 여부만 필요하면 각 빈도를 0 또는 1로 바꿀 수 있다.

출처의 도서 제목 비교는 제목에서 TF-IDF를 만드는 경로와 제목을 임베딩 모델에 입력하는 경로를 별도로 사용한다. TF-IDF 결과를 임베딩 모델의 필수 입력으로 쓰는 과정이 아니다.

## 왜 중요한가

같은 유사도 공식이라도 어떤 특징을 벡터에 담았는지에 따라 결과가 달라진다. 어휘 빈도를 담으면 용어의 겹침을 비교하고, 학습된 의미 표현을 담으면 다른 표현 사이의 의미적 관계를 비교할 수 있다.

표현 방식의 차이를 알면 정확한 용어 일치가 필요한 작업에 희소 표현을 기준선으로 삼고, 표현이 다른 관련 문서를 찾는 작업에 임베딩을 비교할 수 있다.

## 경계와 오해

- **벡터화 ≠ 임베딩과 배타적인 단계** — 임베딩은 벡터화의 한 방법이다.
- **토큰화 → TF-IDF → 임베딩이 필수 순서인 것은 아니다** — 수치 표현의 경로는 목적과 모델에 따라 달라진다.
- **숫자로 표현됨 ≠ 의미가 보존됨** — 빈도와 식별자만으로 의미적 관계가 자동으로 생기지 않는다.
- **밀집 벡터 ≠ 항상 더 작은 차원** — 작은 코퍼스에서는 임베딩 차원이 TF-IDF 어휘 수보다 클 수도 있다.
