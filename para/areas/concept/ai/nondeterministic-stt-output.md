# 음성 인식 출력의 비결정성

같은 오디오 파일을 STT 에 두 번 올리면 **토큰 시각·화자 배정이 조금씩 흔들린다.** 그 위에 얹은 규칙(2초 공백 · 300자 · 화자 변경으로 블록 나누기)은 경계가 옮겨가 블록 수가 5개/6개로 달라진다. 규칙은 두 결과 모두에 그대로 적용되므로 계약 위반이 아니다 — 결과가 결정적이라고 **전제하는 테스트**를 쓰면 안 된다.

## 정의

1. 실시간 STT 는 sub-word 토큰(「이」 「제」)을 낸다. 문장은 서버가 블록으로 묶어야 한다.
2. 종료 후 async 재전사는 실시간보다 화자 분리가 낫고(3명 vs 거칠게 2명) 결과가 매번 완전히 같지는 않다.
3. 테스트는 대역 토큰으로 규칙만 검증한다. 실물은 **증거 파일**(응답 코드 · 토큰 수 · 화자 수 · 소요 · 회차별 블록)로 남긴다.
4. 「전사가 안 나온다」는 코드보다 **입력**부터 본다 — 디코드해 10초 창 RMS/피크 dBFS 를 재면 무음(-50dBFS)과 정상(-28dBFS)이 갈린다. Opus 는 무음이어도 고정 비트레이트로 바이트를 만들어 파일이 커지므로 파일 성장은 근거가 못 된다.

## 사용 예시

```
회의 11(정상)  RMS -27.8 / 피크 -8.2 dBFS · 블록 57
회의 12(멈춤)  스트림① -60.4 / -37.6 · ② -43.2 / -24.2 · ③ -51.2   → Soniox 재전사 토큰 6 / 0 / 0
```

## 왜 중요한가

실시간 전사가 멈추면 재연결·일시정지·세션 관리 코드를 먼저 의심하게 된다. 실물 회의 12 는 WS 3회 재연결 · 파일 계속 성장 · Soniox 연결 유지였는데 원인은 통화 앱이 마이크를 잡아 입력이 20~30dB 낮았던 것이었다. 조사 워커가 스트림별 RMS 와 재전사 토큰 수로 후보 넷을 전부 「아니다」로 닫았다.

## 경계와 오해

- **파일이 커진다 ≠ 소리가 들어온다** — Opus 고정 비트레이트.
- **헤더 여러 개 webm** — 재연결마다 새 `MediaRecorder` 가 새 EBML 헤더를 쓴다. ffmpeg 는 이어 붙여 온전히 디코드하지만, 재연결 공백은 파일 시간축에 없어 종료 후 재전사의 `at_ms` 가 실시간 기준과 수 초 어긋난다.
- **사용자에게 보이는 신호가 없다** — 입력 레벨 막대 · 60초 무토큰 안내는 계약 결정이 필요한 자리다.
