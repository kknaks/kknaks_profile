# AI 자산 인벤토리 (AI Asset Inventory)

조직에 어떤 AI 자산이 있는지 중앙에서 식별하고 관리하는 목록이다. 등록 검증과 사용 권한 관리를 연결하면, 흩어진 자산을 통제하고 재사용하는 기반이 된다.

## 정의

인벤토리가 답하는 첫 질문은 **무엇이 있는가**다. 운영에 연결하려면 자산을 목록에 올리는 조건과 실제 사용하는 조건을 별도로 다뤄야 한다.

| 관리 지점 | 답할 질문 |
| --- | --- |
| 식별 | 어떤 Agent·Model·MCP·Skills·Knowledge가 있는가 |
| 등록 | 정해진 개발·운영 절차를 거친 자산인가 |
| 버전 관리 | 어떤 버전의 자산을 공유하고 사용하는가 |
| 사용 | 요청한 사용자가 이 자산과 연결된 시스템·데이터를 사용할 수 있는가 |

이 구분은 [[S-004-samsung-sds-agent-governance]]의 중앙 인벤토리·Marketplace 설명을 일반화한 것이다. 보편적인 필수 메타데이터 표준이나 완결된 수명주기 명세를 뜻하지 않는다.

```mermaid
flowchart LR
    A["분산된 AI 자산"] --> V["등록 검증"]
    V --> I["중앙 인벤토리"]
    I --> P["사용 권한 확인"]
    P --> U["업무에서 사용"]
```

## 발표에서 확인한 예시

발표는 다양한 환경에서 만들어지는 자산을 FabriX Marketplace에 모으는 흐름을 제시했다. 등록할 때 사내 개발·운영 프로세스 준수 여부를 확인하고, 사용할 때 사용자·Agent·하위 시스템·데이터의 권한을 맞춘다.

AI Workspace에서는 Agent Directory Service와 멀티 Agent 오케스트레이션으로 의도에 맞는 자산을 찾아 사용한다. 이때 인벤토리는 무엇이 있는지 관리하는 기반이고, Workspace는 그 자산으로 업무를 수행하는 접점이다.

발표자는 전사 재사용과 중복 개발 감소를 기대 효과로 설명했다. 실제 자산 수나 재사용률·감소율은 제시하지 않았다.

## 왜 중요한가

자산이 여러 환경에 흩어져 있으면 이미 있는 기능을 다시 만들거나 검증되지 않은 자산을 사용할 수 있다. 중앙 식별과 등록·사용 검증을 연결하면 자산을 찾는 일과 사용할 수 있는지 판단하는 일을 이어갈 수 있다.

## 경계와 오해

- 중앙 목록에 있다는 사실만으로 품질이나 보안이 보장되지는 않는다. 등록 검증의 기준과 실행 시 권한 확인이 따로 필요하다.
- 인벤토리와 Marketplace는 같은 범위가 아니다. 인벤토리는 식별·관리 기반이고, Marketplace는 공유·검색·사용 등 유통 기능을 포함한다.
- 등록 당시 검증을 통과했다고 모든 사용자에게 사용을 허용하는 것은 아니다. [[delegated-authorization]]에서 다루는 하위 실행 권한도 확인해야 한다.
- 자산 변경 뒤의 재검증·폐기 기준과 소유권 관리는 추가로 정해야 한다. 발표에 상세가 없어 완성된 운영 명세로 가져올 수 없다.
- 대화형 Workspace나 특정 제품을 도입해야만 성립하는 개념은 아니다. 자산의 식별·등록·사용 경계를 어떻게 관리하는지가 기준이다.
