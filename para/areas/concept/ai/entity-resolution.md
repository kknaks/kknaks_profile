# 개체 해소 (Entity Resolution)

개체 해소는 서로 다른 이름이나 레코드가 현실의 같은 개체를 가리키는지 판별하고 하나의 표준 식별자에 연결하는 과정이다. 지식 그래프에서는 약어, 동의어, 철자 변형 때문에 같은 개체가 여러 노드로 갈라지는 일을 방지한다.

## 정의

개체 해소는 보통 다음 요소를 결합한다.

1. 대소문자, 공백, 구두점 등을 정리해 표기를 정규화한다.
2. 표준 이름과 약어·동의어를 별칭 사전으로 관리한다.
3. 출처 식별자와 주변 속성처럼 동일성을 확인할 수 있는 단서를 비교한다.
4. [[semantic-search]]나 [[text-embedding]]으로 문맥상 유사한 후보를 찾는다.
5. 기준을 충족한 표현을 하나의 표준 개체에 연결하고 판단 근거를 기록한다.

문자열 규칙은 명확한 표기 변형을 안정적으로 처리하고, 의미 유사도는 규칙만으로 찾기 어려운 후보를 넓힌다. 의미적으로 가깝다는 사실만으로 동일 개체라고 확정하지 않고, 모호한 후보는 사람의 검토나 별도의 검증 단계로 넘긴다.

## 사용 예시

`LLM Wiki`, `LLM 위키`, `대규모 언어 모델 위키`가 같은 대상을 가리킨다고 확인되면 세 표현을 하나의 표준 노드에 연결한다. 반대로 `지식 그래프`와 `Graphify`는 관련되어 있어도 각각 개념과 도구를 뜻하므로 동일 노드로 병합하지 않는다.

## 왜 중요한가

개체 해소가 없으면 같은 개체가 여러 노드로 쪼개지고 각 노드에 연결된 관계도 분산된다. 일부 노드는 연결을 잃은 고립 노드가 되며, 탐색 결과가 관련 자료를 빠뜨릴 수 있다. 잘못된 중복을 줄이면 그래프의 연결성과 검색 재현율이 높아진다.

반대로 서로 다른 개체를 잘못 병합하면 한 개체의 속성과 관계가 다른 개체에 전파된다. 따라서 개체 해소는 단순한 데이터 정리가 아니라 지식 그래프의 사실성을 좌우하는 품질 관리 단계다.

## 경계와 오해

- **개체 해소 ≠ 문자열 정규화** — 문자열 정규화는 후보를 만드는 전처리이고, 개체 해소는 두 표현이 실제로 같은 대상을 가리키는지 판별한다.
- **의미 유사성 ≠ 동일성** — 의미가 가까운 두 표현은 관련 개념일 수 있지만 같은 개체라는 보장은 없다.
- **개체 병합 ≠ 관계 연결** — 같은 개체의 중복 노드를 합치는 것과 서로 다른 개체 사이에 간선을 추가하는 것은 별개의 작업이다.
- **자동화 ≠ 무검증 확정** — 낮은 확신의 병합에는 점수, 근거, 검토 상태를 남겨 되돌릴 수 있어야 한다.
- **식별자가 없는 쪽은 「같은 묶음 안」에서 짝짓는다** — KOS 결제 품목 통계엔 상품 id 가 없지만, 같은 수납의 수납 요약에는 옵션 id 가 있다. 수납 안에서 옵션 이름으로 짝지으면 하나로 정해졌다(수집본 671/671). 범위를 좁히면 이름이 키로 쓸 만해진다. 다만 원천이 사라진 개체(삭제된 상품)는 나중에 이을 수 없으니, **이을 대상 목록을 날마다 쌓아 두고 지우지 않는 것**이 해법이고 남은 것은 사람 확인으로 둔다
- **동명이물은 「충돌」이 아니다 — 떼어 낸다** — 같은 이름이 한 계열에선 제품, 다른 계열에선 시술을 가리키거나, 한 제품 설명이 다른 기기 설명으로 적힌 것은 두 출처의 값이 다른 「충돌」로 세면 틀린 쪽을 고르게 된다. 기계는 이름이 같으면 같은 개체로 묶으므로 이 구분은 사람 눈이 한다 — 「출처 충돌이면 주제 전용 원천 채택」 규칙과 「이름만 같은 다른 것」을 가르는 기준을 따로 둔다. 떼어 낸 진술은 지우지 않고 **원천 확인 목록**으로 보낸다
- **원천 작성자의 이름 붙이기는 외부 지식으로 고치지 않는다** — 코디가 외부 지식으로 「장비」라고 분류해 넣은 것이 실제로는 그 원천에서 케이스 이름이었다. 분류는 원천 문구에서 먼저, 외부 지식은 확인 목록으로
- **공식 식별자(허가번호)에 잇는 규칙은 좁히는 순서로 적는다** — 원장 제품 이름 → 식약처 허가: ① 추측 아닌 「이름 포함/모델명 같음」 그룹 하나 + 업체 일치 → 자동(29) ② 이름 든 제품 여럿 → 라인(상위 제품)으로 자동(60) ③ 같은 성분 · 용량만 다른 허가 = 한 제품 + 규격 ④ 수출용 허가 · 사용목적 불일치 허가는 연결 안 함 ⑤ 취소 허가는 이력 ⑥ 허가번호를 못 특정해도 국내 유통이 출처로 확인되면 「허가번호 미확인」 표시로 살린다. 나머지만 사람 게이트. 끝 = 추천 236 · 제외 116 · 합침 18
- **이름은 역할별 칸으로 고정하고, 「왜 이 이름인가」는 근거 칸에만** — 대표 이름(한글 1) · 허가 이름(공식 표기 그대로 · 허가 쪽에만) · 검색 이름[](+언어). 음역 · 오기 · 약칭 같은 이유를 이름 종류로 저장하면 칸이 늘기만 한다. 원장 오기는 고치지 않고 검색 이름 + 원천 수정 목록
- **원장 업체 ≠ 허가 업체면 단정하지 않고 관계를 조사한다** — 23개 중 같은 제품 17(제조 · 수입 · 판매 역할) · 다른 제품 2 · 확인 불가 4 · 원장 오기 6. 「자회사」 같은 말을 근거 없이 쓴 세션은 닫았다
