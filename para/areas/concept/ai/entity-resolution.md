# 개체 해소 (Entity Resolution)

개체 해소는 서로 다른 이름이나 레코드가 현실의 같은 개체를 가리키는지 판별하고 하나의 표준 식별자에 연결하는 과정이다. 지식 그래프에서는 약어, 동의어, 철자 변형 때문에 같은 개체가 여러 노드로 갈라지는 일을 방지한다.

## 정의

개체 해소는 보통 다음 요소를 결합한다.

1. 대소문자, 공백, 구두점 등을 정리해 표기를 정규화한다.
2. 표준 이름과 약어·동의어를 별칭 사전으로 관리한다.
3. 출처 식별자와 주변 속성처럼 동일성을 확인할 수 있는 단서를 비교한다.
4. [[semantic-search]]나 [[text-embedding]]으로 문맥상 유사한 후보를 찾는다.
5. 기준을 충족한 표현을 하나의 표준 개체에 연결하고 판단 근거를 기록한다.

문자열 규칙은 명확한 표기 변형을 안정적으로 처리하고, 의미 유사도는 규칙만으로 찾기 어려운 후보를 넓힌다. 의미적으로 가깝다는 사실만으로 동일 개체라고 확정하지 않고, 모호한 후보는 사람의 검토나 별도의 검증 단계로 넘긴다.

## 사용 예시

`LLM Wiki`, `LLM 위키`, `대규모 언어 모델 위키`가 같은 대상을 가리킨다고 확인되면 세 표현을 하나의 표준 노드에 연결한다. 반대로 `지식 그래프`와 `Graphify`는 관련되어 있어도 각각 개념과 도구를 뜻하므로 동일 노드로 병합하지 않는다.

## 왜 중요한가

개체 해소가 없으면 같은 개체가 여러 노드로 쪼개지고 각 노드에 연결된 관계도 분산된다. 일부 노드는 연결을 잃은 고립 노드가 되며, 탐색 결과가 관련 자료를 빠뜨릴 수 있다. 잘못된 중복을 줄이면 그래프의 연결성과 검색 재현율이 높아진다.

반대로 서로 다른 개체를 잘못 병합하면 한 개체의 속성과 관계가 다른 개체에 전파된다. 따라서 개체 해소는 단순한 데이터 정리가 아니라 지식 그래프의 사실성을 좌우하는 품질 관리 단계다.

## 경계와 오해

- **개체 해소 ≠ 문자열 정규화** — 문자열 정규화는 후보를 만드는 전처리이고, 개체 해소는 두 표현이 실제로 같은 대상을 가리키는지 판별한다.
- **의미 유사성 ≠ 동일성** — 의미가 가까운 두 표현은 관련 개념일 수 있지만 같은 개체라는 보장은 없다.
- **개체 병합 ≠ 관계 연결** — 같은 개체의 중복 노드를 합치는 것과 서로 다른 개체 사이에 간선을 추가하는 것은 별개의 작업이다.
- **자동화 ≠ 무검증 확정** — 낮은 확신의 병합에는 점수, 근거, 검토 상태를 남겨 되돌릴 수 있어야 한다.
