# 조용한 성능 저하 (Silent Model Degradation)

AI 제품은 **코드를 한 줄도 안 고쳐도** 나빠진다. 모델·입력 분포·법규·단가가 우리 일정과 무관하게 움직이고, 대부분 에러 없이 품질만 떨어진다. 오류가 안 나므로 모니터링 없이는 알아차릴 수 없다.

## 정의

바뀌는 것이 넷이고 관리 방법이 각각 다르다.

| 바뀌는 것 | 무슨 일이 일어나나 | 관리 방법 |
| --- | --- | --- |
| 모델 | 단종(deprecation) 날짜가 제공사 일정으로 정해진다. 같은 프롬프트가 새 모델에서 다르게 동작한다 | 버전 고정 + [[golden-set-regression]] |
| 입력 분포 | 사용자·용어·문서가 바뀌면 에러 없이 품질만 떨어진다 | 품질 모니터링 · 사용자 피드백 회수 |
| 법 · 규제 | 고지 의무, 개인정보, 학습 데이터 저작권, 설명·추적 가능성 | 로그 · 출처 · 동의 이력 (**소급 불가**) |
| 제공사 · 단가 | 벤더 종속. 토큰 단가가 내려가고 더 싼 모델이 나온다 | 호출부를 얇은 레이어로 추상화 |

**소급 불가**가 이 개념의 실무 핵심이다. 기능은 나중에 붙여도 되지만 **지나간 기록은 만들 수 없다.** 입력·출력·모델 버전 로그, 데이터 출처, 동의 이력은 나중에 필요해질 것을 알고 처음부터 넣는다.

반대 방향도 있다. 새 모델이 더 싸고 좋아서 우리가 몇 달 들여 만든 우회 로직이 통째로 필요 없어지기도 한다. 「지금 만드는 것 중 무엇이 곧 쓸모없어질까」를 설계에 넣는다.

## 왜 중요한가

전통적인 소프트웨어의 유지보수 감각이 여기서 깨진다. **배포하지 않아도 제품이 변한다.** 그래서 「완성했다」가 아니라 「유지되고 있는가」가 상태의 단위가 되고, 평가·모니터링이 제품 기능이 아닌 인프라로 취급된다.

개인정보 대목도 그렇다. 프롬프트에 개인정보가 섞이면 외부 API 호출이 곧 제3자 제공·국외 이전이 된다. 「그냥 API 쓰는 것」이 아니다.

## 경계와 오해

- **에러 없음 ≠ 정상** — 이 실패는 에러를 내지 않는다.
- **모델 교체 ≠ 단순 문자열 변경** — 모델 ID 하나를 바꾸는 일이 제품 동작 전체의 변경이다.
- **로그는 나중에 ≠ 가능** — 소급해서 만들 수 없는 유일한 부류다.
- **벤더 종속 ≠ 성능 문제** — 갈아탈 수 있느냐의 문제이고, 호출부 추상화로 비용을 줄인다.
- **최신 모델로 교체 ≠ 개선** — 검증 없이는 개선인지 퇴행인지 알 수 없다.
