# 검색증강생성 (RAG)

모델 **밖의** 지식을 검색해 프롬프트에 붙여 넣는 방식이다. 가중치를 바꾸지 않으므로 학습 이후의 정보나 사내 문서를 다루는 표준 경로가 된다.

## 정의

```text
질문 → 관련 문서 검색 → 컨텍스트에 삽입 → 답변
```

검색은 [[semantic-search]]든 [[lexical-search]]든 둘을 섞든 무방하다. 핵심은 **근거 문서를 그대로 들고 있다**는 점이다 — 그래서 출처를 달 수 있다.

맞는 일과 안 맞는 일이 [[fine-tuning]]과 정확히 반대다.

| | RAG | 파인튜닝 |
| --- | --- | --- |
| 바꾸는 것 | 입력에 붙는 지식 | 가중치(행동·문체) |
| 맞는 일 | 최신 · 사내 지식 | 말투 · 형식 · 작업 정확도 |
| 사실이 바뀌면 | 문서만 갈아 끼운다 | 다시 학습해야 한다 |
| 비용 | 중간(검색 인프라) | 높음(데이터 + 학습) |

비용이 「중간」인 이유는 검색 인프라가 제품이 되기 때문이다 — 색인·청킹·임베딩 갱신·권한 필터가 전부 운영 대상이다. 특히 **임베딩 모델을 바꾸면 기존 벡터를 전부 다시 만들어야 한다.** 규모가 커진 뒤에는 작업량이 크므로 교체 계획을 미리 잡아 둔다.

검색에 들어가는 데이터가 준비돼 있지 않으면 이 구조 전체가 서지 않는다([[ai-ready-data]]).

## 왜 중요한가

환각을 「모델을 더 잘 만들어서」가 아니라 **구조로** 줄이는 방법이다. 모델이 배우는 것은 그럴듯함이므로([[language-model]]), 사실성이 필요하면 사실을 입력으로 넣어 주고 그 근거를 화면에 함께 내놓는 편이 검증 가능하다.

권한 사고가 나는 자리이기도 하다. 검색 결과를 모델에 넘기기 전에 실제 접근 권한을 검사하지 않으면, 「검색되면 답한다」가 그대로 유출 경로가 된다.

## 경계와 오해

- **RAG ≠ 환각 제거** — 근거를 붙일 뿐이다. 붙인 근거를 잘못 읽거나 근거 밖을 지어낼 수 있다.
- **검색되면 답한다 ≠ 답해도 된다** — 권한 메타데이터가 있는 것과 권한을 집행하는 것은 다르다.
- **RAG ≠ 파인튜닝의 대체** — 목적이 다르다. 지식은 RAG, 행동은 파인튜닝이다.
- **문서 추가 ≠ 검색 반영** — 재색인과 재임베딩이 자동이 아니면 별도로 실행해야 한다.
