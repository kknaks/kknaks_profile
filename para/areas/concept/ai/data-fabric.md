# 데이터 패브릭 (Data Fabric)

여러 시스템에 분산된 데이터를 공통 의미, 메타데이터, 접근 규칙과 연결 계층으로 묶어 필요한 곳에 일관되게 제공하는 데이터 운영 구조다. 데이터를 무조건 한 저장소로 복사하는 것보다 서로 다른 위치의 데이터를 발견하고 이해하며 안전하게 사용할 수 있게 하는 데 초점이 있다.

## 정의

데이터 패브릭은 다음 요소를 함께 갖춘다.

1. **발견과 목록화** — ERP, MES, SCADA, QMS, 그룹웨어, 문서 저장소와 로컬 파일에 어떤 데이터가 있는지 카탈로그로 관리한다.
2. **공통 의미** — 고객·공급업체·품목·설비처럼 시스템마다 다르게 표현된 대상을 공통 식별자와 의미 모델로 연결한다.
3. **연결과 제공** — API, 이벤트, 데이터 파이프라인 등의 접근 계층으로 원천 데이터를 필요한 시점에 제공한다.
4. **품질과 계보** — 데이터의 소유자, 최신성, 정확도, 변환 과정과 원천을 추적한다.
5. **보안과 거버넌스** — 역할별 접근 권한, 민감 정보 보호, 보존 정책과 감사 기록을 적용한다.

이 기반 위에서 [[ai-agent]]는 여러 기업 시스템의 정보를 하나의 업무 맥락으로 조회하고, [[workflow-orchestration]]의 각 단계는 동일한 식별자와 의미를 공유할 수 있다.

## 왜 중요한가

AI 모델이 발전해도 필요한 기업 데이터가 흩어져 있거나 의미가 서로 다르면 정확한 판단과 실행은 불가능하다. 데이터 패브릭은 AI가 사용할 수 있는 정보의 범위와 신뢰도를 결정한다.

또한 사람이 시스템별 자료를 모아 다시 입력하는 중복 작업과 데이터 사일로를 줄인다. 실적·재고·품질·생산 데이터를 일관되게 연결하면 월 단위 수작업 보고를 넘어 이상 탐지, 원인 분석과 롤링 포캐스트 같은 지속적인 의사결정을 지원할 수 있다.

## 경계와 오해

- **데이터 패브릭 ≠ 단일 데이터베이스** — 모든 데이터를 한 저장소에 물리적으로 복사해야 성립하는 구조가 아니다. 분산된 원천을 공통 메타데이터와 접근 계층으로 연결할 수 있다.
- **데이터 패브릭 ≠ 데이터 레이크** — 데이터 레이크는 주로 데이터를 저장하는 장소이고, 데이터 패브릭은 위치가 다른 데이터를 발견·연결·통제·제공하는 운영 구조다.
- **연결만 하면 의미가 통합되는 것은 아니다** — 인터페이스가 있어도 고객·품목 코드와 집계 기준이 다르면 같은 데이터를 다르게 해석한다. 의미 모델과 데이터 계약이 필요하다.
- **AI가 데이터 품질을 자동으로 해결하지 않는다** — 누락·중복·오래된 값과 잘못된 식별자는 모델 입력에도 그대로 영향을 준다. 소유자와 품질 기준을 명시해야 한다.
- **전부 수집하는 것이 목표가 아니다** — 가치가 낮거나 민감한 데이터까지 무차별적으로 모으면 비용과 위험이 커진다. 우선순위 업무에 필요한 데이터부터 연결한다.
- **RAG와 같은 개념이 아니다** — RAG는 모델에 관련 지식을 제공하는 한 가지 방식이다. 데이터 패브릭은 RAG를 포함한 여러 소비자가 사용할 기업 데이터의 발견·의미·접근·통제를 다룬다.
