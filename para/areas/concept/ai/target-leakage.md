# 타깃 누수 (Target Leakage)

결과(성공 · 실패)를 정하는 정보가 그 결과를 설명하려는 특징 안에 섞여 들어가는 것이다. 그러면 특징과 결과의 관계가 실제보다 훨씬 강하게 보인다. 특징이 결과를 「예측」하는 게 아니라 결과를 다시 읽고 있을 뿐이다.

## 정의

1. **결과를 정하는 자료가 있다.** 예약 성공을 「고객이 채운 예약표 회신」으로 정하면, 그 회신 메시지가 결과를 정하는 자료다.
2. **특징을 만드는 입력에 그 자료가 들어간다.** 회신 메시지까지 넣고 주제 · 이모지 · 길이를 세면, 성공한 방에만 있는 메시지가 특징을 만든다.
3. **특징이 성공 쪽으로 부풀어 오른다.** 예약표에 통역 · 날짜 칸이 있으면 성공 방마다 「통역」 · 「일정」 주제가 붙는다. 양식 기호(★ · 📝)는 이모지로 센다.

막는 방법은 **결과를 정하는 자료를 특징 입력에서 뺀다**이다. 시간으로 자르는 것(결과 시점 이전만 쓰기)도 같은 원리다.

## 사용 예시

상담 DM 분석에서 LLM 주제 라벨의 입력을 고른 함수(`label_layer2_llm.py` · `llm-0.3.0`). 칸 수(`form_labels` · `form_filled`)는 앞 단계 규칙이 메시지마다 세어 둔 값이다:

```python
def room_lines(con, cid):
    """시간순 [(message_id, tag, 본문)] — 자동응답(우리) · 본문 없는 메시지 · 예약표 메시지(0.3.0) 제외."""
    out = []
    for mid, own, content, auto, labels, filled in con.execute(...):
        if own and auto is not None:
            continue
        if own and labels >= 3:  # 우리 예약표 발송
            continue
        if not own and filled >= 2:  # 고객 예약표 회신 = 성공을 정한 메시지
            continue
        if content is None or not content.strip():
            continue
        out.append((mid, "[S]" if own else "[C]", " / ".join(content.split("\n"))))
    return out
```

| 특징 | 회신 포함 | 회신 뺌 |
|---|---|---|
| 통역을 물은 방의 성공률 | 57.1% | 33.8% (77방) |
| 성공 방의 이모지 사용 | 94.6% | 50.5% |

라벨마다 근거 메시지 id 를 남겨 두었기 때문에 찾을 수 있었다. 「성공 방 주제의 근거가 예약표 메시지인가」를 세었더니 통역 89 · 일정 93 · 위치 75 · 부작용 36 이 전부 예약표였다.

## 왜 중요한가

누수가 있으면 「이걸 물은 손님이 예약을 많이 한다」 같은 결론이 나온다. 숫자가 그럴듯해서 보고서까지 그대로 간다. 고치려면 라벨을 전부 다시 붙이고 집계와 차트를 다시 만들어야 한다. 처음 입력을 고를 때 「결과를 정하는 자료는 뺀다」를 계약에 넣어 두면 이 비용이 들지 않는다.

## 경계와 오해

- **누수 ≠ 상관 · 인과 혼동** — 누수를 없앤 뒤에도 「통역을 물은 방 33.8%」는 원인이 아니다. 방문을 이미 생각하는 손님이 통역을 묻는 것일 수 있다. 누수는 측정이 틀린 것이고, 인과 혼동은 맞게 잰 값을 잘못 읽는 것이다 → [[conversion-rate]]
- **LLM 만의 문제가 아니다** — 같은 누수가 규칙 집계(이모지 수 · 메시지 수 · 턴 수)에도 생긴다. 상담 DM 분석에서는 이모지에서 먼저 발견했고, 같은 꼴을 LLM 주제에서 다시 찾았다
- **근거 id 가 없으면 못 찾는다** — 라벨 값만 저장하면 「왜 이 주제가 붙었나」를 되짚을 수 없다. 근거 메시지를 붙이는 것이 누수 점검의 전제다 → [[evidence-binding]]
- **빼는 범위는 결과 정의에서 나온다** — 성공 정의가 바뀌면 빼야 할 메시지도 바뀐다. 입력 규칙의 버전(`llm-0.3.0`)을 라벨 행에 남겨야 어느 정의로 뺐는지 안다
