# 엔지니어링 거버넌스

엔지니어링 거버넌스는 조직이 축적한 아키텍처 결정을 기계가 읽을 수 있게 구조화하고 코드 생성·검토·병합 과정에 전달해 집행하는 계층이다. 암묵적으로 따르던 규칙을 명시적이고 추적 가능한 정책으로 바꾼다.

## 정의

엔지니어링 거버넌스 계층은 네 가지 기능으로 구성된다.

1. **구조화된 결정 말뭉치** — ADR에 우선순위, 유효 상태, 대체 관계 같은 메타데이터를 두어 충돌 시 어떤 결정이 적용되는지 판별한다.
2. **안정적인 검색** — 같은 코드 변경에 대해 같은 관련 결정을 찾을 수 있도록 검색 과정과 결과를 기록한다.
3. **생성 전 문맥 주입** — 관련 결정을 에이전트가 코드를 쓰기 전에 제공해 사후 수정이 아니라 최초 구현에 반영한다.
4. **CI 집행** — 위반을 경고하거나 병합을 차단하고 판정을 특정 ADR, 일치 조건, 규칙 문구와 코드 증거로 추적한다.

검색과 추천에는 확률적 시스템을 사용할 수 있지만 최종 집행 판정은 저장된 코드·ADR·검색 로그·규칙으로 재구성할 수 있어야 한다. 팀은 정책별로 경고 후 진행을 허용할지, 해결 전까지 변경을 차단할지 집행 강도를 명시한다.

## 왜 중요한가

AI 코딩 도구는 구현 생산량을 늘리지만 조직의 결정 기록을 자동으로 기억하지 않는다. 거버넌스 계층이 없으면 기능적으로 정상인 코드도 서비스 경계나 감사 절차를 우회할 수 있고, 리뷰어의 기억과 시간에 품질 보존 책임이 집중된다.

판정 근거를 재현할 수 있으면 개발자는 병합이 막힌 이유를 확인하고, 감사자와 사고 회고 참여자는 어떤 규칙과 증거가 적용됐는지 검증할 수 있다. 또한 특정 코딩 도구나 모델에 종속되지 않고 여러 에이전트와 자체 호스팅 모델에 같은 결정을 적용할 수 있다.

## 경계와 오해

- **엔지니어링 거버넌스 ≠ 자율 에이전트** — 호출되면 규칙을 적용해 판정을 내리고 종료하며, 다음 행동을 스스로 계획하지 않는다.
- **엔지니어링 거버넌스 ≠ 일반적인 RAG 메모리** — 검색 방법은 바뀔 수 있지만 결정 말뭉치가 원천이며 최종 판정은 확률적 응답에 맡기지 않는다.
- **엔지니어링 거버넌스 ≠ AI 코드 리뷰** — 두 번째 모델의 의견이 아니라 생성 전에 전달된 결정과 재현 가능한 집행 경로가 핵심이다.
- **엔지니어링 거버넌스 ≠ 공급자별 규칙 파일** — Cursor, Claude Code, GitHub Copilot, Codex 또는 자체 호스팅 모델에 같은 정책을 적용할 수 있어야 한다.
- **자유 형식 지침 ≠ 완전한 거버넌스** — 우선순위, 버전, 수명주기와 위반 감지가 없으면 충돌 해결과 집행을 보장하지 못한다.
