# LLM 심판 (LLM-as-judge)

사람이 하던 정성 평가를 모델에게 시켜 자동화하는 것이다. 정량화가 어려운 「답이 쓸 만한가」를 수치로 돌리는 수단이지만, **붙이는 순서를 지키지 않으면 신뢰도를 모르는 점수만 쌓인다.**

## 정의

정성 평가를 정량으로 확장하는 네 단계이고, 순서가 곧 규칙이다.

1. **루브릭을 먼저 쓴다.** 「좋은 답」의 조건을 문장으로 고정한다. 기준이 없으면 평가자마다 다른 항목을 본다.
2. **샘플을 사람이 채점한다.** 수십~수백 건. 이 결과가 기준점(골든셋)이다.
3. **LLM 심판을 붙인다.** 같은 루브릭으로 모델이 채점하게 하고, **사람 채점과 얼마나 일치하는지 먼저 검증한다.**
4. **일치하면 그때부터 자동으로 돌린다.** 일치율은 주기적으로 다시 확인한다.

순서를 건너뛰고 3번부터 시작하면, 채점의 신뢰도를 확인하지 않은 채 평가 결과를 쌓게 된다.

## 왜 중요한가

AI 제품의 평가는 정답 하나와 대조해 끝나지 않는다. 맞는 답이 여러 개고 틀린 답도 그럴듯해 보인다. 그래서 **평가 체계를 만드는 것 자체가 개발 업무**이고, LLM 심판은 그 체계를 사람 속도에서 CI 속도로 옮기는 장치다.

개선보다 평가가 먼저 와야 하는 이유도 같다. 평가 체계가 없으면 프롬프트를 고쳐도 좋아졌는지 알 수 없다([[launch-criteria]]).

## 경계와 오해

- **LLM 심판 ≠ 객관적 채점** — 모델의 편향이 채점에 들어온다. 사람 채점과의 일치율이 유일한 근거다.
- **자동화 ≠ 검증 생략** — 일치율 확인을 건너뛰면 점수의 의미를 모른다.
- **높은 점수 ≠ 좋은 제품** — 루브릭이 재는 것만 잰다.
- **한 번 검증 ≠ 계속 유효** — 모델이나 입력 분포가 바뀌면 일치율이 움직인다([[silent-model-degradation]]).
