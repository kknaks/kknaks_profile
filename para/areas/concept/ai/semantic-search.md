# 의미 검색 (Semantic Search)

의미 검색은 검색어와 문서에 같은 단어가 있는지가 아니라, 둘의 의미가 얼마나 가까운지를 기준으로 결과를 찾는 검색 방식이다. 임베딩 기반 방식에서는 검색어와 문서를 벡터로 표현하고 벡터 사이의 유사도를 계산한다.

## 정의

임베딩 기반 의미 검색은 다음 순서로 동작한다.

1. 문서를 [[text-embedding]]으로 벡터화해 저장한다.
2. 검색어도 같은 임베딩 모델로 벡터화한다.
3. 검색어 벡터와 문서 벡터 사이의 코사인 유사도 같은 척도를 계산한다.
4. 유사도가 높은 문서를 검색 결과로 반환한다.

긴 문서는 검색 결과의 단위를 만들기 위해 여러 청크로 나눈 뒤 각 청크를 임베딩할 수 있다. 이때 문장이나 절의 경계를 보존하면 서로 관련 없는 내용이 한 벡터에 섞이거나 문맥이 중간에서 끊기는 문제를 줄일 수 있다.

## 사용 예시

`안보위기`라는 표현이 들어 있는 노트에 정확히 같은 단어가 없어도, 사용자가 안보상의 위험이나 국가 안전에 관한 의미가 비슷한 검색어를 입력하면 가까운 벡터를 가진 노트를 찾을 수 있다.

QMD는 마크다운 노트를 임베딩하고 검색어 벡터와 비교해 의미가 가까운 노트를 반환한다. 긴 마크다운 문서는 고정된 토큰 수로만 자르지 않고 헤딩 등의 구조를 고려해 청킹한다.

## 왜 중요한가

[[lexical-search]]만 사용하면 작성할 때 쓴 표현을 기억하지 못하거나 동의어로 검색했을 때 관련 문서를 놓칠 수 있다. 의미 검색은 정확한 단어가 떠오르지 않아도 내용상 가까운 문서를 찾게 해 주므로, 표현과 문서 수가 늘어나는 개인 지식 관리나 AI Agent의 메모리 검색에서 회수 범위를 넓힌다.

## 경계와 오해

- **의미 검색 ≠ 생성형 AI의 이해** — 임베딩 벡터의 근접도를 이용한 검색은 관련성을 추정하지만, 검색 결과가 사실이거나 질문의 정답임을 보장하지 않는다.
- **의미 검색 ≠ 문자열 포함 검색** — 같은 단어의 포함 여부가 핵심이라면 [[lexical-search]]의 영역이다.
- **벡터 유사도 ≠ 항상 좋은 검색 품질** — 임베딩 모델의 언어 성능, 문서 청킹 방식, 데이터 특성에 따라 결과가 달라진다.
- **로컬 실행 ≠ 낮은 비용의 보장** — 외부 API 비용은 피할 수 있지만 모델 실행에 필요한 메모리와 연산 성능은 로컬 컴퓨터가 부담한다.
