# 입력 전수 표 — 규칙 전에 입력 꼴 × 데이터 조합을 먼저 세기

**증상이 난 입력 하나씩 규칙을 덧대지 않고, 들어올 수 있는 입력의 꼴을 축으로 나눠 실제 데이터와 곱한 표를 먼저 짓는다.** 그 표를 지금 시스템에 그대로 돌려 실패를 층별로 세고, 설계를 한 번에 고친 뒤 완료를 「표 통과율」 로 판정한다.

## 정의

1. **축을 정한다** — 의도 꼴(무엇을 묻나) × 말 꼴(어떻게 말하나: 조사 · 줄임 · 겹침 · 앞 답 가리키기 · 거둠) × 데이터 실제 조합(원천에 있는 값). 축은 지금까지 터진 증상에서가 아니라 입력이 가질 수 있는 성질에서 뽑는다
2. **표를 짓는다** — 축의 곱에서 실제 데이터로 채울 수 있는 칸만 대화 · 턴으로 만든다. 각 턴에 정답 키(기대 대상 · 턴 종류 · 부위 등)를 단다
3. **지금 시스템에 그대로 돌린다** — 고치기 전에 잰다. 턴마다 **처음 실패한 층**(후보 → 턴 종류 → 부위 → 객체 → …)을 하나만 기록한다
4. **실패 표로 원인을 가른다** — 층별 수가 「데이터 보강」 인지 「구조」 인지를 수로 말해 준다
5. **설계를 한 번 고치고 같은 표로 다시 잰다** — 완료 = 통과율 문턱. 같은 표가 이후 [[golden-set-regression]] 의 기준 묶음이 된다

## 사용 예시

phub-gold-jev 상담 입구: 의도 꼴 × 말 꼴 × gold 실제 조합으로 대화 55 · 턴 255 를 짓고 그대로 돌리니 통과 115/239(48%). 실패 층은 후보 39 · Jev 43 · 앱 규칙 39 · 데이터 3 — 데이터는 3 뿐이라 보강이 아니라 구조(글자 맞춤 resolve 가 후보 관문) 문제였다. 다섯 판을 같은 표에서 재 소넷+별칭 97.1% 로 입구를 갈았다. 이후 표를 대화 78 · 턴 356 으로 넓혔다.

## 왜 중요한가

- **증상 하나씩 막으면 옆에서 새 구멍이 난다** — 조사 · 줄임 · 겹침 · 부위 잇기 규칙을 차례로 덧댄 0.1 ~ 0.3 은 e2e 마다 다른 문장이 터졌다. 규칙끼리 서로를 모르고, 어느 꼴이 아직 안 막혔는지 셀 방법이 없었다
- **원인 층이 수로 나온다** — 「데이터가 모자라서」 와 「구조가 틀려서」 는 체감으로 갈리지 않는다. 층별 실패 수가 갈라 준다
- **「다 됐다」 의 기준이 생긴다** — e2e 에서 안 터졌다는 것이 아니라 표 통과율이 완료 조건이 된다

## 경계와 오해

- **정답 키 · 프롬프트 · 채점을 한 손이 지으면 점수가 부푼다** — 같은 워커가 표 · 프롬프트 · 채점을 함께 지어 소넷 97.1% 가 윗값이었다. 검수가 엄격 채점으로 92.5 ~ 94.1, 프롬프트 예문 8 개가 표 턴과 같다는 것을 찾았다. 표를 짓는 손과 프롬프트를 짓는 손을 가르고, 예문이 표 턴과 겹치는지 grep 한다 → [[llm-as-judge]]
- **표 안의 가짜 앞 답은 실물과 어긋난다** — 앞 답을 가리키는 턴(「그거」 「두 번째」)은 표가 지어 둔 앞 답 기준이라, 실물 시스템이 다른 앞 답을 내면 맞게 답해도 떨어진다(9 턴). 분모에서 따로 센다
- **확률 모델은 같은 코드도 판마다 흔들린다** — 소넷은 같은 코드에서 8 검사 중 6% 가 판마다 바뀌었다. 문턱 판정은 **같은 코드로 두 번** 재서 둘 다 넘을 때만 믿는다
- **전수 표 ≠ 모든 문장** — 축의 곱을 채운 대표 턴이다. 축 밖의 꼴(새 의도 · 새 말버릇)이 나오면 축을 늘려 표를 다시 짓는다
- **[[contract-surface-enumeration]] 과 짝이다** — 그쪽은 계약이 닿는 **코드 자리**를 세고, 이쪽은 시스템에 들어오는 **입력 꼴**을 센다. 둘 다 「목록을 받지 말고 전부 센다」
