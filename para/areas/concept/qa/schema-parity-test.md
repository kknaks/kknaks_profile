# 모델과 수동 SQL 의 어긋남을 구조 시험이 잡는다

같은 표 모양이 **여러 곳에 적혀 있을 때**(코드의 모델 · 처음 까는 DB 용 SQL · 운영에 돌린 ALTER) 그 사이의 어긋남을 사람이 아니라 **시험이 대조하는 것.** 칸 하나를 더할 때 맞춰야 할 자리가 둘 이상이다.

## 정의

1. **표 모양의 사본을 센다** — 모델(ORM) · 새 DB 를 처음 깔 때 쓰는 SQL · 운영에 이미 돌린 수동 ALTER. 마이그레이션 도구가 없거나 일부 표가 수동 SQL 로 관리되면 사본이 생긴다
2. **구조 시험** — 처음 까는 SQL 로 빈 DB 를 만든 뒤 그 칸 · 타입 · 제약을 모델과 비교한다
3. **칸을 더할 때 맞출 곳은 둘이다** — 운영용 ALTER 와 처음 까는 DB 용 정의. 운영이 ALTER 로 맞아 있어도 새로 까는 DB 는 틀린다

## 왜 중요한가

- 운영은 맞고 새 DB 만 틀리는 어긋남은 **운영에서 안 보인다** — 개발자 새 환경 · CI · 재구축 때 처음 터진다. 운영 DB 를 다시 만들 예정이면 그때가 터지는 날이다
- 구조 시험은 단계마다 돌리는 「관련 시험」 에 잘 안 들어간다 — 마지막 전체 시험 한 번이 이것을 잡는 자리다

## 경계와 오해

- **운영 ALTER 가 맞았다 ≠ 스키마가 맞다** — 사본이 하나 더 있다
- **구조 시험 ≠ [[online-schema-change]]** — 그것은 운영에 돌리는 순서, 이것은 적힌 정의끼리의 일치
- 단계마다 관련 시험만 돌리는 것은 옳다 — 다만 그 대가로 이런 교차 대조는 마지막 전체 한 번에서만 잡힌다. 그 한 번을 빼지 않는다
