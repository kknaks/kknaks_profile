# 의존성 올림의 실행 회귀 — 시험이 덮지 않는 동작 변화

하나를 위해 의존성을 올리면 **그 아래 전이 의존성이 줄줄이 움직이고**, 그중 시험이 덮지 않는 실행 동작(웹뷰 · OS 통합 · 창)이 바뀌어 **엉뚱한 곳에서** 회귀가 난다. 빌드와 시험이 통과해도 실측해야 하는 이유다.

## 정의

1. **움직인 범위를 센다** — 올린 것 하나가 아니라 lockfile diff 전체(움직인 크레이트 · 패키지 수)가 바뀐 범위다
2. **시험이 덮는 곳과 안 덮는 곳을 가른다** — 로직은 시험이 덮지만, 웹뷰 생성 옵션 · 창 · 전체화면 · 권한처럼 실행 환경에서만 보이는 동작은 실측으로만 본다
3. **회귀가 나면 diff 를 전수로 좁힌다** — 증상과 가까운 층(예: macOS 웹뷰 생성 코드)의 버전 사이 diff 를 끝까지 읽어 바뀐 것을 하나로 좁힌다. 짐작으로 고치지 않는다
4. **바뀐 기본값을 되돌리고, 그 기본값에 기대던 자리도 고친다**

## 왜 중요한가

- 회귀가 올린 이유와 무관한 곳에서 난다 — Windows 용 플러그인 때문에 올린 판이 macOS 전체화면을 흔드는 식이다. 「이번 변경 범위」 로만 확인하면 못 본다
- 원인을 diff 로 하나로 좁히면 고침이 한 줄이다. 좁히지 않으면 증상(높이)을 CSS 로 덮다가 다른 조합에서 다시 터진다

## 경계와 오해

- **시험 통과 ≠ 회귀 없음** — 전이 의존성의 동작 변화는 시험 바깥에 있다. 검수가 「N 개가 움직였다 — 실행 회귀는 실측으로」 라고 짚으면 그것이 체크리스트다
- **올린 이유가 사라져도 올린 판은 남는다** — 결과적으로 그 플러그인을 한 OS 에만 쓰게 돼도, 올린 판은 모든 OS 에 깔린다
- 증상 근처를 고치는 것 ≠ 원인 — 빈 공간 높이를 맞추는 것과 바뀐 웹뷰 옵션을 되돌리는 것은 다르다. 둘 다 필요할 수 있다(셸 높이 `100vh` → `100%` 사슬)
