# 데모 버튼으로 외부 연동 자리를 대신한다 — 상태 전이는 실제와 같게

아직 없는 외부 연동(상대가 우리에게 보내는 요청 · 우리가 상대에 등록한 결과)을 시연해야 하면, **들어오는 입구 하나만 데모 버튼으로 바꾸고** 그 뒤의 상태 전이 · 저장 · 화면은 실제와 똑같이 만든다. 연동이 생기면 버튼만 실제 수신으로 갈아 끼운다.

## 정의

1. **가짜는 입구에만** — 데모 API(`POST /…/demo/request` · `/demo/modify`)가 하는 일은 「외부에서 요청 한 건이 들어왔다」 를 만드는 것뿐이다. 그 뒤 등록 · 변경 요청 · 수정 확정은 실제 조작 API 로 간다
2. **상태 전이는 back 에 한 곳** — 실제 흐름(본사 → 병원 → KOS)과 같은 전이를 표 하나(`TRANSITIONS`)로 둔다: 확인중 → 확정 / 변경 요청 → 수정 확인중 → 수정 확정 · 이전 줄 변경됨. 맞지 않는 조작은 409
3. **데모 입구는 눈에 띄게 따로** — 화면에서 주황 점선 「데모 전용 · 링키 연동 자리」 상자에 모아, 업무 버튼과 섞이지 않게 한다. 대상이 없으면 막힌다
4. **외부 결과는 그 순간의 스냅샷으로** — 「KOS 에 등록한 화면」 처럼 상대 시스템의 결과를 보여 줘야 하면, 등록 순간의 값을 `snapshot` 으로 저장하고 화면이 그것으로 그린다. 이후 원본 줄이 바뀌어도 그때 보낸 값은 그대로 남고, 등록 전에 바뀐 줄은 `null`(「등록 전에 바뀌어 스크린샷이 없어요」)
5. **연동 자리마다 주석** — 실제 호출이 들어갈 곳에 `kos api 연동 필요`(등록 = 예약 생성 · 수정 = 예약 변경)를 남긴다

## 왜 중요한가

- 화면만 흉내 내면 연동이 생길 때 **화면 뒤를 처음부터 다시** 만든다. 전이 · 저장을 실제처럼 두면 바뀌는 것은 입구 하나다
- 시연 중 「이건 진짜인가」 가 섞이지 않는다 — 데모 버튼이 모인 상자만 가짜다
- 스냅샷이 없으면 「무엇을 등록했나」 를 지금 값으로 다시 그리게 되고, 수정 뒤에는 이전 등록이 사라진다

## 경계와 오해

- **[[runtime-profile-gating]] 의 데모 지름길과 다르다** — 그쪽은 개발 편의(데모 계정 목록)를 운영에서 숨기는 문제, 여기는 아직 없는 외부 입구를 시연에서 대신하는 문제다. 공개 배포에서 데모 버튼을 둘지는 따로 정한다
- **목데이터와 다르다** — [[seed-data]] 는 시작 상태를 채우고, 데모 버튼은 진행 중에 사건을 일으킨다
- **스냅샷 ≠ 캐시** — 갱신하지 않는 것이 목적이다. 「그때 무엇을 보냈나」 의 기록이다
