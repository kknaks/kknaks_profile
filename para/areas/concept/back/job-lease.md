# 작업 lease — 오래 도는 워커 작업의 점유 기한 셈

워커가 큐에서 작업을 집으면 **「언제까지 내 것인가」 기한(lease)** 을 함께 잡는다. 기한 안에 끝내거나 연장(heartbeat)하지 못하면 작업은 **죽은 워커의 것으로 보고 다시 풀린다.** 기한이 짧으면 살아 있는 작업을 남이 또 집고, 길면 정말 죽은 작업이 오래 묶인다.

## 정의

1. **바닥 = 루프가 실제로 부를 수 있는 최대 외부 호출 수 × 호출 하나의 timeout + 여유** — Strong Hajin 회의록 최종 합성은 timeout 900초 × 최대 5호출(재시도·새 세션 포함)을 담아 **6000초 바닥**을 잡았다
2. **heartbeat 로 연장한다** — 도는 동안 주기적으로 기한을 민다. 바닥은 heartbeat 가 멈췄을 때의 안전망이다
3. **heartbeat 의 실패가 본 작업을 끊지 않는다** — 연장 예외가 루프를 깨면 합성은 끝났는데 결과를 적지 못한 **고아**가 된다
4. **같은 대상의 동시 진입은 기록의 비교-교환(CAS)으로 막는다** — 세션 참조처럼 둘이 동시에 쓸 수 있는 칸은 「내가 읽은 값일 때만 바꾼다」 로 갱신한다 → [[optimistic-lock]]

## 왜 중요한가

- 외부 호출(LLM CLI 등)의 timeout 을 늘리면 lease 도 같이 늘려야 한다 — 따로 두면 **긴 작업을 다른 워커가 다시 집어 같은 일을 두 번** 한다
- 셈을 「식」 으로만 시험하면 루프가 바뀌어도 시험이 통과한다. **최악 경로를 실제로 돌려 센 호출 수**와 셈을 대조해야 어긋남이 잡힌다(Strong Hajin 검수에서 실제로 어긋났다)

## 경계와 오해

- **lease ≠ [[distributed-lock]]** — 락은 「지금 들어가도 되나」 를 묻고, lease 는 「집은 작업을 언제 놓은 것으로 볼까」 를 정한다. lease 는 만료가 본질이다
- **lease 를 넉넉히 = 안전이 아니다** — 죽은 워커의 작업이 그만큼 늦게 풀린다. 바닥은 셈으로, 나머지는 heartbeat 로
- 웜스타트처럼 같은 회의의 세션을 만지는 다른 경로도 **같은 락 안**으로 들여야 경주가 닫힌다
