# 상수 풀 (Constant Pool)

`.class` 파일 안에서 이름·문자열·참조가 모여 사는 표. 클래스 이름이든 메서드 이름이든 실제 글자는 여기 한 번만 두고, 나머지는 **몇 번째 항목인지**로 가리킨다.

## 정의

항목마다 앞에 **태그**가 붙어 무엇인지 알려주고, 뒤에 그 종류에 맞는 값이 온다.

| 태그 | 뜻 | 뒤따르는 것 |
|---|---|---|
| `01` | UTF-8 문자열 | 길이 + 아스키 바이트 |
| `07` | 클래스 | 이름이 든 UTF-8 항목의 인덱스 |
| `09` | 필드 참조 | 클래스 인덱스 + name-and-type 인덱스 |
| `0a` | 메서드 참조 | 클래스 인덱스 + name-and-type 인덱스 |
| `0c` | name-and-type | 이름 인덱스 + 타입(디스크립터) 인덱스 |

표 맨 앞에는 **항목 수**가 온다. 그리고 항목들은 서로를 인덱스로 가리켜 층을 이룬다 — 메서드 참조(`0a`)가 클래스(`07`)와 name-and-type(`0c`)을 가리키고, 그 둘이 다시 UTF-8(`01`)을 가리킨다.

## 사용 예시

`HelloWorld` 라는 클래스 이름을 넣는 데 두 항목이 든다.

```plaintext
0003                                     // 상수 풀 항목 3개
07 0002                                  // 07=클래스, 이름은 2번 항목
01 000a                                  // 01=UTF-8, 길이 10글자
48 65 6c 6c 6f 57 6f 72 6c 64            // "HelloWorld"
```

부모 클래스도 같은 모양이다.

```plaintext
0700 04                                  // 클래스, 이름은 4번 항목
0100 10                                  // UTF-8, 16글자
6a 61 76 61 2f 6c 61 6e 67 2f 4f 62 6a 65 63 74   // "java/lang/Object"
```

`System.out.println` 하나를 부르려면 이 참조가 여럿 필요하다 — `java/lang/System` 클래스, `out` 필드와 그 타입 `Ljava/io/PrintStream;`, `println` 메서드와 그 타입 `(Ljava/lang/String;)V` 가 전부 항목으로 들어가고 서로를 가리킨다.

```plaintext
0900 0500 0c                             // 필드 참조: System 의 out
0c00 0d00 0e                             // name-and-type: 이름 + 타입
0100 03 6f 75 74                         // "out"
0100 15 4c 6a 61 76 61 2f 69 6f 2f ...   // "Ljava/io/PrintStream;"
```

## 왜 중요한가

**같은 이름을 여러 번 쓰지 않는다.** 한 클래스에서 `println` 을 백 번 불러도 글자는 상수 풀에 한 번만 있고 나머지는 인덱스다. 파일이 작아지고, 이름을 고칠 자리도 한 곳이 된다.

그리고 이 구조가 **실행 시점에 이름으로 찾는 일**을 가능하게 한다. 참조가 글자로 남아 있으므로 JVM 이 실행할 때 그 이름의 클래스를 [[classpath]] 에서 찾아 연결할 수 있다. 컴파일할 때 주소로 굳어 버리지 않는 것이 Java 의 성질이고, 그 근거가 상수 풀이다.

## 경계와 오해

- **상수 풀 ≠ 상수(`final`)** — 이름이 비슷하지만 다른 것이다. `final` 변수를 모아 둔 곳이 아니라, **클래스가 참조하는 이름과 리터럴의 표**다.
- **인덱스는 1부터 센다** — 0번은 쓰지 않는다. 그래서 헤더의 개수 값과 실제 마지막 인덱스가 어긋나 보인다.
- **`.` 이 아니라 `/` 다** — 상수 풀 안에서 패키지 구분자는 `java/lang/Object` 처럼 슬래시다. 소스에서 쓰는 `java.lang.Object` 표기와 다르다.
