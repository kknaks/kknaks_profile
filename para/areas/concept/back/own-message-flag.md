# 「내가 보낸 줄」 판정 재료를 저장 칸 하나로

여러 원천(슬랙 · 메일 · 카톡)에서 모은 메시지에서 「이 줄은 내가 보낸 것인가」 를 **읽을 때 원천별로 추측하지 않고, 수집할 때 판정해 칸 하나(`from_me`)에 저장하는 것.** 판정 재료는 원천마다 다르지만, 쓰는 쪽(안 읽음 세기 · 알림 · 「내 행동은 안 알림」)은 칸 하나만 본다.

## 정의

1. **원천마다 재료가 다르다** — 슬랙은 원본의 작성자 id(`raw.user`)가 연동 계정 id 인가, 메일은 From 이 연동 계정 주소인가, 카톡은 수집기가 붙인 표지(작성자 id == 내 채팅 컨텍스트 id)
2. **수집 시점에 판정해 칸에 박는다** — 재료가 원본에 남아 있을 때 판정하고, 이후 표시용 가공과 갈라 둔다
3. **쓰는 쪽은 칸만 본다** — 안 읽음 세기에서 내 줄 빼기, 「내 행동은 알리지 않음」 이 같은 칸을 쓴다

## 왜 중요한가

- **표시 이름이 식별자를 덮으면 판정이 조용히 0 이 된다** — 작성자 칸에 id 를 두고 비교하던 코드가, 수집 중 그 칸을 사람이 읽을 표시 이름으로 덮어 버리면 「작성자 == 내 id」 가 한 줄도 맞지 않는다. 에러는 없고 결과만 틀린다(내 줄도 안 읽음으로 센다)
- **재료가 아예 없는 원천이 있다** — 원본(raw)에 「내가 보냄」 이 없으면 칸을 나중에 채울 길도 없다. 수집기를 고쳐 재료를 실어야 하고, 그 전에 다른 원천(로컬 DB 사본 등)과 개수를 맞춰 봐야 판정을 믿을 수 있다

## 경계와 오해

- **식별자 ≠ 표시 이름** — 같은 칸에 두 의미를 섞지 않는다. 사람에게 보일 이름은 따로 두고, 비교는 늘 id 로
- **읽을 때 판정 ≠ 저장할 때 판정** — 읽을 때 원천별 분기를 하면 쓰는 자리마다 분기가 복제되고, 원본 가공이 바뀌면 전부 깨진다
- 백필은 선택이다 — 옛 행에 칸을 채우는 것은 원본 재료가 남아 있을 때만 된다. DB 를 다시 만들 예정이면 하지 않아도 된다
- 운영 DB 로 확인해야 보인다 — 시험 픽스처는 id 를 넣어 두므로 덮어쓰기 버그를 못 본다 → [[dev-prod-parity]]
