# 외부 API 오류 분류 — 403 은 폐기가 아니다

외부 API 의 오류 응답을 보고 **되돌릴 수 없는 처리(연결 끊기·토큰 폐기)를 할지**를 정할 때, 상태 코드 하나로 묶지 않고 **원인별로 갈라** 판단하는 것.

## 정의

| 응답 | 뜻 | 처리 |
|---|---|---|
| 401 · `invalid_grant` · `token_revoked` | 자격이 죽었다 | 연결을 끊음 상태로, 재연결 안내 |
| 403 (속도 제한) | 잠깐 막혔다 | 백오프 재시도 |
| 403 (이 자원 권한 없음) | 이 파일·방만 안 된다 | 그 요청만 실패, 연결은 유지 |
| 5xx · 타임아웃 | 상대가 아프다 | 재시도 |

연결을 끊는 갈래에는 **경고 로그**를 남긴다 — 사용자가 「갑자기 끊겼다」고 할 때 원인을 찾을 길이다.

## 왜 중요한가

403 을 「폐기」로 묶으면, 속도 제한 한 번이나 권한 없는 첨부 하나를 열어 본 것만으로 **멀쩡한 연결이 끊긴다.** 사용자는 다시 동의 과정을 밟아야 하고, 끊긴 사이의 이벤트는 놓친다.

## 경계와 오해

- **같은 403 이 서비스마다 다른 뜻이다** — Gmail 은 속도 제한을 403 으로 준다. 슬랙은 첨부 권한 없음이 403 이다. 본문의 사유 코드를 본다
- **되돌릴 수 있는 처리는 넓게, 되돌릴 수 없는 처리는 좁게** — 재시도는 여러 코드에 걸어도 되지만, 끊기는 확실한 신호에만 건다
- 조용히 삼키는 것과 다르다 — 분류해서 각자 드러낸다 → [[no-silent-fallback]]
