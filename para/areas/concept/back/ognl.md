# OGNL (Object Graph Navigation Language)

**객체 그래프를 문자열 경로로 탐색해 값을 읽고 쓰는 표현 언어.** 파일 경로가 디렉토리를 파고들듯, 점으로 이어진 이름이 객체 안의 객체를 파고든다.

## 정의

- 자바 객체의 **프로퍼티 값을 가리킬 때 쓰는 문법**이다
- 객체에 포함된 객체를 **경로처럼** 따라가 값을 조회한다
- 탐색 대상이 [[object-graph]] 이므로 이름이 그렇게 붙었다

```
owner.address.city
```

이 한 줄이 자바로는 `getOwner().getAddress().getCity()` 다. **호출이 아니라 이름으로 적는 것**이 핵심이다 — 문자열이므로 컴파일 시점에 결정하지 않아도 된다.

## 왜 중요한가

**「어느 값을 가져올지」를 코드 밖에서 정할 수 있게 한다.** 경로가 문자열이므로 설정 파일·템플릿·요청 파라미터 이름에 적어 둘 수 있고, 그 자리를 바꾸면 읽는 값이 바뀐다. 프레임워크가 사용자 코드의 필드를 이름으로 집어 오는 자리마다 이런 표기법이 하나씩 있다 → [[reflective-field-access]]

그래서 OGNL 을 「어떤 라이브러리」로 외우면 놓친다. **「경로 문자열로 객체 안을 가리키는 방식」이라는 갈래**를 알아야, 다른 이름으로 같은 것을 만나도 알아본다.

## 경계와 오해

- **OGNL ≠ [[expression-language]]** — 둘 다 점 표기법으로 객체를 탐색하지만 **서로 다른 명세**다. EL 은 JSP·JSTL 명세의 일부이고 보관소의 값만 읽는 반면, OGNL 은 독립 라이브러리이고 값을 **쓰는 것**과 메서드 호출까지 다룬다
- **문자열 경로는 컴파일러가 검사하지 않는다** — 프로퍼티 이름을 바꾸면 경로가 조용히 깨진다. 리팩터링 도구도 문자열 안까지는 따라가지 않는다 → [[refactoring]]
- **경로가 길수록 `null` 이 끼어들 자리가 늘어난다** — 중간의 어느 객체가 없으면 그 지점에서 끊긴다. 「점 하나」가 「참조 한 번」이다
