# 비밀번호 로그인 다지기 — 해시 · 같은 실패 · 잠금

아이디 + 비밀번호 로그인을 공개 주소에 열 때 최소한 갖출 세 가지. **비밀번호는 느린 해시로만 저장하고, 실패는 이유와 시간이 같게 보이고, 같은 아이디의 연속 실패는 잠근다.** 그리고 로그인 전에 계정이 무엇인지 알려 주는 표면을 없앤다.

## 정의

1. **느린 해시(bcrypt)** — 원문을 저장하지 않는다. 비밀번호 원천이 env/Secret 이면 서버 시작 · 계정 동기화 때 해시하고, **지금 해시와 맞으면 다시 만들지 않는다**(재시작마다 해시가 바뀌지 않게). 비밀번호를 받지 않는 계정은 해시를 지운다 → 로그인 불가
2. **같은 401 · 같은 문구 · 같은 시간** — 없는 아이디 · 비활성 · 해시 없는 계정 · 틀린 비밀번호를 하나의 `invalid_credentials` 로. 없는 아이디도 **가짜 해시로 한 번 비교**해 응답 시간 차이로 존재를 흘리지 않는다
3. **연속 실패 잠금** — 같은 아이디 5회 연속 실패 → 1분 429. 잠금이 풀리면 0부터, 성공하면 실패 수를 지운다
4. **입력 경계** — bcrypt 는 72바이트까지만 본다. 넘는 비밀번호는 틀린 것으로(잘라 비교하면 앞 72바이트만 맞아도 통과)
5. **로그인 전 표면을 센다** — 계정 카드 목록 API 처럼 로그인 전에 부를 수 있는 것은 그 자체로 계정 이름을 흘린다 → API 를 없앤다

## 왜 중요한가

- 「카드를 눌러 바로 들어가는」 PoC 로그인은 주소가 공개되는 순간 누구나 들어온다. 배포 주소가 공개라는 사실이 로그인 강도를 정한다
- 실패 이유를 나누면(「없는 아이디」 / 「틀린 비밀번호」) 공격자가 아이디부터 맞혀 간다. 문구가 같아도 **시간이 다르면** 같은 정보가 샌다

## 경계와 오해

- **메모리 잠금의 한계** — 실패 수를 프로세스 메모리에 두면 재시작하면 사라지고, 파드가 여럿이면 파드마다 따로 센다. PoC(프로세스 1개)라 받아들인 것이다 → [[shared-session-storage]]
- **아이디 단위 잠금은 남의 계정을 잠글 수 있다** — 아이디만 알면 일부러 5번 틀려 1분씩 막을 수 있다. IP 단위 제한 · 점증 지연과 맞바꾸는 문제
- **해시는 비밀번호 강도를 대신하지 않는다** — 약한 비밀번호는 해시해도 사전 공격에 걸린다. 운영 전에 다시 볼 자리
- **인증 ≠ 인가** — 로그인이 되면 무엇이든 할 수 있는 것이 아니다. 역할 검사는 조작 API 마다 → [[delegated-authorization]]
