# SSRF 를 막는 이미지 프록시

외부 문서(메일 HTML)에 박힌 원격 이미지를 브라우저가 직접 불러오지 않게 하고 **우리 서버가 대신 받아 넘기는** 것. 서버가 남의 URL 을 대신 부르는 순간 **SSRF**(서버가 내부망을 부르게 속는 것)의 문이 열리므로, 프록시는 부를 주소를 규칙으로 막는다.

## 정의

1. 문서의 이미지 주소(`src`, CSS `url()`)를 우리 프록시 주소로 바꿔 쓴다
2. 프록시는 대상 호스트를 해석해 **사설·루프백·링크로컬·메타데이터 주소면 거절**한다
3. 리다이렉트를 따라갈 때 **홉마다 다시 검사**한다 — 첫 주소는 공개인데 302 로 내부 주소로 보내는 우회가 있다
4. 이미지 MIME 과 크기 상한만 통과시킨다

## 왜 중요한가

- 브라우저가 원격 이미지를 직접 부르면 보낸 쪽이 **열람 여부·IP** 를 안다(추적 픽셀)
- 프록시를 막 없이 열면 「아무 URL 이나 서버가 대신 불러 준다」가 되어, 내부 관리 페이지·클라우드 메타데이터를 읽는 통로가 된다

## 경계와 오해

- **첫 주소만 검사하면 우회된다** — 리다이렉트 홉마다, 그리고 이름 해석 결과로 검사한다
- **소독기가 지운 것은 프록시가 못 살린다** — HTML 소독기가 배경 이미지·`url()` 을 통째로 지우면 레이아웃이 무너진다. 지우지 말고 `url()` 을 프록시 주소로 **바꿔** 보존했다 → [[output-escaping]]
- **로컬 시험은 루트 인증서 차이로 실패할 수 있다** — 로컬 CA 번들에 루트가 없어 프록시 요청이 TLS 에서 무더기로 실패했다(certifi 번들로 해결). 프록시 결함이 아니라 환경 차이다 → [[dev-prod-parity]]
