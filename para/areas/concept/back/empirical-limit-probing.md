# 외부 한도는 실측으로 — 이분 탐색 − 여유

외부 서비스의 크기 · 개수 한도를 문서의 대략값(「약 8,000토큰」)으로 계산하지 않고, **실제로 보내 보며 통과 · 거절의 경계를 이분 탐색으로 찾은 뒤** 그 값에서 여유를 뺀 것을 기본값으로 쓰는 것. 기본값은 설정으로 빼 두고, 넘으면 무엇부터 줄일지 순서를 함께 정한다.

## 정의

1. **문서값은 단위부터 의심한다** — 「토큰」 한도는 언어 · 토크나이저마다 글자 수가 다르다. 통키는 문서 「8,000토큰(약 1만 자)」으로 계산하자 역방향 용어를 넣은 context(15 ~ 18k자)가 「terms 를 다 빼도 넘는다」 는 결론이 나왔는데, 실제로 보내 보니 6개 언어 전부 통과했다
2. **크기를 키우며 이분 탐색** — 실제 입력이 다 통과하면 경계를 모른다. 같은 모양의 내용을 덧붙여(같은 언어 짝 반복 — 중복만으로는 거절되지 않음을 따로 확인) 크기를 늘리고, 통과 최대치 · 거절 최소치 사이를 좁힌다. 결과: en 25,922 / 26,009 · ja 20,925 / 21,014(가장 작음)
3. **거절이 싸야 탐색이 싸다** — 거절은 오디오 없이 0.41 ~ 0.46초에 왔다. 연결 직후 짧은 창(2초)에서 거절을 판정하면 탐색 한 번이 1초 안이다
4. **기본값 = 변형(언어)별 통과치 × 0.9** — 처음엔 가장 작은 통과치 하나로 모든 언어를 잘랐다(20,925 × 0.9 = 18,832 → 시드 교체 뒤 20,251 → 20,419). 사전이 커지자 한도가 큰 언어가 쓸데없이 잃었다 — zh-Hant 는 역방향 별칭 63개, th 는 `terms` 38개를 버렸다. 언어별로 다시 재서(en 26,027 · ja 22,688 · zh-Hant 24,099 …) **언어별 × 0.9 를 표 한 곳**에 두자 63 → 33 · 38 → 0. 실측 결과는 JSON 으로 남겨 다음에 다시 잴 근거로 둔다
5. **덮어쓰기 설정은 하나로** — env 는 「비면 언어별 표, 값이 있으면 모든 언어를 그 값 하나로」. 언어별 env 를 여럿 두지 않는다. 운영 설정에 값을 넣는 순간 표가 꺼지므로 배포 설정에는 넣지 않는다
6. **넘으면 줄이는 순서를 정해 둔다** — 덜 중요한 것부터: `terms` → 역방향 별칭 → 역방향 기본 → 정방향 별칭. 정방향 기본은 끝까지 남긴다. 그래도 거절되면 정방향만으로 1회 재연결

## 사용 예시

```python
# 통키 back/app/service/interpret/langs.py — 모양만(언어별 통과 최대치 × 0.9 내림)
CONTEXT_MAX_CHARS = {"en": 23_424, "ja": 20_419, "zh": 20_933, "zh-Hant": 21_689,
                     "th": 21_343, "vi": 22_891, "yue": 21_123}

def context_max_chars(lang, override=None):
    return override if override is not None else CONTEXT_MAX_CHARS[lang]   # env 값 = 모든 언어 덮어쓰기
```

## 왜 중요한가

- 문서값으로 계산하면 **안 해도 되는 줄이기**를 설계에 넣는다. 통키는 그 계산대로였다면 역방향 용어(현지명 → 한국어)를 통째로 뺐을 것이다
- 한도를 모르고 꽉 채우면 데이터가 조금 늘어난 날 운영에서 거절된다. 여유(10%)와 줄이는 순서가 그날의 동작을 미리 정한다

## 경계와 오해

- **「통과한 최대 크기 중 가장 작은 값」 은 한도가 아니다** — 실제 입력이 다 통과했다면 그건 입력 크기일 뿐이다. 그 문구대로 쓰면 15,123 × 0.9 = 13,610 이 되어 거절 없이 통과하던 언어에서도 일부러 용어를 뺀다. 한도는 **거절을 실제로 본 경계**다
- **실측값은 시점의 값이다** — 벤더가 예고 없이 바꿀 수 있다. 그래서 하드코딩이 아니라 설정 기본값 + 거절 시 줄이기 · 재연결 경로를 같이 둔다
- **공통 최소값은 안전해 보이지만 손실이다** — 「가장 작은 것에 맞추면 다 통과한다」 는 맞지만, 한도가 큰 언어는 실을 수 있던 것을 버린다. 변형마다 한도가 다르다는 것을 쟀으면 기본값도 변형마다 둔다
- **데이터가 자라면 다시 잰다** — 한도는 그대로여도 입력이 커지면 줄이기가 다시 시작된다(zh-Hant 역방향 별칭 33 은 아직 빠진다). 재측정은 시드 판이 바뀔 때의 할 일이다
- 여유 폭은 데이터 증가 속도로 본다 — 가장 큰 실제 입력(th 17,952)과 기본값 사이가 880자뿐이면 행이 늘 때 그 언어부터 줄기 시작한다
- [[argv-length-limit]] 처럼 **문서화된 고정 한도**는 실측할 필요가 없다. 이 방법은 문서가 대략값만 줄 때다
