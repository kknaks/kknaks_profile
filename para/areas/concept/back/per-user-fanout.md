# 사람별 팬아웃과 접근 확인

이벤트 하나를 **그것을 구독한 사람마다 따로 저장**하는 것(팬아웃). 그리고 구독을 걸 때 **그 사람이 원천에 실제로 접근할 수 있는지를 그 사람의 자격으로 확인**하는 것. 둘이 한 쌍이다.

## 정의

1. 같은 채널을 여럿이 고르면 채널 이벤트 하나가 들어올 때 고른 사람 수만큼 행이 생긴다 — 읽음·보관·삭제가 사람마다 갈리기 때문이다
2. 구독(방 추가)은 **그 사람의 토큰으로** 원천에 접근해 보고 성공할 때만 만든다
3. 이벤트 → 구독 목록 → 사람별 저장 순서. 구독 목록이 곧 권한 목록이다
4. **나가는 쪽도 사람별이다** — 사람별로 저장된 것을 화면에 밀 때도 사람(회원)마다 스트림 하나로 모은다. 사건 종류마다 연결을 따로 열지 않고, 서버는 그 회원 몫의 사건만 그 스트림에 싣는다. 받는 사람을 고르는 판단은 저장 때 끝났으므로 나가는 쪽은 「이 행의 주인이 누구인가」 만 본다 → [[relationship-based-notification]] · [[server-sent-events]]

## 왜 중요한가

팬아웃은 「누가 이 방을 골랐나」만 보고 복제한다. 구독을 만들 때 접근을 확인하지 않으면, 방 ID 만 알면 **남의 DM 방을 골라 그 이벤트를 받아 보는** 길이 생긴다. 이벤트를 받는 연결은 공용이라(앱 하나) 권한 판단은 구독 생성 때 한 번이 전부다.

## 경계와 오해

- **수신 시점이 아니라 구독 시점에 확인한다** — 이벤트마다 상대 API 로 접근을 묻는 것은 비싸고, 공용 연결은 이미 받았다. 대신 구독 생성이 관문이다
- 사람별 저장 ≠ 메시지 원본 중복 걱정 — 원본 내용을 공유 행으로 두고 사람별 상태만 따로 둘 수도 있다. 어느 쪽이든 「사람별로 갈리는 것」이 있으면 팬아웃이다
- 권한이 나중에 회수되는 경우(방에서 나감)는 이 확인으로 안 잡힌다 — 별도 갱신이 필요하다
