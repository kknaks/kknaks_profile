# 보상 트랜잭션 (Compensating Transaction)

**DB 트랜잭션 안에 들어올 수 없는 외부 쓰기를, 실패하면 «되돌리는 쓰기» 로 짝지어 all-or-nothing 처럼 만드는 것.** 롤백이 없는 자리에서 롤백을 흉내 내는 것이 아니라, **되돌리는 행위 자체를 설계의 일부로 만드는 것**이다.

## 정의

```text
[한 트랜잭션]   BEGIN → 쓰기A → 쓰기B → COMMIT/ROLLBACK   ← 외부 API 는 이 안에 못 들어온다
[보상]          외부 쓰기 성공 → 로컬 쓰기(한 트랜잭션) → 실패면 외부를 «취소하는 호출» 로 되돌림
```

순서가 계약이다: **외부가 먼저, 로컬이 나중.** 로컬을 먼저 커밋하면 외부 실패 시 로컬을 지워야 하는데, 이미 커밋된 것을 지우는 것은 또 하나의 실패 지점이다. 외부 성공 → 로컬 한 트랜잭션 → 로컬 실패 시 보상(외부 취소) 순이면 실패 지점이 보상 하나로 모인다.

## 규율

- **보상 대상은 «방금 만든 그 자원 하나»** — 외부가 돌려준 식별자(external id)로 지목한다. 조건으로 재조회해 지우면 **남의 자원을 지울 수 있다.** 재조회 결과가 2건 이상일 때 자동 복구를 포기하는 것과 같은 저울이다.
- **보상도 실패한다 — 그때 원장이 거짓말하면 안 된다.** 외부 쓰기는 실제로 일어났고 지금도 남아 있다. 그것을 «실패» 로 적으면 원장이 「생기지 않았다」고 말하게 된다. 일어난 일은 일어난 대로 적고, 안 된 일(로컬 반영)은 **별도 사실**로 싣는다. 이 계약이 보장하는 것은 「자동으로 되돌린다」가 아니라 **「되돌리지 못하면 그 사실이 보인다」** 다.
- **성공 기록은 체인이 끝난 뒤에** — 외부 쓰기 성공 «시점» 에 성공을 적으면, 뒤 단계 실패 시 «성공 → 실패» 라는 성립하지 않는 전이가 원장에 남는다. 실행 축 기록을 보상까지 끝난 뒤로 미룬다.
- **재시도와는 다른 답이다** — 재시도는 「언젠가 된다」에 걸고, 보상은 「지금 안 되면 되돌린다」에 건다. 사용자가 기다릴 수 없는 동기 흐름(승인 즉시 실행)에는 보상이 맞고, 백그라운드 잡에는 재시도가 맞다.

## 경계와 오해

- **보상은 undo 가 아니다** — 시간이 흐른 뒤의 보상은 그 사이 상태를 밟는다(그 방을 다른 사람이 잡았을 수 있다). 그래서 보상은 **생성 직후 한 자리**로 좁히고, 시간이 지난 뒤의 정리는 별도 표면(사후 취소 게이트)에 맡긴다.
- **보상 실패 건의 상시 탐지(스위퍼)를 반사적으로 만들지 않는다** — 관측이 없는데 만들면 아직 없는 문제에 운영 표면을 하나 더 두는 것이다. 실패가 사실로 표기되고 사람이 그 카드를 본다는 전제로 시작하고, 쌓이면 그때 연다.
