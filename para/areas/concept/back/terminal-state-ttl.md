# 종결 시점 TTL (Terminal-State TTL)

진행 중인 작업의 큐 키에는 만료를 걸지 않고, ack·nack처럼 작업이 끝났다는 사실이 확정되는 시점에만 TTL을 부여하는 키 수명 관리 패턴이다. 재시도로 다시 큐에 들어가는 키는 PERSIST로 TTL을 해제해 처리 도중 만료되지 않게 한다.

## 정의

- 작업이 enqueue 되어 진행 중인 동안은 키에 만료 시간을 두지 않는다.
- 작업이 성공(ack) 또는 최종 실패(nack/DLQ)로 종결되는 시점에만 TTL을 건다.
- 종결된 작업을 재시도로 다시 큐에 넣을 때는 PERSIST로 잔여 TTL을 지워, 처리 중간에 키가 만료되는 일을 막는다.
- DLQ처럼 조사·재시도 여유가 필요한 키는 일반 결과 키보다 TTL을 길게 잡는다.

## 왜 중요한가

큐 키에 처음부터 TTL을 걸면 처리 시간이 긴 작업이 도중에 키를 잃어 상태 추적이 끊긴다. 반대로 TTL을 아예 안 걸면 종결된 키가 무한히 쌓여 메모리를 누수시킨다. 종결 시점에만 TTL을 걸면 두 문제를 동시에 피한다 — 진행 중인 키는 안전하고, 끝난 키는 정리된다.

## 경계와 오해

- **종결 시점 TTL ≠ 캐시 만료** — [[caching]]의 TTL은 "데이터가 stale해지는 시점"을 관리하지만, 이 패턴의 TTL은 "작업이 끝났으니 정리해도 되는 시점"을 관리한다. 목적이 다르다.
- **재시도 시 PERSIST를 빠뜨리면 무효화된다** — 종결 TTL만 걸고 재시도 시 해제를 안 하면, 재큐잉된 작업이 처리 도중 TTL 만료로 상태를 잃을 수 있다. 두 규칙은 항상 짝이어야 한다.
