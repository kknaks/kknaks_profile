# 리틀의 법칙 (Little's Law)

안정 상태 시스템에서 **처리량(λ) = 시스템 내 평균 항목 수(L) ÷ 평균 처리 시간(W)** 이 성립한다는 큐잉 이론의 기본 정리다.

## 정의

원식: `L = λ × W`

- L: 시스템 내 평균 항목 수 (DB 맥락: 평균 활성 커넥션 수)
- λ: 처리량 (TPS)
- W: 평균 체류 시간 (DB 맥락: 평균 쿼리 실행 시간)

DB 커넥션 풀 진단에 변환하면:

```
TPS = 활성 커넥션 수 ÷ 쿼리 실행 시간(초)
```

예: 활성 커넥션 16개, 쿼리 실행 시간 50 ms(0.05 s) → TPS 이론 상한 = 320. 실제 목표는 이론값의 약 80% 수준으로 잡는다.

이 공식은 처리량 증가 경로를 두 가지로 분해한다:

1. **활성 커넥션 수를 늘린다** → 풀 사이즈 확장 (단, [[universal-scalability-law|USL]] 한계 존재)
2. **쿼리 실행 시간을 줄인다** → 쿼리 튜닝, 인덱스, 캐시 → 처리량이 배수로 증가

## 왜 중요한가

처리량이 부족할 때 "풀이 부족하다"와 "쿼리가 느리다"를 구별하는 진단 도구다. 이 구분 없이 풀 사이즈만 늘리면 [[universal-scalability-law]] 법칙에 따라 처리량이 오히려 감소하는 구간에 빠질 수 있다. 활성 커넥션이 이미 DB 코어 × 2에 도달했다면 풀 확장보다 쿼리 실행 시간 단축이 처리량을 배수로 늘린다.

## 경계와 오해

- **리틀의 법칙 ≠ 풀 사이즈 결정 공식** — 처리량 한계를 진단하는 도구다. 적정 풀 사이즈를 계산하는 공식은 [[connection-pool-sizing-formula]]가 별도로 존재한다.
- **안정 상태 전제** — 시스템이 과부하 상태이거나 처리 시간 분산이 크면 정확도가 낮아진다.
- **이론 상한과 실측값은 다르다** — 이론 상한의 약 80%를 실제 TPS 목표로 잡는 것이 일반적이다.
