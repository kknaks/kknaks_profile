# 원격 저장소 (Remote Repository)

호스팅서버 위에 둔 [[git]] 저장소. 내 컴퓨터의 로컬 저장소와 주고받는 상대이고, 여러 사람이 같은 코드를 공유하는 지점이다.

## 정의

로컬과 원격 사이는 세 명령으로 오간다.

| 명령 | 방향 | 하는 일 |
|---|---|---|
| `git clone` | 원격 → 로컬 | 원격 저장소를 내 컴퓨터에 복제해 새로 만든다 |
| `git push` | 로컬 → 원격 | 커밋된 변경을 호스팅서버 저장소에 업로드한다 |
| `git pull` | 원격 → 로컬 | 서버 저장소의 변경 내용을 가져온다 |

주소는 어느 서버의 누구 것인지로 이루어진다.

```bash
$git clone https://github.com/user_name/repo_name
```

- `https://github.com` — 호스팅서버
- `user_name` — 호스팅서버 상의 유저 ID
- `repo_name` — 복제할 레포 이름

### 접근 권한

원격에 쓰려면 내가 누구인지 서버가 알아야 한다. 두 가지가 필요하다.

- **커밋 신원** — `git config` 의 `user.name`·`user.email` 이 호스팅서버 계정과 맞아야 `push` 가 된다
- **인증 수단** — 비밀번호 대신 **토큰**을 만들어 쓴다. GitHub 은 `Settings → Developer settings → Personal access token` 에서 발급하며, 노트·유효기간·접근권한을 정할 수 있다

## 왜 중요한가

**원격 저장소가 협업의 기준점이 된다.** 각자 로컬에서 따로 커밋해도, 서버의 한 저장소를 통해 합쳐지므로 "지금 맞는 코드가 무엇인가"에 답이 생긴다.

그리고 로컬이 아니라 서버에 있다는 것이 **내 컴퓨터가 죽어도 코드가 남는다**는 뜻이다. 버전관리와 원격 저장소는 성격이 다른 두 가지 안전장치다.

## 경계와 오해

- **원격 저장소 ≠ Git** — Git 은 로컬에서 완결되는 버전관리 도구이고, 원격 저장소는 그것을 올려 두는 선택지다. GitHub 없이도 Git 은 돌아간다.
- **`clone` ≠ `pull`** — `clone` 은 없던 저장소를 처음 복제해 오는 것이고, `pull` 은 이미 있는 저장소를 최신화하는 것이다. 한 번 clone 한 뒤로는 pull 을 쓴다.
- **토큰은 비밀번호와 다르다** — 유효기간과 접근권한을 좁힐 수 있어서, 새면 피해 범위가 계정 전체가 아니라 그 토큰에 준 권한까지다. 그래서 비밀번호 대신 쓴다.
