# AI 제품의 방어 가능성 (기술 · 데이터 · 유통)

진입장벽이 낮아진 만큼 경쟁 제품도 쉽게 등장한다. **같은 모델로 비슷한 제품을 만들기 쉽다.** 그래서 무엇으로 차별화할지를 기획 단계에서 정해야 하고, 후보는 셋이다 — 기술력·데이터·유통력.

## 정의

| 축 | 지속성 | 왜 |
| --- | --- | --- |
| 기술력 | 짧다 | 같은 모델을 모두가 API 로 쓴다. 좋은 모델이 나오면 경쟁사도 다음 날 교체한다 |
| 데이터 | 가장 길다 | 모델은 살 수 있어도 제품에서 독자적으로 쌓은 데이터는 살 수 없다 |
| 유통력 | 규모에 비례 | 기존 사용자가 많은 제품에 같은 기능을 붙이면 별도 앱을 쓸 이유가 사라진다 |

- **기술력** — 모델 선택만으로는 차별화가 안 된다. 남는 것은 **평가 체계**(좋은 답의 기준을 알고 있는가), 데이터 파이프라인, 기존 제품과의 결합도다. 선발 주자 우위도 짧다 — 기술 격차로 버는 시간 안에 데이터나 유통에서 우위를 확보해야 한다.
- **데이터** — [[data-flywheel]]이 돌기 시작하면 후발주자는 같은 데이터를 모을 방법이 없다. 다만 보유량과 활용 가능성은 다르다([[ai-ready-data]]).
- **유통력** — 기술과 데이터가 비슷하면 사용자 접점이 승부를 가른다. 구글이 지메일에, MS 가 오피스에 붙이는 순간 경쟁이 끝난다. 그래서 후발·소규모는 **대기업이 진출하지 않은 영역**을 고른다 — 좁은 도메인, 규제가 걸린 업종, 기존 워크플로와의 긴밀한 통합.

## 왜 중요한가

「AI 로 무엇을 만들까」보다 먼저 와야 하는 질문이다. 데모가 쉬워졌다는 것은 **우리 데모도 쉽고 경쟁사 데모도 쉽다**는 뜻이다. 차별화 축을 정하지 않으면 잘 만든 제품이 그대로 복제된다.

평가 체계가 기술력 축에 들어가 있는 점이 눈에 띈다 — 모델이 평준화된 뒤에 남는 기술력은 모델을 다루는 능력이 아니라 **좋은 답의 기준을 아는 것**이다.

## 경계와 오해

- **최신 모델 사용 ≠ 기술 우위** — 같은 API 를 모두가 쓴다.
- **데이터 보유 ≠ 데이터 우위** — 접근·구조·권한이 갖춰져야 쓸 수 있다([[ai-ready-data]]).
- **선발 주자 ≠ 지속 우위** — 버는 것은 시간이지 해자가 아니다.
- **좋은 제품 ≠ 이기는 제품** — 유통 접점이 성능 차를 덮는다.
