# 데이터 플라이휠 (Data Flywheel)

제품을 쓰면 데이터가 쌓이고, 데이터가 쌓이면 모델이 좋아지고, 모델이 좋아지면 제품이 좋아져 더 쓰게 되는 순환이다. 한 바퀴가 다음 바퀴를 키우므로 **시간이 곧 격차**가 된다.

## 정의

```text
제품을 쓴다 → 데이터가 쌓인다 → 모델이 좋아진다 → 제품이 좋아진다 → 더 쓴다
     ↑                                                                  │
     └──────────────────────────────────────────────────────────────────┘
```

돌기 시작하면 후발주자는 같은 데이터를 모을 방법이 없다. 모델은 살 수 있어도 **제품에서 독자적으로 쌓은 데이터는 살 수 없기** 때문이다([[ai-product-defensibility]]).

돌리려면 세 가지가 필요하다.

1. **수집 장치** — 인터페이스가 곧 데이터 수집기다. 긍정/부정 평가, 채택 여부, 수정 이력이 다음 개선의 재료가 된다.
2. **반영 경로** — 모은 것을 평가 셋·프롬프트·파인튜닝 데이터로 되돌리는 절차([[golden-set-regression]]).
3. **정당한 사용 근거** — 동의·라이선스·개인정보 처리 근거. 없으면 쌓아 둔 것을 나중에 통째로 못 쓴다.

## 왜 중요한가

AI 제품에서 **인터페이스가 기능이자 계측기**라는 설계 관점이 여기서 나온다. 수정 기능과 피드백 버튼은 사용자 편의로만 보이지만, 그것이 없으면 플라이휠에 넣을 데이터가 아예 생기지 않는다.

반대로 플라이휠이 도는 척만 하는 경우도 흔하다. 로그는 쌓이는데 반영 경로가 없으면 그냥 저장 비용이다.

## 경계와 오해

- **데이터가 쌓인다 ≠ 플라이휠이 돈다** — 모델·제품으로 되돌아가는 경로가 있어야 순환이다.
- **사용량 증가 ≠ 유효 데이터 증가** — 라벨이 되는 신호(채택·수정·평가)가 섞여야 한다.
- **플라이휠 ≠ 자동** — 수집·정제·반영은 사람이 세우는 파이프라인이다([[ai-ready-data]]).
- **수집 가능 ≠ 사용 가능** — 동의와 라이선스가 사후에 문제가 된다([[silent-model-degradation]]).
