# areas/

## 1. 개요

**정의**
- 지속되는 것이 사는 자리. 내가 누구이고 무엇을 아는가를 담는다.
- 쌓아 두는 것이 아니라 **다음 판단의 근거로 꺼내 쓰는 것**이다.

**특징**
- 지속성 : 시작도 끝도 없다. 계속 남는다.
- 성장성 : 새 출처가 합류할 때마다 두꺼워진다. 새 파일을 만들지 않고 기존 노트를 보강한다.

**구조**

```text
para/areas/
├── personal/     내가 누구인가
│   ├── company/
│   └── summer-star/
└── concept/      내가 무엇을 아는가
    └── cs · back · db · front · ai · infra · design · pm · qa
```

---

## 2. personal/

**무엇**
- 회사와 여름별컴퍼니에서의 내 자리, 그리고 그 변천.

**하위**

| 디렉토리 | 담는 것 |
| --- | --- |
| `company/` | 회사에서의 나 — 조직 · 팀 · 내 역할 |
| `summer-star/` | 여름별컴퍼니에서의 나 — 사업체 운영 · 방향 |

**SoT 는 DB 다.** 여기 md 는 원장이 아니다. 시드 데이터를 넣고 나서 무엇이 md 로 남을지 다시 본다.

## 3. concept/

**무엇**
- 내가 정리한 개념 노트. 아홉 영역으로 나뉜다.

### 3.1 아홉 영역

| 영역 | 담는 것 |
| --- | --- |
| `cs` | 스택 무관한 기초 — 자료구조 · 알고리즘 · 네트워크 · OS, 그리고 소프트웨어 설계 |
| `back` | 서버 — 언어 · 런타임 · 프레임워크 · API, 그리고 코드가 DB 를 다루는 것 |
| `db` | 데이터베이스 자체 — SQL · 모델링 · 엔진 |
| `infra` | 서버 · 빌드 · 배포 · 형상관리 |
| `ai` | 모델 · 에이전트 · 프롬프트 · 평가 |
| `front` | 화면 — 브라우저 · UI 구현 · 클라이언트 |
| `pm` | 제품 · 기획 — 요구 정의 · 우선순위 · 지표 |
| `qa` | 품질 — 테스트 전략 · 검증 · 회귀 |
| `design` | UI/UX — 화면 설계 · 인터랙션 · 디자인 시스템 · 접근성 |

### 3.2 어느 영역인가

| 경계 | 선 |
| --- | --- |
| `cs` ↔ `back` | 개념이 **언어를 바꿔도 남으면** `cs`. 필기가 자바로 쓰여 있다는 것은 근거가 아니다 |
| `db` ↔ `back` | **DB 를 안 바꾸고 프레임워크만 바꿔도 그대로면** `db`. 순수 SQL 과 엔진만 `db` |
| `infra` ↔ `back` | 서버 · 빌드 · 배포 · 형상관리면 `infra` |
| `design` ↔ `front` | 무엇을 어떻게 **보이게 할지**는 `design`, 그걸 **코드로 만드는 것**은 `front` |

`design` 은 UI/UX 뿐이다. 이름에 「패턴」이나 「설계」가 붙어도 화면 얘기가 아니면
`design` 이 아니다. GoF 패턴은 소프트웨어 설계라 `cs` 다.

**두 영역에 걸리면 주 영역 하나에 두고 다른 쪽에서 링크한다.** 사본을 만들지 않는다.

**애매한 것이 나오면 예외를 추가하지 말고 위 기준을 고친다.** 예외 목록을 만들면
기준이 아니라 목록을 외우게 되고, 목록은 늘어나기만 한다.

### 3.3 규약

만드는 순서대로 적는다.

- **먼저 찾는다.** 3.4 맵의 파일명과 내용을 훑는다. 한국어나 약어로 부르는 개념은
  영문 stem 에 안 걸리므로 개념 파일의 `aliases` 를 함께 본다.
  `grep -rn "aliases:" -A6 para/areas/concept/`
- **이미 있으면 새 파일을 만들지 않는다.** `up:` 과 본문 `[[]]` 에 출처를 더하고,
  더해진 내용을 본문에 녹인다. 새 이름으로 불렸다면 `aliases` 에도 더한다.
- **`up:` 이 필수다.** 출처 없는 개념은 성립하지 않는다. 출처가 정말 없다면 그건 개념이 아니다.
- **파일명은 영문 kebab-case 다.** `connection-pool-sizing-formula` 처럼 쓴다.
  한국어 · 대문자 · 날짜를 넣지 않는다. 개념은 시점에 묶이지 않는다.
- **stem 을 바꾸지 않는다.** 링크가 전부 stem 기반이다.
- **다 쓰면 3.4 맵에 한 줄 더한다.**
- **공개 표면에 뜨지 않는다.** DB 에 `concept` 표가 없다. 내가 쓰려고 쌓는 것이다.

양식은 `templates/concept.md`.

## 4. 미결

- **`personal/` 이 갖는 문서의 종류** — SoT 가 DB 라 시드 데이터 이후에 정한다.
- **이력서 · 포트폴리오가 `personal/` 에 오나** — 발행물의 자리를 아직 안 정했다.
- **갈래를 폴더로 내릴 기준** — 한 갈래가 얼마나 두꺼워지면 하위 영역으로 가를지 안 정했다.
- **`design` 이 계속 비어 있으면** — 지울지 둘지.
