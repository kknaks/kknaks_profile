# 백엔드 개발자 · 퀀터스

`2025.08 — 2026.02` · 퇴임 · 서울
스택 — Python · FastAPI · MySQL · Redis · RabbitMQ · WebSocket · ELK · Airflow · LangGraph · AWS · Azure

## 역할

퀀터스에서 백엔드 개발자로, 퀀트 트레이딩 앱의 데이터 파이프라인을 맡았다.

**실시간 시세 파이프라인** — 대표 ETF 60종의 시세를 웹소켓 스트림으로 수집해 자동트레이딩 서버에 전달했다. 하트비트 헬스체크와 서킷브레이커(장애 시 10초 폴링 폴백·자동 복귀), RabbitMQ 메시징, Redis master/slave 복제로 안전장치를 겹쳐 실서비스 6개월 무장애로 운영했다.

**Insight(뉴스·공시)** — 한국·미국 뉴스·공시를 Airflow 로 1시간 주기 수집(하루 약 4천 건)하고, LangGraph 파이프라인이 티커 판별→요약→한↔영 번역을 맡았다. 조회 병목은 MySQL 동기 접근을 Elasticsearch 비동기 검색으로 전환해 풀었다 — k6 실측 고부하 처리량 3.2배·평균 응답 68% 단축. AWS RDS → Azure MySQL 800GB 무중단 이관(DMS·CDC)도 수행했다.

## 해결한 문제

- **고부하에서 무너지던 뉴스·공시 조회 — Elasticsearch 전환으로 처리량 3.2배**

관심 그룹 뉴스·공시 조회가 고부하에서 worker timeout 으로 무너졌다. 원인은 하나가 아니었다 — 인덱스 부재, 국가별 중복 쿼리(호출 3회), 메모리 레벨 페이지네이션, 동기 블로킹이 겹쳐 있었다.

조회 표면을 MySQL 동기 접근에서 Elasticsearch 비동기 검색으로 옮기고(원장-인덱스 분리, Logstash 동기화), 집계 쿼리로 호출을 3회→1회로 접었다. k6 로 전환 전후를 같은 조건에서 실측 — 고부하(300 VUs) 처리량 3.2배(RPS 25.7→81.2), 평균 응답 68% 단축(5,173→1,637ms), P95 57% 개선, worker timeout 해소.

- **장 중 시세 공급이 끊기면 안 된다 — 서킷브레이커 자동 복구 설계**

자동트레이딩의 입력인 실시간 시세는 장 중에 끊기면 트레이딩 서버가 낡은 가격으로 판단하게 된다.

웹소켓 스트림에 하트비트 헬스체크를 붙이고, 장애를 감지하면 서킷을 열어 10초 간격 폴링으로 전환·정상화가 확인되면 자동으로 웹소켓에 복귀하는 구조를 설계했다. 전달은 RabbitMQ 큐, 저장은 Redis master/slave 복제로 안전장치를 겹쳤다 — 실서비스 6개월 동안 장 중 데이터 공백 0회.

- **800GB DB 를 세우지 않고 옮기기 — CDC 기반 무중단 클라우드 이관**

회사의 클라우드 계약 변경으로 주가·뉴스 데이터 800GB DB 를 AWS RDS 에서 Azure MySQL 로 옮겨야 했다.

dump→load · DMS · dual write 세 방안을 중단 시간·데이터 손실·비용으로 비교해 Azure DMS 를 선택했다. MySQL binlog 기반 CDC 로 실시간 복제를 걸어 두고 복제가 따라잡은 시점에 접속만 전환 — 다운타임 없이 이관을 마쳤다.
