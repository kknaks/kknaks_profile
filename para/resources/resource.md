# resources/

## 1. 개요

**정의**
- 밖에서 들어온 자료와, 내가 쓰고 다시 고치지 않는 글.

**특징**
- 불변성 : **쓰고 나면 고치지 않는다.** 박제다. 그 자료가 한 말은 변하지 않는다.
  계속 자라는 것은 여기가 아니라 `areas/concept/` 다.
- 출처 분류 : `areas/` 는 주제로 나누지만 여기는 **어디서 왔나**로 나눈다.
  들어오는 경로마다 다루는 방식이 다르다 — 영상은 자막, 기사는 본문, 세션은 현장 노트.

**구조**

```text
para/resources/
├── note/          내가 쓴 글 — 필기 · 정리 · 실무 기록
├── youtube/       영상 교안 (C-NNN)
├── algorithms/    매일 자동으로 쌓이는 알고리즘 풀이 (A-NNN)
├── docs/          공식 문서 · 스펙 · 논문
├── book/          책
├── article/       뉴스 · 언론 기사
├── blog/          개인 · 회사 블로그 · 쓰레드 · SNS
└── session/       컨퍼런스 · 밋업 · 개발 세션
```

`article` 과 `blog` 를 나누는 이유는 **읽는 법과 믿는 정도가 다르기** 때문이다 —
기사는 사실 전달, 블로그 · 쓰레드는 개인 경험과 주장.

**여기가 `areas/concept/` 의 재료다.** 자료를 읽거나 글을 쓰면서 알게 된 것이 개념으로
올라가고, 개념의 `up:` 이 이 층의 stem 을 가리킨다. 자료는 그 자리에 남고 개념만 자란다.

---

## 2. note/

**무엇**
- 내가 쓴 글. 학습 필기 · 코딩테스트 풀이 · 실무 기록.
- 출처가 남의 자료일 필요 없다 — **겪은 일도 출처다.** 실무 기록에서 개념이 자란다.

**하위** — 과정 · 주제로 나눈다.

| 디렉토리 | 담는 것 |
| --- | --- |
| `bitcamp/` | 비트캠프 부트캠프 필기 — Day01~ (2024-05 ~ 2024-10) |
| `likelion/` | 멋쟁이사자처럼 백엔드스쿨 필기 — Day01~ 재시작 (2024-12 ~ 2025-02) |
| `codingtest/` | 코딩테스트 풀이 — Pr/pr. 알고리즘 기법 개념들의 출처 |
| `network/` | 네트워크 교재 정리 — chapter |
| `db/` | DB 실무 기록 — 마이그레이션 |
| `elk/` | 검색 · 성능 실무 기록 |
| `monitoring/` | 모니터링 · 측정 기록 |
| `backend/` | 서버 설계 기록 — 동기/비동기 · 멱등성 |

Day 파일이 두 계열이다 — **2024-12-30 에 Day01 이 다시 시작**한다. 파일명이 아니라
날짜와 폴더로 가른다.

**DB** — 공개할 글만 어드민에서 `note` 행으로 등록한다. 모든 글이 자동으로 뜨지 않는다.

## 3. youtube/

**무엇**
- 영상 하나 = 교안 하나(`C-NNN-<slug>.md`). 영상을 안 보고도 이 문서만으로 학습할 수 있게 쓴다.
- **유튜브 개념의 출처층이다.** 유튜브에서 자란 개념의 `up:` 이 C-NNN stem 을 가리킨다.

**DB** — `content` 표의 씨드다. frontmatter(`id` · `title` · `summary` · `youtubeId` ·
`duration` · `speaker` · `tags` · `date`)가 컬럼으로 들어가고 파일 경로가 `detail_path` 가 된다.

**파이프라인 상태를 frontmatter 에 두지 않는다.** 처리 상태는 DB `queue` 가 갖는다.

양식은 `templates/resources/youtube.md`.

---

## 4. algorithms/

**무엇**
- 매일 스케줄러가 문제 하나를 만들어 커밋한다(`A-NNN-<slug>.md`). 승인도 검증도 없다.
- **개념으로 올리지 않는다** — 매일 자동으로 도는 것이라 잡음이 쌓인다.
  풀면서 알게 된 것이 있으면 `note/` 에 따로 쓴다.

**DB** — `algorithm` 표의 씨드. `today` 는 한 번에 하나 — 새 문제를 박으면서 어제 것을
같은 커밋에서 내린다.

---

## 5. 비어 있는 것 — docs · book · article · blog · session

자료 캡처(어드민 모달 → `queue` → 게이트 승인)의 도착지다. 승인 시점에 md 가 생긴다.

`book` 과 `session` 은 v1 에서 로직 없이 버튼만 둔다 — 가져올 원문이 없어서 메모와
현장 노트가 유일한 입력이다.

---

## 6. 규약

- **쓰고 나면 고치지 않는다.** 자료에 새로 배운 것이 생기면 이 파일이 아니라
  `areas/concept/` 의 개념을 보강한다.
- **개념을 재서술하지 않는다.** 자료 노트는 요지만 갖고 상세는 `[[개념 stem]]` 으로
  위임한다 — 상세의 SoT 는 개념 노트다.
- **파이프라인 상태를 frontmatter 에 두지 않는다.** 옛 구조의 `status: pending` 문제.
  상태는 DB 가 갖는다.
- **stem 을 바꾸지 않는다.** 개념의 `up:` 이 여기 stem 을 가리킨다.

회사 회의록은 여기 두지 않는다. 밖에서 들어온 자료가 아니라 내 일이라
`areas/personal/company/` 다.

---

## 7. 미결

- **note 신규 글이 어느 하위로 가나** — 지금 여덟 폴더는 이관하면서 생긴 것이다.
  새 주제가 오면 폴더를 만들지, 몇 건부터 가르는지 안 정했다.
- **`docs` · `article` · `blog` 의 양식** — 캡처 파이프라인(케이스 1)을 만들 때 정한다.
- **`book` · `session` 캡처 로직** — v1 은 버튼만.
