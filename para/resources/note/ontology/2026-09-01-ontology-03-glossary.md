# 온톨로지 실행 기록 03 — 용어 정의

이 문서는 [[2026-09-01-ontology-01-roadmap|기록 01]]의 「03 용어 정의」 스텝이 정의한
산출물 — 용어 판정 표 — 이다. [[2026-09-01-ontology-02-research|기록 02]]가 넘긴 질문
8건에 대해 담당자 확인을 받았고, 그 답을 종결(확정)과 대기로 갈라 여기에 판정으로
박제한다. 8건 중 7건이 종결됐고, 유기 신호의 시간 단위 1건만 대기로 남는다. 1차
시도에서 이미 확정된 판정은 재결정하지 않고 승계하며, 승계 근거를 각 항목에 명시한다.
본문의 모든 수치는 브론즈 원본(`reference/ontology_demo/`)에 대해 이 스텝에서 명령으로
재검증한 값이다. 계층 개념은 [[medallion-architecture]] 에 위임한다.

## 1. 용어 판정 표

상태는 세 가지다 — **확정**(오늘 담당자 확인으로 종결), **승계**(1차 시도 판정을 재결정
없이 이어받음), **대기**(가정·영향 범위를 명시하고 04 이후로 미룸).

| 용어 | 정의 (계산식) | 데이터 근거 (재검증값) | 상태 |
| --- | --- | --- | --- |
| 매출 | `sales` 합계. 청구·발생액 기준이 정본이다 | `sales` 비0 5,429행 중 내원 5,428 · 취소 1 · 부도 0 — 결제 발생은 사실상 내원에 종속 | 확정 |
| 수납 | `receipt` 합계. KPI 정본이 아니며 실버에 보존만 한다 | `sales`≠`receipt` 22행(내원 21 · 취소 1). 그중 20행이 `sales`>`receipt` — 미수로 해석. 나머지 2행은 `receipt`>`sales`(수납 선행)로, 미수 해석의 예외이나 KPI 정본이 `sales` 이므로 집계에는 영향 없다 | 확정 |

| 시술 개념(ProcedureConcept) | nexus 강남 생존(미삭제) 루트 카테고리 13종의 폐쇄 목록(2장). 리뷰 라벨은 개념으로 롤업하고 부위는 보조 속성으로만 보존 | 강남(branch 2) 루트 24건 중 미삭제 13건 — 목록·id 는 2장 표 | 확정 |

| 개입 신호 (네이버 리뷰 수) | 마케팅 리뷰 확보 전략의 산출물 — 개입 변수로 취급. 유기 신호와 합산 금지 | 네이버 1,448건(2026-03-21 이후만 존재) — 담당자 확인 완료 | 승계 (1차 판정 + 담당자 확인) |

| 결측일 처리 | 결측일은 0으로 채우지 않고 행 자체를 만들지 않는다 | 결측일 2026-02-17 하루뿐(236일 중 235일 존재) 재확인 | 승계 (1차 판정) |
| 리뷰 예상 평점 | LLM 이 본문 텍스트만 보고 0.5~5점(0.5 단위)의 예상 평점을 매기고 근거 문장을 함께 남긴다. 플랫폼 불문 동일 척도 — 평점 없는 네이버에 강남언니와 같은 자를 대는 장치다. 내용이 없어 채점이 성립하지 않는 건은 점수 없이 **판정불가** | 강남언니 실제 평점과 대조해 채점기를 검증(±0.5 이내 정합 기준). 리뷰 본문 길이 최소 4자 — 초단문 존재 | 확정 |
| 리뷰 감성 | 예상 평점을 임계값으로 분류한다 — **≥4 긍정 / 3~3.5 중립 / ≤2.5 부정**, 채점 불가 건은 **판정불가**. 중립과 판정불가를 합치지 않는다 — 중립 신호의 순도 유지 | 강남언니 분포로 임계값 확정: ≥4점 90.9% / 3~3.5점 6.6%(혼합 톤 실례 확인) / ≤2.5점 2.5%. 부정 구간 표본 13건 — 검증셋이 얇다는 한계 명시 | 확정 |
| 평점의 지위 | 강남언니 실제 평점(0.5~5)은 감성의 정답이 아니라 **검증 게이트**다. LLM 예상 평점과의 정합률을 재고, 큰 불일치 건만 예외 큐로 사람이 검토한다(평점 오기 탐지 포함 — 0.5점인데 본문이 명백히 긍정인 실례 존재). 네이버 채점의 신뢰도는 강남언니 정합률로 추정한다 | 평점은 강남언니 514건에만 존재, 네이버 1,448건은 전부 공란(기록 02) | 확정 |
| 재방문 전환율 (60일) | 월 신환 코호트 중 **첫 내원 후 60일 안에 재진이 1회 이상 발생한 비율**. 코호트 = 해당 월 신환이면서 `chartNo` 가 있는 환자(미식별 그룹 제외). **관찰 기간 60일이 확보되지 않은 코호트는 판정에서 제외하거나 부분 표지를 단다** — 관찰 창 편향으로 하락을 과장하지 않기 위함. 개정 3에 따라 **외국인 추정 여부로 분해**해 병기한다 — 재방문하지 않는 외국인 신환의 구성 변화가 하락을 가장하는지 판별하기 위함 | 06 탐색에서 승격(2026-09-01 개정, 담당자 승인). 60일 고정 창 기준 1월 코호트 74% → 6월 35% 하락이 승격 계기 | 확정 (개정 2·3) |
| 외국인 추정 | `patientName` 에 로마자(A~Z)가 1자 이상 포함된 예약 행을 **외국인 추정**으로 표지한다(`is_foreign_est`). **추정이다** — 영문 표기 내국인·교포가 섞일 수 있고, 국적 원천 컬럼은 존재하지 않는다. 판정은 브론즈에서 수행하고 실버에는 **플래그만 반입**한다(실명 미반입 원칙 유지 — 3장 PII 규칙과 충돌 없음). 비정형 전화번호(1,355행)는 보조 참고 신호로만 두고 판정 기준에 넣지 않는다 | 로마자 이름: 예약 1,701행 · 환자 1,010명(9.7%) · 결제 내원 821건 · 건당 평균 183만 원(한글 이름 24만 원의 7.5배) · 고액(100만+) 매출의 83% · 월 매출 비중 1월 29% → 5월 이후 68~73% · 내원의 82%가 신환 | 확정 (개정 3 — 2026-09-01, 담당자 승인) |

수납 항목의 부기 — 「22행 미수 해석」은 담당자 확정이고, 재검증에서 드러난 구성
(20행 미수 방향 + 2행 수납 선행)은 실버의 미수 플래그를 달 때 방향 컬럼으로 함께
보존한다. KPI 정본이 `sales` 인 이상 어느 쪽도 매출 집계를 바꾸지 않는다.

## 2. 시술 개념 폐쇄 목록 — 13종

정본은 nexus `categories` 에서 강남(branch 2) · 루트(parent 없음) · 미삭제(`deleted_at`
공란) 조건을 만족하는 13건이다. 재검증 결과 강남 루트 24건 중 정확히 13건이 생존한다.

**계층 해석의 주의** — 카테고리 2단은 부위가 아니라 장비·라인 구분이다(제모 아래
아포지플러스 · 젠틀맥스 프로플러스 · 아발란체 등, 재검증 확인). 부위 정보는 SKU 명에만
있다. 따라서 리뷰의 시술 라벨은 개념 13종으로 롤업하고, 부위는 보조 속성으로만
보존한다.

**리뷰 라벨 롤업의 근거** — 강남언니 514건 전건에 `[시술: X]` 태그가 있고, 라벨 문자열
14종 · 복합 표기를 풀면 단일 시술 12종이다(최다 라벨 「턱제모」 274건). 12종 전부가
13종 중 세 개념으로 떨어진다 — 제모 계열 10종(턱·인중·얼굴·볼·겨드랑이·팔·손가락·
종아리·브라질리언·손등) → **제모**, 잇몸보톡스 → **보톡스**, 입꼬리필러 → **필러**.
목록 밖으로 새는 라벨은 0건이다.

**폐쇄 목록 원칙** — 13종 밖 개념 태그는 금지한다. 추가가 필요하면 제안만 하고 사람이
승인한 뒤 목록을 갱신한다(1차 폐기 원인 2 — 키워드 규칙 시술 사전 — 의 재발 방지).

## 3. PII 반입 규칙 — 기록 02 게이트 3 종결

[[2026-09-01-ontology-02-research|기록 02]] 게이트 3의 제안이 담당자 확인으로
확정됐다. 제안과 달라진 것은 `chartNo` 하나다 — 솔트 해시 제안을 기각하고 그대로
반입한다(내부 데모 범위에서 재식별 위험보다 조인·검증 추적성을 우선한다는 판단).

| 필드 | 실버 반입 처리 | 근거 (재검증값) |
| --- | --- | --- |
| `patientName` | **미반입** | 전 행 존재 — 실명은 하위 층에 내리지 않는다 |
| `phone` | **미반입** | 빈 값 7행 제외 전 행 존재 |
| `chartNo` | **그대로 반입** (해시하지 않음) | 빈 문자열 1,456행은 「환자 미식별」 그룹, 동명이인 차트 45건은 장부 오기로 판정 — 1장 환자 식별 항목 |
| `birthday` | **연령대로 축약** | 결측 1,160행은 「미상」 처리 |

## 6. 다음 스텝(04 실버 빌드)으로 넘기는 것

이 문서는 용어만 확정했다. 실버 설계 자체는 04의 일이며, 아래가 04의 입력이다.

1. **리뷰 전처리 명세** — 순서는 직원 실명 마스킹 → 구조 파싱(태그·섹션) → LLM 채점
   (예상 평점 0.5~5 + 근거 문장 + 개념 13종 롤업 + 부위 보조 속성) → 강남언니 실제
   평점과 대조해 채점기 검증(±0.5 정합률, 큰 불일치는 예외 큐) → 검증된 채점기를 전체에
   적용해 임계값 분류(≥4 긍정 / 3~3.5 중립 / ≤2.5 부정 / 판정불가) → System 검증(점수
   범위·0.5 단위, 폐쇄 목록 밖 0건, 근거 문장 본문 실존) → 예외만 사람 검토.
   S-002 방식(AI 추출 · System 규칙 검증 · 사람은 예외만)이며 구체 명세는 04에서
   작성한다. 이 결과가 나와야 대기 항목 1(유기 신호 단위)을 판정할 수 있다.
2. **중복 제거 키 정의** — 모든 필드 완전 동일 행만 제거하며 `staff` 를 키에 포함한다
   (1장 담당자 축 판정). 제거 건수·표본을 빌드 로그로 남긴다.
3. **지점 alias 매핑 테이블** — 표기 4종 → `CERAMIQUE-GN-001` 정본 매핑.
4. **파생 컬럼 규칙** — 연령대 축약(결측 미상), 매출 예외 플래그(취소 & `sales` 비0),
   미수 플래그(`sales`≠`receipt`, 방향 포함), 신환/재진/신규 이탈 판정 컬럼.
5. **보존 전용 컬럼** — `receipt`, `staff` 는 KPI 에 쓰지 않지만 실버에 보존한다.
