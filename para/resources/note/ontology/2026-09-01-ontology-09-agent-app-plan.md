# 온톨로지 실행 기록 09 — 데모 에이전트 앱 구축 계획

[[2026-09-01-ontology-01-roadmap|로드맵]] 완주 후의 구축 단계다. 스펙의 원천은 둘 —
동작은 [[2026-09-01-ontology-08-agent|기록 08]](현황 = View 조회 / 원인 = 전제 검증
후 엣지 역추적), 데이터는 [[2026-09-01-ontology-07-meta|기록 07]]의 nodes 25 ·
edges 27 과 골드 4테이블이다. 화면 스펙은 모니터링 미리보기 HTML(로컬
`reports/2026-09-01-모니터링-미리보기.html`)이 목업으로 확정돼 있다.

## 1. 아키텍처 결정 (2026-09-01 합의)

| 결정 | 내용 | 근거 |
| --- | --- | --- |
| **DB-only, 업로드 없음** | 실버·골드·온톨로지 산출물만 SQLite 에 적재. 웹에서 raw 업로드를 받지 않는다 | 업로드 = 게이트 없는 적재의 문. 수집 파이프라인(대행사 보고서·페북 등)은 다음 단계 |
| Agent 는 판단만 | 집계는 DB View, 관계는 edges 조회. 관계 지식을 프롬프트에 넣지 않는다 | S-001·S-002, 기록 08 검증 명제 |
| 한 화면 | ① KPI 카드(7일 빈도 상태) ② 원인 분석 그래프 ③ 예보 ④ AI 채팅 — 채팅 답변이 밟은 엣지를 그래프에 하이라이트 | 미리보기 목업 · 아모레 SCI BI 대응 |
| 코드 위치 | `app/ontology-agent/` (레포 구조상 코드는 app/). DB 파일·데이터는 로컬 생성(gitignore 유지 — PII 정책) | agents.md 루트 계약 |
| 갱신 주기 | 일 1회 (원천이 일 배치 — 23:30 적재). "실시간" 표방 금지 | 기록 02 manifest 실사 |

## 2. 구현 순서 (2026-09-02)

1. **DB 적재** — `load_db.py`: reference/ontology_demo 의 골드 4 + nodes/edges +
   silver_reservations(드릴다운용) → SQLite. 게이트: 행수 대사(테이블별 CSV 행수 =
   DB 행수), 엣지 참조 무결성(고아 0).
2. **조회 도구 3종** — Agent 에게 주는 손 전부:
   - `query_kpi(sql)` — 골드 대상 read-only SELECT (화이트리스트 테이블만)
   - `trace_ontology(node_id, direction)` — 들어오는/나가는 엣지 반환.
     **채택·산출·보류·기각을 구분해 반환** — 기각 사유도 답변 재료다
   - `get_definition(용어)` — 글로서리 판정 표 조회
3. **그래프 뷰** — nodes/edges 렌더(미리보기 SVG 레이아웃 승계 또는 cytoscape.js).
   노드 색 = 최근 7일 빈도 상태(알림 ≥3일 / 관찰 ≥1일 / 정상). 노드 클릭 → KPI 시계열.
4. **에이전트 루프** — 시스템 프롬프트는 기록 08 스펙 그대로: 전제 검증 먼저, 엣지
   역추적, 수치는 View 역추적 가능하게 인용. **응답 스키마에 `used_edges` 필수** —
   그래프 하이라이트의 입력. LLM 호출 경로는 착수 시 결정: ADR-04(open-kknaks 경유)
   적용 여부 확인이 첫 작업.
5. **예보 규칙** — 미리보기의 2규칙을 코드로: 취소율 7일 중 3일 주의/경고 → 예약 하강
   경보, 강남언니 4주 합계 ≤3건 → 2주 후 신환 위험. 규칙은 엣지에 근거를 링크한다.
6. **웹 통합** — FastAPI + 단일 페이지(또는 Streamlit — 착수 시 결정). 답변 옆
   근거 패널(사용 쿼리·엣지).
7. **회귀 테스트** — 기록 08 시나리오 2본을 자동화: ① "최근 4주 노쇼율 추이"(View
   단독) ② "8월 매출이 왜 떨어졌어"(전제 교정 + 엣지 4개 사용 확인). 추가 검사:
   응답의 `used_edges` ⊆ edges.csv 확정 행, 인용 수치 = DB 재조회 일치.

## 3. 게이트

| # | 게이트 | 기준 |
| --- | --- | --- |
| 1 | 적재 대사 | CSV = DB 행수 오차 0, 엣지 고아 0 |
| 2 | 회귀 2본 | 기록 08 두 시나리오 통과 — 특히 ②에서 전제 교정("매출은 +27%")이 나올 것 |
| 3 | 근거 무결성 | 답변의 수치가 DB 재조회와 일치, used_edges 가 전부 확정 엣지(기각 엣지는 배제 근거 인용만) |
| 4 | 하이라이트 일치 | 그래프에 불 들어온 경로 = used_edges |

## 4. 범위 밖 (이번에 안 하는 것)

raw 업로드·수집 파이프라인(대행사 보고서·페이스북 — 수집 과제 큐), 실버·골드 재빌드
자동화, 알림 발송(슬랙 등), 다지점 확장. 전부 데모 검증 후의 일이다.
