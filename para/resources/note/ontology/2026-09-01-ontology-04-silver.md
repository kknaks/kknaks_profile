# 온톨로지 실행 기록 04 — 실버 빌드

이 문서는 [[2026-09-01-ontology-01-roadmap|기록 01]]의 「04 실버 빌드」 스텝의
명세이자 빌드 기록이다. 1~7장이 빌드 전에 확인받은 명세이고, 7장의 승인 필요 결정
4건이 담당자 승인으로 확정된 뒤 빌드를 실행했다. 빌드 결과와 게이트 판정은 말미
두 섹션에 있다.

모든 변환 규칙의 단일 원천은 [[2026-09-01-ontology-03-glossary|기록 03 글로서리]]다.
각 규칙에 글로서리의 어느 항목에서 왔는지를 근거로 달고, 글로서리에 없는 규칙은 만들지
않는다. 소스 사실(스키마·행수·이상 징후)은 [[2026-09-01-ontology-02-research|기록 02]]
의 실사값을 따른다.

## 1. 입출력 개요

- **입력** — 브론즈 원본 3종: `bronze/vegas/*.json`(78,216행), `bronze/nexus/*.csv`
  (14개), 루트 리뷰 CSV(1,962행). 브론즈는 불변으로 보존하며 읽기만 한다.
- **출력** — `reference/ontology_demo/silver/` 아래 CSV 4종
  (`silver_reservations` · `silver_reviews` · `silver_catalog` · `silver_promotions`)
  과 부속 매핑 CSV(`silver_branch_alias`), 그리고 빌드 로그(제거·제외 건수와 표본).
- **실행 코드** — `reference/ontology_demo/scripts/` 아래에 둘 것을 제안한다
  (7장 승인 항목 3). LLM 호출 경로는 7장 승인 항목 4의 확인 결과를 따른다.

## 2. silver_reservations — 예약·내원 행 (vegas 78,216행 기원)

### 2.1 컬럼 명세

| 컬럼 | 생성 규칙 | 글로서리 근거 |
| --- | --- | --- |
| `branch_code` | `branch` 표기(`세라미크의원 강남`)를 alias 매핑으로 `CERAMIQUE-GN-001` 로 치환한다 | 1장 지점(정본 = `branches.branch_id` 코드) · 6장 3항 |
| `resv_date` | `resvDate`(`YYYYMMDD`)를 `YYYY-MM-DD` 로 형식만 표준화한다 | 값 변환 없음 — 형식 표준화 |
| `chart_no` | `chartNo` 그대로 반입한다(해시하지 않음) | 3장 PII 반입 규칙 |
| `unidentified_flag` | `chart_no` 빈 문자열이면 참 — 「환자 미식별」 그룹(1,456행 예상) | 1장 환자 식별 |
| `age_band` | `birthday` 를 연령대로 축약한다. 구간 폭은 10세 단위로 하고, 결측(1,160행 예상)은 「미상」 | 3장(연령대 축약·결측 미상). 구간 폭 10세는 글로서리가 정하지 않아 이 명세에서 정한다 |
| `staff` | 원본 그대로 보존한다. KPI·분석 축으로는 쓰지 않는다 | 1장 담당자 축 · 6장 5항(보존 전용) |
| `sales` `receipt` `visit_count` `visit_status` | 원본 값 그대로 | 1장 매출(`sales` 정본) · 수납(`receipt` 보존만) |
| `is_new` | `visit_count` = 1 이고 `visit_status` = 내원(3,447행 예상) | 1장 신환 |
| `is_revisit` | `visit_count` ≥ 2 이고 `visit_status` = 내원(44,155행 예상) | 1장 재진 |
| `is_new_churn` | `visit_count` = 0(1,409행 예상 — 전부 취소·부도) | 1장 신규 이탈 |
| `sales_exception_flag` | `visit_status` = 취소이고 `sales` 비0 — KPI 집계 제외 표지(정확히 1건 예상, 2026-08-20) | 1장 매출 예외 행 |
| `outstanding_flag` | `sales` ≠ `receipt`(22행 예상) | 1장 수납 |
| `outstanding_direction` | `sales` > `receipt` 는 「미수」(20행 예상), `receipt` > `sales` 는 「수납 선행」(2행 예상) — 방향을 보존한다 | 1장 수납 부기(방향 컬럼 보존) |
| `is_payment_visit` | `sales` 비0 이고 `visit_status` = 내원(5,428행 예상) — 객단가 분모 | 1장 객단가 |
| `is_foreign_est` (개정 3) | `patientName` 에 로마자 포함 여부 — **외국인 추정** 플래그. 판정은 브론즈에서 하고 플래그만 반입한다(실명 미반입 유지). 1,701행 예상 | 글로서리 개정 3(외국인 추정) — 담당자 요청 2026-09-01 |

**미반입 컬럼** — `patientName` · `phone` 은 실버에 내리지 않고, `birthday` 는 원본
값 대신 `age_band` 로만 남긴다(3장 PII 반입 규칙).

### 2.2 중복 제거

**모든 필드가 완전히 동일한 행만** 제거한다. `staff` 를 포함한 원본 11필드 전부가
비교 키다 — 같은 날 같은 환자라도 담당자나 금액이 하나라도 다르면 별개 예약 건으로
유지한다(6장 2항, 1차 폐기 원인 1 방어). 제거 건수와 제거 행 표본을 빌드 로그로 남기고,
행수 대사 수식(6장 게이트 1)에 제거 건수가 정확히 들어가게 한다.

### 2.3 fail-fast

다음 위반은 경고가 아니라 **빌드 중단**이다(로드맵 04 게이트 — 값 범위·enum 검사).

- `visit_status` 가 내원·취소·부도 세 값 밖인 행이 1건이라도 나오면 중단한다.
- `sales` · `receipt` · `visit_count` 에 음수가 1건이라도 나오면 중단한다.

## 3. silver_reviews — 리뷰 행 (리뷰 CSV 1,962행 기원)

### 3.1 컬럼 명세

| `review_pk` | `플랫폼리뷰ID` 그대로 — PK(1,962건 전건 유니크, 기록 02) | 기록 02 실사 |
| `platform` | `플랫폼`(네이버 1,448 · 강남언니 514) | — |
| `review_date` | `리뷰일` | — |
| `collected_at` | `수집일시_KST` 를 분리 보존한다 — 백필·증분 수집의 왜곡을 뒤에서 판독하기 위함 | 기록 02(수집 방식 왜곡 가능성) |
| `rating` | `평점` — 강남언니만 값, 네이버는 공란 유지. 감성의 정답이 아니라 검증 게이트로만 쓴다 | 1장 평점의 지위 |

| `body_part` | 부위는 보조 속성으로만 보존한다(예: 턱제모 → 개념 「제모」 + 부위 「턱」) | 2장 계층 해석의 주의 |
| `predicted_score` | LLM 이 본문만 보고 매기는 예상 평점. 0.5~5점, 0.5 단위. 채점 불성립 건은 점수 없이 비움 | 1장 리뷰 예상 평점 |
| `score_evidence` | 예상 평점의 근거 문장 — 본문의 부분 문자열이어야 한다 | 1장 리뷰 예상 평점(근거 문장) · 6장 1항(본문 실존 검증) |
| `sentiment` | 예상 평점의 임계값 분류 — ≥4 긍정 / 3~3.5 중립 / ≤2.5 부정 / 채점 불가 건은 판정불가. 중립과 판정불가를 합치지 않는다 | 1장 리뷰 감성 |
| `signal_type` | 강남언니 = 유기, 네이버 = 개입. 두 신호를 한 컬럼으로 합산하지 않기 위한 분리 표지 | 1장 개입 신호 · 유기 신호 |

`작성자` 등 나머지 원본 컬럼은 반입하지 않는다 — 3장의 「리뷰 작성자 그대로」는 반입 시
처리 수위를 정한 것이고, 실버 컬럼 구성은 이 명세가 정한다. 필요하면 `review_pk` 로
브론즈를 역참조한다.

### 3.2 전처리 파이프라인 — 글로서리 6장 1항의 순서 그대로

S-002 방식이다 — AI 가 추출·분류하고, System 이 규칙으로 검증하고, 사람은 예외만 본다.
키워드 규칙은 어느 단계에도 쓰지 않는다(1차 폐기 원인 2 방어).

1. **직원 실명 마스킹** — vegas `staff` 실명형 값을 본문에서 마스킹한다(3장).
2. **구조 파싱** — 강남언니 `[시술: X]` 태그와 4섹션 템플릿을 파싱한다(기록 02 정형성).
3. **LLM 채점** — 예상 평점(0.5~5, 0.5 단위) + 근거 문장 + 개념 13종 롤업 + 부위 보조
   속성을 한 번에 추출한다. 실행 모델·호출 경로는 **승인 필요 결정**이다(7장 항목 1·4).
4. **강남언니 정합 검증** — 실제 평점이 있는 514건으로 채점기를 검증한다. ±0.5 이내
   정합률이 기준치(7장 항목 2) 미달이면 채점기(프롬프트·모델)를 개선해 재실행하고,
   큰 불일치 건은 예외 큐로 보낸다(평점 오기 탐지 포함 — 1장 평점의 지위).
5. **임계값 분류** — 검증된 채점기를 전체 1,962건에 적용하고 감성으로 분류한다(1장).
6. **System 검증** — 점수 범위·0.5 단위, 폐쇄 목록 밖 0건, 근거 문장의 본문 실존을
   규칙으로 전건 검사한다.
7. **예외 사람 검토** — 정합 큰 불일치·System 검증 위반 건만 사람이 본다.

이 결과가 나와야 글로서리 4장 대기 항목 1(유기 신호의 시간 단위)을 판정할 수 있다 —
판정 자체는 이 스텝의 산출물이 아니며, 빌드 후 별도로 올린다.

## 6. 게이트 — 통과 기준

로드맵 04 게이트에 글로서리에서 파생한 검사를 더해, 통과 기준을 수치로 박는다.
하나라도 미달이면 명세로 되돌아가 고친 뒤 재빌드한다.

| # | 게이트 | 통과 기준 |
| --- | --- | --- |
