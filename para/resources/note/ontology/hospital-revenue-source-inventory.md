## 1. Vegas — 매출 · 내원 일지 (S3)

**구조** — `s3://daybeau/json/` 평탄 구조. 파일명 세 세대가 섞여 있다.

| 패턴 | 개수 | 기간 | 비고 |
| --- | --- | --- | --- |
| `YYYYMMDD.json` | 106 | 2025-04-01 ~ 07-15 | 전 지점 통합(한 파일에 12개 지점) |
| `YYYYMMDD_지점명.json` | 5,791 | 2025-06-07 ~ 2026-08-30 | 하루 × 지점당 1개 |
| `seramic_gangnam_mothly_YYYYMM.json` | 3 | 2025-10 ~ 12 | 월 단위 별종 — 아래 ⚠️ |

- ⚠️ **2025-06-07 ~ 07-15 는 두 패턴이 겹친다** — 중복 제거 규칙 필요
- ⚠️ 월별 별종은 스키마가 다르다 — `branch` 필드 없음(파일명에서 유추) ·
  금액이 문자열 · `resvDate` 가 하이픈 형식
- 세라미크 강남 커버리지: 일별 2025-06-07 ~ 2026-08-30, 그중 2025-10~12 는 월별 파일이
  대체. 진짜 구멍 = 2025-09 에 14일 · 2026-01-01~06 · 2026-02 에 1일

**행 스키마** — 형태 A(최상위 배열)로 계속 쌓인다(담당자 확인). 전달 문서의 (B) 전환
안내는 현행 아님

| 필드 | 내용 | 검증에서 확인한 것 |
| --- | --- | --- |
| branch | 지점명 (Vegas 원본 표기) | NFC 정규화 필수 (macOS NFD 이슈) |
| resvDate | 예약일 | 2026 일별 파일은 `YYYYMMDD` |
| patientName · birthday · phone | 환자 정보 — **PII** | phone 이 Vegas↔리뷰 등 조인 키 후보 |
| chartNo | 차트번호 | |
| staff | 담당자 | '미지정' 다수 — Node 의 담당자 축 후보 |
| sales · receipt | 매출 · 수납 | receipt ≈ sales (차액 = 미수 추정) |
| visitCount | 방문 차수, 1 = 신환 | **0 과 275 같은 이상값 존재** — 판정 규칙 검증 필요 |
| visitStatus | 내원 / 취소 / **부도(=노쇼)** | |

**2026년 반입분 검증** (235개 전수 파싱, 2026-08-31)

- 78,216행 · 전부 형태 A · 11개 필드가 전 행 균일 (2025 초기 파일에 있던 `discount` 는 없음)
- visitStatus: 내원 47,602 · 취소 27,815 · 부도 2,799
- 월 매출(내원 행 sales 합) 2.8억 ~ 4.0억원, 8개월 연속 확인 — **매출 데이터 맞다**
- ⚠️ **내원 행의 89% 가 sales=0** — 패키지 선결제(첫 결제에 매출 인식, 이후 회차 0원)
  구조로 추정. `sales` 의 인식 기준 확인이 2단계 용어 정의의 최우선 질문
- ⚠️ 베가스는 과거 파일을 덮어쓴다(환불·정정) — LastModified/ETag 로 증분 재반입

불가하고, ① 리뷰 시술 추출 사전 ② 프로모션 달력 ③ sales 금액↔정가 매칭 휴리스틱(약함)으로
쓴다. v1/v2 는 기간이 같이 살아 있어 정본 판별이 여전히 필요하다.
