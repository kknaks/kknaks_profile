# 온톨로지 실행 기록 05 — 표준 KPI View

이 문서는 [[2026-09-01-ontology-01-roadmap|기록 01]]의 「05 표준 KPI View」 스텝의
명세이자 빌드 기록이다. 1~7장이 빌드 전에 확인받은 명세이고, 7장의 승인 필요 결정
4건이 담당자 승인으로 확정된 뒤 빌드를 실행했다. S-001 의 순서를 따른다 —
**온톨로지보다 표준 KPI View 가 먼저다.** 06 EDA 가 산점도를 그릴 시계열 자체가
이 스텝에서 나온다.

모든 계산식의 단일 원천은 [[2026-09-01-ontology-03-glossary|기록 03 글로서리]]다.
KPI 하나마다 글로서리의 어느 판정에서 왔는지를 근거로 달고, 글로서리에 없는 정의는
만들지 않는다 — 글로서리가 정하지 않은 사항은 전부 7장 승인 필요 결정으로 올린다.
입력 스키마·행수는 [[2026-09-01-ontology-04-silver|기록 04 실버 빌드]]의 산출물을
따른다.

1차 폐기 원인 3 — 프로모션 변수를 명세 없이 즉흥 산출해 추세성 누적으로 가짜 상관을
보고한 것 — 의 재발 방지가 이 스텝의 핵심 방어선이다. 개입 변수는 이 명세를 먼저
승인받은 뒤에만 산출하며, 시작·종료 이벤트 단위를 유지한다.

## 1. 입출력 개요

- **입력** — `reference/ontology_demo/silver/` 의 실버 4종. 읽기만 한다.
  - `silver_reservations.csv` 75,479행 — 예약·내원 행. KPI 의 주 원천
  - `silver_reviews.csv` 1,962행 — 개입 신호(네이버 플레이스 1,448)·유기 신호(강남언니 514)
  - `silver_promotions.csv` 73행 — v1 24 + v2 ko 49, 생존 57(v1 23 + v2 34)
  - `silver_catalog.csv` 6,198행 — 이 스텝에서는 직접 집계하지 않고 참조만 한다
- **출력** — `reference/ontology_demo/gold/` 아래 CSV 3종(7장 승인 항목 2).
  - `gold_kpi_daily.csv` — 일별 KPI 시계열 (235행 예상)
  - `gold_kpi_weekly.csv` — 주별 KPI + 유기 신호
  - `gold_promo_calendar.csv` — 프로모션 개입 이벤트 (57행 예상)
- **실행 코드** — `reference/ontology_demo/scripts/` (기록 04 승인 항목 3의 위치를
  그대로 쓴다).

## 2. gold_kpi_daily — 일별 KPI 시계열

### 2.1 그레인

`resv_date` 일별 1행. vegas 창 2026-01-07 ~ 2026-08-30 중 데이터가 존재하는
**235일**만 행을 만든다. 결측일 **2026-02-17 은 행 자체를 만들지 않는다** — 0으로
채우지 않는다(글로서리 1장 결측일 처리, 승계 판정).

### 2.2 KPI 표

계산식은 글로서리 용어로만 서술한다. 소스는 전부 `silver_reservations` 이며, 개입
신호만 `silver_reviews` 다.

| 지표 (컬럼) | 계산식 | 소스 컬럼 | 글로서리 근거 |
| --- | --- | --- | --- |
| 매출 `sales_total` | 당일 `sales` 합계. **매출 예외 행(`sales_exception_flag` 참)은 제외**한다 | `sales` `sales_exception_flag` | 1장 매출(`sales` 정본) · 매출 예외 행(예외 1건 — 2026-08-20) |
| 결제 내원 수 `payment_visits` | 당일 결제 발생 내원 행수 — `sales` 비0 이고 내원 | `is_payment_visit` | 1장 객단가(분모 정의) |
| 객단가 `avg_ticket` | 매출 ÷ 결제 내원 수. 전체 내원으로 나누지 않는다. 결제 내원 0인 날은 0이 아니라 빈 값 | 위 두 지표 | 1장 객단가(승계 판정) |
| 총 내원 수 `visits` | 당일 `visit_status` = 내원 행수 | `visit_status` | 1장 신환·재진의 상위 개념 |
| 신환 수 `new_patients` | 당일 `visit_count` = 1 이고 내원 | `is_new` | 1장 신환 |
| 재진 수 `revisits` | 당일 `visit_count` ≥ 2 이고 내원 | `is_revisit` | 1장 재진 |
| 예약 수 `reservations` | 당일 전체 예약 행수 — 내원 + 취소 + 부도 | 행수 | 1장 취소율(분모 정의) |
| 취소 수 `cancels` | 당일 `visit_status` = 취소 행수 | `visit_status` | 1장 취소율 |
| 취소율 `cancel_rate` | 취소 ÷ 전체 예약 행(내원 + 취소 + 부도) | 위 두 지표 | 1장 취소율 |
| 부도 수 `noshows` | 당일 `visit_status` = 부도 행수 | `visit_status` | 1장 노쇼율 |
| 노쇼율 `noshow_rate` | 부도 ÷ (내원 + 부도). **취소는 분모에서 제외** — 취소는 「안 온 것」이 아니라 「예약을 무른 것」 | 위 지표 | 1장 노쇼율(승계 판정) |
| 신규 이탈 수 `new_churns` | 당일 `visit_count` = 0 인 예약 행수 | `is_new_churn` | 1장 신규 이탈(승계 판정) |
| 개입 신호 `naver_reviews` | 당일 네이버 플레이스 리뷰 수 — **리뷰일(`review_date`) 기준**. 개입 변수이므로 유기 신호와 합산하지 않는다 | `silver_reviews.platform` `review_date` | 1장 개입 신호(승계 + 담당자 확인) |

`receipt`(수납)와 `staff`(담당자)는 KPI 로 산출하지 않는다 — 글로서리 1장이 각각
보존 전용·분석 축 제외로 판정했다.

### 2.3 파생 컬럼 — 변화량·이동평균

위 지표 각각에 세 컬럼을 붙인다.

- `{지표}_dod` — 전일 대비 변화량 (당일 − 전일)
- `{지표}_dod_pct` — 전일 대비 변화율 ((당일 − 전일) ÷ 전일. 전일이 0이면 빈 값)
- `{지표}_ma7` — 7일 이동평균

결측일(2026-02-17)이 행을 만들지 않으므로 「전일」과 「7일 창」의 해석이 갈린다 —
직전 존재 행 기준인지, 달력일 기준인지. 이 명세는 **직전 존재 행 기준**(2026-02-18 의
전일은 2026-02-16, 이동평균은 자기 포함 직전 7개 존재 행)을 제안하되, 글로서리가
정하지 않은 사항이므로 승인 필요 결정으로 올린다(7장 항목 3).

### 2.4 상태 기준 — 양호 · 주의 · 경고

로드맵 05 는 KPI 마다 상태 기준(양호·주의·경고, 경계값 명시)을 요구한다. 경계값을
어떻게 산정할지는 글로서리에 없으므로 **승인 필요 결정**이다(7장 항목 1). 선택지와
추천은 7장에 정리하고, 여기서는 산출 형태만 명세한다 — 승인된 방식으로 지표별
경계값 2개(주의 진입·경고 진입)를 산정해 `{지표}_status` 컬럼(양호/주의/경고)을
붙이고, 산정에 쓴 방식·경계값을 빌드 로그에 수치로 남긴다. 방향은 지표 성격을
따른다 — 매출·내원·신환은 낮을수록, 노쇼율·취소율·신규 이탈은 높을수록 나쁜 쪽이다.

## 3. gold_kpi_weekly — 주별 KPI + 유기 신호

### 3.1 그레인

**ISO 주** 1행(`iso_year` + `iso_week`, 주 시작일 `week_start` 병기). vegas 창의
첫 주(2026-01-07 수요일 시작)와 마지막 주는 7일을 못 채우므로 `is_partial_week`
플래그를 단다 — 행은 만들되 06 EDA 에서 걸러 쓸 수 있게 표지만 남긴다.

### 3.2 컬럼

- **일별 지표의 주 합계** — 2.2의 계수형 지표(매출·결제 내원·총 내원·신환·재진·
  예약·취소·부도·신규 이탈·네이버 리뷰 수)를 주 단위로 합산한다.
- **비율형 지표의 재계산** — 객단가·취소율·노쇼율은 일별 값의 평균이 아니라 **주
  합계에서 재계산**한다(주 매출 ÷ 주 결제 내원 수 등). 일별 비율 평균은 분모 크기를
  무시하므로 쓰지 않는다.
- **유기 신호** — 강남언니 리뷰만으로 `gu_reviews`(주별 리뷰 수) · `gu_positive`
  (긍정 수) · `gu_negative`(부정 수)를 만든다. **주 단위 + 보조 신호 지위**가
  글로서리 확정 판정이다 — 06 EDA 에서 이 신호 단독으로 엣지를 확정하지 않는다는
  지위를 컬럼 주석과 이 문서에 명시한다. **리뷰 없는 주는 0** — 결측이 아니라 실제
  0건이다(글로서리 1장 유기 신호). 긍정·부정은 `sentiment` 컬럼 기준이며 중립·
  판정불가는 리뷰 수에는 포함되고 긍정·부정 어느 쪽에도 세지 않는다.

개입 신호(네이버)와 유기 신호(강남언니)는 주별 테이블에서도 별도 컬럼이다 — 한
컬럼으로 합산하지 않는다(글로서리 1장, 승계 판정).

## 4. gold_promo_calendar — 프로모션 개입 이벤트

1차 폐기 원인 3 의 방어선이다. 상시 프로모션이 누적되는 **「일별 활성 개수」류의
추세성 변수를 만들지 않는다** — 프로모션은 시작·종료를 갖는 **이벤트 단위**로만
산출한다.

| 항목 | 규칙 | 글로서리 근거 |
| --- | --- | --- |
| 행 단위 | **프로모션 1건 = 이벤트 1행** (시작일·종료일을 가진 이벤트 행). 일별 전개·일별 카운트 금지 | 로드맵 05(이벤트 단위) · 1차 폐기 원인 3 |
| 세대 범위 | v1 + v2 모두 포함. 상세(제목 등)는 v2 만, v1 은 기간·존재만 | 1장 프로모션(v1 과거 실사용 — 담당자 확인) |
| 기간 정본 | **혜택 기간**(`benefit_start`/`benefit_end`). 노출 기간은 참고 속성으로 병기 | 1장 프로모션(기간 정본 = 혜택 기간) |
| 삭제분 | **생존만 기본**(`is_deleted` 거짓) — 57행 예상(v1 23 + v2 34) | 기록 04 5장(생존 기준 준용) |
| 컬럼 | `promo_version` · `code` · `title`(v2 만) · `benefit_start` · `benefit_end` · `display_start` · `display_end`(참고) | 실버 스키마 그대로 |
| 구성 특성 (개정 1) | v2 프로모션에 한해 `silver_mappings`(프로모→이벤트 그룹→상품) 사슬로 구성 특성 4컬럼을 붙인다 — `n_products`(ko 생존·정가>0 상품 수) · `avg_discount_rate` · `avg_discounted_price` · `median_discounted_price`. **v1 은 매핑이 없어 전 컬럼 빈 값**(구성 불명 — 기록 02 Q4). 상품→카테고리 연결 부재(공백 ③)로 카테고리 믹스는 산출하지 않는다. 담당자 요청으로 추가(2026-09-01 개정) — 06 쌍 7(구성 → 기간 KPI)의 입력 | 기록 04 개정 1 · 기록 02 공백 ③ |

06 EDA 에서 이 캘린더는 「이벤트 시작·종료 시점 전후의 KPI 변화」를 보는 개입
변수로만 쓰일 예정이다 — 이 문서는 산출까지만 정의한다.

## 5. 알려진 총계 대조값

빌드 후 게이트에서 골드 집계를 아래 값과 대조한다. 실버 기준 값은 이 명세 작성
시점에 `silver_reservations.csv` 를 명령으로 재집계해 확인한 값이다.

| 항목 | 대조값 (8개월 합) | 비고 |
| --- | --- | --- |
| 매출 합 | **2,615,555,218원** | 매출 예외 1건(2026-08-20, 12,100원) 제외 기준. 브론즈·실버 동일 — 제거된 중복은 전건 매출 무관 |
| 결제 내원 수 | **5,428** | 브론즈·실버 동일 |
| 신환 수 | **3,447** | 브론즈·실버 동일 |
| 총 내원 수 | 브론즈 기준 **47,602** / 실버 기준 **47,537** | 차이 65 = 04 중복 제거로 빠진 완전 동일 내원 행. 골드는 실버가 원천이므로 게이트 대조는 **47,537** 로 하고, 브론즈 값과는 「47,537 + 내원 중복 65 = 47,602」 수식으로 대사한다 |
| 일별 행수 | **235** | 236일 창에서 결측일 2026-02-17 제외 |

부기 — 04 의 중복 제거 2,737행은 상태별로 취소 2,637 + 부도 35 + 내원 65 로
분해되며, 매출·결제 내원·신환 총계는 바꾸지 않았다(명세 시점 재집계로 확인).
재진(실버 44,090)·신규 이탈(실버 1,360)도 같은 이유로 글로서리의 브론즈 재검증값
(44,155 · 1,409)과 다르며, 골드 게이트는 실버 기준으로 대조한다.

## 6. 게이트 — 통과 기준

로드맵 05 게이트를 수치로 박는다. 하나라도 미달이면 명세로 되돌아가 고친 뒤
재빌드한다.

| # | 게이트 | 통과 기준 |
| --- | --- | --- |
| 1 | 실버 재집계 일치 | 골드 일별 매출 합 = 실버 `sales` 재집계 합(예외 플래그 제외)이 **오차 0**으로 일치할 것. 5장 대조값(매출 2,615,555,218 · 결제 내원 5,428 · 신환 3,447 · 내원 47,537)과 전항 일치할 것 |
