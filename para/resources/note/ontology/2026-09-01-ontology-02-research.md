# 온톨로지 실행 기록 02 — 자료 조사·소스 실사

이 문서는 [[2026-09-01-ontology-01-roadmap|기록 01]]의 「02 자료 조사·소스 실사」
스텝이 정의한 산출물 — 원천 인벤토리 기록 — 이다. 브론즈 소스 세 종을 처음 열어
전수 스캔했고, 아래의 모든 수치는 이 실사에서 명령으로 직접 측정한 값이다. 계층
개념은 [[medallion-architecture]] 에 위임하고 여기서는 데이터 사실만 적는다.

소스는 `reference/ontology_demo/` 아래 세 종이다. 같은 디렉터리에 `.env` 파일이
존재하나(233바이트) 접속 정보로 보고 내용은 열지 않았다 — 브론즈 실사 대상이 아니다.

## 1. vegas — 일별 예약·내원 원장 (`bronze/vegas/*.json`)

**파일 구성** — 데이터 파일 235개 + `_manifest.json`(235개 전 파일의 S3 키·etag·
수정시각·크기 목록). 파일명은 `YYYYMMDD_세라미크의원 강남.json` 꼴로 하루 한 파일이다.

**기간** — 2026-01-07 ~ 2026-08-30. 이 구간에서 결측일은 2026-02-17 하루뿐이다
(236일 중 235일 존재).

**스키마** — 최상위가 JSON 배열이고, 전 행이 동일한 11필드 단일 스키마다. 235개
파일 전체에서 키 집합이 정확히 한 종류로 나왔다.

`branch, resvDate, chartNo, patientName, birthday, phone, staff, sales, receipt, visitCount, visitStatus`

`sales` · `receipt` · `visitCount` 는 전 행 정수형이고, `resvDate` 는 `YYYYMMDD`
문자열로 파일명 날짜와 78,216행 전부 일치한다(불일치 0건). `branch` 는 전 행
`세라미크의원 강남` 단일값이다.

**규모·그레인** — 총 78,216행, 그레인은 예약 1건이다. `visitStatus` 분포:

| visitStatus | 행수 |
| --- | --- |
| 내원 | 47,602 |
| 취소 | 27,815 |
| 부도 | 2,799 |

**이상 징후**

- `sales` 비0 행은 5,429건(6.9%)이고, 그중 `visitStatus=취소` 는 단 1건 —
  결제 발생은 사실상 내원에 종속된다. 취소인데 매출이 찍힌 1건은 03에서 처리
  기준을 정할 예외다.
- `chartNo` 빈 문자열 1,456행. 동일 `chartNo` 에 서로 다른 `patientName` 이 붙은
  차트번호가 45건이다(사전 조사에서는 46건으로 집계됐으나 재검증 결과 45건 —
  본 문서는 측정값 45건을 따른다).
- `staff` 는 고유값 30종인데 `미지정` 이 27,671행(35.4%)이고, 나머지도
  `데스크지하1`(18,976) · `데스크1`(13,530) · `데스크2층1`(8,285) 같은 데스크
  단말 계정과 `김예지`(997) · `이수빈`(819) 같은 실명이 혼재한다. 담당자 축의
  분석 단위가 성립하는지는 03에서 판정해야 한다.
- 시술명·상품 식별자 컬럼이 없다 — 예약이 어떤 시술·상품에 대한 것인지 이 원장
  단독으로는 알 수 없다(후술하는 3대 공백 ①).

**PII** — 실명(`patientName`)은 전 행에 존재한다. `birthday` 는 1,160행,
`phone` 은 7행이 빈 문자열이고 나머지 전 행에 값이 있다(사전 조사의 「3필드 전 행
존재」는 부정확 — 실명만 전 행이다). 값은 본 문서에 일절 인용하지 않는다.

## 2. nexus — 시술·프로모션 카탈로그 (`bronze/nexus/*.csv`, 14개)

**파일 구성·규모** — CSV 14개. 예약 원장과 달리 시계열이 아니라 상태
스냅숏이며, `created_at`/`updated_at` 스탬프 범위는 2024-12-24 ~ 2026-08-31 이다.

| 파일 | 행수 | 비고 |
| --- | --- | --- |
| branches | 3 | 강남 id=2 ACTIVE · 신사 id=1 INACTIVE(soft-delete) · 명동 id=3 ACTIVE |
| categories | 157 | 루트 56 + 자식 101, 3단계 0건 — 2단 고정 계층 |
| category_translations_ko | 128 | 전부 ko, category_id 고아 0 |
| procedure_groups | 2,154 | 8개 언어 행 분리(ko 528) |
| procedure_products_ko | 2,996 | ko 슬라이스만 반입 |
| procedure_group_product_mappings | 5,632 | `deleted_at` 컬럼 없음 |
| event_procedure_groups | 1,769 | 8개 언어(ko 482) |
| event_procedure_products_ko | 2,179 | ko 슬라이스만 반입 |
| event_procedure_group_product_mappings | 3,199 | `deleted_at` 컬럼 없음 |
| procedure_packages_ko | 323 | 323건 전부 main_category_id 보유 |
| promotions_v1 | 24 | 연결 매핑 없음 — 고립 |
| promotion_v2s | 287 | 8개 언어(ko 49) |
| promotion_v2_event_group_mappings | 858 | 고아 0 |
| promotion_v2_group_mappings | 0 | 헤더만 존재 |

**구조** — 전 테이블이 `branch_id` 로 branches 를 참조하고 고아는 0건이다.
`branches.branch_id` 는 `CERAMIQUE-GN-001` 류의 전사 코드이고 `slug=gangnam`,
`name=강남점` 이 병존한다. categories 의 `ca_id` 는 지점 간 중복이 39건 —
전역 코드가 아니라 지점 로컬 슬롯이다. 일반 시술 라인(groups → mappings →
products)과 이벤트 라인(event_*)은 컬럼 구성까지 거의 같은 구조적 쌍둥이다.

**이상 징후**

- 상품 파일이 `_ko` 슬라이스만 반입되어, 매핑 5,632건 중 4,330건(77%),
  이벤트 매핑 3,199건 중 2,463건(77%)이 반입되지 않은 비-ko 상품을 가리킨다.
  참조 무결성 자체의 문제는 아니고(ko 상품을 비-ko 그룹이 가리키는 언어 교차는
  양쪽 라인 모두 0건), 반입 범위의 문제다.
- soft-delete 비율이 테이블마다 크게 다르다 — procedure_products_ko 57%,
  event 라인 51%, procedure_groups 36%, promotion_v2s 34%, categories 32%,
  promotions_v1 4%, packages 3%. (사전 조사의 「40~57%」와 달리 실측은
  3~57% 로 하한이 훨씬 낮다.) 매핑 3종에는 `deleted_at` 컬럼 자체가 없어
  삭제가 하드 삭제로 추정된다.
- 프로모션은 promotions_v1(24행, 어디에도 연결 안 됨)과 promotion_v2s(287행)
  두 세대가 공존한다. v2는 이벤트 그룹에만 연결되고(858행 매핑, 고아 0)
  일반 시술 그룹 매핑은 0행이다. 기간 컬럼은 혜택
  (`promotion_started_at/ended_at`)과 노출(`display_started_at/ended_at`)
  두 쌍이며, ko 기준 혜택 기간은 v2 가 2025-12-02 ~ 2027-12-31, v1 이
  2025-12-02 ~ 2027-01-30 으로 vegas 창을 전부 덮는다.
- 패키지 323건은 카테고리에만 연결되고 시술 그룹·상품과는 단절이다.
  역으로 카테고리에 연결된 것도 패키지뿐이다(3대 공백 ③).

## 3. 리뷰 — `세라미크의원_강남_STG_리뷰_2026-08-31.csv`

**구성·규모** — 1,962행 = 네이버 플레이스 1,448 + 강남언니 514. 컬럼 10개:
`플랫폼, 리뷰일, 작성자, 평점, 리뷰내용, 원문URL, 플랫폼리뷰ID, 답변상태,
답변일시_KST, 수집일시_KST`. PK인 `플랫폼리뷰ID` 는 1,962건 전건 유니크다.

**기간** — 리뷰일 전체 범위는 2025-07-05 ~ 2026-08-30 이지만 플랫폼별로 갈린다.
**네이버는 2026-03-21 이전 리뷰일이 한 건도 없고**(2026-03-21 ~ 08-30),
강남언니는 2025-07-05 ~ 2026-08-26 인데 2026년 들어 급감해 vegas 창
(2026-01-07~08-30) 안에는 60행뿐이다. 수집일시 최소값이 2026-03-23 이라
백필+증분 수집으로 보이며, 리뷰일 분포(2026-06 583건 급증 등)는 수집 방식의
왜곡 가능성을 안고 읽어야 한다.

**정형성** — 평점은 강남언니 514건에만 있고 네이버는 전부 공란이다. 강남언니
본문은 `[시술: X]` 태그로 시작해 「시술 전 고민 / 상담 경험 / 시술 결과 / 추가
의견」 4섹션 템플릿을 따른다(511/514건, 예외 3건). 태그는 514건 전건에 있고
라벨 문자열 14종 — 복합 표기(`턱제모, 인중제모` 등)를 풀면 단일 시술 12종 —
이며 최다는 턱제모 274건이다. 작성자는 마스킹 닉네임이다.

**이상 징후** — 리뷰 본문에 vegas `staff` 의 실명이 등장한다(예: 강민성 언급
11건). 닉네임 마스킹과 별개로 본문 자체가 PII 를 품을 수 있다는 뜻이므로,
리뷰 텍스트의 하위 층 반입 수위도 PII 항목에 포함한다.

## 4. 소스 간 연결 — 조인 가능성

**vegas ↔ nexus 직접 키 없음.** vegas 에는 상품·시술 식별자 컬럼이 없고 nexus
에는 예약·환자 축이 없다. 성립하는 연결 축은 두 가지뿐이다.

- (지점, 날짜) — vegas `resvDate` × nexus 프로모션 혜택/노출 기간의 구간 조인.
- 금액 휴리스틱 — vegas `sales` 가 카탈로그 가격과 일치하는지. 강남(branch_id=2) ·
  미삭제 · 판매가(`discounted_price`) 기준으로 5,429건 중 774건(14%)이 일치했다.
  필터를 어떻게 잡느냐에 민감해(정상가 포함·삭제 포함으로 넓히면 2,099건/39%까지
  올라감) 근사 신호 이상으로 쓰기 어렵다. 사전 조사의 827건(15%)과 다른 것은
  휴리스틱 정의 차이로 보이며, 본 문서는 위 정의의 측정값을 기준으로 한다.

**지점 표기 불일치** — 같은 강남 지점이 소스마다 다르게 적힌다: vegas
`세라미크의원 강남`, nexus `강남점` / `gangnam` / `CERAMIQUE-GN-001`, 리뷰 파일명
`세라미크의원_강남`. 실버에서 지점 alias 매핑 테이블이 필요하다.

**리뷰 ↔ 카탈로그** — 강남언니 시술 라벨 12종(단일 기준)과 nexus ko
그룹명·상품명(일반+이벤트 4개 테이블)의 문자열 완전 일치는 0건이다. 라벨 →
SKU 연결은 문자열 조인으로는 성립하지 않고 03의 용어·매핑 정의가 필요하다.

## 5. 3대 공백

1. **예약 ↔ 시술상품 라인아이템 부재** — vegas 예약 행에 어떤 상품을 시술·결제
   했는지가 없다. 금액 휴리스틱(14%)으로는 메울 수 없는 구조적 공백.
2. **시술 개념 ↔ SKU 매핑 부재** — 리뷰의 시술 라벨(예: 턱제모)과 카탈로그
   SKU 사이에 어떤 매핑도 없다(완전 일치 0건).
3. **상품/그룹 ↔ 카테고리 연결 부재** — 카테고리 계층에 연결된 것은 패키지
   323건뿐이고, 시술 그룹·상품은 카테고리와 끊겨 있다.

## 7. 다음 스텝(03 용어 정의)으로 넘길 질문

1. 매출 인식 — `sales` 는 예약일 기준 결제액인가, `receipt` 와의 관계는 무엇인가.
   취소인데 `sales` 비0인 1건의 처리 기준.
