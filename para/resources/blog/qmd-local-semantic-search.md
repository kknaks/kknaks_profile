# QMD로 옵시디언 노트를 의미 기반 검색하기

> 출처: https://thinkingsian.com/QMD/ · 저자 미상 · 날짜 미상

## 요지

- QMD는 마크다운 노트를 로컬에서 인덱싱해 BM25, 벡터 검색, 하이브리드 검색을 제공하는 CLI 도구다.
- 글쓴이는 한국어에서 QMD의 BM25 검색이 잘 맞지 않아, 일반 파일 검색은 AI Agent에 맡기고 의미 검색에만 QMD를 사용한다.
- 기본 임베딩 모델보다 한국어 성능이 나은 Qwen3 Embedding 0.6B 모델로 교체할 것을 권한다.
- 컬렉션의 변경 사항은 자동 임베딩되지 않으므로 `qmd update && qmd embed`를 주기적으로 실행해야 한다.
- QMD를 MCP나 OpenClaw의 메모리 엔진과 연결하면 AI Agent가 로컬 노트를 의미 기반으로 검색하게 할 수 있다.

## 내용

글쓴이는 노트 관리에서 읽기와 쓰기뿐 아니라 필요한 내용을 다시 찾는 과정도 복잡하다고 보고, 옵시디언과 함께 사용 중인 의미 기반 검색 도구 QMD를 소개한다. QMD는 Shopify 창업자 Tobi Lütke가 만든 로컬 마크다운 검색 도구로, 노트를 토큰화하거나 임베딩해 BM25 검색, 벡터 검색, LLM을 결합한 하이브리드 검색을 지원한다고 설명한다.

검색은 크게 검색어가 포함된 문서를 찾는 lexical search와 의미가 비슷한 문서를 찾는 semantic search로 나뉜다. 임베딩 기반 의미 검색에서는 노트와 검색어를 각각 벡터로 변환한 뒤 코사인 유사도를 계산해 가까운 노트를 찾는다. QMD는 긴 문서를 고정된 토큰 수로만 자르지 않고 헤딩 등 마크다운 구조를 고려해 청킹한다는 장점도 있다.

글쓴이의 경험에 따르면 QMD의 BM25 검색은 한국어 복합어를 제대로 분리하지 못한다. 예를 들어 `안보위기`라는 이름의 노트는 `안보`로 찾을 수 있지만 `위기`로는 찾지 못할 수 있다. 그래서 lexical search는 Claude Code 같은 AI Agent가 Grep이나 Glob으로 수행하게 하고, 의미 검색이 필요할 때만 QMD를 사용한다. 글쓴이는 노트가 많아도 대개 1만 개 수준인 PKM에서는 이 방식이 당장 실용적이라고 판단한다.

QMD를 사용하려면 옵시디언 볼트에서 다음과 같이 컬렉션을 추가한다.

```sh
qmd collection add . --name pkm
```

기본 모델 `embeddinggemma-300M-Q8_0`은 한국어 성능이 낮다는 것이 글쓴이의 평가다. 대안으로 Qwen3 Embedding 0.6B 모델을 지정하고 기존 임베딩을 다시 생성한다.

```sh
export QMD_EMBED_MODEL="hf:Qwen/Qwen3-Embedding-0.6B-GGUF/Qwen3-Embedding-0.6B-Q8_0.gguf"
qmd embed -f
```

환경 변수는 사용하는 셸의 설정 파일에 등록해야 한다. 컬렉션의 파일 변경이 임베딩에 자동 반영되지는 않으므로, 글쓴이는 다음 명령을 매일 새벽에 실행하도록 cron job을 구성했다. 상태는 `qmd status`로 확인한다.

```sh
qmd update && qmd embed
```

QMD는 OpenClaw의 메모리 엔진으로도 사용할 수 있다. 대화 메모리가 많아져 일부 내용만 의미에 따라 가져와야 할 때 유용하다는 것이 글쓴이의 설명이다. 또한 QMD의 MCP 서버를 등록하면 Claude Desktop이나 Claude Code 같은 AI Agent가 임베딩된 옵시디언 노트를 검색할 수 있다.

```json
{
  "mcpServers": {
    "qmd": {
      "command": "qmd",
      "args": ["mcp"]
    }
  }
}
```

글쓴이는 본격적인 로컬 LLM의 보편화보다 로컬 임베딩 모델의 실용화가 먼저 올 가능성이 있다고 전망한다. QMD는 과금이나 외부 API 설정 없이 옵시디언 볼트를 AI Agent가 의미 기반으로 검색하게 해주는 도구라는 것이 글의 결론이다.

## 배운 것

한국어 노트 검색에서는 하나의 검색 엔진에 모든 방식을 맡기기보다 문자열 검색과 의미 검색의 역할을 분리하는 편이 현실적이다. QMD를 도입한다면 한국어 성능에 맞는 임베딩 모델을 선택하는 것뿐 아니라 컬렉션 갱신과 재임베딩을 자동화해야 실제 운영이 가능하다. 다만 기본 모델과 Qwen3 모델의 한국어 성능 차이, 로컬 실행에 필요한 구체적인 하드웨어 사양은 이 글만으로 검증하기 어려우므로 별도 측정 자료를 확인할 필요가 있다.
