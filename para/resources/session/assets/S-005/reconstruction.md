# 최종 정리 — 코드 생성 속도를 개발 흐름의 성과로 연결하기

사내 코드 Agent 개발 과정에서 드러난 네 설계 문제로 묶었다. 네 고객사 구축 사례가 아니라 한 개발 체계의 연결된 문제와 대응이다.

## 사례 1 — 사람이 매번 잇던 작업을 이벤트 흐름으로 바꾸기

### 문제 — 구현이 빨라져도 인계와 승인은 남는다

개인의 짧은 구현 루프와 여러 사람이 참여하는 프로젝트 흐름은 속도를 결정하는 지점이 다르다. 일 정의·맥락 연결·결과 판단이 사람에게 남으면 구현량 증가가 개입 횟수 증가로 이어진다.

### 만든 개념 — 기준과 예외가 있는 연속 운영

사람의 단건 지시 대신 개발 이벤트로 시작하고 조회·변경·검증·기록을 이어간다. 완료 기준과 승인·정보 부족의 분기를 둔다.

### 적용과 아키텍처

신규 이슈·코드 변경·테스트 실패·보안 경고·정기 작업이 실행을 시작한다. 기준 충족 시 다음 단계로, 승인 필요 시 사람에게, 예외·정보 부족 시 보완 후 재개한다.

### 결과

이벤트 기반 운영의 설계가 제시됐다. 실제 프로젝트 리드타임이나 승인 대기 감소 수치는 없다. 사내 처리량과 외부 리뷰 통계는 문제 제기 근거이며 이 설계의 전후 성과가 아니다.

## 사례 2 — 흩어진 자료를 실행 가능한 작업 맥락으로 구성하기

### 문제 — 정보가 많아도 무엇을 바꿀지 연결돼 있지 않다

요구사항·코드·운영 설정·담당자 지식·판정 기준이 분산돼 있다. AI는 관련 대상을 다시 찾거나 오래된 정보로 변경할 수 있다.

### 만든 개념 — 목적·대상·제약·산출물·기준·완료 조건의 묶음

AI DLC는 Agent Skills·Rules·Context로 실행 방법과 판단 기준을 연결한다. 공통 ID와 관계 정보, 버전·권한을 함께 관리한다.

### 적용과 아키텍처

요구사항·업무 규칙·설계·컴포넌트·테스트·완료 기준을 연결하고 변경된 관련 정보를 갱신한다. 문서·Wiki·RAG·Graph가 지식 구조화 수단으로 제시됐다.

### 결과

포털 화면과 구성도가 있으며, 발표자는 AI 도구만 제공했을 때보다 협업 생산성이 30% 이상 올랐다는 테스트를 설명했다. 표본·기간·측정식·통제 조건이 없어 일반적인 향상률로 옮길 수 없다.

## 사례 3 — 기업 시스템 직접 연결과 실행 통제를 함께 제공하기

### 문제 — 사람이 전달하는 맥락은 병목이고 무제한 직접 접근은 위험이다

표준 개발 도구 외에도 기업 고유 시스템에서 최신 정보를 가져와야 한다. 접근 경로만 열면 과도한 권한으로 변경이 실행될 수 있다.

### 만든 개념 — 업무 접근 계층과 통제 계층의 분리

커넥터·맥락 구조화·업무 도구화로 접근을 제공하고, 신원·권한·정책·승인·검증·감사로 실행 경계를 관리한다.

### 적용과 아키텍처

Agent가 기업 시스템 AI 접근 계층을 통해 조회·변경한다. AI Pro Governance는 실행 범위와 도구를 제한하고 허용·승인 필요·금지로 나누며 로그를 받는다.

### 결과

기업 접근 구조와 AI Pro의 통제 도식이 확인된다. 외부 사고 예시와 자체 통제를 구분했으며 차단 성공률·감사 완전성·복구 보장은 제시되지 않았다.

## 사례 4 — 남는 판단 병목을 규칙·스킬·도구 개선으로 바꾸기

### 문제 — 예외와 책임 판단은 자동 실행 이후에도 남는다

변경 영향·위험·승인은 사람의 경험이 필요하다. 같은 판단을 반복하면 사람에게 병목이 계속 쌓인다.

### 만든 개념 — 전문가가 개입하는 운영 개선 순환

실행 이력에서 반복 패턴을 찾고 원인을 진단해 룰·평가, 스킬·흐름, 맥락·지식, 도구·연계로 반영한다.

### 적용과 아키텍처

로그·Hook·판단 → 반복 패턴 → 전문가 진단 → 평가·승인·버전 → 단계 적용·모니터링 → 재수집으로 이어진다. 발표의 FDE는 이 진단과 개선을 맡는 역할이다.

### 결과

사람이 맡는 개선 역할과 환류 구조를 확인했다. 자동 자기 개선 완료나 정량 병목 감소를 뜻하지 않는다. 어떤 판단을 규칙으로 전환할지와 그 검증은 여전히 전문가의 일이다.

## 네 사례에서 가져갈 경험

1. **부분 처리량과 전체 완료 속도를 구분한다.** 리뷰·인계·승인 대기까지 보아야 병목을 찾을 수 있다.
2. **자료보다 작업 단위의 연결을 만든다.** 관련 정보의 최신성·권한·완료 조건을 유지해야 재탐색을 줄일 수 있다.
3. **직접 연결에는 실행 경계가 따라야 한다.** 조회 가능과 변경 가능, 자율 실행과 승인 대기를 구분한다.
4. **반복 판단을 개선 재료로 남긴다.** 실행 기록만 쌓지 말고 전문가 진단과 검증을 거쳐 기준·도구로 바꾼다.
