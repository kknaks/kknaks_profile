# AI 생성 코드에 필요한 아키텍처 가드레일

> 출처: https://www.oreilly.com/radar/architectural-guardrails-for-ai-generated-code/ · 2026-08-31

## 요지

- AI가 만든 코드는 정상적으로 작동하고 테스트를 통과하더라도, 에이전트에게 전달되지 않은 조직의 아키텍처 결정을 위반할 수 있다.
- 저자는 이런 아키텍처 드리프트를 막으려면 ADR을 기계가 읽고 검색·주입·집행할 수 있는 구조화된 엔지니어링 거버넌스 계층이 필요하다고 주장한다.
- AI는 관련 결정을 찾거나 추천하는 데 활용할 수 있지만, 병합 차단과 경고의 근거는 명시적인 규칙과 코드 증거로 재현할 수 있어야 한다.
- 더 강력한 모델만 기다려서는 해결되지 않으며, 팀은 ADR의 최신성과 우선순위를 정비하고 경고·차단 정책을 명시적으로 선택해야 한다.

## 내용

기사는 고객 데이터 쓰기가 내부 서비스 API를 우회하면서 감사 로그가 누락된 가상의 사례로 문제를 설명한다. AI 에이전트가 작성한 340줄짜리 PR은 코드가 깔끔하고 테스트도 통과했지만, 2년 전 작성된 ADR에 명시된 직접 데이터베이스 접근 금지 결정을 위반했다. 현재 팀과 에이전트 모두 이 문서를 보지 못해 변경 사항이 배포됐고, 팀은 엔드포인트 재작성과 누락된 감사 기록 보완에 스프린트 대부분을 써야 했다.

저자는 이를 환각이나 모델 품질 문제가 아니라 조직 기억의 전달 실패로 규정한다. Faros AI가 2026년에 4,000개 이상의 팀과 개발자 22,000명 이상의 원격 측정 데이터를 분석한 결과, AI 코드 수용률이 20%에서 60%로 높아진 구간에서 추가된 지 며칠 안에 삭제된 코드의 비율인 코드 churn이 861% 증가했다. 다만 이 수치에는 재작업뿐 아니라 생산적인 리팩터링과 빠른 반복 개선도 포함될 수 있으므로, 저자는 아키텍처 드리프트를 가능한 원인 중 하나로 제시한다.

Cursor Rules나 CLAUDE.md 같은 자유 형식 지침은 우선순위·버전·수명주기와 위반 감지 체계가 부족하다. 린터와 포매터는 구문적 규칙에 머물고, 의존성 검사 도구는 취약점·라이선스·버전을 다루므로 조직 내부의 의미적 라우팅 결정을 판별하지 못한다. 두 번째 LLM을 이용한 코드 리뷰 역시 동일한 결정 기록에 접근하지 못하면 같은 사각지대를 공유한다. 인간 리뷰는 팀의 역사와 충분한 시간이 있을 때 작동하지만, 에이전트의 코드 생산량과 같은 속도로 검토 역량을 확장하기 어렵다.

저자가 제안하는 엔지니어링 거버넌스 계층에는 네 가지 기능이 필요하다. 첫째, 결정의 우선순위와 수명주기 메타데이터를 가진 구조화된 말뭉치를 유지한다. 둘째, 같은 코드에서 같은 관련 결정을 안정적으로 검색한다. 셋째, 코드를 작성하기 전에 그 결정을 AI 문맥에 주입한다. 넷째, CI에서 위반을 경고하거나 차단하고 그 결과를 특정 ADR·검색어·규칙까지 추적할 수 있게 한다.

검색과 추천에는 확률적 시스템을 사용할 수 있지만 최종 집행은 결정론적이어야 한다. 모든 판정은 저장된 코드, ADR, 검색 로그와 규칙 문구로 재구성되고 다른 사람이 재현할 수 있어야 한다. 이 계층은 자율 에이전트나 일반적인 RAG 메모리, 또 다른 AI 코드 리뷰가 아니며, Cursor·Claude Code·GitHub Copilot·Codex와 자체 호스팅 모델을 함께 쓰더라도 동일하게 적용되는 도구·모델 독립적 기반이어야 한다.

엔지니어링 리더에게는 이번 분기에 ADR의 최신 상태와 대체 관계를 점검하고, 위반 시 경고할지 병합을 차단할지 팀 차원에서 정하며, 차세대 모델이 해결해 주리라 가정하지 말라는 세 가지 조치가 제안된다.

## 맥락 — 왜 지금 이야기되나

AI 코딩 도구가 편집 보조를 넘어 구현·수정·리뷰·계획을 병렬로 수행하면서 코드 생산량은 빠르게 늘고 있다. 반면 팀이 오랫동안 축적한 아키텍처 결정은 사람이 읽는 ADR이나 프로젝트 지침에 흩어져 있어, 생성 시점의 문맥과 CI 집행 체계에 자동으로 연결되지 않는 경우가 많다. 기능적 정확성과 테스트 통과만으로는 시스템 전체의 설계 방향을 보존하기 어려워진 것이다.

이에 따라 AI 코딩 스택에는 생성 능력뿐 아니라 조직의 결정을 구조화해 사전에 전달하고 사후에 재현 가능한 방식으로 집행하는 계층이 필요하다는 논의가 부상한다. 규제 산업에서는 감사와 책임성의 요건이며, 일반적인 제품 조직에서도 장기적인 코드 품질과 고객 신뢰를 지키기 위한 문제로 다뤄진다.
