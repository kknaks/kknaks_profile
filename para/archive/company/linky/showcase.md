# 개요

해외 환자를 받는 의료 클리닉의 상담 창구는 나라마다 쓰는 메신저가 다르다. 일본은 LINE, 동남아는 WhatsApp, 글로벌은 Instagram·Facebook, 국내는 KakaoTalk 을 쓴다. 직원이 앱 여섯 개를 오가며 응대하면 누락과 지연이 생기고, 언어까지 갈리면 응대 품질이 사람마다 달라진다.

Linky 는 이 여섯 메신저의 수신·발신을 하나의 통합 인박스로 묶고, 그 위에 AI 상담 파이프라인을 얹은 플랫폼이다. 들어온 메시지는 언어를 감지해 실시간 번역되고, AI 가 클리닉별 시술 정보·말투·상담 스킬을 조합해 답변을 만든다. 사람은 모든 대화를 보지 않는다 — AI 가 답하기 어렵거나 답하면 안 되는 대화만 「신호등」이 골라 직원에게 넘긴다.

무게중심은 백엔드에 있다. 메시지 수신·발신 파이프라인, AI 응답 워커의 상태 기계, LLM 프로바이더 폴백, 대화기록 암호화와 전송 마스킹, 사용량·비용 추적이 그 안에 들어간다. 진행 방식은 문서 우선이었다 — 결정(decision) → 계약(spec) → 작업(work) 세 층으로 나누고, 스펙 50여 건이 각 기능의 외부 계약을 먼저 고정한 뒤 작업 단위로 구현을 발주했다.

# 기술스택

**백엔드 — FastAPI + SQLAlchemy 2.0 async**

메신저 웹훅 수신, LLM 호출, 번역, 외부 발송이 전부 I/O 대기다. 동기 프레임워크로는 워커가 대기에 묶인다. 전 구간을 async 로 세우고 DB 드라이버도 `asyncpg` 로 맞췄다. 엔진은 `lru_cache` lazy 팩토리로 두어, 테스트에서 워커별로 DB URL 을 갈아끼운 뒤에 엔진이 만들어지도록 했다 — 모듈 import 시점에 평가되면 병렬 테스트의 DB 격리가 깨진다.

**비동기 큐 — TaskIQ + RabbitMQ + Redis**

메시지 수신 응답과 AI 응답 생성을 분리해야 했다. 웹훅은 즉시 200 을 돌려주고, AI 한 턴(컨텍스트 조립 → 분류 → 프롬프트 → 툴 루프 → 발신)은 워커에서 돈다. 재시도가 붙는 큐라 멱등성이 필수였고, `(대화 ID, 답변 대상 메시지 ID)` UNIQUE 제약으로 중복 INSERT 를 DB 가 막게 했다.

**LLM — Anthropic SDK 직접 호출 (LangChain·LangGraph 미도입)**

프레임워크 추상화를 걷어내고 vanilla Python `Protocol` 로 `LLMClient` 인터페이스를 정의했다. 프로바이더별 응답 차이(tool_use 포맷, system 블록, finish_reason)는 각 어댑터가 흡수하고, 호출자는 `complete` 하나만 안다. 한 프로바이더 장애로 상담이 멈추지 않도록 `FallbackClient` 가 체인을 순차 시도하며, 체인 구성은 환경변수라 코드 변경 없이 바꾼다. RAG 도 쓰지 않았다 — 시술 지식은 클리닉이 직접 관리하는 카탈로그라 전량 프롬프트 주입이 더 정확하고 검증 가능했다.

**PostgreSQL + Alembic**

클리닉(테넌트) 루트 아래 사용자·고객·대화·메시지·카탈로그가 매달리는 구조라 관계형이 자연스러웠다. 시술 카탈로그를 다국어로 쪼갤 때는 JSONB 한 컬럼 대신 번역 테이블을 정규화했다 — 언어별 부분 갱신과 검색이 필요했기 때문이다. 마이그레이션은 신규 테이블 생성 → 백필 → 레거시 drop 을 별도 리비전으로 끊어, 한 사이클 운영 안정을 확인한 뒤 마지막 단계를 밟는 방식으로 롤백 비용을 낮췄다.

**프론트 — Next.js App Router + TypeScript + Tailwind + Zustand + shadcn/ui**

상담 데스크는 대화 목록·본문·고객 패널이 동시에 살아 있는 화면이라 서버 렌더보다 클라이언트 상태 관리 비중이 크다. 전역 상태는 Zustand 로 얇게 두고, 컴포넌트는 shadcn/ui 를 가져와 직접 소유하는 방식(복사 후 수정)으로 디자인 커스터마이징 여지를 남겼다.

**인프라 — Azure Container Apps / Managed PostgreSQL / Redis / Blob**

의료 상담 데이터를 다루므로 관리형 서비스로 백업·암호화·접근통제를 위임하고, 애플리케이션은 도메인 계약만 책임지도록 경계를 그었다.

# 주요기능

**통합 인박스**

- 6개 메신저(KakaoTalk · Telegram · Instagram · LINE · Facebook · WhatsApp)의 대화를 한 화면에서 응대
- 한 클리닉이 나라별로 운영하는 여러 메신저 계정을 같은 대시보드에 통합
- 메신저별·계정별·상태별 필터와 태그

**AI 상담**

- 지식(시술 정보) / 말투 / 상담 스킬 3레이어를 분리한 답변 생성 — 클리닉이 각 레이어를 따로 설정
- 나라별 응대 차이를 반영하는 문화 레이어
- 툴 사용 루프로 시술·가격·운영 정보를 카탈로그에서 조회해 답변에 반영
- 대화 누적 요약으로 장기 컨텍스트 압축
- 프롬프트 캐싱으로 반복되는 시스템 블록의 토큰 비용 절감
- 환자가 연속으로 메시지를 보내면 마지막 메시지까지 읽고 답변 1건으로 합쳐 발송

**번역**

- 채팅 본문 실시간 번역 — 직원은 한국어, 환자는 모국어로 같은 대화를 본다
- 언어 자동 감지
- 시술명·의학 용어는 용어집을 주입해 번역 흔들림 방지
- 시스템 안내 메시지 다국어 템플릿
- 번역 실패 시 발신 차단(fail-closed) — 잘못 번역된 의료 정보가 나가지 않게

**신호등 — AI ↔ 직원 인계**

- 컴플레인·부작용·환불처럼 사람이 받아야 할 대화를 AI 가 분류해 직원에게 인계
- 위험 판단 기준과 감지 키워드를 클리닉이 직접 편집
- 인계 시 AI 자동 응답을 끄고 직원에게 알림, 대화 목록 상단으로 끌어올림
- 직원이 수동으로 대화를 가져오는 것도 가능

**시술 카탈로그**

- 시술·제품 카탈로그와 다국어 콘텐츠 관리
- 엑셀 양식으로 일괄 등록(검증 후 반영)

**클리닉 운영**

- 상담 매뉴얼, 응대 페르소나(톤·금지 표현·인사말) 설정
- 고객 정보 패널 — 상담 중 고객 정보 확인·수정
- 조직 멤버·지점 프로필 관리, 역할 기반 권한
- 직원 간 내부 채팅
- LLM 사용량·비용 대시보드와 대화 단위 비용 조회
- 구독·크레딧 결제, 사용량 차감, 크레딧 원장과 환불

**개인정보 보호**

- 대화 본문 저장 시 암호화
- AI·번역·로그로 나가는 데이터의 식별정보 마스킹과 복원
- 보관기간 경과 데이터 자동 파기
- 고객 데이터 열람·수정·삭제에 대한 감사 로그
