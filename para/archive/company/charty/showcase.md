# 개요

의료 상담 현장에서 오가는 대화를 그 자리에서 텍스트로 바꾸고, AI 가 곧바로 구조화된 진료 차트로 만들어 주는 웹 서비스다. 상담을 하면서 차트를 쓰면 대화에 집중할 수 없고, 상담이 끝난 뒤 기억으로 되짚어 쓰면 빠지거나 틀리는 항목이 생긴다. 이 둘 사이의 손실을 없애는 것이 제품의 출발점이었다.

브라우저에서 상담을 시작하면 음성이 실시간으로 전사되고, 전사문은 도메인 용어 보정을 거쳐 화면 왼쪽에 쌓인다. 상담이 끝나면 그 전사문 전체가 LLM 에 들어가 핵심 요약·고객 프로필·시술 상세·가격 안내로 나뉜 차트가 된다. 상담 중에도 발화에서 시술 키워드를 감지해 가격표를 옆에 띄우고, 함께 하면 좋은 시술을 한 건 추천한다. 결과물이 "텍스트 덩어리"가 아니라 그 업종의 차트 양식이라는 점이 범용 받아쓰기 도구와 갈리는 지점이었다.

여기에 외국인 환자 상담을 위한 통역 모드가 얹혔다. 발화별로 언어를 가려내 한국어는 그대로 두고 외국어만 한국어로 번역해 자막으로 보여 준다. 번역된 한국어만 차트 입력으로 들어가므로, 통역을 끼고 진행한 상담도 결과물은 한국어 차트 한 장으로 동일하게 떨어진다. 이후에는 구독·결제와 사용량 기반 크레딧 과금까지 붙어 상용 서비스 형태를 갖췄다.

# 기술스택

**백엔드 — Python + FastAPI + PostgreSQL**

실시간 음성 스트림과 LLM 호출이 동시에 도는 서비스라 I/O 대기가 대부분이다. async 를 기본으로 쓰는 FastAPI 와 SQLAlchemy 2.0 async 세션으로 통일했고, 스키마 변경은 Alembic 마이그레이션으로만 반영해 코드와 DB 를 한 방향으로 묶었다. 라우터 / 서비스 / 리포지토리 계층을 분리해, 라우터가 세션을 직접 만지거나 비즈니스 규칙을 들고 있는 형태를 없앴다.

**프론트엔드 — React + TypeScript + Vite**

한 화면에서 전사·차트·가격·통역 자막이 동시에 갱신되는 구조라 상태 관리를 두 갈래로 나눴다. 서버에서 오는 데이터(가격표·사용량·차트 이력)는 TanStack Query 로 캐시와 무효화를 맡기고, 화면 안에서만 사는 상태(상담 진행 상태, 전사 누적, 설정 바 값)는 Zustand 스토어로 뒀다. 서버 상태와 UI 상태를 한 스토어에 섞지 않은 것이 상담 중 잦은 갱신에서 리렌더 범위를 좁히는 데 결정적이었다.

**STT · 번역 — 스트리밍 STT + 번역 모델 분리**

처음에는 음성을 넣으면 번역까지 한 번에 돌려주는 번들 모델을 검토했다. 실측해 보니 발화별 언어가 식별되지 않고, 원문과 번역의 짝이 어긋나며, 한국어까지 강제로 번역되는 문제가 한꺼번에 나왔다. 그래서 **전사 → 언어 판별 게이트 → 번역** 세 단계로 쪼갰다. 한국어 발화는 게이트에서 걸러져 번역 호출 자체를 하지 않기 때문에, 같은 입력 기준 호출 비용이 번들 방식 대비 크게 떨어졌고 자막의 원문·번역 쌍도 안정됐다.

짧은 발화의 언어 자동 감지는 오판이 잦았다. 특히 라틴 문자 계열 언어는 문자만으로 구분이 되지 않았다. 그래서 상담 시작 시 환자 언어를 고르게 하고 자동 감지는 보조 수단으로 내렸다. 지원하지 않는 언어가 들어오면 잘못된 언어 라벨을 붙이는 대신 라벨을 아예 감추도록 했다 — 틀린 정보보다 정보 없음이 낫다는 기준이었다.

**LLM — 모델 교체 가능한 추상화 + 폴백**

차트 생성은 초기에 Anthropic Claude API 를 직접 호출했고, 이후 전사 인프라 일관성을 위해 Azure OpenAI 로 옮겼다. 옮기면서 AI 호출부를 프로바이더 추상화 뒤에 두고 환경변수로 전환하도록 만들어, 마이그레이션 중에도 이전 경로를 롤백 안전망으로 남길 수 있었다. 모든 호출에는 폴백을 필수로 뒀다 — 1차 모델이 5xx·타임아웃이면 경량 모델로 재시도하고, 폴백이 동작했다는 사실 자체를 알림으로 흘려 연쇄 장애를 조기에 본다.

콘텐츠 필터가 상담 원문을 오탐 차단하는 경우는 폴백으로 풀리지 않는다(같은 입력이면 다른 모델도 똑같이 막힌다). 그래서 이 예외만 따로 식별해 기능별로 다르게 흡수했다 — 추천은 배너를 조용히 생략, 차트 생성은 안내 문구와 함께 무과금 처리, 통역은 해당 발화만 건너뛰고 세션은 유지. 예외 하나가 통역 세션 전체를 끊어 버리던 문제가 여기서 정리됐다.

**용어 정확도 — 사전 우선, LLM 은 fallback**

의료 시술명은 LLM 번역에 맡기면 같은 시술이 상담마다 다른 이름으로 나온다. 별도로 관리하는 시술 용어 사전을 백엔드에서 캐싱해 두고(TTL 24시간 + 명시적 무효화), 발화에서 시술 토큰을 뽑아 사전에 맞으면 그 값을 번역 프롬프트에 고정값으로 주입한다. 사전에 없으면 그때만 LLM 번역에 맡긴다. 전사 단계에서도 같은 사전을 힌트로 넣어 비슷한 발음의 시술명이 뒤바뀌는 것을 줄였다.

# 주요기능

**상담 진행**

- 브라우저에서 바로 녹음 시작 — 별도 설치 없이 마이크 권한만으로 상담 개시
- 상담 유형·차트 스타일·템플릿(첫방문/재방문)·목표 시간을 상담 전에 지정, 시작 후에는 잠금
- 전사문 키워드로 상담 8단계(인사 → 문진 → 고민 → 추천 → 설명 → 주의사항 → 가격 → 마무리) 진행률 표시
- 목표 시간 초과 시 배너 경고
- 좁은 화면에서는 단일 컬럼 팝업 모드로 자동 전환 — 상담 데이터·설정은 그대로 유지

**실시간 전사 · 통역**

- 발화 단위 자막 누적, 인식 중인 문장은 반투명으로 미리 표시
- 통역 모드 — 환자 언어를 고르면 외국어 발화만 한국어로 번역해 자막에 표시, 원문 보기 토글 제공
- 한국어 발화와 외국어 발화를 색으로 구분한 카드 UI + 언어 태그
- 일시정지는 "입력 중단" 으로 정의 — 정지 직전까지 처리 중이던 발화는 유실 없이 재개 후 표시

**AI 차트**

- 상담 종료 시 구조화 차트 자동 생성 — 체크리스트 / 차트 / 원본 텍스트 3탭
- 생성된 차트 직접 편집·복사, 새 상담으로 초기화
- 상담 중 추가 시술 추천 배너 — 전사문이 일정 길이 이상 쌓일 때마다 디바운스 호출
- 통역 상담도 차트 입력은 한국어로 통일 — 외국어 원문은 차트에 들어가지 않는다

**가격 · 시술**

- 시술 가격표 엑셀 업로드(관리자·매니저 한정), 양식 다운로드 제공
- 전사문에서 시술명을 유사도 매칭으로 감지해 "감지됨" 목록에 누적 — 조사가 붙은 형태도 정규화해 매칭
- 감지된 시술의 상세 정보 패널 (사전 데이터 우선, 없을 때만 AI 보완)
- 시술 카트 담기 + 환율 연동 가격 표시, 재방문 템플릿 선택 시 첫방문 전용 항목 자동 제외

**계정 · 권한**

- 지점 단위 멀티 테넌시, JWT HttpOnly 쿠키 인증(access + refresh) + 만료 시 안내 후 재로그인
- 관리자 / 매니저 / 스태프 3단 역할 — 역할별로 노출 화면과 계정 관리 범위가 갈린다
- 플랜별 계정 수 한도, 한도 초과 시 안내
- 크롬 전용 접근 제한 — 미지원 브라우저는 안내 화면으로 차단

**구독 · 과금**

- 카드 없이 시작하는 무료 체험 → 카드 등록 후 유료 전환, 정기 결제
- 플랜 변경·해지·재개, 청구 내역과 동의 이력 조회
- 사용한 만큼 차감하는 크레딧 과금 — 차감은 AI 원가가 실제로 발생하는 지점(차트 생성 / 통역 분당)에서만
- 부분 게이팅 — 잔액이 부족해도 전 화면을 막지 않고 원가가 드는 동작만 차단
- 모든 크레딧 증감을 append-only 원장에 남겨 사용자 내역 화면·정산 대조의 단일 근거로 사용
