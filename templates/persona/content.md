# 교안 양식

`persona/contents/C-NNN.md` 의 형식을 정의한다. **이 파일이 교안 형식의 SoT다.**

교안을 만드는 경로는 둘이다 — 승인 게이트(`derived` 스테이지)와 기존 `content_enrich` 잡.
둘 다 여기를 읽어 프롬프트를 만든다. 형식을 고치려면 **이 파일만** 고친다.

> 지식 노트(`reference`·`concept`·`permanent`)는 계열이 다르다 — `templates/knowledge/` 와
> `rules/knowledge-note-pipeline.md` 를 따른다. 교안은 그래프 밖(`persona/contents/`)이라
> 4층 모델의 적용 대상이 아니다.

## 목표

**외부 사람이 영상을 안 보고도 이 문서만으로 이해·학습할 수 있어야 한다.**
영상 요약이 아니라 교안이다. 짧게 압축하지 말고 학습 가능한 수준으로 쓴다.

## 결정할 필드

| 필드 | 규칙 |
|---|---|
| `title` | 한국어/영어 각각. 60자 이내. 원본 제목보다 **간결·구체적으로** |
| `summary` | 핵심 한 줄. 한국어/영어 각각 80자 이내 |
| `tags` | 기술 스택·키워드 3~7개. 소문자 + `#` 접두 (예: `#fastapi`) |
| `concept` | 핵심 개념 문장 **4~6개**. 본문 설명을 한 줄씩 압축한 형태(사이트 카드용) |
| `kind` | `tutorial` · `study` · `talk` · `review` 중 하나 |
| `body` | 아래 8개 H2 섹션 |

`kind` 판정:

- `tutorial` — 따라하면 무언가 만들어지는 hands-on 가이드 (코드 예제 위주)
- `study` — 개념·이론 학습 (요약·해설 위주, 코드는 보조)
- `talk` — 발표·강연·인터뷰 (의견·경험 공유 위주)
- `review` — 도구·라이브러리·기술 리뷰 (장단점 평가)

모호하면 `study`.

## 본문 섹션 — 순서대로 빠짐없이

```text
## 개요
   주제와 왜 중요한지 (1~2문단). 독자가 왜 이 글을 읽어야 하는지.

## 배경 / 사전 지식
   이해에 필요한 선수 지식·용어 정의. 모르는 사람도 따라올 수 있도록.

## 핵심 개념
   단락별 정의 + 작동 원리. 개념별 H3 분리 권장.

## 작동 원리
   단계별 설명 (numbered list 또는 시퀀스 식).

## 코드 예시
   실행 가능한 코드 최소 1개 블록 + 각 블록의 의미 설명.

## 함정·실수
   흔히 빠지는 실수 + 회피법. 영상에서 짚은 것 + 일반적인 함정.

## 베스트 프랙티스
   권장 패턴, 대안, 더 나아가는 팁.

## 참고
   영상에서 언급된 추가 자료·링크. 없으면 "(영상 내 명시 없음)".
```

영상에 명시되지 않은 항목은 자막에서 합리적으로 추론하거나 일반적으로 알려진
베스트 프랙티스로 채운다. **섹션을 비워 두지 않는다.**

## 시스템이 매기는 값 — AI 가 정하지 않는다

`id`(`C-NNN`) · `date` · `day`(`Day NN`) · `duration` · `speaker` · `transcript` ·
`enriched_at` · `status`.

특히 `id` 와 `day` 는 **기존 파일을 세어** 부여한다. AI 에 맡기면 중복 번호가 나온다.

`status` 는 승인 게이트 산출물의 경우 **`published`** 다. `pending` 을 쓰면
`content_enrich` 잡의 스캔 대상이 되어 한 번 더 덮어쓰인다.
