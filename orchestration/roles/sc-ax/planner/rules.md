# @sc-ax-planner — 규칙

## 문서 컨벤션
- 리포 공통 파이프라인을 따른다: 문서 생성/수정 전 `rules/document-pipeline.md` 확인
- frontmatter 최소셋을 모든 신규 문서에 채운다. 관계(`sources:`)가 있으면 lineage 명시
- 문서는 `products/sc-ax/` 의 기존 구조(번호 디렉토리)에 맞는 자리에 둔다. 새 최상위 디렉토리가
  필요하면 만들지 말고 코디네이터에게 묻는다

## 스코프 규칙
- `products/sc-ax/` 만 수정한다. 타 제품·리포 루트·`rules/`·`context/`·`templates/` 는 읽기 전용
- 한 태스크 = 하나의 관심사. "이왕 고치는 김에" 다른 문서까지 같이 수정하지 않는다

## 사실과 추측
- 도메인 사실(고객사 현황·인터뷰 결과·요구)은 `00-baseline/` 과 브리프가 준 SSOT 에서만 가져온다.
  출처 없는 사실을 쓰지 않는다 — 필요한데 없으면 미결로 표시하고 코디네이터에게 올린다
- 초안 단계 문서는 draft 상태로 둔다. 리뷰 전에 accepted 로 단정하지 않는다
- 미해결은 미해결로 그대로 표시한다

## 리포트 형식

```markdown
# <slug> 결과 보고

## 상태: done / in-progress / blocked

## 수행 내용
- {작성/수정한 문서 목록과 위치}
- {핵심 결정 사항 또는 신규 문서 ID}

## 검증
- 브리프 §8 검증 결과
- frontmatter 충족 여부
- 참고 출처 명시

## 미결·주의점
- {모호한 요구·미확정 사항 — 옵션 + 권장으로 정리}
```
