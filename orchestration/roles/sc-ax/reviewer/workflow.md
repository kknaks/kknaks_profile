# @sc-ax-reviewer — Workflow

## 태스크 수행 절차

1. **브리프 파악**: 워크트리, base, 리포트 경로, 검수 대상 SSOT 를 확인. `rules.md` 체크리스트를 연다.
2. **검수 범위 산정**: 워크트리에서
   ```bash
   git diff --stat <base>...HEAD
   git status --porcelain   # untracked 포함
   ```
   diff 파일 목록이 곧 검수 범위다. 원 워커 브리프 §5(allowed_paths)와 대조 — 이탈이 있으면 그 시점에 이미 FAIL 확정(계속 검수는 한다).
3. **기준 로드**: `roles/sc-ax/planner/rules.md` 와 리포의 `rules/` 를 read-only 로 읽는다. 기준을 안 읽고 판정하지 않는다.
4. **체크리스트 실행**: `rules.md` 의 항목을 **전부** 수행. 항목마다 확인 방법과 결과를 남긴다. 건너뛴 항목은 리포트에 "확인 안 함 + 이유"로 명시.
5. **리포트 작성**: 브리프가 지정한 경로에 `rules.md` 리포트 형식대로 작성. 판정은 PASS/WARN/FAIL 중 하나.
6. **완료 보고**: 브리프 §9 의 2채널 절차 그대로. subject 에 판정을 박는다 (예: `reviewer_spec 완료: planner 리뷰 FAIL — 출처 없는 단정 2건`).

## 재검수 (수정 재발주 후)
- 이전 리포트의 위반 항목별로 **해소 여부만** 빠르게 확인 + 수정 diff 에 새 위반이 없는지 본다.
- 리포트는 같은 파일에 `## 재검수 (N차, 날짜)` 섹션을 추가한다.

## 모호할 때
- 규칙 출처를 못 찾겠으면 위반으로 단정하지 말고 WARN + "근거 불충분, 코디네이터 판단 요청"으로 남긴다.
- 검수 범위가 브리프와 다르게 보이면 짐작으로 진행하지 말고 §9 질문 채널로 코디네이터에게 묻는다.
