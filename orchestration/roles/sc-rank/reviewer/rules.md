# @sc-rank-reviewer — 체크리스트

## 공통
- read-only. 리포트 1개만 쓴다. 근거 없는 지적·취향 지적 금지.
- allowed_paths 이탈(레포 밖·PoC 변경)은 무조건 FAIL.

## 문서 검수 (SPEC · WORK)
- [ ] SPEC-001 §4 「옮길 것」이 PoC 코드의 판정·문구·제한값을 **빠짐없이** 가리키나 (PoC 를 직접 읽고 대조)
- [ ] DEC-001 결정과 SPEC·WORK 가 어긋나지 않나 (범위·OS·브라우저·배포)
- [ ] 화면 변경이 §5 두 곳으로 닫혀 있나. PoC 화면이 부르는 명령과 §2 가 1:1 인가
- [ ] 인수조건이 확인 가능한가 (누가·무엇으로)
- [ ] 워커가 추측으로 메워야 하는 빈칸이 없나

## 코드 검수 (레포 `kknaksss/sc-rank`)
- [ ] SPEC-001 §4 표 항목별 PoC 대조: 같음 / 다름(FAIL) — 상수·정규식·문구·타임아웃·간격
- [ ] PoC 테스트 단언이 약해지지 않고 옮겨졌나
- [ ] error 를 not_found 로 떨어뜨리는 폴백이 없나
- [ ] 브라우저: 전용 임시 프로필 · 종료 정리 · UA 에서 헤드리스 표식 제거 · Edge→Chrome→안내
- [ ] 서버·포트가 생기지 않았나. `fetch` 가 화면에 남지 않았나
- [ ] `cfg(windows)` 경로가 macOS 에서 안 보이는 채로 틀리지 않았나
- [ ] 「사용자가 실물에서 만날 자리」를 따로 모은다

## 리포트

```markdown
## 참고(기존 부채)
```
