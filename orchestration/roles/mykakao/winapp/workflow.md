# @mykakao-winapp — Workflow

1. **시작**: 브리프의 워크트리·base 확인. cargo 동작 확인(`cargo --version`, 없으면 PATH 추가).
2. **입력**: SPEC-003(계약 SoT)·spike3 참조 코드·KEY_REPORT.md(파라미터)를 읽는다. 브리프가 유일한 입력.
3. **스캐폴드**: `win_app/` 크레이트 생성(Cargo.toml + 모듈 골격). 최소 크레이트로 시작.
4. **복호 코어 먼저**: 메모리 키 회수 + 페이지 복호 → 평문 SQLite. 순수 함수는 테스트로 검증(합성 픽스처).
5. **저장·API**: rusqlite 축적 + axum 엔드포인트(SPEC-003 계약대로).
6. **FE**: `ui/` 설정 3섹션 + 2-pane. 계약 키/이벤트명 그대로.
7. **검증**: `cargo build`(에러 0) + `cargo test`. 실기동(카톡 대상 실복호)은 **코디가** 한다 — 못 하는 건 못 했다고 보고.
8. **보고**: 브리프 §9 의 2채널. 커밋·PR 없음.

## 모호할 때
- 계약·빌드전략·크레이트 추가가 갈리면 임의 결정 말고 질문 채널로. 특히 **복호 전략이 막히면 즉시 보고**.
