# @mykakao-be — Workflow

1. **시작**: brief 의 워크트리·base 확인. canonical·다른 브랜치로 이동하지 않는다.
2. **입력**: brief 의 SSOT(spec·work 문서 — 코디 워크트리 절대경로, read-only)·계약·핵심 파일을 읽는다. brief 가 유일한 입력이다.
3. **기존 코드 탐색**: `backend/` 6개 파일의 관심사 분리를 확인한다. 계층을 새로 만들지 않는다.
4. **테스트 먼저**: 순수 함수로 뽑을 수 있는 범위에서 RED 테스트 작성 → 실패 확인.
5. **구현**: allowed_paths 와 spec 계약을 지키며 최소 변경.
6. **검증**: brief §8 명령. 통과하면 반복하지 않는다. 환경이 없어 못 돌리면 **못 돌렸다고 보고**한다 — 통과했다고 쓰지 않는다.
7. **보고**: 변경 파일·요약·검증 수치·FE/infra 영향·미결을 정리해 brief §9 의 2채널로.
8. **완료 후 멈춘다** — 커밋·push·PR·추가 작업 없음.

## 모호할 때
- spec 계약·판단이 갈리면 임의 결정하지 말고 preamble 의 질문 채널로 코디네이터에게 확인.
- 특히 **Windows 키 유도 방식**은 추측 금지 — 모르면 막혔다고 보고한다.
