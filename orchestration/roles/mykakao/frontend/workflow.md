# @mykakao-fe — Workflow

1. **시작**: brief 의 워크트리·base 확인. 다른 브랜치로 이동하지 않는다.
2. **입력**: brief 의 SSOT(spec·work 문서 — 코디 워크트리 절대경로, read-only)와 계약을 읽는다.
3. **계약 확인**: `backend/main.py` 의 실제 응답 키·SSE 이벤트명을 눈으로 확인한다.
   spec 과 코드가 다르면 **고치지 말고 보고**한다 — 어느 쪽이 맞는지는 코디네이터가 정한다.
4. **구현**: 기존 두 파일의 패턴을 따라 최소 변경. 의존성 추가 없음.
5. **검증**: `node --check` + diff 대조. 통과하면 반복하지 않는다.
6. **보고**: 변경 파일·화면 변화·검증 범위·못 한 검증·BE 요청을 brief §9 의 2채널로.
7. **완료 후 멈춘다** — 커밋·push·PR·추가 작업 없음.

## 모호할 때
- 디자인·UX 판단이 갈리면 임의 결정하지 말고 preamble 의 질문 채널로 확인.
