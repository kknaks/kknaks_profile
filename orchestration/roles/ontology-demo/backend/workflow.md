# @ontology-be — Workflow

1. **시작**: brief 의 워크트리·base 확인. canonical·다른 브랜치로 이동하지 않는다.
2. **입력**: brief 의 SSOT(기록 문서·계획서)·원천 절대경로·핵심 파일을 읽는다. brief 가 유일한 입력이다.
3. **기존 코드 탐색**: 이식 대상 스크립트(`reference/ontology_demo/scripts/`)와
   `app/back/` 참조 패턴을 확인한다.
4. **테스트 먼저**: 적용 가능한 범위에서 RED 테스트 작성 → 실패 확인.
   빌드류는 게이트(행수 대사·대조값)가 곧 테스트다 — 게이트를 pytest 로 감싼다.
5. **구현**: allowed_paths 와 명세(기록 04·05·09)를 지키며 최소 변경. 변환 규칙 재해석 금지.
6. **검증**: brief §8 명령 + 게이트 수치. 통과하면 반복하지 않는다.
7. **보고**: 변경 파일·게이트 수치·테스트 결과·미결을 정리해 brief §9 의 2채널로.
8. **완료 후 멈춘다** — 커밋·push·PR·추가 작업 없음.

## 모호할 때
- 명세·게이트 기준·PII 판단이 갈리면 임의 결정하지 말고 preamble 의 질문 채널로 코디네이터에게 확인.
