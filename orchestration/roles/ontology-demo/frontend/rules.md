# @ontology-fe — 규칙

## 이 데모의 원칙 (위반 = FAIL)
- **`globals.css` 를 수정하지 않는다.** 데모 토큰은 라우트 그룹 레이아웃의 컨테이너 스코프에
  `--ont-*` 접두로 선언하고 `color-scheme: light` 를 재선언한다(SPEC-004 토큰 레이어 계약).
  값의 SoT 는 디자인 `01-tokens.md` — 창작 금지.
- **PII** — 화면·로그·테스트에 실명·전화·생년월일 원값 0건. 마스킹 표기는 SPEC-001
  (김○○ / 010-****-1234 / 1990-**-**) 그대로. 언마스킹 UI 를 만들지 않는다.
- **파생 카운트 하드코딩 금지** — 기준일 배지·탭 카운트·범례 개수·「그 외 KPI」 등
  SPEC-004 파생 표의 전 항목은 API 응답에서 파생한다. 시안의 숫자를 박으면 FAIL.
- **「실시간」 표방 금지** — 일 배치. 기준일은 `as_of` 파생.
- 채팅은 **2초 폴링**(SPEC-003) — 스트리밍·WS 를 도입하지 않는다.
- 답변 그래프 하이라이트는 **칩 + `?edge=` 모니터링 점프** — 채팅 안 미니그래프 금지(확정).

## 코딩 컨벤션
- 기존 `app/front/` 패턴이 규약이다 — 인라인 style + 토큰 var, 서버 컴포넌트 우선,
  상호작용만 "use client", API 호출은 `lib/` 패턴. 새 CSS 프레임워크·상태 라이브러리 금지.
- 그래프는 고정 좌표 정적 SVG(viewBox 0 0 1130 560)가 기본 — d3-force 필수 아님.
- 프로토타입(.dc.html)·support.js 는 참조물 — 코드·의존으로 가져오지 않는다.
  **문서·data/*.json 이 프로토타입보다 이긴다**(일부 프로토타입은 옛 데이터).

## 스코프 규칙
- allowed_paths(`app/front/`) 안에서도 기존 포트폴리오 파일 수정 금지 — 라우트 그룹
  신설 + 전용 파일만. 공용 파일을 바꿔야만 하면 멈추고 질문.
- git commit·push·PR 금지 — 워크트리에 변경만 남긴다.
