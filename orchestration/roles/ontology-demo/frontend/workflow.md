# @ontology-fe — Workflow

1. **시작**: brief 의 워크트리·base 확인. 같은 워크트리에 BE 워커가 병렬일 수 있다 —
   `app/front/` 밖을 건드리지 않으면 충돌하지 않는다.
2. **입력**: brief 의 SSOT(SPEC-004·003·001·005 + 디자인 패키지)를 읽는다.
3. **phase 순서대로**: 셸·토큰 레이어·게이트 화면 → 모니터링 → 데이터 → 채팅.
   phase 마다 tsc·렌더 확인 후 [진행] 채널로 보고.
4. **API 가 아직 없으면** brief 가 지정한 mock 전략(고정 픽스처, SPEC-003 shape 그대로)으로
   선행하고, 실 API 연결 지점을 한 곳(lib)으로 모은다 — 나중에 스위치 한 번으로 전환되게.
5. **검증**: brief §8 (tsc + build 1회). 라우트 3종 렌더 확인.
6. **보고**: 변경 파일·phase 상태·계약 준수 자체 점검을 §9 의 2채널로.
7. **완료 후 멈춘다** — 커밋·push·PR·추가 작업 없음.

## 모호할 때
- 디자인 ↔ spec 이 어긋나면 **spec 이 이긴다** — 임의로 고르지 말고 보고.
- 공용 파일을 바꿔야만 하는 상황이면 멈추고 질문 채널로.
