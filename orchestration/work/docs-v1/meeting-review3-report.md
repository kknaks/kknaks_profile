| 시안 | `회의록.dc.html` L1693 — 근거 칩 「**09:34 – 09:36**」. 같은 화면 헤더 L1642 「09:30 – 10:30」, 스크립트 타임스탬프 L1778 `09:33` · L1786 `09:34` · L1795 `09:36` · L1803 `10:02` · L1811 `10:18`. 전부 **벽시계 시각**이고 회의 구간(09:30–10:30) 안에 들어간다 |
| 문서 | `meeting.md` L60 (M-11) — 「`at_ms` 는 **회의 시작 기준 오프셋**이다. 근거 칩의 `evidence` 도 같은 기준이라 **벽시계 시각과 섞지 않는다**」 / `spec-008` L339 「`evidence` … **회의 시작 기준 오프셋**이다(M-11)」 / `spec-008` L294 예시 `{"fromMs": 2040000, "toMs": 2160000}` = **34분 00초 ~ 36분 00초** |
| 종류 | **값이 다름** |
| 영향 | 시안대로 그리면 칩·스크립트 라벨을 **벽시계로 렌더**해야 하고, 그러려면 `meeting.start_at` + 오프셋을 매번 더해야 한다. SPEC 예시(`2040000ms` = 34분)를 그대로 「09:34」로 읽으면 **표시가 30분 어긋난다** — 09:30 시작 회의의 34분 오프셋은 **10:04** 다. 저장 기준(오프셋)과 표시 기준(벽시계)의 변환 규칙이 어디에도 없다 |

## 시안에 없어서 정해야 하는 자리

- **근거 칩·스크립트 라벨의 표시 기준** — 저장은 오프셋(M-11), 시안은 벽시계. 둘을 잇는 변환 규칙이 SPEC 에도 ERD 에도 없다 (M-1)
- **읽기 모드 프롬프트 바의 계약** — 존재 여부부터. 남긴다면 「/ 로 종류 선택」 팝오버 규격(종류 4종 목록·안건 셀렉터 팝오버)이 시안에도 SPEC 에도 없다 (M-2)
- **안건 상태의 허용값과 전이** — `done` 말고 「다음으로」에 해당하는 값, 체크박스를 읽기 모드에서 누를 수 있는지, 어느 요청으로 나가는지 (M-4)
- **변경 예정 칩의 값 포맷과 개수 상한** — 「기한 08.29」·「상태 완료」·「메모 추가」 셋이 동시에 붙을 때의 배치 (M-3)
- **통합본 생성 시각** — 시안이 표시하는데 응답 계약에 필드가 없다 (M-13)
- **동적 유형의 색을 헤더 부제에 싣는 방법** — 시안이 색 없는 평문이라 배지로 바꿀지 평문에 색만 줄지 (M-9 · M-14)
- **드로어 안 인라인 오류 표시 규격** — `invalid_pending_change`·`invalid_work_type` 이 이 형태를 요구하는데 그림이 없다 (M-17)
- **회의 상세 드로어(840) 전체** — SPEC U-8 이 문장으로만 있고 §B-3 미설계 목록에도 빠져 있다 (M-8)

## 판단하지 않은 것

- **정정 §A-5(2트랙 → 통합본)가 이 범위에서 어긋남을 만드는지** — 시안의 회의록 탭은 「줄 + 상세 설명 + 근거 칩」(L1687~1697)을 그리는데, 이 그림은 폐기된 단일 트랙 모델과 확정된 `merged` 트랙 **양쪽 모두에 맞는다**. 트랙 구분이 화면에 드러나야 하는지(예: `sourceHumanLineId` 가 있는 줄과 없는 줄의 구분 — SPEC L302)를 SPEC 이 요구하지 않아 어긋남으로 세지 않았다
- **정정 §A-8(AI 요약 탭 트리)·§A-11(첨부 v1 md 만)** — 두 탭 모두 내 범위에서는 **탭 머리만** 보이고(L1459 「AI 요약」 · L1555 「첨부 파일 3」) 선택된 내용 화면이 없다. 내용이 없으므로 대조할 것이 없다
- **드로어 스크림 불투명도** — 시안 `rgba(30,30,30,0.32)`(L2253·L2517·L2811)인데 SPEC 이 값을 주는 것은 **모달**뿐이고(L90 `rgba(30,30,30,0.36)`), FE §6-2 L367 은 「`DrawerFrame` 이 고정한다」고만 적어 **비교할 문서 값이 없다.** 값 대조가 불가능해 제외
- **시안 표본 데이터의 내부 모순 2건** — ⓐ 헤더가 「60분」(L1437)인데 스크립트 푸터는 「전체 스크립트 **12분** · 화자 2명」(L1602) ⓑ 근거 칩 2개 중 「09:41 – 09:42」(L1694)에 대응하는 발화가 스크립트에 없다(L1778·L1786·L1795·L1803·L1811 = 09:33·09:34·09:36·10:02·10:18). 표본 값의 문제이고 규격을 가리키지 않아 어긋남으로 세지 않았다
- **근거 펼침 시 강조 구간이 하나뿐인 것** — 칩은 둘(L1693·L1694)인데 스크립트 강조는 09:34 하나(L1782 `#F4F5FF` + `1px #C9D1FB`). 「칩 하나를 누른 상태」를 그린 것인지 「펼치면 전부 강조」인지 시안만으로 갈리지 않는다. SPEC L128 은 「근거 칩 **클릭** → 그 구간으로 스크롤·강조」라 칩 단위로 읽히지만, 펼침만 한 상태의 강조 여부는 정해져 있지 않다
- **액션 아이템 드로어의 이름** — 시안 헤더는 「**업무 생성**」(L2816) + 부제 「액션 아이템을 내 업무로 등록합니다」(L2817)이고 푸터 CTA 도 「업무 생성」(L2872). SPEC 은 드로어를 「**액션 아이템 추가**」로 부르고 CTA 만 「업무 생성」이다(L151). 드로어 제목의 계약이 SPEC 에 없어 어긋남으로 세지 않았다
- **연관 업무 드로어 이름** — 시안 「**연관 업무 연결**」(L2522) vs SPEC 「**연관 업무 추가**」(L150). 위와 같은 이유
