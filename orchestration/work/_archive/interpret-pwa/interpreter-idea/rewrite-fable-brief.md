0. **결론** — 추천 요금제 1개 · 가격(원 단위 · 무엇당) · 이유 3줄 · 적정 케이스 고객의 월 청구액과 원가 · 마진 · 월 2만원과의 관계 한 줄.
1. **적정 케이스 가정 표** (위 표 — 사용자가 이 표만 고치면 결론이 바뀐다고 명시)
2. **원가 함수** — 식 · 단위 · 실측 2건 대입 확인(짧게)
3. **적정 케이스 원가** — 1시간 원가(상담 · 간단 · 섞음) → 월 원가. 단계별 식
4. **요금제 3안 — 적정 케이스 기준** — 각 안의 과금 공식 · 마진 m 을 지키는 가격 · 고객 월 청구액 · 마진. 정액제는 「포함량」이 필요하면 적정 케이스 사용량 기준으로.
5. **민감도 — 변인 1개만 움직이고 나머지는 적정 케이스 고정** — 변인마다: 범위 끝에서 월 원가 · 각 요금제 마진(그 가격 그대로일 때). **어느 값에서 적자로 넘어가나**(변인 단위로). 그래프는 변인별 「월 원가 vs 각 요금제 월 매출」 — 범례 · 축 단위 필수.
6. **결론을 뒤집는 것** — 2 ~ 3개 한 줄씩.
7. **정할 것 · 조사할 것** — 마진율 · 환율 · 수동 stop 정책 · 실사용 데이터 수집.

## 9. 완료 보고 — **문구 변경 금지**

> **⚠ 핸들은 dispatch preamble 의 값을 믿어라.** 아래 명령에 박힌 코디handle 은 **브리프 작성 시점** 값이라 오래됐을 수 있다 — 세션이 재연결되면 핸들이 바뀐다(2026-07-28·29 두 번 겪음). preamble 의 코디네이터 핸들과 아래 값이 다르면 **preamble 이 맞다.** 두 곳에 다 보내지 말고 preamble 쪽으로만 보내라.


- **커밋·push·PR 하지 마라.** 워크트리에 변경만 남긴다. 검증·PR 은 코디네이터가 한다.
- 끝나면 **아래 두 명령을 모두** 실행한다. 하나만 하면 안 된다.

```bash
# (1) 인박스 적재 — 태스크 완료 처리·영구 기록. 코디네이터를 깨우지 않는다.
orca orchestration send \
  --to term_0065c22f-b4a3-475e-bf78-3b62bac38378 --from term_d6650170-79a6-4a75-ac74-f269eee80776 \
  --type worker_done \
  --task-id <이 태스크의 taskId — dispatch 로 받은 context 에 들어 있다> \
  --dispatch-id <이 태스크의 dispatchId — dispatch 로 받은 context 에 들어 있다> \
  --subject "writer_fable 완료: <한 줄>" \
  --body "변경 파일 목록 / 구현 요약 / 검증 결과(수치) / 계약 준수 / 미결·주의점"

# (2) 직접 주입 — 코디네이터 세션에 유저 메시지로 꽂혀 자동으로 깨운다.
orca terminal send --terminal term_0065c22f-b4a3-475e-bf78-3b62bac38378 \
  --text "[worker_done] writer_fable 완료 — <한 줄 요약>. 상세는 인박스." --enter
```
