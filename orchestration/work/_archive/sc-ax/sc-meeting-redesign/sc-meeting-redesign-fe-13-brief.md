## 1. 무엇을 고치나

**증상**: 23:30 이후에는 회의 예약이 안 된다. 제출 단추가 비활성으로 굳는다.
밤에 테스트를 돌리면 `MeetingList.test.tsx` 5건이 매번 깨진다.

**원인**: `features/meetings/BookingModal.tsx:161`

```ts
const ready = trimmed.length > 0 && headcount > 0 && from < to;
```

`from`·`to` 가 `"HH:MM"` 문자열이라 `"23:30" < "00:30"` 이 **거짓**이다. 자정 넘김을 모른다.

**사용자 결정: 자정을 넘는 회의를 허용한다.** (「다음날이지」)

## 2. ★ 한 줄이 아니다 — 세 자리다

`ready` 만 고치면 **잘못된 데이터를 서버로 보낸다.** 페이로드가 날짜를 하나만 쓴다:

```ts
:131  load({ starts_at: meetingIsoAt(date, from), ends_at: meetingIsoAt(date, to) })   // 회의실 조회
:214  starts_at: meetingIsoAt(date, from),
:215  ends_at:   meetingIsoAt(date, to),                                               // 제출
```

`date` 가 **양쪽 다 같다.** 23:30 → 00:30 이면 `ends_at` 이 `starts_at` **보다 앞선 시각**으로 나간다.

**셋 다 고쳐야 한다:**
1. `ready` — 자정 넘김을 아는 비교로
2. `:214~215` 제출 페이로드 — `to <= from` 이면 `ends_at` 의 날짜를 **다음 날로**
3. `:131` 회의실 조회 — 같은 계산을 써야 **그 시간대에 실제로 빈 방**을 받는다

날짜를 하루 더하는 계산은 **새로 만들지 마라** — `lib/labels.ts` 의 `addDays` 가 이미 있다.

## 3. 경계

| | |
|---|---|
| **BE 는 안 건드린다** | `starts_at`·`ends_at` 이 ISO 라 계약은 그대로다. 서버가 자정 넘김을 거절하면 **그건 보고만** 하고 프론트는 제대로 보낸 채로 둬라 |
| **테스트를 시간 고정으로 덮지 마라** | `vi.setSystemTime` 으로 낮을 만들어 초록만 띄우는 것은 버그를 덮는 것이다. **제품 코드를 고쳐서** 5건이 통과해야 한다 |
| **다만 새 검사는 시간을 고정해라** | 「자정을 넘겨도 예약된다」를 확인하는 **새 테스트**는 `23:30 → 00:30` 을 명시적으로 만들어 잠가라. 그래야 낮에 돌려도 이 회귀를 잡는다 |
