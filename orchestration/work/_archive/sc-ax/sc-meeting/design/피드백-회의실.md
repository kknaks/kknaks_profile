- **D1 재전사 폴백 폐기 + 결과 수신 고침(BE) — 사용자 결정 2026-09-11**: 이번 회의는 Soniox 비동기 전사는 completed 됐으나 `GET /v1/transcriptions/{id}/transcript` 본문 읽기 중 `IncompleteRead(131070 read, 44042 more expected)` → 코드가 「실시간 원문 유지」로 삼키고(`transcript_source=realtime`) 실시간 원문 위에서 합성해 버림. **사용자: 폴백 하지 마라.** 규칙 = 재전사 실패(업로드·상태·결과 수신·빈 결과·상한)는 회의를 「실패」로 보내고 `failure_reason` 사람 말, [다시 시도]는 재전사부터 다시. 최종 스크립트·합성은 언제나 재전사 원문. 결과 GET 은 끊기지 않게 읽고(urllib 단발 → 스트리밍/httpx) 끊기면 재시도. 녹음 없음도 실패. `REALTIME_NOTICE` 경로 삭제. 스펙 D44 정정 필요(planner).
- **D2 스크립트 탭이 회의 끝난 뒤 갱신 안 됨(FE)**: `MeetingDetailPage` 가 원문을 페이지 열 때 한 번만 읽고(`wantsTranscript` 가 상태 변화에 안 바뀜) 종료 뒤 다시 읽지 않는다. 회의 초반에 들어온 참여자 창은 그때 있던 2블록만 남고(서버는 64블록) 실시간으로 붙던 줄은 `live=false` 되며 빠진다. 새로고침하면 64. 종료(summarizing→done) 전이 때 원문 재조회 필요 — 재전사로 원문이 통째로 바뀌므로 어차피 필수.
- **D3 회의 중 시간 칩 점프 없음(FE)**: 줄의 시간 칩 → 스크립트 이동(`onJump`)이 `settled`(끝난 회의)에서만 켜짐. 회의 중 AI 요약 탭 줄은 시각만 표시. 사용자: 회의 중에도 이동해야 함.
- **D4 회의 중 AI 요약에도 「다음 할 일」(사용자 결정 2026-09-11)**: 회의 중 배치가 안건별 후속 업무 후보를 낸다 — 읽기 전용, [업무 생성]·[×] 없음(승격은 종료 뒤 최종에서만). 서버가 회의 중 todos 를 버리던 규칙(WP-003) 폐기: 배치 스키마에 todos 포함 → AI 트랙에 실어 `ai.batch` 로 push → AI 요약 탭 안건 블록 밑 「다음 할 일」 목록. 매 배치 통째 교체(줄과 같은 결). 최종 합성은 지금대로 새로 뽑는다. - **D5 회의 중 AI 요약 줄 시간 칩 대부분 없음(BE 버그, 실물 2회차 09-11 지호 회의)**: 배치는 AI 트랙 전체를 매번 다시 내는데 `demote_line(covered_ms=…)` 의 근거 검증 구간이 **이번 배치의 미처리 발화 구간**(`application.py` batch input `covered_ms=(blocks[0].at_ms, max end_ms)`)뿐이라 앞 배치에서 나온 줄의 근거가 매번 구간 밖으로 떨어져 떼인다. 최신 구간 줄만 칩이 남는다. 고침: 검증 구간 = 회의 시작(0)부터 지금까지 적재된 확정 발화의 마지막 end_ms(최종 합성이 쓰는 `(0, max end_ms)` 와 같은 결). **발주 대기(회의 끝난 뒤).**
