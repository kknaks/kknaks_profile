## 3. 고칠 것 일곱 (코디가 코드에서 확인)

### ① 탭마다 안건 목록이 갈린다 — 이 바퀴의 핵심 (§4.2-6)

`MeetingDetailPage.tsx:862` 가 `shownAgendas.map(...)` **한 벌**만 돌고 `lines` 만 탭에 따라
갈아 끼운다. 계약은 **탭마다 자기 벌의 안건 목록**이다.

```
「메모」 탭   → memo 벌의 안건 목록 + 그 안건들의 memo 줄
「AI 요약」 탭 → ai   벌의 안건 목록 + 그 안건들의 ai   줄
종료 후      → final 벌의 안건 목록 + 그 안건들의 final 줄
```

탭을 넘으면 **안건 목록이 통째로 바뀐다.** 접힘·스크롤 상태를 탭마다 따로 들지,
넘길 때 초기화할지는 시안을 보고 정하고 **정한 것을 보고서에 적어라.**

### ② `can_edit_agendas` 가 불리언 하나가 아니라 벌별 셋이다

`viewModels.ts:917: boolean` → `{human: boolean, ai: boolean, final: boolean}`
(백엔드가 `memo` 로 냈으면 그 키를 써라 — **백엔드 보고가 정본**이다)
`MeetingDetailPage.tsx:293 canEditAgendas` 가 그 값을 벌별로 읽어야 한다.

| 벌 | 안건 더하기 | 안건 고치기·지우기 |
|---|---|---|
| 사람 벌 | 예정 · **진행 중** · 취소 | 예정 · 취소 |
| AI 벌 | **없다** | **없다** (언제나 거짓) |
| 최종 벌 | 종료 · 실패 | 종료 · 실패 (`[수정]` 안) |

**「진행 중」에 더할 수는 있지만 고칠 수는 없다** — 표를 그대로 읽어라.

### ③ 종료 후 원본 두 벌을 여는 자리 — **미결이다**

`§8-11` 이 「세 벌을 전부 응답에 낸다 · 읽기 전용 · 참석자 전원」까지 정했는데
**화면 어디에 두는지는 `OQ-319` 로 열려 있다**(탭 / 드로어 / 접히는 구획).
확정 시안은 「종료에는 탭이 없다」를 전제로 그려서 이 자리를 갖고 있지 않다.

**네가 정하지 마라.** 데이터는 받되 표면은 만들지 말고, **코디에게 게이트로 올려라.**
나머지 여섯을 먼저 하고 이것만 남겨도 된다.

### ④ 결론 표시는 최종 벌에만 (§4.0-5)

`MeetingDetailPage.tsx:890` 의 `mark={settled ? ... : null}` 이 **벌 구분 없이** 모든 안건에 붙는다.
최종 벌 안건에만 서야 한다.

### ⑤ 「안건 1. 안건 1」 (§12 R-50)

자리표시 제목이 「안건 1」인데 화면 라벨이 「안건 N. {제목}」이라 번호가 두 번 붙는다.
v0.5.1 이 **「자리표시 제목은 빈 값」**으로 정리했다 — 빈 제목일 때 화면이 무엇을 낼지가 남는다.
**모델 문제가 아니라 표시 문자열 문제다.** 라벨 쪽에서 닫아라.

### ⑥ 저장 페이로드에 줄 id (§8-9)

`api.ts:958` 의 `lines?: string[]` 이 **더 이상 문자열 배열이 아니다.** 줄마다 id 가 함께 간다.
백엔드가 이렇게 가른다 — **id 를 안 보내면 그 줄은 새 줄이 되고 계보가 죽는다.**

- id 가 왔고 본문 그대로 → 계보 유지
- id 가 왔고 본문 달라짐 → 그 줄의 계보만 삭제
- id 없이 옴 → 새 줄
- 모르는 id → 그 줄만 거절 (저장 전체는 산다)

**편집 화면이 줄 id 를 들고 있어야 한다.** 지금 `bodies` 상태가 `string[]` 이라
(`MeetingDetailPage.tsx:458` 부근) 저장할 때 id 를 못 싣는다 — 여기가 실제 작업이다.

### ⑦ 계보(`merged_from`·`from_lines`) 표면 — **만들지 마라**

프론트에 grep 0건이고 **스펙이 화면을 아직 안 정했다.** 값은 응답에 오지만 지금은 쓰지 않는다.
`OQ-308`(다음 판)이 이 위에 선다. **자리를 지어내지 말고** 응답 타입에만 반영해라.
