## ① 탭마다 자기 벌의 안건 목록 (§4.2-6 · D51)

**무엇을 어떻게** — 벌을 가르는 값 하나를 세우고(`MeetingDetailPage.tsx:292 shownTrack`),
안건 목록을 그 값으로 먼저 거른다(`:531 trackAgendas`).

```
진행 중 「메모」 탭 → memo   ·  「AI 요약」 탭 → ai  ·  예정·취소 → memo  ·  종료·실패 → final
```

`shownAgendas`(`:534`)가 그 목록을 쓰고, 배치가 온 동안에는 배치가 실어 온 것 중 `track === "ai"` 만
쓴다. 거르지 않으면 서버가 한 `agendas` 배열에 세 벌을 다 실으므로 **같은 회의가 최대 3배로 보이고
`order` 가 벌 안에서 1 부터 다시 매겨져 「안건 1」이 셋 선다**(백엔드 보고 §4.5).

**내가 정한 것 — 탭을 넘길 때 스크롤은 맨 위로 돌린다** (`MeetingDetailPage.tsx:401` 부근).
근거: 벌이 다르면 안건도 다른 것이다. 사람 벌 셋째 안건을 읽다 넘어갔을 때 AI 벌 셋째 안건은 같은
이야기가 아니므로, 자리를 지키면 «엉뚱한 곳에서 시작» 한다. **접힘 상태는 들 것이 없다** —
`AgendaBlock` 에 접는 기능이 없고 늘 펴진 채로 선다(시안도 접는 자리를 그리지 않았다).
편집 초안(`bodies`)은 안건 id 로 키를 잡아 벌이 섞이지 않는다(id 가 벌 안에서만 유효하므로 충돌 없음).

## ② 게이트가 벌별 셋이다 (§4.1-6)

- `viewModels.ts`: `can_edit_agendas: boolean` → **`MeetingTrackGates`**(`{memo, ai, final}`),
  그리고 **`can_add_agenda` 를 새로 받았다**(백엔드가 낸다 — 선언이 아예 없던 필드다).
- `MeetingDetailPage.tsx:300~304`: `canEditAgendas = agendaGates?.[shownTrack]` ·
  `canAddAgenda = addGates?.[shownTrack]`.
- **`&& !live && !settling` 을 걷었다.** 상태 게이트를 서버가 이미 그 값에 넣었고(백엔드 보고 §4.2),
  화면이 다시 추론하면 같은 판정이 두 곳에 산다.
- **더하기와 고치기를 갈랐다** — `agendaOpen`(지우기) / `agendaAddOpen`(더하기, `:335`).
  「진행 중」 사람 벌이 그 차이가 드러나는 유일한 자리다: 더할 수는 있고 고칠 수는 없다.
  회의 중의 더하는 자리는 본문 칸이 아니라 **메모 칸의 [+ 새 안건]**이다(§6-4) — 그래서
  `agendaAddOpen` 은 진행 중에 거짓이고, 그 자리는 `MemoComposer` 가 그대로 갖고 있다.

> ⚠ 불리언이던 때 `Boolean(meeting?.can_edit_agendas)` 는 **객체가 늘 truthy 라 조용히 항상 참**이 된다.
> 타입으로 잡혔고, 그래서 형 선언을 `any` 로 넘기지 않았다.

## ③ 종료 후 원본 두 벌을 여는 자리 — **닫혔다 (OQ-319)**

발주서대로 **표면을 만들지 않고 게이트로 올렸고**, 작업 중 답을 받았다:

> **사용자 결정 — 회의록은 최종 회의록만 보여준다. 원본 두 벌을 여는 자리를 만들지 않는다.**
> 탭도 드로어도 접히는 구획도 두지 않는다. 컨트롤 하나도 더하지 않는다.

**지금 화면이 그 답과 일치한다** — 종료·실패에서 `shownTrack === "final"` 이라 최종 벌만 그리고
memo·ai 벌은 걸러진다. 결정을 받고 **아무것도 고치지 않았다**(고칠 것이 없었다).
API 는 그대로 세 벌을 내고 타입도 받지만 화면이 쓰지 않는다 (§8-11 · D53) — 나중에 `OQ-308`
(충돌 판정)이 그 위에 선다. 확정 시안의 「종료에는 탭이 없다」와 일치하므로 **시안 이탈이 없다.**

## ④ 결론 표시는 최종 벌에만 (§4.0-5)

`MeetingDetailPage.tsx:936` — `settled` 하나로 붙던 것을 `settled && agenda.track === "final"` 로 좁혔다.
사람 벌·AI 벌의 안건은 결론 여부를 갖지 않는다.

## ⑤ 「안건 1. 안건 1」 (§12 R-50)

**모델이 아니라 표시 문자열 문제라 라벨에서 닫았다.**
`labels.ts` `meetingScreen.agendaHead` 가 제목이 비면 **번호만** 낸다 — `안건 1`(마침표 없음).
`AgendaBlock` 은 `titlePlaceholder` 를 받아 그 자리에 `--placeholder` 클래스를 건다(서버의
`title_placeholder` 를 그대로 흘린다). **없는 제목을 지어내지 않는다** — 사람이 제목을 넣으면 그때 붙는다.

## ⑥ 저장 페이로드에 줄 id (§8-9) — **여기가 실제 작업이었다**

편집 상태의 «단위» 를 글자에서 줄로 올렸다.

- `MeetingDetailPage.tsx:75` — `type DraftLine = { line_id?: string; text: string }` 신설.
  `linesOf()` 가 `string[]` 대신 `DraftLine[]` 를 낸다(`line_id` 를 버리던 `.map(l => l.text)` 가 그 자리였다).
- `:147` `bodies: Record<string, DraftLine[]>`.
- 편집 칸은 여전히 글자만 본다(`lines: draftOf(agenda).map(l => l.text)`) — **부품은 계보를 모른다.**
  `onChange` 는 **글자만 갈고 id 는 그대로 둔다**(본문이 달라져도 같은 줄이다). `onAdd` 는 **id 없이**
  넣는다 — 그것이 「새 줄」이라는 표시다.
- `:475` 저장이 `{line_id?, text}` 를 싣고 빈 줄만 버린다.
- **409 충돌로 갈아 끼울 때도 id 를 들고 온다**(`:487` `linesOf(stale, "final")`) — 여기서 글자만 뽑으면
  다음 저장이 계보를 통째로 버린다.
- `api.ts:958` `lines?: Array<{ line_id?: string; text: string }>` + 계약 주석(422 · 409 두 자리).

## ⑦ 계보 표면 — 만들지 않았다

`MeetingLine.from_lines` · `MeetingAgenda.merged_from` 을 **타입에만** 더하고 화면에 그리지 않았다.
`OQ-308` 이 그 위에 선다. **충돌 판정 UI(나란히 보이기·판정 카드)도 만들지 않았다.**

## 새 테스트가 무엇을 거는가

`MeetingLive.test.tsx` 끝에 `describe("회의록 세 벌 — 탭마다 자기 벌의 안건 목록")` 7건:

1. **메모 탭과 AI 탭의 안건 목록이 «다르다»** — 줄만 갈리는 것이 아니다(제목·줄 양쪽을 본다)
2. **두 벌을 합쳐 내지 않는다** — 「안건 1.」이 하나만 선다(`order` 가 벌마다 1 부터라 가장 먼저 깨지던 자리)
3. **AI 벌 안건에는 편집 자리가 없다** — 지우기·안건 칸·[안건 추가] 셋 다 없다
4. **「진행 중」 사람 벌은 더할 수는 있고 고칠 수는 없다** — 두 게이트가 갈렸음을 건다
5. **회의 중에는 [업무 생성]이 없다** — 후보는 보이되 승격·빼기 자리가 없다 (§9-3 · D46)
6. **결론 표시는 회의 중 어느 탭에도 없다** (§4.0-5)
7. **자리표시 제목은 번호만 낸다** — 「안건 1. 안건 1」이 서지 않는다

8. **배치가 와도 사람 벌은 그대로 있다** — SSE 페이로드가 AI 벌만 싣게 바뀐 뒤의 회귀 자리(코디 지시 1)

`MeetingDetail.test.tsx` 의 저장 검사가 **`{line_id, text}` 를 싣는 것**을 건다(⑥의 잠금).

## 코디 추가 지시 둘 (작업 중 받았다)

1. **SSE `ai.batch` 페이로드가 «세 벌 전체» → «AI 벌만» 으로 줄었다.**
   받는 쪽이 그것으로 목록을 통째로 갈아 끼우면 **배치가 돌 때마다 사람 벌이 화면에서 사라진다.**
   확인 결과 **이미 안전했다** — 갈아 끼우기가 `aiTab` 조건 «안» 에 있고 `track === "ai"` 로 한 번 더
   거른다(`MeetingDetailPage.tsx:534`). 사람 벌은 상세가 실어 온 `trackAgendas` 를 그대로 쓴다.
   `stream.ts:235` 도 배치를 `agendas` 에 합치지 않고 `batch` 자리에 따로 둔다.
   **그래도 이 성질을 잃기 쉬우므로 검사로 못박았다** — 「배치가 와도 사람 벌은 그대로 있다」.
2. **`can_add_agenda`** — 이미 ② 에서 함께 받았다. `policy.py:177 as_dict()` 로 `{memo, ai, final}` 확인.
3. 백엔드 검수의 FAIL 하나(이전 회의 맥락에 세 벌이 실린다)는 프롬프트 쪽이라 내 작업과 무관하다.

## 남은 것 · 주의

1. **일곱 모두 닫혔다** — 남긴 것이 없다.
2. **SPEC §4.0-2 본문의 `human` 표기가 코드(`memo`)와 어긋난다** — 스펙 정정 대상.
3. **기존 DB 행의 `track` 이 `NULL`** 이라 세 벌 필터 어디에도 안 걸린다(백엔드 보고 §6 · `OQ-320`).
   화면에서는 **안건이 사라진 것처럼 보인다** — 프론트가 메울 문제가 아니라 이관(`OQ-320`)이 정할 일이다.
   내가 `?? "memo"` 같은 폴백을 두지 않은 이유다: 폴백을 두면 AI 벌·최종 벌 안건까지 사람 벌로 끌려온다.
4. 실제 브라우저 검증은 하지 않았다 — 회의를 만들거나 종료하지 않았고 로컬 스택도 건드리지 않았다.
