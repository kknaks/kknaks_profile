| 3 | KOS 등록 미리보기 모달 | `3-preview` | 「KOS 등록 미리보기 · 아래 내용으로 KOS 에 예약을 등록해요」. 표 항목은 고객 · 고객 구분(신규 환자/재내원) · 국적·성별 · 예약 일정(14:00 ~ 14:30) · 층/권역 · 희망 시술 · 통역 · 예약 메모(자동 작성)이고, 모두 KOS 카드 칸에 맞췄다. 버튼은 [취소] [등록하기]이다. 누르면 0.9초 동안 로딩이 돈 뒤 등록된다. `kos api 연동 필요` 주석 자리를 두었다(D-18) |

| 5 | 변경 요청하기 모달 | `5-change-modal` · `5-changed` | 모달 구성: 요청 요약 · **사유 텍스트 입력**(textarea, D-13) · 「보내면 이 줄은 「변경 요청」이 되고 사유가 함께 보여요」. 사유가 비어 있으면 [변경 요청 보내기]가 회색으로 막힌다(node 확인). 보내면 줄 상태가 「변경 요청」(빨강) · 「본사 회신 대기」로 바뀌고, 비고에 빨간 상자 「변경 요청 사유 + 원문 + 10-14 11:13 · 데스크가 본사로 보냄」이 붙는다. 본사 화면은 그리지 않았다(OQ-403) |
| 6 | 수정 요청 이어 붙기 | `6-modify` | [링키 수정 요청 생성]을 누르면 변경 요청이 걸린 예약 **아래에** 새 줄이 붙는다(↳ 화살표로 이어짐). 묶음 머리에 「[JP] TANAKA YUKI · 예약 이력 2건」이 붙는다. 새 줄은 「수정 요청 · 변경 요청 반영」이고 일시가 `10-17(토) ~~10:00~~ → **14:30**` 이다(취소선 → 굵은 파랑, D-14). 상태는 「수정 확인중」, 버튼은 **[KOS 수정하기] · [변경 요청하기]** 이다(D-16). 기존 줄 상태 아래에는 「수정 요청 받음 ↓」가 붙는다. 수정 미리보기 모달은 「KOS 수정 미리보기 · 바뀐 항목 n개」이고, 바뀐 줄은 파란 바탕에 취소선 → 새 값으로 보인다 |
| 7 | 수정 확정 | `7-modified` | 두 갈래를 모두 보인다. **고객 A(확정 뒤 고객 시간 변경)**: 기존 줄은 「변경됨」(회색 · 흐림) · [이전 스크린샷] · 「이력 보관」이고, 새 줄은 「수정 확정」 · [스크린샷 보기]다. 스크린샷 모달 제목은 「예약 1 · KOS 등록 화면」/「예약 2 · …」 · 「이력 보관」이다. **고객 B(변경 요청 → 수정)**: 기존 줄은 「변경됨」 + 사유 상자가 남고 「KOS 등록 전에 바뀌어 스크린샷이 없어요」가 붙는다. 새 줄은 「수정 확정」 · [스크린샷 보기]다 |

데모 순서(빈 상태에서 버튼만 눌러 이어 가는 길): 요청 생성(A) → KOS 등록하기 → 미리보기 → 등록하기 → 확정 · 스크린샷 → 요청 생성(B) → 변경 요청하기 → 사유 입력 → 보내기 → 수정 요청 생성(B 에 붙음) → KOS 수정하기 → 수정하기 → 수정 확정. [링키 수정 요청 생성]은 **변경 요청이 걸린 예약을 먼저** 고르고, 없으면 가장 최근 확정 예약을 고른다(고객 시간 변경). 대상이 없으면 버튼이 막혀 있다.

## 검증

1. **node 실행** — 두 파일의 스크립트를 DCLogic 대역으로 돌렸다.
   - 예약관리: 9개 장면별 테이블 줄 · 상태 · 버튼 · 모달 값을 확인했다(위 표 값이 실제 출력이다). 조작 흐름도 확인했다: 요청 생성 → 미리보기 → 등록하기(0.9초 뒤 「예약 확정」 · 토스트) → 요청 생성 → 변경 요청(빈 사유는 보내지 않음 → 입력 → 「변경 요청」) → 수정 요청 생성(B 아래에 `10:00 → 14:30` 「수정 확인중」)
   - 현황판 폰: 메뉴 열기/닫기, 방 하나 접기, 모두 접기(4/4 접힘). 요약은 내원 4 · 확인 필요 1 · 상담 1 · 시술 2 · 대기 0
2. **실제 고객 정보 0** — KOS 캡처 값(이름 · 읽기 · 차트번호 · 생년월일 · 연락처 · 동행인 · 유입처 · 메모 원문 낱말 10개)을 두 파일에서 `grep` 했다 → **모두 0건**. 스크린샷 모달 값은 지어낸 것이다(`No.9041` · `1991.03.08` · `+886 900 000 000` 같은 꼴). 고객 이름은 시나리오 가짜 이름본에 있는 것만 썼다(7명 전원 `scenario/seed.json` 에 있음을 확인). 시나리오의 `resvMemo` · `custMemo` · 일정 id 는 파일에 넣지 않았다(0건)
3. **직원 이름** — `kos-staff.json`(가짜 이름본) 중 시나리오 `staffIds` 14명만 썼다. `*.orig` · `staff-name-map.json` 은 열지 않았다
4. **기존 시안 무수정** — 쓰기 계획 2경로, 삭제 0. 업로드 전후 `list_files` 차이는 새 파일 2개뿐이다

## 이슈 · 코디가 확인할 것

1. ⚠ **기존 직원 시안의 직원 이름** — `Ceramique 직원 - 코디.dc.html` 을 형식 참고용으로 받아 봤다. 그 안의 직원 이름(우동진 · 이신혜 · 사미령 등 14명)이 **가짜 이름본 `kos-staff.json` 에 없다.** 실명 대응표는 열지 않아서 실명인지는 모른다. r5 보고서에 나오는 이름(오현우 · 임윤서 …)과도 다르니 확인이 필요하다. 나는 이 이름을 쓰지 않고 가짜 이름본으로 바꿔 썼다
2. **수정 줄 버튼 이름** — D-16 대로 수정 요청 줄은 항상 [KOS 수정하기]이다. 그런데 B 갈래(KOS 등록 전에 변경 요청 → 수정)는 KOS 에 고칠 예약이 없다. 이 경우 [KOS 등록하기]가 맞는지 사용자 확인이 필요하다
3. **7번 「이전 스크린샷 보관」** — 원래 예약이 확정됐던 A 갈래에서만 성립한다. 그래서 7번 장면에 A · B 두 갈래를 다 넣었다. 데모를 한 갈래로 줄일지는 사용자가 정한다
4. **렌더링 미확인** — medikit `Header` 에 하위 없는 `menus`(현황판 · 예약관리)를 넘겼다. 이게 상단 탭으로 그려지는지, `Button` 의 `disabled` · `is-loading`(d.ts 에 `isLoading` 은 있고 `disabled` 는 없음)이 먹는지는 눈으로 보지 못했다. 헤더 모양은 WP1 코드가 정본이다
