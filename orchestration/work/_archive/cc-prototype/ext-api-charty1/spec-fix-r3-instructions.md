## 1. DQ7 답 — 코디 기본값(D-38 고침 · D-16 고침 줄)

DQ2 의 뜻은 「접수 뒤 일정마다 **한 번씩**」이다(코디 추천 문구 그대로 사용자가 받음). 그래서 「못 찾음 → 5분마다 다시」를 버리고 **사건이 있을 때만 다시 부른다**로 바꾼다. 일정마다 이력 호출은 아래 넷의 합이다.

1. 접수 뒤 단계로 처음 본 때 1번
2. 못 찾음 뒤, 사본에서 그 일정이 `CONSULTATION_WAITING` 인 것을 **새로 본** 때 1번(재진입 · 이력 지연 대응) — 같은 대기 구간에서는 한 번만
3. 끝난 단계(`home`)로 간 것을 본 뒤 1번(D-40 그대로 — KOS 웹에서만 지나간 대기 · 지연 대응)
4. 실패(5xx · 401 · 403 · 모양 오류)는 5분 뒤 다시 — 실패 재시도는 일정마다 하루 최대 3번(값은 네가 근거와 함께 조정 가능)

- 「못 찾음」만으로는 다시 부르지 않는다. 그래서 하루 이력 호출 ≤ 접수 뒤 일정 수 × 3 + 실패 재시도. D-16 에 고침 줄: 「건수 비례 안 함」 → 「board 요청 수에 비례 안 함 · 하루 합은 접수 뒤 일정 수의 작은 배수」.
- 요청당 10 · 날짜 지나면 멈춤 · 찾은 값만 굳힘 · D-17 대안 덮어쓰기 · D-39(`partialErrors`)는 그대로. §3.6 칸(`checked_at` · `last_failed` · `final_tried` 등)을 이 규칙에 맞게 고친다(필요한 칸만).
- §6.9 · §6.11 비용 문장 · DEC Consequences · T57 을 새 규칙으로. T57 에 「못 찾음 뒤 사건 없이 board 여러 번 → 이력 0번」 · 「대기 새로 관찰 → 1번」 · 「home 뒤 1번 · 그 뒤 0번」 · 「실패 재시도 상한」.
