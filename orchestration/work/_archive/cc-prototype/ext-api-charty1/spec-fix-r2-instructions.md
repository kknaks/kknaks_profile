## 2. FAIL 고치기 — 코디가 정한 방향(코디 기본값으로 적는다)

**F1 + F3 — 처음 상담 대기 시각 저장 규칙(Q14 대체)**
- **찾은 값만 굳힌다.** 이력에서 상담 대기 이벤트를 찾으면 그 시각을 저장하고 다시 부르지 않는다.
- 못 찾음(이벤트 없음) · 실패(5xx · 401 · 403 · 모양 오류)는 **굳히지 않는다.** 일정마다 마지막 시도 시각을 두고 **5분 안에는 다시 부르지 않는다.**
- 요청 1번당 이력 호출 상한을 둔다(값은 네가 정하고 근거를 적는다. 상한을 넘은 일정은 그 요청에서 null · 다음 요청에서 차례).
- 일정의 날짜가 지나면(KST 다음 날) 더 부르지 않는다 — 그때 null 이면 그대로 null.
- 재진입(null 상태 → 사본에서 `CONSULTATION_WAITING` 관찰)은 위 규칙 안에서 자연히 다시 불린다는 것을 적는다.
- D-17 대안으로 바꿀 때 옛 행을 어떻게 다루는지(source 가 다른 행은 덮는다 등) 적는다.
- §6.9 「상한을 바꾸지 않는다」 · §6.11 「하루 합은 … 넘지 않는다」 문장을 이 규칙에 맞게 고친다.
- T57 에 더한다: 실패 뒤 5분 안의 두 번째 board → 이력 0번 · 재진입 갈래(못 찾음 → 상담 대기 진입 → 5분 뒤 다시 부름 → 값) · 요청당 상한.

**F2 — 열람 헤더(Q7 대체)**
- 헤더 의존성은 **헤더를 쓰는 경로에만** 단다: lookup · 예약 상세 · 쓰기 셋. 메뉴 · 예약 · 가능 시간대 · 과거 시술 · 예약 내역은 헤더를 보지 않는다(T53 의 「메뉴도 꼴 검사」 지우기).
- **lookup(기존 경로)**: 꼴이 틀리거나 없으면 400 이 아니라 **없는 것으로 본다**(`staffId` null · 열람 기록 actor 는 `ext:<연동처>`). 기존 계약 그대로.
- **새 경로(상세 · 쓰기 셋)**: 선택 헤더. 없으면 actor `ext:<연동처>`, 있는데 꼴이 틀리면 400.
- 꼴에서 `@` 를 뺀다(참고 R2 — 이메일이 `event_log` 에 남지 않게). `[A-Za-z0-9._-]` 1~64자.
- T71 회귀에 「기존 여섯 경로에 이상한 헤더 → 지금과 같은 응답」을 더한다.
