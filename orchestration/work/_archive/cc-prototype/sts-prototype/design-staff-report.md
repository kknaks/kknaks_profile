## 화면별 설명

### 1. 로그인 (새로 만듦)
- 가운데 카드 하나: 로고 · 명동점 · 「직원 로그인」 · 아이디 · 비밀번호 · [로그인](medikit Button solid blue lg). 틀리면 빨간 안내 한 줄.
- **데스크로 가는 길 = 데스크 계정.** 로그인 폼은 하나이고, **계정의 역할이 첫 화면을 정한다** — 의사 → 오늘 내 일정, 코디 → 지금 내원 환자, 데스크 → 현황판(데스크 페이지). 폼 아래 한 줄로 이 규칙을 적었다.
- 시연용 계정 카드 세 개(의사 · 코디 · 데스크)를 아래에 두었다. 누르면 아이디가 채워지고, [로그인]을 누르면 「○○ 계정 → ○○ 화면으로 이동」 토스트가 뜬다(파일끼리 이동은 시안에서 할 수 없어 토스트로 표시).
- 가져온 것: 헤더 로고 · 브랜드 색 · Button · 카드 모양(흰 카드 · radius 12~16 · 그림자). 새로 만든 것: 입력칸(medikit `Input` 의 props 를 확인할 수 없어 같은 톤의 기본 input 으로 그렸다 — 구현할 때 `Input` 으로 바꾼다).

### 2. 의사 첫 화면 (기존 그대로 + 연결)
- 「의사 모바일」의 헤더 · 「지금 진행 중」 카드 · 「오늘 내 일정」 목록을 **마크업 그대로** 가져왔다(상태 배지 완료/진행 중/다음/예정, n/전체 완료).
- 바뀐 점: 폰에서는 일정 목록이 첫 화면이고, 행(또는 「지금 진행 중」 카드)을 누르면 환자 상세로 넘어간다(뒤로 「‹ 오늘 내 일정」). 기존 시안은 폰에서 상세와 목록을 한 화면에 위아래로 쌓았다. 태블릿(폭 760 이상)은 기존처럼 왼쪽 목록 · 오른쪽 상세 두 칸이고, 고른 행이 하늘색으로 표시된다.

### 3. 코디 첫 화면 — 지금 내원 환자 (새로 만듦)
- 카드 하나에 지금 병원에 와 있는 환자 전부를 행으로 둔다. 머리글은 「지금 내원 환자 · n명 · 외국인 n명」, 그 아래 「대기 n · 상담 n · 시술 n · 경과 긴 순」 요약 한 줄.
- 행: **환자명 + 국적 칩**(외국인만, 예: 「대만」) / **지금 위치(방, 파란 글씨) · 현황판 라벨**(예: 「관리실 14 · 원장 대기」) / 오른쪽에 **상태 배지**(대기 · 상담 · 시술 — 현황판 v3 와 같은 이름 · 같은 색) + **경과 mm:ss**.
- 정렬은 현황판 「현황」 탭과 같은 **경과 긴 순**.
- 라운지에서 기다리는 환자는 방 대신 「라운지 · 접수 후 대기」로 나온다. 아직 도착하지 않은 예약은 나오지 않는다.
- 가져온 것: 의사 「오늘 내 일정」의 행 모양 · 현황판 상태 이름 · 배지 색 · 라벨 문구. 새로 만든 것: 행 구성, 국적 칩.

### 4. 환자 상세 — 두 역할 공통 (기존 환자 카드를 다시 배치)
브리프 §3-4 순서대로 놓았다.
```
‹ 뒤로 (폰만)
[카드] 라벨(진행 중인/다음/예정/완료한 환자 · 코디는 「내원 중인 환자」) · 타이머(대기/경과/예약)
       환자명 + 국적 칩
       성별 · 나이 · #차트번호 · 신규
       ┌ 오늘 예약 내역: 10:50 예약 / 시술 계획 / 담당 원장 · 상담사 / [상태 배지] 지금 방 · 라벨 ┐
       [통역] [진료 시작]        ← 코디는 [통역]만 · KR 이면 [통역] 숨김
[카드] 환자 차트   [펼치기]       ← 기본 접힘. 차트번호 · 성별·나이 · 국적 · 방문 구분 · 예약 그룹 · 오늘 시술
[카드] 환자 메모 n건 [접기]       ← 기본 펼침. 기존 「주의사항」 빨간 박스 + 「상담 메모」 가 여기로 들어왔다
[카드] 시술 이력                   ← 기존 그대로(방문 n회 · 날짜 · 시술 · 시술자 · 「첫 방문 고객」)
- - - - - - - - (점선)
[카드] 오늘 고객 동선              ← 기존 「오늘 ○님 동선」 그대로, 제목만 「오늘 고객 동선」
```
- 버튼 규칙: 의사 — 다음/진행 중 환자에만 [진료 시작]/[진료 완료](기존 동작 그대로: 누르면 진행 중 → 완료, 다음 → 진행 중), 외국인이면 [통역] 이 왼쪽에 붙는다. 완료·예정 환자는 [통역] 만 남는다. 코디 — [통역] 하나만 전체 폭. **KR 환자는 [통역] 이 없고**, 버튼이 하나도 없으면 버튼 줄도 없다.
- 기존 「차트 열기」 버튼은 「환자 차트 [펼치기]」 로 대신했다.
- 내 동선(「지금 진행 중」 · 「오늘 내 일정」)은 상세에 넣지 않았다.

### 5. 통역 모달 (새로 만듦)
- 폰: 아래에서 올라오는 시트(화면 높이 − 24px). 태블릿: 가운데 창(폭 560).
- **위**: 「통역 · 중국어 ▾」 + 아래 작은 줄 「서하은 님 · 중국 · 국적으로 자동 선택 · 눌러서 변경」 · 오른쪽 [닫기]. 언어 이름을 누르면 언어 칩 목록이 펼쳐지고(자동 선택된 것에 「· 자동」 표시), 고르면 닫힌다.
- **가운데 — 메신저형**: 환자 말풍선은 **왼쪽**(흰 바탕), 내 말풍선은 **오른쪽**(브랜드 파란 바탕). 말풍선마다 **원문(크게, heading-md)** + **번역(작게, caption)**, 위에 「서하은 님」/「나」 이름표. 듣는 중에는 마지막 환자 말풍선이 회색 「… / 번역 중…」으로 이어지는 중인 모습을 보여 준다.
- **아래**: 큰 원형 버튼 하나 + 상태 글자.
  - 연결 중 — 회색 원 안에 도는 표시 · 「연결 중」 · 대화 칸은 「연결하는 중이에요」
  - 듣는 중 — 파란 원(바깥으로 퍼지는 고리 애니메이션) 안에 멈춤(Ⅱ) 아이콘 · 「● 듣는 중」 · 「양쪽 말을 모두 들어요 · 누가 말했는지는 자동으로 구분해요 · 누르면 멈춤」
  - 멈춤 — 흰 원 안에 마이크 아이콘 · 「멈춤」 · 「누르면 다시 들어요」
  - 오류 — 빨간 원 안에 마이크 금지 아이콘 · 「오류」 · 위쪽에 빨간 안내 박스(「마이크를 쓸 수 없어요 — 주소창 자물쇠 → 마이크 → 허용」 + [다시 시도])
- **말하는 사람 전환 버튼은 없다.** 위아래 분할(마주 보기)도 하지 않았다.
- 열면 「연결 중」 → 1.2초 뒤 「듣는 중」으로 넘어간다. [닫기] 를 누르면 환자 상세로 돌아간다.

## 내가 정한 것 — 코디가 사용자에게 확인

1. **데스크 페이지로 가는 길 = 데스크 계정.** 로그인 폼 하나, 계정 역할이 첫 화면을 정한다(의사 → 오늘 내 일정 · 코디 → 지금 내원 환자 · 데스크 → 현황판). 로그인 뒤 「역할 고르기」 화면은 두지 않았다.
2. **로그인 화면에 시연용 계정 카드 3개**(의사 · 코디 · 데스크)를 두었다 — 시연 때 아이디를 치지 않게. 빼도 되는 부분이다.
3. **폰에서 의사 첫 화면 = 일정 목록만**, 행을 누르면 상세로 넘어간다(기존 시안은 상세를 목록 위에 같이 쌓았다). 태블릿은 기존처럼 두 칸.
4. **코디 목록 정렬 = 경과 긴 순**(현황판 「현황」 탭과 같게). 요약 줄(대기 · 상담 · 시술 수)을 넣었다.
5. **「지금 내원」 = 접수했고 아직 귀가 전.** 라운지 대기 환자는 넣고, 도착 전 예약은 뺐다.
6. **국적 칩은 외국인만**, 이름은 한국어 국가명(대만 · 중국 · 홍콩 · 일본 · 미국 · 태국 …).
7. **버튼 노출 규칙**: 의사의 [진료 시작] 은 「다음」 · 「진행 중」 환자에만(진행 중이면 [진료 완료] — 기존 시안 동작). 완료 · 예정 환자는 [통역] 만. 브리프 「코디는 [통역]만 · KR 이면 [통역] 숨김」은 그대로.
8. **환자 메모에 고객 메모 + 상담 메모를 같이** 넣고, 고객 메모(`visitor.memo`)는 기존 「주의사항」처럼 빨간 박스로 그렸다. 메모 카드는 기본 펼침, 환자 차트는 기본 접힘.
9. **환자 차트에 넣은 칸**: 차트번호 · 성별·나이 · 국적 · 방문 구분 · 예약 그룹 · 오늘 시술. 「차트 열기」 버튼은 없앴다.
10. **오늘 고객 동선 앞에 점선 구분선**을 두어 브리프의 `──────` 을 표시했다(위쪽 구분선은 카드 경계로 대신).
11. **통역 모달 모양**: 폰은 아래에서 올라오는 시트, 태블릿은 가운데 창.
12. **국적 → 기본 언어**: TW · CN · HK → 중국어, JP → 일본어, US → 영어, TH → 태국어, FR → 프랑스어, **PH → 영어, IN → 영어**(타갈로그어 · 힌디어도 고를 수 있다). 고를 수 있는 언어 8개: 중국어 · 영어 · 일본어 · 태국어 · 프랑스어 · 스페인어 · 타갈로그어 · 힌디어.
13. **통역 열기 = 바로 듣기 시작**(연결 중 → 듣는 중). 따로 [시작] 을 누르지 않는다.
14. **듣는 중 버튼 아이콘 = 멈춤(Ⅱ)**, 멈춤 상태 아이콘 = 마이크. 즉 아이콘은 「누르면 일어날 일」을 보여 준다.
15. **이름표 「나」/「○○ 님」** 을 말풍선 위에 붙였다.
16. 샘플 이름은 **기존 두 시안의 샘플 이름**(정해린 원장 · 서하은 · 김서연 …)을 그대로 쓰고, 코디 이름(윤다솜) · 환자 4명(이소담은 현황판 샘플, 김나연 · 노예진 · 한유나)을 더했다. 실제 고객 값은 하나도 넣지 않았다. 대화 샘플도 지어낸 문장이다.

## 이슈 · 코디가 확인할 것

1. **렌더링을 눈으로 확인하지 못했다.** medikit 번들이 로컬에 없어서다. JS 는 node 로 문법 · 값 계산을 확인했다(의사 · 코디 · 상태 · 로그인 모두 오류 없음, 상태 전환 · 진료 시작 · 로그인 토스트 동작 확인). 원본 링크에서 처음 열 때 깨진 곳이 있으면 알려 주면 고친다. 특히 확인할 곳: 클래스 안에 값을 섞은 칩(`class="cc-btn {{ … }}"`), 상태 파일의 sc-for 안 sc-for, 로그인 input 의 `onChange`.
2. **파일명의 `—` 가 `-` 로 바뀌었다**(업로드 시 변환). 이름 규칙을 `—` 로 꼭 맞춰야 하면 알려 달라.
3. **DesignSync 도구 설명에는 「디자인 만들기에 쓰지 말라(design-sync 스킬 전용)」고 적혀 있다.** 브리프와 `_RESUME` 결정(「시안은 frontend 워커(DesignSync)가 초안」)을 따라 새 파일 4개만 썼다. 다음 판부터 다른 경로(Design Artifact 등)로 바꿀지 정해 달라.
4. **두 화면이 같은 상태를 본다** — 시안의 상태 이름 · 배지 색 · 라벨 문구 · 방 이름은 현황판 v3 와 같게 했다. 다만 시안 파일끼리는 실제로 이어지지 않는다(의사 파일에서 [진료 시작] 을 눌러도 코디 파일 값은 안 바뀐다). 의사 파일 안에서는 [진료 시작] 을 누르면 그 환자 상태가 「상담」, 끝난 환자는 「코디 대기 · 진정 관리」로 바뀌게 해 두었다.
5. **[진료 시작] 을 누르면 현황판에서 어떤 상태가 되는지**(상담? 시술?)는 정해지지 않았다. 시안은 「상담」(원장 진료)으로 두었다 — SPEC 에서 정할 것.
6. **번체 표시**: 대만 · 홍콩 환자 대화 샘플은 번체로 그렸다. 조사 리포트상 Soniox 번역 결과가 번체로 나오는지는 문서에 없다 — 간체로 나오면 변환이 필요할 수 있다.
7. **환자 메모에 어느 메모를 띄울지** — 데이터에는 `visitor.memo`(12건) · 상담 메모(143) · 예약 메모(174) · 오더 메모(141) · 담당자 메모(237)가 있다. 시안은 앞의 두 개만 그렸다.
8. **차트번호를 시연 화면에 그대로 띄울지**(조사 리포트 §D 개인정보) 정할 것.
9. **시술 이력 · 방문 횟수는 캡처에 없다**(KOS API 보강 결정이 있음). 보강 전이면 「첫 방문 고객」/빈 칸으로 나온다.
10. 기존 「현황판 v3」 · 「의사 모바일」 및 다른 파일은 손대지 않았다(쓰기 계획에 새 파일 4개만 잠갔고, 의사 모바일을 다시 읽어 로컬 사본과 같음을 확인).
