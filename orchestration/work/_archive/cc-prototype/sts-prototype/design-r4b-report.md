## 내가 정한 것

1. 예시 고객은 **시술 3건인 10-09 방문**(윤가온)으로 골랐다. 지시서 예시의 ₩ 1,280,000 대신 실제 결제 합계 ₩ 439,000 을 쓴다.
2. 미결제 금액은 **방문 결제 합계 한 줄**이다(시술별 금액은 쪼개지 않음). KOS 결제 품목과 시술 작업이 1:1 이 아니어서다(이벤트 묶음 상품).
3. 미결제 동안 방 칸 문구는 「다음 단계 대기」 그대로다. workflow 「결제 중 표시 없음」에 따랐다.
4. 수납필요 단계에도 [배정] 을 막지 않았다. 지시가 없어서다.
5. [상담 내용 보기] 는 화면을 옮기지 않고 **패널 안에서 펼친다**. 현황판이 데스크 화면이라 직원 환자 상세로 넘어가지 않는다.
6. [초기화] 는 확인 상자를 한 번 거친다.

## 이슈

1. 렌더링 눈 확인이 필요하다. 미결제 노란 줄 · [초기화] 확인 상자(오른쪽 위 고정) · 패널 안 펼침의 2단 `sc-for` 를 봐야 한다.
2. 시안의 [초기화] 는 **처음 장면(14:45)** 으로 돌아간다. SPEC 의 시드는 **개원 전**이라 실제 앱과는 돌아가는 상태가 다르다.
3. 상담 「완료」 뒤에 들어온 시술이 상담사가 넣은 것인지 데스크가 넣은 것인지는 단계에 표시하지 않았다(§0-a 는 상담 완료 이벤트로 들어온다고만 함). 필요하면 출처 칩을 더한다.
