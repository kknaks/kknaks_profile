## 설명 초안

DAY는 병원 직원이 시술 진행 상황을 확인하고 동료와 업무를 주고받는 앱입니다.

- 시술 현황과 룸별 진행 상황 확인
- 직원 간 채팅과 사진·동영상 공유
- 업무 알림 확인과 호출 응답
- 의료진과 고객의 대화를 돕는 음성 통역

이용하려면 연결된 병원에서 사용하는 직원 계정이 필요합니다. 로그인한 직원의 병원과 권한에 따라 이용 가능한 정보와 기능이 달라집니다.

예약 화면 등 아직 준비 중인 기능은 소개에 넣지 않았다. 출시 전 실물 기능과 대조해 문구를 확정한다.

## 심사 메모 초안

이 앱은 연결된 병원의 직원을 위한 업무 도구이며 Unlisted 배포를 신청할 예정입니다. 일반 이용자의 회원가입 기능은 제공하지 않습니다. 심사 전용 데모 계정을 App Review Information의 별도 로그인 칸으로 제공합니다.

정식 DAY 앱의 로그인 화면에서 해당 계정으로 로그인하면 서버가 심사용 데모 환경으로 연결합니다. 심사관이 환경이나 서버 주소를 변경할 필요는 없습니다. 데모 병원에서 시술 현황, 직원 채팅, 알림 및 통역을 확인해 주세요.

위 문구는 로그인 넘김·데모 데이터·해당 기능 접근을 실물로 확인한 뒤에만 제출한다. 실제 계정·암호는 이 문서에 기록하지 않는다. 역할별 확인 경로와 푸시 재현 방법은 실기기 검증 뒤 메모에 추가한다.

## Unlisted 신청 사유 초안

DAY의 이용 대상은 서비스에 연결된 병원의 직원으로 한정됩니다. 일반 소비자가 병원을 검색하거나 서비스를 구매하기 위한 앱은 아닙니다. 병원 직원에게 설치 링크를 안내하고, 앱 내 직원 계정 인증과 병원별 권한으로 업무 정보 접근을 제한합니다.

설치 기기의 소유·관리 방식과 대상 조직·사용자 규모는 아직 확인하지 않았으므로 신청서에 추측해서 넣지 않는다.

Apple은 심사에 제출한 정식 배포 준비 상태에서 Unlisted 신청을 받는다. 심사 메모에 의도를 적고 별도 신청을 하며, 승인 후 배포 방식을 확인한다. 링크 소유만으로 업무 데이터 접근을 허용하지 않는다. [Apple Unlisted 안내](https://developer.apple.com/support/unlisted-app-distribution/)

## App Privacy 작성 근거 초안

최종 응답은 운영 서버·보관 정책·외부 공급자 정책을 확인한 뒤 확정한다. ‘수집하지 않음’으로 일괄 선택하지 않는다. Apple의 수집 정의에는 실시간 요청을 처리하는 데 필요한 시간보다 오래 접근 가능한 외부 전송이 포함된다. [Apple App Privacy](https://developer.apple.com/app-store/app-privacy-details/)

## 스크린샷 준비

실제 release 앱의 데모 데이터로 촬영한다. 환자·직원 실제 정보가 보이는 기존 캡처는 쓰지 않는다. 알파 없는 PNG/JPEG를 사용하고, 현재 Apple 표에서 허용하는 iPhone 화면과 iPad 13인치 화면 규격으로 준비한다. 촬영 계획은 iPhone 1320×2868 및 iPad 2064×2752(세로)로 잡고, 촬영 직전 ASC의 필수 화면 칸과 최신 규격을 대조한다. [Apple 스크린샷 규격](https://developer.apple.com/help/app-store-connect/reference/app-information/screenshot-specifications/)

장면 초안: 시술 현황 → 룸 상세 → 직원 채팅 → 알림 → 통역. 로그인 화면만으로 기능 소개를 대신하지 않는다. 이미지 합성·가짜 알림 수신을 실물 증거로 쓰지 않는다. 현재 제출용 이미지 미생성.

## 제출 전 남은 일

1. 개인정보처리방침·지원 URL 확정, 현재 없는 앱 내부 개인정보 링크를 추가. 통역은 실제 외부 처리 흐름을 설명하며, 실제 개인정보 공유가 있는 경우 적용되는 고지·허가 조건을 확인. 별도 동의 팝업은 무조건 필수로 정하지 않음. Apple은 앱 내부 개인정보 링크 및 제3자 AI를 포함한 개인정보 공유의 고지와 명시적 허가를 요구한다. [심사 가이드 5.1.1·5.1.2](https://developer.apple.com/app-store/review/guidelines/)
2. 앱: 예약 탭 ‘곧 출시 예정’ 숨김 또는 기능 완성 결정을 스펙에 반영. 사용자: 정식 DAY 앱 record, 첫 제출 버전, 서명 방식 M-16, 설치 대상 M-1 확정.
3. 서버 코디: dev APNs 허용 앱에 정식 앱 추가(M-20), 정식 앱으로 데모 로그인 넘김과 푸시 실물 검증. 앱 세션에서 서버 설정 변경 금지.
4. 정식 앱 실기기에서 로그인·병원 선택·로그아웃·만료·채팅·미디어 권한·통역·푸시 수신/탭/수락 확인. 병원 권한에 맞는 데모 데이터 준비.
5. 제출용 스크린샷, App Privacy·연령 설문·가격·지역·연락처 확정.
6. 사용자 판단 뒤 배포 서명 → IPA 검증 → 업로드 → ASC 빌드 처리 확인 → 제출 메타데이터 반영 → 심사 제출·Unlisted 신청. 공개 시점은 별도로 확인.

## 코드 검토에서 확인한 보완 후보

- 앱 내부 개인정보처리방침 링크 및 Soniox 외부 전달에 관한 별도 허가 단계가 없다. 링크는 보완하고, 단순 통역만으로 개인정보 포함이나 별도 동의 팝업 필수를 단정하지 않는다. 실제 데이터 처리 범위에 따라 판단한다.
- 예약 탭에 ‘곧 출시 예정’ 화면이 남아 있다. 최종 배포 상태를 요구하는 심사 및 Unlisted 신청 전에 숨길지·기능을 완성할지 정한다. 이번 준비 작업에서 임의로 탭을 제거하지 않았다.
- SDK 개인정보 선언은 빌드 리포트와 독립 검수 결과를 함께 확인한다. 누락된 manifest가 있다는 사실만으로 특정 SDK의 현재 제출 차단을 단정하지 않는다.

현재 최소 지원 OS는 iOS 13.0이다. 이전 개발 앱 업로드의 90068 경고와 차기 요구사항은 실제 업로드 직전에 다시 확인한다.

현재 서명 없는 빌드는 기기 설치·App Store 업로드용 IPA가 아니다. 앱 검사만으로 서버 통합·심사 통과를 주장하지 않는다.
