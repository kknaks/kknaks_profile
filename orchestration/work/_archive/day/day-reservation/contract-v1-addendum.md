## 코드 검수 뒤 사용자 결정 (2026-11-23)

4. **행 경합 = 날짜 쪽이 양보**(be-fix-1 대안 ①): 날짜 최신화 반영 transaction 에 짧은 잠금 대기 상한(`SET LOCAL lock_timeout` 1 ~ 2초 · 값은 설정) · 고객 행을 정렬된 순서로 씀 · 부딪히면 날짜 쪽 `error`(중간 상태 없음 · 다시 열면 다시 돈다) · 오늘 회차는 바뀌지 않음
5. **권한 시드 = 서버 시작 때**: 앱이 뜰 때 기본 권한 행(`reservation` view 포함)을 넣는다(이미 있으면 그대로 · migration 없음). 배포 직후 403 없음
6. **꺾쇠 연타 = 이번 판에 막음**: 화면은 날짜 바꾸기를 짧게 늦춰(debounce) **마지막으로 멈춘 날짜만** 요청한다(중간 날짜는 요청 · 최신화 안 함). 서버는 **병원당 날짜 최신화를 한 번에 하나만** 돌린다(다른 날짜 요청이 들어오면 C2 대로 — 조용히 버리지 말고 실패 또는 차례 대기 · 방법은 backend 가 정하고 이유를 적는다)
7. **정원 null 열 머리 = 「30분」만**(지금 구현 그대로)
8. **(6 바꿈) 잠금 전에 Redis 10초 캐시**(사용자 2026-11-23 「레디스에 저장해 놓고 10초 캐싱 · 락 걸기 전에」): 날짜 최신화 요청이 오면 (병원 · 날짜) 「최근 10초 안에 최신화함」 표시(Redis · TTL 10초 · 값 한 곳)를 먼저 본다 — 있으면 task 를 넣지도 잠금을 잡지도 않는다(화면은 지금 DB 사본). 없을 때만 task → (병원 · 날짜) 잠금 → 최신화. 표시는 최신화가 시작될 때 세운다(진행 중 요청도 막음) · 실패면 지운다(다음 열기에 다시). 잠금은 그대로(만료 순간 겹침 대비). **「병원당 날짜 최신화 동시 1개」는 뺀다** — 화면 debounce(6 의 화면 쪽) + 10초 캐시로 충분
9. **(5 바꿈) 권한 행 = 데이터 migration**(사용자 2026-11-23 「마이그레이션 해주면 되는 문제 아니야」): 새 alembic migration 하나 — 살아 있는 모든 `job_role` 에 (`reservation`, view) 행을 넣는다(`ON CONFLICT DO NOTHING` · 기존 행 안 건드림) · downgrade = 그 키 행 삭제. 기존 시드(`default_permissions.seed` — 기준 정보 회차 · 로그인 준비)는 그대로 둔다(이후 새로 들어오는 직무 몫). **「서버(worker) 시작 때 시드」는 넣지 않는다**(이미 넣었으면 뺀다). 브리프의 「migration 금지」는 이 한 건에 한해 풀린다(코디 잘못 — 권한 기본값은 migration 이 맞다)
