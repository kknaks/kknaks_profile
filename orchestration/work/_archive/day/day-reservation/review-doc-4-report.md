## WARN

### W4-1. 「실패 → 이전 사본」이 계약(C2)인지 기본안(C4 · OQ-R23)인지 섞여 있다
- C2(S6:L289 · 계약): 「못 하면 **실패로 끝나고 이전 사본을 그린다**」. C4(S6:L291 · 기본안 · 사용자 확인): 「KOS 실패 · 시간 초과면 이전 사본을 그린다」. OQ-R23(S6:L435): 선택지에 아직 **ⓑ 오류 화면**이 있다.
- 케이스 줄 S6:L330 은 실패의 종류를 나누지 않고 「KOS 오류 · 시간 초과 · 키 보충 · 구매 단계 실패 → **200 · 이전 사본**(C2 · C4 기본안)」으로 고정해 버렸다.
- 이렇게 되면 OQ-R23 ⓑ를 고르는 순간 C2 · L330 과 부딪친다. 조건끼리 모순은 아니다. C2 를 「잠금 · 보충 실패」로 좁혀 읽으면 C4 와 겹치지 않는다. 다만 지금 문장으로는 범위를 알 수 없다.
- 고칠 것(둘 중 하나):
  - ① C2 의 「이전 사본」은 **중간 상태를 보이지 않는다**는 뜻으로만 둔다. 화면에서 실패를 어떻게 보일지(사본 · 오류 화면)는 OQ-R23 으로 보낸다. L330 의 HTTP · 화면 칸에는 「OQ-R23(기본안 200 · 이전 사본)」 표시를 붙인다.
  - ② OQ-R23 의 ⓑ 오류 화면을 지우고 「C2 로 정해짐」이라고 적는다.

### W4-2. 오늘 화면과 C1 — 「OQ-R22 와 함께」라고 했는데 OQ-R22 에는 그 내용이 없다
- 사실 줄 S6:L311: 「오늘 10초 회차에도 같은 틈 · 오늘 화면에 C1 을 어떻게 적용할지는 OQ-R22 와 함께」. 그런데 OQ-R22(S6:L434)는 「오늘도 가져올지」만 묻고 C1 을 말하지 않는다.
- OQ-R22 의 기본안 ⓐ(오늘은 사본만 읽음)를 고르면 오늘 화면은 10초 회차의 중간 상태(`emr_sync.py:243` commit 뒤 · `tasks/emr.py:111` 보충 전)를 그대로 읽는다. 그러면 R20 전제(그룹 빈 카드 없음)가 오늘 화면에서는 지켜지지 않는다.
- C1 은 「그 날짜 최신화」의 조건이라 문장상 모순은 아니다. 하지만 오늘 화면에 C1 이 적용되는지가 빈칸으로 남는다.
- 고칠 것: OQ-R22 에 「ⓐ면 오늘 화면은 C1 밖(10초 회차 틈이 보임 — `emr_sync.py:243` · `tasks/emr.py:111`) · 오늘에도 C1 을 걸지」를 한 줄 넣는다.

### W4-3. C1 의 「구매」 범위가 R26 보다 좁게 쓰였다
- R26 범위 = 일정 + 키 보충 + **구매 · 시술권 · 선불카드**. ③-3(S6:L273)과 Rule 7(S6:L371)도 같다. C1(S6:L288)은 「③-3 구매(결제 포함)」만 말한다.
- 시술권 · 카드도 「모두 반영된 상태만」에 드는지 읽는 사람이 짐작해야 한다. 이 화면은 시술권 · 카드를 읽지 않으니(§3 칸 표) 영향은 작다.
- 고칠 것: C1 에 「③-3 구매 · 시술권 · 선불카드」라고 쓰거나, 「이 화면이 읽는 칸만」이라고 범위를 밝힌다.
