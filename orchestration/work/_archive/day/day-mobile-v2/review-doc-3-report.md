## 2. 잔재 · 새 어긋남 grep

같은 줄 안의 `~~` 짝으로 「취소선 밖 = 살아 있음」을 가렸다. 검색어는 「줄마다 취소」 · 「취소할 때마다」 · 「취소 횟수」 · 「채널 이름 … 미정」 · 「사용자가 만든다」 · 「두 벌」 · 「사용자 준비」 · 「Firebase 준비」 · 「닫힐 때만」 · 「migration 없음」 · 「확인 안 됨」이다.

### WARN

- **N-1. `S5:458` OQ-N16(닫음) 행에 「다만 줄마다 취소하면 알림은 취소 횟수만큼 온다(줄 단위 · 기록)」가 살아 있다.**
  - 사용자 답 OQ-N17 「일부 줄 취소 = 알림 없음 · 완전히 닫힐 때만 한 번」과 정반대다(`S5:271` · `:459`). 같은 파일에서 두 동작을 말한다.
  - 고칠 것: 그 구절에 취소선을 긋고 「→ OQ-N17 닫음: 호출이 완전히 닫힐 때만 한 번(일부 취소 = 알림 없음)」을 단다.
- **N-2. `S5:473` §5 「모델 대조」에 「→ 이번엔 호출 취소 알림을 쓰지 않음 · migration 없음(사용자 2026-11-17 · 다음 스펙)」이 살아 있다.**
  - 이 줄은 origin/main 판부터 있던 문장이라 1 · 2차에서 놓쳤다.
  - 같은 문단 앞부분도 「`notification.kind`(DB enum …)는 … 바꾸지 않는다」로 읽힌다.
  - DAY-SPEC-000 2026-11-20 개정(`doctor_call_cancel` enum 값 추가 = migration)과 맞선다. backend 가 SPEC-005 「모델 대조」를 보고 migration 을 빼면 안 된다.
  - 고칠 것: R-1 과 같은 방식으로 취소선을 긋고 「→ 2026-11-20 개정: `notification_kind` · `push_kind` 에 `doctor_call_cancel` 추가 = migration(DAY-SPEC-000)」을 단다.
- **N-3(작음). 사슬로 여러 호출이 함께 닫힐 때 행 하나의 `doctor_call_id`.**
  - `S5:272` 는 「사슬로 여러 호출이 함께 닫히면 각 호출의 받은 계정 합 · 한 계정에는 한 번」이다. 그런데 알림 행(`S5:273`)은 `doctor_call_id` 칸이 하나뿐이다. 앱의 원래 푸시 지우기(`S5:275` ②)도 `callId` 하나 기준이다.
  - 그래서 두 호출을 다 받았던 계정에서는 한쪽 원래 푸시가 OS 알림 센터에 남을 수 있다.
  - 참고로 지금 코드 `cancel_call` 은 유효 호출 하나만 `closed_at` 을 채운다(`board_calls.py` — `if all(... receivable(call))` 은 `call` 하나). 지금 구현대로라면 「함께 닫힘」은 생기지 않는다.
  - 고칠 것: 「한 계정 한 번일 때 `doctor_call_id` = 유효 호출 · 다른 닫힌 호출의 원래 알림은 서버 `read_at` 으로만 닫음」 한 줄이면 된다. 아니면 「지금 코드상 한 호출만 닫힘」으로 줄인다.
