## ② 화면 A · B · C 가 어디서 보이나

- 틀: CRM 틀 그대로(네이비 바탕 · 둥근 Main · 헤더 44 · 페이지 머리 줄). 왼쪽 아이콘 줄은 **빈 띠**(CRM 메뉴는 에이전시와 무관해 항목을 넣지 않음). 헤더 왼쪽 = 에이전시 이름 | 병원 이름, 탭 = 「요청 목록」 · 「새 요청」.
- **A 요청 목록** = 탭 「요청 목록」의 왼쪽 320 칸(`.ag-side` · 카드 = 기준 `.ibc`). 「답변 대기중 n」 묶음이 맨 위, 그 아래 「보낸 요청 n」(새로 보낸 것이 맨 위). 카드: 이름(발음) · 새 글 빨간 점 · 「답변 대기중」 · 스레드 상태 배지 · 최신 버전 종류 `신규 v1` / 희망 일시 / 예약 그룹 / 여권 성명. 페이지 머리 오른쪽 [새 요청].
- **C 요청 상세 = 스레드** = 같은 탭의 오른쪽. 가운데 400 = 지금 요청 값 요약(고객 7줄 · 구분선 · 「예약 정보 + 버전 배지」 · 내원 일시 · 원장/상담사 · 희망 시술 · 통역 · 유입 채널 · 예약 메모 · 버튼 줄) — 기준 `.rd-left/.rv-l/.rv-kv/.rv-act`. 오른쪽 = 스레드(기준 `.th`): 버전 카드 · 병원 댓글(**왼쪽 회색**) · 내 댓글(**오른쪽 primary-100**) · 시스템 줄 · 입력부. 버튼: 요청됨 = [철회] [수정 요청] / 확정 = [취소 요청] [수정 요청] / 취소됨 · 닫힘 = 없음 + 입력부 없음.
- **B 새 요청 · 수정 요청 폼** = 탭 「새 요청」(수정은 C 의 [수정 요청] · [이 시간으로 수정 요청]에서). 왼쪽 560 = 폼(기준 `.md-form/.md-sec/.fld/.ct-box/.md-foot` · 예약 등록 창 모양), 오른쪽 = 「예약 가능 시간」 표(기준 `.rd-sum/.sum-t` · 열 = 예약 그룹 · 줄 = 10:00 ~ 21:00 · 칸 = 가능/마감 · ‹ › 날짜). 칸을 누르면 내원 일시 + 예약 그룹이 채워짐.

## ⑤ 질문 (정하지 못해 기본값으로 그린 곳)

1. **접근 방식** — 에이전시 로그인? 에이전시마다 링크(토큰)? 시안은 머리에 에이전시 이름 · 병원 이름만 두고 로그인 · 계정 화면을 그리지 않음. 「내 요청 목록」 범위(에이전시 전체 / 담당자 본인)도 이것에 달림.
2. **화면 크기** — 데스크톱(1280 이상) 기준으로 그림. 모바일이 필요한가?
3. **재진 고객 고르기** — `/customers/lookup` 을 이 페이지에 열어 줄지. 시안은 고르지 않음(`customerId` 없이 보냄 → DAY 판정 · 2명 이상이면 A5 처럼 「고객 확인 필요」 댓글).
4. **철회 기록** — 결정 표엔 시스템 줄이 「병원 처리」(`reservation_applied`)뿐. 에이전시가 철회하면 스레드에 무엇이 남나? 시안은 시스템 줄 「요청 철회됨」으로 그림.
5. **생성 전 수정 버전 종류** — 결정 표 「planner 틈 ①: 생성 전 `change` = 신규로 기록」과 브리프 A2 「수정 v2」가 다름. 시안은 브리프대로 「수정 v2」(병원 시연 버튼은 생성 전이면 [예약 생성]). 에이전시 화면에 어떤 종류로 보일지 정해야 함.
6. **취소 요청 뒤 버튼** — 확정 뒤 취소 요청을 보내 병원 처리를 기다리는 동안(상태 요청됨 · 최신 = 취소) 수정 · 철회를 열지? 시안은 버튼 없음(댓글만).
7. **가능 시간 표 단위** — ext `GET /availability` 의 시간 단위(1시간 / 30분) · 그룹 열 수 · 「마감」을 보여 줄지. 시안 = 1시간 줄 · 그룹 5열 · 가능/마감. 칸 고르기 외에 날짜를 달력으로 고르는 길이 필요한가(지금은 ‹ › 만).
8. **유입 채널 표시** — 페이지마다 고정 `funnelId` 의 이름을 무엇으로 보일지(에이전시 이름 = KOS 유입 채널 이름인가). 시안 = 「한빛 트래블」 한 줄(폼 아래 · 요약).
9. **알림** — 병원 새 글을 에이전시가 어떻게 아나(이 페이지 점 · 메일 · 없음). 시안은 목록 빨간 점만(열면 꺼짐). 알림 설정은 그리지 않음.
10. **댓글 글쓴이 이름** — ext 댓글 `authorName` 에 에이전시 담당자 이름을 넣을지. 시안은 「윤하늘」.

## 결정과 다르게 그린 곳 · 제안

- 제안: 목록 「답변 대기중」을 따로 묶어 맨 위에 둠 → 「새로 보낸 것이 목록 맨 위」는 「보낸 요청」 묶음 안 맨 위가 됨. 한 줄로 합칠지는 사용자 확인.
