## 1. 무엇을 만드나

DAY CRM 에는 링키(외부 서비스)가 ext API 로 예약 **요청**을 보내고, 병원 코디가 예약 현황판 「예약 요청」 스레드에서 답하는 기능이 막 생겼다(SPEC-008). 이번 시안은 **링키가 아닌 외부 에이전시**가 같은 요청을 보내는 **별도 웹 페이지**다.

- 이 페이지 = 링키가 ext 로 보내는 것과 **같은 형식**을 사람이 화면에서 채워 보내는 곳. 병원 쪽 화면(현황판 스레드)은 그대로이고, 이 페이지는 그 스레드의 **반대편(요청 보내는 쪽)** 이다.
- 디자인 = **우리 CRM 디자인과 비슷하게**(사용자 11-27). 기준 시안의 「CRM 공통」 토큰 · 부품으로 그린다.
- 유입 채널 = 페이지마다 다르다(사용자 11-26: 「외부 에이전시용 페이지, 병원 공식 홈페이지 … 유입값이 각 외부 페이지에 따라 다를 것」). → 이 페이지는 **유입 채널이 정해져 있다**(고르지 않음 · 읽기 전용 표시).

## 3. 계약 — 화면 · 상태 (전부 시안에 있어야 한다)

### 3-1. 화면 셋 (한 파일 · 탭 또는 왼쪽 메뉴로 오감)

**A. 요청 목록**
- 내가 보낸 요청 스레드 목록: 고객 이름 · 희망 일시 · 예약 그룹 · 스레드 상태 배지(요청됨 · 확정 · 취소됨 · 닫힘) · 최신 버전 종류(신규 · 수정 · 취소) · 병원 새 글 점.
- 병원이 변경 요청을 보내 「답변 대기」인 것이 눈에 띄게.
- [새 요청] 버튼.

**B. 새 요청 폼** — 칸 = `ext-request-body-draft.md` §1 · §3 (`customerId` 는 뺀다 — 이 페이지는 DAY 고객 id 를 모른다)
- 고객: 이름(필수 · 여권 성명) · 발음 이름 · 성별 · 국적 · 생년월일 · 이메일 · 연락처(국가번호 + 번호) · SNS(종류 + 계정)
  - **식별값 규칙(최종 · 초안보다 우선)**: 생년월일 · 연락처 · SNS · 이메일 중 **하나 이상** 필수(생년월일 단독 필수 아님). 하나도 없으면 보내기 막고 안내.
- 예약: 내원 일시(필수) · 예약 그룹(필수 · 목록에서) · 지정 원장(선택 · 직원 목록) · 지정 상담사(선택 · 직원 목록) · 희망 시술(글) · 통역 언어(선택 · 없음 = 통역 필요 없음) · 예약 메모
- 유입 채널: **고정 값 읽기 전용** 한 줄(예: 「유입 채널 · ○○ 에이전시」 — 가짜 값).
- 내원 일시 고르기 = 기준 시안 예약 현황 요약 표 모양을 빌린 **빈 시간 표**(ext `GET /availability` 가 있다 — 그룹별 · 시간별 가능 여부만, 다른 고객 정보 없음). 날짜 ‹ › 넘기기.
- 보내기 → A 목록 맨 위에 「요청됨 · 신규 v1」로.

**C. 요청 상세 = 스레드** (기준 시안 3열 스레드를 이 페이지 쪽 시점으로)
- 위: 지금 요청 값 요약(최신 버전) · 스레드 상태 배지
- 스레드: 버전 카드(신규 v1 · 수정 v2 · 취소 v3 · 앞 버전 대비 바뀐 값 「13:00 → 14:00」) · 병원 댓글(직원 이름) · 내 댓글 · 시스템 줄(「예약 생성됨」 · 「예약 수정됨」 · 「예약 취소됨」 — 병원이 처리했을 때만)
- 병원 **변경 요청** 댓글(예: 「14:00 가능할까요?」 + 제안 일시) → 상태 「답변 대기중」 · 이 쪽 버튼: [이 시간으로 수정 요청](제안 일시로 채운 수정 폼 열기) · 그냥 댓글로 답하기. 새 버전을 보내면 그 제안은 「대체됨」.
- 아래 입력부: 댓글 글 + 보내기.
- 버튼(스레드 상태에 따라):
  - 요청됨 → [수정 요청](완성본 폼 · 값 채워짐) · [철회]
  - 확정 → [수정 요청] · [취소 요청](사유 선택 입력)
  - 취소됨 · 닫힘 → 버튼 없음(읽기만)
