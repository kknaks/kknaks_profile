# 정정 4 — 저장소 컨테이너가 생겼다 · 이름은 `dev` · `prod` (2026-11-11 · 코디 실물 확인)

사용자(2026-11-11): 「env 없는데? 컨테이너 안 받은 거 아니야?」 → 코디가 저장소를 조회했다.

## 사실 (코디 확인 2026-11-11)

- 저장소에 컨테이너 셋: **`dev` · `prod`** · `files`(처음 만든 것). `daydev` · `dayprod` 라는 이름의 컨테이너는 **없다** — 인프라 담당이 만든 이름은 `dev` · `prod` 다.
- 권한: 사용자 계정 = `dev` · `prod` · `files` 각각에 파일 쓰기(Storage Blob Data Contributor) · 저장소 계정 Reader.
- **서버(VM 관리 ID)**: dev api 컨테이너 안에서 관리 ID 토큰으로 `dev` · `prod` · `files` 세 컨테이너 모두 목록 읽기 = 됨(HTTP 200). 올리기 · 읽기 · 지우기는 아직 확인 안 함(코드 배포 뒤).

## 고칠 것

- 컨테이너 이름: `daydev` → **`dev`** · `dayprod` → **`prod`**(스펙 · 작업 계획 · Delivery 의 모든 자리). 「아직 없음 · 사용자가 인프라에 요청」 → **「있음(2026-11-11) · 관리 ID 권한 확인됨(목록 읽기)」**. 미결 줄 「컨테이너 요청」은 닫는다.
- `files` 컨테이너: 쓰지 않는다(사실로 한 줄 · 지울지는 사용자/인프라 — 판단 문장 없음).
- 코드 워크트리 `deploy/config/dev.env` 의 `DAY_BLOB_CONTAINER` 는 코디가 이미 `dev` 로 고쳤다(설정값 · 코드 변경 없음 · `tests/deploy` 102 passed). `prod.env` 는 값 없음 그대로.
- 그 밖 계약(환경 = 컨테이너 · 키 `{용도}/{병원 id}/…` · 관리 ID · 실패 동작)은 9판 그대로.
