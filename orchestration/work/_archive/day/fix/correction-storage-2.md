# 정정 — 저장소 7판 문서 리뷰 지적 + 사용자 결정 (2026-11-11 · 코디)

근거: `review-doc-3-report.md`(판정 WARN · FAIL 0 · WARN 7 · 계약 변경 없음) · 사용자 2026-11-11.

## 사용자 결정 (새로 확정)

1. **폴더 이름 `chat` · `identity` · `before-after` 확정**(「응 폴더 이름 그대로 쓸 거야」) — 스펙의 「코디 기본값」 표시를 사용자 확정으로 바꾼다.
2. **환경 분리는 「환경마다 접근할 컨테이너를 다르게」로도 할 수 있어야 한다**(사용자: 「컨테이너만 분리해서 생성하면 각각 env 에서 접근할 컨테이너가 달라지는 거 아니야?」). 지금 컨테이너는 하나뿐이고 새 컨테이너는 인프라 담당에게 요청해야 한다(우리 권한 밖). 그래서:
   - **컨테이너 이름은 환경별 설정값**이다(`DAY_BLOB_CONTAINER` — dev · prod 가 **다른 값을 가질 수 있다**). 7판의 「dev · prod 같은 값」은 「지금은 같은 값(컨테이너가 하나뿐이라)」으로 고친다.
   - 컨테이너가 환경별로 나뉘면 dev 는 dev 컨테이너만, prod 는 prod 컨테이너만 **설정상** 본다 — 이것이 사용자가 말한 분리다. (같은 VM 관리 ID 가 두 컨테이너 권한을 다 가지면 권한상으로는 서로 읽을 수 있다는 한계는 문서에 사실로 한 줄만 — 판단을 붙이지 않는다.)
   - 맨 위 환경 폴더(`{APP_ENV}/`)는 **그대로 둔다**(사용자 확정 「dev/prod 디렉토리 나누고」) — 컨테이너가 나뉜 뒤에도 해가 없고 설정 실수를 막는다.
   - 컨테이너 분리 요청 자체는 사용자가 인프라 담당에게 한다 — 미결 「dev ↔ prod 차단」 줄을 이 내용으로 고친다.

리포트의 「고칠 방향」대로. 코디가 정한 것:
