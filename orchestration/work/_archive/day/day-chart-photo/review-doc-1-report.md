## 5. 구현 가능성 · 6. 서로 맞는지 — WARN

### W1. 차트 탭 저장의 `event_log` 「요청 하나에 1행」이 규칙 27 과 부딪힘
- `spec-002:1144`(규칙 31 ④ 「`event_log` 는 요청 하나에 1행 `visit.chart_save`」) · `:1135`(규칙 21 「조작 1번 = `event_log` 1행」) vs 같은 규칙 31 ② 「수락 · 진행중은 **규칙 27 전부**(… `event_log` `task.doctor_change` …)」.
- 근거: 코드 `services/board_tasks.py:272 · :307` — `_change_doctor_rows` 가 `task.doctor_change` 1행을 쓴다. 의사차트 탭에서 집도의를 바꾼 줄이 N개면 한 요청에 `visit.chart_save` 1 + `task.doctor_change` N 행이 된다. 앞 판(줄 저장)도 이미 2행이었다.
- 고칠 방향: 규칙 31 ④ 를 「차트 저장 이벤트는 요청 하나에 1행 — 규칙 27 의 `task.doctor_change` 는 줄마다 그대로」로 적는다. outbox 를 어느 event 에 묶는지도 적는다(지금 코드 `_queue(session, current, v, event, intents, …)` = 그 저장 event 하나에 묶음 → 「모든 줄의 intent 를 `visit.chart_save` 하나에」가 자연스럽다).

### W2. 사진 직원 토큰 없음 · KOS 401 의 HTTP 응답이 안 닫혀 있음
- `spec-002:788` — 「DAY-SPEC-006 『공지 저장 — KOS 네트워크 · 5xx · 401 · 직원 토큰 없음』 줄과 같은 처리 · `kos_unavailable` 꼴 · **KOS 401 이면 그 세션을 끝내는 갈래도 같음**」.
- 근거: DAY-SPEC-006 :617 = 그 경우 전부 **503 `kos_unavailable`**이고 세션 종료 갈래는 없다. 세션 종료는 코드(SessionExpired)에만 있다 — planner 보고 「SPEC(503)과 코드(SessionExpired)로 갈려 있다」. 코드 워커는 둘 중 무엇을 구현할지 되물어야 한다.
- 고칠 방향: 사진 줄에 HTTP · 코드를 직접 적는다. 예: 「토큰 없음 · KOS 401 → (지금 코드 공지 저장과 같게) 세션 만료 처리 · 그 밖 KOS 실패 → 503 `kos_unavailable`」 둘 중 하나로 정하고 「기본값」으로 표시. SPEC-006 쪽 어긋남은 「무관(기존)」으로 따로 둔다.

### W3. 썸네일 · 원본 · 삭제마다 KOS 목록을 다시 읽는지 안 닫힘(호출 수)
