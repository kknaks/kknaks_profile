## 배경

DAY 직원이 iPhone·iPad에서 시술현황과 같은 병원 활성 직원 간 채팅을 사용할 수 있도록 직원 앱과 필요한 서버 API를 추가한다. [Delivery #235](https://github.com/MediSolveAIDev/CENTURION_DAY/issues/235)의 승인된 v7 결과 계약을 구현한다. 앱은 기존 프로토타입 `77173cf8`의 화면 구조·문구를 유지하고 DAY 색상·권한·서버 계약을 적용한다.

## 변경 내용

### 1. 직원 앱·시술현황·통역

로그인·병원 선택·Keychain 세션 복원과 예약현황/시술현황/채팅/설정 4메뉴를 구성했다. 예약현황은 「곧 출시 예정」이다. 시술현황은 4필터와 카드만 보여 주고, 상태 박스는 2줄·진행 시간은 mm:ss로 표시한다. 원장은 본인 즉시 수락, 간호사 등 대리 권한자는 원장 선택 후 수락한다. 룸 상세는 방 이름을 가운데 두고, 미수락 호출만 강조하며 시술 행은 시작·종료·완료 경과와 더보기에 집중한다. 서버 needs[]·can*·lastSeconds·pickable을 소비한다.

통역은 기존 드로어·빠른 말하기 칩을 유지하며 고객 언어를 매핑한다(TW→중국어 번체). 성공 토스트는 본인 조작 성공 응답에만 표시한다. 서버에 없는 문구·업무 판정을 앱이 만들지 않는다.

### 2. 인증 대상·권한·세션

기존 D1 서버 변경도 포함하는 누적 PR이다. 고정 로그인 진입점에서 데모 이메일을 dev 인증으로 연결하고 일반 계정은 현재 서버에 둔다. 앱은 검증된 로그인 응답의 대상·토큰·환경·만료·직원 ID를 세션 묶음으로 저장하고, HTTP·SSE·WS·네이티브 수락은 그 대상만 쓴다. 늦은 이전 세션 응답은 현재 세션을 바꾸지 않는다.

활성 직원의 채팅 진입은 시술현황 권한과 독립이다. /me 200에서 시술현황 권한만 없으면 셸·채팅·설정은 유지하고 판 API/SSE·고객 정보·통역은 시작하지 않는다. /me 자체 403은 기존 전체 차단을 유지한다. 실제 /me가200이어도 채팅 API/SSE가 비활성 직원·멤버십 상실을403으로 차단한다.

### 3. 내부 채팅·기기·APNs·첨부

같은 병원 활성 직원 간 1:1/그룹 대화·초대·나가기·읽음·숨기기/음소거·수정/삭제·전달·검색·사진/동영상·모아보기를 원형 화면대로 이식했다. 채팅 전용 연결줄·서버 unreadRooms 배지·앱 안 배너와 환경/병원별 푸시 이동을 연결했다.

서버 HTTP20·SSE6종·기기 등록/해제·채팅 APNs·첨부 저장을 추가했다. 방 seq/재가입 from_seq·지운 메시지 포함 clientId 멱등·기기 토큰 이름공간·늦은 이전 로그인 등록/해제 경합을 DB 잠금/유일성으로 보호한다. SSE는 Redis 구독 확인 뒤 HTTP 머리를 보내 재접속 메우기와 구독 사이 누락을 막는다. 첨부는 Bearer·no-store·Range로 제공하고 크기/형식/권한을 검증한다.

APNs/Blob 비밀은 선택 Key Vault 배선으로 준비했으며 미설정 시 기능을 닫는다. 로컬 disk는 전용 사용자 권한과 named volume으로 영속화했다. 실제 키·리소스·서명 값은 넣지 않았다. 채팅 푸시는 종 알림함과 별개다. 알림 목록·종 배지·원장 호출 발송(SPEC005/v8)은 아직 이 코드에 없다.
