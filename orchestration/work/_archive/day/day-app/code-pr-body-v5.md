## 배경

DAY 직원이 iPhone·iPad에서 시술현황을 보고 호출·수락·시술 조작을 할 수 있도록 Flutter 앱을 추가한다. [Delivery #235](https://github.com/MediSolveAIDev/CENTURION_DAY/issues/235)의 승인된 결과 계약을 따른다. 목록과 상세는 기존 직원 앱의 구조에 DAY 브랜드·색과 서버 권한을 적용한다.

## 변경 내용

### 1. 직원 앱과 시술현황

로그인·병원 선택·세션 복원과 예약현황/시술현황/채팅/설정 4메뉴를 구성했다. 예약현황은 「곧 출시 예정」이며, 채팅은 자리만 둔다. 공통 머리에는 DAY·탭 제목·알림 종을 두고 계정은 설정으로 옮긴다. 미읽음 수 서버 계약이 없어 배지는 그리지 않는다.

목록 카드는 방·수납, 고객명·한글 발음, 제공된 기타 정보, 상태 박스 순서다. 시술 대기·마취 중·마취 완료 후 대기·시술 중의 상태 박스는 첫 줄 상태·시간/담당의, 둘째 줄 시술명으로 맞춘다. 복수이면 「외 N개」를 붙이며 화살표는 없다. 진행 중 시간은 초 단위 `mm:ss`, 마취 완료는 분으로 표시한다. 시술 중 시간·담당의·이름은 같은 첫 진행 시술을 설명한다.

목록·상세·호출 탭에서 원장은 본인 즉시 수락, 간호사 등 대리 권한자는 원장 선택 후 수락한다. 의사 호출 시트에서 시술과 원장을 함께 고른다. 룸 상세의 방 이름은 헤더 가운데 두고, 호출 강조 박스는 미수락 시술이 남은 호출만 표시한다. 시술 행의 수락·상태 배지를 제거하고 시작·종료와 경과 시간에 집중했다. 모든 조작은 둘째 줄 오른쪽이며 진행 중은 큰 mm:ss와 [종료]·세로 더보기, 완료는 회색 「완료 N분」과 더보기를 표시한다. 호출 중 [시작]은 비활성이고 준비중·수락 뒤는 기존 서버 canStart를 따른다. 취소는 기존 DAY 확인 창을 거친다. 서버 `needs[]`, `canRecall`, `lastSeconds`, `pickable`과 `can*`를 소비한다.

### 2. 인증 대상과 세션 일관성

고정 로그인 진입점에서 서버가 데모 이메일을 판별해 dev 인증으로 연결한다. 일반 계정은 해당 서버에 남는다. 전체 60초·리다이렉트/재시도 없음·동시 상한 4·dev 장애 시 503을 사용한다. 기존 D1 백엔드 변경을 포함하는 누적 PR이며, 이번 UI 후속 변경은 `app/`에만 있다.

앱은 로그인 응답의 HTTPS origin과 환경을 검증한 뒤 대상·토큰·만료·직원 ID를 Keychain 레코드 하나에 저장한다. HTTP·SSE·WS·푸시 수락은 그 세션 대상만 사용한다. release는 환경값이 없는 응답을 거절하며 로컬 HTTP는 명시한 debug 빌드 설정에서만 허용한다. 이전 세션의 늦은 응답과 숨은 화면의 토스트를 차단한다.

### 3. 통역·실시간·알림 클라이언트

SSE 갱신·재연결과 APNs 기기 등록/해제·알림 이동·네이티브 본인 수락 클라이언트를 구성했다. 통역은 시술현황 보기 권한을 따르며, 기존 드로어와 빠른 말하기의 스피커 아이콘·둥근 칩을 사용한다. TW는 중국어(번체)로 시작하며 앞 고객의 언어로 덮어쓰지 않는다. 원천이 없는 vi/yue 빠른 문구는 추가하지 않았다.

성공 토스트는 본인 조작의 성공 응답에만 2.6초 표시하고 새 토스트가 덮어쓴다. 되돌리기 버튼은 없다. D2 기기/APNs 발송 서버, D3 통역/사전 서버, D5 알림 목록·미읽음 서버 전체는 이 PR 범위 밖이다.
