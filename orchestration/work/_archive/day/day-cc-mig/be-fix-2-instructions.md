# backend 고침 2 — 코드 검수 WARN 반영 (코디 2026-11-20)

검수 리포트 `review-code-1-report.md`(같은 폴더) W1 ~ W7 을 먼저 읽어라. 같은 워크트리 · 같은 범위 · 커밋 금지. W8 은 사용자 결정 대기 — **손대지 마라**(지금 코드 그대로).

- **W1** — 부모 id 묶음 SELECT(`in_`)로 N+1 제거 · `external_updated` 한 문 · 반영 상한을 10초 주기보다 짧게 하거나 `schedules` 와 같은 잠금 안에서 반영(동시 쓰기 · deadlock 방지 — 고른 방식과 이유를 리포트에) · query-count 테스트 1개.
- **W2** — 목록 밖 값 · 반영 실패 경고는 프로세스 단위(또는 Redis 한 번 · TTL 하루)로 한 번만 · 이후는 셈만.
- **W3** — `missing` · `unresolved` 만 있는 회차도 셈 한 줄(값 바뀔 때만이든 주기든 폭주 없게) · 잠금 못 얻음 로그 · `tasks/emr.py` `_kos_keys` 배선 테스트(반영 실패 · 지연에도 일정 · 기준 정보 · 구매 태스크 status 그대로 · `run_hospital` 예외에도 master status).
- **W4** — `visit.reservation_status_at` 은 이번에 채우지 않는다(P08 · P33 는 2단계 ext 의 「예약 하나 · 날짜 하나 받기」에서 붙인다). 테스트 주석 「상세」 정정 · 리포트에 「늘 null — 2단계」 명시.
- **W5** — `Refs.link` 를 원래 뜻으로 되돌리고, `external_updated_at` 을 덮지 않는 처리는 **직원 · 상담 · 고객 연결 호출 자리에서만**(그 호출자가 값을 안 넘길 때 유지) — 구매 · 카드 · 메뉴 · 방문 의 「바뀜」 판정은 고침 1 전과 같게. 테스트: 그 네 경로 바뀜 판정이 전과 같음 + 직원 · 상담 · 고객 재회차 쓴 행 0.
- **W6** — 예약 규칙 이력 중복 열쇠 = KOS 원래 값(이력 종류 문자열 · 직원 KOS id · 시각 · payload). 필요하면 원래 값 칸을 0012 에(SPEC 밖 칸이면 멈추고 질문).
- **W7** — 업데이트 경로 진행 키를 stage 별로 분리(지난 백필 위치를 지우지 않게) · 병원 설정 부분은 운영 1시간 새 단계와 같은 잠금 이름 사용.
- 검증: 바꾼 테스트 + migrations · emr 관련 pytest · ruff · mypy 1회. 로컬 DEMO 는 동기화 두 회차만(경고 · 재회차 쓴 행 0 · 회차 시간) — local 세션 하나 · 끝에 해제.
