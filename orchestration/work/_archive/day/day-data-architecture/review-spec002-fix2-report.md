## 새 지적

### M1. 「실패 토스트」를 무엇이 실어 오는지 계약에 없다 — 10초마다 다시 뜨거나, 아예 안 뜬다
- 규칙 22(L494): 「`failed` 가 되면 그 방문을 보는 화면에 실패 토스트를 띄운다(SSE 로 알린 뒤 조각에 토스트)」.
- 그런데 웹 SSE 는 **본문 없는 신호**이고, 받으면 `GET /board` 조각을 다시 받는다(L459-460). 스냅샷 · 조각 값에는 실패를 나타내는 칸이 없다. `reflecting: bool`(L332)은 반영 중 여부일 뿐이고, `sync.lastError` 는 조회 실패다.
- 그래서 정해지지 않은 것이 둘이다. ① 조각이 무엇을 보고 토스트를 그리나(`event_log` `outbox.failed` 행? 실패 op 목록?). ② **한 번만** 띄우는 기준. 조각은 10초마다(L461 ⑤) · 조작마다 다시 오니, 「지금 failed 인 op 이 있으면 토스트」라고 하면 그 방문이 귀가할 때까지 계속 다시 뜬다.
- cc 는 바로 이 자리를 OQ-522 로 열어 둔 채 끝났다(cc SPEC-003 L929 「스냅샷 `kos.status` 가 `failed` 로 바뀔 때 토스트를 띄울지는 정하지 않았다」). 결정은 「토스트만」으로 났지만 싣는 길은 아직 없다.
- 「그 방문을 보는 화면」은 판이 병원 전체 카드를 보여 주므로 결국 그 병원의 시술 현황 화면 전부다. 문구도 그렇게 맞춘다.
- 고칠 방향: 토스트가 무엇에서 나오는지와 한 번만 뜨는 기준을 **기본값 표시와 함께** 적는다. 예: SSE ④ 「outbox 상태가 바뀔 때」 중 `failed` 로 바뀐 순간에만 조각에 토스트를 싣는다. 앱 짝(스냅샷에 실패를 싣는지)도 한 줄 적는다. 사용자 질문은 아니다 — 결정 「토스트만」을 구현할 길을 정하는 일이다.

### M2. 실패 뒤 멈춘 op 의 상태가 없다 — `pending` 으로 남으면 「KOS 에서 고치면 폴링이 맞춤」이 안 된다
- L448: 「`attempts` 3 이면 `failed` … 실패 뒤 같은 방문의 뒤 op 은 보내지 않는다」. 그런데 **보내지 않은 뒤 op 의 status** 를 정하지 않았다.
- L422: 그 방문에 `pending` · `sent` op 이 있고 그 op 이 바꾸는 칸이면 조회 값으로 덮지 않는다.
- 둘을 합치면 이렇게 된다. 호출 op 이 `failed` 가 되면 그 뒤 수락 · 시작 · 종료 op 은 `pending` 그대로 남는다. 그러면 그 칸들(작업 완료 · 집도의 · 단계)은 KOS 값으로 영영 덮이지 않는다. 데스크가 KOS 에서 고쳐도 DAY 가 맞춰지지 않는다 — OQ-07 결정(S-7 L203 · L448 끝)과 정면으로 어긋난다.
- cc 는 이를 정해 두었다. cc SPEC-003 L220 · L311(r2 N2): 「앞 op 실패로 보내지 않은 op 도 `failed`(사유: 앞 op 실패로 보내지 않음) · 멈춘 op id 는 `event_log(kos_failed)` `payload.blockedOpIds`」.
- 고칠 방향: L448 에 cc r2 N2 를 옮긴다. 멈춘 뒤 op = `failed`(사유) · `blockedOpIds`. **N1 의 「토큰 없음 → `pending` 그대로」(규칙 24)와는 다른 경우**라는 것도 한 줄 밝힌다. 토큰 없음은 그 의사가 로그인하면 나가야 하니 `pending` 이 맞다.

### M3. DAY-SPEC-000 `staff.is_system_account`(S0 L608) 설명이 이번 결정과 어긋난다 — 고칠 곳
- 지금 S0 L608: 「사람이 아닌 계정(시스템 · 공용) — 원장 목록 등에서 뺀다 (cc KOS_EXCLUDE_ACCOUNT_IDS)」.
- 실제(#226)와 이번 결정: 이 플래그는 **병원 연결 sign-in 시스템 계정 하나**에만 켜진다. 공용 · 마취용은 1차에 빼지 않는다. cc 제외 id 목록은 따르지 않는다. 이제 S0 설명은 사실도 결정도 아니다. 데이터 칸은 S0 가 정본이라(S2 L25) 구현자가 S0 를 읽으면 공용 계정을 빼는 쪽으로 간다.
- 코디의 「SPEC-000 변경 없음」은 **새 칸 · 설정 키를 만들지 않는다**는 뜻이었다. 설명 한 칸을 사실에 맞추는 것은 그 결정에 어긋나지 않는다. 다음 동기화로 미루지 않고 이번에 고칠 곳으로 판정한다.
- 고칠 방향: S0 L608 설명을 「병원 연결의 sign-in 시스템 계정(`crm_connection.config` `system_email`) — 원장 목록에서 빠지고 KOS 담당자(`assigneeIds`)로 쓴다. 마취용 · 공용 같은 다른 사람 아닌 계정은 1차에 켜지 않는다(사용자 2026-11-06 · DAY-SPEC-002 규칙 19 · 25)」로 바꾼다. cc `KOS_EXCLUDE_ACCOUNT_IDS` 는 지운다.
- 그에 맞춰 S2 닫은 OQ-11(L535)의 「DAY-SPEC-000 변경 없음」은 「DAY-SPEC-000 새 칸 없음 · `is_system_account` 설명만 맞춤」으로 바꾸고, log 줄에 DAY-SPEC-000 을 더한다.
