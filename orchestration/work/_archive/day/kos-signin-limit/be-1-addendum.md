# be-1 추가 지시 (코디 2026-11-17 · 사용자 결정) — 이 파일이 브리프 §3-3 · §7 보다 우선

사용자: 「로그아웃 때 해제 안 해도 된다 · 다시 로그인할 때 선택하면 된다」 → **직원 기기 선택 단계를 이번 범위에 넣는다.** 로그아웃 때 KOS 해제는 하지 않는다(그대로 범위 밖).

## 흐름 (웹 로그인 · 앱 로그인 API 둘 다)
1. 직원 sign-in → 401 `SignInLimitExceeded`.
2. 서버가 그 자리에서 목록(`get-active-sign-ins` · 이메일 · 비밀번호)을 받아 **선택 단계**로 보낸다 — 지금 로그인의 「병원 고르기」 중간 단계(`pending_token` · `services/auth.py` :186- · 웹 템플릿 · 앱 API)와 **같은 방식**으로 새 단계 하나.
3. 사용자가 하나 고르고 「계속하기」 → 서버가 그 `signInId` 를 해제(`revoke-active-sign-in`) → sign-in 다시 → 이후는 지금 로그인 흐름 그대로(병원 고르기 등).
4. 비밀번호는 선택 단계 동안 **서버 임시 보관만**(Redis 등 기존 pending 보관 자리 · **5분 만료 · 한 번 쓰면 삭제**). DB · 로그 · 화면 hidden 칸 · 응답에 넣지 마라. 만료되면 처음 로그인으로(기존 만료 오류 처리 재사용).
5. 다시 sign-in 이 또 막히면 목록을 다시 보여 준다(무한 반복 없이 사용자 선택마다 1회).

## 화면 (웹) — 새 시안 없음 · 병원 고르기 화면과 같은 레이아웃 · DS 컴포넌트 · 손 CSS 0 · 인라인 스크립트 0
글자는 KOS 화면 문구 그대로(사용자 승인) — 그 밖 글자 짓지 마라:
- 제목 「이미 로그인 중인 기기가 있습니다」
- 안내 「최대 5개 기기에서만 동시 로그인이 가능합니다.」 / 「아래 목록 중 로그아웃 시킬 기기를 선택해주세요.」
- 항목 = 라디오 카드 하나만 선택 · 1줄 「{OS} {브라우저} · {IP}」 · 2줄 상대 시각(「n분 전」 · 「방금 전」 — 기존 상대 시각 함수가 있으면 그것) · 처음 선택 = 첫 항목
- 버튼 「계속하기」
- `{OS} {브라우저}` 는 `userAgent` 를 간단히 읽어 만든다(예 macOS Chrome) · UA 끝 표시 ` (local)` 등은 이번엔 따로 바꿔 보이지 않는다(글자 미정).

## 앱 API
- 같은 단계를 앱 로그인 API 에도(새 응답 단계 · 목록 · 선택 제출 엔드포인트). **앱 코드는 고치지 마라** — 깔린 앱이 이 새 단계를 받으면 어떻게 보이는지(일반 실패 등) 코드 사실로 리포트에.

## 테스트 추가
- 막힘 → 선택 단계(목록 · 비밀번호가 응답 · 화면에 없음) → 선택 제출 → 해제 + 재 sign-in → 로그인 완료 · 만료 · 잘못된 signInId · 재차 막힘.
