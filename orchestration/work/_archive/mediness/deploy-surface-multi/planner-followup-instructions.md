# [planner 추가 지시] 시안(21-html) 을 surface 축에 맞춘다

**보고 잘 받았다. SPEC-051 개정은 통과다** — 코디가 직접 `lint-pipeline.py --strict` 돌려 0 error 확인했고, 옛 2축 표현 잔존 grep 도 통과했다. `기본` 을 sentinel 로 만들지 않고 **그룹 행 수**로 `/gm` surface 표기를 판정한 것, `surface_key` 만 PATCH 허용하고 `product_slug`·`environment` 를 불변으로 둔 것, NOT NULL 을 계약으로 못박은 것 — 세 판단 다 맞다.

네가 ②로 보고한 **`21-html` 미수정이 이번에 닫혀야 한다.** 내가 앞 브리프 §5 에서 "실질 수정 대상은 spec-051 한 파일"이라고 좁게 적은 탓이다 — **네 잘못이 아니다.** 범위를 여기서 넓힌다.

## 왜 닫아야 하나

FE 코드가 이 파일을 시안 SoT 로 참조한다 (`front/components/admin/products/DeployInfoModal.tsx` 머리 주석 = `시안 deployModal SoT`). 시안이 구 모델(「제품 × 환경 = 유니크」)을 말하는 채로 FE 구현을 발주하면 **워커가 시안을 보고 구 모델을 만든다.** 스펙과 시안이 갈린 채로 구현에 들어가는 게 제일 비싸다.

## 대상 — `products/mediness/21-html/Product Management.html` 한 파일

**이건 디자인 재설계가 아니라 확정된 모델의 기계적 반영이다.** 색·간격·타이포·레이아웃 골격을 바꾸지 마라. 바꾸는 것은 **배포정보 모달의 데이터 축 하나**다.

확인된 자리 (전수는 아니다 — 네가 다시 훑어라):

1. `:269` — `환경(prod/stg/dev)별 서버 URL + 시연계정. 제품 × 환경 = 유니크.` 설명 문구
2. `:276` — `제품 × 환경 중복이면 저장 시 409.` 안내 문구
3. `:518` — 저장 로직 주석 `제품 × 환경 중복은 인라인 경고`
4. `:453 envBlockHTML(d={})` — 블록에 **surface 입력 필드**가 없다
5. `:515 nextEnv()` — **이미 쓴 환경을 소진**시킨다(= FE `usedEnvs` 와 동형). surface 축이 생기면 **같은 환경을 다시 고를 수 있어야 한다**
6. `:398 DEPLOYS` 목업 데이터 — 행 shape 에 `surface` 없음
7. `:536` 저장 시 중복 판정 축

## 해야 할 것

1. **`Product Management.html` 을 열어 배포정보 모달 관련 전 구간을 훑어라.** 위 7개는 내가 grep 으로 본 것뿐이고 전수가 아니다 — **「제품 × 환경」이 유니크라고 가정하는 자리를 전부 찾아라.** 하나 남으면 FE 워커가 그걸 본다.
2. 블록에 **surface 이름 입력 필드**를 넣는다. 자유 입력 텍스트(§Validation: 비어있지 않음 / 같은 제품·환경 안 중복 금지). 기존 필드들과 같은 스타일·같은 간격을 쓴다 — 새 컴포넌트를 발명하지 마라.
3. **환경 소진 로직을 없앤다** — 같은 환경으로 블록을 여러 개 추가할 수 있어야 한다. `nextEnv()` 의 역할을 다시 정해라.
4. **중복 판정 축을 `(제품, 환경, surface)` 로** 바꾼다 (목업 저장 로직 + 안내 문구 + 409 문구).
5. **목업 데이터에 한 환경 복수 surface 예시 1건**을 넣어 시안만 봐도 이 모양이 보이게 한다. **`nexus` 의 실 URL·실 계정은 쓰지 마라** — 목업다운 가짜 값(`https://example…` 류)으로. 비밀번호 평문 금지는 그대로다.
6. 시안이 **SPEC-051 §2 Wireframe·UX Contract 와 어긋나지 않는지** 대조한다. 어긋나면 **시안을 스펙에 맞춘다**(스펙이 방금 사용자 확정을 반영한 쪽이다).

## 범위 제약 — 그대로 유지

- **spec-051 을 다시 고치지 마라.** 이미 통과했다. 6번 대조에서 **스펙 쪽이 틀린 게 발견되면** 고치지 말고 보고해라 — 내가 판단한다.
- WP 작성 금지 · 코드 레포 수정 금지 · 커밋/push/PR 금지 — 전부 그대로.
- 디자인 톤(색·폰트·간격·아이콘)을 바꾸지 마라. 축 하나만 넣는다.
- `21-html` 의 **다른 화면·다른 섹션**은 건드리지 마라. 배포정보 모달 관련 구간만.

## 검증

- `python3 scripts/lint-pipeline.py --strict` → mediness ERROR 0 유지 (기존과 동일).
- 브라우저 없이라도 **목업 JS 를 눈으로 따라가** 같은 환경 블록 2개가 추가되고 surface 가 다르면 저장되는지, 같으면 경고가 뜨는지 논리로 확인해라.
- `products/mediness/21-html/Product Management.html` 안에 **「제품 × 환경」 유니크 가정이 한 군데도 안 남았는지** grep 으로 전수 확인.
