# [backend] 2루프 E-6 — AX 초안 수정 = 옛 초안 닫고 새 초안 (사용자 결정 2026-10-07)

기존 규칙 그대로(커밋 금지 · 관련 시험만 · `frontend/` 손대지 마라 — FE 2루프 진행 중). 원인은 네 리포트 `W/be-loop2-report.md`(mcp.py:460 · 사유 가려짐).

## 사용자 결정 — A-3(대체형)
- 사용자가 대화에서 초안을 고치라고 하면(「체크리스트 줄여 줘」 · 「참석자 추가해 줘」 등) AX 는 **고친 전체 내용으로 새 초안 제안**을 낸다(업무 `task.create_self` · `work_request.create` · 회의 `meeting.reservation.create` 모두)
- 서버는 새 초안이 설 때 **같은 대화의 같은 종류 대기(pending) AX 초안을 닫는다** — 옛 카드에 「새 초안으로 대체됨」. 등록(확정)은 지금처럼 사람만
- 위임 턴의 `action_item_command` 는 지금처럼 `ax.*` 항목을 막는다(save_draft 도) — 고치는 길은 새 제안이다. 거절 문구는 명령에 맞게(「기존 초안은 고치지 않고 새 초안을 내세요」)
- **C 전부**: C-1 도메인 예외 → `ToolError("<코드>: <한 줄>")` · C-2 Codex 요약이 실패 결과의 사유를 쓴다(`codex_cli.py:816`) · C-3 명령별 문구

## 먼저 확인 — 테이블이 받는가
1. `action_items`·결정 항목·submission 상태값에 「대체됨/닫힘」 으로 쓸 수 있는 값이 **이미** 있나(파일:줄). 화면이 그 상태를 어떻게 그리나(카드가 사라지나 · 표지가 서나)
2. 「같은 대화의 같은 종류 대기 초안」 을 찾을 수 있나(대화 id · 턴 · kind 연결)
3. **새 상태값·칸·마이그레이션이 필요하면 구현하지 말고 그 내용만 리포트로 보고** — 사용자에게 다시 묻는다. 기존 값으로 되면 구현한다

## 구현(위 확인이 「기존으로 된다」 일 때만)
- 새 AX 초안 생성 경로에 「같은 대화 · 같은 kind · pending 인 옛 AX 초안 닫기」 를 같은 트랜잭션으로 · 정책·도구 설명에 「고치라고 하면 고친 전체 내용으로 새 초안」 (부분이 아니라 **전체** — 체크리스트 100개면 줄인 결과 전체)
- 시험: 업무 초안 수정 요청 → 새 초안 · 옛 초안 닫힘 · 다른 대화/다른 종류는 안 닫힘 · 회의 초안 참석자 추가 → 새 초안 · 도구 실패 사유가 모델·실행 기록에 남음 · 재현 시험 `test_e6_ax_draft_save_repro.py` 를 새 동작에 맞게
- 화면 쪽 표지(「새 초안으로 대체됨」)가 FE 변경을 요하면 리포트에 FE 몫으로 적어라(네가 고치지 마라)
