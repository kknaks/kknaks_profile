# [backend] 2루프 E-6 — AX 도 사람과 같은 「수정」(save_draft → 같은 카드 다음 회차) (사용자 결정 2026-10-07 · 대체형 결정을 바꿈)

기존 규칙 그대로(커밋 금지 · 관련 시험만 · `frontend/` 손대지 마라). 앞 판 C(사유 노출)는 그대로 둔다.

## 결정 (사용자)
- **누가 고치든 같은 수정이다** — AX 전용 도구를 만들지 않는다. 사람이 [수정]→저장할 때 쓰는 `save_draft` 를 AX 도 쓴다 · 결과는 **같은 카드의 다음 회차**(초안 1 → 사람 수정 2 → AX 수정 3). 옛 회차는 회차 이력에만 남는다 · ~~옛 카드 닫고 새 카드(대체형) · 새 상태값 superseded~~ 는 하지 않는다
- 대상: AX 초안 셋 — `task.create_self` · `work_request.create` · `meeting.reservation.create`(`DRAFT_SAVE_ACTION_TYPES`)

## 할 일
1. `entrypoints/mcp.py:460` 위임 턴 거절에서 **`save_draft` 만 통과**(그 항목에 서버가 save_draft 를 열어 둔 경우만 — 봉투 규칙 그대로). **확정(confirm)·거절(reject)은 지금처럼 막는다**(`AX_DECISION_REFUSED`). C-3 의 `AX_DRAFT_EDIT_REFUSED` 문구는 이제 쓰지 않으면 걷는다
2. **부분 수정 = 바뀐 칸만 지금 회차 위에 덮기**(메디니스 `merge_intake_patch` 와 같은 규칙): 보낸 칸만 바꾸고 안 보낸 칸은 유지 · 값 `null` = 비우기(선택 칸만) · **모르는 칸·바꿀 수 없는 칸은 422**(조용히 무시 금지 — 사유는 C-1 로 AX 에게) · 체크리스트 같은 목록 칸은 **목록 전체를 보내면 그 목록으로 교체**(항목 단위 add/remove 는 만들지 않는다). **사람 저장도 같은 병합 규칙을 탄다**(지금 화면이 전체 draft 를 보내도 결과가 같아야 한다 — 회귀 시험). 첨부 선택을 안 보내면 지금 회차 것을 유지
3. 정책·도구 설명: 「사용자가 초안을 고치라고 하면 `save_draft` 로 **바뀐 칸만** 보낸다 · 등록은 사람이 한다」
4. 회차 기록에 **누가 고쳤는지(사람/AX)** 가 남는지 확인 — 이미 남으면 그대로, 남지 않으면 새 칸 없이 기존 기록(audit 등)으로 되는지 · 새 칸이 필요하면 구현하지 말고 리포트에
5. 시험: 업무 초안 체크리스트 줄이기(AX save_draft → 2회차 · 나머지 칸 유지) · 회의 초안 참석자 추가(AX) · 초안→사람 수정→AX 수정 = 3회차이고 사람이 고친 칸 유지 · 모르는 칸 422 + 사유 · AX 의 confirm/reject 여전히 거절 · 사람 전체 draft 저장 회귀 없음 · 고친 것 없으면 회차 안 오름 · 재현 시험을 새 동작에 맞게
