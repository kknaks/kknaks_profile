## 2. 바꾼 것

### 2.1 슬랙 — 채널 맨 아래 입력창
- 대화 아래 고정 입력창(대화 폭 880 에 맞춤): 서식 막대 **굵게 · 기울임 · 링크 · 목록 · 코드**(모양만 — 누르면 아무 일 없음) → 입력칸(placeholder 채널 「#pilot-launch에 메시지 보내기」, DM·그룹 DM 「오지훈에게 메시지 보내기」) → 아래 줄 왼쪽 **「+」 = 첨부 창 열기**(숨은 `<input type=file multiple>`) · 「Enter 보내기 · Shift+Enter 줄바꿈」 · 오른쪽 **보내기**(글·첨부가 없으면 비활성)
- 고른 파일은 입력창 **안**에 DS `FileList` 줄(종류 글리프 · 이름 · 크기 · 빼기)로 선다
- 파일을 입력창 위로 끌어오면 **칸 전체가 DS `.scax-dropzone.scax-dropzone--over`** 모양(연보라 바닥 · 보라 점선)이 되고 가운데 DS `__cursor` + 「여기에 놓으면 첨부됩니다」, 안의 것은 흐려진다. 놓으면 FileList 에 붙는다
- 보내면 **내 이름(유하람)** 의 메시지로 대화에 바로 선다(사용자 토큰) — 「보내는 중…」(본문 흐림) → 잠시 뒤 보통 메시지. 첨부는 받은 메시지와 같은 파일 카드(여러 개면 「N개의 첨부 파일」 묶음)
- 실패: 메시지 아래 붉은 「보내지 못했습니다 · **다시 보내기**」 → 누르면 다시 보내는 중 → 보냄. 보내는 중·실패 줄은 연속 묶음에서 뺀다

### 2.2 슬랙 — 스레드 답글
- 「답글 N개」를 펼치면 답글 아래에 **작은 입력창**(「답글 달기…」 · 서식 막대 없음 · 「+」 첨부 · 끌어다 놓기 · 보내기) — 첨부 방식은 같다
- 보낸 답글은 스레드 안에 내 이름으로 붙고 「답글 N개」·「마지막 답글」이 갱신된다

### 2.3 메일 — 답장 · 전체 답장
- 원문 머리 오른쪽 **`답장` · `전체 답장`**(작성 중이면 비활성). `전달`·새 메일 쓰기는 없다
- 누르면 **원문(과 첨부) 아래에 답장 작성 칸**이 펼쳐진다(모달 아님)
  - 머리: 「답장」/「전체 답장」 · 「보내는 계정 {받은 계정}」
  - `받는 사람` · `참조`: 칩(이름 + 주소 · × 빼기) + 주소를 쳐서 Enter/쉼표로 더하기. **답장** = 보낸 사람만 · 참조 비움 / **전체 답장** = 보낸 사람 + 받는 사람(나 빼고) · 참조 그대로(나 빼고)
  - `제목`: `Re: {원 제목}` 고정
  - 본문 입력칸
  - 「··· 이전 내용」 접힘 — 펼치면 원문 날짜·보낸 사람 + 원문 인용
  - **DS `DropZone`**: 머리 「첨부할 파일을 끌어다 놓거나 추가하세요」 + 「파일 추가」 · hint **「한 번에 25MB까지」** · 고른 파일은 칸 안에 **DS `FileList`**. 25MB 를 넘는 파일은 지우지 않고 흐리게 + 「25MB 를 넘어 붙지 않습니다」(FileList `reason`) — 이 파일이 있으면 보내기 비활성
  - `취소` · `보내기`
- 보내는 중: 보내기 단추가 「보내는 중…」 비활성 · 입력·첨부 잠김
- 보냄: 작성 칸이 닫히고 원문 아래에 **「보낸 답장」** 한 덩어리(받는 사람 · 참조 · 방금 · 본문 · 첨부 파일 카드)
- 실패: 작성 칸 안에 StatusNote 「답장을 보내지 못했습니다 / 연결이 끊겼거나 Gmail 이 받지 않았습니다. 쓴 내용은 그대로 남아 있습니다.」 + `다시 보내기`

### 2.4 상태 토글 (시안 전용)
- 앞 판 `StateSwitch`(고정 문구) 대신 같은 DS 모양의 `DevSwitch` 를 화면 파일 안에 두었다 — **화면 머리 가운데 한 줄**(아래에 두면 슬랙 입력창을 가린다)
- `화면`: 기본 · 빈 · 로딩 · 오류 (앞 판 그대로)
- `답장`: 없음 · **작성 중** · **스레드** · **끌어오기** · **보내는 중** · **보냈음** · **실패**
  - 메일에서: 작성 중 = 전체 답장 칸 + 본문 + 첨부 2(하나는 31MB 라 「못 붙은 이유」) · 보내는 중 · 보냈음(「보낸 답장」 덩어리) · 실패
  - 슬랙에서: 작성 중 = 입력창에 글 + 첨부 1 · 스레드 = 첫 스레드 펼침 + 답글 입력창에 글·첨부 · 끌어오기 = 입력창 `--over` · 보내는 중 · 실패 = 대화 끝에 내 메시지
- 실제로 누르는 보내기는 시안에서 늘 성공한다(1.2초 뒤). 실패는 토글로만 본다

- node 렌더(react-dom/server, `_ds_bundle.js` 의 DropZone·FileList 실제 부품 포함): 답장 상태 7 × (메일 m1 · 채널 r1) — 예외 없음. 메일 작성 칸·DropZone·「한 번에 25MB까지」·못 붙은 이유·보내는 중·실패·보낸 답장, 슬랙 입력창·FileList·`--over`·보내는 중·실패·스레드 답글 입력창이 각 상태에서 나온다. placeholder 채널/DM 둘 다 확인
- 코드(주석 제외)에 「업무로 추가 · 내 업무로 · 확인완료 · 원문 확인하기 · 대화방 열기 · 전달」 없음
- 헤드리스 Edge 캡처 9장: 메일 작성 중·보냈음·실패, 슬랙 DM 작성 중·끌어오기·실패, 채널 스레드 답글. 캡처에서 찾은 2건(상태 토글이 입력창을 가림 · 받는 사람 칸 입력에 테두리가 생김)을 고친 뒤 올렸다

## 4. 일부러 안 그린 것
- 업무로 옮기기 · 확인완료 · 업무/참고 배지 · 리액션 추가 · hover 행동 막대 — 여전히 없음(결정)
- 메일 `전달` · 새 메일 쓰기 · 숨은참조(BCC) · 서명 넣기 · 받는 사람 자동완성 · 본문 서식(HTML 편집기) — 답장은 평문 칸 하나
- 슬랙 서식 막대의 실제 서식 적용 · 이모지 고르기 · @멘션 자동완성 · 메시지 수정/삭제 · 보낸 메시지 hover 메뉴 · 「채널에도 보내기」(스레드 답글을 채널에 같이 올리기)
- 메일 작성 칸의 끌어다 놓기 `--over` 강제 표시 — DS DropZone 이 상태를 안에 갖고 있어 토글로 켤 수 없다(실제로 끌어오면 뜬다)
- 임시 저장(초안) · 보내기 취소 · 예약 보내기
- 첨부 업로드 진행률 — 보내는 중은 메시지/칸 단위로만 보인다

## 5. 미결·주의
- 25MB 를 넘는 파일이 있으면 메일 보내기를 막았다(빼면 보낼 수 있다) — Gmail 이 메일 전체를 거절하므로 그렇게 그렸다. 「넘는 파일만 빼고 보내기」가 맞으면 말해 달라
- 슬랙 첨부 한도는 문구에 넣지 않았다(계약 사실이 없다)
- 스레드 답글의 「보내는 중/실패」는 채널 메시지와 같은 규칙으로 그렸다(토글에선 채널 쪽만 보인다)
- 「보낸 답장」 덩어리는 메일함의 실제 보낸 메일을 다시 읽어 오는 것인지, 우리가 보낸 기록인지 정해지지 않았다 — 시안은 「방금」 보낸 것을 원문 아래에 붙이기만 한다
- 받는 사람 칩의 이름은 주소 앞부분을 쓴다(새로 친 주소) — 연락처 이름을 붙일지는 정하지 않았다
