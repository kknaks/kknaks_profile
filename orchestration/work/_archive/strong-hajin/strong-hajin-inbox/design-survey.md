### 2.1 틀

- 좌 레일 = `GutterList title="설정 메뉴"` 안의 메뉴, 본문 = 섹션 상자들 (`ST:340`)
- 메뉴 두 묶음 (`ST:9-19`)
  - **연동**: `메일 연동` · `슬랙 연동` · `카카오톡 연동` — 메뉴 줄 꼬리에 **대상 개수**(`counts`, `ST:334`)

- 머리 제목 = 고른 메뉴 이름 (`ST:335`)

## §3 수신함 화면 (`Inbox.html`)

### 3.1 틀

- 내비 `수신함` 항목이 **독립 화면 `./Inbox.html`** 로 연다 (`NAV` `{ id: 'inbox', … href: './Inbox.html' }`), 화면은 `activeId="inbox"` (`IB:175`)
- 좌 레일 = `GutterList title="수신함" count={미읽음 카드 수}` + 머리 끝 출처 전환 / 본문 = 고른 카드의 원문 (`IB:1-2` 주석 · `IB:178-191`)
- 머리 단추: `모두 읽음으로` (`IB:176`)
- 시안 주석: 「레일 머리에 출처 전환(전체·메일·슬랙·카톡)을 둔다 — **업무 탭 수신함 레일과 같은 폼**」, 「카드는 **업무 탭의 InboxCard 규칙을 그대로** 쓰고, 대화방 미리보기 줄과 아래 두 버튼만 더했다」 (`IB:2-4`)

### 3.2 필터·탭

| 무엇 | 시안 | 근거 |
|---|---|---|
| 출처 전환 (SegmentedControl, aria 「출처」) | `전체` · `메일` · `슬랙` · `카톡` | `IB:8-13` · `IB:182` |
| 그 밖의 필터(업무/참고·미읽음 등) | **시안에 없음** | `IB:170` 필터는 `source` 하나 |
| 레일 숫자 | 미읽음 **카드** 수(대화방은 메시지가 여러 건이어도 카드 1) | `IB:172` |

### 3.3 카드 한 장 — 출처별로 모양이 다르다

시안 주석: 「메일은 **단건** 카드, 슬랙·카카오는 **대화방 카드 한 장에 쌓인 메시지를 묶는다 (카드 하나 = 대화방 하나)**」 (`IB:3`). 목데이터 주석: 「메일은 단건(`kind: 'mail'`), 슬랙·카카오는 **대화방 단위**(`kind: 'room'`)로 들어온다. 대화방 카드는 **마지막으로 읽은 뒤 쌓인 메시지**(messages)를 함께 들고 온다.」 (`ID:1-3`)

## §5 기존 수신함과의 관계

**판단: 시안의 「수신함」은 기존 수신함을 대체하지 않는 새 화면이다. 업무 탭의 수신함 레일은 시안에 그대로 남아 있다. 둘을 합칠지는 시안에 나오지 않는다(§7 C-1).**

근거:

1. **화면 자리가 다르다** — 시안 수신함은 내비의 독립 항목 `./Inbox.html` (`NAV`), 기존 수신함은 업무 화면의 **좌 레일** (`MW` `railLeft={<InboxRail …/>}`; 코드 `code/frontend/src/features/work/MyWorkPage.tsx:404` `<InboxRail`)
2. **시안 안에서도 둘이 공존한다** — 같은 프로젝트의 `MyWork.html`(`MW`)은 지금도 `InboxRail` 을 그린다. Inbox.html 이 그것을 지우지 않았다
3. **담는 것이 다르다**
   - 시안 수신함: **외부에서 수집한 것만** — `kind: 'mail' | 'room'`, `source: 'mail' | 'slack' | 'kakao'` (`ID` 전체). 업무 요청·참조·판단 항목 없음
   - 시안 업무 탭 레일: `업무`/`참고` 갈래(`MWD` `INBOX_FILTERS` 전체·업무·참고), 출처 「메일」「메신저」(`MWD` `INBOX_ITEMS`)
   - 기획(S001 U-12): 수신함 = **업무 요청(내가 답할 것) + 참고(CC)**, 참고는 읽으면 사라짐 (`S001:482-503`)
   - 코드: `InboxRail` = **「판단이 필요한 업무」(`actionItems`)**, 분류는 상태 축(전체·판단 대기·조정 필요) (`code/frontend/src/shell/InboxRail.tsx:12-41`). 백엔드 `requests.py:743` `inbox()` 는 업무 요청 수신함
4. **시안이 스스로 「같은 폼」이라고만 한다** — 「업무 탭 수신함 레일과 같은 폼」, 「업무 탭의 InboxCard 규칙을 그대로」(`IB:2-4`), CSS 도 「카드는 업무 탭의 `.scax-inbox-card` 를 그대로 재사용」(`inbox.css` 머리 주석). 모양을 공유한다는 말이지 같은 목록이라는 말은 아니다
5. **이름이 같다** — 둘 다 제목이 「수신함」(`IB:180` `title="수신함"` · `MW` `GutterList title="수신함"`). 기존 기획에서 「수신함」이라는 말은 업무 요청·참고를 가리킨다 (`S001:482`, `B001:167`)

참고 — 앞 판에서 이미 미정으로 남긴 것: 수신함 카드의 아바타·수신 시각·**출처 아이콘·미읽음 수는 계약 없음(M-22)**, 「답장」「원문 확인하기」는 계약 없음·**메일·메신저 통합은 승인 밖**(M-7) (`S003:317-331`). 출처라는 개념은 이미 있다 — 「유입 경로(메일·슬랙·AI 채팅)와 세 행위의 구분은 별개」(`B002:194` V-3).

## §6 기존 기획·코드와 다른 점 (한 줄씩 — 고치지 않았다)

1. 수신함이 업무 탭의 레일이 아니라 **내비의 독립 화면**으로 선다 (`NAV` · `IB`) ↔ 기획·코드는 업무 화면 좌 레일 (`S001` U-12, `MyWorkPage.tsx:404`)
2. 시안 수신함의 항목은 **외부 메일·대화방**이다 ↔ 기획의 수신함 항목은 업무 요청·참고(CC) (`S001:482`)
3. 시안 수신함 필터 축은 **출처**(전체·메일·슬랙·카톡) ↔ 기획 레일 필터는 종류 칩, 코드는 상태 축(판단 대기·조정 필요) (`S003:322-325`, `InboxRail.tsx:36-40`)
4. 슬랙·카톡은 **대화방 하나 = 카드 하나** ↔ 기존 카드는 항목(요청·판단) 하나 = 카드 하나 (`IB:3`, `InboxRail.tsx:100-137`)
5. 시안 수신함은 **읽어도 카드가 남는다** ↔ 기획의 참고 카드는 읽으면 수신함에서 사라진다 (`ID:39`·`:46`, `S001:487`·`:497`)
6. 시안에 **`모두 읽음으로`** 가 있다 ↔ 기획엔 카드별 `읽음` 만, 업무 요청에는 읽음이 없다 (`IB:176`, `S001:494-505`)
7. 시안 카드에 **수신 시각·보낸 사람·출처·미읽음 수**가 선다 ↔ 계약 없음(M-22), 코드는 그리지 않는다 (`IB:33-39`·`:65-84`, `S003:317`, `InboxRail.tsx:18-21`)
8. 시안에 **`답장`·`원문 확인하기`·`대화방 열기`** 가 있다 ↔ 계약 없음(M-7)·메일/메신저 통합은 승인 밖 (`IB:42-43`·`:120`, `S003:326-331`)
9. 기획은 「수신함·메일·그룹웨어 → 다음 slice」로 밀어 두었다 ↔ 시안이 그 slice 의 화면을 그렸다 (`S001:172`, `B001:335` X1)
10. 기존 기획은 메일·그룹웨어 **API·권한·회신 성공 판정을 원문 미결**로 둔다 ↔ 시안은 메일을 **IMAP 계정·비밀번호** 방식으로 그렸다 (`B001:337` C-2, `ST:172-193`)
11. 사용자가 정한 카톡 수집 = **Tauri 앱이 개인 Mac 의 카톡 로컬 DB 를 읽고, 서버엔 복호화 키·저장한 방 ID** ↔ 시안 카톡 화면엔 **기기·키·앱 상태 자리가 없고**, 방을 **이름으로** 넣으며, 「참여자에게 안내가 전송되고 동의 이후부터 적재」라고 쓴다 (브리프 §2, `ST:226-241`)
12. 사용자가 정한 메일 = **회사 Google Workspace** ↔ 시안 폼은 IMAP 하나뿐, Gmail OAuth 는 목데이터 한 줄로만 나온다 (`ST:172-193`, `SD:4`)
13. 시안 설정의 **`계정 설정`(프로필 편집·비밀번호 변경)·`알림 설정`** 은 기존 기획 문서에 대응 절이 없다 — 이번 조사에서 찾은 범위(S001·S007·work-003/008/009)에서 확인 못 함
14. 업무 생성 쪽 「출처」 표기는 기획상 **AX 제안·요청·직접 배정** 세 종류뿐이다 ↔ 외부 메시지에서 온 업무의 출처 자리는 기획에 없다 (`S007:876-882`)
15. 시안 수신함엔 **AX 자리가 없다** ↔ 기획의 「AX 제안 N」 칩은 업무 목록 쪽에 있고 「받은 요청 수신함에는 섞이지 않는다」 (`S001:245-252`)
16. 시안 수신함엔 로딩·오류 상태가 없다 ↔ 시안 README 규약 「화면은 네 상태를 같이 그린다」 (`README.md`(원격) 「화면은 네 상태를 같이 그린다」, `IB` 전체)
17. 시안 업무 탭 레일 카드도 출처 「메일」「메신저」·`답장` 을 이미 그리고 있었다 ↔ 코드는 그 자리를 버렸다(K-1 발명 금지) (`MWD` `INBOX_ITEMS`, `InboxRail.tsx:18-21`)
