## 2. 바꾼 것

### 2.1 이름과 범위
- 화면 이름 **메시지함** — 내비 라벨 · `<title>` · 화면 머리 · 레일 제목 전부
- 출처 전환 = `전체 · 메일 · 슬랙` — **카톡 탭·카드 삭제**(목데이터에도 없음)

### 2.2 레일 카드 — 모양은 그대로, 행동만 걷었다
- 삭제: `+`(업무로 추가) · `내 업무로` · `답장` · `확인완료` · `원문 확인하기` · `대화 보기` · `대화방 열기` · 메일 카드의 `업무`/`참고` 배지 · 카드 아래 단추 줄(`.scax-inbox-card__actions` CSS 포함)
- 남김: 카드를 누르면 원문 + 읽음 · 머리 `모두 읽음으로`
- 메일 카드: 출처 배지 `메일` + 안 읽음 빨간 점 · 제목 · 본문 두 줄 · 보낸 사람 · 시각 · 첨부 수(클립)
- 슬랙 카드: `슬랙` 배지 + 미읽음 수 · 방 이름(`#채널` / DM 상대 이름 / 그룹 DM 참여자 이름) · 마지막 3줄 미리보기 · 「참여 N명 · 마지막 …」 — 시안 모양 그대로

### 2.3 메일 본문 (읽기 폭 720px)
- 머리: 제목 → 표처럼 `보낸 사람`(이름 굵게 + 주소) · `받는 사람` · `참조`(있을 때만) · `날짜` · `받은 계정`
- 본문: **HTML 메일 틀**(`.scax-mail-html`) — 문단 · 표 · 목록 · 서명(`.sig`) · 인용(`blockquote`)의 모양을 그대로 담는다. 목업은 data 의 HTML 조각을 그대로 넣는다
- 인용 접기: 「··· 이전 내용 보기」 / 「이전 내용 접기」
- 첨부: **슬랙과 같은 파일 카드**(유형 색 아이콘 · 굵은 이름 · 유형명·크기 · 받기 아이콘). 이미지 첨부는 썸네일 + 그 아래 파일 카드

### 2.4 슬랙 본문 — 대화방처럼
- 머리: 방 이름 · 「슬랙 · 채널/DM/그룹 DM」 · 「참여 N명」 · 오른쪽 「슬랙에서 열기」 외부 링크
- 날짜 구분선: 가운데 알약(「10월 2일 금요일」·「어제」·「오늘」)
- 메시지: 아바타(이니셜 · 사람마다 색) · **이름** · 시각 → 본문. **같은 날 · 같은 사람 · 5분 안**이면 묶어 아바타·이름 없이 왼쪽에 시각만
- 서식: 굵게 · 번호 목록 · 글머리 목록 · 들여쓴 하위 목록 · `@멘션` 칩 · 링크 · 인라인 코드 · 이모지
- **URL 미리보기(언퍼일)**: 둥근 상자 · 굵은 사이트 이름 · 굵은 제목 · 설명 2줄 · 회색 도메인 · 오른쪽 썸네일 / 썸네일 없는 링크는 텍스트만 (추가 지시 1)
- **첨부 여러 개**: 「N개의 첨부 파일 ▾ | ⤓ 모두 다운로드」 머리 + 파일 카드 가로 배치(줄바꿈) (추가 지시 2)
- **PDF 하나**: 「PDF ▾」 머리 + 큰 카드 — 위 아이콘·이름·「PDF · N쪽 · 크기」·받기, 아래 **첫 페이지 미리보기**(잘린 채, 아래로 흐려짐) (추가 지시 3)
- 이미지: 「파일명 ▾」 + 큰 썸네일 (추가 지시 4)
- 리액션: 이모지 + 수 칩 — **읽기 전용**(누를 수 없음 · 더하기 없음)
- 스레드: 부모 아래 「(답글 단 사람 얼굴) 답글 N개 · 마지막 답글 …」 줄, 누르면 답글이 들여쓴 채 펼쳐진다
- 봇 메시지: 같은 모양 + 이름 옆 `앱` 표시
- 맨 아래 「↓ 새 메시지 N개」 알약 (실시간 도착 표시 — 목업은 고정 값)
- 대화 폭 최대 880px

### 2.5 네 상태
- 화면 아래 `StateSwitch`(dev 전용, 기존 업무 화면과 같은 부품)로 `기본 · 비어 있음 · 로딩 · 오류` 를 바꿔 본다
- 레일: 로딩 = 카드 Skeleton 5개 · 빈 = 「쌓인 메시지가 없습니다 / 설정에서 메일·슬랙을 연결하면 받은 메시지가 여기에 쌓입니다.」 · 오류 = StatusNote 「메시지함을 불러오지 못했습니다」 + `다시 시도` · 출처 필터로 빈 경우 = 「이 출처에는 메시지가 없습니다」
- 본문: 로딩 = 제목·문단 Skeleton · 빈(고른 것 없음) = 「고른 메시지가 없습니다」 · 오류 = 「원문을 불러오지 못했습니다」 + `다시 시도`
- 처음 열면 `#pilot-launch` 가 골라져 있다(서식·첨부가 가장 많은 방을 바로 보이게)

### 2.6 목데이터 (전부 가상 — 사람 · 회사 「노을랩」 · 사이트 `*.example` · 파일)
- 메일 3: ① HTML 표 · 서명 · 참조 2명 · 인용 · 첨부 xlsx+pdf ② 목록 · 이미지 첨부 2 ③ 짧은 평문 · 읽음
- 슬랙 채널 `#pilot-launch`: 날짜 3일 · 굵게+번호 목록+하위 목록+멘션+이모지 · 연속 메시지 묶음 2곳 · PDF 1 · 링크+언퍼일(썸네일 없음)+스레드 3 · 링크+언퍼일(썸네일 있음) · 봇 메시지+인라인 코드 · 첨부 3개(md 2 + pdf) · 이미지 · 리액션
- DM `오지훈`: 2일 · 묶음 · 링크 / 그룹 DM `문다은, 배성민`: 이미지 · 리액션

## 3. 확인한 것
- node 에서 JSX 를 변환해 렌더(react-dom/server): 화면 전체 · 레일/본문 × 로딩·빈·오류 · 메일 3 · 방 3 · 스레드 답글 — 예외 없음. 채널에서 묶음 2 · 날짜 구분 3 · PDF · 파일 카드 3 · 리액션 5 · 「답글 3개」 · 「새 메시지」가 나온다
- 로컬 사본 + 새 파일로 헤드리스 Edge 화면 캡처(1600 폭): 채널 위·아래, 메일 m1, 그룹 DM — 읽기 폭·머리 표·HTML 표·파일 카드·PDF 미리보기·언퍼일·리액션·날짜 알약이 의도대로 선다. 번호 목록 숫자가 DS 리셋으로 사라져 `list-style` 을 명시해 고쳤다
- 화면에 남은 금지 문구: 없음(「답장」·「확인완료」는 JSX 머리 주석에 「일부러 그리지 않는다」로만 나온다)

## 4. 일부러 안 그린 것
- 모든 행동: 업무로 옮기기 · 답장 · 확인완료 · 원문/대화방 열기 단추 · 업무/참고 가르기 (결정 2026-10-05 — 메시지함은 조회·읽음만)
- 슬랙: 메시지 입력창 · hover 행동 막대 · 리액션 추가 · 스레드에 답글 달기 · 메시지 수정/삭제 표시 (조회 전용)
- 카카오톡 탭·카드 (2026-10-06 뒤로 미룸)
- 메일 받는 사람·참조 「더 보기」 접기 — 짧은 목록만 목데이터에 넣어 필요가 드러나지 않았다
- 실제 이미지·파일 미리보기: 썸네일과 PDF 첫 페이지는 **흉내낸 자리**다(그라데이션 상자 · 글자 줄). 실물은 받은 파일이 선다
- 「새 메시지 N개」 를 눌러 아래로 내려가는 동작 · 실시간 갱신 애니메이션
- 「모두 다운로드」·받기 아이콘의 동작 — 보이게만 둔다(추가 지시)
- 설정 화면(`Settings.html`) — 이번 범위 밖, 건드리지 않음

## 5. 미결·주의
- 그룹 DM 이름: 시안은 참여자 이름을 「, 」로 잇는다(`문다은, 배성민`). 실측상 슬랙은 `mpdm-…` 이름이라 서버가 참여자 실명으로 풀어 줘야 한다(_RESUME 2026-10-06)
- 카드 표기: _RESUME 의 「슬랙 - #채널명」 표기는 카드에선 `슬랙` 배지 + 방 이름 두 줄로, 본문 머리에선 「슬랙 · 채널」로 나눠 그렸다 — 한 줄 표기가 필요하면 말해 달라
- 메일 카드 본문 미리보기 글자색은 업무 탭 카드 규칙(`components.css`) 그대로라 옅다 — 이번에 손대지 않았다
- 아바타 이미지(`assets/avatar-person.png`)는 로컬 사본에 여전히 없다(앞 판 §0)
