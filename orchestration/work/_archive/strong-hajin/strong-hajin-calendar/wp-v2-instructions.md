## 무엇을 더하나

K19~K24 를 **새 Phase 넷**으로 내린다. 1루프 Phase(BE-1·BE-2·FE-1·FE-2)는 **전부 done** 이다 —
Status 를 `DONE` 으로 바꾸고 커밋 sha 를 적어라 (`1c15d02` · `2a85176` · `c5b109d` · `aa8576b`).

**Phase 이름은 2루프임이 드러나게** — 예: `BE-3` · `BE-4` · `FE-3` · `FE-4`.

## Phase 나누기 — 이 경계를 지켜라

**직렬이다. BE 가 닫히기 전에 FE 를 태우지 않는다.**

| Phase | 무엇 |
|---|---|
| **BE-3** | **K22 겹침 검증** — `overlapping_blocks(member_ids, 구간)` 한 함수 + 배정 생성·시각 변경에 걸기 + 에러 `TASK_SCHEDULE_OVERLAP` |
| **BE-4** | **회의 쪽 검증**(생성·시각 변경, `quick-start` 제외) + `MEETING_TIME_OVERLAP` + **K19 `approval` 필드** + 운영 대장 |
| **FE-3** | **K20** 월 뷰 종일 띠만·시간순 · **K21** 겹치면 나란히 · **K19** 카드 배지 둘 |
| **FE-4** | **K22 거절 문구**(이름은 말하고 내용은 안 말한다) · **K23·K24** 업무 탭 레일에 회의 |

**왜 BE 를 둘로 가르나** — 회의 도메인을 건드리는 것(BE-4)이 **Scope Out 을 뒤집는 자리**다.
배정 쪽(BE-3)만 먼저 서면 그것만으로도 쓸 수 있고, 회의 쪽에서 막히면 배정 쪽이 인질이 안 된다.

## 반드시 담을 것

1. **`Domain / Schema`** — 새 표는 **없다.** `task_schedules` 에 `approval` 을 넣는 게 아니다
   (그건 합본 조회 **응답 필드**다). 스키마 변경이 없다는 것을 **명시**하라.
2. **겹침의 한계를 WP 도 적는다** — 「하루 한 칸」은 DB 가 막고 겹침은 application 이 막는다.
   **DB 제약으로 올리려는 시도를 하지 마라** — 두 표 사이엔 못 건다(SPEC §2.9).
3. **`Code Surface`** — 회의 도메인에서 닿는 자리를 **세어라**. `meetings` 생성·시각 변경 경로,
   `quick-start` 가 그 검증을 **안 타는** 것까지. 1루프에서 「`my_meetings`·`readable_rows` 를
   건드리지 않는다」가 걸렸던 것처럼, **공유 함수의 다른 소비처**를 확인하라.
4. **운영 대장** — 새 라우트가 **없다**(기존 회의 라우트에 검증만 붙는다). `http_count` 가
   **안 는다**. 응답 필드가 느는 것(`approval`)이 `http_signature` 에 드는지는 확인해서 적어라.
5. **인수조건 추적** — SPEC v0.3.1 §6 에 새로 생긴 줄을 **전수 매핑**하라. 1루프 때처럼
   묶음·줄 수·닫는 Phase 로. **닫는 Phase 가 없는 줄이 있으면 그것이 이 WP 의 구멍이다.**
6. **검수 이월 하나** — 「K12 를 가리키는 지도 셋이 `409` 가 둘이던 때의 말이다」
   (추적표·1차 이력표의 「Case Matrix 두 409 행」 → 이제 셋, §4 의 「그 409」).
   계약은 안 갈리지만 **그 표를 손댈 때 숫자를 맞춘다** — Open Issues 에 한 줄.
