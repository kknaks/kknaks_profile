## 2. 보정 1 — 이미지 push 는 **외부 쓰기**다

### 2-1. 무엇이 문제였나

`2) I-4 arm64 이미지 빌드·푸시` 가 **한 단계로 묶여 게이트 위**에 있었다. 그런데 이 한 단계 안에
성격이 다른 두 일이 들어 있다:

| | 무엇 | 되돌릴 수 있나 |
|---|---|---|
| **빌드** | 이 기기에서 이미지를 만든다 | 그렇다 — 지우면 끝이다 |
| **push** | **외부 레지스트리에 발행한다** | **어렵다** — 태그를 지워도 **이미 당긴 사람에게는 남는다** |

게이트가 「클러스터냐」로만 그어져 있으니 push 가 그 위에 남았다. **클러스터 밖이라고 해서
이 기기 밖이 아닌 것은 아니다.**

### 2-2. 고친 것 — 2a / 2b 로 갈랐다

```
2) I-4 arm64 이미지 — **빌드와 push 는 다른 일이다. 갈라서 읽는다.**
   2a) 로컬 빌드·검증 (승인 없이 가능)
       docker build --platform linux/arm64 … → 로컬에서 실행·헬스체크까지.
       이 기기 밖으로 아무것도 나가지 않는다.
   2b) 레지스트리 push (**승인 필요 · 외부 쓰기**)
       ⚠ push 는 클러스터가 아니라 외부 레지스트리에 쓰는 일이고, 되돌리기 어렵다
         (태그를 지워도 당긴 사람에게는 남는다).
       ⚠ **D-2 가 먼저다** — 어느 레지스트리 namespace 인지 미정. 제품 레포가
         kknaks/Strong_hajin 이라 ghcr.io/medisolveaidev 와 **org 소유가 다르다.**
       ⚠ **D-3 가 먼저다** — 회사 org 이름으로 이미지를 «발행»해도 되는지가 미결.
         기술 문제가 아니라 **소유·권한 문제**다.
       → **둘 다 풀리기 전에는 2a) 까지만 한다.** image.tag 주입은 push 뒤의 일이다.
```

**머리말도 고쳤다** — 「구분선 위의 1)·2) 만 승인 없이 진행할 수 있다 — 다만 **2) 안에도 승인이
필요한 절반이 있다(레지스트리 push)**」.

**본문에 경계의 «이유»를 적었다**:

> 2b) 는 구분선 위에 있지만 승인 대상이다 — 구분선이 가르는 것은 「클러스터냐 아니냐」이고,
> 2b) 는 **클러스터 밖이지만 이 기기 밖**이다. 승인이 필요한 이유가 구분선과 다르므로 단계 안에 적었다.

**2b) 를 구분선 «아래»로 내리지 않은 이유**: 아래는 「클러스터 쓰기」 구역이고, push 는 클러스터
쓰기가 아니다. **거짓 분류로 줄을 맞추기보다, 단계 안에 승인 조건을 박는 쪽**을 골랐다.

### 2-3. §9-1 승인 경계 표에 **레지스트리 행**을 더했다

| | 한 것 | 하지 않은 것 |
|---|---|---|
| 레포 | 신규 파일 14개 작성 | 커밋 · push · PR |
| helm | `lint` · `template`(로컬 렌더) | `install` · `upgrade` |
| **레지스트리** | **아무것도** | **이미지 빌드 · `docker push`**(§9 2b — D-2·D-3 선행) |
| 클러스터 | **아무것도** | `kubectl apply` · AppProject 적용 · Argo sync |

표에 행이 없으면 **「안 한 일」이 아니라 「생각해 보지 않은 일」로 읽힌다.**
