## 4. 항목별 확인

### 4-1. 디렉터리가 더 이상 침묵하지 않는다 (PASS)

```js
const present = readdirSync(candidateDir).map((name) => ({
  name,
  isDirectory: statSync(join(candidateDir, name)).isDirectory(),   // ← 거르지 않고 «표시»한다
}));
const extra = present.filter((entry) => !recordedNames.has(entry.name));
```

- **필터가 사라지고 «종류»가 속성이 됐다** — 디렉터리도 집합에 들어온다.
- `extra` 의 기준이 `wanted`(해시 있는 것)가 아니라 **`recordedNames`(기록된 이름 전부)** 다.
  덕분에 **기록된 `.app` 이 «섞였다»(5)로 오인되지 않고** 코드 8 로 간다 — 경계가 정확하다.
- 출력이 디렉터리임을 **명시**한다: `… : X.app/ (디렉터리)`.
- **보고서가 자기 잘못을 정확히 진단했다** — 「Phase 9 본편 §5-2 에 「기록에 없는 파일이 섞인
  것도 실패다」라고 써 놓고 **그 규칙을 파일에만 적용했다. 규칙이 틀린 게 아니라 적용 범위가
  새었다**」. 검수 판단도 같다.

### 4-2. 해시 없는 자산 = 검증 불가 (PASS)

- **코드 8 신설**(`EXIT_UNVERIFIABLE_ASSET = 8`). 메시지가 **무엇을 해야 하는지**까지 적는다:

  `.zip` 등으로 싸야 한다 — F-5/F-6 이 그 두 갈래를 정확히 나눈다.
