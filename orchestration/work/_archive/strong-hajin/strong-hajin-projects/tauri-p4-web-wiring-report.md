## 3. 셸 감지와 호출 경계 (계약 1)

`shell.ts` **밖에서 `invoke` 를 부르지 않는다** — `api.ts` 밖 `fetch` 금지와 같은 결이다.

- **셸 존재 판정은 커맨드가 아니다**: 셸 전용 전역(`__TAURI_INTERNALS__`) 유무로만 본다
- **없으면 한 번도 부르지 않는다**(`E-01`). `@tauri-apps/api` 는 **동적 import** 라
  브라우저에서는 **모듈을 불러오지도 않는다**
- 범용 invoke·파일 권한·운영 origin 을 **더하지 않았다.** 내보내는 것은 넷뿐이다:
  `shellInfo` · `acquireWakeGuard` · `releaseWakeGuard` · `openExternal`
- **타이머가 없다**(WORK I-3). TTL·주기 갱신·참조계수 없음

> `shellInfo` 는 배선에 쓰이지 않는다 — 실패를 기능 부재로 단정하지 않기 위해
> **획득을 그냥 시도**하는 것이 SPEC §4 의 계약이라, 녹음 시작 경로는 `shell_info` 를 기다리지 않는다.

## 4. 회의 녹음 경로 (계약 2)

### 획득 — 마이크가 «실제로» 열린 뒤

`stream.ts` 의 `startMicrophone(...).then(handle => …)` 안, **핸들을 받은 바로 그 시점**이다.
연결 시도도 준비 신호(`onReady`)도 아니다.

- **세션 키는 회차마다 새로 만든다**(`newWakeSession()` = `crypto.randomUUID()`).
  **회의 id 를 쓰지 않는다** — 회차를 넘어 같은 값을 쓰면 `E-08`·`E-09` 의 보호가 사라진다
- **중복 획득을 만들지 않는다**: 키는 마이크가 열린 회차마다 **한 번** 생성되고,
  같은 키의 재요청은 «거는» 방향(재무장)이라 점유가 늘지 않는다
- `stopped` 인 회차에서 핸들이 늦게 도착하면 **핸들만 닫고 획득하지 않는다**

### 해제 — 녹음이 «실제로» 끝난 뒤

| 자리 | 사건 | 규칙 |
|---|---|---|
| `onClosed` | 스트림이 닫혔다(정상 종료·미인증·끊김 — 사유 무관) | **L-02** |
| `onClosed`(`kind==="taken"`) | 업스트림 자리를 뺏겨 구독으로 바뀐다 | **L-05** — 마이크가 닫히는 **같은 시점**이라 같은 자리에서 풀린다 |
| effect cleanup | 마이크를 멈추는 정리 코드 | **L-10** |

`releaseWake()` 는 **키가 서 있을 때만** 동작한다(멱등). 마이크가 열린 적이 없으면 아무 일도 없다.

### 획득하지 않는 자리

- **구독 역할**(`effectiveRole !== "upstream"`) → 마이크를 열지 않으므로 애초에 경로에 닿지 않는다 (**L-04**)
- **마이크 열기 실패**(`.catch`) → `micDenied` 만 세우고 **걸지 않는다** (**L-03** · `E-13`)

### L-14 재확인 — 사건이 있을 때만

`visibilitychange` 에서 문서가 다시 보이게 되면 **같은 키로 한 번** 다시 요청한다(`E-09` 재무장).
**주기적으로 도는 것이 아니다**(I-3). 응답이 `on` 이면 U-3 이 사라지고, `degraded` 면 남는다.
정리 때 리스너를 떼어 회차가 끝난 뒤에는 돌지 않는다.

## 5. 브라우저 녹음 경로 (계약 3)

세션 키는 **이미 있는 `captureId`**(`crypto.randomUUID()`, 창이 뜰 때마다 새 값)를 그대로 쓴다.

| 자리 | 사건 | 규칙 |
|---|---|---|
| `start()` — `startBufferedAudioCapture()` **성공 직후** | 마이크가 실제로 열렸다 | **L-07 획득** |
| `stop()` 성공 | 업로드가 끝났다 | **L-08 해제** |
| `stop()` 실패 | 오디오가 남아 **재시도할 수 있다** | **유지**. 단 서버가 이미 `completed` 면 해제 |
| `interrupt()` | 취소·실패로 끝났다 | **L-08 해제** |
| 폴링이 종료 상태 관측 | 마이크를 닫았다 | **L-08 해제** |
| 언마운트 정리 | 마이크를 닫는다 | **L-08 해제** |
| `start()` 의 `catch` | 마이크는 열렸는데 **녹음 시작이 실패**했다 → 그 마이크를 닫는다 | **해제** (아래 참고) |

### 획득하지 않는 자리

- `item.status !== 'waiting'` early return
- **마이크 권한 거부·미지원** → `startBufferedAudioCapture()` 가 던지므로 획득 줄에 닿지 않는다
- **마이크가 열리기 전 실패** → 같은 이유로 닿지 않는다

### 늦은 획득/해제의 최종 잔존 0

`start()` 에서 획득은 `void holdWake()` 로 나가고, 곧이어 `startBrowserRecording` 이 실패하면
해제가 뒤따른다. **`shell.ts` 가 같은 세션 키의 호출을 한 줄로 세우므로** 해제가 언제나 획득
뒤에 가고 **최종 잔존이 0** 이다(SPEC §4 「늦게 도착한 획득은 걸지 않는다」 — 수단은 구현이 고른다).
**영구 기록도 타이머도 두지 않았다.**

## 6. 실패를 다루는 법 (계약 4)

| 상황 | 녹음 | 화면 |
|---|---|---|
| 셸 없음 (`E-01`) | 그대로 | **아무것도 보이지 않는다** |
| 획득 결과 `on` | 그대로 | 아무것도 |
| 획득 결과 `degraded` (`E-02`·`E-03`) | **계속된다** | **U-3 한 줄** |
| 획득 **호출 실패** (`E-14a`) | **계속된다** | **U-3 한 줄** (degraded 와 같게 본다) |
| 해제 **호출 실패** (`E-14b`) | **다시 켜지 않는다** | **다른 문구** — 정리 실패 사실 |

- `acquireWakeGuard` 는 **던지지 않는다.** 실패를 `{kind:"degraded"}` 로 바꿔 돌려주므로
  **녹음 경로가 예외로 깨질 수 없다**
- U-3 은 **마지막으로 확인된 상태**를 보인다. 한 번 뜨고 마는 알림이 아니다
- CTA 를 두지 않았다 — 녹음을 막지 않는 안내일 뿐이다

### ⚠ 「labels.ts 에 U-3 한 줄만」과 문구가 둘인 이유

발주는 「U-3 한 줄만 추가」라고 했고, 동시에 「release 실패는 `E-14b` 사실을 드러내라」고 했다.
SPEC-006 U-3 은 **정리 실패에 «다른 문구»를 쓰라고 명시**한다 — 녹음이 이미 끝났으므로
「녹음 중에는…」이 **거짓이 되기 때문**이다. 그래서 **문자열은 둘**을 넣었다:

- `wakeGuardDegraded` — U-3 본문 (녹음 중)
- `wakeGuardCleanupFailed` — `E-14b` 본문 (녹음이 끝난 뒤)

**화면에 동시에 뜨지 않는다** — 한 번에 한 줄이다. 「한 줄만」을 «화면의 줄 수»로 읽었고,
문자열 개수를 하나로 줄이면 SPEC 을 어기게 되어 이 해석을 택했다. **다르게 읽어야 하면 알려 달라.**
