### 2-2. 재측정의 «핵심 주장» 을 내가 직접 다시 쟀다

재측정 보고서는 **「사용자 보고와 기기 상태가 어긋난다」**(설치했다고 했으나 CA 가 없다)는
민감한 주장을 한다. 이것은 확인이 필요한 자리라 읽기 전용으로 재실행했다:

```text
$ security find-certificate -a -c "SCAX WORK-006 probe local CA"        → (출력 0건)
$ security verify-cert -c frontend/.dev-certs/localhost.pem
  Cert Verify Result: CSSMERR_TP_NOT_TRUSTED
$ openssl x509 -in frontend/.dev-certs/localhost.pem -noout -fingerprint -sha1
  sha1 Fingerprint=BD:7B:86:6C:75:EF:C0:64:39:CA:62:7A:60:20:C5:50:54:48:4C:3E
```

**셋 다 재측정 보고서 §2 의 기록과 정확히 일치한다 — leaf 지문의 20바이트까지 같다.**
→ 재측정 보고서의 주장은 **관측에 근거한 것이 맞다.** 사용자 보고와 어긋나는데도 **보고를 근거로
실측은 그대로 진행한** 처리도 옳다(기기 상태 판정이 아니라 셸 동작으로 답을 낸다).

### 2-3. 재측정이 «덜» 주장한 것도 정확하다

1차는 `screencapture` 로 「빈 흰 화면」을 화면 관측으로 남겼고, **재측정은 스크린샷을 찍지 않았으므로
화면 상태를 주장하지 않는다** — 로그 침묵만 적는다. **찍지 않은 것을 본 것처럼 쓰지 않았다.**

**P-4 (WARN) — 브라우저 경로에 대한 한 줄이 근거보다 세다.**

측정 문서 §판정 말미:

> 브라우저 인터랙션 경로는 「보완 ②③」에 **해당하지 않는다** — 후보가 내려앉지 않았고 1순위 그대로 낙착됐다

표의 **보완 ③은 두 갈래**다 — 「**후보 셋 전부 실패** 또는 **서버가 그 업로드를 거부**」.
제시된 근거(후보가 내려앉지 않았다)는 **앞 갈래만** 배제한다. **뒷 갈래(서버 수용)는 미측정**이고,
같은 문서가 §M-2 에서 「③ 서버 수용 = 미측정」이라고 적는다.

→ 「해당하지 않는다」가 아니라 **「②는 배제됐고, ③의 서버 수용 갈래는 미측정이라 아직 배제할 수 없다」**
로 고칠 것. **한 문장 교정이다.**

**P-1 (WARN) — 완료 보고서가 재측정 이전 판이다.**

```text
$ stat -f '%Sm %N' …
  Sep 22 19:52  tauri-p2-measurement-report.md     ← 완료 보고서
  Sep 22 19:54  (M-1 재측정 실행 시각 · 로그 epoch)
  Sep 22 19:56  tauri-measurement-r1.md            ← 재측정 반영됨
  Sep 22 19:56  tauri-p2-m1-rerun-report.md
```

완료 보고서는 **재측정을 모른다.** §8 이 「CA 신뢰 설치 후 **M-1 재측정**」을 *앞으로 할 일*로 적는데,
그 일은 **이미 시도됐고 실패했다.** **판정(보완·조건부)은 재측정 뒤에도 그대로라 결론은 틀리지 않았다.**
다만 **완료 보고서만 읽는 사람은 재측정 회차가 있었다는 사실 자체를 모른다.**

→ 완료 보고서에 **「§8-1 은 19:54 에 1회 시도됐고 결과는 `tauri-p2-m1-rerun-report.md`, 판정 변화 없음」**
한 줄을 추가할 것. (측정 문서 `r1` 쪽은 이미 갱신돼 있다 — 머리말·요약표·전용 절 셋 다.)

## 6. 그 밖의 관측 (INFO — 막지 않는다)

**P-5 — 평문 fixture 를 쓴 근거가 실제 사용 범위보다 좁게 인용됐다.**

측정 문서 §0-3 은 평문 사용의 근거로 WORK §Phase 1 작업 7 을 든다. 그 조항의 원문은
「평문 `localhost` 스택 — **M-2·M-4 의 마이크·녹음 전용**」이다. 그런데 실제로 평문에서 잰 것은
**M-2 ① · M-3 ①② · `E-06`(ACL origin 거절)** 이다.

- **규칙 위반은 아니다** — 금지 규칙은 「**M-1** 을 평문으로 대체하지 않는다」 하나이고, 그것은 지켜졌다.
  M-3 에는 프로토콜 지정이 없다
- 다만 **인용한 근거가 실제 사용을 덮지 못한다.** 「M-3·`E-06` 은 프로토콜 지정이 없어 평문에서 쟀다」를
  따로 적으면 된다
- 덧붙여: `E-06` 의 거절은 **평문 origin 이 허용 목록 밖이기 때문**이다. 즉 **허용 origin(https)에서
  ACL 이 «통과» 시키는지는 아직 관측되지 않았다.** 문서가 이것을 M-1 의 통과로 쓰지 않은 것은 옳으나,
  **AC-T24 의 절반만 관측됐다**는 점은 Phase 3 이 알고 있어야 한다

**P-6 — M-9 의 「막는 인수조건」이 SPEC §6 과 다르다.**

| | 인수조건 |
|---|---|
| SPEC §6 표 | M-9 → **AC-T01 ~ AC-T03** (AC-T04 는 M-2, AC-T05~T07 은 **M-11**) |
| 측정 문서 §M-9 | AC-T01 ~ **AC-T04** (그리고 **AC-T05~T07**) |

내용상 넓힌 것이 부당하진 않다(AC-T04 「회의 뒤 평소 절전으로 돌아간다」는 절전 경계다). 다만
**SPEC 과 다르게 적었으면 다르다고 적어야** 인벤토리가 흔들리지 않는다. 한 줄 각주면 충분하다.

**P-7 — Windows 축의 기술 위치가 균일하지 않다.**

요약표(§1)는 10행 모두 Windows 칸을 채우지만, 본문에서 `### Windows` 소절을 가진 것은 **M-2 하나**다.
나머지 아홉은 §1 표와 전역 주석이 대신한다. **WORK 의 검증 항목(「열 항목 각각에 OS 축별 관측값」)은
표로 충족되므로 미통과는 아니다.** 다음 회차에서 Windows 실기가 붙으면 **절마다 축이 필요해진다** —
그때 구조를 맞추면 된다.

**P-8 — 1차 회차의 부작용(광범위 `pkill`)은 공개됐고, 재측정 회차에서 교정됐다.**

완료 보고서 §7-1 이 **사용자의 기존 vite 프로세스(pid 59876)를 죽였다**고 스스로 적었다.
**숨기지 않은 것은 옳고, 복구 불가를 인정한 것도 옳다.** 재측정 회차는 같은 실수를 반복하지 않았다 —
**자기가 띄운 PID 둘(31759 · 31890)을 파일에 기록하고 그 PID 만 종료**했고, 종료 뒤 5180 listener 0 ·
다른 vite 0 을 확인했다. **교정이 실제로 일어났다.**

→ 다음 발주 브리프에 **「프로세스 정리는 자기 PID 만. 패턴 `pkill` 금지」**를 상시 문구로 넣기를 권한다
(재측정 브리프에는 이미 들어갔던 것으로 보인다 — 그 효과가 §7 표에 나타난다).

**P-9 — 기기 구성 정보가 문서에 남아 있다.** (§4 참조)
`dump-trust-settings -d` 의 제3자 CA 6종과 `pmset` 의 앱 이름·PID. **증거로서 실릴 자리는 맞다.**

## 7. 잘한 것 — 다음 회차가 지켜야 할 것

1. **상태어를 네 개로 갈랐다** — 미측정 / 부분 측정 / **측정 불가(환경 무효)** / 검증 불가(장비 없음).
   특히 M-9 의 「환경 무효」는 **재려 했으나 재는 것 자체가 성립하지 않았다**를 정확히 표현한다
2. **「호출이 실패했다」와 「호출이 발생하지 않았다」를 구분했다**(재측정 §4). 커맨드 넷에 대해
   **「에러 원문을 요구받았으나 지어낼 수 없는 자리라 빈칸으로 둔다」**고 적은 것은 모범이다
3. **곁가지 관측을 통과로 쓰지 않았다** — IPC 전역 주입과 ACL 거절을 관측하고도
   **「이 둘은 M-1 의 «통과» 가 아니다」**를 두 문서에 반복해 적었다
4. **웹뷰의 TLS 에러 원문을 갖지 못했다고 명시**하고, 다른 클라이언트(openssl·curl)의 원문을
   **웹뷰의 것이라고 쓰지 않았다.** 그 «갖지 못함» 자체가 M-7 의 결과라는 연결까지 적었다
5. **자기 부작용 둘을 스스로 열었다**(§7). 검수가 찾아내야 했을 것을 보고자가 먼저 적었다

## 9. Phase 3 진행 가능 여부에 대한 검수 의견

**완료 보고서의 「조건부 가능」에 동의한다.** 다만 조건을 하나 더 세게 적기를 권한다.

- ✅ **중단 사유가 하나도 관측되지 않았다** — 회의 라이브 단일 MIME 이 **지원으로 관측**됐고,
  「원격 문서에 IPC 가 닿지 않는다」는 구조적 실패도 관측되지 않았다
- ✅ **Phase 3 의 작업 대부분(커맨드 계약 · 점유 수명 · 허용 목록 · 창 훅)은 M-1 의 «최종» 확인과 독립**이다
- ⚠ **조건 1 — M-1 을 닫기 전에 Phase 3 완료기준을 닫지 않는다.** SPEC §6 이 M-1 에 매어 둔 인수조건이
  AC-T01~T19 · T21 · T22 · T36~T41 · T43 으로 광범위하다. **CA 신뢰 설치가 실제로 반영되는 것이 선행**이며,
  **19:54 재측정이 실패한 이상 이것은 「곧 될 것」이 아니라 «아직 열려 있는 블로커»다**
- ⚠ **조건 2 — M-7 을 Phase 3 의 «설계 입력» 으로 올린다.** SPEC U-2 가 「감지 수단이 없으면 구현 차단 사유」라고
  써 둔 자리다. **Phase 3 이 수단을 정하지 못하면 그때 다시 게이트를 열어야 한다** — 조용히 U-2 를 빼면 안 된다
- ⚠ **조건 3 — Windows 축은 실행도 컴파일도 미검증인 채 열려 있다**(OQ-W01)
- ⚠ **조건 4(검수가 더한다) — AC-T24 는 절반만 관측됐다.** 허용 목록 «밖» origin 의 거절은 봤으나
  **허용 origin 에서의 «통과» 는 못 봤다**(P-5). M-1 과 함께 닫힌다
