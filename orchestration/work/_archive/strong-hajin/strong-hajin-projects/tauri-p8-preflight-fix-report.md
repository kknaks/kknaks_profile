## 2. W-1 — 연습이 0 으로 끝나던 문제

### 2-1. 무엇이 문제였나

`--shell-root` / `SHELL_ROOT` 로 사본 트리를 가리키고 증거 파일로 G5 를 채우면, 관문 여섯을
모두 지나 **`exit 0`** 이 나왔다. 출력에는 「연습 통과(관문 통과가 아니다)」라고 적혀 있었지만
**그 문장은 종료 코드에 실리지 않는다.** 스크립트를 파이프라인에 넣는 순간 그 구분이 사라진다.

**내가 Phase 8 에서 이 경로를 만든 이유는 정당했다**(통과 분기가 한 번도 실행되지 않은 관문은
관문이 아니다). **틀린 것은 그 연습의 «결과를 무엇으로 표현했는가»였다** — 경고 문구로 표현했고,
경고 문구는 기계가 읽지 않는다.

### 2-2. 고친 것 — 종료 코드를 넷으로 갈랐다

```js
const EXIT_PASS      = 0;   // **진짜 관문 통과 — 오직 기본 src-tauri 에서만**
const EXIT_BLOCKED   = 1;   // 관문이 막았다
const EXIT_USAGE     = 2;   // 돌릴 수 없다(입력·경로 문제)
const EXIT_REHEARSAL = 3;   // 연습 — 모든 관문을 지나도 이 코드다
```

통과 분기 맨 끝에서 한 번 더 가른다:

```js
if (rehearsal) {
  console.log(`⚠⚠ **exit ${EXIT_REHEARSAL} (연습)** — 모든 관문을 지났지만 **기본 src-tauri 가 아닌 트리**를 읽었다. ` +
    "**exit 0 은 진짜 설정에서만 나온다** — 이 실행을 관문 통과로 집계하지 말 것.");
  process.exit(EXIT_REHEARSAL);
}
process.exit(EXIT_PASS);
```

**막은 것은 「연습을 못 하게」가 아니라 「연습이 통과로 집계되지 못하게」다.** 연습은 그대로 쓸 수 있고,
사람이 읽는 배너·`"rehearsal": true` manifest 도 그대로다 — **종료 코드가 하나 더해졌을 뿐이다.**

곁들여, 연습일 때 「다음 단계 1)」이 `(이미 일치함을 확인했다)` 라고 말하던 줄도 고쳤다 —
사본만 본 실행이 **진짜 설정을 확인했다고 말하면 안 된다**:

> `1) **진짜** shell.config.json · capability 를 <origin> 로 확정 — 이번 실행은 사본만 보았다`

### 2-3. 없는 경로를 주면 — **스택 대신 판정**

`SHELL_ROOT=/nonexistent` 는 `readFileSync` 의 **ENOENT 스택**으로 끝났다. 그것은 **관문의 판정이
아니라 도구의 사고**로 읽히고, 무엇을 고쳐야 하는지도 말하지 않는다. 읽기 **전에** 막는다:

- 경로가 없거나 디렉터리가 아니면 → 한 줄 진단 + **exit 2**
- 디렉터리는 있으나 `shell.config.json` · `tauri.conf.json` · `Cargo.toml` · `src/lib.rs` ·
  `capabilities` 중 **없는 것을 이름으로 나열**하고 → **exit 2**

마지막 줄을 이렇게 적었다: **「읽을 것이 없는 것은 «통과»도 «차단»도 아니다.」**
2 를 1 과 섞지 않은 이유다 — 「관문이 막았다」와 「관문을 돌리지 못했다」는 다른 사실이다.

### 4-1. V-6 — `exit 0` 이 **죽은 분기가 아님**을 어떻게 보였나

연습을 3 으로 바꾸면 **이 저장소에서는 0 이 영원히 안 나온다**(운영 origin 미정). 그러면
「통과 분기가 살아 있는가」를 아무도 확인하지 못한다 — Phase 7 의 `.icns` 함정과 같은 모양이다.

그래서 **스크립트 자체를 scratchpad 에 복사**해, 그 사본에게는 옆의 `src-tauri` 가 **«기본» root**
가 되도록 두고 돌렸다. `rehearsal` 은 **「기본이 아닌 root 를 지정했는가」**로 판정되므로 이 사본에게는
연습이 아니다 — 결과 **exit 0 · `"rehearsal": false` · `"originsAgree": true`**.

**통과 분기는 살아 있다.** 그리고 이 실험은 **진짜 워크트리를 한 글자도 건드리지 않았다.**

> 솔직히 적어 둘 한계: 이 방법이 보여 주듯, **스크립트를 옮기면 누구나 0 을 만들 수 있다.**
> W-1 이 막은 것은 「문서화된 연습 스위치가 0 을 돌려주는 것」이지 **모든 우회**가 아니다.
> 관문은 **실수와 자동화의 오집계**를 막고, **의도적 우회는 막지 못한다** — 그것은 관문이 아니라
> 리뷰와 서명의 몫이다.

## 4-2. **자동화 진입점 — `make` 로는 이 코드들을 읽을 수 없다**

> 이 절은 W-1 보정 회차(`tauri-p8-w1-fix-report.md`)에서 더했다.

위 표의 1·2·3 은 **스크립트를 직접 불렀을 때**의 코드다. **`make` 로 부르면 셋이 하나가 된다** —
GNU make 는 레시피가 0 이 아닌 값으로 끝나면 **자기 코드 2** 로 감싸기 때문이다. 실측:

| 실행 | 스크립트 | `make shell-final-preflight` |
|---|---|---|
| 차단 | **1** | **2** |
| 경로 없음 | **2** | **2** |
| 연습 | **3** | **2** |

(`GNU Make 3.81` · 합성 타깃 `@exit 1|2|3` 으로도 재현 — **전부 2**)

**그래서 W-1 이 만든 구분이 make 뒤에서 사라진다.** 「막혔다」와 「돌리지 못했다」와
「연습이었다」가 자동화 눈에 같은 값이 된다.

**종료 코드를 읽어야 하는 쪽(자동화·CI)은 스크립트를 직접 부른다**:

```
cd frontend && node scripts/verify-final-build.mjs [--origin <https://host>] [--evidence <path>]
```

**`make shell-final-preflight` 는 사람이 보는 편의 진입점으로 남긴다** — 출력을 눈으로 읽을 때 쓴다.
같은 내용을 Makefile 의 타깃 주석에도 적었다.
