# 최종 재검수 리포트 — SPEC-006 v0.2.1 / R2 수정 범위 (2026-09-22)

## 판정: **WARN** — FAIL 0 · WARN 5

**R2-F1 ~ F4 · R2-W1 ~ W7 열한 건이 전부 닫혔다. 미반영 0건.** 새로 생긴 **직접 회귀도 없다** —
수정이 만든 빈틈을 찾으려고 취소·실패·재시도·늦은 완료 경로를 다시 펼쳤지만 계약이 전부 답했다.

**구조는 닫혔다.** 「점유는 녹음이 실제로 끝날 때만 풀리고, 그 판단을 신호의 부재에 맡기지 않는다」가
이제 양쪽에서 막혀 있다 — **푸는 쪽**은 «완료» 사건으로만(L-06·L-09·L-13 + 웹의 L-02·L-05·L-08·L-10),
**거는 쪽**은 사건 기반 재무장으로(E-09·L-14). TTL·주기적 갱신·참조계수는 되살아나지 않았고
커맨드는 넷 그대로다. 내가 R2 마지막에 「볼 자리」로 지목한 **「푸는 방향이 다시 열렸는가」는
열리지 않았다.**

WARN 다섯은 **전부 표현·숫자·한 줄 공백**이다. 계약의 뜻을 바꾸지 않고, 고치는 데 각 한 줄이면 된다.
**문서 승인을 막을 사유로 보지 않는다** — 코디 판단으로 지금 고치거나 WP 때 얹어도 된다.

> **이번 검수는 R2 범위만 봤다.** 이미 통과한 조사·사실·구조 검증을 다시 하지 않았고,
> 선호 기능을 새로 요구하지 않았다. 미실측·미정 OS·배포 주소·사용자 선택은 문서 오류와 갈라 적었다.

## R2 항목별 닫힘 확인

### R2-F1 — AC-T17 ↔ L-10 모순 → **닫힘**

- `AC-T17`(`:698-701`)이 **셸 동작으로** 다시 쓰였다 — 「셸은 앱 안의 화면 전환과 같은 문서 안의
  주소 변경을 **문서 교체로 보지 않는다** … **재는 것은 셸의 훅이 발화하는가**이지 점유가 남아
  있는가가 아니다. (녹음이 실제로 끝나 **웹이** 푸는 것은 별개이고 L-10 이 그 계약이다)」
- **두 주체가 갈렸다**: 「셸이 자동 해제하지 않음」(AC-T17) ↔ 「웹이 녹음을 끝내며 해제」(L-10, `:535`).
  이제 **녹음 중에 이 AC 를 실행해도 오판정이 나지 않는다** — 재는 대상이 점유가 아니라 훅이다.
- M-3(`:770`)의 칸이 그대로인 것도 맞다 — M-3 은 처음부터 「훅이 발화하는가」였다.
- **덧붙은 한 줄(「무엇을 재는가」)이 이 수정의 핵심**이고, 그게 없었으면 QA 가 다시 점유를 볼 위험이 남았다.

### R2-F3 — 해제 트리거가 「요청/완료」 미구분 → **닫힘**

- **L-06**(`:530`) — 「창이 **실제로** 닫힌다·앱이 **실제로** 끝난다 … **해제 시점은 «완료»다** —
  닫기·종료를 **요청**한 순간이 아니다. **되묻기에서 사용자가 계속하기를 골라 요청이 취소되면
  점유는 그대로 유지된다**」
- **L-09**(`:533`) — 「문서가 **실제로** 바뀐다 … **시도만 하고 막힌 이동은 여기 해당하지 않는다**」
- **L-11**(`:536`) — 같은 문서 주소 변경 **+ 취소·차단된 이동**(`E-05`)을 함께 흡수. **동일 문서 URL 변경과
  막힌 이동이 한 줄에서 「트리거 아님」으로 정리**됐다.
- **비교표**(`:349`) — 「녹음 중에 스스로 풀릴 수 있나: 없다」 → **「신호가 안 와서 풀리는 일이 있나: 없다」**
  로 좁히고, 바로 아래 단서로 **「『녹음 중에 절대 안 풀린다』고 쓰지 않는다」**를 박았다.
  **내가 R2 에서 과장이라고 지적한 문장이 정확히 그만큼만 남았다.**
- **AC-T36**(취소된 닫기 — 점유 유지 + 그 뒤 자동 절전 시간을 넘겨도 안 잠든다) · **AC-T37**(막힌 이동)
  · **M-13** 신설. S-6 3~4 도 「요청만으로는 아무것도 풀리지 않는다 / `닫기`면 **실제로 닫히고** 그때 풀린다」로 갱신.
- 조사 §10-3 에 **정정 근거**가 남았다 — `CloseRequested` 는 *"has been requested to close"* 라
  취소 가능하고 실제 완료는 `Destroyed`/`Exit`, `on_navigation` 은 취소 가능하고 실제 교체 신호는
  `PageLoadEvent::Started`. **「어느 API 를 쓸지는 구현의 몫이고 SPEC 은 『완료에만 푼다』는 관찰 가능한
  결과만 요구한다」**로 닫은 것이 맞다 — 플랫폼 상세를 SPEC 에 끌어들이지 않았다.
- **대칭 보강도 확인**: 「웹이 **종료되지 않았는데 푸는** 경로도 두지 않는다」(`:562`) — 웹 쪽 네 자리가
  전부 녹음이 실제로 끝나는 자리임을 명시했다. 요구하지 않았는데 같은 부류의 빈틈을 함께 막았다.

### R2-F4 / R2-W1 — 늦은 `acquire` · 키 유일성 → **닫힘**

### WARN-3. Placement 의 「녹음 중인 화면일 때만」이 `E-14b` 문구와 어긋난다

  상태 영역에 한 줄 (U-3)」

### WARN-4. AC-T32 가 AC-T36 에 완전히 포함된다

- **위치**: §6 AC-T32(「녹음 중 창을 닫으려 하면 되묻고, `계속 녹음` 을 고르면 창이 닫히지 않는다」) ·
  AC-T36(「… 창도 녹음도 남고 **점유도 그대로 유지된다** …」)
- **문제**: AC-T36 이 AC-T32 의 내용을 전부 포함한다. 같은 시험을 두 번 적는다.
- **교체 문장 (둘 중 하나)**: ① AC-T32 를 **「녹음 중 창 닫기에 되묻기가 뜬다(닫기 동작이 즉시
  일어나지 않는다)」**로 좁히고 결과는 AC-T36 이 갖게 한다. ② AC-T32 를 지우고 M-6 의 칸을
  `AC-T36 · AC-T38` 로 옮긴다. **①을 권한다** — M-6(되묻기가 도는가)의 짝이 남는다.

### WARN-5. `shell_info` 가 실패했을 때 `acquire` 를 시도하는지가 없다

- **위치**: `E-14a`(「그 실패가 `shell_info` 또는 `wake_guard_acquire` 였다 → **degraded 와 같게
  다룬다**」) ↔ §4 「웹이 아는 기능이 `features` 에 없으면 그 기능만 끄고 …」
- **문제**: `shell_info` 가 실패하면 `features` 를 **모른다.** 그때 웹이 ① `wake_guard_acquire` 를
  그래도 시도하는지 ② 기능이 없다고 보고 아예 안 부르는지가 정해져 있지 않다. ①이면 **성공할 수도
  있는데** `E-14a` 를 따라 U-3 을 띄워 **틀린 경고**가 되고, ②면 절전 방지 없이 녹음이 도는데
  그 사실은 맞게 드러난다. (셸 **존재** 판정은 전역으로 하므로 `E-01` 과는 겹치지 않는다.)
- **교체 문장 (§4 `shell_info` 아래 한 줄)**: 「**`shell_info` 가 실패해도 웹은
  `wake_guard_acquire` 를 시도한다.** 그 응답이 최종 상태이고, 응답조차 실패하면 `E-14a` 로 간다.
  `features` 를 모른다는 것이 기능이 없다는 뜻은 아니다.」

## 문서 품질 통과 ↔ 남는 것 — 갈라 적는다

### 문서 오류 — **이번에 전부 닫혔다 (0건 잔존)**

R2-F1~F4 · R2-W1~W7 열한 건 전부. 위 WARN 5 는 **계약의 뜻을 바꾸지 않는 표현·숫자·한 줄 공백**이다.

### 후속 **사용자 결정** — 11건, 늘지 않았다

OQ-T01 ~ OQ-T11 그대로. `max(3T, 30분)` 을 OQ 가 아니라 **QA 기준**으로 확정한 처리에 동의한다.
성격이 바뀐 것 하나 — **OQ-T01(지원 OS)의 무게**가 W7 정정으로 늘었다(대상 macOS 가 Sequoia 하나가
아니라 Sonoma·Ventura 까지). 이것은 **문서 오류가 아니라 사용자 결정 항목**이다.

### 후속 **구현 실측** — 15건 (M-1 ~ M-14 + M-2b)

이번에 M-13·M-14 신설 · M-1·M-12 확장. **개발 fixture 로 뗄 수 있다는 판정은 그대로**이고,
운영 주소가 막는 것은 M-1·M-5 의 «최종» 확인과 인수조건 최종 통과뿐이다.
가장 무거운 둘은 그대로 — **M-1**(원격 문서에서 커맨드 호출 성립) · **M-2**(대상 OS·웹뷰 판의 녹음 포맷).
**이것들이 미실측이라는 사실은 FAIL 사유가 아니다.**

### 이 SPEC 이 여전히 보장하지 않는 것 — **과장 없음을 확인했다**

웹이 살아 있는 채로 멈춘 경우의 정리(L-12) · OS 가 풀리는 «순간»을 아는 것 · 재무장의 성공 ·
수동 절전 복귀 직후의 OS 상태 · 되묻기를 어느 층이 내는가 · 늦은 획득을 어떤 수단으로 막는가.
**여섯 모두 「보장하지 않는다」로 적혀 있고, 그 자리마다 실측 항목이나 한계 표시가 붙어 있다.**
