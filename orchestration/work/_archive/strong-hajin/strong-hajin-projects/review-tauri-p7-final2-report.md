### 3-1. 두 갈래 분리 · strict 승격 범위 (PASS)

**코드 구조**(`verify-shell-build.mjs`):

```js
const unverifiable = [];   // 구성 미비 — 채우면 사라진다
const hostNotes    = [];   // 호스트 한계 — 기기의 성질

```

- **`hostNotes` 는 `failed` 계산에 들어가지 않는다** — 어느 모드에서도 승격되지 않는다.
- 출력이 **두 건수를 따로** 찍는다: `문제 0건 · 구성 미비 1건 · 호스트 한계 1건`.
  글리프도 갈린다 — 구성 미비는 `⚠`/`✗`(모드별), 호스트 한계는 **언제나 `ℹ`**.
- **strict 통과 메시지가 플랫폼 대체를 계속 막는다**:
  「ℹ 호스트 한계는 남아 있다 … **이 기기에서 못 구운 플랫폼을 «검증됐다»고 쓰지 않는다** —
  strict 통과는 «구성이 갖춰졌다»는 뜻이지 «모든 플랫폼이 구워진다»는 뜻이 아니다」
  → 직전 W-1 이 우려한 「초록 = 다 된다」 오독을 **strict 쪽에서도** 막았다.

**재현한 동작표**:

| 명령 | exit | 요약 줄 |
|---|---|---|
| `make shell-verify` | **0** | 문제 0 · 구성 미비 1 · 호스트 한계 1 |
| `make shell-verify SHELL_STRICT=1` | **2** | 실패 **1건**(호스트 한계는 안 올림) |
| `make shell-verify-strict` | **2** | 위와 같다 |
| `make shell-verify SHELL_TAG=v0.0.1` | **0** | 태그 대조 통과 |
| **`… SHELL_TAG=v0.0.1 SHELL_STRICT=1`** | **2** | 태그 통과 + 구성 미비 1건 승격 |
| `make shell-verify SHELL_TAG=v9.9.9` | **2** | `✗ 코드 태그와 판 번호가 다르다` · 문제 1건 |
