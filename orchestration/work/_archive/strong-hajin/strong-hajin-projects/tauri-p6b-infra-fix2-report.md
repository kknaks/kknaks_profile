## 2. 무엇이 어긋나 있었나

| | 직전 판이 말한 것 |
|---|---|
| **§9 runbook** | `0) AppProject 적용` 이 구분선 **위** → 승인 없이 해도 되는 일로 읽힌다 |
| **§9-1 표** | 「하지 않은 것 · 클러스터」에 **`AppProject 적용`** 이 들어 있다 |

**읽는 사람은 둘 중 하나를 믿는다.** 그리고 runbook 이 실행 순서라서, 실제로는 **더 위험한 쪽**
(구분선 위 = 승인 없이 실행)을 믿게 된다. 문구 하나가 **승인 게이트를 한 단계 새게** 만들고 있었다.

**내가 그렇게 쓴 이유도 적어 둔다**: 직전 회차의 지시가 「AppProject 를 먼저 적용하는 단계를
추가하라」였고, 나는 그 **「먼저」를 순서의 맨 앞으로** 옮기는 것으로 읽었다.
하지만 「먼저」의 뜻은 **「클러스터 작업들 «사이»에서 첫 번째」**이지 **「승인보다 먼저」**가 아니다.
지금 판은 그 구분을 본문에 못박았다 — `**클러스터 작업들 «사이»의 선행 조건**이지 승인보다 앞서는
예외가 아니다`.

## 3. 고친 것

### 3-1. 구분선을 AppProject 단계 **위**로 올리고 번호를 다시 매겼다

| 전 | 후 |
|---|---|
| `0)` AppProject 적용 ← **게이트 위** | `1)` D-1·D-2 결정 |
| `1)` D-1·D-2 결정 | `2)` 이미지 빌드·푸시 |
| `2)` 이미지 빌드·푸시 | **════ 승인 게이트 ════** |
| **──── 승인 게이트 ────** | `3)` **AppProject 적용** ← 게이트 **아래** |
| `3)`~`8)` 클러스터 작업 | `4)`~`9)` 클러스터 작업 |

**번호를 0 에서 시작하지 않게 된 것이 부수 효과가 아니라 본질이다** — `0)` 이라는 번호 자체가
「본 순서 밖의 예비 단계」로 읽혔다. 지금은 **1)~9) 가 연속**이고, 그중 **3) 부터가 게이트 아래**다.

구분선 자체도 바꿨다:

```
════════ 승인 게이트 · 여기서부터 «전부» 클러스터를 건드린다 ════════
        (사용자/코디 승인 후, 별도 지시로만 실행한다)
```

### 3-2. 머리말을 「단계 번호」가 아니라 「구분선」 기준으로 다시 썼다

| | 문장 |
|---|---|
| **전** | 「이 순서의 **3) 부터는** 클러스터에 손대는 일이다 … 1)·2) 는 레포/이미지 작업이라 **그 앞에 둘 수 있다**」 |
| **후** | 「**구분선 «아래»는 전부 클러스터 쓰기다 — AppProject 적용도 그중 하나다.** … 구분선 위의 1)·2) 만 승인 없이 진행할 수 있는 레포/이미지 작업이다」 |

번호로 경계를 말하면 **번호가 바뀔 때마다 문장이 낡는다.** 구분선으로 말하면 그 문제가 없다.

### 3-3. AppProject 단계에 「클러스터 쓰기」를 명시

```
3) argocd/projects/strong-hajin.yaml (AppProject) 를 **먼저** 적용한다

   ⚠ … **클러스터 작업들 «사이»의 선행 조건**이지 승인보다 앞서는 예외가 아니다.
```
