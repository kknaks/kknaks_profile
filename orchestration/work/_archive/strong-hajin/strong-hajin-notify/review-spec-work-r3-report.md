## 2. 회귀 — §4.1 연결 수명을 한 줄로 읽어 보기

수명: 첫 연결 → `ready`(첫) → 끊김 →
- ⓐ 네트워크 오류: 브라우저 `CONNECTING` → 같은 인스턴스가 다시 붙음 → `ready`(둘째)
- ⓑ 비-200: `CLOSED` → `/api/auth/me`
  - 401 → 세션 상실(로그인)
  - 그 밖 → 백오프 새 인스턴스(쿼리 있으면 실음) → `ready`(둘째) → 순번이 있었으면 이어 받기 + `resync(reconnected)`
  - 10번 이어 실패하면 멈춤 → 화면 활성 · 포커스 때 1회부터 → `ready`(둘째)

- **모순 없음.** 「첫 `ready` = `GET` 으로 읽기 · 둘째 이후 = 다시 읽기」(:218 · :234)가 ⓐ ⓑ 와 멈춤 뒤 재개를 모두 덮는다. 「앱을 다시 열면 늘 첫 연결」(:234)과도 맞는다. S8 §4.4(:498)와 AC-35(:887)가 같은 문장을 쓴다
- **R3-W2 — 다시 읽기가 두 번 돈다.** 순번이 있는 재연결에서는 서버가 `ready` 다음에 이어 받기 + `resync(reconnected)` 를 보낸다(:219 · :230). 그러면 화면은 **둘째 `ready` 로 한 번, `resync` 로 또 한 번** 다시 읽는다. 결과는 맞지만 메시지함 · 설정 연동 · 알림 목록 GET 이 한 재연결에 두 번씩 나간다. 또 `ready` 때 읽은 목록 위로 이어 받기 줄이 끼워지는 순서도 정해져 있지 않다
  - 고칠 것(한 줄): 「같은 연결에서 둘째 `ready` 로 다시 읽었으면 뒤따르는 `resync(reconnected)` 는 무시한다(`replay_overflow` · `dropped` 는 따른다)」, 또는 「순번을 실은 재연결이면 `ready` 가 아니라 `resync` 에서만 다시 읽는다」
- **R3-W1 — 10회 멈춤이 서버 장애에도 걸린다.** 세는 대상이 「백오프 새 연결이 `ready` 없이 10번」(:261)이다. 백오프(1·2·4·8·16·30·30·30·30·30초 ≈ **약 3분**)로 보면 **3분 넘는 서버 · Cloudflare 장애**에서도 멈춘다. 그때 앱이 뒤에 있으면(포커스 · 화면 활성이 없으면) **장애가 끝나도 실시간 · OS 알림이 사용자가 창을 누를 때까지 조용히 멈춘다**. D-06 의 「앱이 켜져 있을 때 OS 알림」 에서 벗어난다. R-W6 의 원래 대상은 `403`(같은 origin 앱에서는 생기지 않음)이다
  - 고칠 것(택일):
    - ① 「`/api/auth/me` 가 **200 인데** 스트림만 실패한 횟수」 로만 센다(장애 중엔 `/api/auth/me` 도 실패하므로 세지 않는다)
    - ② 멈춘 뒤에도 느린 재시도(예: 5분마다 1회)를 남긴다
  - 그리고 S11 :261 · AC-02b · W13 :251 · 시험 ⑤ 에 반영한다
- 그 밖에 고친 절 주변(§2.5 묶음 · §4.5-2-3 표 · §4.6 · §7 OQ-1102 · §4.5-3 위치 이동)에서 새 모순은 보지 못했다. 다른 절이 「§4.5-3」 을 부르는 번호도 그대로라 깨진 참조가 없다
