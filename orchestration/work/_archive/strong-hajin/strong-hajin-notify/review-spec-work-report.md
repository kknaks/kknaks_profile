## 6. SSE 계약의 운영 조건 — **FAIL 1 · WARN 2**

**F-1 (FAIL) — 재연결 · 401 계약이 `EventSource` 동작과 맞지 않는다.**
- 표준 `EventSource` 는 **200 이 아니거나 `text/event-stream` 이 아닌 응답을 받으면 연결을 «fail» 시키고 다시 붙지 않는다**(readyState CLOSED). 자동 재연결은 **네트워크 오류**에서만 돈다. 또 화면 코드는 **응답 상태 코드를 볼 수 없다**
- 그런데 S11 은 다음 셋을 전제한다
  - (a) 「`401` → EventSource 는 닫힌다 → 화면은 로그인 화면으로」(:197). 닫힘이 401 때문인지 화면이 가를 수 없다
  - (b) 「`401` 로 닫히면 다시 붙지 않고 세션 상실」(:242) · 「지금 WS 의 백오프는 걷는다」(:243)
  - (c) Case Matrix 「배포 재시작 → 브라우저가 3초 뒤 `Last-Event-ID` 로 다시 붙는다」(:526)
- 실제로는 배포 재시작 · ingress 502/503 · Cloudflare 52x 때 재연결 시도가 비-200 을 받는다. 그러면 **실시간이 영구히 끊기거나**, (a)대로 짜면 **멀쩡한 세션이 로그인 화면으로 튕긴다**. 새 `EventSource` 를 만들면 `Last-Event-ID` 머리도 실리지 않는다
- 고칠 것(S11 §4.1-1 · §4.1-3 · §4.1-6 · Case Matrix · W13 WP1-FE :245)
  - ① 화면이 CLOSED 를 받으면 세션 확인 API(기존 `me` 류)로 401 인지 가린다
  - ② 401 이 아니면 **화면 쪽 백오프로 새 EventSource** 를 연다
  - ③ 마지막 id 를 **쿼리(`?last_event_id=`)로도 받는** 서버 계약을 더한다(머리가 있으면 머리가 우선)
  - ④ 시험에 「비-200 뒤 회복」 을 넣는다

**W-2 — 사건 순번과 커밋 순서.** id = 전역 시퀀스이고 「커지기만 하면 된다」(S11 :219)고 했다. 그런데 순번은 `nextval` 때 정해지고 보이는 순서는 **커밋 순서**다. 순번 100 의 트랜잭션이 101 보다 늦게 커밋되는 중에 끊겼다가 `Last-Event-ID: 101` 로 붙으면 100 은 이어 받기에서 빠진다.
- 목록은 `resync` 뒤 다시 읽으니 메워진다. 잃는 것은 **그 줄의 실시간 끼우기와 OS 알림**뿐이다
- SPEC 에 「이어 받기는 `seq > last − 여유` 로 읽고 받은 id 로 거른다」 또는 「`resync` 가 메운다(OS 알림은 잃을 수 있다)」 중 하나를 명시하라
