- example10단계 API 흐름: 신규 계약 테스트와 전체 백엔드 검증에서 통과.

## 미결과 배포 조건

- OQ203: 미완료 하위가 있을 때 완료보고 선제출 허용 여부. 답 전에는 현행 동작을 보존하며 정책 확정이라고 쓰지 않는다.
- OQ206: 회의에서 승격한 요청의 인간 완료 승인자. 답 전 자동 승인/임의 승인자 지정 없음. 해당 완료 승인 경로는 미완료로 남는다.
- 로컬 실행 DB가 비어 있어 BASE U1/U2/U6·운영 인덱스 검증은 배포 전 실제 데이터 DB에서 재확인해야 한다. 빈 DB의 0건은 배포 승인 근거가 아니다.
- 스키마 최신 여부 확인 후 스택 기동. 스택 시작은 사용자 몫이며 기존 사용자 프로세스는 건드리지 않는다.

## 사용자 브라우저 E2E — 실행 대기

| 시나리오 | 조작 | 기대 결과(눈으로) |
|---|---|---|
| E-1 | 보고서 만들고 그 아래 디자인을 **다른 사람에게 요청** | 보고서 하위에 「수락 대기」 행이 선다. 상대의 **수행할 업무 소유 목록에는 아직 없고**, 내 업무 탭의 「받은 요청」에서 수락·거절할 수 있다 |
| E-2 | 상대가 **수락** → **시작** | 같은 행이 담당 확정으로 바뀌고, 수락과 시작이 **다른 시각**으로 읽힌다 |
| E-3 | 상대가 **거절**(사유) | 그 행이 **「취소됨 — 요청 거절」**로 읽히고 「완료 업무」의 취소로 간다 |
| E-4 | **재요청** | 같은 상위 아래 **새 행**이 서고 이전 취소 로그가 남아 있다 |
| E-5 | 하위가 남은 채 **최종 완료** 시도 | 거부되고 **읽을 수 있는 막는 하위의 이름**이 보인다. 비공개 하위만 막으면 이름·ID·건수 없이 일반 안내가 보인다 |
| E-6 | **완료 보고 → 보완 → 재보고 → 승인** | 같은 업무에서 **회차**가 쌓이고 별도 검토 업무가 생기지 않는다 |
| E-7 | **담당 변경 제안 → 거절** | 기존 담당이 그대로이고 업무가 취소되지 않는다 |
| E-8 | **담당 변경 제안 → 수락** | 담당이 바뀌고 중간에 담당 없는 구간이 보이지 않는다 |
| E-9 | 수락 후 **취소 제안 → 동의** | 동의 전에는 아무것도 안 바뀌고, 동의하면 취소된다 |
| E-10 | 완료된 상위 아래 **하위 재개** 시도 | 거부되고 **상위를 먼저 재개하라**고 읽힌다 |
| E-11 | **요청자가 하위와 연결 자료 열기** | 열린다. **수행자의 다른 업무·미연결 자료는 없는 것처럼** 보인다 |
| E-12 | 취소 항목 **목록 정리** | 목록에서 빠지고 이력에는 남는다 |

## 시안 반영 범위

3탭·표·필터·업무 기한 캘린더·수신 레일·2열 생성창·v2 상세 조작이 이번 구현 대상이다. SPEC/WORK에서 후속으로 명시한 별표·근무시간·회의 일정·수신 카드 미읽음/아바타·메일/메신저 통합·새 내비 페이지는 이번 구현 완료에 포함하지 않는다. 전체 원본 시안 완료라고 표시하지 않는다.

## 최종 기록

실제 테스트 로그/exit, 코드 리뷰, 각 인수조건의 테스트 위치, 실행 순서와 데이터 준비 방법을 기록했다. 브라우저 E2E는 사용자 확인 전까지 미실행으로 남긴다.

생성 모달 첨부는 기존 자료 쓰기권한에 따라 본인 업무의 생성→업로드 두 단계만 지원한다. 배정·요청·회의 승격은 담당자가 상세에서 첨부한다(요청은 수락 후). 첨부 실패 시 업무 재생성 없이 재시도/상세로 이동하는 경로를 사용자 E2E에서도 확인한다. Composer의 200자는 표시 눈금이며 기존 본문을 잘라내지 않는다.
