### F-5. migration 의 「기존 표 인덱스는 사람이」가 **재현·검증 가능한 형태가 아니다**

네 구멍이 한 자리에 있다. **하나의 결함으로 센다.**

1. **DDL 문장이 문서에 없다.** `:320` 과 Phase 1 작업 `:470` 이 「`CREATE INDEX CONCURRENTLY` 문을
   **이 문서의 Rollout 절에 적는다**」인데, Rollout 절(`:326-334`)에는 `③ 인덱스 추가(기존 표) →
   CREATE INDEX CONCURRENTLY, 사람이 실행` 한 줄뿐 **어떤 인덱스인지·어떤 문장인지가 없다.**
   Pre-deploy Check `:954` 도 「사람이 실행했다」만 묻는다. **사람이 무엇을 실행하는지가 어디에도 없다.**
2. **격리 PG 가 이 결손을 재현하지 못한다.** `make test-postgres`(`Makefile:52-54`)의 테스트 DB 는
   `create_all` 로 새로 뜨므로 **인덱스가 처음부터 다 있다.** `schema_sync.plan()` 이 `CreateIndex` 를
   **새 표 분기 안에서만** 내는 것(`schema_sync.py:27-30`)이 문제의 원인인데, 그 경로가 격리 PG 에서는
   밟히지 않는다. Phase 1 검증 `:537` 은 「**새 표**의 인덱스가 생겼는지」만 본다 — **기존 표 쪽은 아무도 안 본다.**
3. **부분 유일 인덱스는 중복이 있으면 생성이 실패한다.** `uq_tasks_source_work_request` 는
   `unique=True` + `postgresql_where`(`persistence.py:900-908`)다. 실행 DB 에 그 인덱스가 없었다면
   **그동안 중복이 들어갈 수 있었다는 뜻**이고, 만들려는 순간 실패한다.
   Phase 0 의 확인 항목(`:432`)은 **존재 여부만** 세고 **중복은 안 센다.**
4. **`CONCURRENTLY` 의 실패 모드가 절차에 없다.** 트랜잭션 블록 안에서 못 돌고, 실패하면
   **INVALID 인덱스가 남아** 다음 시도를 막는다. Rollback 표 `:344` 는 성공 경로만 적었다.
- **최소 수정 — Phase 0 에 한 줄, Phase 1 작업·검증에 각 한 줄, Rollout ③ 를 두 단으로**:

  > Phase 0 작업: - [ ] `uq_tasks_source_work_request` 의 **존재와 함께 중복을 센다** —
  >       `SELECT source_work_request_id, count(*) FROM tasks WHERE source_work_request_id IS NOT NULL
  >       GROUP BY 1 HAVING count(*) > 1;` **0건이 아니면 인덱스를 만들 수 없다 — 사용자에게 올린다.**
  > Phase 1 작업: - [ ] **기존 표 인덱스 DDL 을 레포 안 파일 하나로 남긴다** —
  >       `backend/migrations/manual/2026-09-17-w2-indexes.sql`. 그 파일이 **적용 단위이자 증거**다.
  >       `CREATE INDEX` 판과 `CREATE INDEX CONCURRENTLY` 판을 **같은 파일에 나란히** 둔다
  >       (전자는 격리 검증용, 후자는 운영 적용용 — **어느 쪽을 언제 쓰는지 파일 머리에 적는다**).
  > Phase 1 검증: - [ ] **격리 PG 에서 기존 표 결손을 인위로 재현해 닫는다** —
  >       대상 인덱스를 `DROP INDEX` 한 뒤 위 `.sql`(비-CONCURRENTLY 판)을 적용하고 `pg_indexes` 로
  >       재확인한다. **`schema_sync` 가 만들 것이라고 쓰지 않는다**(O-24). 재현·재실행이 이 한 줄로 닫힌다.
  > Rollout ③ 를 둘로: `③-a 격리 PG — .sql(비-CONCURRENTLY) 적용 + pg_indexes 확인 (에이전트)` /
  >       `③-b 운영 — 같은 파일의 CONCURRENTLY 판, 사람이 실행. 실패 시 INVALID 인덱스를
  >       DROP INDEX 하고 다시 시작한다 (트랜잭션 블록 안에서 돌지 않는다)`.
  > Pre-deploy Check `:954` 를 「그 `.sql` 이 적용됐고 `pg_indexes` 로 확인됐다」로 바꾼다.
