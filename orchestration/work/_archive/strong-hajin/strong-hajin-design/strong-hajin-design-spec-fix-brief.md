## 2. FAIL · WARN

### FAIL — §7 에 행 셋 추가

기존 계약과 어긋나는 자리 셋이 §7 에 등록되지 않았다. **본문을 고치지 말고 §7 에 행만 더한다.**

- SPEC-001 U-7 구획 순서 고정 ↔ 네 덩어리
- SPEC-001:764-765 「한 건씩 떼는 전용 명령을 두지 않는다」 ↔ 신규 후행 해제 명령
- SPEC-005:219·:1194 「후행 조회를 만들지 않는다」 ↔ 후행 조회 개설

셋 다 **사용자가 확정한 것이라 SPEC-007 이 이긴다.** 「기존 계약의 이 줄을 대체한다」로 적고,
대체되는 원문 줄을 인용한다. 기존 문서를 **고치지는 마라** — 대체 사실만 기록한다.

### WARN — 무거운 셋은 반드시 닫는다

1. **못 읽는 선행의 화면 표현** — SPEC-001 「건수만 낸다」에서 「자리를 남긴다」로 바뀌었고
   AC 874 가 건수 문구 없이도 초록이다. **후행과 같은 규칙으로 통일한다: 건수만 낸다.**
   AC 를 건수 문구까지 검사하도록 고친다
2. **못 읽는 선행이 셈과 배너에 어떻게 세어지나** (state 가 null) — **셈에 포함한다.**
   후행에서 「셈이 비공개를 포함한다」를 이미 계약으로 박았으니 선행도 같다.
   배너 본문에는 제목을 못 쓰므로 「끝나지 않은 선행 N건」으로 낸다
3. **`read_only` 갈래에 후행이 실리나** — **실린다.** 읽기 전용은 보는 범위가 아니라 고치는 범위다.
   해제 단추만 없다

나머지 WARN 다섯은 고치거나, 안 고치면 **이유를 리포트가 아니라 스펙 본문에** 남긴다.

## 3. OQ 여덟 — 코디 판정. 이대로 닫아라

| OQ | 판정 | 근거 |
|---|---|---|
| **701** 상태·판단 구획 여덟이 어디 서나 | **덩어리를 둘 더 만든다.** 네 덩어리 뒤에 `진행과 판단`(완료 보고·승인/반려·취소 제안·조건 변경·담당 변경)과 `이력`(활동 이력). `AX` 는 업무 메타 오른쪽 단추 | 판단은 관계와 성격이 다르다 — 연관 업무에 섞으면 관계와 결재가 한 덩어리가 된다 |
| **702** 「편집」 단추 조건 | **A(기본)에만.** B(막힘)·C(편집 중)엔 없다 | 시안이 그렇다 |
| **703** 인덱스 설치 방법 | **스펙은 「인덱스가 필요하다」까지만 쓴다.** 설치 방법은 backend 워커가 답한다 | Alembic 부재·schema_sync 한계는 구현 문제다 |
| **704** 연결 편집 저장의 원자성 | **칸마다 따로 저장한다**(네 기본값 유지). 한 칸이 거절돼도 나머지는 남는다. 화면은 거절된 칸만 되돌리고 그 칸의 오류를 보여준다 | 여러 업무를 건드리는 한 번의 트랜잭션은 이 범위 밖이다 |
| **705** 「산출물」 개명 범위 | **업무 상세 화면만.** 전역 개명은 이번 판 밖 | 시안이 바꾼 자리가 거기뿐 |
| **706** `single-source-of-truth` 개념 노트 부재 | **이번 판 밖.** dangling 링크를 그대로 둔다 | DEC-004 도 같은 상태. 개념 정리는 작업 마감 때 |
| **707** 기존 계약과 갈린 셋 | **셋 다 SPEC-007 이 이긴다** (아래 상세) | 사용자 확정 |
| **708** 후행 해제를 A 담당자에게 여나 | **연다.** A 담당자가 자기 후행을 해제할 수 있다 | 사용자 확정 — 「후행 해제는 반영하고 담당자한테 보낸다」. 네 기본값(대개 거절)은 이 결정과 어긋난다 |

### OQ-707 상세 — 셋 다 SPEC-007 이 이긴다

① **시작 막힘의 자리·문구** — 시안대로 **상단 배너 + 「시작할 수 없습니다 — <선행 제목>이 끝나지 않았습니다」**.
   SPEC-001 U-14(버튼 옆)를 대체한다. 이유: 어느 업무가 막는지를 말해 준다.
   (못 읽는 선행이면 제목 대신 「끝나지 않은 선행 N건」)

② **후보를 미리 줄이지 않는다** — 사용자 확정 「유효성은 서버가 판정한다」가 이긴다.
   SPEC-001 U-13(화면이 후보에서 뺀다)을 대체한다. 이유: 읽기 권한·순환·프로젝트 일치를
   화면이 선제로 판정하려면 화면이 트리 전체를 알아야 하는데, 업무 상세는 그것을 들고 있지 않다.
   **거절 문구를 칸 아래에 그대로 보여주는 것**을 AC 로 박아라

③ **상위를 옮기면 자손 프로젝트가 따라간다** — **따라간다.**
   이유: 생성 때 `project_for(…, parent)` 가 이미 부모에서 프로젝트를 끌어온다.
   안 따라가면 한 트리 안에서 프로젝트가 갈라지고 프로젝트 화면의 간트가 깨진다.
   **자손 전체가 움직인다는 것을 계약으로 박고 AC 를 붙여라**
