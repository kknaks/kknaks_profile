## 사용자가 실물에서 만날 자리

1. **푸터가 없다** — 업무 상세 아래쪽이 비어 있고, 닫기는 오른쪽 위 × 뿐이다. 「완료 처리」 단추를 찾던 습관과 다르다.
2. **진행 상태가 셀렉트다** — 트리거 색이 목록의 상태 칸과 같다. 「업무 취소」는 맨 아래 빨강이다. 확인 대기·취소 업무는 셀렉트 없이 글자다.
3. **선행이 안 끝난 업무**에서 「진행 중」을 고르면 고른 직후 빨간 토스트 「끝나지 않은 선행업무가 있습니다: …」가 뜨고, 셀렉트가 「시작 전」으로 남는다(배너 없음).
4. **완료한 일반 업무**에는 「업무 취소」가 없다(예전에는 있었다). **요청자로 연 업무**에는 시작·막힘·완료가 없다.
5. **`⋯`** 는 수락된 요청 업무를 요청자가 「관리 가능한 입구」로 열 때만 선다. 요청자는 대개 「보낸 업무」(읽기 전용)로 열기 때문에 **`⋯` 를 거의 못 볼 수 있다**(SPEC §2.10.7 ⚠ · 워커 미결 1 — 예전 푸터도 같았다).
6. **담당 셀렉트**는 내 업무에서 연 상세 + `task.assign`(팀장)일 때만 선다. 고르면 사유 모달이 뜨고, 보낸 뒤 「{이름}에게 변경 제안 중」 배지와 「담당 변경 대기」 상자가 선다. 기존 담당 이름은 그대로다.
7. **걸린 일 상자**가 메타 정보 바로 아래 쌓인다(막힘 사유 · 완료 확인 대기 · 보완 필요 · 담당 변경 대기 · 제안 · 미완 하위). 없으면 메타 정보 다음이 곧 「업무 정보」다.
8. **저장 중에는 셀렉트·`⋯`·담당이 잠긴다**(회색). 제목 아래·날짜 아래에 「저장 중…」 작은 글자가 선다.
9. **업무 내용**에 마우스를 올리면 옅은 테두리가 보이고, 누르면 같은 자리에 입력 상자가 선다(글자가 뛰지 않아야 한다). 캐럿은 누른 자리에 선다.
10. **「⋯」 모양**이 아이콘이 아니라 글자다(W4).
11. **AX 패널**의 입력 위 「업무 · 제목」 칩이 더 이상 없고, AX 를 열 때의 참고 자료 오류 토스트도 없다.
12. **완료 보고 모달을 연 채 제목을 고치면** 제출이 「task version is stale」로 거절될 수 있다(W1).

## 사용자 E2E 체크리스트 초안 — 업무 상세(고도화 3차 전체)

> 데모 DB 에서 아래 업무를 하나씩 준비한다. 「내 업무」 탭에서 연다(별도 표기가 없으면 담당자 본인).
> 각 줄은 **누를 것 → 보여야 할 것**이다. 공통 확인 넷: ① 머리 = 제목 + ×(겹이면 「뒤로」) ② 아래쪽 푸터 없음 ③ 「진행과 판단」 제목 없음 ④ 「AX에게 이 업무 묻기」 없음.

**A. 시작 전 · 일반 업무(본인)**
1. 연다 → 메타 정보 행이 이 순서로 선다: 진행 상태 · 버전 · 담당 · 시작 예정일 · 마감일 · (결재·참조·출처 있으면).
   - 시작 예정일·마감일은 비어 있어도 날짜 칸으로 선다.
   - 실제 시작일·실제 종료일 행은 없다.
2. 진행 상태 셀렉트를 연다 → 「시작 전」 · 「진행 중」 · 「완료」 · 맨 아래 빨간 「업무 취소」.
3. 제목을 누른다 → 그 자리에서 고쳐진다. Enter → 「저장 중…」 뒤 버전이 +1 된다. Esc → 원래 제목이고, 모달은 닫히지 않는다.
4. 제목을 다 지우고 Enter → 저장되지 않고 원래 제목이다. 한글 조합 중 Enter 로는 저장되지 않는다.
5. 업무 내용을 누른다 → 같은 자리에 입력 상자가 서고 글자가 안 뛴다. 두 줄을 쓰고 바깥을 누른다 → 저장되고 버전이 +1 된다.
6. 마감일을 고른다 → 즉시 저장된다. 시작 예정일보다 앞 날짜를 고른다 → 저장되지 않고 칸 아래 「시작 예정일은 마감일보다 늦을 수 없습니다.」.
7. 제목을 고치자마자 마감일을 고른다 → 둘 다 저장되고 오류가 없다(버전이 +2).
8. 「업무 취소」 → 사유 모달이 뜬다. 비우면 「업무 취소」 단추가 비활성이다. Esc → 모달만 닫히고 상태는 「시작 전」 그대로다.
9. 「진행 중」 → 바로 시작된다. 성공 토스트가 뜨고, 「실제 시작일」 행이 생긴다.

**B. 시작 전 · 선행이 안 끝난 업무**
1. 연다 → 「시작할 수 없습니다」 배너가 없다. 「연관 업무」 선행 칸에는 미완 배지가 그대로다.
2. 「진행 중」을 고른다 → 빨간 토스트 「끝나지 않은 선행업무가 있습니다: …」, 셀렉트는 「시작 전」. 「완료」를 골라도 같다.
3. 선행을 완료한 뒤 다시 「진행 중」 → 시작된다.

**C. 진행 중 · 일반 업무 · 체크리스트 일부 미완**
1. 셀렉트 → 「막힘」 · 「완료」 · 「업무 취소」.
2. 「막힘」 → 사유 모달(필수). 보내면 상태가 「막힘」이 되고, 메타 정보 아래 「막힘 사유」 상자가 선다.
3. (다시 진행 중으로 만든 뒤) 「완료」 → 「남은 단계가 있습니다」 확인창이 뜬다. 「돌아가기」 → 그대로다. 「그래도 완료」 → 완료된다.

**D. 막힘 · 일반 업무**
1. 셀렉트 → 「진행 중」 · 「업무 취소」(완료 없음). 「막힘 사유」 상자가 보인다.
2. 「진행 중」 → 바로 재개되고, 막힘 사유 상자가 사라진다.
3. (팀장 계정으로) 담당 셀렉트에서 다른 사람을 고른다 → 사유(선택) 모달 → 「변경」을 누르면 다음이 보인다.
   - 토스트 「담당 변경을 제안했습니다…」
   - 담당 값은 기존 사람 그대로이고, 옆에 「{그 사람}에게 변경 제안 중」 배지
   - 「담당 변경 대기」 상자
   - 담당 셀렉트가 이름 글자로 바뀐다

**E. 완료(최종) · 일반 업무**
1. 셀렉트 → 「진행 중」만 있다(「업무 취소」 없음). 「실제 종료일」 행이 있다.
2. 「진행 중」 → 재개 사유 모달(선택). 비워도 보낼 수 있고, 재개된다.

**F. 완료(확인 대기) · 결재자가 있는 업무 / 요청 업무 보고 뒤**
1. 진행 상태가 셀렉트가 아니라 글자다.
2. 「완료 확인 대기」 상자가 있다. 요청자 계정으로 열면 상자 안에 「완료 인정」·「보완 요청」이 있다.

**G. 요청받은 업무(담당자 = 나, 수락 후)**
1. 시작 전: 셀렉트 → 「진행 중」만.
2. 진행 중: 「막힘」 · 「완료」. 「완료」 → **완료 보고 모달**(결과 요약 필수).
3. 막힘: 「진행 중」 · 「완료」(→ 완료 보고).
4. 「업무 취소」는 어느 상태에도 없다.
5. 출처 행이 「{요청자}가 보낸 업무」 + 요청 링크다.

**H. 요청자 쪽 — 수락된 요청 업무(관리 가능한 입구가 있다면)**
1. 머리에 `⋯` → 「취소 제안」 · 「조건 변경 제안」 → 각 작은 모달이 뜬다.
2. 제안을 보낸 뒤 → `⋯` 가 사라지고, 「취소/조건 변경 제안」 상자 안에 「제안 철회」.
3. 담당자 계정으로 같은 업무를 열면 → 그 상자에 「동의」·「동의하지 않음」이 있다.
4. 「보낸 업무」에서 열면 → 제목·내용·날짜가 글자뿐이고 `⋯`·셀렉트가 없다(읽기 전용).

**I. AX 제안에서 생긴 업무**
1. 내 업무에서 연다 → 출처 행 「AX 제안 · 판단 보기」. 「판단 보기」 → 판단 상세가 열린다.
2. 홈 또는 캘린더에서 연다 → 「AX 제안」 글자만 있고 링크가 없다.

**J. 마감 지난 업무**
1. 「마감일 초과」 빨간 배지가 **마감일 값 옆**에 있고, 머리에는 없다.

**K. 읽기 전용 입구**(「조직 업무」·「완료」 탭·채팅 카드 「업무 열기」·관계 그래프·요청/판단에서 따라 들어간 상세)
