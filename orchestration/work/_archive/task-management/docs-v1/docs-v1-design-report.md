### 0-B. `홈화면.dc.html` 이 워크트리에서 지워져 있다

`설정 · 프로필 관리`, `설정 · 목소리 등록`.
그리고 **홈·채팅은 md 00~15 어디에도 문서가 없다** (`00-README.md` §구성 표에 md 항목 없음).
→ **Q-27 · Q-37 · Q-38**

### 0-C. 사이드바가 8개 영역을 요구한다 — 패키지가 덮는 것은 6개

`디자인 시스템.dc.html [06 — COMPONENTS] Sidebar` · `홈화면.dc.html [홈화면]` 의 사이드바:
**홈 · 채팅 · 캘린더 · 내 업무 · 회의록 · 자료함 · 메시지 · 설정** (8개, 200px 고정, active = Ink pill).

`00-README.md` L3 이 밝힌 패키지 범위는 **내 업무 · 로그인/개인 설정 · 회의록 · 캘린더 · 문서함 · 메시지함**
6개. 즉 **홈 · 채팅은 사이드바에 존재하지만 md 문서가 없다.**
`README.md` L7(제품 지도)도 「홈 · 채팅 · 캘린더 · 내 업무 · 회의록 · 자료함 · 메시지 · 설정」 8영역을 말한다.
범위(v1/v2) 판단은 하지 않는다 — 인벤토리에는 8영역 전부를 싣는다.

### 6-2. 진행 순서 제안 — 의존이 적은 것부터

의존 관계(사실):

- 회의록 줄 `task`/`action` → **업무 PATCH/POST** (`12-meeting-notes.md` §줄 종류와 서버 요청)
- 캘린더 생성·상세 → **업무 생성/상세 드로어 · 회의록 생성 드로어 재사용** (`13-calendar.md` §생성 흐름·§상세 흐름)
- 업무 참고자료 「자료 첨부 → 자료함 선택」 → **자료함** (`04-task-detail.md` §항목 추가)
- 회의록 첨부 「자료함에서 열기」·회의 중 md 는 `source=local` → **자료함** (`12-meeting-notes.md` §첨부 파일)
- 메시지 「내 업무로 등록」·「일정으로 추가」 → **업무 · 캘린더** (`메시지함.dc.html [메시지]`)
- 메시지 수신 → **설정 · 연동 관리** (`11-auth-profile.md` L15 · `[설정 · 연동 관리]`)
- 홈 = 메시지·업무·일정의 **집계** (`홈화면.dc.html [홈화면]`)
- 채팅 = 업무 데이터 참조 + 문서 생성 → **업무 · 자료함** (`홈화면.dc.html [채팅 – 대화][채팅 – 문서 생성/첨부]`)

제안 순서:

```
0  공통 기반          토큰 · AppShell · 오버레이 3종 · PageHeader · PeriodStepper · 배지/dot
                      → 의존 0. 전부의 전제
1  내 업무            Task 가 다른 영역이 전부 참조하는 원자 도메인.
                      1280 반응형이 유일하게 그려진 영역이라 반응형 규약도 여기서 확정된다
1' 인증 · 설정         ← 1 과 병렬 가능(의존 거의 없음). 단 「연동 관리」는 5(메시지)의 선행
2  회의록             1 의 PATCH/POST 를 소비. 자체 난도가 가장 높으므로 1 다음
3  자료함(문서함)      1·2 의 첨부 대상. 반대로 1·2 는 「자료함에서 선택」만 하면 되므로
                      스텁으로 먼저 두고 여기서 실체화해도 된다
4  캘린더             1·2 의 드로어를 재사용 → 신규는 그리드(C-30~32)뿐. 늦게 할수록 싸진다
5  메시지             1(업무 생성) · 4(일정 추가) · 1'(연동 관리) 를 소비
6  홈                 1·4·5 의 집계 뷰. 앞이 다 서야 만들어진다
7  채팅               전 영역 참조 + AI 렌더 계약. md 문서부터 필요(Q-37)
```

**뒤집힐 수 있는 지점** — 3(자료함)을 2(회의록)보다 앞에 둘 수도 있다. 회의록 첨부가 자료함에 의존하기
때문이다. 다만 회의록 쪽 의존은 「자료함에서 고르는 드로어」 하나뿐이라(`12-meeting-notes.md` §첨부 파일)
스텁으로 미룰 수 있다고 보아 위 순서로 제안한다. **결정은 baseline 에서.**
