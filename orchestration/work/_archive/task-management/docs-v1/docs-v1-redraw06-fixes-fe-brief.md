## 1. 고칠 것

### G-0. 칸반 드래그가 아예 안 된다 — **동작 버그**

`KanbanBoard.tsx:122` 가 원인이다.

```jsx
{isDragging ? (
  <div className="h-24 ... 점선 플레이스홀더" />   // ← 카드를 통째로 대체한다
) : (
  <article {...dnd.dragProps(task)} onClick={...}>
```

**`onDragStart` 가 뜨는 순간 `isDragging=true` 가 되어 카드 `<article>` 이 언마운트된다.**
브라우저는 **드래그 소스 요소가 사라지면 드래그 세션을 중단**한다 — 그래서 카드만 없어지고 드롭이 성사되지 않는다.
사용자가 「클릭하면 카드가 사라진다」고 본 것이 이것이다(클릭이 아니라 살짝 끌린 순간 드래그가 시작됐다 죽는 것).

**고칠 것**
- **카드를 언마운트하지 마라.** 드래그 중에는 같은 `<article>` 을 유지하고 `opacity-40` 만 얹는다
- 시안 U-4 의 「원래 자리 플레이스홀더」는 **카드를 지우라는 뜻이 아니다** — 끌고 있는 동안 그 자리가 비어 보이지 않게 하라는 것이다. 카드를 흐리게 두면 그 역할을 그대로 한다
- **클릭 → 드로어는 정상 동작이다. 건드리지 마라.** 다만 드래그 직후에 클릭이 따라 발생하면 드로어가 잘못 열린다 — `onDragStart` 에서 플래그를 세우고 `onDragEnd` 직후의 `onClick` 한 번을 무시해라
- 드롭 대상 컬럼 하이라이트(`#F1F2FE` + `1px #7181F8`)와 드롭 불가 처리는 **이미 있다.** 그대로 둬라

**드래그는 「상태 변경 UI」다 — 순서를 저장하지 않는다** (2026-09-06 사용자 확정 · DEC-002)
> **업무는 서로 순서 관계가 없다.** 각자 상태를 가질 뿐이고 「A 다음에 B」가 도메인에 없다.
> 그래서 **「이 카드 뒤에」를 지원하지 않고 삽입 가이드선도 두지 않는다.** `order_index` 를 만들지 마라.
> 컬럼 안 정렬은 **정렬 드롭다운을 그대로 따른다.**

**화면이 보여줄 것은 「어느 상태로 보낼 수 있는가」다** — 시안 U-4 규격이 이미 그렇게 정해져 있다. 확인하고 빠진 것만 채워라.

| 상태 | 규격 |
|---|---|
| 끌고 있는 카드 | **`opacity-40`**(언마운트 금지 — 위 참조). 브라우저 기본 고스트를 쓰고 회전 효과 없음 |
| **놓을 수 있는 컬럼** | 배경 **`#F1F2FE`** + **`1px #7181F8`** 테두리 |
| **놓을 수 없는 컬럼** | 배경 그대로 + **불투명도 0.5** · 커서 `not-allowed` · **놓이지 않는다** |
| 놓은 직후 | 서버 응답까지 카드 **불투명도 0.6**(로딩). **낙관적으로 옮기지 않는다** |
| 완료 컬럼 | 드롭 가능으로 보인다 — **게이트 판정은 놓은 뒤 서버가 한다.** 미충족이면 **원래 컬럼으로 돌아가고** 거부 토스트 |

**전이 그래프가 막는 조합**(예: 완료 → 취소)이 「놓을 수 없는 컬럼」이다. 툴팁 「완료는 취소할 수 없습니다 · 먼저 진행중으로 되돌리세요」.

**검증** — `PORT=3100` 으로 띄우고 **실제로 카드를 다른 컬럼에 끌어다 놓아** 상태가 바뀌는 것을 확인해라.
> macOS 네이티브 드래그는 playwright 합성 이벤트가 잘 안 먹는다(WORK-005 에서 실패한 이력). **자동화가 안 되면 「자동 검증 불가」라고 보고하고 넘어가라** — 되는 척하지 마라. 사람이 확인한다.

### G-0b. 연관업무 블록 — 시안 규격

사용자가 시안을 지목했다. 지금과 대조해서 어긋난 것을 전수로 고쳐라.

**시안 (`업무 화면 정의서.dc.html` 새 업무 드로어 · 연관업무 자리)**
- 연결된 항목이 **행 카드**로 쌓인다 — 흰 배경 · border `#D9D9D9` · r8 · 좌측에 **유형 색 dot** + 제목
- 그 아래 **점선 「+ 업무 연결」 버튼** — `border 1px dashed #D9D9D9` · r8 · 가운데 정렬 · `#9EA2AE` · hover 시 배경 흰색 + `#1E1E1E`
- **비어 있을 때만** 「연결한 업무가 없습니다」 캡션. 항목이 있으면 캡션 없이 카드만
- **참고자료 블록도 같은 구조**다(좌측이 dot 대신 파일 유형 배지 `XLS`·`DOC`)

**지금 어긋난 것으로 보이는 자리** — 항목이 있어도 「+ 업무 연결」이 실선인지 점선인지, dot 이 있는지, 카드 규격이 맞는지 **직접 대조해서 판단해라.** 코디가 실측하지 않았다.

### G-0c. 자동 저장 실패 토스트가 **무엇이 틀렸는지 말하지 않는다**

지금 서버 422 는 전부 「**입력값을 확인해 주세요**」 하나로 뜬다. 사용자가 **어느 칸을 고쳐야 할지 모른다.**

**클라이언트가 먼저 잡는 것은 이미 구체적이다** — `DueDateField` 가 「시작일이 종료일보다 뒤일 수 없습니다」를 입력칸 아래 인라인으로 띄운다. **그건 그대로 둬라.**

**고칠 것은 서버 422 가 화면에 닿았을 때다.**
- SPEC-002 U-7 규격이 이미 있다 — 토스트 「**저장하지 못했습니다 · `<필드 이름>`**」 + 그 필드 테두리 `#E2685B` + 「저장되지 않았습니다 · 다시 저장」
- **자동 저장 경로의 422 는 이 규격을 타야 한다.** 지금은 `validation_error` 의 서버 문구(「입력값을 확인해 주세요」)를 그대로 토스트에 뿌린다
- **어느 필드가 실패했는지는 이미 안다** — 자동 저장은 필드 단위로 나간다(`useTaskFieldSave`). 그 필드 이름을 문구에 넣어라
- 일정 필드면 「저장하지 못했습니다 · **일정**」

> **참고 — 사용자가 본 422 는 이미 사라진 원인이다.** 옛 백엔드가 `startDate` 를 모르던 상태(`extra="forbid"`)였고 재시작으로 해결됐다. **그 자리를 고치는 게 아니라, 앞으로 어떤 422 든 필드를 짚어 주게 만드는 것이 이 항목이다.**
