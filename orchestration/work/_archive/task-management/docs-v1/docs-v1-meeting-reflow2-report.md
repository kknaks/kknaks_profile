## 5. 정정 — MF-66 푸터는 모드별 (2026-09-07 추가)

§3 ① 「취소 · 저장 · 넣기」 셋은 **폐기.** 사용자 판정 MF-66 — **편집 모드 = 「취소 · 저장」**(회의록을 고치는 자리 · `payload` 만 줄에 · 업무 없음) / **보기 모드 = 「취소 · 넣기」**(확인하고 바로 업무 생성·갱신). 모드마다 버튼 하나씩, 한 푸터에 셋을 두지 않는다. 고친 곳 — SPEC-008 U-6 머리 · U-9 · U-10 푸터 · S-6~S-9 푸터 문구 · §5 Flow · 구현 규칙(`submitMode:"save"|"insert"`) · AC 6건 · §7 두 행 · 정합 #1 / frontend README §2 규칙 8 `submitMode` / SPEC-003 U-1 · U-3 문단 `submitMode`(같은 prop 이라 함께). 다른 곳은 손대지 않았다.

**MF-66 최종 확정 반영 확인(2026-09-07)** — 앞의 두 메시지는 무시하고 최종 판정만 따랐다: 편집 모드 「취소 · 저장」(`payload` 만 줄에 · 업무 없음) / 보기 모드 「취소 · 넣기」(업무 생성·갱신), U-9 · U-10 둘 다 같다, 한 푸터에 셋 없음. SPEC-008 U-9 · U-10 푸터 · §5 Flow · 구현 규칙(`submitMode:"save"|"insert"`) · AC · frontend `submitMode` 는 이미 이 판정과 같아 그대로 두었고, **Case Matrix `invalid_status_transition` 행에 「보기 모드 넣기에서만 난다 — 편집 모드 저장은 업무를 안 건드린다」 한 구절을 더했다.** 다른 곳은 손대지 않았다.
