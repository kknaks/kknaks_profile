## 0. 왜 이 일을 하나

SPEC-006·007·008 을 시안 정본으로 재작성했는데, **시안에 그려져 있으나 기획(BASE-003)·정책(DEC-003)에 없는 기능이 계약으로 들어갔다.**

코디가 브리프에 「시안이 시각 정본」이라고만 쓰고 **「기획에 없는 기능은 만들지 마라」를 빠뜨린 것**이 원인이다.

**기획 BASE-003 §Raw 가 명시적으로 배제한 문장이 있다:**
> **「AI 제안은 필요 없다 — 회의 중 AI는 AI 탭만 채우면 된다.」**

## ⛔ 1. 원칙

**시안에 그려져 있어도 기획·정책에 없으면 계약에 담지 않는다.**
시안은 **시각 정본**이지 **기능 정본이 아니다.** 기능의 정본은 BASE-003 · DEC-003 이다.

**지우기만 한다. 새 기능을 만들지 마라.**

## 2. 지울 것 — 5건

### T-1. 시작 전 **AI 안건 생성** — SPEC-006

**기획에 없다.** BASE-003 이 「AI 제안은 필요 없다」로 배제했고, DEC-003 §1 In scope 에도 없다.

지울 것 (코디가 찾은 자리 — **전수로 다시 찾아라**):
- `POST /api/meetings/{id}/agendas/draft` — API 표 L393 · Request/Response L514 · Flow L608·L615
- **에러코드 `agenda_draft_failed`** — Case Matrix L567 · 근거 L573 · L657
- U-6 프롬프트의 「안건 초안 생성」 동작 L267
- **S006-OQ-23 · S006-OQ-25** — 「기획에 없어 제거」로 닫는다

**남길 것** — 프롬프트 바 자체는 **안건 입력창**으로 남는다(`POST /agendas` 로 1건 추가).
시안의 모드 칩 「새 안건 ▾」·전송 버튼·추천 안건 칩 3개·빈 상태 문구 「안건 초안을 만들어 줍니다」는 **AI 생성 전제이므로 함께 지운다.**
빈 상태 문구는 「**아래에 안건을 적어 주세요**」 류로 바꾸고 **그 자리를 §7 에 「코디가 정한 문구」로 표시**해라.

### T-2. **「되돌리기」** — SPEC-008

**기획에 없다.** BASE-003 §Raw 에 편집 이력 얘기가 없고, DEC-003 은 「편집은 덮어쓰기」다. 이력 표도 ERD 에 없다.

- 시안 L1883 의 「되돌리기」 버튼을 **계약에서 뺀다**(화면에 그리지 않는다)
- **S008-OQ-2** 를 「기획에 없어 제거」로 닫는다

### T-3. **상태 바 파형** — SPEC-007

**기획에 없다.** 오디오 분석(`AnalyserNode`)이 FE §8 캡처 경로에 없고, 같은 상태 바가 화면마다 있고 없다.

- 시안 L813~829 의 파형을 **계약에서 뺀다**
- 상태 바는 **문구만** 남긴다(「기록 중 · 경과 시간」)
- **S007-OQ-6** 를 「기획에 없어 제거」로 닫는다

### T-4. **취소된 회의** — SPEC-006

**기획에 없다.** 상태는 `scheduled | recording | generating | ended` 4종이고(DEC-003 §3 · §A-6), 취소는 그 집합에 없다.

- 시안 L120~127 의 취소 행(배지·취소선·회색)을 **계약에서 뺀다**
- **S006-OQ-1 · S006-OQ-2** 중 취소 관련분을 「기획에 없어 제거」로 닫는다
- **⚠ S006-OQ-2 의 「목록에서 녹음 중인 회의를 구분할 수 없다」는 별개 문제다** — 취소와 무관하니 **그 부분은 OQ 로 남겨라**

### T-5. **「내 목소리 등록됨」** — SPEC-006

**정책이 금지한다.** DEC-003 §2 L74 「참석자·발언자 이름 없음. **익명 화자 라벨(화자 1/2)까지만**」.

- 시안 L644 의 「MacBook Pro 마이크 · **내 목소리 등록됨**」에서 **뒷부분을 뺀다**. 장치명만 남긴다
- **S006-OQ-20** 을 「정책이 이미 답을 준다 — DEC-003 §2 L74」로 닫는다

## 3. 함께 닫을 것 — 근거가 이미 있는 OQ 2건

지우는 김에, **다른 문서에 답이 있는데 OQ 로 올라온 것**을 닫아라.

| OQ | 답이 있는 곳 |
|---|---|
| **S008-OQ-18** 회의 상세 드로어 그림 없음 | **DEC-005 §2 L41** — 「회의록이 소유하고 캘린더가 재사용한다(**업무 상세 드로어와 같은 구조**). 회의록은 **전체 페이지 + 상세 드로어 두 표면**을 제공」. **업무 상세 드로어(SPEC-003 U-3)와 회의록 전체 페이지 시안을 합치면 된다** — 새 그림이 필요 없다. SPEC-008 에 **U-n 으로 신설**하고 SPEC-009 L166·L282 가 가리키는 번호와 맞춰라(지금 U-8 을 가리키는데 U-8 은 연관업무 드로어다 — **번호가 어긋나 있다**) |

## 4. 지킬 것

1. **지우기만 한다.** 새 기능·새 화면을 만들지 마라(T-3 의 「회의 상세 드로어」만 예외 — **기존 두 문서를 합치는 것**이다)
2. **전수로 찾아라** — 위에 적은 줄 번호는 코디가 훑어본 것이고 **전부가 아니다.** API 표·Request/Response·Validation·Case Matrix·Flow·Acceptance·§8 근거표까지 다 본다
3. **지운 자리를 §7 에 남겨라** — 「T-x 로 제거. 근거: BASE-003 §Raw / DEC-003 §y」
4. **다른 것을 고치지 마라.** 남은 OQ 를 임의로 닫지 마라
5. **SPEC 3개만 고친다.** 정책서·기획서·ERD·디자인 원본을 건드리지 마라
6. **커밋·push 하지 마라**
