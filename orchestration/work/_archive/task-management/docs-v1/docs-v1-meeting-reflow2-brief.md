## ⛔ 고칠 것 셋

### 1. MF-64 — 「+ 액션 아이템」도 줄이 먼저 생긴다

```
지금 SPEC-008 U-10   「업무 생성과 줄 갱신은 한 요청 · 한 트랜잭션」
                    칩 진입 → POST …/lines { agendaId, kind:"task", newTask:{…} }
                    → 저장을 안 하면 줄도 안 생긴다

바꾼다              칩 넷이 **전부 같은 방식**이다

  [ + 논의 ]  [ + 결정 ]  [ + 연관 업무 ]  [ + 액션 아이템 ]

  넷 다 **줄이 먼저 생긴다.** 그다음 드로어가 뜬다
  드로어를 닫아도 줄은 남는다
```

**「+ 연관 업무」가 이미 그렇게 돼 있다**(줄 먼저 · 드로어 나중). 액션만 달랐다.

### 2. MF-65 — 드로어는 액션·업무 각각 하나. **payload 있고 없고가 전부**

```
지금 SPEC-008 U-9   payload 있는 줄(AI) → 「넣기」 모드
                   payload 없는 줄(사람) → **평소 그대로 자동 저장**
                   → 사실상 드로어가 두 개로 갈렸다

바꾼다             **하나다.**
  액션 줄  → 새 업무 드로어      (업무 탭 U-1 + 안건 셀렉터)
  업무 줄  → 업무 상세 드로어    (업무 탭 U-3 + 헤더 업무 셀렉터)

  AI 가 만든 줄     payload 가 차 있다 → 값이 채워진 채로 뜬다
  사람이 만든 줄     payload 가 비어 있다 → 사람이 채운다 → **그 값이 payload 가 된다**

  필드 같다 · 저장 경로 같다 · **둘 다 「넣기」다**

⛔ AI 것과 사람 것으로 드로어를 나누지 마라
⛔ 「AI 줄은 넣기 모드 · 사람 줄은 자동 저장」으로 가르지 마라
```

**헤더에 업무 셀렉터를 붙인다 — 앞 단계(후보 고르기)를 따로 두지 않는다**

```
┌─ 업무 상세 드로어 840 ──────────────────────────────┐
│  [ 캐스티 틱톡 검색 붙이기  ˅ ]   ← 누르면 후보 고르기 팝오버 │
│  [ 미팅·회의 ]  [ ● 후보 검증 프로젝트 ]            │
│                                                     │
│  일정   2026-09-07 ─ 2026-09-14                     │
│  상태   진행중                                       │
│  …                                                  │
├─────────────────────────────────────────────────────┤
│                               취소   [   넣기   ]   │
└─────────────────────────────────────────────────────┘

왜   지금 SPEC 은 「업무 연결」(후보 고르기)이 **사람이 적은 줄에만** 붙어 있다
     → **AI 가 엉뚱한 업무를 골랐을 때 바꿀 길이 없다**

후   헤더 제목 자리가 셀렉터다. 둘 다 여기서 바꾼다
     사람이 적은 줄은 비어 있으니 여기서 고른다 — 앞 단계가 사라진다
     팝오버는 업무 화면의 `RelationPopover` 그대로다(이미 있다 —
     `features/tasks/components/RelationPopover.tsx`, 업무 상세·새 업무 드로어가 쓴다)
```

### 3. **payload 저장과 업무 생성을 가른다**

```
지금        드로어 저장 = 업무 생성 (한 요청)
            → 편집에서 액션을 추가하면 **바로 업무가 생긴다**

사용자 확정   편집에서 액션을 추가하면 **payload 를 만드는 것**이지 업무를 만드는 게 아니다

  [+ 액션 아이템]
    → 줄이 생긴다                    (MF-64)
    → 드로어에서 사람이 채운다
    → 저장하면 **payload 가 줄에 붙는다.** 업무는 아직 없다
    → **「넣기」를 눌러야 업무가 생긴다**   (MF-59)

→ AI 가 채운 줄과 사람이 채운 줄이 **완전히 같은 상태**가 된다.
  둘 다 「payload 를 가진 줄」이고, 「넣기」가 그것을 업무로 만든다
```

**이게 MF-59 의 원래 뜻이다** — 「최종 회의록의 액션·업무 줄에 **DB 에 바로 넣을 페이로드**를 담는다」.
페이로드는 **줄에 붙는 데이터**이고, 업무는 **넣기를 눌러야** 생긴다.
