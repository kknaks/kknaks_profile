## 이번 묶음의 구획 분할·범위 추적 계약

1. 구조를 실제로 확인한 뒤 문맥을 유지하는 상위 객체·카테고리·항목 구획을 정한다. 작은 원장은 구획1개도 가능하다. 큰 원장은 한 번의 화면 출력·한 번의 분석으로 전부 읽으려 하지 말고 구획별로 순차 읽는다. 문자 수·토큰 예산만으로 문장 중간을 자르지 않는다. 긴 값도 나눌 때 전체 값과 앞뒤 문맥을 참조하게 한다.
2. 자기 결과 폴더에 `coverage.json`을 만든다. 구획 ID, 원문 Pointer 범위/실제 말단 Pointer 집합, 상위 문맥 참조, 직접 읽은 상태, 대응하는 review 파일/절을 기록한다. 기계 추출과 직접 읽기를 구분한다. 아직 안 읽은 구획을 완료로 쓰지 않는다.
3. 모든 원문 말단 값(및 빈 컨테이너)을 어느 구획이 담당하는지 대응시킨다. 공동 참조하는 상위 메타데이터·문맥과 구획이 실제로 소유한 값은 구분한다. verify.py에 전체 원문 경로 집합과 구획별 소유 경로 합집합의 양방향 대조, 누락·불필요 중복 검사, 구획별 상태·결과 파일 실재를 넣는다. 개수만 맞춰 통과시키지 않는다.
4. 구획 하나를 읽을 때마다 관찰·수동 표현·미결을 그 구획에 남긴다. 문맥 압축/세션 재개가 필요해도 마지막으로 읽은 위치와 남은 구획을 파일에서 찾을 수 있어야 한다.
5. 출력이 길면 review.md는 상태·전체 컬럼 구성·구획 목차를 갖고, 모든 값은 `review-part-*.md`에 나눠 실을 수 있다. 각 구획에 원본 컬럼명·자료형·원문 값·Pointer·잠정 관찰 분리를 유지한다. 전체 구획이 탐색 가능해야 하며 표본만 보여주지 않는다. verify.py는 분할된 문서도 대조해야 한다.
6. 입력이 커도 원장 전체가 이번 대상이다. 일부 구획만 수행했으면 부분 진행으로 보고한다. 새 서브에이전트는 띄우지 않는다. 원장 전체 수집 기준을 채우면 알려진 분석 한계·의미 과제를 기록하고 1차를 종료한다. 완벽한 형태소 정답·최종 의미 확정을 위해 반복하지 않는다.
7. 미결 문자의 뜻은 통일한다: A=에이전트 추출/해석 오류, B=원문 정보 부족, C=현재 사용자 결정 필요. 알려진 분석 한계 K·잠정 P·후속 F·원문 불일치 I는 보조 상태로 구분 가능하다. 원문 내 불일치를 C라고 부르지 않는다. 원본 변경 제안은 현재 원본 보존 지시 아래 후속 확인 후보이며 지금 선택 대기로 올리지 않는다. 사용자 결정0은 잔여 항목 처리 상태·영향 검토 후에만 표시한다.

## 6. 수행 단계

1. 원본 해시·크기와 전체 구조·값 대응 범위를 고정한다.
2. 전체 원문을 위에서 아래로 구획별 직접 읽고, 구조·값·문맥을 수집한다.
3. 전체 텍스트 형태소 분석과 문맥 포함 복합 표현 수집을 수행한다. 자동 처리와 직접 읽기 범위를 정확히 구분한다.
4. 원문 누락·중복·포인터·문자구간·해시·적용/제외 대응을 검증한다. 별도 읽기 검토로 수식·조건·부정·오분절 영향을 확인한다.
5. 에이전트가 해결할 실제 추출 오류는 고친다. 원문 부족, 잠정 해석, 후속 의미 조사, 실제 사용자 결정 필요를 구분한다. 도구 선택 같은 에이전트 판단을 사용자 결정으로 넘기지 않는다.
6. 1차 수집 기준을 충족하면 종료하고 코디에 보고한다. 최종 의미 해석이나 모든 형태소 정답을 얻기 위해 반복하지 않는다. 알려진 오류의 위치·영향·한계를 남기고 후속 과제로 구분한다. 새로운 누락·오류가 있으면 그 부분만 수정·재검증한다.

원본·기존 작업 수정/삭제·복구·다른 원장 조사·공통 문서 갱신·추가 에이전트·커밋·push·PR·Git clean/reset/checkout 금지. 임상·법적 사실을 승인하거나 외부 자료로 보충하지 않는다. 원문에 없는 단위·백분율·뜻·적용 부위를 채우지 않는다. 선택을 받지 않은 해석을 확정 데이터로 쓰지 않는다. 원문 보존만으로 미결을 닫지 않는다.

## 8. 검증·완료 보고

원본 해시 시작/끝 불변, 원문 구조·값 양방향 대응, Pointer·구간 원문 재현, 중복/누락 검사, 분석 적용·제외 대응을 실제 검증하고 명령·결과를 validation.md에 남긴다. verify.py는 원본과 결과를 읽고 실패 시 nonzero로 종료하며 다른 파일을 수정하지 않게 만든다. 코디가 레포 루트에서 `python3 orchestration/work/phub-ledger-redesign/first-pass/combo-recipes/verify.py`로 재실행할 수 있어야 한다.

## 9. 완료 보고 — **문구 변경 금지**

> **⚠ 핸들은 dispatch preamble 의 값을 믿어라.** 아래 명령에 박힌 코디handle 은 **브리프 작성 시점** 값이라 오래됐을 수 있다 — 세션이 재연결되면 핸들이 바뀐다(2026-07-28·29 두 번 겪음). preamble 의 코디네이터 핸들과 아래 값이 다르면 **preamble 이 맞다.** 두 곳에 다 보내지 말고 preamble 쪽으로만 보내라.


- **커밋·push·PR 하지 마라.** 워크트리에 변경만 남긴다. 검증·PR 은 코디네이터가 한다.
- 끝나면 **아래 두 명령을 모두** 실행한다. 하나만 하면 안 된다.

```bash
# (1) 인박스 적재 — 태스크 완료 처리·영구 기록. 코디네이터를 깨우지 않는다.
orca orchestration send \
  --to term_9817d7e4-b067-40b3-9235-c8dcddad8f26 --from <라이브 preamble의 워커 handle> \
  --type worker_done \
  --task-id <이 태스크의 taskId — dispatch 로 받은 context 에 들어 있다> \
  --dispatch-id <이 태스크의 dispatchId — dispatch 로 받은 context 에 들어 있다> \
  --subject "researcher 완료: <한 줄>" \
  --body "변경 파일 목록 / 구현 요약 / 검증 결과(수치) / 계약 준수 / 미결·주의점"

# (2) 직접 주입 — 코디네이터 세션에 유저 메시지로 꽂혀 자동으로 깨운다.
orca terminal send --terminal term_9817d7e4-b067-40b3-9235-c8dcddad8f26 \
  --text "[worker_done] researcher 완료 — <한 줄 요약>. 상세는 인박스." --enter
```
