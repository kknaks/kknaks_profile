# pih-risk.json — 미결·한계 기록 (1차)

미결 문자: **A**=에이전트 추출/해석 오류 · **B**=원문 정보 부족 · **C**=현재 사용자 결정 필요.
보조 상태: **K**=알려진 분석 한계 · **P**=잠정 관찰 · **F**=후속 의미 조사 · **I**=원문 내 불일치.
원문 내 불일치(I)는 C 가 아니다. 원본 변경 제안은 현재 원본 보존 지시 아래 **후속 확인 후보**일 뿐 선택 대기로 올리지 않았다.

## A — 에이전트 추출/해석 오류

### A1 (추출 오류 아님 — 작업 중 사고 기록)
- 표시용 보조 명령(`cat > $TMPDIR/show.py`)이 표준입력을 기다리다 시간 초과됨. 정리하려고 `pkill -f cat -u <사용자>` 를 실행했다 — **같은 사용자의 다른 `cat` 프로세스가 있었다면 함께 종료됐을 수 있다**(확인 불가). 원본·결과 파일 영향 없음. 보조 스크립트는 스크래치에서 다시 만들어 사용.
- verify.py 초기판이 변이 시험 M4 에서 예외 종료(StopIteration) — 가드 추가로 보완(validation.md §3).
- 추출 데이터 오류: verify.py 기준 **0** (Pointer·구간·값·소유·적용/제외). 잔여 0.

## B — 원문 정보 부족

### B1 비율의 분모·관찰 기간·출처·기준 집단의 행 단위 적용
- 원문: `/description` "Fitzpatrick skin type III-IV (한국인 대다수)를 기준으로 작성", `/risk_levels/*`, 26개 `/procedures/{i}/pih_rate`
- 부족: % 가 환자당·회차당·누적 중 무엇인지, 관찰 기간, 출처(문헌·근거 칸 없음). 13번 note 는 'Fitzpatrick I-III에 최적' 으로 기준 집단과 다른 범위를 말한다 — 행 단위로 어느 피부형 기준 수치인지 표기 없음.
- 제한: 발생률로 바꿔 쓰기·행 간 수치 비교·근거 수준 표시가 불가. 보고 사건 구성비 등으로도 단정 못 함.

### B2 risk_levels 경계 포함/제외
- 원문: `/risk_levels/low` "1-5%" · `/moderate` "5-15%" · `/high` "15-30%" · `/very_high` "> 30%" · `/very_low` "< 1%"
- 부족: 5·15·30 이 인접 두 구간에 걸침. 끝점 포함 여부 없음.
- 제한: pih_rate 를 수치 구간으로 바꿔 등급을 재계산·검증하는 규칙을 원문만으로 못 세운다(I1·I2 판정에도 영향).

### B3 기간의 기준 시점
- 원문: `/procedures/1/prevention` "4주 이상", `/procedures/4/prevention` "SPF 50+ 3개월 이상", `/procedures/5/prevention` "2개월 이상", `/procedures/22/prevention` "4주 이상", `/procedures/24/prevention` "2개월 이상"
- 부족: 시술 후부터인지 등 시작 시점이 없다. (간격 '시술 간격 2-4주'·'4주 이상' 은 시술 사이 간격으로 원문이 명시.)
- 제한: 관리 타임라인(시점 축)에 배치 불가.

### B4 수치 기준 없는 정도어
- 원문(출현은 expressions.json status B): '과도한'·'높은'·'적정'·'적절한' fluence/에너지/농도/깊이(0,1,2,3,5,7,8,9,11~14,16,18,19,21,22,23 번 등), '깊은 ablation(depth)'(4,5), '짧은 펄스폭'(9,12), '짧은 간격 반복'(2,7), '다층 도포'·'최소 레이어 수'(25), '에너지 조절'(19), 'Fitzpatrick IV에서 주의'(14)
- 기준이 있는 예외: '짧은 시술 간격(2주 미만)'(0), '깊은 니들 깊이(1.5mm+)'(20), '높은 TCA 농도(35%+)'(24), '긴 파장 필터(590nm+)'(9), '어두운 피부(IV+)'(13) — 해당 행에만 적용. 다른 행으로 옮기지 않는다.
- 제한: 세팅 조건을 수치 속성으로 정규화 불가. 수식어+대상으로만 보존 가능.

### B5 '필요 시' 기준과 전처치 정보
- 원문: `/procedures/4/prevention` "필요 시 hydroquinone 전처치"(기간 없음), `/procedures/5/prevention` "필요 시 전처치"(약제·기간 없음), `/procedures/24/prevention` "필요 시 hydroquinone 전처치 4주"
- 제한: 전처치 조건·약제·기간을 4·5번에 채울 수 없다.

### B6 17번 위험도의 사용 방식 기준
- 원문: `/procedures/17/pih_risk` "low", `/pih_rate` "1-5%", `/fitzpatrick_note` "RF 자체는 안전하나, IPL/다이오드 복합 사용 시 PIH 가능"
- 제한: 값이 RF 단독/광에너지 병합 중 어느 조건의 위험도인지 연결 불가.

### B7 23번 BHA 기준 농도
- 원문: `/procedures/23/name` "AHA/BHA 필링 (표재성)", `/fitzpatrick_note` "… 글리콜산 30-50% 기준"
- 제한: BHA 쪽 조건 없음.

### B8 '어두운 피부' 의 기준
- 원문: risk_factors '어두운 피부' 14 출현 + '532nm 사용 시 어두운 피부'(11), '어두운 피부(IV+)'(13 — 유일한 기준 표기)
- 제한: 기준 집단(III-IV) 안에서의 상대 기준이 없음. 13번 기준을 일반화하지 않는다.

## C — 사용자 결정 필요: 0

**C 0 의 근거(잔여 항목 처리 상태·영향 검토 후):**
- B1~B8 은 사실 부족이다. 사용자에게 추측으로 정하게 하지 않는다 → C 아님.
- I1~I3 은 원문 내 불일치다. 어느 쪽이 맞는지는 원본 확인(후속) 사안이며, 1차 수집은 두 값을 그대로 보존해 끝난다 → 지금 선택 대기 아님.
- F1~F7 은 전체 원장 비교·공통 모델 단계의 의미 조사다. 지금 사용자 선택이 1차 수집 범위를 바꾸지 않는다.
- 도구 선택(Kiwi cong·사용자 사전 미사용·제외 정책)은 에이전트 판단으로 기록했다(morphology.json analyzer·policy).
- 영향: C 0 이 「미결 없음」을 뜻하지 않는다. B·I·P·F·K 가 모두 열려 있다.

## I — 원문 내 불일치 (후속 확인 후보)

### I1 5번 등급 ↔ 비율
- `/procedures/5/pih_risk` "high"(=`/risk_levels/high` "15-30%") vs `/procedures/5/pih_rate` "10-20%". 하한 10 이 high 밖, moderate "5-15%" 와 겹침.

### I2 12번 등급 ↔ 비율 경계
- `/procedures/12/pih_risk` "very_low"(="< 1%") vs `/procedures/12/pih_rate` "~1%". 근사 1% 가 '< 1%' 경계·low 하한과 겹침. B2(경계 규칙) 확인 뒤 재판정.

### I3 notes M17 근거 강도
- `/notes/M17` "표피 손상 최소로 PIH 해당 없음" — '최소'(0 아님) 를 이유로 '해당 없음'. 다른 notes 는 '없어'·'작용하지 않으므로'.

나머지 24행의 pih_risk ↔ pih_rate 는 risk_levels 범위 안에 들어간다(0번 '~5%' 는 low 상한과 맞닿음 — B2). 대조표는 review.md §대조.

## P — 잠정 관찰 (묶음)

### P1 행 단위와 procedure_ref 깊이
- 같은 procedure_ref 를 여러 행이 공유: M8-1-1(0,1 — 에너지 세팅), M8-5(12,14), M11-1(18,19 — 바늘 종류), M13(21,22 — 온도). 깊이 혼재: M12(카테고리 수준, 20), M15-1(25) vs M15-1-1/1-2, M8-5 vs M8-5-3, M9-2-5(17, subcategory '복합 에너지') 가 M9-2(16, 'RF') 아래 코드 형태.
- 잠정: 행 = 시술+세팅/변형. procedure_ref 는 행의 정체가 아니다. 확정 안 함.

### P2 fitzpatrick_note 칸의 내용 범위
- 칸 이름은 피부형 주석이지만 기전(0번 '저에너지 반복 조사로 멜라닌 점진적 제거'), 장비 기술(8번 'FOCUS 렌즈 어레이'), 다른 행 비교(2·3·5·14·19번) 를 함께 담는다. 필드명으로 내용 종류를 단정하지 않는다.

## F — 후속 의미 조사

### F1 코드 연결
- `/notes` 키 M1_to_M7·M10·M16·M17, procedures category·procedure_ref 를 다른 원장(taxonomy 등)과 잇는 일. 이 원장 안에서 M14 는 나오지 않는다. 다른 원장은 열지 않았다.

### F2 기호의 뜻
- '/' (장비명 병기·대안: 엑셀브이/더마브이, 써마지/올리지오, IPL/다이오드, 더마롤러/더마펜, 열플라즈마/플렉서, AHA/BHA, HIFES/EMS, 도포/주사, density/coverage, DCD/contact cooling, 색소/토닝)
- '+' (파장 결합 1550+1927nm·532+1064nm, 모달리티 결합 RF + IPL/다이오드, 이유 결합 '비박리성 + 피코초', **이상** SPF 50+·590nm+·1.5mm+·35%+·IV+)
- '-' (범위 1-5%·III-IV·중간-심층, 구분 '니들RF - 절연침'), '~' (근사 ~5%, 범위 비박리~얕은 박리)
- README 작성 규칙은 참고만 — 기호만으로 의미 관계를 확정하지 않는다.

### F3 행 간 비교·대안 지칭
- 2 'QS 대비'(0/1 중 불명) · 3 '1064nm 대비'·'1064nm 우선 고려' · 4 '비박리성 대안 고려' · 5 'CO2 대비' · 13 '1064nm Nd:YAG 우선'·'IV에서는 1064nm 권장' · 14 '1064nm 대비' · 18 risk '비절연 니들 사용 시' · 19 '절연침 대비'·'절연침 우선'. 11번 '1064nm 위주'·'532nm 최소화' 는 같은 장비 안 파장 선택으로 보임(구분 필요).

### F4 조건의 적용 범위
- 4번 prevention 둘째 문장 '사용 시' 가 뒤 세 조치에 모두 걸리는지. 23번 '글리콜산 30-50% 기준' 이 행 전체(pih_rate 포함)의 조건인지.

### F5 원인·선후 사슬과 생략 대상
- 10 '자반(purpura) 후 PIH 가능' + '자반 유발 세팅(…)' + '비자반성 세팅 우선'. 16 '과도한 에너지로 인한 표피 화상 시 이차적 PIH'. 15 risk '… 사용 시 드물게 가능'(가능한 대상 생략). 17 risk '광에너지(IPL/다이오드) 병합 시'(결과 생략).

### F6 같은 기호·수치의 다른 대상
- '%' = 위험 비율(pih_rate·risk_levels) vs 약제 농도(23·24). '1.5mm' = 카트리지(15) vs 니들 깊이(20). '빈도' = 시술 반복 빈도(20 '과도한 시술 빈도'). '부위' = 손상 자리(21) — 해부 부위 아님.

### F7 이름 정체
- name_candidate facet 표현 46 개(괄호 예시 '등' 포함 15·18), notes 의 M1~M7 이름. 시술·장비·기법·계열 구분은 후속.

## K — 알려진 분석 한계

### K1 형태소 오분절 (미교정)
- 51 출현을 구획별로 기록(morphology.json `segmentation_review.occurrences`, 각 review-part §4). 심각: '고에너지'(6, 길이 0 토큰 + 이/VCP 고/EC), '자반 유발'(10, 자/IC 반 유 발), '비의존적'(16, 비/NNG), '더마롤러'(20), '니들 깊이'(20), '박리(성)' 10 출현, '깊이'→MAG(15·20·25), 부등호 '<'·'>' → 괄호 태그, 범위 '1-5' → W_SERIAL, '~'(근사/범위 동일 SO), '+'(이상) SW 분리.
- 같은 말의 칸별 분절 불일치(피코초·저에너지·절연침·전처치·비교적·필링). 동형이의어 '조사'(照射) 구분 없음.
- 기록 범위: 원문 직접 읽기에서 눈에 띈 전문어·수식·부정·비교·범위 관련 출현. 그 밖 토큰의 정확성은 보장하지 않는다.

### K2 field_name 분석
- 15 종 영문 snake_case 키는 Kiwi 가 SL/SW 로만 쪼갠다. 한국어 의미 분석 정보 없음. 역할(스키마 키)만 기록. notes·risk_levels 키는 식별자/열거 코드로 제외(사유 morphology.json policy).

### K3 정규식 보조 후보
- 수량·단위·범위 regex 후보 107 개 전부 수동 표현 구간에 포함됨(covered_by_manual). 정규식은 탐색 보조이며 의미 판정이 아니다.
