# 원장 1차 조사

## 적용 범위와 시작 조건

[재개 노트](../_RESUME.md)의 현재 지시·결정·진행 상태를 먼저 확인한다. 이 스킬 작성이나 열람은 조사 실행 허가가 아니다. 사용자 진행 지시 후 지정한 원장 단위로 수행한다.

승인된 병렬 방식은 **한 워커 = 한 원장 전체 + 자기 결과 폴더**다. 워커는 추가 서브에이전트를 띄우지 않는다. 공통 스킬·재개 노트·다른 워커의 결과는 수정하지 않는다. 종료 후 세션 정리는 코디가 관리한다.

원장 3판은 작업 디렉토리 기준 `../phub-recommend/bronze/phub-ledger/`에 있다. 원본과 기존 작업 폴더는 읽기 전용으로 취급한다. 결과는 새 작업 디렉토리 안에만 작성한다. 기존 결과의 삭제·덮어쓰기가 필요하면 정확한 경로와 영향을 제시하고 확인받는다. 복구나 이전 산출물 재사용을 선행 조건으로 삼지 않는다.

## 1차 조사의 목적과 경계

실제 원장에 어떤 구조·값·표현이 있는지 빠짐없이 수집한다. 단어 목록뿐 아니라 원문과 문맥을 보존해 이후 의미 조사·공통 의미 모델·ERD 설계의 근거를 만든다.

- 1차에서 확정하는 연결은 **추출 기록 ↔ 원문 위치·문맥**이다.
- 원문에 이미 있는 ID·참조·계층은 원장의 구조적 사실로 기록한다. 그 관계가 의미적으로 옳다고 승인하지 않는다.
- 정보 종류·수식 대상·관계에 대한 관찰은 근거를 붙인 잠정 해석으로 별도 기록한다. 관찰이 없다고 의미가 없다는 뜻은 아니다.
- 부위·시술 등의 공통 개념 ID를 부여하거나 동의어 병합·상하 관계·관계 방향·적용 조건을 확정하지 않는다. 품사·필드명·문자열 유사성만으로 의미 분류하지 않는다.
- 부위 체계·시술 목록·실버 스키마를 미리 가정하지 않는다. 1차 수집 종료는 전체 의미 조사 또는 정규화 완료가 아니다.
- 의미 분해·공통 개념 식별·관계 확정은 전체 원장 수집 뒤 비교·설계 단계의 과제다. 1차 수집·검토 기준을 충족하면 이 과제를 남긴 채 다음 원장으로 넘어간다.

## 수행 순서

### 1. 원본과 조사 범위 고정

파일 경로·크기·해시를 기록하고 전체 JSON 구조를 열거한다. 객체의 키, 자료형, 계층, 배열 순서·길이, 모든 말단 값, 빈 객체·빈 배열·빈 문자열·null도 포함한다. 필드명의 출현 위치도 남긴다. 문자열 외의 숫자·불리언을 버리지 않는다.

JSON 파서가 중복 키를 조용히 덮어쓰지 않도록 감지한다. 파싱 실패·중복 키가 있으면 원본을 수정하지 말고 위치와 영향을 기록한다. 중복 키 등으로 JSON Pointer만으로 위치를 식별할 수 없으면 원본 파일 구간과 출현 순서를 추가한다.

### 2. 원장 전체를 문맥과 함께 읽기

상위 항목에서 내부 값까지 순서대로 읽는다. 긴 원장은 상위 문맥을 유지한 구획으로 나누고 각 구획의 읽기 범위를 기록한다. 표본·이름·설명만 읽고 나머지를 자동 처리하지 않는다. taxonomy의 모든 계층·항목·products·problem, extracted의 기전·적응증·안전·시간·관리 문구도 동일하게 취급한다.

각 값에 원문 그대로의 내용, JSON Pointer, 상위 항목 위치, 함께 해석할 주변 필드·문장을 연결한다. 같은 문자열이 반복돼도 각 출현 위치를 유지한다. 경로 목록 생성만으로 읽음 처리하지 않는다.

### 3. 전체 텍스트의 형태소 분석

텍스트 값과 필드명에 형태소 분석을 적용하되 둘의 역할은 구분한다. 비언어적 식별자·URL 등 분석이 부적합한 문자열은 원문을 보존하고 제외 사유를 기록한다. 누락을 숨기지 않는다.

- 원문 표면형·기본형·품사·원문 내 문자구간·원문 기록 ID를 남긴다. 형용사·부사·조사·어미·부정 표현을 불용어로 제거하지 않는다.
- 분석기 이름·버전·사전·사용자 사전·분석 옵션·품사 체계를 기록한다. 분석기 선택은 실행 시 결정하고 기록하며, 이 스킬은 특정 도구를 전제하지 않는다.
- 분석기가 기본형·구간 등을 제공하지 않으면 지원하지 않는 값을 만들어 채우지 않는다. 미제공 상태와 보완 방법을 명시한다.
- 원문 정규화가 필요하면 정규화 전후 대응을 남긴다. 분석기 오프셋과 원문 오프셋을 혼동하지 않는다.
- 문자구간은 기준 문자열과 단위, 시작 포함·끝 제외 여부를 명시한다. 권장 기준은 디코딩된 원문 문자열의 Unicode 코드 포인트 인덱스 `[start,end)`이다. 파일 바이트 위치와 구분한다.
- 전문용어·혼합 언어·숫자·단위·기호의 오분절과 미등록어를 원문 읽기와 대조해 기록한다. 형태소 기본형은 도메인 개념의 표준명이 아니다.
- 알려진 형태소 분석 오류는 출현 위치(Pointer·구간)·원시 토큰·영향을 표시하거나 구조화해 기록하고 한계로 명시한다. 모든 토큰의 정답이나 최종 의미 해석을 얻으려고 같은 원장을 반복 조사하지 않는다.

### 4. 복합 표현과 문맥 보존

형태소를 넘어 함께 다뤄야 할 구절을 원문 구간으로 수집한다. 시술명·제품명처럼 보이는 표현, 부위 표현, 수량·단위·시간, 수식·조건·부정·가능성·범위가 있는 구절을 살핀다. 이 명칭들은 탐색 관점이며 확정 분류표가 아니다. 어느 범주에도 안 맞는 표현도 버리지 않는다.

예컨대 `드물게 눈꺼풀 처짐이 발생할 수 있다`는 형태소와 함께 전체 문장 및 필요한 겹치는 구절을 보존한다. 이 예시는 원장 실측 내용이 아니다. `드물게`를 백분율로 바꾸거나 `얕은`을 mm로 바꾸지 않는다.

복합 표현·문장 구간은 겹칠 수 있다. 의도된 겹침과 중복 생성 오류를 구분한다. 후보 추출에 정규식·키워드를 썼다면 방법을 밝히고, 결과를 전수 의미 해석으로 표현하지 않는다.

### 5. 구획별 검토와 미결 정리

원문을 읽으며 구조·값·형태소·복합 표현 기록을 대조한다. 누락·잘못된 Pointer·잘못된 구간·원문 변형 같은 실제 추출 오류는 에이전트가 해결한다. 형태소 분석기의 오분절은 3단계 기준대로 기록하고 한계로 남길 수 있다. 원문 부족은 무엇이 부족하고 이후 어떤 판단이 제한되는지 기록한다. 후속 의미 조사에서 판단할 항목은 그 상태로 남기고 해결된 것으로 세지 않는다.

사용자 결정이 필요하면 원문·위치·이유·추천·선택지·영향·적용 범위를 제시한다. 같은 원인은 묶고 결정과 예외를 재사용한다. 자료 부족을 사용자 추측으로 채우지 않는다. 선택 대기·선택됨·반영됨·재검증됨을 구분한다. 선택 UI가 필요하면 실제 표시·선택·응답 전달을 작은 예제로 확인한다.

### 6. 원장 전체 검증과 상태 보고

기계 검증으로 원본 해시 불변, 전체 구조·값의 대응 누락·중복, 포인터 유효성, 원문 구간 재현, 형태소 분석 적용·제외 내역을 확인한다. 단순 개수 일치만으로 누락 없음을 판정하지 않는다.

별도 읽기 검토로 모든 구획의 문맥 보존, 복합 표현·수식·조건·부정의 탈락, 분석 오류와 잠정 해석의 근거를 다시 확인한다. 1차에서 검토하지 않은 의미 관계는 미검토로 표시한다. 기계 통과를 의미 정답으로 주장하지 않는다.

## 산출물 계약

원장별 읽기용 Markdown과 기계 처리 가능한 구조화 기록을 만든다. 실행 전 실제 파일 경로·형식을 정하고 기록한다. 새 형식을 계속 추가하기보다 아래 대응이 유지되는 최소 구성을 택한다.

- **원본·구조·값 기록:** 원본 식별·해시, 구조와 모든 출현 위치, 자료형·원문 값·문맥 참조.
- **형태소·표현 기록:** 출현별 원문 참조, 표면형·기본형·품사·문자구간, 복합 표현과 분석 설정·제외·오류 내역.
- **읽기용 조사 Markdown:** 조사한 구조·구획과 실제 원문 표현, 관찰·미확정 사항, 구조화 기록으로 가는 위치. 필드 목록·빈도표만으로 대신하지 않는다. 형식은 아래 「읽기용 결과 형식」을 따른다.
- **검토·미결 기록:** 전수 읽기 범위, 기계 검증 결과와 실행 근거, 별도 읽기 검토, 열린 문제와 영향·후속 단계. 원문 대응과 잠정 의미 판단을 구분한다.

### 읽기용 결과 형식

원본 컬럼명·자료형·원문 값·잠정 관찰을 서로 다른 칸으로 나눈다. 원문과 관찰을 한 칸에 섞지 않는다.

- **컬럼 구성 표:** 한 행에 필드/JSON 경로 패턴, 자료형과 배열/객체 중첩 구조, 실제 원문 예시와 그 위치(Pointer)를 보여준다. 값·구조의 형태가 다른 변형, 선택적 필드(일부 항목에만 있음), 빈 값(빈 문자열·빈 배열·빈 객체·null)도 각각 행으로 남긴다.
- **항목별 값:** 각 항목의 모든 값을 원본 컬럼명 그대로 붙여 보여준다(`moa_summary`를 `moa`로 줄이지 않는다). 배열은 원본 순서를 유지하고 각 값에 원문 Pointer를 붙인다.
- **잠정 관찰:** 원문 칸과 분리된 별도 칸이나 별도 절에 근거 위치와 함께 적는다.

## 종료 기준

**1차 범위 종료와 원장 전체 완료는 다르다.** 이 스킬이 다루는 것은 1차 범위 종료다.

모든 구조·내부 값에 원문 대응이 있고 전체 구획을 실제로 읽었으며, 전체 텍스트의 형태소 분석 또는 명시된 제외, 복합 표현(문맥·형용사·부사·부정·조건 포함) 수집과 원문 대조를 마치고, 기계 검증과 별도 읽기 검토를 통과해야 1차 범위를 종료할 수 있다. 단순 토큰·컬럼 목록으로 전수 읽기를 대체하지 않는다. 도구 미지원·추출 실패(누락·잘못된 Pointer·구간·원문 변형)로 필요한 기록이 빠졌다면 종료하지 않는다.

알려진 형태소 분석 오류가 3단계 기준대로 기록돼 있으면 그것만으로 종료를 막지 않는다. 열린 의미 과제·원문 부족·알려진 분석 오류는 종료 보고에 명시한다. 1차 범위를 종료하면 같은 원장을 반복 조사하지 않고 다음 원장으로 넘어간다. 새 누락·오류를 발견했거나 원장 간 비교에 필요할 때만 다시 확인한다.

상태를 `전수 읽기`, `구조·값 수집`, `형태소·표현 수집`, `기계 검증`, `읽기 검토`, `알려진 분석 오류`, `열린 미결`, `후속 의미 조사`로 나누어 보고하고, 맨 위에 `1차 범위 종료` 여부와 `원장 전체 완료 아님`을 따로 적는다. 미결이 남은 원장을 전체 완료라고 하지 않는다. 이후 의미 조사·공통 모델·실버 변환은 별도 단계다.
