## 6. 데이터 검사 제안(silver-check 규칙 꼴)

```text
R-CONCERN-REACH-1  (FAIL)
  모든 concern c 에 대해:
    reach(c) = ∪ { indication.target_code | target_table = procedure_case
                   · concern_code ∈ {c} ∪ descendants(c) }
    |reach(c)| ≥ 1  이거나  c ∈ concern_reach_exempt(사유 ∈ {먹는약, 바르는약, 시술행없음, 묶음})
  출력: 안 닿는 고민 코드 · 이름 · 제품 indication 수 · 원장 출처

R-CONCERN-REACH-2  (WARN)
  아래 고민이 0 이고 자기 행(케이스 · 제품 indication)도 0 인 고민 c 의
  가장 가까운 「케이스 닿는 윗고민」 이 대분류이면 경고
  (허브 upper=auto 가 대분류 전체를 물려받아 엉뚱한 진료항목을 낸다 — 지금 9 고민)

R-CONCERN-REACH-3  (WARN)
  제품 indication 의 concern c 에 대해, 그 제품의 case_product 케이스 가운데
  concern_site(c) 부위가 맞는 케이스가 있는데 c 가 그 케이스에 없으면 「붙일 후보」 로 보고
  (이번 (c) 의 ② 근거를 기계로 다시 찾는 규칙)
```

`concern_reach_exempt` 는 새 작은 표다(고민 코드 · 사유 · 원장 출처). D 묶음 7 이 첫 행들이 된다.

## 7. 셈 방법(다시 셀 때)

- 닿음 = silver `indication`(target_table = procedure_case) 의 concern_code 가 자기 또는 자손(`concern.parent_code` 나무)인 케이스가 1 이상.
- 「명동점_지금」 = 허브 18105 `concern-candidates?upper=auto&to_procedure=none` read_all → `reach == 케이스 직접` 행의 candidate_code → `$J items[].hub.case_codes` 와 겹치는 진료항목 수.
- 「명동점_붙인뒤」 의 셈은 판정마다 다르다. (b)는 합칠 곳의 reach ∪ 후보, (c)는 후보 케이스, (a)는 눈가주름 ∪ 눈가 처짐 reach 로 `$J` 진료항목을 센다.
- 부위 맞음(② 거름)은 「케이스 부위가 고민 부위의 조상이거나 자손」 이다. 고민 부위가 없으면 조직(멜라닌 · 혈관 · 근육 등)으로 손으로 걸렀다(예 포트와인 → 혈관 조직만 · 모낭 케이스 뺌).
