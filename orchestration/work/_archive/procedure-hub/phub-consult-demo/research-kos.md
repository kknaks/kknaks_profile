## 1. 받기

### 1-1. 어떻게 받았나

- 계정은 `~/.config/day/kos-test-account.env` 의 env 로만 실었다. 스크립트에는 env 이름만 있다(`fetch_kos_products.py:96-101`).
- 로그인은 1 번 했다(`:123-141`). 기기 제한에는 걸리지 않았다(401 `SignInLimitExceeded` 없음).
- 테넌트 목록의 `hospitalName` 은 **「세라미크의원 명동점 DEMO」** 와 **「세라미크의원 명동점」** 둘이었다. 「명동」 을 포함하고 DEMO 가 아닌 쪽은 하나뿐이라 그것을 골랐다(`:378-388`). 이름이 헷갈리지 않아 코디에게 묻지 않았다.
- 부른 API 는 로그인 · 테넌트 목록 · 가이드 §3 A ~ F(E 는 closed false · true 두 번) · 세션 목록 · 세션 해제뿐이다. 경로는 `:39-47` 에 고정돼 있다.
- 호출 사이는 0.35 초를 쉬었다(`:36`, `:60-86`). UA 끝에는 ` (product-json)` 을 붙였다(`:31-35`).
- 원응답은 레포 밖 세션 scratchpad 에만 두었다. JSON 은 그 원응답으로 다시 만들었다(`--from-raw` · 재호출 0).

### 1-4. 꼴을 옮기며 만난 것(가이드 §4 는 바꾸지 않았다)

- **옵션에는 `closed` 칸이 응답에 없다.** 그래서 493 개 모두 `null` 이다. 옵션 키는 `badges · compositions · count · deleted · description · displayChannels · frequentlyUsedOption · id · medicalService · medicineAndMachines · price · procedure · promotionConfigurations · title · translsMap · type` 이다. 옵션에는 `order` 도 없어서 옵션 정렬은 title 순이다.
- 수가 유형 가격의 `visitorType` 은 `{id, name}` 객체로 온다. 가이드 꼴은 문자열이라 `name` 을 넣었다(`:266-267`).
- 묶음 구성의 `price` 는 옵션 가격과 같은 객체다. 가이드 꼴은 숫자라 `price.amount.value` 를 넣었다.
- 구성 안 `medicineAndMachines[]` 의 꼴은 `{id, name}` 뿐이다(91 줄 · 고유 31). 약품인지 기기인지 가르는 칸이 없다. 그래서 같은 id 가 시술 항목 약품 · 기기에 있는지로 갈랐다. 31 개 모두 이미 들어 있는 id 라(약품 16 · 기기 15) 새로 더해진 것은 0 이다.
- 상품 단위 `medicineAndMachines`(236 줄 · 고유 73) · 옵션 단위(438 · 고유 70)는 가이드 규칙 밖이라 옮기지 않았다. 상품 단위에만 있는 이름은 **「수액」** 1 개다.
- 선불카드 칸은 응답 이름이 `balance` · `point` · `expirationDurationInDays` 다. 각각 `charge_balance` · `charge_point` · `expiration_days` 로 옮겼다.
- 시술 항목 300 은 단품 옵션에서 온 것 288 과 묶음 구성에서만 온 것 12 를 합친 수다. 구성의 `treatment_item_kos_id` 가 목록 안을 가리키게 하려고 구성 쪽 `medicalService` 도 모았다. 가이드 문구는 「옵션의 `medicalService`」 라서 이 합침이 맞는지 **정할 것** E-1 로 넘긴다.

## 3. 허브 gold 1차 대조(셈만)

- 허브 쪽은 로컬 PG `phub-medallion-pg` 를 SELECT 로만 읽었다.
