### P1-1 LLM 블록의 옵션 가격이 장부(`llm_user_message`)에 남는다 — JS6 「장부 가격 숫자 0」 과 충돌

- 고칠 방향(코디 판단 · 둘 중 하나).
  - (가) 스펙 JS6 에 「프롬프트 보관본(`llm_user_message`)은 LLM 블록의 사본이라 가격이 든다」 를 한 줄 더한다. 코드 고침 0 이고, 시험은 「`cart` · `rec` · `items` · `consult` 칸 가격 0」 으로 범위를 밝힌다.

  - 가격이 공개 홈페이지 값(`display_channels: HOMEPAGE`)이라면 (가)가 맞다고 본다.

### S-1 6 턴 — LLM return(t1)을 규칙 new 가 이겨 새 주제 t3
- 코드는 스펙대로다(`topics.decide`). 지금 주제 t2(기미)에 M1 을 더하면 A = 0, 이번 턴만으로는 B = 106 이고 되돌리기 표지는 없다. 그래서 TP3 4 자동 넘어감이 new 를 낸다. 후처리 TP11(같은 조건 주제 되돌림)은 t1 의 **저장 조건 {M1 · 입꼬리 · KR}**(좁혀진 뒤 — TP12)이 이번 턴 {M1} 과 「완전히 같지」 않아 걸리지 않는다. TP14 ② 「다르면 규칙」 이므로 LLM 의 유효한 `return t1` 은 버려진다.
- 원인(스펙): 규칙 return 의 문은 둘뿐이다. ① 되돌리기 표지 + 부분집합(TP3 2) ② 조건이 완전히 같음(TP11)이다. 「표지 없이 앞 주제의 일부 조건만 다시 말함」 은 규칙이 늘 new 로 본다. 표지가 없을 때 LLM `to` 가 들어올 문은 ⑤(조건 0 일 때)뿐이다.
- 고칠 방향(코디 · 사용자 판단 · 하나 고름).
  - (가) **TP14 ⑥ 예외**를 둔다. 규칙이 **자동 넘어감(TP3 4 · 표지 없음)**으로 new 를 냈고, LLM 이 return + 유효한 `to` 를 냈고, **이번 턴 조건이 그 `to` 주제의 저장 조건의 부분집합**이면 return 으로 간다(`to_from: llm` · TP6 은 부분집합이라 조건 더함이 변화 0). 표지 new(TP3 3)는 그대로 규칙이 이긴다. 시험: 6 턴 꼴(t1 = {M1 · 입꼬리 · KR}, 지금 t2 = {기미}, 말 = M1, LLM return t1 → t1), 반대 꼴(LLM new → 규칙 new 그대로).
  - (나) TP11 을 「이번 턴 조건 ⊆ 앞 주제 저장 조건이면 그 주제로」 로 넓힌다. LLM 없이도 같은 결과가 나지만, 넓은 말(「보톡스」)이 좁은 앞 주제로 끌려가는 쪽으로 치우친다.
  - (다) 그대로 둔다(넓은 새 주제가 맞다고 보는 경우). 그때는 R11 문구가 「다시」 를 쓰지 않게 블록 `topic_change` 에 「새 주제 · 비슷한 앞 주제 있음」 을 실는다.
  - 검수자 추천은 (가)다. 사용자 결정 「되돌림 대상은 LLM `to`」 · r6 P1-2 (가) 「조건 없는 되돌림 = LLM」 과 같은 결이고, 규칙이 막을 수 있는 오판(조건이 저장 조건 밖)은 그대로 막는다.

### S-2 5 턴 — 「같이 받아도 돼요?」 가 장바구니 쌍을 못 잡음
- 원인은 셋이고, 하나씩 겹쳐 있다.
  1. **이해 호출(pick)에 「같이」 = 장바구니라는 규칙이 없다.** 그래서 0.3 follow 가 앞 대상을 채워 M1 · CON-068 을 냈다(장부 kind follow). 그 결과 조건이 바뀌어 LS1(막은 칸 보톡스 · R8 대상)이 되었고, 0.4 재료가 M1 의 허브 pair 행 전부(322 KB)를 실었다.
  2. **LC5 덧붙이기로 장바구니 쌍 줄(PRC-001|PRC-001 · 재시술 간격 16 행)은 4 턴에만 실렸다.** 5 턴 블록에는 장바구니 · 쌍 줄이 없다(장부 `pairs: []`). 세션에는 4 턴 메시지가 남아 있지만, 5 턴 메시지 안의 0.4 pair 행이 훨씬 가깝고 크다.
  3. **R10 이 「LC9 재료로만」 이라 적었지만 대상을 정하지 않는다.** 모델은 0.4 재료의 pair 행(이것도 허브 원본)을 써서 「기미 시술 + 보톡스」 로 답했다. 지어낸 것은 없지만, 손님이 물은 장바구니 쌍은 빠졌다. R8(막은 조건을 말하고 바꿀지 묻기)을 안 한 것도 1 의 잘못 감지가 만든 LS1 이라 생긴 일이다.
- 고칠 방향(스펙 · 코드 순 · 코디 판단).
  - **pick 규칙 한 줄**: 시술을 말하지 않은 「같이 받아도 / 함께 / 동시에」 질문은 대상 0(장바구니 질문) · `topic.move = continue`. follow 로 앞 대상을 채우지 않게 한다. TP3 7 로 조건 · 목록이 그대로이고 LS 도 안 탄다.
  - **LC9 · LC5 예외**: 이번 턴 말에 같이 받기 표지(앱 낱말 — TP4 꼴 상수: 「같이」 · 「함께」 · 「동시에」)가 있고 장바구니 진료항목이 둘 이상이면, 그 턴 블록에 장바구니 줄 + 쌍 줄을 **다시** 싣는다(덧붙이기 예외).
  - **R10 문구**: 「시술 이름 없이 묻는 같이 받기는 장바구니 진료항목 쌍(블록 「같이 받기」 줄)으로 답한다. 장바구니 쌍이 같은 시술(a = b)이면 재시술 간격 행으로 답한다. 시술 이름을 말했으면 그 시술의 허브 pair 재료로 답한다」 로 나눈다.
  - 시험: 장바구니 둘 + 「같이 받아도 돼요?」 → 블록에 쌍 줄 다시 · 조건 칸 그대로 · LS 0. 실물 e2e(WP-7 · §9-2 「같이 받아도 돼?」(pair) 줄)에서 장바구니 쌍 행이 답 근거로 쓰였는지 장부로 본다.
