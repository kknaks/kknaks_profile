# SPEC-010 — 명동점 상담 화면 0.5

경로 접두어: `$W` = 이 폴더 · `$A` = clinic_chat 워크트리 `phub-consult-demo`(읽기만 · 구현은 여기에 이어서) · `$H` = PROCEDURE-HUB 워크트리 `phub-consult-demo`(읽기만) · `$J` = 매핑 JSON **v3**(`data/kos/myeongdong-mapping-20261120-v3.json` · sha256 `8f4e6393…`(0.3.0 — 고침 A-7 로 sites 만 넓힘 · items · products 값 같음 · 옛 `94b88022…` · `1af2216c…`) — 앱 워크트리 · 메인 로컬 같은 바이트 · git 무시 · v2 `-20261120.json` 은 남지만 안 씀).
「시안」 = `$W/design-consult-20261120.html` · 「시안 줄 N」 = 그 파일의 줄 번호.

줄마다 상태를 적었다.
- **결정** = `_RESUME` §2 에 행이 있다.
- **시안** = 시안에 그대로 있다(정본 1).

## 1. 목적 · 범위

### 1-1. 목적

0.4 화면은 「고민 → 허브 시술 리스트」 였다. 0.5 는 같은 대화 위에서 **명동점이 실제로 파는 진료항목**을 보여 준다. 근거 결정은 `_RESUME` §2 11-19 「목표 확인」 · 11-20 「매핑 JSON v2」 다.

- 의학 정보는 허브에서 온다.
- 병원 정보(진료항목 · 옵션 · 가격)는 `$J` 에서 온다.
- 둘을 잇는 끈은 케이스 코드 하나다.

### 5-2. 허브 호출 묶음

- 한 턴에서 같은 (도구, 인자) 는 한 번만 부른다. 쪽 넘김이 있는 도구(`concern-candidates` · `scope`)는 `HubRest.read_all` 로 끝까지 읽는다.
