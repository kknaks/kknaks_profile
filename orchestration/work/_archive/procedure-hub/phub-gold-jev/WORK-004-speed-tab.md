# WORK-004 — 속도 탭

## 목적

첫 탭 = 얼마나 **잘** 가져오나(정확도 · 지금 화면 그대로). **둘째 탭 = 얼마나 빨리 가져오나.** 가설: Jev 가 필요한 정보만 골라 LLM 에 넘기면(입력이 작아져 추론 · 쓰기가 줄어) C gold MCP 보다 빠르다.

## 새 열 `b_slim`(화면 이름 「B 선별」)

- ①~④ 는 B 와 **같은 코드**(경로 · 허브 폭 전부 읽기 · 깊이 · 틀린 말 검사) — 허브에서 **읽는 것은 줄이지 않는다**(원칙).
- **④' 선별(새)**: 읽은 폭을 **정보 묶음**으로 나눈다 — 묶음 목록은 결정론(gold 표 · 칸 기준)으로 고정: 후보 목록(이름 · 층) · 개요(profile overview · mechanism_text) · 원리(mechanism_name) · 효과(outcome) · 적응 부위(indication 부위 칸) · 제품 이름 · 같은 날 / 간격 / 순서(pair) · 부작용(adverse · detail) · 금기 · 회복 · 상품 · 패키지. 실제로 행이 있는 묶음만 후보.
- Jev **한 요청**: 묶음마다 Noul 「Is `bundles[i]` needed to answer `question`?」(instructions 영어 · state 는 질문 + 묶음 이름 · 한 줄 설명 · 행 수) — llms.txt §2 Noul fan-out. 문턱 = 기존 설정(yes 0.7 · 사이는 넘김 쪽 — 빠뜨림보다 넘김). 틀린 말 검사(gate)가 필수로 잡은 행(물은 범위의 금기 · 회피 등)은 점수와 무관하게 넘긴다.
- ⑤ LLM: **고른 묶음의 행만** 넣어 같은 답 프롬프트 · 같은 모델 · 같은 effort(low)로.
- 기록: `selection{bundles[]{name, rows, bytes, noul, sent}}` · LLM 입력 바이트 · 토큰 · 첫 글자 · 추론 여부 · 단계별 ms(선별 포함).
- runner `--columns` 에 `b_slim` 추가 · batch 에서도 고를 수 있게. 첫 탭 · 채점 · 답 키는 건드리지 않는다(b_slim 은 채점 대상 아님 — 이번 판은 속도만).

## 둘째 탭(화면)

- 탭 둘: 「정확도」(지금 화면) · 「속도」.
- 속도 탭: 질문 입력 / 세트 문항 → **B 선별 · C** 카드 나란히(체크로 B 전체도 켤 수 있음) · 답 스트리밍.
- 카드 머리: 전체 ms · 첫 글자 ms · 단계별 ms 막대(Jev · 허브 · 선별 · LLM) · LLM 입력 KB / 토큰 · 출력 토큰 · 추론 함/안 함 · 모델 · effort.
- B 선별 카드: 「넘긴 묶음 / 뺀 묶음」 표(묶음 · 행 수 · KB · Noul).
- 「세트 몇 문항 한꺼번에」: 고른 문항들을 차례로 돌려 표(문항 × 열: 전체 ms · 첫 글자 ms · 입력 KB · 출력 토큰) + 평균 · 중앙값.
- 문구는 지어 넣지 않는다(위에 적은 말 · 기존 화면 말만).
