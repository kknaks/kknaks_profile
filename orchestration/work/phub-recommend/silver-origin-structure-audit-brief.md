# 원장↔실버 의미·미정·메타데이터 조사 및 데이터 구조 재설계안

## 목표·사용자 최신 지시

사용자는 앱 코드 수정으로 원천 품질을 우회하지 말고 원장↔실버 문제 조사부터 진행하며 데이터 구조부터 다시 잡으라고 지시했다. **조사·구조 제안만** 수행한다. 앱/Hub 구현, projection 구현, 새 스펙 구현 발주는 보류 상태다. 기존 계획을 이번 조사의 전제로 강요하지 않는다.

## 시작점과 위치 확인

profile cwd는 이 브리프가 있는 orchestration의 상위 레포다. 먼저 루트 AGENTS 및 orchestration/roles/procedure-hub/researcher 문서와 문서 버킷 규약을 읽는다. 사용자가 지정한 reference/2026-10-27-skills-procedure-hub/README.md와 각 관련 SKILL.md·규칙/record-schema를 읽는다. **스킬과 실버를 옮겼다는 사용자 설명**을 반영하여 현재 실제 위치·원본/사본·정본·소비 경로부터 확인한다. 기존 하드코딩 경로를 정본이라 가정하지 않는다. 초기 후보는 orchestration/work/phub-recommend/step1~9 JSON·decisions·apply·source-map 및 PROCEDURE-HUB/phub-recommend/backend의 raw manifest/config와 silver 입력 경로다. 비밀 env 값은 출력하지 않는다.

## 조사 1: 원장→실버 대조

1. 실제 원장(브론즈 snapshot) 파일, 실버 단계1~9 정본/결정/생성기, semantic 및 Gold 입력 사이 lineage 지도와 파일 hash를 만든다. 원장=실버 생성 결과라는 순환 검증을 피하고 원래 원장 원문을 직접 대조한다. 원장이 없거나 버전 불일치면 추정하지 말고 범위를 명시한다.
2. 전 단계의 미정/ambiguous/후보전부/계열만/조건부/부위없음/해석안됨/원천질문/근거약/충돌보수결정 및 누락 provenance·scope를 **실제 필드별 전수 집계**한다. 스키마 errors0/open0을 의미 품질 통과로 취급하지 않는다. 미정이 다른 status로 숨겨지거나 후보가 확정 연결로 바뀐 규칙을 찾는다. 표본 검토와 전수 검사를 명확히 구분한다.
3. 실제 원문 대조 우선순위는 7단계 고민·조합·목적/8단계 관계·조건·안전/5단계 제품×계열×단위 상속이며 나머지1~4·6·9도 누락 없이 inventory/미정 집계한다. 원장 자체 불명확, 실버 오해석·누락, 실버 표현/메타데이터 부족, Gold 변환/노출 오류를 구분한다. **원장이 불명확하다고 실버 오류로 단정하지 않고, 원장에 명확한데 옮기며 잃은 것은 직접 지적한다.**
4. 기존 실제 문제는 가설/시작점일 뿐 결론으로 복사하지 않는다: 부위 없는 필러 후보 U5-082..089, 팔자 CC에서 목주름 문장, canonical pair 없는 synergy note7, 제품276과 family override, K8 metadata, patient 언어 잎/한정. build-out/wp11-response-review-scope-contract-report.md §5~9 및 실물 artifact를 보조 참고하되 로컬 Gold export를 원장의 대체 정답으로 쓰지 않는다.

## 조사 2: 필요한 메타데이터와 데이터 구조 제안

엔터티(제품/계열/단위시술/부위/고민), 원천별 주장, 적용 범위, 관계(쌍/조합/방향/시간/조건), 후보 매핑, 판정/확정 상태와 이력을 분리하는 최소 구조를 제안한다. 기존 구조가 충분한 부분은 유지 근거를 쓴다. 모든 attachment를 적용 승인으로 취급하지 않는다.

필요 필드마다 의미·타입·필수/선택·missing/null/[] 의미·어느 원장 필드에서 오는지·추출/정규화/사람 확인 책임·기존 실버 migration 대응을 적는다. 후보 필드: 원문/원장 파일·JSON 경로·버전/hash, 주장 subject/predicate/object, 제품/계열/단위 대상과 상속 범위, 부위/용법/환자 조건/제외 범위, 관계 양끝/조합 구성/방향/간격, 수치·단위·한정, 원천 표현과 normalized값, mapping 근거/규칙, 확정·후보·미확정 상태와 사유, 검토자/결정 근거·변경 이력. 원장에 없는 임상 사실은 필드를 추가한다고 채워지지 않으며 원천 질문으로 분리한다.

실제 문제 행에 대해 원장→현재 실버→제안 구조를 before/after 예시로 보여준다. 확정값을 추정하지 말고 미확정이면 미확정 자체를 정확히 표현한다. 기존 원문 주장과 보수적으로 접은 resolved 결과를 분리하고 조건 손실·상충 은폐가 없는지 확인한다. 후보 연결을 확정 추천으로 소비하지 못하게 하는 데이터 불변식과 검수 기준도 제안한다. 원장 재확인/실버 수정/스키마 보강/골드 변환 수정의 수정 목록과 순서를 제시한다.

## 산출물·수용

허용 작성 경로는 이 폴더 아래 silver-origin-structure-audit/ 하나다. report.md(핵심 결론·coverage·데이터 구조·우선수정·원천 질문), issues.json(행별 증거), inventory.json(파일/hash/단계/분모·검토수/정본경로), 필요 시 읽기 전용 분석 script를 둔다. issue는 ID/단계/원장 file+JSONpath+원문/실버 file+JSONpath+현재값/변환 규칙/문제 분류/영향/확정 여부/필요 metadata/수정안/확인 질문을 포함한다. 출처 없는 단정·고정 Q002 전용 구조 금지.

시간이 걸려도 얕은 표본으로 전수 완료를 주장하지 않는다. 초기에 실제 경로/분모/조사 계획을 Orca status로 알려주고, 막힌 원천이 있으면 ask한다. 최종 보고는 검증된 문제 수와 미확인 범위를 분리한다. 기존9/326을 새 조사 문제 수로 중복 합산하지 않는다.
