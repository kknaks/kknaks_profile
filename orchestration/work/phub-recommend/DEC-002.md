# 시술 원장 정의 — 단위 시술 · 부위 트리 · 이름 원칙

**정한 것.** taxonomy 의 「시술 항목」 칸에는 제품(나보타) · 부위(사각턱) · 목적(다한증) · 기법(스킨보톡스) · 패키지(풀페이스큐레이션)가 섞여 있다.
그래서 taxonomy 를 시술 원장으로 쓰지 않고 **브론즈 원천으로만** 쓴다. 실버의 시술은 **단위 시술 = 무엇을(약제·장비 계열) × 어디에(부위) × 어떻게(기법)** 으로 다시 정의한다.
제품 · 용량은 단위 시술의 속성이 된다. 목적은 고민 → 단위 시술 엣지, 패키지는 단위 시술 묶음이다.
부위는 37개 노드의 트리로 확정했다. 노드 이름은 상담 용어로, 해부학 · 기법 의학 용어는 속성으로, 구어는 동의어로 둔다.
이 결정은 DEC-001 D-13a(노드 단위)와 D-13f(부위)를 대체한다. SPEC-001 · 원천 수정 목록 · 그래프는 다시 만들어야 한다(D-08).

> 결정의 정본은 `_RESUME.md` §2 의 2026-10-27 행 4개다. 이 문서는 그것을 풀어 쓴다. 스키마 · 테이블 · API 는 개정 SPEC 이 갖는다.
> 원천 근거는 stg 저장본 `phub-stg-2026-10-26/`(PROCEDURE-HUB 워크트리, 2026-10-26 수집)만 읽었다. stg 는 다시 부르지 않았다.

## Decision

| ID | 결정 | 근거 |
|---|---|---|
| D-01 | **taxonomy 의 위치** — taxonomy 는 시술 원장이 아니다. 관리 화면용 분류 트리다. Hub 그래프에서는 **브론즈 원천으로만** 쓴다 | `_RESUME` §2 10-27 「taxonomy 는 시술 원장이 아니라 분류 트리」 |
| D-02 | **단위 시술** — 제일 작은 단위 행위 = **무엇을(약제·장비 계열) × 어디에(부위) × 어떻게(기법)**. 예: 「보툴리눔 톡신 · 사각턱 · 근육 내 주입」 · 「보툴리눔 톡신 · 얼굴 전체 · 진피 내 미세 주입(스킨보톡스)」 · 「HA 필러 · 코 · 주입」(층 속성: 콧등 골막상 · 코끝 연골막상) | 같음 |
| D-03 | **축별 자리** — 아래 표. 약제·장비 계열 = 「무엇을」 / 제품 · 용량 · 샷 = 단위 시술의 **속성**(제품 노드는 두고 「쓰는 제품」 엣지로 잇는다) / 목적 = **고민 → 단위 시술 엣지** / 패키지 = **단위 시술 묶음** | 같음 · 「제품·용량은 속성, 목적은 고민→시술 엣지, 패키지는 단위 시술 묶음」 |
| D-04 | **이름 원칙** — 노드 이름 = **상담 용어** / 해부학 · 기법 의학 용어 = **속성** / 구어 표현 = **동의어**. 이유: 질의와 Jev 선택지는 상담 언어로 들어온다(DEC-001 D-08). 안전(위험 부위 원장)과 의료진 검수는 해부학 이름으로 본다 | `_RESUME` §2 10-27 「이름은 상담 용어, 해부학·기법 의학 용어는 속성, 구어는 동의어」 |
| D-05 | **부위 트리** — 아래 「부위 트리」. 쪼개는 규칙: ① 원천 데이터가 따로 부른다(시장가 · 고민 분류 · 용도별 · 위험 부위) ② 가능 시술 · 안전이 달라진다. **둘 다 아니면 쪼개지 않는다.** 노드마다 원천 근거 표를 단다. 해부학 이름 속성 칸은 두되 값은 비워 둔다(OQ-202 — 의학 용어 확정은 의료진) | `_RESUME` §2 10-27 「부위 트리 확정」 |
| D-06 | **시술 ↔ 부위** — 「이 시술을 이 부위에 할 수 있다」 엣지. 예: 「턱쪽에 필러」 → 부위 턱의 하위 중 필러 가능 엣지가 있는 턱끝 · 턱선(사각턱 제외) → 외부 LLM 이 되묻는다(DEC-001 D-08) | `_RESUME` §2 10-27 「시술↔부위 가능 엣지(「턱쪽 필러」→ 턱끝·턱선, 사각턱 제외)」 |
| D-07 | **이름에 붙은 부위 · 고민 분리** — 「팔자주름」 = 부위 팔자 + 고민 주름. 시장가 「이마 주름 (수입)」 같은 항목도 부위(이마) + 고민(주름) + 제품 등급(수입)으로 나눈다. 「얼굴 전체」는 부위 노드다 | `_RESUME` §2 10-27 「「팔자주름」= 부위 팔자 + 고민 주름」 · 부위 트리의 「얼굴 전체」 |
| D-08 | **대체 · 영향** — DEC-001 **D-13a**(시술군 + 시술 항목 둘 다 노드)와 **D-13f**(위험 부위 11곳만 부위)를 대체한다. 영향(개정 내용은 여기 쓰지 않는다): ① SPEC-001 §3.2 노드 · §3.3 엣지 개정 ② 원천 수정 목록 A2~A6 제안값 재생성(후보 이름이 taxonomy 시술 항목 기준이었다) ③ 그래프 재빌드 | 사용자 · 브리프 |

## 부위 트리

규칙(D-05): ① 원천이 그 부위를 따로 부른다 ② 가능 시술이나 안전이 그 부위에서 달라진다 — 둘 다 아니면 쪼개지 않는다.
노드 37개(최상위 4: 얼굴 · 목 · 두피 · 바디). 대괄호 안은 하위 노드다. 이름이 같은 상위와 하위(예: 「눈가」 아래 「눈가」)는 상위 = 묶음 · 하위 = 그 이름이 가리키는 좁은 부위다.

├─ 이마 ─ [이마 · 미간]
├─ 관자놀이
├─ 눈가 ─ [눈가 · 눈밑 · 눈꺼풀]
├─ 코 ─ [코 · 코끝]
├─ 볼 ─ [볼 · 광대]
├─ 입가 ─ [팔자 · 입술 · 입꼬리 · 잇몸]

## Rationale

- 판단 기준: 단위 시술이 상담의 질의 단위(「턱쪽 필러」 = 무엇을 + 어디에)와 안전의 판단 단위(위험 부위 · 기법별 금기)를 함께 담아야 한다. 섞인 칸을 노드로 쓰면 둘 다 흔들린다(D-03 표)
- 이름을 상담 용어로 두는 이유: 사용자 질의와 Jev 선택지(DEC-001 D-08)가 상담 언어라 노드 검색이 결정론 일치만으로 닿아야 한다(DEC-001 D-12). 해부학 이름은 안전 원장 · 의료진 검수가 쓰므로 버리지 않고 속성으로 둔다(D-04)
- 부위를 쪼개는 규칙을 두 개로 묶은 이유: 원천이 부르는 이름만 따르면 「입꼬리 · 잇몸」처럼 한 항목에 묶여 온 부위를 못 나누고, 안전만 따르면 시장가 · 고민이 부르는 부위를 놓친다(D-05)
- 리스크: 단위 시술 목록은 아직 없다. 다음 단계의 축 분류표(사용자 답)가 나오기 전에는 SPEC-001 을 개정할 수 없다
