# 사용자와 직접 논의하는 데이터 검토 담당자

사용자가 지금 새 에이전트 하나를 열어서 직접 질문·논의하고 함께 작업하겠다고 요청했다. 이 문서를 읽은 에이전트가 그 담당자다. 코디네이터의 결과 보고용 워커가 아니며 새 orchestration Task/Dispatch를 만들지 않는다. 사용자와 직접 대화한다.

## 처음 할 일

아래 검토판과 근거를 읽고 현재 상태를 파악한 뒤, 준비됐다고 짧게 알리고 사용자의 질문을 기다린다. 사용자가 아직 묻지 않은 대규모 조사·수정·추가 워커를 자동으로 시작하지 않는다. 이후에는 사용자의 지시에 따라 같이 논의하고 작업한다.

경로는 이 문서가 있는 폴더 기준이다.

- `silver-decision-cards/index.html` — 사용자에게 전달한 현재 HTML v2.
- `silver-decision-cards/review.json` — 카드의 문제·근거·미확인·영향·처리안·선택지와 전체 원문 내용.
- `silver-decision-cards/README.md` — 화면의 사용법과 검토 한계.
- `DATA-001.md`, `WORK-013.md` — 현재 데이터 계약/실행 계획.
- `silver-origin-structure-audit/report.md` — 경로가 없으면 해당 폴더의 실제 report 파일을 확인. 원문↔실버 초기 조사.
- `silver-batch1-validator-closeout-review/report.md` — 최신 검증기 독립 폐쇄 검수 PASS.
- 필요할 때 `_RESUME.md` — 과거 기록이 매우 길므로 위 자료를 먼저 읽는다.
- 전체 방향: 레포 루트 `reference/2026-11-03-procedure-hub-data-and-traversal/WORK.md`.

## 사용자가 원하는 것

앱이 많이 탐색하면서도 “정보 없음”을 내는 문제를 겪었고, 데이터 품질/구조를 먼저 바로잡기로 했다. 앱 예외 처리나 탐색량 조정으로 원천 문제를 덮지 않는다. 원문→실버→골드→Jev/앱 순서다.

사용자는 자신이 결정할 수 있도록 **무엇이 문제인지, 어디에 근거가 있는지, 그대로 두면 무엇이 잘못되는지, 제안은 무엇인지**를 명확하게 설명받고 싶다. “대상 미확정, 원장 확인 필요” 같은 추상 문구로 판단을 떠넘기면 안 된다. `원장`은 여기서 원천 데이터/ledger를 가리킨다. 의료인 확인과 혼동하지 않는다.

## 현재 완료와 미완료

- 첫 이관 후보판 `silver-batch1-candidate/**`를 생성했지만 정본 전환은 하지 않았다.
- 제품395/계열27, 안전·사후관리 원문580행1394필드4170잎 보존.1242 attachment는 적용 unknown이고,152필드는 미부착이다. 152개의 오류가 확정됐다는 뜻이 아니다.
- 검증기가 원문 없는 scope 범위 추가/qualifier 삭제/제품 line 관계 삭제를 놓치던 BR-H1·BR-M1은 보완과 독립 재검수 PASS. 검수는 원문 보존·계약 정합에 한정한다. 의학적 정확성, 전체247필드 의미, 정본 전환을 승인한 것이 아니다.
- 현재 감독받는 활성 워커는 없다. 이 에이전트는 사용자가 직접 같이 일하는 새 세션이다.
- 골드 신규 적용·Jev/앱 연결·서비스 활성화는 아직 진행하지 않았다.

## 카드 v1의 잘못과 v2에서 구분한 것

v1은 미부착152필드를 전부 결정 문제처럼 제시하고, 여러 시술에 연결된 경우에도 단일 대상을 고르라고 해서 사용자가 반려했다. 현재 v2는 26개 주제로 정리했다. 중복 제외62원문행152필드를 모두 보존한다.

1. 구체적인 원문 문맥 확인4건: 다한증·주름·목주름/턱선 행의 교근 섬유화 문장, PLLA 실리프팅 행의 주입/비가교HA 문맥. **문맥 의심 및 출처 확인 대상이지 의학적 오류 확정 아님.** 원문 내용을 먼저 보여준다.
2. 복수 연결 규칙1건: 주름·다한증·입꼬리/잇몸미소/코끝·목주름/턱선·빼당주사,5행17필드. 기존 units와 각 대상 시술의 동일 ledger source ID를 대조했고 복수 연결 근거는 있다. 여러 대상이라는 사실만으로 오류/미정이라고 하지 않는다. 연결 보존과 모든 문장의 공통 임상 적용은 별개다.
3. 스킨보톡스 연결 근거1건: 기존 실버는 M4-P-3→U5-009라고 적지만 U5-009 sources에 M4-P-3는 없다. 기존 basis의 결정 문서까지 추적해야 한다. 이름만으로 자동 연결 확정 금지.
4. 기존부터 후보 관계19건49필드: 엑소좀/줄기세포/실의 소재·형태/알렉산드라이트/지방분해주사 명칭 등. 후보 수가 많다는 사실만으로 오류라고 하지 않는다. 소재·부위·주입/도포 같은 다른 축과 실제 관계를 구분한다.
5. 범위 제외1건:37행83필드는 패키지·도포제·의약품 등 기존에도 원문 보관으로 분류되어 이번 대상 이관에서 빠진 것이다. 개별 필드별 데이터 오류 승인 문제가 아니라 후속 이관 범위 문제다.

## 작업과 결정의 주의점

지금까지 원문·기존 실버·골드·앱·DB는 바꾸지 않았다. 사용자와 논의해 결정된 내용은 근거/결정/미정 상태를 명확히 기록하고, 필요한 변경 범위를 설명한 뒤 사용자 지시에 따라 작업한다. 선택 하나로 의학적 승인이나 정본 반영이라고 해석하지 않는다. 외부 레포 코드 작업은 레포의 AGENTS/runbook 절차를 따른다. 이 레포 안 작업은 AGENTS의 로컬 작업 경로를 따른다.

`results/ui-export.json`, `results/review-test-export.json`은 자동 테스트이며 사용자 결정이 아니다. 적용 금지. v1 JSON은 질문/선택 의미가 바뀌어 v2로 자동 이월하지 않는다. 현재 `review_fingerprint`는 v2 설명과 데이터판을 고정하며 사용자 선택을 받을 때 판 일치를 확인한다.

현재 화면의 정확한 문제를 묻는다면 추상적인 “검증 통과”나 “152개 주장”으로 답하지 말고 해당 행의 원문과 관계를 열어서 설명한다. 확정된 사실과 조사해야 할 부분을 구분한다. 사용자 질문 중에는 필요 없는 수정 발주를 시작하지 않는다.
