# WP-8 추가 지시: Q002 과탐색 실물 로그

사용자가 Q002 실물 로그의 `hub_page#coverage-6~251`(약 250회)과 `hub_full` 다수, Claude 두 호출(각 약 23초·22초)을 보고 "이게 맞아?"라고 지적했다. **맞지 않다.** 현재 브리프의 답변 관문과 함께 이 경로를 수치로 진단한다.

1. Q002에서 page 호출을 node/section/갈래별로 집계한다. 각 호출이 어떤 필수 target/facet/안전 항목을 닫기 위해 필요한지, 이미 지원된 뒤에도 읽은 페이지가 있는지, 어떤 조건이 `not_required`를 막는지 확인한다.
2. 코드 수정 범위에서 안전하게 가능한 경우, 지원 근거와 필수 안전 적용이 확인된 갈래의 무관한 뒤 page·형제 unit 조회를 멈춘다. **부재를 주장하는 범위**와 미지원 필수 항목은 계속 실제 완료를 증명한다. 고정 4걸음/바이트 제한으로 조용히 자르지 않는다.
3. 현재 WP-8 답 관문과 충돌하거나 Hub API 변경이 필요하면 추측성 최적화를 하지 말고 원인·필요 계약·예상 감소 호출을 보고서에 남긴다. Q002를 한 번 넘게 반복하지 않는다. 최종 수치에는 Hub 호출/수신 bytes와 Claude 입력 bytes/TTFT/전체 시간을 모두 적는다.

## 사용자 교정: 탐색 경계

I-01 `팔자주름` 질문의 경계는 **anchor → 직접 추천 관계(`treats`/검증된 파생 관계) → 후보 시술 → 그 후보에 적용되는 역할·조건·안전 fact**다. 안전 fact는 이 질문 탐색의 종착점이다. `필러 → 부작용 → 다른 시술(보톡스) → 다른 고민` 식으로 역방향/옆방향으로 확장하지 않는다. 실제 Q002 trace가 이 경로로 넘어갔다고 주장하지 말고, 7개 직접 후보와 133개 `safety.side_effects` 페이지의 과도한 펼침을 분리해 분석한다. 각 갈래는 역할·명칭/방식·적용 조건·필수 안전이 증명되면 종료하며, 부재를 말할 해당 facet만 마지막 페이지까지 확인한다. 이 경계를 코드/시험으로 표현할 수 있으면 반영하고, 현재 브리프 범위를 넘으면 다음 작업의 명시 계약과 수치를 보고한다.

**정정: 종착 규칙은 안전에 한정하지 않는다.** Jev의 질문 분류가 만든 target×facet(추천 역할, 효과, 방식, 기간, 가격, 조건, 안전 등)마다 필요한 인용 가능 근거와 scope를 정의한다. frontier는 그 미지원 facet을 지원할 수 있는 허용된 typed edge만 확장하고, 필요한 근거가 확인되면 해당 facet의 이웃/후속 page는 `not_required`로 종료한다. depth는 미지원 facet에 따라 동적으로 늘 수 있으나, 질문과 무관한 관계·형제·역방향으로 넓어지지 않는다. 지원 근거가 끝내 없다고 말하려는 facet만 허용 frontier와 해당 section/page를 완료 증명한다. 오류·시간 제한·불명확한 관계는 `incomplete`이지 `정보 없음`이 아니다. 안전은 이 일반 규칙의 한 예다. WP-8 범위를 넘어 전체 walker 재설계가 필요하면 정확한 함수·상태 전이·회귀 시험을 보고해 다음 발주로 넘긴다.
