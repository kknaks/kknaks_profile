## 원칙 (시술 쪽 v2.1~v2.3 과 동일하게 부작용 쪽에 적용)
A. 미상 칸이 하나라도 있으면 다른 이름과 접지 않는다.
B. 조각을 버리지 않는다. 한 칸에 후보가 둘이면 단위를 둘로 나누거나(부위 「이마/눈가」→ 둘) 미해결로 둔다.
C. 수식어(경과·부위)는 **같은 멤버 안에서 바로 붙은 사건**에만 준다. 이름 전체에서 끌어오지 않는다.
D. 표현(adverse_expression)은 단위를 **가리키기만** 한다. 표현에서 새 단위를 만들지 않는다.

## 수정 6건 (검토서 번호 대응)
1. **2-A′ 부위 상속·버림 제거** (§1.5 L119). site 는 C 원칙으로 같은 멤버 안에서만. 부위 후보가 둘(「이마/눈가」)이면 B 원칙으로 튜플 둘. 사건에 붙지 않은 부위 조각은 `extra_sites` 에 보존하고 접지 않는다. 「두통 × 주사 부위」류 틀린 조합이 0 이 되는지 실측.
2. **2-B′ raw_name 칸의 이름 전체 상속 제거** (§1.5 L122). 미등록 이름(raw_name)에는 course·site 를 아예 주지 않는다(둘 다 미상, candidate_name 만). LOP 가 raw 칸에서 「지연」이 되지 않는지 실측.
3. **2-C′ 표현이 새 단위를 세우지 않음** (§1.5 L123). adverse_expression 의 분해 결과가 **기존 단위(complications 65 + extracted/taxonomy safety 이름 유래)** 와 세 칸 완전 일치할 때만 연결(match_status=exact). partial 이면 연결하지 않고 unlinked + candidate 보존. 표현만으로 생기던 새 튜플 57 → 0 인지 실측.
4. **adverse_tuple_assign 대상 범위 문구** — partial/unlinked 뿐 아니라 모든 raw_name 단위·표현을 대상으로 적을 수 있게 §5.2 문구 수정.
5. **CAT- 「계열 코드」기준 명시** — taxonomy 트리 위치(reclassification 메모 적용 전)임을 §1.4·§2.3 에 한 줄로. 실측과 일치시킨다.
6. **site_id 출처** — 「파생」이 아니라 이름·참조 키 목록(what_id 와 같은 방식)으로 §2.5·§2.14 수정.
