## 옮기면서 정한 것 — 코디 확인 부탁

1. **T25 기대 발화 수 = 1 · ③ 은 넣지 않았다.** 목록 「기대」 칸이 수를 말하지 않는다(「앞말이 다음 번역에 붙지 않음」). FAIL 칸 두 가지만 ② 로 옮겼다: 번역이 앞말로 시작하고 **뒤에 말이 이어지면**(붙음) · **번역이 빈 확정 줄**. 앞말이 따로 한 줄로 나오고(번역 있음) 본문이 다음 줄이면 기계 판정은 pass · 조각 수 +1 로만 남는다. 2 가 맞다면 `expected_finals` 만 고치면 된다.
2. **T23 · T24 · T26 은 ③ 하나만** — FAIL 칸의 조각 문구(따로 번역된 앞부분 등)는 발화 수로 드러나므로 글자 규칙은 넣지 않았다(조각 번역 문구는 정상 문장 안에도 나올 수 있어 헛걸림).
3. **3절 밖 문장에는 ③ 을 넣지 않았다** — FAIL 칸이 발화 수를 말하지 않는다. 조각 수(실제 − 기대)는 결과에 그대로 남는다.
4. 영문 이름 · 대소문자: 「영문」 · 이름 문구는 대소문자 안 가림 · 「소문자」 를 FAIL 로 적은 것(T07 한 규칙)만 가림. 앞말 · 「이름 + 호칭」 · 「is you」 류는 낱말 경계(`\b`) 정규식 — 정상 문장의 더 긴 낱말 안에서 헛걸리지 않게(예 「is you」 ⊂ 「is your」).
5. 원문 쪽 규칙은 4절 인식(T27 · T28) 둘 — 잘못 들은 한국어가 원문에 나오면 걸림. T28 은 띄어쓰기 없는 꼴도 잡게 ②. FAIL 칸의 「→ 年」(번역 쪽 결과)은 원문 규칙으로 갈음해 넣지 않았다.
6. 외→한 T22 는 번역(한국어)에서 반말 꼴만 — 높임 꼴이 이어지면(「…요」) 안 걸리게 ②.
7. 규칙 파일 머리에 `made: "2026-11-14 WP22 ① 초안 — 코디 확인 전"` 을 적었다. 확인 뒤 바뀌면 A 실행 전에 고친다(돌린 뒤엔 안 바꿈 · SPEC §9.3).
