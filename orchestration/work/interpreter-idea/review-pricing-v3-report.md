## WARN

### W-a. 결론 이유 3번 「무엇을 재서 청구하는지가 이미 정해져 있다」가 §7 #6(계정별 집계 미확인)을 말하지 않는다

- `:16` 은 「토큰은 Soniox 사용 기록의 숫자 그대로다」로 끝난다.
- 그런데 그 숫자를 **고객 계정별로** 가를 수 있는지는 확인하지 않은 〔가정〕이다(§7 #6 · §6 둘째).
- 결론 절만 읽으면 토큰제의 계량이 이미 된다고 읽힌다. 이 가정이 깨지면 추천이 바뀐다(§6 둘째).
- 고칠 방향: `:16` 끝에 「단 계정별 집계는 아직 확인 전 — §7 #6」 한 마디를 붙인다.

### W-b. 「한꺼번에 최악」 토큰제 27.9% 는 문서가 밝힌 실현 가능 조건을 한 점 넘는다

- `:212` 는 조건을 「발화 연결 시간 + 세션마다 60초 ≤ 3,600초」로 밝혔다. 그런데 뽑힌 점(상담 · 세션 1회 · 발화 41개)을 넣으면 41 × 87.6초 + 60초 = 3,651.6초로 조건 밖이다.
- 원인은 `calc2.py` 의 `corner()` 다. `kmax` 가 1 미만일 때도 `k = 1.0` 을 그대로 평가한다(`for k in (1.0, kmax)` 에서 1.0 은 거르지 않음).
- 조건 안의 최악은 발화 40개 · 세션 1회이고, 100만 토큰 원가 9,164원 · 마진 **28.4%** 다.
- 결론(토큰제만 양수)은 바뀌지 않는다. 다만 결론표 · `:14` · `:212` 의 27.9% 와 9,230원이 문서 자신의 조건과 어긋난다.
- 고칠 방향: `corner()` 에서 `n·d + k·60 > 3600` 인 점을 거르고 재실행한다(또는 조건 문장을 실제 계산에 맞게 고친다).

### W-c. pd2-D 에서 토큰제 △ 표지가 시간제 ○ 에 가려진다 — 본문 「표지가 엇갈려 찍혀 있다」와 다르다

- pd2-D 는 표지를 정수 대수(1 ~ 5대)에만 찍는다. 그래서 시간제 ○ 와 토큰제 △ 가 같은 x 에 겹쳐 △ 가 거의 보이지 않는다.
- 그런데 `:253` 은 「표지가 엇갈려 찍혀 있다」고 적었다. pd2-H · pd2-ks 는 실제로 엇갈려 찍혀 있다.
- 범례와 그림 안 주석(「시간제 = 토큰제」)은 있어서 읽을 수는 있다.
- 고칠 방향: pd2-D 만 △ 를 반 칸 비켜 찍거나, `:253` 문장을 「같은 점에 겹친다」로 고친다.
