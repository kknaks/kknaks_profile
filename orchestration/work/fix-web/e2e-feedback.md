## 보충(사용자)

- W6 · W7: 탭 이름이 바뀌면서 탭 아래 아코디언은 **전부 없앤다**. 탭 = 목록 하나.
- W4: 카드 구조 = **머리 줄: 룸 이름 · 상태 · 경과값** / **아래 줄: 사람 이름 (오른쪽에 [재호출])**. 지금은 머리=룸 이름만 · 이름 줄 · 상태 줄 따로.
- W4: 버튼은 **이름 줄 한 칸 아래**(지금 위치 그대로).
- W5 → **확인 필요 상황 = 3가지만**: ① 대기가 길 때(wait) ② 호출했는데 안 올 때(call) ③ 귀가 대기 처리가 필요할 때(home). 지금 코드 `board_rules.py` `needs()` = 5가지(wait · anes 마취 초과 · call · accept 수락 뒤 미시작 · home) → **anes · accept 빼기**. 규칙 16 · U-10 「확인할 상황」 스펙 변경 건.
- 사용자: 「귀가 대기 버튼이 확인 필요에 계산 안 된다」 — 코드상 home 은 needs 에 들어감(모든 시술 완료 · 귀가 대기 안 누름). 화면에서 안 세지는 거면 버그 — 확인 필요.
- W5 갱신(사용자): **마취 경과도 넣는다** → 확인 필요 상황 = **4가지**: wait(대기 길 때) · anes(마취 초과) · call(호출했는데 안 옴) · home(귀가 대기 처리 필요). 빼는 건 **accept(수락 뒤 미시작) 하나**.
- 확인 필요 카드의 [귀가 대기] 버튼(왼쪽 사이드바) — 지금 뜸(2차 #238 추가 · 조건: 시술 전부 완료 · 귀가 대기 안 누름 · 편집 권한).
- **W10(사용자)**: 왼쪽 사이드바 확인 필요 카드의 **[귀가 대기] 버튼 뺀다**(2차 #238 에서 들어간 것). 귀가 대기 상황 카드는 남고 버튼만 없음 → 사이드바 카드 버튼은 [재호출] 하나.
- **결정 A(사용자 11-12)**: W5 수락 뒤 미시작은 **웹(프론트)에서만 거른다** — 앱 심사 중이라 API(`needs()` · `limits.acceptMin`)는 그대로. 앱 영향 0. 웹·앱 확인 필요 정의가 당분간 다름 → 스펙에 명시.
- W4 범위(사용자 정정): 카드 구조 변경은 **확인 필요 카드(need_card)만**. 수락 대기 탭 카드(call_card)는 구조 그대로.
- **W11(사용자)**: 수락 대기 탭 카드(call_card)에서 **[재호출] 버튼만 뺀다** → 버튼은 [수락] 하나.
- **결정 A 변경(사용자 11-12)**: 수락 뒤 미시작은 **백에서 버린다**(`needs()` 등) + 프론트도 수정. 앱 코드 수정 · 새 빌드 없음(앱 화면에서도 accept 안 보이게 됨 — 사용자 확인).
- **귀가대기 경과(사용자 11-12)**: 확인 필요 카드 머리에 「귀가대기」 글자만 — 경과(n분째) 없음. 스펙 ⑳ 그대로 · 코드 고침.
