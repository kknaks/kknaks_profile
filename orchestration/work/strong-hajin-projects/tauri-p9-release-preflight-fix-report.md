## 2. 무엇이 문제였나 — **침묵이 문제였다**

```js
// 고치기 전
const present = readdirSync(candidateDir).filter((name) => {
  const info = statSync(join(candidateDir, name));
  return info.isFile();            // ← 디렉터리는 여기서 사라진다
});
```

`extra` 는 이 `present` 에서만 계산된다. 그래서 candidate 에 `Strong Hajin.app/` 이 들어 있어도
**«섞였다»로 잡히지 않고, 화면에도 한 줄 나오지 않고, exit 0 이 나왔다.**

**내가 Phase 9 본편 §5-2 에 「기록에 없는 파일이 섞인 것도 실패다」라고 써 놓고,
그 규칙을 파일에만 적용했다.** 규칙이 틀린 게 아니라 **적용 범위가 새었다.**

`isFile()` 필터만 되살린 사본으로 같은 fixture 를 돌렸다:

**초록이 나왔다.** 있지도 않은 것처럼 센 자산 하나를 데리고. 이것이 WARN 이 가리킨 것이다.

## 3. 고친 것

### 3-1. 디렉터리를 세되, **두 경우를 가른다**

```js
const present = readdirSync(candidateDir).map((name) => ({
  name,
  isDirectory: statSync(join(candidateDir, name)).isDirectory(),
}));
```

| candidate 의 항목 | 판정 | 코드 |
|---|---|---|
| **기록에 없다**(파일이든 디렉터리든) | 섞였다 | **5** |
| 기록은 **파일**인데 candidate 는 **같은 이름의 디렉터리** | 종류가 다르다 | **5** |
| **기록에는 있으나 해시가 없다**(`bundleDir`) | **대조 불가** | **8**(신설) |
| 기록에 있고 해시가 있다 | 해시 대조로 넘어간다 | 0 / 6 |

«섞였다» 줄에는 디렉터리임을 붙여 적는다 — `… Phase 8 이 본 적 없다: Strong Hajin.app/ (디렉터리)`.

### 3-2. 코드 **8** 을 새로 뗀 이유

「기록에 없다」와 「기록에는 있는데 잴 수 없다」는 **다른 사실**이고, 사람이 할 일도 다르다:
앞은 **빼야 하고**, 뒤는 **해시를 낼 수 있는 형태로 싸야 한다**. 이 스크립트는 원인마다 코드를
따로 주는 규칙으로 만들었으므로, 5 에 욱여넣지 않고 하나 더 뗐다.

```
**candidate 에 대조할 수 없는 자산이 있다** — 기록에는 있지만 **해시가 없다.**
  Strong Hajin.app/ — Phase 8 이 디렉터리 번들로 기록해 sha256 이 없다
  디렉터리는 바이트 하나로 묶이지 않아 이 관문이 동일성을 말할 수 없다.
  **올리려면 해시를 낼 수 있는 형태로 싸세요**(예: `.app` 대신 그것을 담은 `.dmg`/`.zip`).
  **«해시가 없다»를 «같다»로 바꾸지 않는다.**
```

**기존 규칙을 바꾸지 않았다**: 해시 없는 기록은 여전히 «검증 불가»이고, 여전히 **«같다»로 세지 않는다.**
바뀐 것은 **그것이 candidate 안에 실제로 있을 때 막는다**는 것뿐이다.

### 3-3. 기록된 `.app` 이 candidate 에 **없으면** 그대로 통과한다(F-6)

올리지 않는 것을 막을 이유가 없다. 그때는 예전처럼 `ℹ` 한 줄로 남는다:

```
ℹ Strong Hajin.app — 디렉터리 번들이라 해시가 없다. **«같다»고 쓰지 않는다**
```
