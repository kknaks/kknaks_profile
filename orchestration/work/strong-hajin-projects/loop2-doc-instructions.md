## 2. SPEC-005 개정 — 계약이 바뀌는 자리만

**조문마다 결정 번호를 달아라.** 기존 인수조건 번호를 **함부로 재배열하지 마라** —
더할 것은 뒤에 붙이고, 뜻이 바뀐 줄은 그 자리에서 고쳐라.

- **§2 UX** — 좌 레일 헤더 한 줄(+건수 배지 위치) · 헤더 「프로젝트 추가」 버튼과 **그 게이트** ·
  생성 모달의 **네 칸**(`name` 필수 1~300·공백 정규화 후 빈 문자열 거절 / `description` /
  `starts_on` / `ends_on` — `starts_on` 보다 앞이면 거절. **`external_key` 는 API 가 안 받는다**) ·
  간트 라벨 칸 틀고정과 **첫 진입 오늘 기준** · 간트→좌 레일 **자동 스크롤** ·
  우 레일 **블록 순서와 「업무 정보」** · 메타 표 규칙 · **상태 드롭다운(내 업무만)** ·
  완료 바 색 · 제목·소제목 색
- **§4 Interface Contract** — **체크리스트·업무 내용의 읽기 범위 변경**이 유일한 계약 변경이다.
  ⚠ 지금 `access`(`owner`/`read_only`)가 **읽기 범위와 쓰기 범위를 한 값으로 묶고 있다.**
  그 둘을 가르는 방식을 **정해서 적어라** — 「`access` 를 셋으로(`owner`/`project`/`read_only`)」 대 
  「`checklist` 를 싣는 조건만 따로」. **쓰기 경로의 가드는 건드리지 않는다**(그 사실을 명시)
- **자동 초대의 게이트 제거** — 붙는 자리 서술에서 **「열쇠는 배정 권한」을 빼고**
  「배정이 성립하면 붙는다」로. 관련 인수조건도 함께
- **§6 인수조건** — 새로 더한 것마다 **관측 가능한 문장**으로. 특히:
  「빈 상태(프로젝트 0개)에서도 생성 버튼이 선다」 · 「관리 권한 없는 프로젝트에서는 관리 버튼이
  없고 생성 버튼은 있다」 · 「같은 프로젝트의 남의 업무에서 체크리스트 항목이 보인다」 ·
  「내 업무가 아니면 상태 드롭다운이 아니라 읽기 배지다」 · 「가로 스크롤해도 업무 이름이 남는다」
- **§7** — 새로 여는 미결이 있으면 적는다. 없으면 「없다」

⚠ **SPEC-003(업무 상세 계약)까지 닿는지 확인하라.** 체크리스트 읽기 범위는 그 문서의 계약일 수 있다.
닿으면 **고치지 말고** SPEC-005 에 「SPEC-003 의 어느 줄과 무엇이 달라지는지」를 적고 §7 로 올려라.

## 3. WORK-005 에 「2루프」 절 추가

**WORK-004 의 선례를 따른다** — 그 문서에 `## Execution — 2루프 (…)` 절이 있다.
기존 1루프 Phase 들은 **건드리지 마라**(done 기록이다).

- Phase 구성: **BE(A-1 게이트 제거 · B-11 체크리스트 열기) 를 «먼저», 그 다음 FE(화면 9건)** —

  **B-11 이 FE 가 받는 응답을 바꾸므로** FE 는 BE 가 끝난 뒤 **실물 응답을 보고** 짠다.
  WORK 의 Phase 순서와 `Dependency` 절에 그 사실을 적어라
- FE 를 하나로 묶을지 둘로 쪼갤지는 **네가 판단해서 근거를 달아라** (간트 관련과 우 레일 관련은
  서로 다른 파일을 만진다)
- **각 Phase 에 닫는 인수조건 번호**와 **근거 결정 번호**를 단다. **인수조건 전수 배정 · 누락 0**

  표는 안 바뀔 것**이다. 확인해서 「변경 없음」이면 그렇게 적어라
- **검증 계획**: Phase 0 가 닫혔으므로 **`make verify` 가 exit 0 를 내는 것이 기준선**이다
  (코디 실측 2026-09-22). 이제 「기준선 밖 실패 0」이 아니라 **「실패 0」**이 조건이다.

  마커를 달아야 하고, 안 달면 conftest 걸개가 즉시 실패시킨다**
