# 수정 2회차 추가 지시 — 사용자 원칙(11-16) 「질문에 빠지는 정보가 있으면 안 된다」

사용자 말: 「목표는 질문에 대해서 빠지는 정보가 있으면 안돼 · 모든 정보에 대해 접근 하되 더 깊이 들어갈지는 별도 판단」

= **폭은 빠짐없이, 깊이만 판단.** `_RESUME.md` §2 맨 위 행에 결정으로 있다.

SPEC-002(필요하면 SPEC-001)에 반영:

1. **폭 = 앱 결정론 · 전부.** 질문 범위의 1홉 행 · 후보는 쪽 넘김 끝까지 전부 조회하고, 후보 목록 전체를 답 재료(verified)로 넘긴다. Jev 점수로 폭을 자르지 않는다.
2. **Jev = 깊이만.** 후보마다 Noul 은 「이 후보를 더 깊이(다음 홉 · 상세 facet) 볼지」 를 묻는다. 낮은 점수 = 목록에서 빠짐이 아니라 「깊이 안 봄」 표시. 지금 단계 5 의 「보류 = 빠짐」 꼴을 전부 고친다(grep 으로 보류 · uncertain · no_at 쓰는 곳 전수).
3. **종료** = 폭 다 읽음 + 깊이 판단 끝 + gate 통과. `answer_ready` 단독 종료 없음(종료 제안으로만).
4. **크기** — 폭이 큰 질문(Q08 524 행 · 후보 130 · 역방향 379)을 LLM 에 잘라 내지 않고 넘기는 법은 열린 것으로(선택지 예: 결정론 묶음 표 · 쪽 나눔 · 요약 칸만 + 펼침 · 추천 포함). 잘라 내기 · 상위 N 은 선택지에 넣지 마라.
5. 채점 · 결정론 검사에 「폭 누락(전체 키 대비 빠진 후보 · 행)」 을 B · C 공통 지표로 명시. hard gate 목록과 이어서.
6. 변경 기록에 「사용자 원칙 11-16」 행.
