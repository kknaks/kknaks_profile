# Session Reconstruction

세션 현장에서 남긴 불완전한 원본을 근거가 추적되는 발표 재구성 문서로 바꾼다. 산출물은
`para/resources/session/assets/S-NNN/reconstruction.md` 한 장이다.

## 먼저 읽을 것

1. `para/resources/resource.md`의 `session/` 규약. 경로·원본·사진에 관한 규칙의 SoT다.
2. [reconstruction-format.md](references/reconstruction-format.md). 산출물 구조와 판정 기준이다.
3. 처음 작업하거나 형식이 모호할 때만
   `para/resources/session/assets/S-001/reconstruction.md`를 완성 예시로 참고한다. 예시의
   발표 내용이나 절 개수를 새 문서에 복사하지 않는다.

## 입력과 경계

사용자가 지정한 한 세션의 자료만 다룬다.

- `transcript.txt`: STT 원문. 수정하거나 정리본으로 덮어쓰지 않는다.
- 음성 원본: 이름·숫자·제품명·문장 경계처럼 STT가 불확실한 대목을 확인하는 근거다. 현재
  리소스 규약에는 영구 보관 파일명이 없으므로 자동 이동·변환·삭제하지 않는다.
- 발표 사진: 슬라이드의 문구, 표, 구조와 발표 순서를 복원하는 근거다.

사진이 HEIC 등 웹에서 바로 보기 어려운 형식이고 원본이 대상 폴더 밖에 있다면, 발표 순서의
`NN-<semantic-slug>.webp` 파생본을 대상 폴더에 만든다. 원본은 건드리지 않는다. 이미 대상
폴더 안에 있는 원본을 삭제하거나 이름을 바꾸려면 먼저 사용자 승인을 받는다.

이 스킬은 다음 파일을 만들지 않는다.

- `para/resources/session/S-NNN-<slug>.md` 최종 세션 노트
- `para/resources/resource.md`의 맵 항목
- `para/areas/concept/`의 concept 문서
- PDF

## 작업 흐름

### 1. 원료 상태를 먼저 판정한다

파일 목록, 사진 수, transcript의 첫·끝 타임스탬프, 음성 길이를 확인한다. 다음 이상을 작업
초기에 기록한다.

- 녹취의 앞·뒤 잘림과 긴 무음 구간
- 사진 번호 누락, 중복, 순서 불명
- 읽을 수 없는 사진이나 발표와 무관해 보이는 사진
- 음성 길이와 transcript 종료 시각의 차이

### 2. 사진과 발화를 대응시킨다

사진을 발표 순서로 놓고 각 사진에 대응하는 transcript 시간대와 발화를 찾는다. 슬라이드
제목·고유명사·숫자를 검색 단서로 사용한다. 필요하면 작업 중에만 다음 표를 만들어 추적한다.

| 사진 | 추정 시간 | 슬라이드 제목 | 대응 근거 | 불확실성 |
| --- | --- | --- | --- | --- |

사진이 없는 발화 구간도 버리지 않는다. 도입, 전환, 데모 설명, 질의응답처럼 사진이 없었다고
명시해 시간순 복원에 포함한다.

### 3. 음성으로 필요한 부분만 검증한다

transcript 전체를 새로 받아쓰지 않는다. STT가 다음 항목에서 모호할 때 해당 시간대의 음성만
확인한다.

- 발표자·회사·팀·제품·기술 이름
- 수치, 단위, 전후 비교
- 부정 표현과 책임 주체
- 문장이 잘려 의미가 뒤집힐 수 있는 부분

음성으로도 확인되지 않으면 `미확인`, `청취 불가`, `발표만으로 확인할 수 없음`으로 남긴다.

### 4. 시간순 재구성을 쓴다

[reconstruction-format.md](references/reconstruction-format.md)에 따라 사진과 발화를 분리해
쓴다. 사진에서 읽은 것은 `슬라이드`, 말로 들은 것은 `발표자`에 둔다. 사진에 없는 구조를
발표자의 말만으로 슬라이드 내용처럼 만들지 않는다.

표·단계·대조는 Markdown 표나 `text` 블록으로 다시 그리고, 관계가 핵심인 구조만 Mermaid로
그린다. Mermaid에 넣는 노드와 연결도 원료에서 확인된 것만 사용한다.

### 5. 불확실성과 충돌을 남긴다

`재구성하면서 남긴 것` 절에 누락·충돌·비식별·읽기 실패를 모은다. 슬라이드 수치와 발표자의
말이 다르면 둘 중 하나를 선택하지 말고 두 근거를 나란히 적는다.

### 6. 사례별 최종 정리를 붙인다

시간순 복원이 끝난 뒤에만 발표를 사례 단위로 다시 읽는다. 각 사례를 `문제 → 만든 개념 →
적용과 아키텍처 → 결과`로 정리하고, 마지막에 다른 업무에도 적용할 수 있는 경험을 뽑는다.
발표자의 주장과 발표 자료로 확인된 결과를 구분하며, 정량 근거가 없으면 성과를 만들어내지
않는다.

## 근거 규칙

- 웹 검색이나 일반 지식으로 발표의 빈칸을 채우지 않는다. 외부 확인이 필요하면 재구성과 별도
  작업으로 제안한다.
- 직접 인용은 transcript 또는 확인한 음성에 있는 말만 쓴다. 조사·띄어쓰기·문장부호는 읽기
  위해 다듬을 수 있지만 의미와 수치에는 손대지 않는다.
- 사진의 작은 글자를 추정해 채우지 않는다. 읽을 수 없는 것은 읽을 수 없다고 쓴다.
- 회사 정책으로 가려진 데이터, 데모에서 빠진 기능, 공개되지 않은 성과를 일반론으로 보충하지
  않는다.
- 발표자가 말한 효과는 `발표자는 ...라고 설명했다`로 귀속한다. 검증되지 않은 주장을 문서의
  사실로 승격하지 않는다.

## 완료 검증

- 모든 발표 사진이 본문에서 한 번 이상 참조되거나 제외 사유가 기록됐는가.
- 시간순으로 읽었을 때 사진과 transcript가 역전되지 않는가.
- 슬라이드 내용과 발표자의 말을 구분했는가.
- 이름·수치·비교·부정 표현을 원료와 대조했는가.
- 사진 없는 구간, 녹취 누락, 근거 충돌을 드러냈는가.
- 최종 정리의 각 결과가 발표에서 확인 가능한 범위를 넘지 않는가.
- `transcript.txt`, 음성 원본, 사진 원본을 변경하지 않았는가.
