# permanent

개념들을 엮어 세운 **종합 판단**. 타입: `permanent`, 층: `synthesis`.

원자 개념 자체는 여기가 아니라 `concept/` 에 둔다.

## 여기 두는 것
- 한 노트 = 한 생각. 자료를 베끼지 않고 내 언어로 재서술하며 "왜 중요한지/맥락"을 덧붙인 노트.

## 여기 두지 않는 것
- 미정제 생각 → `inbox/`.
- 외부 자료 정리 → `reference/`.
- **재사용 가능한 개념 자체 → `permanent/concept/`** (여기는 그 개념들을 엮은 판단만).
- 안 쓰게 된 노트 → `permanent/archive/` (permanent·concept 공용).

## quick-rule
- **`up:` 대상은 `concept` 다.** reference 를 직접 up 하지 않는다 — 자료에서 개념을 거쳐 판단으로 오는 것이 4층 모델의 방향이다.
- `up: [stem]` + 본문 `[[]]` 로 연결한다. **연결하며 다시 쓰는 것이 정제**다.
- **SoT 위임** — 개념 내용을 재서술하지 않고 엮은 판단만 소유한다. 판단 문장 안에 개념 요지가 인용되는 것은 허용한다.
- 제품 문서(baseline/decision/spec)를 `up:` 하지 않는다. 방향이 거꾸로다(L4) — 참조는 본문 `[[]]` 로만.
- permanent와 product/post는 별개 SSOT로 평행하게 산다(`up:`은 인용일 뿐 중복 아님).
- 안 쓰면 `archive/`로 내린다.
