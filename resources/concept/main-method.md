# main() 메서드 (Entry Point)

프로그램이 시작되는 자리. [[jvm]] 은 클래스를 실행할 때 정해진 형식의 `main` 을 찾아 그것부터 호출한다.

## 정의

형식이 고정되어 있다.

```plaintext
public static void main(String[] 변수명)
```

네 부분이 모두 조건이다.

- `public` — JVM 이 클래스 밖에서 부를 수 있어야 한다
- `static` — 객체를 만들지 않고 불러야 한다. 시작 시점에는 인스턴스가 없다
- `void` — 반환값을 받을 상대가 없다
- `String[]` — 실행할 때 넘긴 값을 받는 자리 → [[command-line-arguments]]

변수명만 자유롭다. 관례로 `args` 를 쓴다.

## 사용 예시

형식을 어긋나게 쓰면 어떻게 되는지가 이 개념의 핵심이다.

```java
class Test4 {
    static void main(String[] a) {}
}
```

`public` 이 빠졌다. **컴파일은 된다** — 문법에 어긋난 것이 없는 그냥 메서드이기 때문이다. 그런데 실행하면 JVM 이 시작할 `main` 을 찾지 못해 멈춘다.

## 왜 중요한가

**컴파일 성공과 실행 가능이 다른 것이라는 것을 가장 분명하게 보여주는 자리다.** 컴파일러는 문법만 보고, "시작점이 있는가"는 [[jvm]] 이 실행할 때 본다. 그래서 오타 하나로 `main` 이 다른 메서드가 되어도 컴파일러는 아무 말을 하지 않는다.

이 구분을 알면 오류를 읽는 순서가 정해진다 — 컴파일 단계에서 났는가 실행 단계에서 났는가를 먼저 가르고, 실행 단계라면 형식·[[classpath]]·클래스 이름을 본다.

## 경계와 오해

- **`main` 이 있다 ≠ 실행된다** — 형식이 하나라도 어긋나면 JVM 에게는 없는 것과 같다. 이름만 `main` 인 평범한 메서드가 된다.
- **`static` 은 편의가 아니라 필수다** — 시작 시점에는 그 클래스의 객체가 아직 없다. 인스턴스 메서드라면 부를 대상이 없다.
- **클래스마다 있어도 된다** — `main` 은 클래스당 하나씩 둘 수 있고, 실행할 때 **어느 클래스를 실행할지** 지정하는 것으로 시작점이 정해진다. 프로젝트에 하나만 있어야 하는 것이 아니다.
- **어디서 지정하는지가 실행 방법마다 다르다** — `java` 명령으로는 인자로 클래스를 주고, [[gradle]] 로는 `build.gradle` 의 `mainClass` 가 정한다. `gradle init` 이 만든 기본값(`org.example.App`)을 안 고치면 클래스를 못 찾아 실행되지 않는다. **`main` 이 맞게 있어도 지정이 틀리면 안 되는 것**이라, 형식 문제와 지정 문제를 갈라서 봐야 한다.
