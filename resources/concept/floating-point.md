# 부동소수점 (Floating Point, IEEE 754)

실수를 **부호 + 지수 + 가수** 세 조각으로 나눠 저장하는 방식. Java 의 `float`·`double` 이 이것이고, 규격은 IEEE 754 를 따른다.

## 정의

세 조각이 각각 다른 방법으로 저장된다.

| 조각 | 저장 방법 |
|---|---|
| 부호 | 비트 1개 |
| 지수부 | **K-excess** (bias 를 더해 기준을 옮긴다) |
| 가수부 | **sign-magnitude** → [[twos-complement]] |

**K-excess** 는 음수 지수를 담기 위해 값에 bias 를 더해 기준을 옮기는 것이다. 8비트 기준으로 bias = 2^(8-1) − 1 = 127 이므로, 지수 13 은 13 + 127 = 140 = `0b1000 1100` 으로 저장된다.

변환은 세 단계다.

1. 값을 2진수로 변환
2. **정규화** — `1.xxx * 2^n` 꼴로 만든다
3. 가수부는 sign-magnitude, 지수부는 K-excess 로 변환

정규화하면 정수부가 **항상 1** 이 되므로, 그 1 은 저장하지 않는다(생략해도 복원할 수 있다).

## 사용 예시

`12.375` 를 32비트로 저장하는 과정이다.

```plaintext
1) 2진수 변환      12.375 → 1100.011
   정수부 12       → 0b0000 1100
   소수부 0.375    → 0.375 * 2 = 0.75 … 0
                     0.75  * 2 = 1.5  … 1
                     0.5   * 2 = 1.0  … 1     → 0b011

2) 정규화          1.100011 * 2^3
                   (정수부 1 은 항상 1이므로 저장하지 않는다)

3) 지수부          3 + 127 = 130 → 1000 0010
   가수부          100011 (뒤는 0으로 채운다)

결과   0b 0100 0001 0100 0110 0000 0000 0000 0000
       0x 4146 0000
```

소수부를 구할 때 **2를 곱해 정수 부분을 떼는 것을 반복**한다. `0.375` 는 세 번에 끝났지만, 끝나지 않는 값도 있다.

## 왜 중요한가

**소수 계산이 정확하지 않은 이유가 이 구조에 있다.** 2진 소수로 딱 끝나지 않는 값(`0.1` 같은 것)은 가수부 비트 수만큼만 담기고 나머지가 잘린다. 그래서 `0.1 + 0.2 != 0.3` 이 되고, 돈 계산에 `double` 을 쓰면 안 되는 이유가 된다.

지수와 가수를 나눠 담기 때문에 **아주 크거나 아주 작은 수를 같은 비트 수로 담을 수 있다**는 것이 이 방식의 값이다. 정밀도를 내주고 범위를 얻은 것이다.

## 경계와 오해

- **부동소수점 오차는 버그가 아니다** — 규격대로 동작한 결과다. 고칠 방법은 방식을 바꾸는 것(정수로 다루거나 10진 소수 타입을 쓰는 것)이고, 반올림으로 덮는 것은 미루는 것이다.
- **가수부에 2의 보수를 쓰지 않는다** — 음수를 다루는 데 2의 보수가 표준인데, 부동소수점의 가수부는 sign-magnitude 다. 방식마다 쓰는 자리가 다르다.
- **정규화된 1 은 저장되지 않지만 존재한다** — 비트를 세어 보면 가수부가 하나 짧아 보이는데, 생략된 1 이 실제 정밀도에 포함된다.
- **`float` 과 `double` 은 조각 크기만 다르다** — 구조는 같고 지수부·가수부에 주는 비트 수가 다르다.
