# 메시지 브로커 (Kafka · 발행-구독)

**보내는 쪽과 받는 쪽 사이에 저장소를 하나 두는 통신 방식.** 보낸 쪽은 **응답을 기다리지 않고**, 받는 쪽은 **자기 속도로** 가져간다.

## 정의

```
[HTTP]    서비스 A ──요청──▶ 서비스 B
                  ◀─응답──          A 는 B 가 답할 때까지 멈춰 있다

[Kafka]   프로듀서 ──발행──▶ [토픽] ◀──소비── 컨슈머
                                    ▲         컨슈머가 여럿일 수 있고
                                    └─ 저장   나중에 다시 읽을 수도 있다
```

| 축 | HTTP | Kafka |
|---|---|---|
| 통신 방식 | 요청-응답 | **발행-구독** |
| 데이터 저장 | 전달하고 **남기지 않는다** | 토픽에 **보관 기간 동안 남는다** |
| 처리 | 동기 — 응답을 기다린다 | **비동기** |
| 확장 | 서버를 늘린다 | 브로커·파티션으로 **수평 확장** |
| 전달 보장 | 재전송은 직접 구현 | At most / At least / Exactly once **옵션** |
| 부하 | 몰리면 서버에 집중 | **버퍼링**하고 컨슈머 그룹이 나눠 처리 |
| 순서 | 요청마다 독립 | **파티션 안에서 순서 보장** |
| 실패 | 즉시 오류 응답 | **재시도·다른 컨슈머로 전달** 가능 |

세 낱말이 전부다.

- **토픽**(topic) — 메시지가 쌓이는 이름 있는 통
- **프로듀서**(producer) — 토픽에 **발행**한다
- **컨슈머**(consumer) — 토픽에서 **소비**한다

```bash
rpk topic create   order-created           # 토픽 만들기
rpk topic produce  order-created           # 발행
rpk topic consume  order-created           # 소비
```

**레드판다(Redpanda)는 카프카와 같은 방식으로 쓰는 구현**이다 — 명령과 개념이 그대로다.

## 왜 중요한가

**서비스끼리 직접 부르지 않게 된다.** A 가 B 를 HTTP 로 부르면 **B 가 죽으면 A 도 실패**하고, B 가 느리면 A 도 느리다. 토픽에 던져 두면 **B 가 없어도 A 는 끝난다** → [[microservice-architecture]] · [[remote-procedure-call]]

**그리고 한 사건을 여러 곳이 들을 수 있다.** 「주문이 생겼다」를 발행하면 재고·알림·정산이 각자 가져간다 — **보내는 쪽은 누가 듣는지 모른다** → [[observer-pattern]]

**부하를 시간으로 흡수한다는 것도 크다.** 순간적으로 몰린 요청이 토픽에 쌓이고 컨슈머가 자기 속도로 처리하므로, **서버가 무너지는 대신 늦어진다** → [[queue]] · [[little-law]]

## 경계와 오해

- **비동기는 응답을 포기하는 것이다** — 「처리했다」를 그 자리에서 알 수 없으므로, 결과가 필요하면 **또 다른 토픽이나 조회**가 필요하다. 즉시 답이 필요한 API 는 여전히 HTTP 다
- **결과적 일관성으로 넘어간다** — 발행 시점과 처리 시점이 다르므로 **잠깐 어긋난 상태**가 정상이 된다. 한 트랜잭션으로 묶을 수 없다는 뜻이다 → [[transaction]] · [[microservice-architecture]]
- **순서는 파티션 안에서만이다** — 파티션을 늘려 처리량을 얻으면 **전체 순서는 잃는다.** 같은 키를 같은 파티션으로 보내는 설계가 그래서 필요하다
- **「Exactly once」는 조건부다** — 옵션으로 제공되지만 대가가 있고, 대부분은 **At least once + 멱등 처리**로 간다. 같은 메시지를 두 번 받아도 괜찮게 만드는 쪽이 현실적이다 → [[primary-key]]
- **브로커가 새 단일 실패 지점이다** — 서비스 간 결합은 끊겼지만 **모두가 브로커에 의존**한다. 그래서 브로커 자체를 여러 대로 둔다 → [[distributed-processing]]
- **메시지가 남는다는 것은 지워야 한다는 뜻이기도 하다** — 보관 기간·용량 설정이 없으면 디스크가 찬다 → [[object-storage]]
