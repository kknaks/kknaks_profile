# 웹 애플리케이션 배치 (Deployment · war)

**내 코드를 실행하는 것이 아니라, 이미 돌고 있는 서버가 찾아갈 자리에 놓는 일.** Day63 이 방법을 셋 보여 준다(Tomcat Embedded 로 켜기 · war 를 톰캣의 `webapps` 에 놓기 · Eclipse 가 임시 폴더에 놓아 주기). **셋의 차이는 「누가 서버를 갖나」 하나**다 → [[tomcat]] · [[servlet-container]]

## 정의

Day63 이 프로젝트 폴더의 두 자리를 갈랐다 — 「프로젝트 하위 폴더에 webapp에서 정적자원을 관리하고, WEB-INF에서 동적 파일 및 설정 파일 관리한다」.

| 자리 | 무엇이 들어가나 | 브라우저가 URL 로 가져갈 수 있나 |
|---|---|---|
| `src/main/webapp/…` | HTML·CSS·이미지·JS → [[static-and-dynamic-content]] | **가져간다** |
| `src/main/webapp/WEB-INF/…` | 클래스(`classes`)·라이브러리(`lib`)·설정 | **못 가져간다** |

**아래 칸의 진짜 성질은 「동적이라서」가 아니라 「내려받히면 안 되기 때문」이다**(아래 「경계와 오해」). 그리고 컨테이너가 서블릿을 찾는 자리도 여기다 — Day63 의 톰캣 부팅 코드가 그것을 두 줄로 적었다.

```java
resources.addPreResources(new DirResourceSet(resources,
    "/WEB-INF/classes",                       // 서블릿 클래스 파일의 위치 정보
    new File("bin/main").getAbsolutePath(),   // 그 위치에 실제로 붙일 폴더
    "/"
));
```

**앞 인수는 규격이 정한 자리이고 뒤 인수는 내 빌드 산출물이다.** 둘을 이어 붙이는 이 두 줄이 배치의 최소 형태이고, 뒤쪽이 틀리면 서버는 정상으로 뜨고 서블릿만 없다 → [[classpath]] · [[tomcat]]

### 세 가지 방법

| Day63 의 이름 | 배포물 | 서버는 누구 것인가 | 컨텍스트 경로 |
|---|---|---|---|
| **간접실행** (Tomcat Embedded) | jar — 「라이브러리를 통해서 Tomcat Embedded Server를 구축 하여 jar파일을 생성한다」 | **내 빌드에 들어 있다** | 코드가 정한다 (`addWebapp("/")`) |
| **직접실행 / 직접배치** | war — 「생성된 war파일을 tomcat 서버 webapps에 놓는다」 | 운영 환경에 깔린 것 | **파일 이름**이 정한다 |
| **Eclipse 배치** | (없음) | IDE 가 관리하는 톰캣 | IDE 설정이 정한다 |

Day63 이 직접배치의 결과를 적었다 — 「서버를 실행하면 war파일의 압축이 풀리면 app폴더가 생성 된다」. **그 폴더 이름이 URL 의 앞부분이 된다** — `app.war` 를 놓으면 `/app/...` 이고, `/` 로 두려면 `ROOT.war` 여야 한다.

## 왜 중요한가

**「실행한다」가 「놓는다」로 바뀐다.** 지금까지 배포는 없었다 — `main` 을 실행하면 그것이 프로그램이었다. 직접배치에서는 내 코드에 시작점이 없고, **파일을 어디에 놓았는지가 실행 여부를 정한다.** 그래서 「코드는 맞는데 안 뜬다」의 원인이 코드 밖에 생기는 첫 자리다 → [[main-method]] · [[filesystem-path]]

**그리고 서버 하나에 앱이 여럿 얹힌다.** `webapps` 아래 폴더마다 앱 하나이므로 한 프로세스에 내 앱과 남의 앱이 함께 있고, 메모리·쓰레드·포트를 나눠 쓴다. 앱마다 클래스 로더가 따로 있어 같은 라이브러리의 다른 버전을 각자 쓸 수 있는데, **그 격리가 완전하지 않다는 것**이 뒤에 겪을 문제다 → [[process]] · [[class-loading]]

**버전 문제가 여기서 실제로 물린다.** 간접실행은 톰캣을 내 빌드가 품으므로 **어디서 실행해도 같은 서버**이고, 직접배치는 **운영 환경의 버전이 동작을 정한다.** [[java-ee]] 의 대응표가 종이 위의 표가 아니라 배포 사고가 되는 자리가 이것이다 → [[build]] · [[gradle]]

## 경계와 오해

- **`WEB-INF` 는 「동적 파일 자리」가 아니라 「내려받히지 않는 자리」다** — 필기의 설명(「동적 파일 및 설정 파일 관리」)을 정적/동적 축으로 외우면 **왜 클래스와 라이브러리와 설정이 하필 같은 폴더에 있는지**가 설명되지 않는다. 공통점은 성질이 아니라 **밖에서 URL 로 가져가면 안 된다는 것**이다 — 클래스 파일은 [[bytecode]] 라 되돌려 읽을 수 있고, 설정 파일에는 DB 비밀번호가 있다. 이 구별을 놓치면 백업 파일이나 `.sql`·`.properties` 를 `webapp` 아래 두어 **URL 하나로 그대로 내려가게** 만든다 → [[web-server]] · [[filesystem-path]]
- **war ≠ jar** — 둘 다 압축 파일이고 [[build]] 가 만들지만, jar 는 **스스로 실행될 수 있고**(간접실행에서는 그 안에 톰캣이 들어 있다) war 는 **서버가 열어 주기를 기다린다.** 그래서 같은 코드가 어느 쪽으로 포장되는지에 따라 「실행 명령이 있는가」가 갈린다 → [[gradle]] · [[build]]
- **war 를 다시 놓아도 옛 파일이 남는다** — 서비스되는 것은 war 가 아니라 **압축이 풀린 폴더**다. 새 war 를 놓으면 그 폴더에 덮어쓰이는데, **이전 버전에만 있던 파일은 지워지지 않는다.** 그래서 「지운 화면이 계속 열린다」·「고친 JS 가 안 바뀐다」가 나오고, 답은 코드가 아니라 **폴더를 지우고 다시 놓는 것**이다. 배포가 「파일 복사」인 구조에서 상태가 남는다는 것이 이 방식의 성질이다 → [[filesystem-path]]
- **파일 이름이 URL 을 정한다** — 컨텍스트 경로가 폴더(= war 파일) 이름에서 오므로, **같은 앱을 다른 이름으로 두 번 놓으면 두 URL 에 두 벌이 뜬다.** 각자 세션을 갖고 각자 스케줄러를 돌리므로 「왜 메일이 두 번 가나」 같은 증상이 여기서 난다. 반대로 이름을 바꾸면 **밖에 알려 둔 URL 이 전부 깨진다** — 배포물의 파일명이 계약의 일부라는 뜻이다 → [[web-server]]
- **간접실행/직접실행은 이 필기의 이름이고 표준 용어가 아니다** — 실무에서는 embedded(서버를 품는다)와 standalone·외부 톰캣(서버가 밖에 있다)으로 부른다. 필기의 이름만 외우면 같은 것을 말하면서 대화가 안 된다. 갈리는 실질은 하나다 — **서버 버전이 내 빌드에 적혀 있는가** → [[tomcat]]
- **Eclipse 배치는 재현되지 않는다** — 「Eclipse임시 배치 폴더에 웹프로젝트가 생성된다」인데, 그 폴더는 IDE 가 관리하는 작업 영역 안이라 **빌드 산출물이 아니다.** IDE 에서는 되고 서버에서는 안 되는 상태가 여기서 만들어지고, 원인이 코드가 아니라 **IDE 가 대신 해 준 일**(클래스 위치 연결·라이브러리 복사)에 있어서 찾기 어렵다. 필기의 이 줄이 「서버를 Pulishgkaus Eclipse임시 배치 폴더에」로 깨져 있어 **절차 자체가 기록에 남지 않았다** — 순서는 서버를 추가하고 프로젝트를 그 서버에 얹은 뒤 Publish 를 실행하는 것이고, 그때 프로젝트가 IDE 의 배치 폴더로 복사된다 → [[build]]
- **배치 ≠ 빌드** — 빌드는 소스를 산출물로 바꾸는 일이고 배치는 그 산출물을 서버가 볼 자리에 놓는 일이다. 위의 `bin/main` 문제가 그 경계에서 난다 — **빌드는 성공했는데 배치가 다른 폴더를 보고 있는** 상태이고, 둘을 한 낱말로 묶어 두면 「빌드가 됐으니 됐다」에서 진단이 멈춘다 → [[build]] · [[classpath]]
- **웹 애플리케이션의 「하나」가 프로세스가 아니라 컨텍스트다** — 앱을 다시 배치하면 그 컨텍스트만 다시 시작되고 서버 프로세스는 계속 돈다. 그래서 **다시 뜨는 것과 다시 켜는 것이 다른 일**이고, 메모리에 있던 세션·쓰레드에 매달린 값·캐시가 사라지는 범위도 갈린다 → [[servlet-container]] · [[thread-local]]

Eclipse 배치 절은 「서버를 Pulishgkaus Eclipse임시 배치 폴더에 웹프로젝트가 생성된다」로 문장이 깨져 **절차가 기록에 남지 않았다**
