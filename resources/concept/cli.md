# 명령줄 인터페이스 (CLI)

글자를 입력해 컴퓨터에 명령을 내리는 방식. Command-Line Interface 의 줄임말이다.

## 정의

사용자가 컴퓨터에 지시를 전달하는 방식은 크게 둘이다.

- **CLI** — 명령어를 글자로 입력한다. 한 줄이 하나의 지시다.
- **GUI** — 화면의 요소를 가리키고 누른다.

같은 프로그램이 두 방식으로 배포되기도 한다. Git 도 CLI 버전과 GUI 버전이 따로 있고, 부트캠프에서는 CLI 버전을 받았다.

## 사용 예시

Git Bash 에서 사용자 폴더로 이동해 작업 폴더를 만드는 과정이 명령어 네 줄이다.

```bash
pwd          # 현재 위치 확인 — 처음 열면 root 에 있다
cd           # 사용자 폴더로 이동
mkdir git    # git 폴더 생성
ls           # 만들어졌는지 확인
```

각 줄이 독립된 지시이고, 결과를 보고 다음 줄을 정한다. 폴더를 만들었는지 확인하는 것까지 명령어다 — GUI 라면 눈으로 보고 끝나는 단계가 CLI 에서는 `ls` 라는 지시가 된다.

## 왜 중요한가

**서버에는 화면이 없다.** 원격의 기계를 다룰 때 GUI 를 띄울 수 없으므로, CLI 를 못 쓰면 서버 작업 자체를 시작할 수 없다.

자원 소비가 적다는 이점도 여기서 온다. 화면을 그리지 않으니 안정성·속도·용량 면에서 유리하고, 원격 작업처럼 대역폭이 제한된 상황에서 차이가 커진다.

그리고 명령이 **글자로 남는다**는 성질이 크다. 글자는 파일에 적어 다시 실행할 수 있어서, CLI 로 하는 일은 그대로 자동화의 재료가 된다. 마우스 조작에는 이 성질이 없다.

## 경계와 오해

- **CLI ≠ 터미널 ≠ 셸** — 터미널은 글자를 주고받는 창, 셸(`bash`·`zsh`)은 입력을 해석해 실행하는 프로그램, CLI 는 그 방식 전체를 부르는 이름이다. "터미널을 배운다"는 말이 실제로는 셸 문법을 배우는 것인 경우가 많다.
- **CLI 는 Command-Line Interface 다** — Character User Interface(CUI)는 별개의 약어다. 옛 필기에 둘을 같은 말의 줄임으로 적어 두었는데, 갈라서 기억하는 것이 맞다.
- **CLI 가 GUI 보다 항상 빠른 것은 아니다** — 이점은 자원 소비와 원격·자동화 쪽이다. 명령어를 외우기 전까지는 GUI 보다 느리고, 그 학습 비용은 실제로 존재한다.
