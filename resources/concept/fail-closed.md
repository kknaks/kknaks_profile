# fail-closed — 판정하지 못하면 막는다

**확신이 없을 때 어느 쪽으로 넘어질지 미리 정해 두는 것.** 모르는 입력·미선언 기능·확인 안 된 출처를 **통과가 아니라 차단**으로 처리한다.

## 정의

```
[fail-open]    판정 실패 → 일단 통과시킨다      가용성을 지키고 위험을 받는다
[fail-closed]  판정 실패 → 막는다              위험을 막고 가용성을 내준다
```

**둘 중 하나를 안 고르면 「구현이 우연히 정하는」 상태가 된다.** 검증 코드에 없는 분기로 값이 새어 나가는 것이 대개 그 결과다.

### 어디에 걸리나

| 경계 | 모르는 것이 오면 |
|---|---|
| 직렬화 | 모르는 필드 → 막는다 (버전이 앞서간 데이터를 조용히 먹지 않는다) |
| 외부 실행 | 보안 판정이 안 되면 → 실행하지 않는다 |
| 툴·권한 | 등록·허용·검증·정책 중 하나라도 못 넘기면 → 실행에 닿지 않는다 |
| 값 변환 | 선언되지 않은 기능 → 지원한다고 보지 않는다 |

**경계마다 다시 적용한다.** 한 층에서 막았다고 다음 층이 믿지 않는다 → [[interface]]

## 왜 중요한가

**틀렸을 때의 비용이 비대칭이기 때문이다.** 막아서 생기는 것은 「안 된다」는 즉시 보이는 실패이고, 통과시켜 생기는 것은 **나중에 다른 곳에서 터지는** 실패다. 앞의 것이 훨씬 싸다 → [[exception-handling]]

**그리고 회복 경로를 근거 없이 만들지 않게 한다.** 실패했을 때 무엇을 할지는 실제로 실패를 본 뒤에 정하는 편이 낫다 — 추측으로 만든 회복 코드는 대개 안 도는 코드다.

## 경계와 오해

- **fail-open 이 맞는 자리도 있다** — 읽기 전용 조회나 관측처럼 **막는 비용이 통과 비용보다 큰** 곳이다. 「무조건 막는 것」이 아니라 **어느 쪽 비용이 큰지로 고르는 것**이다 → [[monitoring]]
- **가용성을 깎는다** — 모르는 것을 막으므로 상류가 새 필드를 더하면 하류가 멈춘다. **버전 협상이 함께 있어야** 한다 → [[serialization]]
- **막는 것만으로는 부족하다** — 왜 막혔는지가 안 남으면 운영에서 원인을 못 짚는다. 차단과 기록은 한 벌이다
- **기본값이지 예외 없음이 아니다** — 명시적으로 허용을 선언한 것은 통과한다. 그 선언이 어디 있는지가 계약이다
- **「검증 안 함」은 fail-open 이다** — 아무것도 안 하면 통과한다. 판정을 안 넣은 것과 fail-open 을 고른 것은 결과가 같고, **고른 적 없다는 점만 다르다**
