# IP 주소 (IP Address)

**네트워크 안에서 기계 하나를 가리키는 번호.** Day45 의 정의가 「IP주소 : 포트 전까지 컴퓨터의 위치」이고, 포트와 짝을 이뤄 「어느 기계의 어느 프로그램」을 완성한다.

## 정의

주소가 두 칸으로 나뉘어 있고 IP 가 앞 칸이다.

| 칸 | 가리키는 것 | Day45 의 비유 |
|---|---|---|
| IP 주소 | 기계 | 건물의 주소 |
| 포트 번호 | 그 기계 위의 프로그램 | 상세 주소 |

「포트 전까지」라는 표현이 정확하다 — **IP 만으로는 무엇을 하는지 정해지지 않는다.** 건물 앞까지 갈 수 있지만 몇 호에 들어갈지는 아직 모르는 상태이고, 그래서 소켓 생성자는 두 값을 함께 받는다.

```java
Socket socket = new Socket("IP주소",(int) 포트번호);
```

**클라이언트만 이 값을 갖는다.** 서버 코드에는 IP 가 없다 — 자기 기계로 들어온 것을 받는 쪽이라 자기 주소를 적을 이유가 없다. **주소를 아는 것은 찾아가는 쪽의 일**이라는 것이 이 비대칭의 내용이다 → [[socket]] · [[client-server-model]]

가장 먼저 쓰게 되는 값이 자기 자신을 가리키는 주소다.

```java
Socket socket = new Socket("127.0.0.1", 8888);   // 같은 컴퓨터
```

`127.0.0.1`(= `localhost`)은 **네트워크 카드로 나가지 않고 OS 안에서 되돌아오는 주소**다. 서버와 클라이언트를 한 컴퓨터에서 함께 띄워 볼 수 있는 것이 이것 때문이고, Day45 의 실습이 성립하는 조건이기도 하다.

### 같은 날 Day46 — 주소가 타입을 얻는다

Day45 가 문자열로만 넘기던 값에 Day46 이 **전용 클래스**를 붙인다 — 「Java에서는 IP주소를 사용하기 위해 java.net패키지의 InetAddress로 표현한다」.

```java
InetAddress ia = InetAddress.getLocalHost();            // 내 기계의 주소
InetAddress ia = InetAddress.getByName(도메인);          // 이름으로 얻는다
String IP = InetAddress.getHostAddress();               // 점 넷 표기로 꺼낸다
```

**세 줄이 하는 일이 다르다** — 앞 둘은 주소를 **얻고**, 마지막은 얻은 것을 **문자열로 꺼낸다.** 객체가 중간에 있으므로 「어디서 왔는지」와 「어떻게 적히는지」가 갈리고, `Socket` 생성자도 문자열 대신 이 객체를 받는 형태가 따로 있다 → [[socket]] · [[domain-name-system]]

그리고 Day46 이 주소가 붙는 자리를 한 줄로 못 박는다 — 「IP 주소 : 컴퓨터의 고유 주소로 **LAN카드 마다 할당된다**」. **같은 문장 안에서 「컴퓨터의 고유 주소」와 어긋나는데**, 뒤쪽이 맞다 → [[computer-network]]

마지막 줄은 그대로는 컴파일되지 않는다 → 아래 「경계와 오해」

## 왜 중요한가

**「내 컴퓨터에서는 됐는데」의 절반이 이 값이다.** 개발 중에는 `127.0.0.1` 로 통하던 코드가 클라이언트를 다른 기계로 옮기는 순간 안 된다 — 그 기계의 `127.0.0.1` 은 자기 자신이다. **주소를 코드에 적어 두면 배포가 곧 코드 수정**이 되고, 그래서 접속 주소는 대개 설정 파일이나 실행 인자로 뺀다 → [[command-line-arguments]]

**어디까지 도달할 수 있는가가 이 값의 종류로 정해진다.** 집·사무실 안에서만 유효한 주소(`192.168.x.x` 같은 사설 주소)와 인터넷에서 찾아갈 수 있는 주소가 다르고, 사설 주소를 쓰는 서버는 **바깥에서 IP 와 포트를 알아도 닿을 수 없다.** 「서버는 떠 있고 포트도 맞는데 접속이 안 된다」의 남은 절반이 여기다.

## 경계와 오해

- **IP 주소 ≠ 도메인 이름** — `new Socket("localhost", 8888)` 처럼 이름을 넣어도 되므로 둘이 같은 것으로 보이는데, **이름은 번호로 바뀐 뒤에 쓰인다.** 그 변환(DNS 조회)이 접속 전에 한 번 더 일어나므로 실패하는 방식이 두 가지가 된다 → [[domain-name-system]] — 이름을 못 찾는 것(`UnknownHostException`)과 찾았는데 붙지 못하는 것(`ConnectException`)이다. **같은 「접속 안 됨」인데 원인이 이름 쪽인지 서버 쪽인지가 예외 종류로 갈린다** → [[exception-handling]]
- **IP 주소 ≠ 컴퓨터 하나** — 「컴퓨터의 위치」로 외우면 1:1 로 읽히는데 실제로는 **네트워크 연결마다 하나**다(Day46 의 「LAN카드 마다 할당된다」가 이것을 정확히 적은 표현이다). 유선과 무선을 함께 쓰는 기계는 주소가 둘이고, 그 둘 다 자기 자신이다. 반대로 여러 기계가 하나의 공인 IP 를 공유하기도 한다(NAT). **주소와 기계가 1:1 이 아니라서** 서버가 어느 주소로 들어온 접속을 받을지도 선택 사항이 된다.
- **`"IP주소"` 는 문자열이지만 임의의 문자열이 아니다** — `new Socket(String, int)` 이 문자열을 받으므로 컴파일은 무엇을 넣어도 통과한다. **형식이 틀린 주소는 실행 시점에야 드러나고**, 그것도 「형식 오류」가 아니라 「그런 호스트 없음」으로 나온다. Day45 의 코드가 `"IP주소"` 라고 적어 둔 그대로 실행하면 정확히 그 예외다. Day46 의 `InetAddress` 가 이 문제에 대한 자바의 답이다 — **주소를 문자열이 아니라 타입으로 들고 다니면** 검사가 만들 때 한 번 끝나고, 그 뒤로 넘겨 다니는 값은 이미 확인된 것이 된다 → [[data-type]] · [[immutability]]
- **`String IP = InetAddress.getHostAddress();` 는 컴파일되지 않는다 — 원본 코드의 실제 결함이다** — `getHostAddress()` 는 **인스턴스 메서드**라 객체 없이 클래스 이름으로 부를 수 없다. 맞는 형태는 바로 위 두 줄에서 얻은 객체를 쓰는 `ia.getHostAddress()` 다. **원인이 바로 위 두 줄에 있다** — `getLocalHost()`·`getByName()` 이 정적 메서드라서 `InetAddress.` 로 시작하는 형태가 세 줄 내리 눈에 익었고, 셋째 줄만 성질이 다른 것이 안 보였다. 같은 클래스에 정적 메서드와 인스턴스 메서드가 섞여 있을 때 나오는 전형적인 실수이고, **「어떻게 얻나」와 「무엇을 물어보나」가 같은 이름 아래 있는 것**이 이 클래스의 설계다 → [[static-member]] · [[method]]
- **「내 IP」에는 정답이 없다** — `getLocalHost()` 가 하나를 돌려주지만 **카드가 여럿이면 어느 것인지는 정해지지 않는다.** 이 메서드는 호스트 이름을 먼저 알아내 그것을 다시 주소로 바꾸는 방식이라, 설정에 따라 `127.0.0.1` 을 주기도 한다 — **그 값을 남에게 「나에게 접속할 주소」로 알려 주면 상대는 자기 자신에게 붙는다.** 서버 코드에 자기 IP 가 필요 없는 이유가 여기서 한 번 더 나온다 → [[domain-name-system]] · [[socket-binding]]
- **IPv4 는 32비트라 개수가 정해져 있다** — `0~255` 네 칸으로 적는 것이 32비트를 8비트씩 나눈 표기이고, 그래서 `192.168.1.300` 같은 값은 존재할 수 없다. 주소가 모자라서 나온 것이 사설 주소·NAT·IPv6 이고, **「주소가 유한하다」가 위의 「IP ≠ 컴퓨터 하나」를 만든 원인**이다 → [[data-type]]
- **`localhost` 로 되는 것과 남이 붙을 수 있는 것은 다른 문제다** — 서버가 어느 주소로 들어온 접속을 받을지는 바인딩할 때 정해지는데, 자기 자신만 받도록 묶어 두면 같은 기계에서는 되고 밖에서는 안 된다. **테스트가 통과하는 것이 접속 가능함의 증거가 아니다** — Day45 의 실습은 한 컴퓨터 안에서 도는 구성이라 이 구별이 나오지 않고, **같은 날 Day46 이 「특정 IP에만 할당하는 방법」으로 그 문법을 준다**(무엇이 달라지는지는 여전히 적지 않았다) → [[socket-binding]]
