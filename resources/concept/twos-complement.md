# 2의 보수 (Two's Complement)

음수를 비트로 저장하는 방법. **1의 보수(비트 반전)에 1을 더한 값**이며, Java 를 비롯한 대부분의 언어가 이 방식을 쓴다.

## 정의

음수를 담는 방법은 세 번에 걸쳐 정해졌다. 앞의 둘이 왜 버려졌는지가 이 개념의 내용이다.

### 1. Sign-Magnitude — 부호 비트 + 절대값

최상위 비트를 부호로 쓰고(양수 `0`, 음수 `1`) 나머지에 절대값을 담는다. 간단하지만 두 가지가 깨진다.

```plaintext
0001 (1) + 1001 (-1) = 1010 (-2) ?!
```

- **덧셈이 성립하지 않는다** — 부호를 따로 보고 분기해야 한다
- **0 이 둘이다** — `+0` 과 `-0` 이 다른 비트열이 된다

그래서 일반 정수에는 쓰지 않고, [[floating-point]] 의 **가수부**에 쓰인다.

### 2. 1의 보수 — 비트 반전

주어진 비트를 그대로 뒤집는다. 여전히 양수 + 음수 계산이 어긋나고 0 이 둘이다.

### 3. 2의 보수 — 1의 보수 + 1

1의 보수를 구한 뒤 1 을 더한다. 이렇게 하면 **부호가 다른 같은 수를 더했을 때 0 이 나온다** — 자리 올림이 최상위 밖으로 넘어가(overflow) 버려지기 때문이다.

## 왜 중요한가

**부호를 신경 쓰지 않고 더하기만 하면 된다.** CPU 가 음수를 위한 별도 회로를 갖지 않아도 되고, 뺄셈도 "2의 보수를 더하는 것"으로 처리된다. 하드웨어가 단순해지는 것이 이 방식이 이긴 이유다.

0 이 하나라는 점도 크다. `+0`·`-0` 이 갈리면 "이 값이 0인가"를 비교할 때마다 두 경우를 봐야 하는데, 그 문제가 사라진다.

## 경계와 오해

- **음수 범위가 양수보다 하나 넓다** — 0 이 하나로 합쳐진 자리만큼 음수가 하나 더 들어간다. `byte` 가 `-128 ~ 127` 인 이유이고, 그래서 `-128` 의 절댓값은 같은 타입에 담기지 않는다.
- **최상위 비트는 부호 비트가 아니다** — 2의 보수에서 최상위 비트가 1이면 음수인 것은 맞지만, 나머지 비트가 절대값인 것은 아니다. sign-magnitude 와 혼동되는 지점이다.
- **overflow 가 버그가 아니라 원리다** — 부호 다른 수를 더해 0 이 나오는 것은 자리 올림이 버려지기 때문이고, 이것이 정상 동작이다.
