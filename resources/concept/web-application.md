# 웹 애플리케이션 (Web Application)

내려받아 설치하지 않고, 웹 브라우저 위에서 통신을 통해 이용하는 소프트웨어.

## 정의

컴퓨터에서 출발해 네 번 갈라 내려오면 웹 애플리케이션에 도달한다.

| 갈림 | 두 갈래 | 웹 애플리케이션이 속한 쪽 |
|---|---|---|
| 컴퓨터 | 하드웨어 / 소프트웨어 | 소프트웨어 |
| 소프트웨어 | System S/W / Application S/W | Application S/W |
| 애플리케이션 | Standalone / Client·Server | Client/Server |
| 클라이언트/서버 | 설치형 / 비설치형 | **비설치형** |

각 갈래의 기준은 아래와 같다.

- **하드웨어** — CPU·HDD·RAM 처럼 컴퓨터의 물리적 부분
- **소프트웨어** — 컴퓨터 프로그램과 그에 수반되는 문서
- **System S/W** — 하드웨어를 제어하는 소프트웨어 (OS, 드라이버, 임베디드, IoT)
- **Application S/W** — System S/W 를 제외한 응용프로그램 (MS-Office, LoL)
- **Standalone** — 외부 소프트웨어의 도움 없이 설치 후 독자적으로 실행 (MS-Office)
- **Client/Server** — 외부 소프트웨어와 통신해야 실행 (LoL) → [[client-server-model]]
- **설치형** — 프로그램을 내려받아 실행하며 그것이 외부와 통신
- **비설치형** — 내려받지 않고 웹 브라우저를 통해 실행 → **웹 애플리케이션**

### 통신 상대편에 있는 것

브라우저 반대편은 하나가 아니다. 웹 애플리케이션에 필요한 기술은 **웹 서버와 DBMS 사이의 통신**을 위한 것들이다 — 요청을 받아 처리하는 쪽(웹 서버)과 데이터를 보관하는 쪽(DBMS)이 따로 있고, 그 둘을 잇는 기술이 필요하다.

## 왜 중요한가

"웹 개발"이 무엇을 만드는 일인지를 이 분류가 정한다. 웹 애플리케이션은 클라이언트/서버의 한 종류이므로 **서버가 없으면 성립하지 않는다** — 브라우저에 보이는 화면은 절반이고, 나머지 절반은 웹 서버와 DBMS 로 통신 상대편에 있다. 백엔드가 왜 따로 있어야 하는지가 여기서 나온다.

비설치형이라는 성질에서 배포의 성격도 갈린다. 설치형은 사용자가 새 버전을 내려받아야 바뀌지만, 웹 애플리케이션은 서버만 갱신하면 다음 접속부터 모두가 새 버전을 본다.

## 경계와 오해

- **웹 애플리케이션 ≠ 웹사이트** — 브라우저로 열린다는 것만으로는 가르지 못한다. 읽기만 하는 정적 페이지도 브라우저로 열리지만, 그 안에서 **기능이 동작하는가**가 애플리케이션이라 부르는 기준이다.
- **비설치형 ≠ 설치가 아예 없다** — 브라우저는 이미 깔려 있어야 한다. 내려받지 않는 것은 **그 애플리케이션**이고, 실행 환경은 있다는 전제다.
- **Standalone ≠ 오프라인 전용** — 기준은 네트워크를 쓰는지가 아니라 외부 소프트웨어에 **의존해야 실행되는가**다.
