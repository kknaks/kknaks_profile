# 클라이언트/서버 (Client/Server)

외부 소프트웨어와 통신해야 비로소 실행되는 애플리케이션 구조. 요청하는 쪽(클라이언트)과 응답하는 쪽(서버)으로 나뉘어 있다.

## 정의

애플리케이션은 실행에 외부가 필요한지로 먼저 갈린다.

- **Standalone** — 외부 소프트웨어의 도움 없이 설치 후 독자적으로 실행 가능 (MS-Office)
- **Client/Server** — 외부 소프트웨어와의 통신을 통해 실행 (LoL)

클라이언트/서버는 다시 클라이언트를 어떻게 얻는지로 갈린다.

- **설치형** — 프로그램을 내려받아 실행하고, 그 프로그램이 서버와 통신한다
- **비설치형** — 내려받지 않고 웹 브라우저가 클라이언트 역할을 한다 → [[web-application]]

## 왜 중요한가

이 구조를 택하면 **프로그램의 절반이 내 컴퓨터에 없다.** 그래서 standalone 에서는 없던 문제가 전부 새로 생긴다 — 통신이 실패할 수 있고, 상대가 응답하지 않을 수 있고, 양쪽 버전이 어긋날 수 있다. 서버·네트워크·프로토콜을 배우는 이유가 여기서 시작한다.

역으로 얻는 것은 **한 곳만 고치면 된다는 성질**이다. 로직과 데이터가 서버에 있으면 클라이언트를 전부 다시 배포하지 않고도 동작을 바꿀 수 있다.

## 경계와 오해

- **클라이언트/서버 ≠ 컴퓨터 두 대** — 역할의 구분이다. 한 대 안에서 클라이언트와 서버가 함께 돌 수도 있다(로컬 개발이 그렇다).
- **Standalone ≠ 네트워크를 안 쓴다** — 업데이트 확인처럼 통신을 하더라도 통신 없이 **본래 기능이 실행되면** standalone 이다. 기준은 통신 여부가 아니라 실행 의존이다.
