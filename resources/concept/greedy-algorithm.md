# 그리디 (정렬해서 앞에서부터 고르기)

**지금 가장 좋아 보이는 것을 고르고 되돌아보지 않는 것.** 대개 **정렬이 먼저**이고, **무엇을 기준으로 정렬하느냐**가 풀이의 전부다 → [[sorting]]

## 정의

```
1. 무엇을 기준으로 정렬할지 정한다   ← 여기가 문제의 핵심
2. 앞에서부터 하나씩 본다
3. 조건에 맞으면 고르고, 아니면 건너뛴다
```

이 문제집의 네 문제가 **전부 「무엇으로 정렬하나」에서 갈린다.**

| 문제 | 정렬 기준 | 고르는 규칙 |
|---|---|---|
| 회의실 배정 | **끝나는 시간** | 겹치지 않으면 고른다 |
| 소가 길을 건너는 시간 | **도착 시간** | 현재 시각과 비교해 검사 시간을 더한다 |
| 순회 강연 | 날짜 | 큐가 날짜를 넘으면 **가장 싼 것을 버린다** → [[priority-queue]] |
| 먹방 라이브 | 남은 시간이 짧은 순 | 짧은 것부터 없앤다 |

**회의실 배정이 전형이다** — 시작 시간으로 정렬하면 틀리고 **끝나는 시간으로 정렬해야** 맞는다. 빨리 끝날수록 뒤에 더 많이 들어가기 때문이다.

## 왜 중요한가

**전부 보지 않고 답에 닿는다.** 완전탐색이 모든 조합을 보는 자리에서, 그리디는 **한 번 훑고 끝낸다** — 정렬 O(n log n) 에 순회 O(n) 이다 → [[time-complexity]] · [[brute-force]]

**그리고 「기준을 찾는 것」이 곧 문제를 이해하는 것이다.** 정렬 기준이 정해지면 코드는 열 줄이고, 정해지지 않으면 아무리 코드를 고쳐도 안 맞는다.

## 경계와 오해

- **그리디가 언제나 맞지는 않는다** — 「지금 최선」이 「전체 최선」이 되는 문제에서만 성립한다. 성립하지 않으면 **되돌아보는 방법**(완전탐색·DP)이 필요하다
- **기준을 잘못 잡으면 조용히 틀린다** — 회의실 배정을 **시작 시간**으로 정렬하면 예제는 통과하고 반례에서 틀린다. **왜 그 기준인지 설명할 수 있어야** 안심할 수 있다
- **정렬 기준이 둘 이상일 수 있다** — 먹방 문제가 「음식 시간」과 「음식 번호」 두 축을 함께 본다. 비교 함수에서 **1순위가 같을 때 2순위**를 정해야 한다 → [[sorting]]
- **「되돌아보지 않는다」에 예외를 두는 형태도 있다** — 순회 강연은 일단 넣었다가 **초과하면 가장 싼 것을 다시 뺀다.** 우선순위 큐가 그 「빼기」를 O(log n) 에 해 준다 → [[priority-queue]]
- **증명을 못 해도 반례는 찾아봐야 한다** — 이 문제집이 「반례, 경계값」을 항목으로 둔 이유다. 그리디는 **반례 하나로 무너진다**

## 출처

- [[2025-07-09-pr1931]] — 회의실 배정. **그리디의 교과서**이고, 이 문제집은 「정렬을 통한 그리디 / 도착 시간 기준으로 정렬 / 현재시간과 도착시간을 비교」로 절차를 적었다
- [[2025-07-08-pr14469]] — 소가 길을 건넌 이유. **앞 문제와 같은 골격**을 다른 문장으로 만난 자리다 — 도착 시간으로 정렬하고 현재 시각과 비교해 검사 시간을 더한다. 두 노트의 「사용 알고리즘」이 거의 같은 문장인 것이 그 증거다
- [[2025-07-07-pr2109]] — 순회 강연. **넣었다가 빼는 그리디**로 한 걸음 나간다 — 날짜로 정렬해 큐에 넣고, 「큐 사이즈 > 날짜」면 가장 싼 강연을 뺀다 → [[priority-queue]]
- [[2025-07-04-pr]] — 먹방 라이브. 「가장 빨리 먹는 음식(시간이 가장 짧은) 기준으로 회전 → **그리디 알고리즘**」이고, **두 기준(음식 시간·음식 번호)** 이 필요해 map·우선순위 큐를 함께 쓴다
