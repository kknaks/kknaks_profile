# URI · URL · URN (자원 식별자)

**인터넷의 자원 하나를 가리키는 문자열, 그리고 「어디에 있나」로 가리키는 것(URL)과 「무엇이라 불리나」로 가리키는 것(URN)을 합쳐 부르는 상위 이름(URI).** Day65 가 세 줄로 정확히 적었다 — 「URI는 일반적으로 URL과 URN을 포함하는 상위 개념이다」·「URN은 자원의 위치에 의존하지 않고, 그 자원의 고유한 이름을 나타낸다」·「URL은 자원의 접근 방법(프로토콜)과 그 자원이 위치한 장소를 나타낸다」 → [[computer-network]] · [[servlet]]

## 정의

셋의 관계는 **포함이고, 가르는 축은 하나다** — 위치로 찾는가 이름으로 찾는가.

| | 무엇으로 가리키나 | Day65 의 문장 | 예 |
|---|---|---|---|
| **URI** | (상위 개념) | 「인터넷에 있는 자원의 식별자 … 식별하고 위치를 나타내는 데 사용」 | 아래 둘 전부 |
| **URL** | **위치** — 접근 방법 + 있는 곳 | 「자원의 접근 방법(프로토콜)과 그 자원이 위치한 장소」 | `http://localhost:8080/user/view?no=3` |
| **URN** | **이름** — 위치와 무관 | 「위치에 의존하지 않고, 그 자원의 고유한 이름」 | `urn:isbn:9788968481901` |

**URL 은 「옮기면 달라지는」 식별자이고 URN 은 「옮겨도 같은」 식별자다.** 그래서 URL 은 깨질 수 있고(문서를 옮기면 링크가 죽는다) URN 은 깨지지 않는 대신 **그것만으로는 가져올 수 없다**(어디 있는지를 따로 찾아 줘야 한다). 웹이 URL 로 굴러가는 이유가 그 두 번째 문장이다.

### URL 의 조각

Day65 의 코드에 나온 URL 을 펼치면 조각이 이렇게 갈린다.

```text
http://localhost:8080/user/view?no=3
└─┬─┘  └───┬────┘└─┬┘└───┬───┘└─┬──┘
스킴     호스트    포트   경로    쿼리 스트링
```

| 조각 | 정하는 것 | Day65 에 나온 자리 |
|---|---|---|
| 스킴 | 어떤 규칙으로 말을 거나 | (생략 — 상대 경로만 쓴다) |
| 호스트 · 포트 | 어느 기계의 어느 문 | 톰캣 부팅 코드의 `setPort` → [[tomcat]] · [[port-number]] |
| 경로 | 그 안의 어느 자원 | `@WebServlet("/user/view")` 의 문자열 |
| 쿼리 스트링 | 그 자원에 딸린 값 | `?no=3` · `?name=…&email=…` → [[request-parameter]] |

**Day61 까지 사람에게 물어보던 것이 이 한 줄에 다 들어 있다.** [[client-server-model]] 노트가 Day63 을 두고 「Day61 에서 사용자에게 묻던 서버 주소와 포트가 URL 로 옮겨 가는 것도 이 회차의 결과다」라고 적어 둔 자리가 여기서 실물이 된다 — 주소·포트·무엇을 할지·인수까지가 **문자열 하나**로 접혔다 → [[socket-binding]] · [[network-protocol]]

## 사용 예시

Day65 의 목록 화면이 **다음 화면으로 갈 URL 을 만들어 심는다.**

```java
out.println("<p><a href='/user/form.html'>새 회원</a></p>");

for (User user : userDao.list()) {
  out.printf("      <tr><td>%d</td><td><a href='/user/view?no=%1$d'>%s</a></td><td>%s</td></tr>\n",
      user.getNo(), user.getName(), user.getEmail());
}
```

그리고 필기가 링크의 골격을 따로 적었다 — 「태그에 링크를 연결하기 위해서는 `<a href="url">내용</a>`를 작성한다」.

**이 두 줄이 이 회차의 화면 이동 전부다.** 회원마다 `?no=` 뒤의 숫자만 다른 URL 이 생기고, 그것을 누르면 `@WebServlet("/user/view")` 가 붙은 클래스가 그 숫자를 받는다. 즉 **URL 이 「어느 클래스」와 「어느 데이터」를 한꺼번에 지정한다** — 앞쪽은 경로가, 뒷쪽은 쿼리 스트링이 → [[dispatch-table]] · [[primary-key]]

정적 자원도 같은 방식으로 가리킨다.

```java
out.println("    <link href='/css/common.css' rel='stylesheet'>");
out.println("  <a href='/'><img src='/images/home.png'></a>");
```

**한 화면이 요청 하나로 끝나지 않는다** — 서블릿이 만든 HTML 한 장이 CSS·이미지 URL 을 가리키고, 브라우저가 그것을 다시 요청한다. 문서를 만드는 것과 딸린 자원을 내보내는 것이 다른 주체인 것도 여기서 갈린다 → [[static-and-dynamic-content]]

## 왜 중요한가

**URL 이 코드와 화면을 잇는 유일한 끈이고, 그 끈을 아무도 검사하지 않는다.** `href='/user/view?no=…'` 의 문자열과 `@WebServlet("/user/view")` 의 문자열이 같아야 화면이 이어지는데, 둘은 서로를 모르는 두 문자열이다. 한 글자가 틀리면 컴파일도 되고 기동도 되고 **누를 때 404** 다. [[servlet-context]] 의 문자열 키 문제가 「리스너와 서블릿 사이」였다면 여기서는 **「내가 만든 HTML 과 내 클래스 사이」**로 한 번 더 나타난다 → [[literal]] · [[annotation]]

**그리고 값을 URL 에 실으면 그 값이 URL 이 가는 모든 곳에 간다.** 브라우저 주소창·히스토리·북마크·서버 액세스 로그·다음 요청의 리퍼러 헤더가 전부 URL 을 그대로 들고 있다. 「전송되는가」만 보면 GET 과 POST 가 같아 보이지만, **남는가**에서 갈린다 — 이 회차의 폼이 암호를 URL 에 실어 보내는 것이 정확히 그 차이에 걸린 자리다 → [[html-form]]

**URI 와 URL 을 갈라 두면 「식별과 접근이 다른 일」이 보인다.** 이름만 알고 어디 있는지 모르는 상태가 성립하고(URN), 그것이 자원을 옮겨도 참조가 살아 있게 만드는 유일한 길이다. REST 의 「자원마다 URI 를 준다」나 XML 의 네임스페이스 URI 처럼 **가져오지 않는데 URI 인 것들**이 이 구분 위에 서 있다 → [[xml]]

## 경계와 오해

- **URL ≠ URI — 그런데 실무에서 섞어 쓰는 것이 대개 맞는 이유가 따로 있다** — 필기가 포함 관계를 정확히 적었으므로 개념은 갈렸다. 문제는 **웹에서 만나는 URI 가 거의 전부 URL** 이라는 것이다(`urn:` 으로 시작하는 문자열을 브라우저 주소창에 넣을 일은 없다). 그래서 「URI 라고 쓰여 있으면 URL 을 뜻한다」가 대개 맞고, **그 습관 때문에 진짜 URN 을 만났을 때 「왜 이건 열리지 않나」가 된다** — 열리지 않는 것이 정상이고, URN 은 열려고 만든 것이 아니다.
- **`/css/common.css` 는 「앱의 루트」가 아니라 「호스트의 루트」다 — 이 회차에서는 두 개가 같아서 드러나지 않는다** — `/` 로 시작하는 경로는 컨텍스트 경로를 포함하지 않는다. 이 실습은 톰캣을 임베디드로 띄워 앱이 루트(`/`)에 붙어 있으므로 잘 동작하지만, 같은 코드를 `myapp.war` 로 만들어 `webapps` 에 넣으면 실제 주소가 `/myapp/css/common.css` 가 되어 **CSS·이미지·모든 링크가 한꺼번에 깨진다.** Day63 이 배치 방법 세 가지를 적었으므로 이 코드는 이미 두 번째 방법 위에서 깨질 준비가 돼 있고, 증상이 「스타일이 안 먹는다」로만 보여서 원인이 멀다. 답은 경로를 `request.getContextPath()` 로 앞에 붙이는 것이고 필기에는 없다 → [[web-application-deployment]] · [[servlet-context]]
- **쿼리 스트링은 경로가 아니다 — 그래서 서블릿 매핑에는 쓸 수 없다** — `@WebServlet` 이 보는 것은 `?` **앞까지**다. `/user/view?no=3` 과 `/user/view?no=7` 은 **같은 서블릿**으로 가고 다른 것은 값뿐이다. 「URL 마다 클래스가 하나」로 읽으면 회원 수만큼 클래스가 필요해 보이는데, 갈라 두면 **클래스는 화면 하나고 값은 인수**라는 것이 보인다 → [[parameter-and-argument]] · [[request-parameter]]
- **URL 인코딩 — 필기의 「URL인코딩」 절은 이미지 한 장만 있고 글이 없다** — 답은 이렇다. URL 에 그대로 쓸 수 있는 글자는 ASCII 중 일부(영문·숫자·`-_.~` 와 몇 개의 구분자)뿐이고, 그 밖의 것은 **바이트로 만든 뒤 `%XX` 두 자리 16진수로** 바꿔 실어야 한다(퍼센트 인코딩). 한글 「홍길동」이 `%ED%99%8D%EA%B8%B8%EB%8F%99` 이 되는 것이 그것이다. 여기서 두 가지가 따라 나온다.
  - **`%XX` 는 문자가 아니라 바이트라서 어느 문자집합으로 바꿨는지가 함께 정해져야 한다.** 보내는 쪽이 UTF-8 로 만들고 받는 쪽이 다른 것으로 읽으면 글자가 깨지고, **URL 자체에는 그 정보를 담는 자리가 없다.** 그래서 요청 쪽 인코딩이 응답 쪽과 따로 정해져야 하는 문제가 생긴다 → [[character-encoding]] · [[unicode]] · [[request-parameter]]
  - **구분자를 인코딩하지 않으면 값이 문법을 침범한다.** 값 안에 `&`·`=`·`#` 이 들어 있으면 그 자리에서 파라미터가 갈리거나 잘린다 — 이름이 `A&B` 인 회원 하나로 뒤가 전부 어긋난다. [[sql-injection]] 이 「데이터를 문법으로 읽는 자리」에서 생겼던 것과 **같은 형태의 문제가 주소 문자열에서** 나타나고, 답도 같다 — 값과 문법을 섞지 않는다.

  그리고 같은 문자가 자리에 따라 다르게 표기된다 — **공백은 경로에서 `%20`, 쿼리 스트링에서는 `+` 로도 쓴다.** 그래서 값에 든 `+` 는 반드시 `%2B` 로 인코딩해야 하고, 그러지 않으면 받는 쪽에서 공백이 된다.
- **「URL 이 자원의 위치를 나타낸다」가 파일의 위치는 아니다** — `/user/view` 라는 디렉토리도 파일도 서버에 없다. 이 회차의 URL 은 **클래스에 붙인 이름**이고, 정적 파일을 가리키는 `/css/common.css` 만 실제 파일 위치와 닮았다. 「위치」를 파일 경로로 읽으면 서블릿 URL 이 왜 아무 모양이나 될 수 있는지가 설명되지 않는다 → [[filesystem-path]] · [[static-and-dynamic-content]]
- **URL 은 대소문자와 끝 슬래시에 민감하다 — 다만 어느 조각인가에 따라 다르다** — 스킴과 호스트는 대소문자를 구별하지 않고, **경로부터는 구별한다.** `/User/View` 는 이 서블릿을 부르지 못한다. `/user/list` 와 `/user/list/` 도 다른 문자열이다. 컴파일러가 검사하지 않는 문자열이라 이 규칙이 오타를 그대로 404 로 만든다 → [[string-comparison]]
- **URL 길이는 규격에 상한이 없지만 실제로는 있다** — 브라우저·서버·프록시가 각자 상한을 두므로(대개 수 KB) 쿼리 스트링으로 큰 값을 보내는 것은 **어느 층에서 잘릴지 모르는** 일이 된다. 이 회차의 등록 폼이 GET 이라 값이 늘면 그 상한에 먼저 닿고, 그것이 「긴 글은 POST」라는 관용의 근거다 → [[html-form]] · [[length-prefix-framing]]
