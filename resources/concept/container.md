# 컨테이너 (Container)

**하나의 운영체제 커널 위에서 서로 영향을 주지 않고 독립적으로 도는 프로세스.** 가상 머신처럼 격리되지만 **운영체제를 따로 띄우지 않으므로** 가볍고 빠르다.

## 정의

```
[가상 머신]                      [컨테이너]
  앱 · 라이브러리                    앱 · 라이브러리
  게스트 OS  ←── 무거운 곳          (게스트 OS 없음)
  하이퍼바이저                      컨테이너 런타임
  호스트 OS · 커널                  호스트 OS · 커널  ←── 공유한다
```

**커널을 공유하는 것이 차이의 전부**다 — 격리는 커널이 제공하는 기능(네임스페이스·cgroup)으로 이루어지고, 그래서 컨테이너는 **결국 프로세스 하나**다 → [[process]]

## 왜 중요한가

**「내 컴퓨터에서는 되는데」가 사라진다.** 애플리케이션과 그것이 필요로 하는 라이브러리·설정을 **함께 묶어** 옮기므로, 실행 환경이 서버마다 다르다는 문제가 없어진다 → [[web-application-deployment]] · [[platform-dependency]]

**그리고 「똑같은 것을 여러 개 띄우기」가 싸진다.** 부하가 늘면 같은 컨테이너를 더 띄우면 되고, 그것이 가능하려면 **애플리케이션이 상태를 갖지 않아야** 한다 — 파일을 서버 디스크가 아니라 스토리지에 두고, 세션을 서버 메모리가 아닌 곳에 두는 이유가 여기서 만난다 → [[object-storage]] · [[http-session]] · [[distributed-processing]]

**스프링 부트가 JAR 하나로 실행되는 것과 짝을 이룬다.** 서버를 따로 설치하지 않고 실행 파일 하나를 담으면 되므로, 부트 이후의 배포는 대개 컨테이너다 → [[spring-boot]]

## 경계와 오해

- **컨테이너는 가상 머신이 아니다** — 커널을 공유하므로 **호스트와 다른 커널이 필요한 것은 못 돌린다.** 「가벼운 VM」으로 읽으면 그 제약이 안 보인다
- **격리가 완전하지 않다** — 커널을 공유한다는 것은 **커널의 취약점이 곧 모두의 취약점**이라는 뜻이다. VM 보다 경계가 얕다
- **컨테이너는 사라지는 것을 전제로 한다** — 안에 쓴 파일은 컨테이너를 지우면 없어진다. 남겨야 하는 것은 **밖(볼륨·스토리지·DB)** 에 둔다 → [[object-storage]]
- **이미지와 컨테이너는 다르다** — 이미지는 **틀**이고 컨테이너는 그것을 실행한 **인스턴스**다. 클래스와 객체의 관계와 같다 → [[instance]]
- **가볍다는 것이 공짜라는 뜻은 아니다** — 컨테이너 하나마다 프로세스와 메모리가 든다. 줄어드는 것은 **게스트 OS 의 몫**이다
- **아키텍처 선택과는 별개다** — 모놀리식 애플리케이션도 컨테이너로 배포한다. 컨테이너가 [[microservice-architecture]] 를 요구하지는 않는다 — **다만 그 아키텍처를 현실적으로 만든 도구이긴 하다**

## 출처

- [[2025-01-13-Day10]] — 엿새 뒤. **컨테이너가 배포 단위가 된다.** `docker build -t ${이미지명} .` 로 만들고 `ghcr.io` 레지스트리에 밀어 두었다가 서버가 받아 실행한다 — **서버에서 소스를 빌드하지 않는다.** `docker run` 의 옵션들이 이 회차에서 자세히 풀린다(`-d`·`--name`·`--restart unless-stopped`·`-p`·`-e`·`-v`), 특히 **볼륨(`-v`)이 왜 필요한지**가 SSL 인증서 보관으로 실물이 된다. 그리고 컨테이너 안에서 호스트의 DB 에 붙을 때 **`172.17.0.1` 로 들어온다**는 것과 그 주소에 권한을 줘야 한다는 함정도 기록됐다 → [[reverse-proxy]] · [[ci-cd]]
- [[2025-01-07-Day06]] — **실제로 쓰는 첫 자리**다. `docker run -p 3306:3306 --name maria_container -e MARIADB_ROOT_PASSWORD=1234 -d mariadb` 한 줄로 DB 를 띄우고 애플리케이션이 `localhost:3306` 으로 붙는다 — **설치 없이 DB 를 갈아 끼울 수 있다**는 것이 컨테이너의 실습상 이점이다. `-p`(포트 연결) · `-e`(환경 변수) · `-d`(백그라운드) 세 옵션과 `docker exec -it ... bash` 로 **안에 들어가 로그를 보는** 것까지가 한 벌로 나온다 → [[port-number]] · [[externalized-configuration]]
- [[2024-10-25-Day102]] — 「컨테이너」 절이 두 줄로 정의한다: **「하나의 운영체제 커널에서 다른 프로세스에 영향을 받지 않고 독립적으로 실행되는 프로세스」**와 「가상화 상태에서 동작하는 프로세스보다 가볍고 빠르게 동작한다」. 짧지만 **커널 공유**와 **프로세스**라는 두 낱말이 정확히 들어 있어, 가상 머신과 갈리는 지점이 정의 안에 담겼다. 이어지는 절이 모놀리식·마이크로서비스 아키텍처를 대비하지만 **원본이 마이크로서비스 설명 도중 끊겨 있어** 도커의 실제 사용(이미지·Dockerfile·명령)은 이 노트에 없다 → [[microservice-architecture]]
