# 암시적 형변환 (Type Promotion)

산술 연산을 할 때 Java 가 피연산자의 타입을 **알아서 맞추는** 것. 가장 자주 걸리는 규칙은 **정수 연산의 최소 단위가 `int`(4바이트)** 라는 것이다.

## 정의

`int` 보다 작은 타입은 연산 전에 `int` 로 승격된다. 임시 4바이트 메모리를 만들어 값을 옮긴 뒤 계산하므로, **결과도 `int` 다.**

```plaintext
byte  + byte  = int
short + short = int
byte  + short = int
```

`int` 이상은 피연산자 타입을 그대로 따른다.

```plaintext
int    + int    = int
long   + long   = long
float  + float  = float
double + double = double
```

타입이 서로 다르면 **큰 쪽으로 맞춘 다음** 연산한다.

## 사용 예시

`byte` 끼리 더하면 결과가 `int` 라서 `byte` 에 담을 수 없다.

```java
byte x = 5, y = 6, z;
z = x;          // OK
z = y;          // OK
// z = x + y;   // 컴파일 오류! x + y 는 int 다
```

그런데 **리터럴끼리 더한 것은 된다.**

```java
byte b;
b = 5;          // OK — 리터럴 5 는 4바이트 정수지만 byte 범위 안이라 허락한다
b = 5 + 6;      // OK — 리터럴끼리의 연산 결과도 리터럴로 간주한다
```

**컴파일 단계에서 값이 얼마인지 확인할 수 있는지가 기준이다.** 리터럴은 컴파일할 때 값이 정해져 있어 범위 검사가 되지만, 변수는 값을 알 수 없으니 타입만 보고 판단한다 → [[literal]]

## 왜 중요한가

**"작은 타입을 쓰면 메모리를 아낀다"가 연산에서는 성립하지 않는다.** 어차피 `int` 로 올려 계산하므로 `byte` 로 선언해도 연산 중에는 4바이트를 쓴다. 그래서 옛 필기의 결론이 이렇다 — **정수를 다룰 때는 크기에 상관없이 그냥 `int` 를 쓰라.** `byte` 는 파일 데이터를 읽어 들일 때처럼 바이트 단위가 의미 있는 곳에 쓴다.

그리고 이 규칙을 알면 **컴파일 오류가 나는 이유를 짐작할 수 있다.** "작은 값을 작은 변수에 넣는데 왜 오류인가"의 답이 연산 결과 타입에 있다.

## 경계와 오해

- **암시적 형변환 ≠ [[type-casting]]** — 이것은 **기본 타입의 값을 바꾸는 것**이고, 타입 변환(업/다운캐스팅)은 참조 변수가 객체를 보는 창을 바꾸는 것이다. 같은 「형변환」이라 불리지만 다른 이야기다.
- **결과를 큰 변수에 담아도 연산은 이미 끝나 있다** — `long r = intX + intY;` 에서 덧셈은 `int` 로 수행된 뒤 `long` 에 복사된다. 넘치면 담기 전에 이미 잘려 있다 → [[overflow]]
- **승격은 값을 잃지 않는다** — 작은 타입에서 큰 타입으로 가는 것이라 안전하다. 반대 방향(큰 → 작은)은 자동으로 되지 않고 명시해야 한다.
