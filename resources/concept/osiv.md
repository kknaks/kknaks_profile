# OSIV (Open Session In View)

**DB 세션(영속성 컨텍스트)을 HTTP 요청이 끝날 때까지 열어 두는 패턴.** 화면을 그리는 동안에도 DB 에 다시 물어볼 수 있게 해 주고, 그 대가로 **커넥션을 요청 내내 붙든다.**

## 정의

JPA/Hibernate 는 조회한 엔티티를 [[persistence-context]] 에 담아 두고, 아직 안 읽은 연관 데이터는 **쓸 때 그때 가져온다**(지연 로딩). 그런데 그 컨텍스트가 서비스 계층에서 닫히면 화면에서 연관 데이터를 만질 수 없다.

```
[OSIV 끔]   요청 ─▶ 컨트롤러 ─▶ 서비스 [세션 열림·닫힘] ─▶ 뷰(세션 없음 — 지연 로딩 실패)
[OSIV 켬]   요청 ─▶ 컨트롤러 ─▶ 서비스 ─▶ 뷰 ────────────────────▶ 응답
                    └───────────── 세션이 여기까지 열려 있다 ─────────┘
```

**스프링에서는 기본이 켜짐**이다(`spring.jpa.open-in-view=true`).

## 왜 중요한가

**편리함의 대가가 커넥션 점유 시간이라는 것이 이 패턴의 전부다.** 화면에서 아무 데이터나 꺼내 쓸 수 있게 되는 대신, **요청 하나가 끝날 때까지 DB 커넥션 하나가 묶인다** → [[data-source]] · [[connection-pool-sizing-formula]]

요청이 짧으면 티가 안 난다. **문제는 요청이 길어질 때** 드러난다.

### SSE 와 겹치면 바로 터진다

[[server-sent-events]] 는 **연결을 몇 분·몇 시간 열어 둔다.** 그 요청이 아직 안 끝났으므로 OSIV 는 커넥션을 계속 붙들고 있고, 결과가 셋이다.

1. **커넥션 고갈** — 동시 접속자 수만큼 커넥션이 묶인다. 풀이 열 개면 **열 명이 접속하는 순간 나머지 요청이 전부 대기**한다
2. **메모리 누수 위험** — 영속성 컨텍스트에 캐시된 엔티티가 계속 쌓인다
3. **처리량 저하** — 동시에 처리할 수 있는 요청 수가 커넥션 풀 크기에 갇힌다

**「연결을 오래 여는 기능」과 「요청 내내 커넥션을 붙드는 설정」이 만나면 안 된다** — 둘 다 각자는 합리적인데 곱하면 상한이 무너진다 → [[little-law]] · [[connection-lifetime-mismatch]]

## 경계와 오해

- **OSIV 는 성능 최적화가 아니라 편의 기능이다** — 얻는 것은 「뷰에서 지연 로딩이 된다」뿐이고, 성능 쪽으로는 **잃기만 한다.** 이름이 패턴이라 좋은 것처럼 읽히는 자리다
- **끄면 코드가 바뀌어야 한다** — 서비스 계층에서 **필요한 것을 다 읽어 내보내야** 하므로, 화면이 쓸 데이터를 미리 정해 조회하거나 DTO 로 변환해 넘긴다. **경계를 명시하게 만드는 것**이 오히려 설계에는 이롭다 → [[service-layer]]
- **커넥션 풀을 키우는 것은 답이 아니다** — SSE 연결 수만큼 커넥션이 필요해지는 구조라면 풀을 늘려도 DB 쪽 상한에서 막힌다. **구조를 바꿔야 하는 종류의 문제**다 → [[connection-pool-sizing-formula]]
- **「기본값이라 켜져 있다」가 가장 위험한 조건이다** — 아무도 켠 적이 없으므로 아무도 의심하지 않는다. 장시간 요청을 만들 때 **먼저 확인할 설정**이다 → [[spring-boot]]
- **커넥션을 붙드는 것과 트랜잭션이 열려 있는 것은 다르다** — OSIV 가 세션을 열어 둘 뿐 트랜잭션은 서비스에서 끝난다. **뷰에서 바꾼 것이 저장되지는 않는다** → [[declarative-transaction]]

## 출처

- [[2025-01-09-Day08]] — 이레 뒤. **열어 두는 그 「세션」이 무엇인지가 채워진다** — 1차 캐시·변경 감지·지연 로딩·동일성 보장을 갖는 영속성 컨텍스트이고, 그것의 원래 수명은 **트랜잭션**이다. OSIV 가 하는 일은 그 수명을 요청 끝까지 늘리는 것이고, 그래서 **뷰에서 지연 로딩이 도는 대신 커넥션이 붙들린다**는 맞바꿈이 성립한다 → [[persistence-context]]
- [[2025-01-02-Day03]] — 「참고. OSIV(Open Session In View)문제」 절이 개념 세 줄과 **SSE 와 함께 쓸 때의 문제 세 가지**(커넥션 고갈 · 메모리 누수 · 성능 저하)를 각각 두세 줄로 적었다. **「OSIV 는 요청이 끝날 때까지 데이터베이스 커넥션을 유지한다 / SSE 는 장시간 연결을 유지하는 특성이 있어, 연결이 끊어질 때까지 데이터베이스 커넥션을 계속 점유한다」**는 두 문장이 이 개념의 핵심 충돌이고, 「다수의 SSE 클라이언트가 연결되면 데이터베이스 커넥션 풀이 빠르게 소진될 수 있다」로 결과까지 이었다. 스프링에서 **기본이 켜짐**(`spring.jpa.open-in-view=true`)이라는 것도 명시했다. 다만 끄면 무엇을 고쳐야 하는지, 커넥션 유지와 트랜잭션 유지가 다르다는 것은 다루지 않았다 → [[server-sent-events]]
