# MAC 주소와 ARP

**랜카드마다 박혀 있는 48비트 고유 번호.** IP 주소가 「어디에 있는가」라면 MAC 주소는 **「어느 장치인가」**다.

## 정의

```
1C-1B-B5-08-A4-26      8비트 단위로 하이픈이나 콜론, 16진수 표기
1C:1B:B5:08:A4:26
└──── OUI ────┘└─ UAA ─┘
```

- **OUI**(Organizational Unique Identifier) — 상위 24비트. **제조사에 부여된 코드**
- **UAA**(Universally Administered Address) — 하위 24비트. 제조사가 그 랜카드에 부여한 번호

**앞이 만든 회사, 뒤가 일련번호**인 셈이라 전 세계에서 겹치지 않는다.

### 프레임에 실린다

데이터링크 계층은 **보내는 MAC + 받는 MAC + 프로토콜 정보**를 헤더로 붙여 프레임을 만든다 → [[data-link-layer]]

헤더의 프로토콜 필드가 「이 프레임 안에 무엇이 들었나」를 알려 준다.

| 값 | 무엇 |
|---|---|
| IPv4 | 32비트 IP 주소 체계 |
| IPv6 | 주소 부족을 푼 128비트 체계 |
| **ARP** | **IP 주소로 MAC 주소를 알아내는** 프로토콜 |

### ARP — IP 는 아는데 MAC 을 모를 때

```
A(192.168.0.2) 가 B(192.168.0.3) 에게 보내려 한다

1. A: "192.168.0.3 쓰는 사람, MAC 주소 뭐예요?"   ← 모두에게 (브로드캐스트, ARP 요청)
2. B: "저예요, 제 MAC 은 ...입니다"                ← ARP 응답
3. A: B 의 IP-MAC 을 표에 적어 둔다                ← ARP 테이블
4. 이제 A 는 B 에게 직접 보낼 수 있다
```

**IP 주소만으로는 프레임을 못 만든다** — 실제로 지목하려면 MAC 이 필요하고, 그 둘을 잇는 것이 ARP 다 → [[ip-address]]

## 왜 중요한가

**주소가 두 층에 따로 있는 이유가 여기서 드러난다.** MAC 은 **바뀌지 않는 장치의 이름**이고 IP 는 **망에서의 위치**다 — 노트북을 다른 사무실로 옮기면 IP 는 바뀌고 MAC 은 그대로다. **위치로 길을 찾고, 이름으로 지목한다** → [[network-layer]]

**그리고 ARP 테이블은 캐시다.** 매번 물어보면 브로드캐스트가 넘치므로 한 번 알아낸 것을 적어 두고 쓴다 → [[caching]]

## 경계와 오해

- **MAC 주소는 「고유」하지만 바꿀 수 있다** — 하드웨어에 박혀 있어도 소프트웨어로 위장할 수 있다. **MAC 으로 인증하는 것이 안전하지 않은 이유**다 → [[spring-security]]
- **ARP 는 물어보고 믿는다** — 「제가 그 IP 예요」라는 응답을 검증하지 않으므로, 거짓 응답으로 통신을 가로챌 수 있다(ARP 스푸핑). **같은 망 안이라는 것이 신뢰의 근거가 되지 못한다**
- **브로드캐스트는 같은 망 안에서만 퍼진다** — 라우터를 넘지 못한다. 그래서 **다른 망의 MAC 은 ARP 로 알 수 없고**, 대신 라우터의 MAC 으로 보낸다 → [[network-layer]]
- **MAC 은 끝까지 안 간다** — 라우터를 지날 때마다 **다음 구간의 MAC 으로 바뀐다.** 출발지·목적지 IP 는 그대로인데 MAC 만 계속 바뀌는 것이 이 두 주소의 성격 차이다
- **IPv4/IPv6/ARP 가 「프로토콜의 종류」로 한 줄에 나열되지만 성격이 다르다** — 앞의 둘은 **주소 체계**이고 ARP 는 **그 둘 사이를 잇는 절차**다. 프레임 헤더의 같은 필드에 들어간다는 점에서만 나란하다

## 출처

- [[2024-10-14-chapter4-dataLink]] — 「MAC주소」 절이 **48비트가 OUI(제조사)와 UAA(제조사가 부여한 고유번호)로 갈린다**는 것과 16진수 표기 두 가지를 적었다. 「프레임의 구조」가 **송신자·수신자 MAC 과 프로토콜 정보**를 헤더에 넣는다는 것을 보이고, 그 프로토콜 자리에 IPv4·IPv6·ARP 가 온다는 것으로 이어진다. **「ARP를 이용하여 MAC주소를 얻는 과정」 네 걸음**이 이 절의 핵심이다 — 브로드캐스트로 묻고(ARP 요청), 해당 컴퓨터가 답하고(ARP 응답), 그것을 표로 저장하고(ARP 테이블), 그다음부터 통신한다. **「모든 컴퓨터에게 질의하는 행위를 브로드캐스트라고 한다」**는 정의도 여기서 나온다. 다만 ARP 응답을 검증하지 않는다는 것, MAC 이 구간마다 바뀐다는 것은 다루지 않았다 → [[ip-address]]
