# 시간 복잡도 (제약에서 알고리즘 고르기)

**입력이 커질 때 연산 횟수가 어떻게 늘어나는지.** 코딩 테스트에서 이것을 먼저 계산하는 이유는 **문제의 제약이 답의 종류를 알려 주기 때문**이다.

## 정의

이 문제집의 풀이가 언제나 같은 순서로 시작한다.

```
1. 시간 복잡도, 공간 복잡도
2. 최대·최소 조건        ← 여기서 1번의 상한이 나온다
3. 사용 알고리즘          ← 1·2 가 정해 준다
4. 반례, 경계값
```

**「최대 조건」을 먼저 읽고 거기서 쓸 수 있는 복잡도를 역산한다.**

| 입력 상한 | 허용되는 복잡도 | 이 문제집의 예 |
|---|---|---|
| n ≤ 100×100 | O(n²) 도 된다 | 미로 전체 탐색 → [[breadth-first-search]] |
| n ≤ 9 | 무엇이든 — 조합을 다 봐도 된다 | 난쟁이 아홉 → [[brute-force]] |
| 지수가 매우 크다 | **O(log n) 이어야 한다** | A^B mod C → [[divide-and-conquer]] |
| 조회가 반복된다 | O(1)·O(log n) 자료구조 | map 으로 이름↔번호 → [[hash-based-collection]] |

**「O(n²) 로 풀 수 있나」를 먼저 묻고, 안 되면 그때 더 나은 방법을 찾는다** — 순서가 반대면 필요 없이 어려운 풀이를 만든다.

## 왜 중요한가

**제약이 힌트다.** 「N ≤ 100」과 「N ≤ 1,000,000」은 **다른 알고리즘을 요구하는 다른 문제**다. 문제를 읽자마자 상한을 확인하는 습관이 풀이의 방향을 절반 정해 준다.

**그리고 「돌아가는 코드」와 「통과하는 코드」가 다르다.** 완전탐색은 거의 언제나 정답을 내지만 **시간 안에 못 낸다** — 맞고 틀림이 아니라 **시간이 채점 기준**이라는 것이 이 판의 성격이다.

**실무에서도 같은 물음이 반복된다.** 반복문 안의 질의가 N 번 나가는 것(→ [[n-plus-one]]), OFFSET 이 커질수록 느려지는 것(→ [[pagination]]), 인덱스 없는 검색이 전수 조회가 되는 것(→ [[database-index]]) — 전부 **입력이 커질 때 무엇이 몇 번 일어나는가**의 문제다.

## 경계와 오해

- **상수는 무시하지만 현실에서는 안 무시된다** — O(n) 두 개와 O(n) 하나는 같은 표기이지만 실행 시간은 두 배다. **표기가 같아도 통과와 시간 초과가 갈릴 수 있다**
- **공간 복잡도를 잊기 쉽다** — 이 문제집이 시간과 공간을 나란히 적는 이유다. `visited[104][104]` 처럼 배열을 미리 잡을 때 **크기가 메모리 제한을 넘는지** 봐야 한다
- **자료구조를 고르는 것이 곧 복잡도를 고르는 것이다** — 배열에서 찾으면 O(n), map 이면 O(log n), 해시면 평균 O(1) → [[linear-search]] · [[hash-based-collection]]
- **최악만 보는 것도 함정이다** — 평균적으로 빠른데 최악이 나쁜 방법이 실전에서는 나을 때가 있다. 다만 **채점은 최악을 넣는다**
- **「전체 탐색 O(n²)」 같은 표기는 대충일 수 있다** — 이 문제집의 미로 문제에서 실제 방문은 칸 수만큼이라 O(N×M) 이고, n 을 한 변으로 보면 n² 이다. **무엇을 n 이라 했는지**를 함께 말해야 뜻이 통한다

## 출처

- [[2025-04-30-Pr2309]] — 아홉 중 일곱을 고르는 문제에서 **상한이 작다는 것이 곧 완전탐색 허가**가 된다. 두 명을 빼는 모든 조합이 36가지뿐이라 이중 반복문으로 끝난다
- [[2025-05-09-Pr1629]] — 「분할 정복을 사용하여 **O(log n)** 으로 해결 가능하다」로 **필요한 복잡도에서 알고리즘을 역산**한 자리다. 지수를 하나씩 곱하면 O(n) 이고 그것으로는 안 된다는 판단이 먼저 있다
- [[2025-06-11-pr2178]] — 「모든 좌표를 전체 탐색했을 때 O(n^2)」와 「좌표의 최대 조건은 100 × 100」이 나란히 적혀 있다 — **상한을 보고 전체 탐색이 가능하다고 판단한** 뒤 BFS 로 간다
- [[2025-05-08-Pr1620]] — 「map 구조는 탐색 시 **O(logN)** 으로 가능하다」로 **자료구조 선택이 곧 복잡도 선택**이라는 것을 적었다
