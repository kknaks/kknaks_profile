# 스테이징 영역 (Staging Area)

다음 커밋에 담을 파일을 미리 등록해 두는 중간 자리. `git add` 가 여기에 올리고, `git commit` 이 여기 있는 것만 저장소에 보관한다.

## 정의

[[git]] 에서 파일이 저장소에 들어가기까지 두 단계를 거친다.

1. `git add` — 이번 버전에 담을 파일을 목록에 등록한다
2. `git commit` — **목록에 등록된 파일만** 식별자를 붙여 저장소에 보관한다

고쳤지만 `add` 하지 않은 파일은 커밋에 들어가지 않는다. 즉 편집한 것과 기록할 것이 같지 않아도 된다.

## 사용 예시

```bash
$git add .                              # 현재 디렉토리의 변경 전부를 등록
$git commit -m "변경내용(메세지)"        # 등록된 것만 저장소에 보관
```

`git add .` 의 `.` 은 현재 디렉토리라는 뜻이다. 파일을 하나씩 지정하면 그 파일만 등록되고, 나머지 변경은 작업 디렉토리에 남아 다음 커밋으로 넘어간다.

## 왜 중요한가

**커밋의 단위를 사람이 정할 수 있다.** 한 번 작업하는 동안 성격이 다른 변경 여러 개를 만드는 일이 흔한데, 스테이징이 없으면 그것이 전부 한 커밋에 섞여 들어간다. 그러면 나중에 하나만 되돌릴 수 없고, 이력을 읽어도 무엇을 한 커밋인지 알 수 없다.

편집과 기록을 갈라 놓은 덕에 **"고치는 일"과 "무엇을 한 변경으로 남길지 정하는 일"을 따로 할 수 있다.**

## 경계와 오해

- **스테이징 ≠ 백업 목록** — 옛 필기에 "백업파일목록"이라 적어 두었는데, 여기 등록해도 어디에도 보관되지 않는다. 보관은 `commit` 이 한다. `add` 만 하고 커밋하지 않은 채 파일을 되돌리면 그대로 잃는다.
- **`add` 는 시점을 찍는다** — 등록한 뒤 그 파일을 또 고치면, 커밋에는 **`add` 한 시점의 내용**이 들어간다. 다시 `add` 해야 최신 내용이 담긴다.
- **한 번 `add` 하면 계속 따라오는 것이 아니다** — 커밋할 때마다 등록이 필요하다.
