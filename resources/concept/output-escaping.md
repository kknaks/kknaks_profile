# 출력 이스케이프 (Output Escaping)

값을 문서에 꽂을 때 **그 값이 문법으로 읽히지 않도록 특수문자를 바꿔 쓰는 것.** `<` 를 `&lt;` 로 만들면 태그가 아니라 글자가 된다.

## 정의

문제의 모양은 항상 같다 — **데이터가 코드로 읽히는 것**이다.

| 문자 | 이스케이프 |
|---|---|
| `<` | `&lt;` |
| `>` | `&gt;` |
| `&` | `&amp;` |
| `"` | `&quot;` |
| `'` | `&#39;` |

JSP 에서는 [[jstl-core-tag]] 의 `c:out` 이 이것을 **기본으로** 한다.

```jsp
<c:out value="${title}"/>                    <%-- 이스케이프한다 (escapeXml 기본 true) --%>
<c:out value="${title}" escapeXml="false"/>  <%-- 하지 않는다 --%>
${title}                                     <%-- 하지 않는다 --%>
```

**끄는 쪽이 명시적이고 켜는 쪽이 기본**이라는 설계다 — 잊었을 때 안전한 쪽으로 떨어진다.

## 사용 예시

제목에 스크립트를 넣은 글이 있다고 하자.

```
제목: <script>alert(document.cookie)</script>
```

```jsp
${board.title}                     <%-- 브라우저가 실행한다 --%>
<c:out value="${board.title}"/>    <%-- 글자로 보인다 --%>
```

위쪽은 그 글을 열어 본 **모든 사용자의 브라우저에서** 그 스크립트가 돈다. 세션 쿠키를 읽어 어딘가로 보내는 것도 그 안에서 된다 → [[cookie]] · [[http-session]]

## 왜 중요한가

**같은 모양의 사고가 계층마다 반복된다.** 값이 문장의 일부로 읽히면, 그 문장을 해석하는 쪽이 무엇이든 사고가 난다.

| 어디서 | 값이 무엇으로 읽히나 | 막는 방법 |
|---|---|---|
| SQL 문장 | 쿼리 문법 | 값 자리를 `?` 로 분리 → [[prepared-statement]] · [[sql-injection]] |
| HTML 문서 | 태그·스크립트 | 이스케이프 |
| CSV·JSON | 구분자·구조 | 인용·이스케이프 → [[csv]] · [[json]] |

**「문법과 데이터를 섞어 문자열로 만든다」는 것이 공통 원인**이고, 해법은 둘 중 하나다 — 아예 섞지 않거나([[prepared-statement]] 처럼 자리를 분리), 섞되 데이터를 문법이 아니게 만들거나(이스케이프).

HTML 쪽이 특히 잊히기 쉽다. SQL 은 [[sql-injection]] 이라는 이름이 붙어 배우지만, 화면에 값을 찍는 것은 **너무 당연해서 위험해 보이지 않는다.**

## 경계와 오해

- **EL 은 이스케이프하지 않는다** — `${title}` 은 값을 **그대로** 쓴다. `c:out` 이 존재하는 이유가 정확히 이것이고, 「EL 이 더 짧으니 그걸 쓰자」가 조용히 구멍을 만드는 자리다 → [[expression-language]]
- **입력을 검사하는 것과 출력을 이스케이프하는 것은 다른 일이다** — 저장할 때 `<script>` 를 걸러 내는 것으로 대신하려 하면, 걸러야 할 목록이 계속 늘어나고 정상 값(`a < b`)까지 망가진다. **넣을 때가 아니라 꺼내 쓸 때, 쓰이는 문맥에 맞게** 처리하는 것이 기준이다
- **문맥마다 이스케이프 규칙이 다르다** — 같은 값이라도 태그 사이에 들어갈 때, 속성값 안에 들어갈 때, `<script>` 블록 안에 들어갈 때, URL 자리에 들어갈 때가 각각 다르다. `escapeXml` 이 처리하는 것은 첫 번째와 두 번째까지다
- **`escapeXml="false"` 가 필요한 경우가 있다** — 에디터로 작성한 본문 HTML 을 그대로 보여 줘야 할 때다. 그때는 **저장 전에 허용 태그만 남기는 처리**가 따로 있어야 하고, 그것 없이 끄면 그냥 열어 두는 것이다
- **이스케이프는 값을 바꾸지 않는다** — 저장된 것은 여전히 `<script>` 이고, **보여 줄 때의 표기만** 바뀐다. 다시 꺼내 쓸 때 또 처리해야 한다는 뜻이다

## 출처

- [[2024-09-11-Day74]] — 「c:out」 절이 「일반적인 출력과 달리 **HTML 이스케이프 처리가 기본으로 적용**되므로, HTML 태그가 그대로 출력되는 것을 방지할 수 있다」고 적고, `escapeXml` 속성의 기본값이 `true` 이며 `false` 로 끌 수 있다는 것을 명시했다. **기본값이 안전한 쪽이라는 설계**가 이 개념의 핵심인데, 필기는 그것을 「방지할 수 있다」까지만 적고 방지하지 않으면 무엇이 일어나는지(스크립트 실행·세션 탈취)는 다루지 않는다. `${...}` 로 그냥 쓰면 이스케이프되지 않는다는 대비도 명시되지 않았다 — 같은 노트가 EL 을 훨씬 자주 쓰고 있어 실제로 갈리는 자리다
