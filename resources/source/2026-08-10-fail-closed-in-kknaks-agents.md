# fail-closed 가 kknaks-agents 결정에서 요구된 자리들

`kknaks-agents` 의 package 경계 결정 일곱 건(DEC-002·003·004·005·006·007·008)이 전부 **fail-closed** 를 기본값으로 채택했다. 개념 노트가 없어 각 결정이 그 말을 자기 문맥에서 다시 정의하고 있었다. 개념을 세우기 위해 그 자리들을 모은 **실무 기록**이다.

## 관찰된 자리

| 결정 | 무엇을 막나 |
|---|---|
| DEC-002 (turn runtime) | 회복 경로를 근거 없이 만들지 않고 **실패를 그대로 드러낸다** |
| DEC-003 (core 계약) | 계약 밖의 것은 통과시키지 않는다 |
| DEC-004 (process 격리) | **「판정하지 못하면 막는다」** — 보안 경계 13항목의 판정 원칙 |
| DEC-005 (provider 변환) | capability 가 선언하지 않은 것은 지원한다고 보지 않는다 |
| DEC-006 (tools) | 등록·허용·검증·정책 중 하나라도 못 넘기면 실행에 닿지 않는다 |
| DEC-007 (sessions) | 직렬화에서 **모르는 필드가 오면 막는다**(unknown fail-closed) |
| DEC-008 (skills) | 투영 값의 출처·신뢰 등급이 확인되지 않으면 model 에 닿지 않는다 |

## 반복된 문장

DEC-002 가 이유를 가장 짧게 적었다.

> **fail-closed 를 고르는 이유는 회복 경로를 근거 없이 먼저 만드는 것보다 실패를 보는 편이 싸기 때문이다.**

DEC-004 는 판정 규칙 자체로 적었다.

> **fail-closed — 판정하지 못하면 막는다.**

## 공통된 모양

1. **모르는 것을 통과가 아니라 차단으로 처리한다.** 새 필드·미선언 capability·미등록 tool 이 전부 「일단 허용」이 아니라 「막음」이다.
2. **회복을 미리 만들지 않는다.** 실패했을 때 무엇을 할지는 근거가 쌓인 뒤에 정한다 — 추측으로 만든 회복 경로가 더 비싸다는 판단이다.
3. **경계마다 다시 적용된다.** 한 층에서 막았다고 다음 층이 믿지 않는다.

## 갈리는 지점

- **fail-open 이 맞는 자리도 있다.** 읽기 전용 조회나 관측처럼 **막는 비용이 통과 비용보다 큰** 곳이다. 이 결정들이 전부 fail-closed 인 것은 **실행 경계**를 다루기 때문이다.
- **fail-closed 는 가용성을 깎는다.** 모르는 것을 막으므로, 상류가 새 필드를 더하면 하류가 멈춘다. 버전 협상이 함께 있어야 한다.
